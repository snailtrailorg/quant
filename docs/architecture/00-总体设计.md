# 00 - 总体设计

## 1. 背景与目标

私有化部署的个人多市场量化交易平台，部署在 Linux 云服务器（Amazon Linux 2023），7×24h 常驻运行。覆盖三类标的，风险严格分层：

| 市场 | 模式 | 权限 |
|---|---|---|
| A股个股 | 仅分析（日线选股 + 分钟级研判），输出操作建议 | **只读，物理禁下单** |
| 可转债 / 场内ETF | 全自动 T+0 程序化交易 | 自动开平仓 |
| 加密货币永续合约（币安/OKX） | 全自动 CTA/网格/对冲 | 自动开平仓 |

核心差异化：**A股只分析不下单，可转债/ETF/加密合约全自动交易**，权限从代码层、网关层、AI 层三重隔离。

## 2. 设计原则

1. **私有化优先**：数据、密钥、策略全部自留，无第三方托管。AI 模型只用国内模型（DeepSeek/GLM），不接 Anthropic/OpenAI 运行期。
2. **成熟开源优先，零自研底层**：交易/网关/回测/数据轮子用 vnpy + VeighNa + 第三方数据源，只在配置层、抽象层、AI 层自建。
3. **统一模型结构、分离执行语义**：策略逻辑层统一抽象（Strategy/因子/信号/适配器），各市场执行规则（T+1/T+0/涨跌停/时段）下沉到 ExecutionAdapter。
4. **配置驱动而非硬编码**：因子组合、权重、参数走 Web 配置 + DSL 表达式，避免每个模型改代码。
5. **回测与实盘同构零迁移**：数据 schema 现在就和未来 XTP 实时行情对齐，策略模板回测/实盘共用。
6. **权限三重隔离**：代码层注销 A股下单函数；网关层 A股 adapter 永久 raise；AI 层下单类工具永不注册。
7. **轻量化**：venv + systemd，无 Docker；PostgreSQL（含 pgvector）+ Valkey 统一承载业务/时序/向量，弃 TimescaleDB/重型向量库。

## 5. 模块间数据流

**行情流入**
```
Tushare/AkShare ──┐
币安/OKX WS ──────┤──> 数据中台(清洗) ──> PostgreSQL(历史) + Valkey(实时)
                  │                              │
                  └──────────────────────────────┴──> 各策略 on_bar/on_tick
```

**策略执行流**
```
策略收到行情 ─> 因子计算 ─> 信号聚合 ─> [风控中心 check_order] ─> ExecutionAdapter.send_order
                                          │ (A股 adapter raise, 永不下单)
                                          └─> vnpy 网关 ─> 券商/交易所
```

**AI 流**
```
盘后报告/研报/可转债条款 ──> LLM网关.chat(tier=...) ──> DeepSeek(主)/GLM(备) ──> 结果回写
Web自然语言查询 ──> LLM网关.chat(tools=[查持仓/查盈亏/查策略状态]) ──> 工具调用 ──> 返回
   (下单类工具永不注册)
飞书机器人 ──> LLM网关.chat(tools=[读类 + 操作类])
   ├─ 读类工具(查持仓/盈亏/研判) ──> 直接执行 ──> 回飞书
   └─ 操作类工具(熔断/恢复/停策略) ──> 发确认卡片 ──> 用户确认 ──> 执行 ──> 回飞书
      (下单类工具永不注册；操作类带交互确认)
```

**风控/告警流**
```
风控触发 ─> 告警/通知.notify(level, msg) ─> 微信/Discord
一键熔断 ─> 风控中心.emergency_halt() ─> 所有自动交易策略暂停开仓
```

**调度流**
```
Celery beat ─> 定时任务(选股/数据增量/盘后报告) ─> 调用对应模块 ─> 结果入库 + 告警推送
```

        # 委托 ExecutionAdapter，A股 adapter 此处 raise

class AStockReadonlyAdapter(ExecutionAdapter):

## 7. 部署拓扑

单机（阶段1）/ 多节点拆分（阶段2，资源不足时）。

**单机（默认）：** 一台 Linux ECS 跑全部模块，PostgreSQL+Valkey+vnpy 进程+Web+调度+LLM 网关全部 systemd 守护。

**分布式拆分（按需）：**
- 数据节点：数据中台 + PG + Valkey
- 交易策略节点：vnpy 核心 + 三市场策略
- Web 管控节点：Web 后台（最低配）
- 跨节点通信用 RPC + Valkey 消息队列（vnpy 原生支持）

所有服务 systemd 开机自启、异常重启、崩溃告警；数据库定时备份、日志分级+过期清理。

## 8. 关键约束

1. **A股三重只读**：代码层注销下单函数 + AStockReadonlyAdapter raise + AI 不注册下单工具。
2. **国内模型**：运行期 AI 只用 DeepSeek/GLM；Claude/OpenAI 仅作开发助手（Claude Code），不进平台运行期。
3. **资源轻量**：Python3.10 venv（不用 3.14，vnpy/vnpy_xtp 无预编译 wheel），无 Docker，PG+Valkey+pgvector 统一存储。
4. **可转债/ETF 实盘走中泰 XTP + vnpy_xtp**（Linux 原生），待券商确认门槛/品种/费率后回填参数。
5. **回测与实盘 schema 对齐**：Tushare/AkShare 历史数据 schema 现在就和未来 XTP 实时行情对齐，20 天等待期回测结果零迁移切 live。
6. **单系统多用户 RBAC，非多租户**：平台定位为**单套系统多用户**（Admin/Operator/Viewer 共享同一套数据与交易系统，仅权限分层），**不做多组织数据隔离**。多租户需求的产品形态是**售出独立实例**（软件/配置好的主机/VPS），而非单系统内隔离。
7. **权限层在访问边界**：权限分层放 Web/飞书/LLM 网关访问层，vnpy/策略引擎/风控单例是边界后共享服务，不动；API 密钥系统级托管，仅 Admin 管理。
8. **多语言国际化（i18n）**：Web 前端按浏览器语言自动切换中/英文；LLM 回复/飞书回复/告警推送按用户语言偏好输出；日志统一英文。检测：Web 端 `navigator.language`，服务端 `LANG` 环境变量，飞书用户 locale，DB 可配用户偏好覆盖。

## 8.5 访问控制与角色（RBAC）

平台**单系统多用户**，三个角色共享同一套数据（持仓/盈亏/策略/行情），差异仅在**能做什么**。不是多租户，数据不加 `user_id` 隔离，只加 `audit_log.actor` 记操作人。

| 角色 | Web API | 飞书工具 | 系统管理 |
|---|---|---|---|
| **Viewer**（查看） | 只读 GET（持仓/盈亏/研判/日志） | 读类工具 | 无 |
| **Operator**（操作） | 读 + 策略启停 + 参数改 + 熔断 | 读类 + 操作类（带确认） | 无 |
| **Admin**（管理） | 全部 + 账户/密钥 + 风控规则 + 系统配置 | 全部（操作类带确认） | 全部 |

**安全约定：**
- **API 密钥**（XTP/币安/OKX）系统级托管，仅 Admin 管理，Operator/Viewer 永不见明文。
- **熔断**：Operator+Admin 可 `emergency_halt`（安全冗余，任何人能紧急停）；`resume` 仅 Admin（避免操作员擅自恢复）。
- **审计**：所有 mutation（启停策略/改参数/熔断/改风控/改密钥）必带 actor，写 `audit_log`，Web 可查。
- **LLM 网关工具按角色过滤**：每次 `chat()` 按调用者角色决定可用工具集（详见 01）。
- **并发指令**：多 Operator 同时操作同一策略，用乐观锁/状态机防冲突。

权限不进 vnpy/策略引擎/风控单例——它们是边界后共享服务，收合规请求即执行。详见 08（Web 认证+RBAC）、11（飞书角色映射）、01（工具按角色过滤）。
