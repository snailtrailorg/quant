# 00 - 总体设计

## 1. 背景与目标

私有化部署的个人多市场量化交易平台，部署在 Linux 云服务器（Alibaba Cloud Linux 3 / OpenAnolis / al8 / RHEL8 系），7×24h 常驻运行。覆盖三类标的，全部可实盘（受实盘三级开关 + 分市场分项控制）：

| 市场 | 模式 | 交易通道 | 开关分项 |
|---|---|---|---|
| A股个股 | 日线选股 + 分钟级研判 + 实盘交易 | 中泰 XTP（vnpy_xtp） | `astock` |
| 可转债 / 场内ETF | 全自动 T+0 程序化交易 | 中泰 XTP（vnpy_xtp） | `convertible` / `etf` |
| 加密永续合约 | CTA 趋势（双均线）+ 网格/对冲（未来） | 币安/OKX（vnpy 加密网关，外部 gate） | `binance_perp` / `okx_perp` |

核心差异化：**多市场混合 + 配置驱动策略 + 平台化通用接口**——别人通过配置 + 实现接口子类即可接入自己的数据源/通道/AI/工具，不改平台代码。

## 2. 设计原则

1. **私有化优先**：数据、密钥、策略全部自留，无第三方托管。运行期 AI 只用国内模型（DeepSeek/火山方舟/GLM），不接 Anthropic/OpenAI 运行期。Claude Code 仅作开发助手。
2. **成熟开源优先，零自研底层**：交易/网关用 vnpy + vnpy_xtp，回测自建 BacktestEngine（纯 Python，不依赖 vnpy CtaBacktestingEngine）。
3. **统一模型结构、分离执行语义**：Strategy 基类 + Factor 注册制 + SignalAggregator + DSL，各市场执行规则下沉到 ExecutionAdapter。
4. **配置驱动而非硬编码**：因子组合/权重/参数走 Web 配置 + DSL 表达式，每策略改代码是错误做法。
5. **策略注册制 + 双模式统一执行**：`@register_strategy("type")` + `from_config` 按 type 分发。DSL 编译成 Python + 代码模式直接 Python，都成 Strategy 子类实例走 on_bar→ActionSignal→风控→执行。执行一套（区别于专家"双引擎两套执行"），可审计/AI 生成统一。
6. **回测与实盘同构零迁移**：数据 schema 与未来 XTP 实时行情对齐，on_bar 逻辑回测/实盘一致。
7. **平台化通用接口**：6 大接口抽象（DataSource / Broker / MessageChannel / Task / RiskRule / LLMProvider），基类 + DB 配置表 + 工厂 `get_<x>(provider)`，别人实现子类即接入。
8. **多模型 fallback**：LLM 网关按 `priority` 全局排序，primary + fallback 容灾（2026-08-07 移除 tier 分级）。
9. **实盘三级开关**（AND）：`.env ENABLE_LIVE_TRADING` 总闸 + Web `live_trading_config` 5 分项 + 策略 `enabled`+`backtest_verified`。任一关即拒单。
10. **轻量化**：venv + systemd，无 Docker；PostgreSQL 18 + pgvector + Valkey 统一承载，弃 TimescaleDB/重型向量库。

## 5. 模块间数据流

**行情流入**
```
Tushare/AkShare ──┐
XTP 实时 tick ────┤──> 数据中台(清洗/validate_bars) ──> PG(历史 bar)
                  │                                      │
                  ├── direct: strategy_runner 自连 MD: tick→BarGenerator→on_bar
                  └── hub: quant-md-hub(MD 单实例) → MinuteAggregator
                        → Valkey Streams hub:bars:{symbol} → worker(hub 模式) → on_bar
                        （影子期 bar_hub vs bar_shadow 双轨 diff 门禁，切流走批 6）
```

**策略执行流（实盘）**
```
strategy_config（配方）+ live_task（任务，一标的一进程）
  → strategy_runner --task-id <live_task_id>
  → 读 strategy_snapshot + live_task.symbol + live_task.params
  → XtpGateway tick → BarGenerator → strategy.on_bar(bar, history)
    → 因子计算 → SignalAggregator → Signal
    → check_order(三级开关 + 风控规则 + adjusted 覆写)
    → XTPAdapter.send_order(Order)
    → _log_signal_order(写 signal_log + order_log)  ← 三账数据来源
    → record_broker_usage(写 broker_usage)
```

**策略执行流（回测）**
```
BacktestEngine.run(config, bars, on_bar_callback)
  → monkey-patch place_order(跳风控, BacktestAdapter 按收盘价成交)
  → 每 bar 推 progress/bar/trade/equity 到 Valkey → SSE 前端实时
  → validate_no_future_data + precheck_backtest_data(预检)
```

**AI 流（工具闭环）**
```
Web/飞书 → gateway.chat(messages, tools, role, caller)
  → LLM 返回 content + tool_calls
  → 循环执行 tool_calls(query_position/risk_state/astock_analysis...)
  → 结果回填 messages → 再 chat → 最终 content
  → 飞书操作类(emergency_halt/strategy_stop) → 确认卡片 → execute_confirmed_tool
```

**三账对账流**
```
策略 place_order → signal_log(信号) + order_log(委托)  ← backtest_runs.task_id 关联 tasks.id（PT1 卡死检测复用）
ExecutionAdapter 事件 → trade_log(成交)
reconcile_three_books → 比对(信号无委托/委托不成交/滑点异常) → 告警
```

**风控/通知流**
```
事件源(邮件失败/任务失败/风控/数据异常) → alert_notify.notify(level, category, title, body)
  → PG notifications(持久化) + 顶栏铃铛(60s轮询 active) → 点击按 category 跳转 → 全部确认
  → 仅 risk+critical 推外部通道(Discord/WechatWork)；订阅型 report() 保留外推
一键熔断 → emergency_halt(Valkey) → 所有策略 check_order 拒单
```

**邮件流**
```
接口触发(邀请/重置/开通) → queue_email(email_outbox 落PG) → try_row(立即试发)
  → 成功: status=sent
  → 失败: 指数退避重发(1→2→4→8→16→30min, 6次耗尽标failed → 通知中心铃铛)
Celery beat email_outbox_sweep 每分钟扫描待发
SMTP 配置走 system_config(smtp_*五项, 密码Fernet加密, 弃.env)
```

- polkit 规则：quant 用户可 `systemctl start/stop/restart quant-live-task@*`（Web 控制）
- 数据库定时备份：`backup-db.sh`（pg_dump + gzip + 保留 7 天）
- 资源限制：`MemoryMax`/`MemoryHigh`/`CPUQuota` cgroup 限策略进程
- **部署隔离铁律**（与 safebox 共存）：clear-redis 只 `FLUSHDB -n` 不 `FLUSHALL`；restart-web 用 `reload` 不 `restart`；clear-pg 严格 `DROP DATABASE quant` 不碰 safebox 库

## 8. 关键约束

1. **实盘三级开关**（AND，铁律）：`.env ENABLE_LIVE_TRADING` + Web `live_trading_config` 5 分项（convertible/etf/astock/binance_perp/okx_perp）+ 策略 `enabled`+`backtest_verified`。任一关 → `check_order` 拒单。
2. **运行期 AI 只用国内模型**：火山方舟（当前主）/ DeepSeek（fallback）/ GLM（备），不接 Claude/OpenAI 运行期。LLM 回复按输入语言自然回复（2026-08-07 移除 lang 注入）。
3. **Python 3.10 本地 / 3.11 服务器**：不用 3.14（vnpy 硬 pin PySide6）。
4. **回测自建 BacktestEngine**：纯 Python，不依赖 vnpy CtaBacktestingEngine。回测与实盘 on_bar 一致。
5. **平台化通用接口**：6 大接口按通用方向设计，实现可简化。别人配置 + 实现子类即接入。
6. **策略注册制**：新策略继承 Strategy + @register_strategy，from_config 按 type 分发。配置驱动非硬编码。
7. **可转债/ETF 实盘走中泰 XTP + vnpy_xtp**（Linux 原生），需中泰开户。
8. **配置驱动非硬编码**：策略因子组合/权重/参数走 Web 配置 + DSL，每个策略改代码是错误做法。
9. **schema 版本管理**：alembic 迁移文件为唯一真相源，不手动 ALTER。运行时 DDL 清零（2026-08-13），`verify_schema()` 启动校验。
10. **类型级同步异步化**：耗时同步操作走 Celery 异步 + Valkey 进度轮询。per-symbol 单只同步保持同步（快）。
11. **N 语言架构**：注册表驱动（en 缺省），加语言=只加条目零逻辑改动。条款全语言堆叠；邮件跟操作者界面语言；页面跟浏览器。
12. **错误码化**：`ApiError(status, CODE, 中文兜底)` → `{detail, code}`；前端 `apiErr(e)` 本地化映射+回落。
13. **SMTP 配置 DB 化**：`system_config` 表 smtp_* 五项（密码加密），弃 .env。条款单一源 terms.py。
14. **账户保护**：管理页不能动自己（末位 admin 隐式不可达）；自助注销路径末位 admin 显式设防。删除=软删+脱敏。

## 8.5 访问控制与角色（RBAC 四角色）

平台**单系统多用户**，四个角色共享同一套数据，差异仅在**能做什么**。非多租户，数据不加 `user_id` 隔离，只加 `audit_log.actor` 记操作人。

| 角色 | Web API | 飞书工具 | 说明 |
|---|---|---|---|
| **Viewer**（查看） | 只读 GET | 读类工具 | 默认角色 |
| **Analyst**（研究） | + 策略/回测/数据同步 | 读类工具 | 研究隔离防误操作 |
| **Trader**（交易） | + 策略启停/熔断/参数改 | 读类 + halt + 策略启停 | 交易操作 |
| **Admin**（管理） | 全部 + 账户/密钥/风控规则/系统配置 | 全部（操作类带确认，resume 仅 Admin） | 系统管理 |

**安全约定**：
- 用户密码 bcrypt（hashpw/checkpw，旧 sha256 自动重置）。
- API 密钥系统级 AES 加密存储（`crypto_utils.encrypt/decrypt`），仅 Admin 管理。
- 用户开通方式：admin 邀请制（填 email 发邀请邮件 → 被邀请者自助开通，默认 Viewer）。非开放注册，非多租户。
- 熔断：Trader+Admin 可 `emergency_halt`；`resume` 仅 Admin。
- 审计：所有 mutation 必带 actor 写 `audit_log`。
- LLM 工具按角色过滤（`_filter_tools`：角色白名单 ∩ 传入 tools）。
