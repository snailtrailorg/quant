## 1. 分层心智：按消费模式分三档

```
第一档 全局定时（幂等批量）      第二档 池内增量（per-symbol）     第三档 按需实时（详情页）
全市场覆盖，盘后/盘前定时        只拉池内 30-100 只，随池滚动      用户点开标的才拉，用完即弃
batch_date：1 次 API=全市场 1 天  per_symbol：1 标的 1 次全历史     1-3 次 API + 5min TTL 缓存
存 DB ← 选股引擎因子从这读       存 DB ← 池内深度分析从这读        不落库不落盘（Valkey 缓存）
sync_config cron 驱动（游标增量） 池成员驱动（无 sync_config）      请求驱动
```

**为什么分档（抽象依据）**：数据的"消费广度 × 更新频率 × 存储价值"三轴不同——
- 选股因子要**全市场**但只要**日频落库**，batch 接口 10 次/天就够，多拉即浪费；
- 深度财务/筹码**全市场拉不动也没人看**（Tushare per-symbol 限速），只有池内 30-100 只有消费价值；
- 详情页的"实时价/今日资金分时"**过夜即失效**，落库纯浪费存储，TTL 缓存恰好匹配生命周期。

## 2. 模块归位与分层（铁律对齐）

| 关注点 | 归属 | 理由 |
|---|---|---|
| 第一档 handler | `data_sync/engine.py` `_HANDLERS` 注册表 + `_make_tier1_handler` 工厂 | 与既有日线同步同一调度面（sync_config cron + 游标增量 + backfill 语义），复用 sync_log/SyncLock/告警全链 |
| 第二档同步 | `data_sync/pool_data.py` **独立模块**（U 审修正 #3：不碰注释态池分钟 beat） | 驱动源不同：池成员集合（动态）而非 sync_config 游标；时间盒模式（280s 到即收工下轮续）而非全量完成 |
| 第三档聚合 | **不在 web_api 写业务**（分层铁律）——聚合逻辑下沉服务模块（实施时落 `astock_analysis` 或新 `stock_detail`），web_api 只参数校验+调用 | 组合根不寄生业务逻辑 |
| 表结构 | 迁移 0045（9 表）/0046（10 表），列名=Tushare 原始列名 | 全列存（财务四表核心列+raw_json），渲染层选核心列展示——上游加列零迁移 |
| 层级 | data_sync=层 3、web_api=层 4（入口），tests/test_layering.py 断言守门 | 既有铁律，本设计零破例 |

## 3. 第一档：全局定时同步（选股地基，已上线）

**9 张表**（迁移 0045）：`stk_limit` 涨跌停价（盘前 8:40）/ `moneyflow` 资金流（盘后）/ `margin_detail` 融资融券（T+1）/ `top_list` 龙虎榜 / `block_trade` 大宗 / `cyq_perf` 筹码胜率汇总 / `forecast` 业绩预告 / `namechange` 曾用名（ST 识别，U-1 补）/ `concept` 概念板块（U-1 补）。

**机制**：
- `_make_tier1_handler(table, pull_fn, pk, floats)` 工厂两模式：**批量日期循环**（按 sync_config 游标逐日拉，幂等 upsert）与**全量重建**（namechange/concept 这类变更驱动表，整表 DELETE+INSERT）。
- 调度：sync_config 种子错峰 cron（8:45 涨跌停 / 17:0x 盘后族）+ `data_sync_scheduler` 300s 扫描触发（U 审修正 #1：**不动 beat 加新调度**）。
- 超时：`sync_via_celery soft_time_limit=3600` 覆盖全局 300s（U-3：全市场 batch 带限速必超默认值）。

**生产验证**（2026-08-19）：stk_limit 7749 / moneyflow 5541 / block_trade 48 / concept 1346 / namechange 10000 / forecast 1；top_list、cyq_perf 当日无数据、margin_detail T+1 属预期。

## 4. 第二档：池内 per-symbol 深度（已上线）

**10 张表**（迁移 0046，PK 含 `ann_date` 处理财报重述）：财务四表 `income`(85列)/`balancesheet`(152)/`cashflow`(97)/`fina_indicator`(108)——**核心列+raw_json 全列**；`cyq_chips` 筹码分布（PK 含 price 档位）/ `top10_holders` / `dividend` / `pledge_stat` / `share_float` / `stk_holdernumber`。

**机制**（`pool_data.py`）：
- `_get_pool_ts_codes()`：`pools JOIN pool_symbols WHERE category='astock'`（`vt_to_ts` 符号归一）——**出池自动停更**（只拉池内，历史保留，U 审修正 #6）。
- `sync_pools_data(timebox_s=280, full=False, symbols=None)`：时间盒到即收工下轮续 + `SyncLock("pool_data")` 防重叠 + **必写日志护栏**（FATAL/skipped 也落 sync_log，celery 静默死排障刚需）。
- **增量**（2026-08-20，U 审项 10）：财务四表（income/balancesheet/cashflow/fina_indicator）按公告日窗口 `[cursor, today]` 拉（含起点重叠幂等防漏），游标存 `pool_data_cursor` 表（迁移 0047，表级，二档不进 sync_config）。推进条件=该表本轮覆盖全部池标的（timebox/error 不满足则不推进，下轮重拉同窗口）。**dividend 窗口过滤实测无效**（全量有数据窗口 0 行矛盾）维持全量；小表（cyq_chips 只拉当日、季频/事件表量小）不增量。
- **入池回补**（项 9，2026-08-20）：`POST /api/pool/{pid}/symbol` 入池时 astock 池自动投递 `symbols=[ts]` 定向回补（无窗口全量、不推进游标、sync_log mode=backfill）——增量游标只认窗口，新标的历史靠这一投。
- **全量校准**：手动 `POST /api/sync/pool-data/trigger?full=true` + beat `pool-data-full-calibrate` 周日 04:07 自动（游标照常推进——兜住迟到公告/上游改历史/长期失败冻结的窗口）。
- beat `pool-data-sync` 300s（queue=data expires=290）+ `pool_data_sync_task`（soft_time_limit=320）。
- Web：`POST /api/sync/pool-data/trigger?full=` + `GET /api/sync/pool-data/progress`（读 sync_log 最新一轮——原读 Valkey `sync:pool:minute` 是池分钟的键，恒 idle，2026-08-20 修正）。

**生产验证**（2026-08-20）：beat+手动双 `done saved=3802`（2 标的 × 10 接口全历史）。

## 6. U 审裁定存档（防走回头路）

**3 高严重度**：U-1 表 7→9（namechange/concept 不能漏）/ U-2 非池实时改 akshare（Tushare 盘中空）/ U-3 per-task 放宽 soft_time_limit。

## 8. 已知缺口与坑（实施第三档前先清）

1. ~~progress 端点读错键~~ ✅ 2026-08-20 修正：改读 sync_log 最新一轮（原读 Valkey `sync:pool:minute` 是池分钟的键，恒 idle）。
2. ~~ann_date 增量（项 10）~~ ✅ 2026-08-20：游标表 0047 + 窗口拉取 + 入池回补 + 周日 full 校准；duration_ms 修真、raw_json 全量重写随窗口拉取自然消失。**新增注意**：单标的长期失败会冻结该表游标（窗口逐日变长）——出口是周日 full 校准自动解冻；dividend 窗口过滤实测无效（Tushare 返回 0 行矛盾）已撤出增量维持全量。
3. **celery 静默死（两犯）**：部署后 worker 未真正重启 → 新任务 submitted 后无痕迹死亡。验证三件套：部署输出见 `✅ restart-celery done` + 手动 trigger + 查 sync_log。必写日志护栏已是 pool_data 内置模式，新任务照抄。
4. tier1 修过 3 bug（防复发）：INSERT placeholders 必须含 PK 列 / forecast 按 ann_date 非 trade_date / backfill_from 含当日不加 1 天。
5. **接口参数实测才可信**：Tushare 文档声称支持 ≠ 实际过滤生效（dividend 教训：窗口参数不报错但返回 0 行）。二档窗口拉取前对每张增量表做"全量行数 vs 窗口行数"对照实测。
