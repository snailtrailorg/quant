# 23 - 历史数据方案

> 状态：2026-09-07 定稿。本文是历史数据的**完整方案**——数据源、分工、抽象、配置、同步、整合、表结构、界面、合规、稳定性。代码真相源在 `server/src/data_platform/`（中台）+ `server/src/data_sync/`（同步），本文描述"为什么与是什么"。

## 1. 目标与范围

**目标**：为回测、因子、策略、研判、详情页提供**统一口径、可追溯、可回补**的历史数据，并保证**回测与实盘 schema 零迁移对齐**（06 号核心设计）。

**范围**：
- **历史数据**：日/周/月线（慢路径）、分钟线（快路径）、基本面/财务/筹码（三档）、交易日历、基准指数。
- **数据源**：Tushare（主，付费积分）、腾讯（免费行情）、XTP（实时自攒）、币安/OKX（未开通）。
- **不含**：Tick 级高频存储、跨交易所深度套利数据、行情转售。

**核心原则**（06 号 §1）：回测历史数据 schema 现在就和 XTP 实时行情一致，20 天等待期回测结果零迁移切 live。

## 2. 数据源体系

### 2.1 数据源清单与分工协作

| 数据源 | 角色 | 负责数据 | 频率 | 免费/付费 | 状态 |
|---|---|---|---|---|---|
| **Tushare** | 主源 | 日线、基本面、财务、复权因子、交易日历、三档批量数据、基准指数 | 日线/按日批量 | 200 积分（日线够）→ 2000（分钟线） | ✅ 在跑 |
| **腾讯** | 免费补 | 实时 quote、当日分时、**历史分钟 K 线（mkline）** | 实时 + 收盘后攒 | 免费无 key | ✅ 在跑 |
| **XTP** | 实时自攒 | 实盘实时行情 → `bar_hub` 分钟 bar | 实时流 | 券商开通 | ✅ 在跑（只实盘标的） |
| **币安/OKX** | 加密 | 加密永续 K 线/资金费率 | 实时 | 未开通 | ⛔ 待接 |

**分工逻辑（谁负责什么，不重叠）**：

1. **日线及以下慢数据**：Tushare 独家（积分 200 够用，`astock_daily`/`etf_daily`/`cb_daily` 全市场按日同步）。
2. **分钟线历史**：**腾讯攒（当前）→ Tushare 分钟线（终极，2000 元/年开通后切换）**，互斥开关 `minute_data_source`（详见 21 号）。腾讯 1min 只 320 根滚动窗口（≈1.33 交易日），只能每日收盘后取一次攒；Tushare 分钟线可拉全历史。
3. **实盘实时行情**：XTP 经 `md_hub` 消费，落 `bar_hub`（只订阅实盘在跑标的，2026-09-04 缩小后不再为攒数据订阅非实盘标的）。
4. **当日分时曲线**：腾讯优先（全天免费）→ `bar_hub` 兜底（自攒次日全天）。
5. **三档批量数据**（涨跌停/资金流/融资融券/龙虎榜/大宗/筹码/业绩预告/更名/概念）：Tushare 按日全市场批量同步（第一档）。

### 2.2 数据源抽象机制

**接口**（`data_platform/data_source.py`，平台化 PT3）：

```python
class DataSource(ABC):
    # 必须实现
    @abstractmethod
    def get_client(self): ...        # 返回数据源客户端（tushare pro / Wind / akshare）
    @abstractmethod
    def test_connection(self) -> bool: ...
    # 可选（带默认实现）
    def get_rate_limit(self, api_name: str) -> float: ...   # 限速间隔秒
    def record_usage(self, ...): ...                        # 用量记录
```

- **注册表** `_REGISTRY`：`provider -> DataSource 类`。加 Wind = 实现子类 + DB 配置，不改 engine。
- **配置归 DB** `data_source_config`：`credentials_encrypted`（秘密加密）+ `params`（运维参数 JSON）。
- **限速三级覆盖 + 时段乘数**（06 号 §9）：`DEFAULT_RATE_LIMITS`（代码默认）→ `params.rate_limits`（DB 覆盖）→ `params.rate_time_overrides`（时段乘数，盘后放宽）。Tushare 另有积分档 `points_tier`（200/2000/5000 预设批量覆盖，L1）。
- **熔断 CircuitBreaker**：连续失败 5 次 → Open 快速失败 → 60s 后 Half-open 探测。按 DataSource 实例级（配额=账号级）。

## 4. 同步任务

### 4.1 任务清单（`_HANDLERS` 注册表）

| 类 | sync_id | 目标表 | 说明 |
|---|---|---|---|
| **日线 K** | astock_daily / etf_daily / cb_daily | bar_1D | per-symbol 按日 |
| **分钟 K** | astock_minute / astock_minute_5min | bar_1min/bar_5min | **禁用**（200 积分跑不动），改腾讯攒 |
| **基准指数** | index_daily | bar_index | 沪深 300 等 |
| **静态** | astock_basic / astock_list / etf_list / cb_basic | 静态表 | 全量/增量 |
| **日历** | trade_cal | trade_cal | 交易日历 |
| **三档第一档**（9） | stk_limit / moneyflow / margin_detail / top_list / block_trade / cyq_perf / forecast / namechange / concept | 各专用表 | 按日批量/全量重建 |
| **池分钟** | pool_minute | bar_1min | **禁用**（Tushare 分钟线，1 次/小时） |
| **腾讯分钟** | tencent_minute | bar_1min | **新**（15:20 收盘后攒，21 号） |

### 4.2 编排机制

- **Celery beat** 定时触发（`scheduler/app.py` `beat_schedule`），队列分 data/risk/analysis。
- **SyncLock**（Valkey 心跳锁，TTL 60s + 后台心跳）：防重叠，进程被杀 TTL 过期自然释放。
- **sync_log** 可观测：每轮写 status（done/partial/timeout/error）+ failed_dates。
- **三态游标**（日线）：`last_sync_date` 成功才推进；分钟线 per-symbol 失败粒度（不因单标的失败退全市场游标）。
- **交易日校验**：按日拉取用 `trade_cal` 校验预期 vs 实际成功日，缺口暴露在 sync_log。
- **限速**：engine 侧 `rate_limit_context` 声明式（非 adapter 侧），值从 DataSource 取。

### 4.3 回补

`sync(sync_id, backfill_from=YYYYMMDD)` 回补历史缺口，**不推进** `last_sync_date` 游标。池分钟/腾讯分钟用 `MAX(ts)` 缺口判定 + 断点续。

## 5. 数据整合机制

### 5.1 拉取 → 清洗 → 存储 → 推送

```
Tushare/腾讯 ──定时增量──> 清洗(复权/停牌/异常过滤) ──> PG bar 表
XTP WS ───────实时──────> hub 聚合 ──> bar_hub + Valkey Streams ──> worker 消费
```

### 5.2 清洗规则（06 号 §8）

- **复权**：A 股前复权为主，存原始 + 复权因子 `adj_factor`，回测按需取；NULL 因子 = 1.0 降级（16 号）。
- **停牌**：前收盘填充 + source 标记。
- **异常价格**：超涨跌停/0 价 → 过滤告警（`validate_bars` 剔 ohlc=0）。
- **前视偏差**：只用当日收盘后可得数据回测；分钟线严格按时间戳。

### 5.3 三档数据供给（17 号）

- **一档**（全局批量 9 表）：全市场按日同步（涨跌停/资金流等）。
- **二档**（池内 per-symbol 10 表）：池内标的深度数据（财务/筹码/股东）。
- **三档**（按需实时不落库）：详情页实时查询。

### 5.4 回测/实盘 schema 对齐

`bar_{freq}` 表 schema 与 XTP 实时行情一致（11 字段），回测实盘同形。分钟标注统一「分钟末」（16 号：hub `MinuteAggregator` ts=分钟+1min，腾讯/Tushare 口径对齐，21 号实证）。

## 10. 合规设计

1. **密钥管理**：token 加密存 `data_source_config.credentials_encrypted`（`quant_common.crypto` HKDF 派生密钥），`.env` fallback；秘密禁入 Valkey/日志（`stk_mins` 闸门 key 不含 token）。
2. **限速防封禁**：Tushare 积分档 + 三级覆盖 + 时段乘数，engine 侧声明式限速（绝不超 Tushare 官方频控）。
3. **熔断**：连续失败快速失败，防账号被封禁（配额共享体粒度）。
4. **腾讯免费接口**：User-Agent 伪装 + 5s 超时 + 失败重试 1 次 + 负缓存（防高频轮询阻塞/被封）。
5. **数据源授权**：腾讯分钟线属公开免费接口，仅用于自用攒数据，不做转售（06 号 §3 非目标）。
6. **不扫描/不落盘密钥**：全仓合规边界见 CLAUDE.md。

## 11. 稳定性与性能设计

1. **限流熔断**（§2.2/§10）：三层限速 + 时段乘数 + DataSource 级熔断。
2. **SyncLock 心跳锁**：进程被杀 TTL 过期自然释放，防僵尸锁卡死。
3. **幂等 + 断点续**：`ON CONFLICT DO NOTHING` 幂等；游标（last_sync_date / MAX(ts) / Valkey cursor）断点续；腾讯攒游标环形轮转防尾部标的永久排不上。
4. **漏取检测**：腾讯 1min 滚动窗口漏一天断 ~4h → `_check_gap` 用上一交易日（trade_cal）比对 MAX(ts)，落后告警 `minute.gap`。
5. **批量写入**：`executemany` + 单事务（psycopg3 pipeline），杜绝逐行 INSERT（18 号写路径规范）。
6. **时间盒**：同步任务 `timebox` 到点收工下轮续（幂等），防 soft_time_limit 杀。
7. **可观测**：`sync_log`（status/failed_dates）+ `data_source_usage`（用量）+ `sync:pool:minute`/`ds:tencent:minute:cursor`（Valkey 进度）。
8. **连接池**：`get_conn()` 返回 `raw_connection()`，with 退出还池。
9. **时区**：A 股分钟 bar 统一 +08:00（naive datetime 依赖 PG 会话时区，21 号盲审 P2 建议显式 aware，任务 C 一并处理）。
