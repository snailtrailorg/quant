# 24 - 多源架构总方案（历史/实时/交易三层，单源激活）

> 状态：方案 v6（双盲审 A/B 同判修订）。整合 24 号多数据源 + 25 号限速聚合 + 能力矩阵/供给矩阵/归一化。

## 一、分层模型与统一原则

| 层 | 平台 | 抽象接口 | 注册表 | 单源选择 | 现状（诚实定位） |
|---|---|---|---|---|---|
| **历史数据** | Tushare/聚宽/米筐 | `BaseDataAdapter`（拉取+映射）**+** `DataSource`（连接/限速/熔断/用量） | `_ADAPTERS` + `_REGISTRY` | `sync_config.provider` | 24 号已做核心 |
| **实时行情** | XTP/同花顺 | vnpy `BaseGateway` | 无（**硬编码 ThinGateway("XTP")**） | **待新建** `system_config` 行情源键 | ⚠️ 待新建 MD 源注册表 |
| **交易** | XTP/券商 | `Broker`（配置+连接）**+** `ExecutionAdapter`（下单） | `get_broker` + `create_adapter`（两处，key 需对齐） | `strategy_account.broker_provider` | 双层已抽象 |

**腾讯** = 分钟数据攒 pipeline（`tencent_minute.py`，独立机制），**不是 `BaseDataAdapter` 体系**——标注为「分钟攒旁路」，不适用「单源激活+切换」原则。

**统一原则**：
1. 每层「抽象接口 + 多实现注册表 + 单源激活 + 可切换」；**暂不做多源并存**（不主备降级、不双源同时写）。
2. **三层切换语义各异，无公共切换接口**：历史=重建（delete+backfill）、实时/交易=重连。修辞统一，结构不统一。
3. **本批只做历史数据多源**；实时/交易仅写接口契约 + 诚实标注「待建」，不承诺本批 UI/配置。

## 二、历史数据多源（本方案主体）

### 2.1 抽象 + 归一化（✅ 已做 + 待补归一化）

`BaseDataAdapter` 已做：`pull_daily`/`pull_minute`/`to_bar_rows`（11 字段唯一出口）+ 能力方法。mapper 三合一已编码（金标准兜底）。

**待补：归一化（预留多源）**——加 4 个带默认实现的方法（Tushare 直通，聚宽/米筐覆写）：

```python
def to_source_symbol(self, symbol) -> str: return symbol   # pull 边界收 ts_code ↔ 源格式（.SH↔.XSHG）
def to_source_freq(self, freq) -> str: return freq         # '1min' ↔ '1m'
def to_source_adj(self, adj) -> str | None: return adj     # 'pre' ↔ 'qfq'
def from_source_symbol(self, src) -> str: return src       # 源格式 → vt_symbol（存储态）
```

**11 字段契约钉死（盲审 A-P1-2/B-P1-2，数据正确性根本）**：
- `volume = 股`、`amount = 元`——**各源在 `to_bar_rows` 内换算**（Tushare vol 手×100、amount 千元×1000；聚宽/米筐本就元/股，直通）。**不信任各 adapter 自觉，`to_bar_rows` 收口强制转换**。
- `ts` 归一到 **A 股 +08:00 naive datetime**（统一时区，跨源不错位）。
- 存储态唯一真值 = `vt_symbol`（SHSE/SZSE/BSE）；pull 边界收 `ts_code`（来自静态表）。

### 2.2 限速抽象聚合（25 号，待编码）

`RateLimitPolicy` 策略模式替代「四层覆盖」：
- `FixedIntervalPolicy`（Tushare：间隔秒，类默认 + DB 覆写两级）
- `DailyQuotaPolicy`（聚宽/米筐：每日额度）——**语义注明**：`86400/N` 平均间隔是**下界近似**（防超不防 burst，under-utilize）；「日上限硬顶 + 当日计数」留真接批补。
- `DataSource` 持 policy，`get_rate_limit` 委托。
- **去掉**：`POINTS_PRESETS` 积分档、`points_tier` 层、`rate_time_overrides` 时段乘数。

**engine 限速 ds 按 provider 路由（盲审 A-P1-3，24 号已编码的遗留 bug）**：`rate_limit_context` 的 ds 现在硬编码 `get_data_source("tushare")`，切 provider 后限速/熔断错源。改为 `get_data_source(provider) fallback tushare`，breaker key 用真实 provider。

**去积分档前置（盲审 A-P1-4/B-P1-4）**：批 A 编码前盘点生产 `data_source_config.params` 现值，若有 `points_tier`/`rate_time_overrides`，迁移等价到 `rate_limits` 覆写档 + 补「限速值等价」回归（防 stk_mins 从 0.3s 退化 3600s）。

### 2.3 能力矩阵 + 同步项级 provider + 切换重建（待编码）

- **能力声明 = adapter 类属性派生**（盲审 A-P2/B-P2：不用 DB JSON，双真相源会漂移）：`BaseDataAdapter.capabilities: set[str]`（该平台能提供的 sync_id），供给矩阵读注册表。
- **能力矩阵只列真正 adapter 路由的 sync_id（K 线五类）**（盲审 A-P1-5/B-P1-1）：`astock_daily`/`etf_daily`/`cb_daily`/`astock_minute`/`astock_minute_5min`。静态/日历/三档硬编码 `_get_pro`（Tushare 专属），**明确标注 Tushare-only 不可选**。
- **同步项级 provider**：`sync_config.provider`（已加列），每同步项单选。
- **标的集分流（改正事实）**：靠 **6 位代码段不重叠**（510xxx 基金 / 600xxx 股票 / 11-12x 转债），非后缀。**补测试断言三 kind 代码段互斥固化前提**；若未来发重叠段，`ON CONFLICT DO NOTHING` 静默丢数据 → 加代码段冲突告警。
- **切换重建完整流程**（盲审 A-P2/B-P2）：
  1. `delete-by-sync_item`（全量删该同步项标的，**新增原语**，非 per-symbol）
  2. 重置 `last_sync_date` 游标
  3. full 回填（含 adj_factor 按新源清空+回填，盲审 A-P1-6）
  4. 校验 source 一致性
  5. 幂等可重入（中断重跑）
