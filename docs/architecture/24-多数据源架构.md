# 24 - 多数据源架构（历史 K 线数据源无关化）

> 状态：方案 v3（两轮盲审修订）。本文=八步法步 1 设计稿。
> 对标 vnpy `BaseDatafeed`。亮点=任务级 provider 路由。

## 一、目标

历史 K 线数据源可插拔：加聚宽/米筐 = 实现 adapter 类 + 注册 + DB 配 `provider`。**Tushare 默认路径输出逐字节不变**（金标准测试兜底）。

## 二、抽象分层（厘清与 DataSource 的关系，复审 B-P1-5）

**两层职责分明，adapter 组合 DataSource，不重复不继承**：

| 层 | 抽象 | 职责 |
|---|---|---|
| 连接/治理 | `DataSource`（已有，data_source.py） | token 解密、限速（rate_limit_context）、熔断、用量（record_usage） |
| 拉取/映射 | `BaseDataAdapter`（新增） | K 线拉取 + 字段映射到 11 字段；**内部持 DataSource 做限速/熔断/用量** |

- `BaseDataAdapter` **不定义 get_client/get_rate_limit**（那是 DataSource 的），只定义拉取+映射。
- adapter 内部 `self.ds = get_data_source(provider)`，限速用 `rate_limit_context(self.ds, api)`。
- 消除 v2 的「`_ADAPTERS` vs `_REGISTRY`」「两套 pro 实例」重叠：**pro 实例统一走 DataSource**，tushare_adapter 的模块级 `get_pro()` 废弃（engine 路径改走 DataSource 注入的 client）。

## 四、核心设计

### 4.1 BaseDataAdapter 接口（per-symbol 核心，batch 能力方法）

```python
class BaseDataAdapter(ABC):
    provider: str = ""

    @abstractmethod
    def pull_daily(self, symbol: str, start: str, end: str, adj=None) -> pd.DataFrame:  # per-symbol 日线
    @abstractmethod
    def pull_minute(self, symbol: str, freq: str, start: str, end: str) -> pd.DataFrame:  # per-symbol 分钟
    @abstractmethod
    def to_bar_rows(self, df: pd.DataFrame, freq: str, adj_map: dict | None = None) -> list[tuple]:
        """**唯一** 11 字段生产点。source=self.provider；adj_map 注入 adj_factor（None=缺省）。
        freq='1D' 读 trade_date 列、freq 含 min 读 trade_time 列（内部分支）。"""

    def pull_daily_batch(self, trade_date: str, kind: str) -> pd.DataFrame:
        """按日全市场批量（Tushare pro.daily/fund_daily 专属）。默认 raise UnsupportedFeature。"""

    def pull_adj_factor(self, symbol=None, trade_date=None) -> pd.DataFrame:
        """复权因子。默认返回空 DataFrame（因子缺省 NULL）。"""
```

**11 字段契约**：`(symbol, freq, ts, open, high, low, close, volume, amount, adj_factor, source)`；source=provider；未复权价+逐行因子。

### 4.2 mapper 三合一（复审 A-C/B-P0-2 残留）

`_daily_to_rows`（engine）+ `to_save_rows`（日）+ `to_save_rows_min`（分钟）**三个 mapper 全部删除**，统一 `adapter.to_bar_rows`。cb_daily/index/分钟/断点补采/on-demand 全走它，`source` 只此一处注入。

### 4.3 engine 改造

- `_get_pro` 拆 `_get_tushare_pro`（B 表）+ `_get_kline_adapter(cfg)`（A 表）
- `_sync_by_trade_date` 也拆（复审 B-P1-4）：K 线（astock_daily/etf_daily）传 adapter 方法；非 K 线（astock_basic）仍传 Tushare `pro.daily_basic`，共享函数不改 provider 语义、由调用方传对
- per-symbol 路径 `_get_pro_api` 返回 adapter（非 bound method），调用点 `api_fn(ts_code=,start_date=,end_date=)` 改 `adapter.pull_daily(symbol, start, end)` / `pull_minute`
- 限速 `rate_limit_context` 用 adapter 的 `self.ds`

### 4.4 symbol 格式（复审 A-E/B-2）

本批 symbol 仍 `ts_code`（Tushare 专属 `.SH/.SZ`），**聚宽/米筐的 `.XSHG/.XSHE` 转换留真接批**（stub 不实现，记风险）。换源（真接时）需在 adapter 内做 symbol 归一化（源格式↔ts_code）。

### 4.5 换源运维（A-P1-6/B-P1-2）

换 provider = `delete_symbol` 重建 + 文档化 + 验收用例（bar 唯一键 `(symbol,ts)`，source 不在键内，换源旧行被 DO NOTHING 跳过）。

## 七、回滚

单 commit 原子；provider 默认 'tushare'；TushareAdapter 是 mapper 三合一收编（金标准双比对兜底逐字节一致），非 K 线零改动。

## 八、风险与边界

1. **本批不做**：静态/日历/三档 adapter 化、限速配额型、主备降级、cb_daily 区间拉取的 adapter 化（换源走 per-symbol 降级）、symbol 格式转换（真接聚宽批）。
2. **stub 不接真源**：真接需装 SDK + 字段映射（money元/total_turnover/fq=None）+ symbol 归一化。
3. **效率降级**：cb_daily 换源（聚宽）从全市场区间拉到 per-symbol 循环，~800 只逐只，文档化。
4. **越界回步 1**：只动「K 线拉取+映射+复权因子+限速」，不碰静态/日历/三档 handler。
