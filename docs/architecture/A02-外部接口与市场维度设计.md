## 一、核心立法(三句话)

1. **行的边界=账号(连接身份)**——外部接口配置表(external_interface)一行=一个可独立认证的连接身份(XTP 账号/tushare token/腾讯无凭证公开接口)。端点是配置的**字段**(md_*/td_*),不是配置的行。
2. **列的语义=能力(capabilities)**——每行标注能力子集({daily}/{minute,snapshot}/{trading,quote});配置能力恒 ⊆ 代码能力(adapter 实现),写侧校验+漂移告警。
3. **页签=能力过滤视图**——「数据源」页签=能力∩{daily,minute,snapshot,quote}≠∅ 的行;「交易账号」=能力∋trading。多能力接口(XTP=交易+行情/腾讯=历史分钟+实时快照)**单份配置多处可见,不被页签撕两半**。

**消解的紧耦合谬误**:按"历史/实时/交易"拆配置=把同一账号身份拆多处(凭证复制漂移);系统区分业务选不同服务器=**运行时会话路由**(hub 读 quote 能力行建 MD 连接/下单走 trading 建 TD),发生在消费侧,不要求配置侧拆分。

## 二、维度栈(五层,注册表单源 quant_common/markets.py)

```
市场 market(A股/加密——交易结算域:货币/监管/时段体系)
 └─ 交易所 exchange(SHSE/SZSE/BSE;BINANCE/OKX)——场所
     └─ 板块 board(暂不建实体——涨跌停等规则以交易所属性承载,校验接线属风控批)
         └─ 品类 category(资产品类 stock/etf/convertible/fund/reits/perp;数据品类 daily/minute/snapshot/quote)
供应商 provider(Tushare/腾讯/XTP/币安/OKX)——独立正交维度:能力覆盖=供应商×市场×品类矩阵
```

- **交易所覆盖用 `exchanges text[]` 包含式集合**(NULL=注册表全所)——单一机制,排除式(excluded)退役。
- **权限五键三分混一的立法化解**:MARKET_OP_DECOMP(market_op 五键→(market, category, venue) 无损映射)——astock=市场/etf·convertible=品类/binance_perp=供应商×品种的混用在注册表层显式化,权限键本身不动。

## 三、能力模型

- **能力真源=代码**:`adapter.capabilities`(sync_id 复合串,如 astock_daily)经 `SYNC_ID_CAP_MAP` 归一为配置层枚举;无 adapter 的通道(tencent 快照/xtp 网关)走 `NON_DATA_PROVIDERS` 直标。
- **配置列=用户启用子集**:`check_capability_subset()`(data_platform/capabilities.py)写侧校验越集 400+启动/GET 漂移告警(批33b 防漂移闸同模式)——同时解决"能力时间有效性"(积分涨跌/供应商覆盖变化)。
- **能力枚举=系统消费粒度,非供应商目录**:tushare 百余接口只登记系统消费的(daily/minute);未实现的能力物理上标不进(⊆校验),枚举永不爆炸。
- 未来接基本面:adapter 实现→注册表加 fundamental→配置行更新启用,页签零改。

## 四、分层与守门

- 注册表(纯数据)在 **quant_common(层 0)**;能力查询/校验(读 _ADAPTERS)在 **data_platform(数据层)**——层 0 禁 import 上层(test_layering 铁律,55-0 实证被守门抓过一次)。
- 前端 **ChannelTableShell** 壳(拖拽手柄列+reorder 乐观重排)为通道表格通用层;弹窗不抽(凭证/枚举异构真实)。

## 六、不并入的边界

短信/邮件/LLM 页签**不并入**外部接口表——通知与辅助服务,无市场/交易语义,凭证体系异构;合并它们=另一种紧耦合。

## 七、配置存放立法(2026-09-19 用户裁定)

**`.env` 只放加密密钥**(SECRET_KEY/ENCRYPTION_KEY——加密体系本体);**其他所有配置入库**,敏感值用密钥加密后入库(credentials_encrypted/api_key_encrypted 列,Fernet)。

- **鸡生蛋例外**(留 .env):QUANT_DB_URL/VALKEY_URL/CELERY_BROKER_URL/CELERY_RESULT_BACKEND——读库/消息层/celery 进程启动即需,先于 DB 可用。
- 代码侧 `.env` fallback 读点(TUSHARE_TOKEN/XTP_TEST_*/SMTP/LARK/LLM)保留为韧性路径——立法落在**清 .env 值**而非删代码;.env 无值后 fallback 永不命中,配置缺失以连接失败显性暴露。
- 迁移次序铁律:**先建库行(含加密凭证)验证生效,再清 .env 值**——顺序反了断服务。
