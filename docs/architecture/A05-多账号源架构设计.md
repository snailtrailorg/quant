## 一、定位与边界

### 1.1 一句话锚点

一个策略绑一个交易账号；行情来自该账号所属市场、下单走该账号柜台，成交/持仓/资金与该账号对得上。

### 1.2 平台定位

**个人小资金多账号平台**（非机构级）。用户持多个交易账号，每个账号品种权限不同（创业板/北交所/主板等），不想也无法整合成一个账号。

### 1.3 责任三层分离

| 层 | 内容 | 本方案 |
|---|---|---|
| 软件稳定性 | 单子下得对不对、行情对不对、进程稳不稳 | ✅ 负责 |
| 交易可靠性 | 费率对账 / 资金隔离 / 账户级敞口 | ✅ 负责（三样，见 §六） |
| 监管合规 | 举牌/一致行动人/减持/要约/税务/报备/反洗钱 | ❌ 不实现（见 §七出界清单） |

原则：被砍的全落第三层，与「单子下得对不对」无关；保留的三样本质是「把账算对」，即使没有法条也得做。

## 二、核心抽象

### 2.1 Venue = 交易账号

- 一个 `external_interface` 行 = 一个交易账号 = 一个 **Venue**（不是「券商」：同券商多账号 = 多个 Venue）。
- A股 provider = `xtp` / `emt_emq`；加密 provider = `binance_perp` / `okx_perp`。
- 身份锚点：内部 `venue_id`（FK）+ **稳定语义键**（新列、UNIQUE）。语义键独立于 row_id——删行重建不换语义键、历史不断。语义键取值来源（XTP「资金账号」vs「股东账号」，沪/深各一）是 D2 首决，本稿只钉「必须存在且唯一」。
- 下单/查询链路同样 per-venue：TD 网关/适配器**按 venue 的 provider+凭证构建**，禁硬编码 XTPAdapter 或全局单例（否则 A 任务下单落到 B 账户——见 §五契约 9）。

### 2.2 同源分市场边界

| 市场 | MD 行情 | TD 交易 |
|---|---|---|
| A股 | **单 hub**（L1 全市场同源；保留 doc14 M5 单活双实例，不退役、不 per-venue） | **per-venue**（成交/持仓/资金必须来自实际交易券商） |
| 加密 | **per-venue** | **per-venue** |

理由（A股为何 MD 单 hub）：A股 L1 由交易所统一编制、各券商转发同一份快照（内容一致、仅毫秒级转发时延差），且策略分钟级低频——拆 N 个 hub 只换来毫秒级时延差消除（对分钟级策略无意义），代价是 N 份租约/监控/deploy 改造面 + N-1 个故障点（某 venue 的 MD 掉线 → 其 worker 被闸卡死整天，即使另一 venue 有完全相同的行情）+ N 份订阅浪费。加密 per-venue（mark/index/funding 交易所特定）同理成立。

### 2.3 同源校验 = 跨进程运行时事实

同源校验是**跨进程运行时事实校验**，不是「从同一行派生两个值再比」（空转断言，永远相等、抓不到绑错）：

- **A股 MD 单 hub**：无 venue 维度，无同源风险（全市场同源，所有 venue 共享同一份行情）。
- **加密 MD/TD per-venue**：流消息带 `venue_id` 字段，worker 比对 `int(fields["venue_id"]) == venue.id`，不符即 fail-fast。

## 三、权限模型（三维正交：category / exchange / board）+ ST 子布尔（仅主板）

| 维度 | 取值 | 真源 | 生效范围 |
|---|---|---|---|
| category | stock / etf / convertible / fund / reits / perp | `security_master.category`（已有列，不用代码前缀） | 全品种 |
| exchange | SHSE / SZSE / BSE（股东户维度） | `security_master.exchange`（**已有列**，迁移 0092 填充链从 ts_code 后缀落库，非前缀判断）；venue 侧=该 venue 股东户/交易所开通情况 | 仅 stock |
| board | main / star / chinext / bse（CDR→star） | `asset_static_info.market` 中文文本归一化→**新增 `security_master.board` 枚举列**（D1 首决：否决复用 market 列） | 仅 stock |
| ST | is_st 布尔（**board=main 子状态，非独立维度**） | `security_state` kind='st'（判定布尔须官方名单 fail-closed，见 §四）；venue 侧=`venue_permission` 的 is_st 允许布尔 | 仅 board=main（科创/创业/北交 ST 涨跌幅与非 ST 同，无独立权限，归排除提示） |

- **标的侧真源**（上表）之外，还需**venue 侧权限存储**：`venue_allows(venue, symbol)` 依赖 venue→(允许 category 集合 + 允许 exchange 集合 + 允许 board 集合 + is_st 允许布尔（仅主板）+ 可转债权限 + 加密分项) 的映射，其存储位置（external_interface 加列 / 新表 / 扩 live_trading_config）是 D1 首决——本稿只钉「必须有一处 venue 侧权限存储契约」。
- 校验顺序：category → exchange → board →（board=main 且 is_st 时）ST → 分项；`etf/fund/reits` 跳过 exchange+board；`convertible`→可转债权限（10 万+2 年）；`perp`→加密分项 gate。**exchange 是股东户维度（沪/深/北）**，board=main 横跨沪/深，需 exchange 兜底细分。**ST 不是独立维度**：涨跌幅已由 `band_rules.pct_st` 覆盖（主板 ±5%），适当性=venue_permission 的 is_st 布尔，退市风险=选标的排除提示。
- 三级时点：①建任务拒绝 ②worker 启动 fail-fast ③下单前拦截。
- 权限人工配置，券商柜台兜底（平台校验是最快拒绝，不是最终放行）。
- 出界（不加维度，收进 §七）：港股通 ETF、两融账户、可转债转股/回售（操作）、北交所 ST 口径。

## 四、数据字段化（退役前缀判断）

board/category 落 `security_master` 列作单一真源，退役 `_board_of`（板块）/ `detect_category`（品类）前缀判断；**`_market_of`（分项 market_op 五键）是另一维度，不退役**（etf 分项=场内基金全体、perp 分项需 venue.provider 区分，与 category 拆分 etf/fund/reits 不同构，退役即下单闸断裂）。

- 现状（已核实，三函数算三维度）：`security_master` 有 `category` 列和 `market` 列（market=astock|crypto，非中文板块），无 `board` 列；板块由 `security_master.py:246 _board_of(vt_symbol)`（仅被竞价/时段 applicable_phases/is_auction 调用）、品类由 `factor.py:719 detect_category`（因子路径）、分项由 `risk.py:175 _market_of`（check_order 分项 gate）分别从代码前缀算——三者不是同一维度。
- 失败模式：fail-open=歧义越权、fail-closed=要枚举主板段集还是千年虫——两条都是死路。
- **board 归一化**：`asset_static_info.market` 中文文本值→board（主板→main / 创业板→chinext / 科创板→star / 北交所→bse / CDR→star），新增 `security_master.board` 枚举列（D1 已裁定，非复用 market 列）。
- **is_st 判定（board=main 子布尔，非独立维度）**：现由曾用名含「ST」派生（戴帽/摘帽有滞后）——D1 定为官方名单（交易所公告）+ 失效兜底 fail-closed。「下错单」风险本质=主板涨跌幅 ±5%（`band_rules.pct_st` 已覆盖）+ 退市风险（选标的排除），权限层只需 is_st 布尔。
- **价格/状态事件字段**：强赎（forced_redeem）与退市整理期是**时变状态**，前缀判不出，须落字段（如 `security_state` kind 扩展），支撑选标的排除——见 §七（强赎/退市整理期不是「边角操作」，是数据字段化范围）。
- 前提：board 回填须先于校验闸启用。

## 五、契约（稳定语义契约）

> 这些是「交易正确性不变量」，是架构层必须钉死的语义；落实到哪些文件是编码阶段 grep+人工审计双轨的事（§八）。

1. **Venue 身份**：`live_task.venue_id BIGINT NOT NULL REFERENCES external_interface(id) ON DELETE RESTRICT`；稳定语义键为**新列**（`UNIQUE(provider, account_key)` 复合唯一，取值来源 D2 首决：XTP 资金账号 vs 股东账号）；`delete_interface` 守卫与 FK 同版本（防静默级联删实盘任务）。

2. **流/心跳/租约键**：
   - A股（单 hub，无 venue 维度）：`hub:bars:{symbol}` / `quant:hb:md-hub` / `hub:lease`
   - 加密（per-venue）：`hub:bars:{venue_id}:{symbol}` / `quant:hb:md-hub:{venue_id}` / `hub:lease:{venue_id}`
   - 加密**历史暖机/回放**也按 venue 分源（币安数据不得喂 OKX 任务），与实时流同源。

3. **同源运行时校验**（per-venue 流）：hub 写流带 `"venue_id"` 字段；worker `int(fields["venue_id"]) == venue.id`（decode_responses 读出是 str，须 int 转换 + try/except fail-fast，否则每条 bar 误判跨源 exit 78）。

4. **权限校验**：`venue_allows(venue, symbol) -> bool`，判定顺序 category 先于 board，三级时点见 §三；依赖**venue 侧权限存储**（D1 首决，见 §三）。

5. **数据字段**：`security_master.category`（已有）+ `board`（market 归一化，复用或加列只留一处真源）+ `security_state(kind='st'/'forced_redeem'…)`（官方名单 fail-closed）；board 回填先于校验闸。

6. **账户/持仓快照 per-venue**（交易正确性；已核实实际 schema）：
   - `position_snapshot` 已多行、已有 `account_id TEXT` 主键 → **语义统一为 `venue_id BIGINT FK`**（改名+类型转换+回填）；
   - `account_snapshot` 现为单行全局 → **新增 `venue_id` 列 + 多行化**；
   - 读写方均按 venue 过滤：下单量（strategy.py）、敞口（risk.py）、资金基线读方 per-venue，否则混仓；
   - **写侧**：`initial_capital`/资金基线按 venue 的来源与写入路径须钉死（现来自策略级默认 100 万，无 per-venue 来源）。

7. **身份线统一**：`live_task.account_id` / `position_snapshot.account_id` / `position_refresh.account_id` → `venue_id`；`strategy_account` 退役——其 `leverage`/`initial_capital` 列的去向须在 D2 落位（leverage 是保证金实参）；对账路径（trade_log / order_log / `/api/reconcile`）per-venue——**实质是 order_log/trade_log 加 `venue_id` 列 + 回填**（现只有 strategy_id，且 strategy_id→venue 无唯一约束），否则 A 任务成交归因到 B 账户。

8. **选源**：TD 人工显式选源（建任务 Web 选 venue_id）；建任务候选收窄到 **enabled + capabilities ∋ trading**（加密 venue 无 `quote` 能力，不得用 trading+quote 收窄）。

9. **TD 网关 per-venue 构建**：TD 网关/适配器按 venue 的 provider+凭证构建，禁硬编码 XTPAdapter / 全局单例；`query_position` / `query_account` / `order` / 对账全走该 venue 会话。XTP 每日连接窗只套 A股 XTP，EMT/加密不套（分支在 D5 定义）。

## 六、金融面（只做交易可靠性三样）

1. **资金隔离**：每 Venue 独立记账。
2. **账户级敞口**：同 Venue 同标的同向合并，读写方 per-venue；**同标跨账户反向持仓（自己两个 venue 对敲）须显式处置**（落敞口约束或 §七出界声明）。
3. **费率对账**：印花税（卖出 0.05%）+ 过户费（0.001%）+ 佣金；可转债/场内基金免印花；加密资金费 + maker/taker + USDT→CNY。

## 七、出界清单（不实现）

**机构监管合规**（个人平台层面砍掉）：举牌 5%、一致行动人、减持、要约线、增值税/企业所得税（个人买卖股票免）、程序化报备（券商侧办理，非平台软件功能）、反洗钱/外汇（加密本就不合规，不做声明）。

**选标的排除（金融边角，非权限校验维度）**：港股通 ETF、两融账户、加密合规（用户自担）。

**品类差异化操作（预留扩展点，非出界）**：可转债转股/回售、ETF/LOF 申赎等品类专属**操作**当前不实现，但架构预留「品类操作插件」扩展点——品类差异 = 数据列（属性，D1 落 category/exchange/board）+ 插件（操作，未来新增品类/操作不改顶层代码），对标「通用能力中心化、差异化能力插件化」。

**数据字段化范围（不是排除，是 §四落字段支撑排除）**：强赎（价格向赎回价塌陷的事件）、退市整理期股票。
