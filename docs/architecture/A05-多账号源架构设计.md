## 一、定位与边界

### 1.1 一句话锚点

一个策略绑一个交易账号；行情来自该账号所属市场、下单走该账号柜台，成交/持仓/资金与该账号对得上。

### 1.2 平台定位

**个人小资金多账号平台**（非机构级）。用户持多个交易账号，每个账号品种权限不同（创业板/北交所/主板等），不想也无法整合成一个账号。

### 1.3 责任三层分离

| 层 | 内容 | 本方案 |
|---|---|---|
| 软件稳定性 | 单子下得对不对、行情对不对、进程稳不稳 | ✅ 负责 |
| 交易可靠性 | 费率对账 / 资金隔离 / 账户级敞口 | ✅ 负责（三样，见 §六） |
| 监管合规 | 举牌/一致行动人/减持/要约/税务/报备/反洗钱 | ❌ 不实现（见 §七出界清单） |

原则：被砍的全落第三层，与「单子下得对不对」无关；保留的三样本质是「把账算对」，即使没有法条也得做。

## 二、核心抽象

### 2.1 Account 语义与系统身份（批189 修订）

- **业务语义**：一个物理交易账号 = 一个 Account（同券商多账号=多个）。**系统身份**不再用账号行：交易接口 `trade_interface.code` 是下单/持仓/成交的身份，行情接口 `market_interface.code` 是行情的身份；同一物理账号的 MD/TD 是两行两进程，凭证独立。
- 三层关系：物理账号（业务概念）→ 交易接口（`td-*`）→ 任务/订单/持仓（`account_code` FK）。
- A股 provider = `xtp` / `emt_emq`；加密 provider = `binance_perp` / `okx_perp`。
- 身份锚点：**交易接口 `code`（不可改、全局唯一）**；`account_key` 保留为物理账号语义键（同券商同账号的 MD/TD 共享，用于租约归并）。删行重建=新 code，历史按软删保留（D11）。
- 下单/查询链路按**交易接口**：TD 网关按该接口 provider+凭证构建，禁硬编码 XTPAdapter 或全局单例（否则 A 接口下单落到 B 接口——见 §五契约 9）。

### 2.2 同源分市场边界

| 市场 | MD 行情 | TD 交易 |
|---|---|---|
| A股 | **per-interface**（行情接口一 hub、交易接口一 exec；MD/TD 凭证与启停独立） | **per-interface**（成交/持仓/资金必须来自实际交易券商） |
| 加密 | **per-interface**（公开行情接口一 hub，无需账户凭证） | **per-interface**（开户后交易接口一 exec） |

拓扑统一理由（全市场唯一形态=实例化，详 `D26-市场接入架构.md` §零五理由；批189 由账号级细化为接口级）：分支税（双形态 10+ 处分支是多个历史 bug 的根因）/故障域=账号域（单 hub=全平台单点）/跨账户 bar 微差在双时态语义下属 best-effort 可接受（对账锚=PG 盘后回补）/底座同质化（hub 从共享基础设施退化为账号附属进程，代码路径唯一）/M5 互备体系随统一拓扑整体退役（无多实例抢一键空间场景）。哲学：逻辑越简洁代码质量越高，资源不足加配置。

### 2.3 同源校验 = 跨进程运行时事实

同源校验是**跨进程运行时事实校验**，不是「从同一行派生两个值再比」（空转断言，永远相等、抓不到绑错）：

- **全市场统一**：流消息带 `account` 字段（MD code），worker 按本任务映射的 MD code 比对，不符即 fail-fast（无按市场跳过分支）。

## 三、权限模型（三维正交：category / exchange / board）+ ST 子布尔（仅主板）

| 维度 | 取值 | 真源 | 生效范围 |
|---|---|---|---|
| category | stock / etf / convertible / fund / reits / perp | `security_master.category`（已有列，不用代码前缀） | 全品种 |
| exchange | SHSE / SZSE / BSE（股东户维度） | `security_master.exchange`（**已有列**，迁移 0092 填充链从 ts_code 后缀落库，非前缀判断）；account 侧=该 account 股东户/交易所开通情况 | 仅 stock |
| board | main / star / chinext / bse（CDR→star） | `asset_static_info.market` 中文文本归一化→**新增 `security_master.board` 枚举列**（D1 首决：否决复用 market 列） | 仅 stock |
| ST | is_st 布尔（**board=main 子状态，非独立维度**） | `security_state` kind='st'（判定布尔须官方名单 fail-closed，见 §四）；account 侧=`account_permission` 的 is_st 允许布尔 | 仅 board=main（科创/创业/北交 ST 涨跌幅与非 ST 同，无独立权限，归排除提示） |

- **标的侧真源**（上表）之外，还需**account 侧权限存储**：`account_allows(account, symbol)` 依赖 account→(允许 category 集合 + 允许 exchange 集合 + 允许 board 集合 + is_st 允许布尔（仅主板）+ 可转债权限 + 加密分项) 的映射，其存储位置是 D1 首决——本稿只钉「必须有一处 account 侧权限存储契约」；**批189 起该存储锚 `provider_session_slot.login_key`（物理账号），不挂已删除的 `trading_account`**。
- 校验顺序：category → exchange → board →（board=main 且 is_st 时）ST → 分项；`listed_fund/fund/reits` 跳过 exchange+board；`convertible`→可转债权限（10 万+2 年）；`perp`→加密分项 gate。**exchange 是股东户维度（沪/深/北）**，board=main 横跨沪/深，需 exchange 兜底细分。**ST 不是独立维度**：涨跌幅已由 `band_rules.pct_st` 覆盖（主板 ±5%），适当性=account_permission 的 is_st 布尔，退市风险=选标的排除提示。
- 三级时点：①建任务拒绝 ②worker 启动 fail-fast ③下单前拦截。
- 权限人工配置，券商柜台兜底（平台校验是最快拒绝，不是最终放行）。
- 出界（不加维度，收进 §七）：港股通 ETF、两融账户、可转债转股/回售（操作）、北交所 ST 口径。

## 四、数据字段化（前缀判断 → 列真源）

board/category 落 `security_master` 列作单一真源（前缀判断 `_board_of`/`detect_category` 已移除）；**`_market_of`（分项 market_op 五键）保留**——它是另一维度：etf 分项=场内基金全体、perp 分项需 account.provider 区分，与 category 拆分 etf/fund/reits 不同构，若随之前缀判断一并移除会断裂下单闸。

- 现状（已核实，三函数算三维度）：`security_master` 有 `category` 列和 `market` 列（market=astock|crypto，非中文板块），无 `board` 列；板块由 `security_master.py:246 _board_of(vt_symbol)`（仅被竞价/时段 applicable_phases/is_auction 调用）、品类由 `factor.py:719 detect_category`（因子路径）、分项由 `risk.py:175 _market_of`（check_order 分项 gate）分别从代码前缀算——三者不是同一维度。
- 失败模式：fail-open=歧义越权、fail-closed=要枚举主板段集还是千年虫——两条都是死路。
- **board 归一化**：`asset_static_info.market` 中文文本值→board（主板→main / 创业板→chinext / 科创板→star / 北交所→bse / CDR→star），新增 `security_master.board` 枚举列（D1 已裁定，非复用 market 列）。
- **is_st 判定（board=main 子布尔，非独立维度）**：现由曾用名含「ST」派生（戴帽/摘帽有滞后）——D1 定为官方名单（交易所公告）+ 失效兜底 fail-closed。「下错单」风险本质=主板涨跌幅 ±5%（`band_rules.pct_st` 已覆盖）+ 退市风险（选标的排除），权限层只需 is_st 布尔。
- **价格/状态事件字段**：强赎（forced_redeem）与退市整理期是**时变状态**，前缀判不出，须落字段（如 `security_state` kind 扩展），支撑选标的排除——见 §七（强赎/退市整理期不是「边角操作」，是数据字段化范围）。
- 前提：board 回填须先于校验闸启用。

## 五、契约（稳定语义契约）

> 这些是「交易正确性不变量」，是架构层必须钉死的语义；落实到哪些文件是编码阶段 grep+人工审计双轨的事（§八）。

1. **任务身份**：`live_task.account_code TEXT NOT NULL REFERENCES trade_interface(code) ON DELETE RESTRICT`；接口 code 不可改（改名=新身份）；删除走软删（`retired_at`），有历史禁物理删（D11）。

2. **流/心跳/租约键**（批189 起身份=接口 code）：
   - `hub:bars:{md_code}:{symbol}` / `iface:hb:md:<md_code>` / `hub:lease:{md_code}`；TD 侧 `td:cmd:{td_code}` + `iface:hb:td:<td_code>`
   - **历史暖机/回放**按接口分源（币安数据不得喂 OKX 任务），与实时流同源；TD 侧 `td:cmd:{td_code}` / `td:exec:{td_code}`。

3. **同源运行时校验**：hub 写流带 `"account"` 字段（MD code）；worker 比对 `fields["account"] == 本任务映射的 md_code`，不符即 fail-fast。

4. **权限校验**：`account_allows(account, symbol) -> bool`，判定顺序 category 先于 board，三级时点见 §三；依赖**account 侧权限存储**（D1 首决，见 §三）。

5. **数据字段**：`security_master.category`（已有）+ `board`（market 归一化，复用或加列只留一处真源）+ `security_state(kind='st'/'forced_redeem'…)`（官方名单 fail-closed）；board 回填先于校验闸。

6. **账户/持仓快照按交易接口**（批189）：
   - `position_snapshot/position_refresh/account_snapshot` 的 `account_code TEXT` FK→`trade_interface(code)`；主键/唯一约束含 `account_code`；
   - 读写方按 `account_code` 过滤（下单量/敞口/资金基线），否则混仓；
   - 写侧 `initial_capital` 基线按 trade interface 取首条快照（不再用策略级默认）。

7. **身份线统一（批189）**：`live_task/position_snapshot/position_refresh/account_snapshot/order_log/trade_log` → `account_code TEXT` FK→`trade_interface(code)`；**`account_permission` 锚 `login_key`（物理账号权限，不随 TD 行）**；`data_source_usage.interface_id`→`ds-*` code。对账按 code 归因，禁止数字 id。

8. **选源**：建任务显式选**交易接口 code**；候选=有 `execution` 载体的交易接口（与 SA4 同源）。`enabled=false` 仍可被绑定但进程空转，页面标注。

9. **TD 网关 per-account 构建**：TD 网关/适配器按 account 的 provider+凭证构建，禁硬编码 XTPAdapter / 全局单例；`query_position` / `query_account` / `order` / 对账全走该 account 会话。XTP 每日连接窗只套 A股 XTP，EMT/加密不套（分支在 D5 定义）。

## 六、金融面（只做交易可靠性三样）

1. **资金隔离**：每 Account 独立记账。
2. **账户级敞口**：同 Account 同标的同向合并，读写方 per-account；**同标跨账户反向持仓（自己两个 account 对敲）须显式处置**（落敞口约束或 §七出界声明）。
3. **费率对账**：印花税（卖出 0.05%）+ 过户费（0.001%）+ 佣金；可转债/场内基金免印花；加密资金费 + maker/taker + USDT→CNY。

## 七、出界清单（不实现）

**机构监管合规**（个人平台层面砍掉）：举牌 5%、一致行动人、减持、要约线、增值税/企业所得税（个人买卖股票免）、程序化报备（券商侧办理，非平台软件功能）、反洗钱/外汇（加密本就不合规，不做声明）。

**选标的排除（金融边角，非权限校验维度）**：港股通 ETF、两融账户、加密合规（用户自担）。

**品类差异化操作（预留扩展点，非出界）**：可转债转股/回售、ETF/LOF 申赎等品类专属**操作**当前不实现，但架构预留「品类操作插件」扩展点——品类差异 = 数据列（属性，D1 落 category/exchange/board）+ 插件（操作，未来新增品类/操作不改顶层代码），对标「通用能力中心化、差异化能力插件化」。

**数据字段化范围（不是排除，是 §四落字段支撑排除）**：强赎（价格向赎回价塌陷的事件）、退市整理期股票。
