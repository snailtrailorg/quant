> **智能体按需读取——不全部读。** 状态/进度的单一真相源在 `flow/待办.md` 与 `flow/进展.md` 顶部一条；本文只回答「要做什么读什么」。`A01-总体设计` 是全貌（新会话先读它 §3/§4 建立地图，再按下表钻取）。

## 文档体系五层

| 目录 | 定位 | 内容 |
|---|---|---|
| `docs/architecture/` | 架构级真相 | 总体方案（A01-A05）+ 跨模块契约（接口契约 + 模块契约 19 份） |
| `docs/design/` | 模块设计 + 横切规范 | 各模块设计（D01-D19）+ 数据域设计（D20-D23）+ web 设计系统（D24）+ 未完成任务执行规格（批 61/62/63） |
| `docs/manual/` | 操作手册 | 面向使用者（因子/策略/回测/实盘/数据源切换，Web 内置 /help 同步） |
| `docs/reference/` | 外部资料 | 第三方 SDK/协议/客户竞品（非本项目原创） |
| `docs/obsolete/` | 过时归档 | 已废弃/已吸收的文档 + 已完成任务文件（保留历史不删除） |

## 状态注记约定

- 每份文档**头部 blockquote 记录重大变更注记**（含日期 + 原编号）；批次类状态（进行中/✅）一律指向 `flow/待办.md`，不在架构文档里重复维护计数。
- 设计文档描述「为什么与是什么」；代码签名以模块契约为准；两者矛盾时**以代码+契约为准并回写本文档**。
- 已废弃/已吸收文档移 `docs/obsolete/`（清单见其 README）；外部参考在 `docs/reference/`（索引见其 README）；操作手册在 `docs/manual/`。
