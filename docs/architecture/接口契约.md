## 一、6 大平台接口（PT1-PT8，别人实现接入）

> 统一模式：抽象基类（`ABC`）+ DB 配置表 + 注册表 `_REGISTRY` + 工厂 `get_<x>(provider)`。
> 新增实现：实现子类 + 注册表加一行 + DB 配置（provider=...），**不改调用方代码**。

### 1. DataSource（数据源）
- **文件**：`server/src/data_platform/data_source.py`
- **DB 表**：`data_source_config`（migration 0013）— `provider / credentials_encrypted / params / enabled`
- **契约**：
  ```python
  class DataSource(ABC):
      @abstractmethod
      def get_client(self) -> Any                  # 返回数据源客户端（tushare pro / Wind）
      @abstractmethod
      def test_connection(self) -> bool
      def record_usage(self, api_calls=1, api_name="", success=True, latency_ms=0, provider="") -> None
        # 写 data_source_usage 表（A4 #36）；失败不抛；provider 缺省 self.provider
  ```
- **工厂**：`get_data_source(provider: str) -> DataSource | None`（无配置返回 None，调用方 fallback .env）
- **实现**：`TushareDataSource`（token DB 优先 `.env` fallback；`_get_token` 解密）
- **扩展**：加 Wind → 实现 `DataSource` 子类 + `_REGISTRY["wind"] = WindDataSource` + DB 配 `provider='wind'`

### 2. Broker（交易通道）
- **文件**：`server/src/strategy_framework/broker.py`
- **DB 表**：`broker_config`（migration 0016）— `provider / credentials_encrypted / params / enabled`
- **契约**：
  ```python
  class Broker(ABC):
      @abstractmethod
      def get_credentials(self) -> dict            # 解密凭证 dict（无 market 参数！）
      @abstractmethod
      def test_connection(self) -> bool             # 检查 REQUIRED_FIELDS 完整
  ```
- **工厂**：`get_broker(provider: str) -> Broker | None`
- **实现**：`XTPBroker`（REQUIRED_FIELDS=app_id,app_secret）/ `BinanceBroker`（api_key,api_secret）/ `OKXBroker`（+passphrase）
- **market -> provider 映射**（PI3 strategy_runner 用）：
  - `astock` / `convertible` / `etf` → `provider="xtp"`（中泰 XTP 通道）
  - `binance_perp` → `provider="binance"`；`okx_perp` → `provider="okx"`
  - ⚠️ `get_credentials()` **无 market 参数**；按 market 选 provider 是调用方职责（`get_broker(_MARKET_TO_PROVIDER[market]).get_credentials()`）
- **扩展**：加 IB/CTP → 实现 `Broker` 子类 + `_REGISTRY["ib"] = IBBroker`

### 3. MessageChannel（消息通道）
- **文件**：`server/src/alert_notify/channel.py`
- **DB 表**：`channel_config`（migration 0015）— `provider / credentials_encrypted / enabled`
- **契约**：
  ```python
  class MessageChannel(ABC):
      @abstractmethod
      def send(self, title: str, body: str, level: str = "info") -> bool
      @abstractmethod
      def test(self) -> bool                        # 发一条测试消息
  ```
- **工厂**：`get_channel(provider: str) -> MessageChannel | None`
- **实现**：`WechatWorkChannel` / `DiscordChannel`（都继承 `_WebhookChannel`，webhook URL）/ `ServerChanChannel`（sckey）
- **level**：`info` / `warn` / `error`（title 前缀 `[level]`）
- **扩展**：加钉钉 → 实现 `MessageChannel` 子类 + `_REGISTRY["dingtalk"] = ...`

### 4. Task（后台任务管理，PT1）
- **文件**：`server/src/task_manager.py`
- **DB 表**：`tasks`（migration 0014）+ `task_logs` — 见数据模型
- **契约**（模块级函数，非类）：
  ```python
  create_task(task_id: str, name: str, task_type: str, trigger_type: str,
              trigger_user: str, params: dict | None = None) -> None
      # status='running', last_heartbeat=now；ON CONFLICT DO UPDATE（可重试）
      # task_type: backtest/sync/ai/trade；trigger_type: manual/schedule/event
  update_heartbeat(task_id: str, progress: dict | None = None) -> None
      # progress: {current, total, pct, step}（JSON 存 tasks.progress）
  complete_task(task_id: str, status: str = "completed", error: str | None = None) -> None
      # status: completed/failed/terminated
  log_task(task_id: str, level: str, message: str,
           step_name: str | None = None, sql_or_api: str | None = None) -> None
      # level: INFO/WARN/ERROR/DEBUG；写 task_logs（故障定位）
  list_tasks(status: str | None = None, limit: int = 100) -> list[dict]
  get_task(task_id: str) -> dict | None              # 含最近 50 条日志
  terminate_task(task_id: str) -> None               # status='terminated'（进程 kill 由调用方）
  force_delete_task(task_id: str) -> None            # 删 tasks + task_logs
  detect_stuck(timeout_s: int = 300) -> int          # running + heartbeat 超时 -> stuck，返回标记数
  notify_on_failure(title: str, body: str, provider: str = "wechat_work") -> None
      # PT7 跨层联动：复用 MessageChannel 发告警
  ```
- **任务纳入**：任何异步任务（回测/同步/AI/策略）调 `create_task` + `update_heartbeat` + `complete_task` 即纳入统一管理 + 卡死检测 + 告警

### 5. RiskRule（风控规则，PT6）
- **文件**：`server/src/risk_control/risk_rule.py`
- **DB 表**：`risk_rules`（migration 0017）— `type / params(JSON) / enabled`
- **契约**：
  ```python
  @dataclass
  class RiskCheckResult:
      approved: bool
      reason: str = ""

  class RiskRule(ABC):
      @abstractmethod
      def check(self, order: dict, context: dict) -> RiskCheckResult
          # context: {position_pct, today_loss, ...}（调用方填）
      @abstractmethod
      def get_params(self) -> dict
  ```
- **工厂**：`get_rule(rule_type: str, params: dict | None = None) -> RiskRule | None`；`load_rules_from_db() -> list[RiskRule]`
- **实现**：`MaxPositionRule`（max_pct）/ `MaxSingleOrderRule`（max_amount）/ `DailyLossLimitRule`（max_loss）
- **⚠️ 与 risk_control 的关系**（PI2 已澄清）：
  - `RiskRule`（本接口）= **单规则抽象**（type=max_position 等），`check(order, context)` 返回 `RiskCheckResult`，供后续新规则扩展
  - `risk_control.RiskControl`（旧实现）= **dict 参数风控**（读 risk_rules 表 type=global/etf_conv/crypto 的 params），`check_order` 返回 `RiskDecision`
  - 两者**独立**：`risk_control` 自己读 risk_rules 表的 global/etf_conv/crypto 行（不用 `load_rules_from_db`），`RiskRule` 接口保留给新单规则
- **扩展**：加"日内次数限制" → 实现 `RiskRule` 子类 + `_REGISTRY["max_trades_per_day"] = ...`

### 6. LLMProvider（LLM 网关，单例）
- **文件**：`server/src/llm_gateway/gateway.py`；单例 `gateway = LLMGateway()`
- **DB 表**：`llm_model_config`（migration 0005+0010+0012）— `provider/model/api_key_encrypted/base_url/context_window/supports_tools/max_input_tokens/max_output_tokens/temperature/priority/enabled`
- **契约**：
  ```python
  gateway.chat(messages: list[dict], *,
               tools: list[Tool] | None = None,
               role: Role = "viewer",               # viewer/analyst/trader/admin
               timeout: float = 30.0,
               retries: int = 1,
               caller: str | None = None) -> LLMResponse
      # caller 写 llm_usage：feishu/web_chat/daily_report/health_check/astock/test
  async gateway.chat_stream(messages, *, tools=None, role="viewer",
                           caller=None) -> AsyncGenerator[str, None]
  ```
- **路由**：按 `priority` 全局排序，primary + fallback（前两个）；熔断 closed/open/half_open（半开放一个试探）+ 指数退避
- **工具过滤**：`_filter_tools(role, tools)` — 角色白名单 ∩ 传入 tools（调用方只能缩小，不能越权）
  - viewer/analyst=READ_TOOLS；trader=+halt+启停策略；admin=+resume
  - `FORBIDDEN_TOOLS`={modify_risk_rule, modify_strategy_params}（永不注册）
- **输入限制**：入口 50 万字符拒；超 `max_input_tokens` 截断（保留 system + 最新）；输出传 `max_tokens=max_output_tokens`
- **刷新**：`gateway.reload_models()`（Web 改配置后调）

- **DB 表**：`bar_1D` / `bar_1min` / `bar_5min`（同结构，UNIQUE(symbol,ts)）
- **读写**：写=`data_sync.engine`；读=`backtest`/`astock_analysis`/`web_api`（K线端点）

**`BarContext`**（`factor.py`）— 因子计算上下文：


**`parameter_defs`**（参数定义，存 `strategy_config.params["parameter_defs"]`）：
```python

  {"name": "use_trailing_stop", "type": "boolean", "default": False},

```

**`Factor`**（`factor.py`）：
```python
class Factor:
    name: str = ""
    params: dict
    def compute(self, ctx: BarContext) -> float
```
- **预置因子注册**：`@register_factor("name", category="trend", params={"n":20}, needs_history=20)`；`list_factors(static_only=False)` / `get_factor(name)`
- **自定义因子（DB 化）**：用户 Web 写 `compute(ctx, **params)` Python 代码，存 `factor_def` 表（含 `needs_history`）；`_make_factor_class()` 编译；`load_factors_from_db()` 启动加载
- **静态/动态**：`needs_history=0` 静态（可选股+策略），`>0` 动态（只能策略）；选股引擎 `static_only=True`
- **DSL**：`DSLFactor(name, expr)`（AST 白名单安全 eval）
- **品类兼容**：`validate_strategy_factors(vt_symbol, factor_configs) -> dict`（防 crypto 因子跑 A 股）

**`PythonStrategy` + `StrategyContext`**（#15 Python 代码模式）：

**`ExecutionAdapter`**（`adapters.py`，ABC）：
```python
class ExecutionAdapter(ABC):
    @abstractmethod
    def send_order(self, order: Order) -> str       # 返回 order_id（client_id）
    @abstractmethod
    def cancel_order(self, order_id: str) -> None
    @abstractmethod
    def query_position(self) -> list[Position]
    # 以下默认空，子类按需 override：
    def query_account(self) -> list                 # XTPAdapter 实现
    def query_orders(self) -> list                 # 事件缓存
    def query_trades(self) -> list                 # 事件缓存
```
- **实现**：`XTPAdapter`（vnpy_xtp，事件驱动查询：调 query 后轮询等 EVENT）/ `CryptoPerpAdapter` / `BacktestAdapter`（回测，按 bar 收盘价成交）
- **工厂**：`create_adapter(adapter_type, gateway=None, event_engine=None) -> ExecutionAdapter`（xtp/binance_perp/okx_perp）
- **⚠️ Broker vs ExecutionAdapter**：Broker=配置+连接测试（凭证 DB）；ExecutionAdapter=交易执行（send_order 等）。PI3 后 XTPAdapter.__init__ 用 `Broker.get_credentials()` 取凭证（替代 .env）

## 四、返回格式约定

### 状态枚举
- **sync status**：`success` / `partial`（部分失败）/ `error` / `empty`（无数据）/ `uptodate`（无缺口）
- **task status**：`running` / `paused` / `completed` / `failed` / `terminated` / `stuck`
- **severity**：`info` / `warn` / `critical`
- **log level**：`INFO` / `WARN` / `ERROR` / `DEBUG`

### 错误处理约定
- **同步任务**：单条/单日失败不中断整体，记 `failed_dates`（含原因），status=`partial`
- **网关**：provider 失败切 fallback，全失败返回 `LLMResponse(content="", usage={"error":...})`，不抛
- **风控**：拒单返回 `RiskDecision(approved=False, reason, severity)`，不抛
- **DB**：`get_conn()` 连接池，`with` 退出还池（P3 回写 2026-08-20：删"新库容错 CREATE TABLE IF NOT EXISTS"——运行时 DDL 已清零，schema 唯一真相源=alembic）

### dict vs dataclass
- **dataclass**（类型契约强）：`Bar`/`Signal`/`Order`/`Position`/`Trade`/`BacktestResult`/`RiskDecision`/`RiskCheckResult`/`LLMResponse`/`Tool`
- **dict**（灵活/DB 行）：`StrategyConfig.factors`/`aggregator`/`risk`/`params`、`SyncResult`、`task_manager` 返回、`progress`/`params` JSON 字段
- **约定**：跨模块公开返回优先 dataclass；DB 行/flexible 配置用 dict

## 五、不变量与约定

### 标识符
- **vt_symbol**：`raw.EXCHANGE`（`600000.SHSE` / `000001.SZSE` / `113549.SHSE` / `BTCUSDT.BINANCE`）
  - 转换：`to_vt_symbol(ts_code)` / `to_ts_code(vt_symbol)` / `parse_vt_symbol(vt) -> (raw, ex)`
  - 交易所后缀：`SHSE`（沪）/ `SZSE`（深）/ `BSE`（北）/ `BINANCE` / `OKX`
- **freq**：`1D` / `1min` / `5min` / `15min` / `30min` / `60min`（bar 表后缀 = freq）
- **ts**：`TIMESTAMPTZ`；A 股 +08:00，加密 UTC

### 实盘三级开关（铁律，AND）
1. `.env ENABLE_LIVE_TRADING`（总闸，`settings.is_live_trading_enabled()`）
2. Web `live_trading_config` 分项（`risk.is_live_trading_allowed(market)`，在 `check_order` 前置）
   - 分项：`convertible` / `etf` / `astock` / `binance_perp` / `okx_perp`
3. `strategy_config.enabled` + `backtest_verified`（策略级，scheduler 层检查）
- 任一关 → `check_order` 拒单（返回 `RiskDecision(approved=False)`）

### 平台化原则
- **结构接口通用，实现可简化**：6 大接口按通用方向设计，别人配置 + 实现子类即接入，不改平台代码
- **业务菜单保留**：管理设置类（数据源/通道/风控/AI/系统设置）通用化；业务菜单（交易/策略/分析）不动
- **配置驱动非硬编码**：策略因子/权重/参数走 Web 配置 + DSL，每个策略改代码是错误做法

### 数据库
- **连接**：`get_conn() -> psycopg.Connection`（连接池，`with` 退出还池）；`get_engine()` 给 SQLAlchemy/pandas
- **schema 版本**：`alembic` 唯一真相源（migration 文件，不手动 ALTER）；**运行时零 DDL**（2026-08-13 起各 handler 的 `CREATE TABLE IF NOT EXISTS` 已全部入迁移，动态表 `bar_{freq}` 的 `ensure_table` 是唯一豁免）。（P3 回写 2026-08-20：删"各 handler CREATE TABLE IF NOT EXISTS 兜底"旧述）
- **migration head**：0049（0017 head 为 2026-08-11 时点状态，早已过时）（P3 回写 2026-08-20）

### 运行期 AI
- 只用国内模型（DeepSeek 主 + GLM 备），**不接 Claude/OpenAI 运行期**；Claude Code 仅开发助手
- LLM 回复按输入语言自然回复（i18n：移除 lang 注入）；日志统一英文
