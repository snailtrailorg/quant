# D25 · 三层能力模型（能力 → 能力集/域 → 接口）

> 状态：**v3 批189 修订**（2026-11-18）。原「5 token / 页签合并 / 两域」改为「5 token / 三类接口域 / 页签=接口类型」；token 词表本身不变。
> 需求与迁移：`flow/方案/批189-TD-MD接口拆分-现状与需求.md`。

## 一、三层模型

```
能力（DataKind，细粒度）          代码真源（adapter/端口声明）
 └─ 能力集（5 个 token）          配置层可见的归类
     └─ 接口（三类各一行）          数据源 / 行情接口 / 交易接口
```

- 能力是唯一真源；能力集是归类视图；接口是配置实体。
- 三层之间只有「能力 → token」是映射，接口不复制能力定义。

## 二、5 个能力 token（不变）

| token | 中文 | 接口域 |
|---|---|---|
| `hist_quote` | 历史行情 | 数据源 |
| `ref_data` | 参考数据 | 数据源 |
| `inst_event` | 标的事件 | 数据源 |
| `rt_quote` | 实时行情 | 行情接口 |
| `trading` | 交易 | 交易接口 |

- 三域集合**互斥**（同一 token 只属一个域）且**并集=全部 token**；由守门测试钉死，新增 token 必须同时入域。
- 历史遗留 `daily/minute/snapshot/quote` 已归一为 `hist_quote/rt_quote`；代码中 `trading` 作为域谓词保留，不再拆词。

## 三、接口域与页签

- 「数据源」页签 = `data_source` 行；「行情接口」= `market_interface`；「交易接口」= `trade_interface`。
- 页签按**接口类型**划分，不再按能力过滤；能力在表单内只读展示（由 provider manifest 派生）。
- 一个 provider 可同时出现在行情与交易页签，但那是**两条独立记录**（各自凭证/启停/生命周期）。

## 四、能力校验

- 写侧：`check_capability_subset(provider, declared)`（⊆ 代码能力）+ `check_capability_domain(interface_type, declared)`（⊆ 域集）。
- 启动/读取：配置漂移告警（能力超出代码声明时不静默）。
- 交易接口额外校验：provider 必须有 `execution` 载体，否则只能保存为「待接入」且不可启用。

## 五、与数据/交易面的关系

- 数据源：hist/ref/event 走拉取（datasource 插件）。
- 行情接口：rt_quote 走 hub 进程（订阅/推送）。
- 交易接口：trading 走 exec 进程（下单/持仓），并通过 `td_md_map` 关联行情接口取价（1:N 主备）。
