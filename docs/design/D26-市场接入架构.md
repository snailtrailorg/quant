# D26 · 市场接入架构（MarketSpec 声明 + 扁平 provider 插件）

> 状态：**v4 设计定稿**（2026-09-25 v3 终裁后双盲审全修：金融 P1×4+P2×5 / 架构 P1×5+P2×6）
> 定位：接入面演进锚点；实施触发点=下一次接入面动工；**实施批方案细化须再过双盲审**（§五清单为本稿核心交付）。
> 核心一句话：**一个账号 = 一行接口配置 = 一个 hub + 一套 TD 会话；hub 绑死账号行，MD/TD 同凭证。**

## 零、终裁记录（推翻 A05「A 股 MD 单 hub」，2026-09-25 用户裁定）

**全市场唯一拓扑 = 账号级实例化**——A 股也不例外（XTP 双账号=双行=双 hub）。五条理由：

1. **分支税**：A 股/加密分支 10+ 处；**最强活证据=v3 盲审挖出的现存加密潜伏 bug**——worker `_hub_alive`（hub_worker.py:116）读裸键 `quant:hb:md-hub`，加密 hub 写 per-account 键 → 加密 worker hub_alive 恒 False（加密实盘未开闸所以未爆，buy_ok 门失真）。迁移批顺带修复，并列为加密实盘开闸前必修项。
2. **故障域反转**（措辞修正自 v3）：故障域=账号域——实例局部故障（进程崩溃/OOM）在重拉窗内仅该账号受影响；共模故障（代码 bug/Valkey 挂）两种拓扑等同；单点的时间界由 systemd 重拉压至 1-2 分钟。承载裁定的是⑤，本条不单独承载。
3. **一致性反对弱化**：微差 bar 在 A03 §8.4 双时态语义下非新罪（流生成版本允许微差）；但**对账前提=锚落地**（见 §3.4 依赖注记）。
4. **M5 退役红利**：互备体系（switch.py 265 行实测/active_instance/intent/guarded Lua/AB 双实例）全部退役（退役边界精确定义见 §4.1）。
5. **底座同质化（根本）**：「聚合 hub」特殊形态组件消失——hub 从共享基础设施退化为账号附属进程，单一形态=注册即行 CRUD、代码路径唯一、故障模式单一。

**哲学（用户立法）**：逻辑越简洁代码质量越高，真实故障点越少；资源不足加配置即可。

## 三、架构模型

### 3.1 市场域判据（沿用）

市场域=行情事实权威按标的唯一的品种域；域内撮合差异由 A05 三维+A03 scope 承载。

### 3.2 结构：一份声明 + 一层插件 + 一种拓扑

```
MarketSpec（quant_common/markets.py 扩展——纯数据）
│  trading_day_anchor: 自然日 | UTC0点 | 夜盘开盘沿    ← 法定字段（期货夜盘 C4 防雷）
│  sessions_skeleton: 日盘/夜盘/24×7（骨架；market_hours 表=运营真源）
│  channels: [bar(聚合), depth_snapshot/trade_tick/order_tick(透传，L2 启用)]
│            + per-channel 旋钮：stream_maxlen / 订阅上限（§3.4 内存与配额上界）
│  flush_policy: 三窗 finalize | stale 周期
│
└─ provider 插件（扁平；角色可选 MD/TD/pull——现状无一家双角色齐备，隐含必备=空实现陷阱）
```

### 3.3 账号=hub 宿主（核心立法 + 盲审补强）

> 一行 trading 域 external_interface = 一个账号 = 一个 hub + 一套 TD 构建器；hub 用该行凭证开 MD，worker 用同行开 TD。

- 流键统一 `hub:bars:{account_id}:{symbol}`；同源校验全市场统一（无跳过分支）。
- **订阅真相源保持全局**（`_desired_symbols`=running∪白名单∪临时订阅，无 account 维）——各 hub 全量复制订阅。代价=A股 L1 订阅额度×N（per-hub 连接额度反宽裕，已接受）+ **L2 授权费 per 账号×N + 加密 per-IP 限速共享预算（同机 N hub 共享币安 weight——「加配置」对 IP 限速不成立，须上界意识）**。
- `hub:latest_tick` 契约（盲审 P2）：写者=各账号 hub 各写 `hub:latest_tick:{account_id}:{symbol}`（TTL 65s）；读者（stock_detail）=**SCAN `hub:latest_tick:*:{symbol}` 取在场者**（TTL 天然防陈旧）——禁「读任意裸键」（会变相复活选行逻辑）。
- **md_row 跨通道解耦不做**，且注记：非纯加法——流键/同源校验/水位键身份全锚 account_id，后补 md_row 须重定义流身份=MD 源行 id（重新分叉），故若未来要做，**现在就把流身份措辞定义为 MD 源行 id** 可买断分叉（实施批措辞按此）。
- **XTP client_id 上限守卫**（盲审 P2-3）：同账号 worker 派生 `(tid−1)%98+2`——tid 相差 98 撞号=「任务在跑但 TD 永远连不上」；建任务时校验同账号 client_id 占用。
- **多账号一致性用户警示**（盲审 P2-4）：双账户对照实验/逐步迁移仓位场景——行为**不复制**（偶发信号分叉+成交侧排队/部分成交差异远大于行情微差）；对照口径建议意图级非逐 bar 级；迁移场景预期持仓漂移以 reconcile 对账。

### 3.4 核心不变式（+落地依赖与缺根补强）

| 不变式 | 全市场统一态 |
|---|---|
| 同源数据不复制 | **best-effort**：多账号 hub=多份公共流各自聚合；**对账锚=PG 盘后回补** |
| hub 不碰交易 | TD 不流经 hub |

**对账锚落地依赖（金融 P1-1，诚实注记）**：A 股分钟侧 hub 落库已退役（2026-09-23）、stk_mins 未购买——**bar_1min 现为空，锚暂不存在**；加密盘后回补仅是 A03 §8.4 蓝图。锚落地前 best-effort=无对账的知情接受（A股锚=stk_mins 采购 gate；加密锚=回补批）；diff 告警（A03 per-field 容差）列为实施批配套。

**缺根≠微差（金融 P1-2，实施批配套）**：hub 重启窗内分钟不产 bar；重启后首桶 volume 只含剩余增量且 span>30s 不标 untrusted=**静默半根**——回补只修历史不救当日决策。实施批加 worker **ts 域缺口检测**（`ts_key − max_ts > 60s` → rewarm+告警，一行比较挂在 R-DL1 链）。回补归因配套（金融 P2-5）：order_log 加 bar 指纹列（ts+OHLCV+gen 随下单落）。

**Valkey 内存上界公式**（架构 P2-5）：STREAM_MAXLEN=5000/标的/账号 × ~250B——100 标的×2 账号 ≈ 250MB，线性、立法内；MarketSpec channels 留 per-market maxlen 旋钮。

### 3.5 真源分层（v2 立法沿用）

FIELD_SCHEMA 真源留 `interfaces/base.py`（引用不复制）；MarketSpec 纯数据落 quant_common（收编三处重复归属）；TD builder 下沉可引用层。

## 四、M5 退役与生命周期（v4 精确定义）

### 4.1 退役边界与守卫（架构 P1-1 修——方案 a）

```
退役：renew 循环 / intent / active_instance 仲裁 / guarded Lua / AB 双实例部署
保留：boot 守卫 = SET NX EX 30（新进程启动抢自己的键）
     失败 → exit 3 + RestartSec=30 自愈（30s 后旧 TTL 过期重拉即愈——
     真实竞态是旧 lease TTL 比旧进程活得久，非双活进程，systemd 同名串行保证后者）
gen：守卫通过后 INCR（守卫失败不自增——防空代次让 worker 无谓重暖机）；
     worker 跳变检测语义原样完整
WatchdogSec/sd_notify：EngineLoop 级进程挂死检测，与 M5 无关，保留
```

**退出码矩阵（v4 重写）**：留 `0`（优雅退出）/`1`（故障重拉）/`9`（接口行 provider 变更自重启，批 64——与 M5 无关）/`78`（EX_CONFIG）；`6`/`5` 随 M5 退役；`3`（boot 守卫失败自愈）/`4`（重试耗尽）按方案 a 保留。unit 文件 `RestartPreventExitStatus` 与注释随改；`run_hub_postverify.py` 旧注释同步。

### 4.3 观测面 N 化与配置界面（v4 独立小节——架构 P1-4/P1-5）

**观测面（从 1→N，五处清单；「crypto 现状推广」不成立——加密 per-account 心跳今天不在任何观测面，是从零建）**：
1. collector.py hub 快照读：单 hash → N 实例结构
2. monitor.py R4 hub_hb_lost / R6 tick_stalled：单 streak 状态机 → per-account streak+告警 component 去重键
3. /readyz `hub_hb` 检查：语义**裁定=全部期望 hub 心跳在场才算 ready**（fail-closed）
4. deploy `deploy_hub_hb_redis_key` + quant-hbcheck postverify：单键 → 集合发现（SCAN `quant:hb:md-hub:*` 或 DB 驱动）
5. 前端 Health 页 hub 单对象渲染 → N 实例
观察日三查口径：hub 零重启/心跳/241 根完整性 → 「hub 集合」判定。

**position/拖拽收束（消二义——架构 P1-5）**：
- position 列**保留**（routing 软排序消费+create 全局 max+1 依赖）；reorder 端点**保留**（全局全量序列，语义不动）
- 前端仅 trading 域行**撤拖拽手柄**（通道切换语义消失）；pull 型数据源行保留拖拽
- `get_interface_row()` **删缺省选行分支**，改 row_id 必填 raise（无主路径会静默绑首行账号；与「hub 绑死账号行」fail-fast 哲学一致）
