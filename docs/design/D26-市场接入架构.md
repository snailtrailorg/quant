# D26 · 市场接入架构（MarketSpec 声明 + 扁平 provider 插件）

> 状态：**v2 设计定稿**（2026-09-25 双盲审修订：金融软件专家 P1×5+P2×6 / 软件架构设计师 P0×1+P1×4+P2×4 全吸收；v1 的「两级插件树」收敛为本形态）
> 定位：接入面的**演进方向锚点**——不立即实施；以期货接入为唯一实施触发点。
> 前序裁定（沿用）：hub 边界=市场域；品类=流维度；通道=切换池（批 64）；同源数据不复制（astock 强不变式）。

## 一、背景与演进

D25 后「市场」一级仍是散落代码分支（`market ==` ×8 处、SA4 加密特例、A 股固定双实例）。v1 提案「两级插件树」经双盲审**收敛**：市场级持有的四样（拓扑/时段/通道/期望态）全是**声明数据、零行为多态**——把数据铸成代码插件层级违反本方案自己的术语法（适配器=行为连接件）；正确形态是 **MarketSpec 纯数据注册表 + provider 保持扁平插件**（markets.py/perm_registry 先例，批 63 二已验证扁平收益）。

一句话：**加市场 = 加一份 MarketSpec 声明；加供应商 = 注册一个扁平 provider 插件（角色可选）；hub 数量与形态 = MarketSpec 的声明属性。**

## 二、术语规范（用户原词 → 本方案术语 → 业界通用）

| 用户原词 | 本方案术语 | 业界通用 | 纠正说明 |
|---|---|---|---|
| 模块/插件 | 适配器（Adapter）/插件（Plugin） | Connector / Gateway | 与项目 `adapter` 一致；「网关」保留给 MD/TD 连接件 |
| 国内市场模块 | **MarketSpec（市场声明）** | Market（市场域） | v1「Market Adapter」废止——纯数据不配插件层级 |
| 下一级插件（券商） | 供应商插件（Provider Plugin） | Brokerage/Data Connector | 券商=通道**供应商**（数据源=**交易所及其信息公司**——L2 经营主体是上证所信息网络/深圳证券信息，单独授权计费） |
| hub（保留） | hub（行情馈送中枢） | Feed Handler | 对外文档注英文 |
| 实盘能力 | **MD 能力**（Market Data） | Market Data | 「实盘」=live trading 开关，与行情无关 |
| 交易能力 | **TD 能力**（Order Execution） | Brokerage / Execution | CTP/XTP 原生缩写 |
| 完整的插件（加密） | 自包含供应商 | Vertically-integrated provider | 账号实例化即自带 hub 宿主 |
| 每源一个hub | **账号级实例化**（account-level） | Per-account instantiation | v1「源级实例化」废止——加密 MD 是空凭证公共流，账号≠数据源（P1-2） |
| 单hub | 共享单例（shared singleton） | Singleton | |
| 节奏域 | 交易时段（Trading Sessions） | Market Calendar | Spec=形态骨架，market_hours 表=日期级运营真源（A03 §4.2 主从裁定） |
| 品类管道 | 数据通道（Data Channel） | Feed Channel | bar 线（聚合）/ depth_snapshot 线等 |

## 三、架构模型（v2）

### 3.1 市场域判据（v2 修正——P1-1）

> **市场域 = 行情事实权威按标的唯一的品种域。**

（v1「独立撮合事实体系」废止：按其字面沪深北应拆三域、币安 OKX 应并一域，与实际划分矛盾。A 股合为一域的依据=每标的有唯一权威行情源+各通道转发同一份快照+分钟级策略对毫秒差不敏感；域内撮合差异（转债临停/北交 ±30%/收盘竞价 scope）由 A05 三维+A03 scope 层承载，与域划分无关。）

### 3.2 结构：一份声明 + 一层插件

```
MarketSpec（quant_common/markets.py 扩展——纯数据，CI 可断言）
│  feed_topology: shared_singleton | account_level
│  trading_day_anchor: 自然日 | UTC0点 | 夜盘开盘沿     ← 法定字段（P1-5：C4 翻日判据按锚，
│                                                          否则期货夜盘跨午夜 volume 全钳 0）
│  sessions_skeleton: 日盘/夜盘/24×7（骨架；market_hours 表=运营真源）
│  channels: [bar(聚合), depth_snapshot(透传), trade_tick/order_tick(将来)]
│  flush_policy: 三窗 finalize | stale 周期               ← 第五声明属性（P2-2：bar 终结策略）
│
└─ provider 插件（扁平——现有 create_md_gateway + _TD_BUILDERS 模式）
     xtp        roles=[MD, TD]
     emt_emq    roles=[MD, TD]（EMQ 行情身份 ≠ EMT 交易身份——一份分组 schema 两套凭证）
     tushare    roles=[pull]（纯数据供应商：无运行时角色，配置面归 D25 单表）
     tencent    roles=[pull]
     binance_perp / okx_perp    roles=[MD, TD]
```

**角色立法（双盲审 P1-3 共识）：MD / TD / pull 可选，零运行时角色合法**——现状没有任何一家双角色齐备（TD builder 仅 xtp、加密 TD=stub），隐含必备会迫使空实现。角色缺失的闸=SA4 期望表按角色存在性过滤（等价现状 `list_md_gateway_providers`）+ worker builder miss→EX_CONFIG。

**L2 通道立法（金融 P1-4）**：通道命名精确化（`depth_snapshot`/`trade_tick`/`order_tick`——A 股「L2」是三种不同物，现有十档取五是**增强快照**非完整 L2，消息 schema 与档位取舍须显式声明）；通道声明带 **per-provider 支持矩阵**——L2 可用性是供应商属性（XTP 增强行情/EMQ L2 各自授权独立端点），切换池切到无 L2 供应商时**告警降级**（depth→五档），禁静默消失；L2 独立建连生命周期归 provider 插件。

### 3.3 核心不变式（含一致性等级——金融 P1-2 诚实化）

| 不变式 | astock | crypto |
|---|---|---|
| 同源数据不复制 | **强不变式**（两份聚合=跨账户 bar 分叉） | **best-effort**：同交易所两账号=两份公共流各自聚合，hub 重启窗不同则同标的 bar 可分叉——对账锚=PG 权威+盘后回补，消费方不得假设同域同 bar |
| hub 不碰交易 | 全域成立（MD/TD 双角色平行注册，TD 不流经 hub） | 同 |

### 3.4 真源分层（架构师 P0 修——消第五处声明）

| 声明物 | 落点 | 说明 |
|---|---|---|
| MarketSpec（拓扑/时段/通道/flush） | `quant_common/markets.py` | 纯数据；**顺手收编三处重复**：PROVIDER_MARKET、NON_DATA_PROVIDERS、InterfaceProvider.market |
| FIELD_SCHEMA | `data_platform/interfaces/base.py`（现状不动） | Spec **引用不复制**——层序铁律下 ProviderSpec 不越层收编 |
| MD 网关类 | strategy_framework/md_gateway 注册表（现状） | |
| TD builder | `_TD_BUILDERS`（**从 strategy_runner.main 下沉**至可引用层） | |

## 四、注册与生命周期（补故障/轮换/升级——架构 P1-3）

| 事件 | 归属 | 动作 |
|---|---|---|
| 市场上线 | MarketSpec 注册 | 按拓扑拉起 hub |
| 供应商接入 | provider 插件注册（角色可选） | shared_singleton→进切换池；account_level→行实例化自带 hub（SA4 按声明管期望态，输入集=拓扑 ∪ 行 enabled/capabilities ∪ MD 角色过滤——防 78 死循环） |
| 账号增删 | 行 CRUD | 池序变化 / hub 伸缩（先维护键后停） |
| 通道切换 | Web 拖 position | hub exit 9 自重启（**M7 口径白名单预登记「切换窗丢根+冷启动重基线」**——防对账狼来了） |
| **行变更（provider/凭证/参数）** | `_poll_iface_switch` 扩展 | provider 变更=exit 9（现状）；**凭证/参数变更同走 exit 9**（补现存缺口：hub 持旧凭证跑到下次重启） |
| **故障恢复** | systemd+SA4+M5 | 机制不变（声明只影响期望态） |
| **升级迁移** | 部署窗三段+M5 | 波次动态采集（已修） |
| 供应商退役 | **先清行/禁用，后删码** | 反序=hub/worker 78 循环；78 告警文案指路 |
| 市场退役 | MarketSpec 注销 | hub 全回收（无场景，仅定义） |

**MarketHours 主从（架构 P1-4）**：Spec 声明**形态骨架**（日盘/夜盘/24×7）；`market_hours` 表（A03 §4.2）=**日期级运营真源**（节假日/临时休市）——时段是运营数据，全代码声明=每个节假日发版。

## 五、与现状映射及迁移

| MarketSpec 构件 | 现状落点 | 迁移动作 |
|---|---|---|
| 拓扑声明 | A 股固定双实例 / SA4 加密特例 | 声明化 |
| 交易日锚 | 隐含（astock=自然日恰好成立） | **法定字段显式化 + C4 翻日判据改用锚**（`parts.py:79` `t.date()` → 锚函数） |
| 时段骨架 | `_in_bar_session` 分支 | **先钉契约测试再迁**（分钟末标注/竞价条并入/豁免双门限——历史修过的语义，直接映射 A03 phase 表会丢收竞价根） |
| 通道 | MinuteAggregator（bar 线） | depth/trade/order 线随 L2 启用 |
| flush 策略 | astock 三窗 finalize / crypto flush_stale（代码分支） | 声明化 |
| provider 归属 | PROVIDER_MARKET + NON_DATA_PROVIDERS + InterfaceProvider.market 三处 | 收编单源 |
| TD builder | strategy_runner.main `_TD_BUILDERS` | 下沉 |
| 键空间 | `_key(base, account_id)` | 已参数化，收编 |

**迁移策略**：以**期货接入为唯一触发点**（v1「L2 也触发」废止——L2 是 astock 域内加通道，按本设计自身立法零触及市场级抽象，不构成验证；架构 P2-1）。**抽象回收判据（可验证）**：期货接入时 `market ==` 分支=0 且 hub 通用面零改动。日常小步收编三处重复归属。

## 六、扩展场景验证（波及面诚实化——架构 P2-2）

| 场景 | 动作 | 波及面 |
|---|---|---|
| 加 A 股券商 | 注册 provider | 零（进池） |

## 七、范围外

- 不实施 A03 完整五层总线（正交）。
- 双源并行（互备热切换/对账）归 M7。**L1 聚合 bar vs L2 对账只能弱对账**：量累计同源应一致可强对；价（high/low/close）因快照节奏差天然有差，白名单（金融 P2-4）——防 M7 立强不变式。
- D25 能力集不受影响（正交维度）。
- 期货域通道远期清单（结算价/open_interest/保证金档——A03 占位已有）届时补；「单所体系」措辞不预设（CTP 多所统一接入，五大所撮合独立——拓扑届时裁）。
