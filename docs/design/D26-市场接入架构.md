# D26 · 市场接入架构（MarketSpec 声明 + 扁平 provider 插件）

> 状态：**v3 设计定稿**（2026-09-25 用户终裁：**全市场统一账号级 hub 拓扑**——推翻 v2 双拓扑声明与 A05「A股 MD 单 hub」部分裁定，见 §零；v2 双盲审处置见 §八）
> 定位：接入面演进锚点；实施触发点=下一次接入面动工（期货/L2/拓扑迁移任一先到）。
> 核心一句话：**一个账号 = 一行接口配置 = 一个 hub + 一套 TD 会话；hub 绑死账号行，MD/TD 同凭证。**

## 零、v3 终裁（推翻记录，2026-09-25）

**裁定：全市场唯一拓扑 = 账号级实例化（account_level）**——A 股也不例外（XTP 双账号=双行=双 hub）。

推翻 A05「A 股 MD 单 hub」的五条理由（详 flow/decisions.md 当日条）：
1. **分支税**：A 股/加密分支 10+ 处（流键分叉/同源校验跳过/部署形态/SA4 特例/暖机过滤…），多个历史 bug（D6 键分叉、flush_stale 坑）本质是分支税。
2. **故障域反转**：单 hub=全平台单点故障（挂了全市场 worker 陪葬）；per-account=故障域恰为账号域（挂了只影响该账号）——A05「N-1 多余故障点」的视角是反的。
3. **一致性反对弱化**：「两份聚合 bar 微差」在 A03 双时态语义下不是新罪（流生成版本本就允许微差，权威=盘后 PG 回补）；跨账户偶发不同决策=多账号自治的自然属性。
4. **M5 退役红利**：互备体系（switch.py 265 行/active_instance 仲裁/intent/guarded Lua/AB 双实例部署）存在的全部理由是「多实例抢一键空间」——统一后无抢的对象，整套蒸发。
5. **底座同质化（最根本）**：「聚合 hub」这个**特殊形态组件本身消失**——hub 从「共享基础设施」（需双模式注册、全局仲裁、通道池、全局键空间）退化为「**账号的附属进程**」（读自己的行→连自己的网关→聚自己的 bar→写自己的键空间）。若保留共享单例形态，hub 这个底座必须同时支持两种拓扑——「做成可注册」说着简单，双模式解耦的全部复杂度落在底座上并传染全系统（它是所有实盘的地基）；统一后底座单一形态=注册即行 CRUD、代码路径唯一、测试面最小、故障模式单一。

**哲学（用户立法）**：逻辑越简洁代码质量越高，真实故障点越少；资源不足加配置即可——**用空间换简洁**。

## 一、背景与演进

D25 后「市场」一级是散落代码分支（`market ==` ×8、SA4 加密特例、A 股固定双实例）。v1 两级插件树→v2（双盲审收敛）MarketSpec+扁平 provider→**v3 用户终裁统一拓扑**。演进方向一致：声明化、收编分支、消特例。

## 三、架构模型（v3）

### 3.1 市场域判据（v2 立法沿用）

> 市场域 = 行情事实权威按标的唯一的品种域。（域内撮合差异由 A05 三维+A03 scope 承载。）

### 3.2 结构：一份声明 + 一层插件 + 一种拓扑

```
MarketSpec（quant_common/markets.py 扩展——纯数据）
│  trading_day_anchor: 自然日 | UTC0点 | 夜盘开盘沿    ← 法定字段（期货夜盘 C4 防雷）
│  sessions_skeleton: 日盘/夜盘/24×7（骨架；market_hours 表=运营真源）
│  channels: [bar(聚合), depth_snapshot/trade_tick/order_tick(透传，L2 启用)]
│  flush_policy: 三窗 finalize | stale 周期
│  （v2 的 feed_topology 字段删除——全市场唯一 account_level）
│
└─ provider 插件（扁平；角色可选 MD/TD/pull）
```

### 3.3 账号=hub 宿主（v3 核心立法）

> **一行 external_interface（trading 域）= 一个账号 = 一个 hub + 一套 TD 构建器。hub 用该行自己的凭证开 MD 与 TD（XTP 凭证本就 MD/TD 一体；币安同理）。**

- worker 流键统一：`hub:bars:{account_id}:{symbol}`（全市场无分叉）+ 同源校验统一（所有 worker 一律比对 account_id，无跳过分支）。
- 「XTP 账号 A 想用 EMQ 行情」的跨通道解耦**不做**（裁定 A）——真需要时加 `md_row` 参数（加法容易），现状无此配置。
- 换行情通道=换行（编辑 provider/凭证，或新行+任务迁移）——无切换概念。

### 3.4 核心不变式（v3 统一）

| 不变式 | 全市场统一态 |
|---|---|
| 同源数据不复制 | **best-effort**（全市场统一）：同交易所多账号 hub=多份公共流各自聚合，微差 bar 属流生成版本，**对账锚=PG 盘后回补**；消费方不得假设跨账号同 bar |
| hub 不碰交易 | TD 不流经 hub（worker 按账号行构建 TD 会话） |

### 3.5 真源分层（v2 立法沿用）

FIELD_SCHEMA 真源留 `interfaces/base.py`（引用不复制）；MarketSpec 纯数据落 quant_common（收编 PROVIDER_MARKET/NON_DATA_PROVIDERS/InterfaceProvider.market 三处重复）；TD builder 下沉可引用层。

## 四、M5 互备退役与生命周期（v3 重大简化）

### 4.1 退役清单

```
switch.py M5 切换协议（265 行）→ 退役（无多实例抢键空间场景）
active_instance 仲裁 / intent / guarded Lua → 退役
AB 双实例部署（@quant2）/ HUB_INTERFACE_ROW 概念 → 退役
lease（租约）→ 大幅简化（键空间无竞争者；systemd 同名单实例防重复启动；仅重启竞态留轻量守卫）
gen（代次）→ 保留（worker 跳变检测重暖机）
```

互备三目的的归属：防进程崩溃=systemd 重拉（本来主力）；防通道故障=换行（编辑行，无切换）；不断流热切换=接受冷切换秒级窗（M7 白名单「切换窗丢根」已预登记）。

### 4.2 生命周期（v3 简表）

| 事件 | 动作 |
|---|---|
| 账号接入/增行 | SA4 按行拉起 hub（统一，A股特例消失） |
| 账号停用/删行 | 先维护键后停实例（防反拉起） |
| 行凭证/参数变更 | hub exit 9 自重启重读行（凭证轮换=现存缺口的补法） |
| 进程崩溃 | systemd 重拉+gen 跳变重暖机 |
| 换行情通道 | 换行（编辑 provider/凭证或迁移任务） |

### 4.3 配置界面连带简化（position/拖拽退役）

- 拖拽手柄/position 列/orderNote 提示：**删**（hub 选行语义消失）
- reorder 端点退役（或仅服务 pull 型数据源行优先序）
- **保留**：tushare 等多数据源行的优先序（与 hub 无关）+ routing 软排序（A03 体系）
- 观察/心跳：`quant:hb:md-hub` 改 per-account 键（crypto 现状推广）；观察日三查口径改「hub 集合」判定；`hub:latest_tick` 写者=各账号 hub 各写自己（详情页降级链读任意）

## 五、与现状映射及迁移

| MarketSpec 构件 | 现状落点 | 迁移动作 |
|---|---|---|
| 统一拓扑 | A股单活双实例+M5 / SA4 加密特例 | **A股切 account_level：hub 键加 account 维度+SA4 统一+M5 下线** |
| 交易日锚 | 隐含自然日 | 法定字段+C4 判据改锚函数 |
| 时段骨架 | `_in_bar_session` 分支 | 先钉契约测试再迁（分钟末标注/竞价条/豁免双门限——历史语义勿回退） |
| 通道 | bar 线 | L2 透射线随启用（per-provider 授权矩阵+切换降级） |
| flush 策略 | 代码分支 | 声明化 |
| position/拖拽 | InterfacesCard+reorder | 退役（§4.3） |
| TD builder | strategy_runner.main | 下沉 |
| 键空间 | `_key(base, account_id)` | A股键统一带 account_id |

**迁移时机**：现网仅 1 个 A 股账号+1 任务，切换成本最低；与 D25 挂账（sync_kind_config 增量行等）合批或独立小批均可。**实施前必过方案细化+双盲审**（v3 是方向锚点，实施批展开细节）。
