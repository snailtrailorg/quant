# D26 · 市场适配器架构（两级插件树）

> 状态：**设计草案**（2026-09-25 立项，源自用户提议 + hub/能力模型系列讨论演进；待用户确认后双盲审）
> 定位：数据面与接入面的**演进方向锚点**——不要求立即实施，作为 L2 接入、期货接入前的架构共识，防各自为政。
> 前序结论（已裁定）：hub 边界=市场域（D25 讨论系列）；品类=流维度；通道=切换池（批 64 语义）。

## 一、背景与演进脉络

D25 实施后，接入面的形状已接近统一，但「市场」这一级仍是**散落的代码分支**（`market == "crypto"` 判断、`_in_bar_session` 分支、SA4 的加密特例、A 股固定单活双实例）。用户提议将其显式化为**两级插件树**：

```
Market Adapter（市场适配器 = 市场域容器）
  └─ Provider Adapter（供应商适配器，两级注册）
```

一句话：**加市场 = 注册一个 Market Adapter；加券商/交易所 = 在市场域下注册 Provider Adapter；hub 的数量与形态是市场适配器的声明属性。**

## 二、术语规范（用户原词 → 本方案术语 → 业界通用）

**立法：本方案起，接入面讨论统一用下列术语**（用户口述词与业界术语的对照，含纠正理由）：

| 用户原词 | 本方案术语 | 业界通用词 | 纠正说明 |
|---|---|---|---|
| 模块/插件 | **适配器（Adapter）/插件（Plugin）** | Connector / Gateway / Plugin | 「适配器」与项目现有 `adapter` 词汇一致；「网关（Gateway）」保留给 MD/TD 连接件（vnpy 惯例） |
| 国内市场模块 | **市场适配器（Market Adapter）** | Market（市场域）+ Session 容器 | 「市场域」= 一个独立撮合事实体系（A 股/加密/期货各一个） |
| 下一级插件（券商） | **供应商适配器（Provider Adapter）** | Brokerage Connector / Data Connector | 券商是**通道供应商**，不是数据源（数据源=交易所）——「供应商」准确于「券商」 |
| hub（项目词，保留） | hub（= 行情馈送中枢） | **Feed Handler**（馈送处理器） | 业界低延迟系统对「接收外部行情→标准化→分发」组件的标准称呼；项目内继续叫 hub，对外文档注英文 |
| 实盘能力 | **MD 能力（Market Data，行情）** | Market Data | 「实盘」在项目语境=live trading（交易开关），与行情无关——避免混用 |
| 交易能力 | **TD 能力（Order Execution，订单执行）** | Brokerage / Execution | CTP/XTP 语境原生缩写：MD=行情/TD=交易 |
| 完整的插件（加密） | **自包含供应商（self-contained provider）** | Vertically-integrated provider | 加密供应商=自带 hub 宿主 + MD + TD 全套 |
| 启动 hub | **馈送生命周期管理** | Feed lifecycle | hub 的拉起/仲裁/回收 |
| 节奏域（项目词） | **交易时段（Trading Sessions）** | Market Calendar / Trading Hours | 交易时段集合=市场日历（A 股日盘/期货夜盘/加密 24/7） |
| 品类管道 | **数据通道（Data Channel）** | Feed Channel | hub 内按品类分的管道：bar 线（聚合）/depth 线（透传） |
| 单hub/每源一个hub | **馈送拓扑：共享单例 / 源级实例化** | Singleton / Per-source instantiation | hub 数量=市场适配器的声明属性 |

## 三、架构模型

### 3.1 两级插件树（统一形态）

```
MarketAdapter（市场域容器：hub 拓扑 + 交易时段 + 数据通道 + 期望态声明）
│
├─ astock                          ← 馈送拓扑=共享单例；时段=A股日历；通道=[bar(L1聚合), depth(L2透传)*]
│   ├─ provider: xtp              ← 注册即获得双角色：MD(进切换池) + TD(builder 入表)
│   └─ provider: emt_emq          ← 同上；L2 端点就绪（品类通道启用即用）
│
├─ crypto                          ← 馈送拓扑=源级实例化；时段=24/7；通道=[bar]
│   ├─ provider: binance_perp     ← 每账号实例化 = 自包含供应商（自带 hub 宿主）
│   └─ provider: okx_perp
│
└─ futures（将来）                 ← 馈送拓扑=共享单例*；时段=日历+夜盘；通道=[bar]
    └─ provider: ctp
```

\* L2 通道为将来项（EMQ L2 端点已在批 63 备案）；期货拓扑届时按「单所体系」定共享单例。

### 3.2 核心不变式（沿用既有裁定，此模型全部内化）

| 不变式 | 在模型中的体现 |
|---|---|
| hub 边界 = 市场域 | 馈送拓扑是 Market Adapter 的声明属性 |
| 品类 = 流维度 | 数据通道是市场域内的管道，不产生新 hub |
| 通道 = 切换池 | Provider 的 MD 角色进池（A 股），Web 拖 position 切换 |
| 同源数据不复制 | 共享单例拓扑的立法根基（两份聚合=跨账户 bar 不一致） |
| hub 不碰交易 | TD 角色与 MD 角色平行注册，不流经 hub |

### 3.3 Provider 注册语义（双角色）

```
register_provider(market, ProviderSpec) =
  ├─ MD 角色：拓扑=共享单例 → 进 hub 切换池（external_interface 行，position 序）
  │           拓扑=源级实例 → 行实例化即自带 hub 宿主（SA4 按声明管期望态）
  └─ TD 角色：TD builder 入 _TD_BUILDERS 注册表，worker 建任务按 account_id 构建 per-task 会话
```

一个供应商 = 一个 MD 网关实现 + 一个 TD builder 实现 + 一份凭证 schema（FIELD_SCHEMA）——三者同源自 ProviderSpec 声明。

## 四、注册与生命周期

| 生命周期事件 | 归属 | 动作 |
|---|---|---|
| 市场上线 | Market Adapter 注册 | 声明拓扑/时段/通道；拉起 hub（按拓扑） |
| 供应商接入 | Provider Adapter 注册 | 双角色注册；A 股→切换池候选；加密→SA4 拉起专属 hub |
| 账号增删 | external_interface 行 CRUD | A 股→池序变化；加密→hub 实例伸缩（先维护键后停，防反拉起） |
| 通道切换 | Web 拖 position | hub exit 9 自重启换网关（批 64 语义） |
| 供应商退役 | 注销注册 | 池摘除 / hub 回收；凭证行按用户操作 |
| 市场退役 | Market Adapter 注销 | hub 全回收（至今无场景，仅定义） |

## 五、与现状映射及迁移路径（增量，非重写）

| 模型构件 | 现状落点 | 迁移动作 |
|---|---|---|
| Provider 双角色注册 | `create_md_gateway` 注册表 + `_TD_BUILDERS`（分离） | 合并为 ProviderSpec 单点声明 |
| 馈送拓扑 | 散在代码（A 股固定 @quant/@quant2；SA4 加密特例） | 声明化进 Market Adapter |
| 交易时段 | `_in_bar_session(t, market)` 分支 + XTP 连接窗 | 收编为市场日历声明（A03 MarketHours 的实施落点） |
| 数据通道 | MinuteAggregator（bar 线） | 加 depth 透射线（L2 启用时） |
| 键空间 | `_key(base, account_id)` | 已参数化，原样收编 |
| 期望态（SA4） | scheduler 内 crypto 特例 | 按 Market Adapter 声明通用化 |

**迁移策略**：不突击重构——下一个自然触发点（L2 接入或期货接入）实施此架构，日常小步把 market 分支收敛为声明。

## 六、扩展场景验证（模型自检）

| 场景 | 动作 | 波及面 |
|---|---|---|
| 加 A 股券商 | 市场域下注册 provider | 零（进池） |
| 加密加账号 | 行 CRUD | 一个 hub（SA4） |
| 启用 L2 | astock 通道声明启用 | 同一 hub 加透射线 |
| 接期货 | 注册 futures Market Adapter | 一个新 hub + CTP provider |
| 换 A 股行情通道 | Web 拖 position | 零（hub 内切换） |

全部单点动作、跨市场零波及——通过。

## 七、范围外

- 本方案**不实施** A03 完整五层总线（L1-L5 路由/门面）——Market Adapter 是接入面的容器化，与总线正交。
- 双源并行（互备热切换/对账）不在此案——归 M7 质量闭环（批 62）讨论。
- D25 能力集/三层能力模型不受影响（正交维度：能力=品类、市场=域、provider=通道）。
