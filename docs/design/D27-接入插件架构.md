# D27 · 接入插件架构（端口 · 注册表 · 声明式规格 · 插件）

> **定位**：接入面的目标架构（"应该是什么"），替代 D26 §3.2 的"扁平 provider 插件"并补其缺口。
> **状态**：架构定稿（2026-11-10 用户两项决策确认）。**实施须独立立项、按批展开、每批双盲审**；D27 只定架构与契约，不改代码。
> **与既有文档关系**：A02（外部接口配置模型：行=账号/列=能力集）、A03（数据供给总线：能力模型/路由解析）、D25（三层能力模型）、D26（账号级 hub 拓扑/进程模型）。D27 承接 D26 的"provider 插件"意图，**新增两个正交层：声明式规格（MarketSpec/InstrumentSpec）与端口契约**，并回答"vnpy 放哪、规则放哪"。

## 零、两项核心决策（用户裁定 2026-11-10，硬约束）

1. **vnpy 收进插件内部**：`vnpy` / `vnpy_xtp` / 任何第三方 SDK 只允许出现在 provider 插件包内部；通用层（应用/编排/端口/规格/注册表）**不得 import vnpy**，也不得出现 vnpy 数据结构。
2. **交易规则用声明式数据，不用代码实体**：市场制度（MarketSpec）与品种规则（InstrumentSpec）是**数据/小表**，运营可改、不发版；代码只保留「插件实现（协议/连接）」与「规则消费方（组合器）」。规则的变化不应触发代码发布。

## 一、为什么重做（现状问题，证据锚点）

1. **provider 被劈成三截**：凭证=`Broker`（`broker.py`）、装配/建连=`td_registry.py` 的 `_build_xtp_runtime`/`_build_emt_runtime`、执行接口=`ExecutionAdapter`。账号相关功能没有封装在一个实体里。
2. **抽象重复**：vnpy `BaseGateway`（`send_order` 返 `vt_orderid`）与项目 `ExecutionAdapter`（`send_order` 返本地 `client_id`）两套并发抽象，外加 `_cid2vt` 映射成本。
3. **越过插件边界**：`vnpy_xtp.__all__=["XtpGateway"]`，项目却直接 `from vnpy_xtp.gateway.xtp_gateway import XtpTdApi`（内部类）+ 自写 `ThinTdGateway` 壳——依赖非公开 API，升级即炸。
4. **品种规则错放在 provider 维度**：171s 把 `close_action/close_reference_price/has_limit_band/...` 定价规则放在 `ExecutionAdapter`（provider 维度），但涨跌停/T+1/最小价位是**品种维度**——同一 XTP 下股票/ETF/可转债规则不同。
5. **规则硬编码/散落**：涨跌停幅度有 `band_rules` 表，但 T+1、可卖口径、订单类型、持仓方向、申报范围散在 `strategy.py`/`trading.py`/`risk.py`，改一处要发版。

## 二、目标与非目标

**目标**：任一「账号 × 标的」的交易能力，由「插件实现 + 声明式规格」组合得到；新增市场=加插件包，新增品种/规则=加数据行；通用层零 `if provider/品种` 分支；vnpy 不外泄。

**非目标**（本架构不解决，另立项）：期货/期权的组合保证金、期权定价与行权、跨境结算、撮合级仿真。D27 只保证这些**有扩展位**（见 §十）。

## 三、分层（依赖只向下，无反向）

```
应用层     strategy / risk / scheduler / web / IM
   │  只依赖 Ports + Registry（不认 provider、不认 vnpy）
编排层     hub(MD) / worker(TD) / 命令通道 / 生命周期调度
   │  零 provider 分支
端口层     ExecutionPort · MarketDataPort · AccountPort · HistoryPort   （Protocol）
   │
规则层     RuleSet = MarketSpec × InstrumentSpec × ProviderCaps        （声明式数据组合）
   │
注册表     REGISTRY: provider_id → Plugin(manifest + factory)
   │
插件层     providers/xtp/ · providers/emt/ · providers/ctp/ · providers/binance/ …
   │  每包自包含：凭证解析/连接/号段/连接窗/重连/字段映射/vnpy 适配
第三方     vnpy_xtp · XTP-SDK · binance-ws · okx …（仅插件内部可见）
```

**依赖规则（守门）**：`应用→端口`、`编排→端口+注册表`、`插件→端口+规格`；`端口/规格` 不 import `插件/第三方`；`应用/编排` 不 import `第三方`。加静态扫描守门（禁 `import vnpy` 出现在插件目录之外）。

## 四、四个正交维度 + 组合器

| 维度 | 问题 | 承载 | 形态 |
|---|---|---|---|
| **Market** | 日历/时段（日盘/夜盘/24×7）/竞价阶段/结算 | `MarketSpec` | 声明式数据 |
| **Instrument** | 涨跌停/tick/lot/T+/可卖/订单类型/持仓方向/申报范围 | `InstrumentSpec` | 声明式数据 |
| **Provider** | 协议/连接/字段映射/号段/连接窗/重连 | `ProviderPlugin` | 代码插件 |
| **Risk** | 仓位/回撤/频次/熔断 | 风控层 | 代码+配置 |

**组合器**（唯一把四者拼起来的地方）：

```
resolve(account, symbol, need) ->
    prov = REGISTRY.pick(account.provider, need)        # 能力协商
    ms   = MarketSpec.of(prov.market, symbol)           # 市场制度
    ins  = InstrumentSpec.of(symbol)                     # 品种规则
    rules = RuleSet(ms, ins, prov.caps)                  # 合成
    driver = prov.build(account)                         # 插件装配（含连接/号段）
    return driver, rules

place(account, symbol, intent):
    driver, rules = resolve(...)
    rules.validate(intent, tick)     # 涨跌停/tick/lot/T+/申报范围/订单类型/方向
    px = rules.reference_price(intent, tick)   # 定价（见 §6.3；171s 定价族归此）
    return driver.send(intent.with_price(px))
```

**关键**：定价/校验属 `RuleSet`（品种/市场维度），**不属 provider**——修正 171s 的维度错位。

## 五、端口契约（Ports，抽象；插件实现子集）

```
class ExecutionPort(Protocol):
    def capabilities(self) -> set[str]: ...                 # 支持子集
    def send(self, order: Order) -> OrderReceipt: ...       # 同步返回本地接收态
    def cancel(self, client_order_id: str) -> None: ...
    def query_positions(self) -> list[Position]: ...
    def query_account(self) -> AccountState: ...
    def query_orders(self) -> list[OrderState]: ...
    def query_trades(self) -> list[Trade]: ...
    def order_id_map(self, client_order_id: str) -> str | None: ...   # 本地号→venue 号

class MarketDataPort(Protocol):
    def subscribe(self, symbols: list[str]) -> None: ...
    def snapshot(self, symbol: str) -> Tick | None: ...
    def stream(self) -> Iterator[Tick]: ...                 # 或回调

class AccountPort(Protocol):
    def credentials(self) -> dict: ...                      # 插件内部解释，通用层不解析
    def health(self) -> Health: ...

class HistoryPort(Protocol):
    def fetch(self, req: HistoryRequest) -> list[Bar]: ...
```

- **不支持的能力**：`capabilities()` 不含即不调用；调用未实现方法**抛 `UnsupportedCapability`**（禁止空实现 no-op——D26 已点名"隐含必备=空实现陷阱"）。
- **领域模型**（`quant_common/domain`）：`Order/OrderReceipt/Position/AccountState/OrderState/Trade/Tick/Bar/Instrument`，纯数据、无第三方依赖。
- **异步查询同步化**：由插件内部完成（如 XTP 事件缓存）；端口对上层恒同步返回。

## 六、声明式规格（本架构核心）

### 6.1 MarketSpec（市场制度）

```
market: astock | hk | us | futures | crypto
trading_day_anchor: natural | utc0 | night_open
sessions: [ {name, begin, end} ]          # 日盘/夜盘/24×7 骨架
auction_phases: [open_call, continuous, close_call, after_hours]
settlement: T+0 | T+1 | T+2
currency: CNY | HKD | USD | USDT
channels: [bar, depth_snapshot, trade_tick, order_tick]
```
存储：`market_spec` 表（`market` 主键，`effective_from`，`source`，`version`）。运营可改，即时生效（缓存 TTL）。

### 6.2 InstrumentSpec（品种规则）

```
instrument_key: (exchange, category, board)        # 或 symbol 级覆盖
category: stock | listed_fund | convertible | perp | future | option
board: main | chinext | star | bse | null
price_band: { mode: pct | none | venue, normal, st, ref: pre_close | prev_settle }
tick_size: decimal
lot_size: int | contract
t_plus: int
sellable_rule: volume_minus_frozen | yesterday_only | any
order_types: [limit, market_best5, market_fak, ...]
position_side: long_only | long_short | net
price_range: { mode: venue | pct | none, lower, upper }   # 有效申报范围
venue_flags: { convertible_halt, after_hours_fixed, ... }
effective_from, source, version
```
- **优先级**：`symbol 显式覆盖 > (exchange,category,board) > (category) > 缺省`。
- **已有雏形可复用**：`security_master.category/board` + `band_rules(exchange×board→pct_normal/pct_st)` 直接并入 `InstrumentSpec`，不另起炉灶。
- **存储**：`instrument_spec` 表（按 `instrument_key` + `effective_from`），与 `security_master` 按 `vt_symbol` 关联。

### 6.3 规则合成（RuleSet）

```
class RuleSet:
    def validate(order, tick):        # 涨跌停价带、tick_size 对齐、lot 取整、T+1 可卖、申报范围、订单类型、方向
    def reference_price(intent, tick): # 平仓定价：有跌停线→跌停价；无→对手价按方向让价（171s 定价族迁此）
    def sellable(pos):                # 按 t_plus/sellable_rule 计算可卖
    def pre_trade_checks(...):        # 供风控调用的市场/品种前置约束
```
- **跨维度耦合显式合成**：如"有效申报范围"= `price_range`（品种）× `venue` 实际规则（市场），在 `RuleSet` 内合成，禁止各处自行判断。
- **不臆造**：规则缺失（该品种未配置）→ **fail-closed 明确报错**（不是静默用缺省），并在 UI 标"规则未配置"。

### 6.4 运营与 UI

- 表结构带 `effective_from/source/version`，支持"改规则不改代码"、"按日生效"、"来源审计"。
- 管理面：系统管理 → 交易规则（两个页签：市场制度 / 品种规则），按交易所+板块列表格编辑，改后即时生效（缓存失效）。
- 配置驱动原则沿用 A02「配置入库、`.env` 只放密钥」。

## 七、Provider 插件契约

### 7.1 manifest（唯一声明面）

```
id: "xtp"
capabilities: [trading, rt_quote, hist_quote, ref_data]
markets: [astock]
transport: "vnpy_xtp" | "sdk" | "rest_ws"
config_schema: [ {key, label, type, sensitive, required, default, validate} ]
session_policy: { mode: window|always, window_ref: "system:xtp_session", reconnect: {backoff} }
client_id: { mode: range, min: 2, max: 99 }        # 或插件代码分配
version_lock: "vnpy_xtp==2.2.32.2.3"               # 依赖边界显式化
```

### 7.2 插件包结构

```
server/src/providers/xtp/
  __init__.py        # 导出 plugin 实例（注册）
  manifest.py        # 上述 manifest
  plugin.py          # ProviderPlugin: build(account)->ExecutionPort/MarketDataPort
  _transport.py      # 内部：vnpy_xtp / XtpTdApi / ThinTdGateway / 连接窗 / 号段（全部私有）
  requirements.txt   # 该插件专属第三方依赖（可选）
```
**规则**：`_transport.py` 等私有模块可 import vnpy/SDK；`plugin.py`/`manifest.py` 不得向通用层泄漏第三方类型。

### 7.3 生命周期（统一接口）

```
class ProviderPlugin(Protocol):
    manifest: Manifest
    def build(self, account: AccountConfig) -> ProviderRuntime: ...  # 装配（凭证→连接→端口）
    def start/stop/health(self): ...
class ProviderRuntime:      # 一次账号装配的产物，含各端口实例
    execution / market_data / account / history（按 capabilities 提供）
```
编排层只调 `start/stop/health` + 端口方法，不解释连接窗/号段/重连（这些在插件 `session_policy`/私有实现）。

### 7.4 vnpy 内化原则（用户决策 1）

- 通用层**零 `import vnpy`**（静态扫描守门）。
- 插件内部可自由用 `vnpy_xtp`；若需 TD-only（如 hub MD / worker TD 分离），把 `XtpTdApi` 的使用**封在插件私有模块**，并**声明依赖内部 API + 版本锁**；建议项目自维护 `vnpy_xtp` fork（与 `vnpy-4.5.0+nogui` 同款做法），把 TD-only 入口固化为自己的稳定 API。
- 领域模型与 vnpy 解耦：插件边界做 `Order ↔ OrderRequest` 转换（现在 adapter 已做，收进插件）。

### 7.5 号段 / 连接窗 / 重连归属

- **号段**：`client_id` 在 manifest 声明策略，插件内部实现（XTP 1–99、EMT 1–127、加密无）。通用层不感知。
- **连接窗**：`session_policy`（window/always），插件内部判定；通用层只调 `health/start/stop`。
- **重连/退避**：插件内部（`session_policy.reconnect`）。

## 八、注册表与动态发现

- `REGISTRY: dict[provider_id, ProviderPlugin]`；`discover()` 扫描 `providers/` 目录（或 Python entry points）自动 import/注册。
- **能力协商**：`REGISTRY.pick(provider, need)` 校验 `capabilities ⊇ need`；不足 → `UnsupportedCapability`。
- **优先级**：同能力多插件时按 `manifest.priority` 排序（A03 路由思想的落点）。
- **热插拔边界**：新增/升级插件只影响其包；通用层零改。插件版本锁写在包内。
- **启动校验**：注册表加载后校验 manifest 完整性（id 唯一、capabilities ⊆ 合法集、config_schema 合法），失败 fail-fast。

## 九、与现有实现的映射（迁移分批；每批双盲审）

| 现状 | 目标归属 | 批次 |
|---|---|---|
| `quant_common/domain`（新建：Order/Position/Tick/…） | 领域模型层 | P1 |
| 端口 Protocol（Execution/MarketData/Account/History） | 端口层 | P1 |
| `REGISTRY` + `discover` + 启动校验 | 注册表 | P1 |
| `market_spec`/`instrument_spec` 表 + 迁移 + 管理面 | 规格层 | P2 |
| `broker.py` 的 `runner_client_id/build_xtp_setting/xtp_setting_from/get_xtp_param` | `providers/xtp/` 私有 | P3 |
| `td_registry._build_xtp_runtime`（ThinTdGateway/XtpTdApi/连接窗） | `providers/xtp/` 私有 | P3 |
| `td_registry._build_emt_runtime` + `EmtAdapter` 连接/号段 | `providers/emt/` | P4 |
| `adapters.py` `ExecutionAdapter` 的通用部分 → 端口；`close_*` 定价族 → `RuleSet` | 端口层 + 规则层 | P3/P2 |
| 加密 `CryptoPerpAdapter` + stub 分支 | `providers/binance|okx/`（gate 开前实现+单测） | P5 |

## 十、边界、风险与扩展位

- **期货/期权**（保证金/组合/平今平赎/交割/行权）：`InstrumentSpec` 留 `derivative_flags` + 插件专用子规则扩展位；**不在本架构首批实现**，需独立验证（其复杂度不能按 ETF 对待）。
- **vnpy_xtp 内部 API 依赖**：用版本锁 + 插件私有模块隔离；建议自维护 fork。
- **迁移期双轨**：新旧路径并存期间，必须"同账号只能一套生效"（防双写/双下单），由 `REGISTRY` + 账号行唯一 provider 保证。
- **回测/paper**：`ExecutionPort` 增加 `BacktestExecutionPort`/`PaperExecutionPort` 实现，与实盘同接口（复用现有 BacktestEngine/paper_mode 语义）。
- **规则数据来源**：`InstrumentSpec` 可由 `security_master`/交易所公告同步生成，但**最终以表为准**（可人工覆盖 + 审计）。

## 十一、验证（守门，行为级）

- **S1 解耦**：静态扫描——`server/src` 除 `providers/` 外**零 `import vnpy/vnpy_*`**；端口/规格层零第三方依赖。
- **S2 零分支**：编排层/端口层源码无 `provider ==` / `if "xtp"` / `if category ==` 字面量（AST 扫描）。
- **S3 能力协商**：请求不支持能力 → `UnsupportedCapability`（禁 no-op）；多插件按 priority 选中。
- **S4 声明式规则**：改 `instrument_spec` 一行（如 tick_size/涨跌停）→ 行为随之变、**代码零改**（真库+行为断言）；规则缺失 fail-closed。
- **S5 组合器**：`RuleSet.validate/reference_price` 三品种矩阵用例（股票/ETF/可转债/加密）各断言正确（含 171s 定价族迁移后的等价性）。
- **S6 动态插拔**：新增一个假插件包（`providers/_fake/`）→ `discover()` 自动注册、可被路由命中；删包即消失。
- **S7 迁移等价**：XTP 插件化后，与旧路径同输入产出**同结果**（订单字段/号段/回报映射逐项对比）。
- **S8 生命周期**：连接窗/号段/重连由插件内部决定，编排层无感知（断言编排层无相关字段）。

## 十二、开放问题（实施前需定）

1. 领域模型是否完全自建，还是允许"插件边界用 vnpy 模型、端口内转"（本稿按自建，成本在 P1）。
2. `instrument_spec` 粒度：`(exchange,category,board)` 够不够，是否要 symbol 级覆盖表（预计需要）。
3. 规则热更新的缓存失效机制（TTL vs 发布事件）。
4. 期货/期权的 `derivative_flags` 子规则如何与插件协作（首批不实现，但接口要先占位）。
5. 迁移期是否允许"XTP 走新插件、EMT 仍走旧路径"长期并存（建议限定一个版本窗内完成）。
