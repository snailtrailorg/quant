## 0. 术语

| 词 | 定义 |
|---|---|
| **sync_id** | `sync_config` 一行 id（如 `listed_fund_daily`）；不是能力真源 |
| **kind / sub_kind** | DataKind 能力键（`bar_daily` / `stock`\|`listed_fund`\|`convertible`） |
| **游标** | `sync_config.last_sync_date`：下次增量起点（加速器，不是正确性依据） |
| **窗口** | `[下界, 上界]`，一次同步/对账实际核算的日期范围 |
| **期望集** | 窗口内应有数据的日期集合＝日历 ∩ 边界 − 豁免 |
| **实际集** | 窗口内实表覆盖的日期集合 |
| **缺口** | 期望集 − 实际集，按连续段（区间）表达 |
| **锚** | 缺口段起始日；`sync_gap` 唯一键 `(sync_id, symbol, gap_start)` |
| **轮次** | `reconcile:round`（Valkey `INCR` 严格单调） |
| **deferred** | 数据尚未就绪（空帧/低覆盖）的日期：**未判定**，不是缺口，也不是成功 |

## 1. 三条执行面

### 1.1 增量（`engine.sync`，353）

1. `SyncLock(sync_id)`（Valkey NX + 60s TTL + 20s 心跳）互斥。
2. `end_date = today`（378）——无数据可用门。
3. 路由：`_VIA_KIND_IDS` → `_sync_via_kind`；否则 `_HANDLERS`。
4. `_sync_via_kind`：`start > end_date` 时**早退返回 0/0**（3033）。
5. 游标（443-460）：有 `last_success_date` 者——全失败不动／部分失败推至连续成功末日／否则推 `end_date`；无该键者——`cursor_upto or end_date`。
6. 收尾：`excluded` → `sync_gap`；本轮新 open 聚合告警（只响新增）。

### 1.2 回补
`backfill_from` 非空 ⇒ 不推进游标（462）。

### 1.3 对账（三层）

| 层 | 实现 | 窗口 | 粒度 | 触发 |
|---|---|---|---|---|
| per-date | `_reconcile_dates`（2249） | 本轮同步窗口 | 日期级 | handler 收尾内联 |
| per-symbol | `_reconcile_symbols`（2390） | 每标的 `[floor, end]` | 标的级 | 周日 03:33 |
| 连续性 | `data_continuity_check`（tasks.py:554） | 近 7 日 | 标的级计数 | 每小时 :17 |

per-symbol 覆盖＝`_RECONCILE_SYMBOL_SCOPE`（1581）：当前只含加密 perp 与 A 股分钟族（分钟族 sync_config 已 disabled ⇒ 实际只覆盖 crypto）。

## 2. 窗口模型

### 2.1 下界（`_window_floors`，1105）

```
floor = max(inception, retention, source_earliest)
```
- `inception`＝`security_master.list_date`（NULL＝显式未知）
- `retention`＝`sync_config.retention`（日期型）
- `source_earliest`＝`adapter.available_range(kind)[0]`（未实现即抛）
- 排除段：`[inception, source_earliest)`→`unreachable`；`[已知下界, retention)`→`policy_discard`
- **未接入**：`sync_config.retention_days`（0164，仅清道夫与 Web 消费）

### 2.2 上界

| 族 | 上界 | 位置 |
|---|---|---|
| crypto perp | `min(end_date, today(UTC) − publish_lag)` | `_crypto_end`（1182） |
| A 股/基金/转债/指数 | `end_date`＝今天 | `sync()`（378） |
| T+1 按 trade_date 族 | `_data_ready_end_date(lag_trade_days)` | 293 |

调度默认 `30 16 * * 1-5`；实际存在 09:43 手动补跑（`sync_log` 有记录）。上界恒为「今天」⇒ 早于发布时刻运行必产空帧（D1）。

## 3. 缺口状态机（`sync_gap`，0140）

### 3.1 五态（`SYNC_GAP_STATES`，1558）

| 状态 | 含义 | 进入 | 退出 |
|---|---|---|---|
| `open` | 已检出未补齐 | 本轮现算锚且无行 | 确证补齐 |
| `closed` | 已补齐 | 锚不在本轮现算集 | 重开（新事件） |
| `unreachable` | 源不可达（非缺口） | 排除段登记 | 只告警不改写 |
| `policy_discard` | 主动不保留（非缺口） | 排除段登记 | 只告警不改写 |
| `uncertain` | 期望集不可信 | 日历未覆盖/本地不可读/快照过期/inception 未知 | 覆盖恢复 |

### 3.2 视图式集合差（`_sync_gap_sync`，1955）

```
锚 ∈ 现算集 → 对齐（gap_end/last_seen/hit_rounds）
锚 ∉ 现算集 → closed
本轮有锚、库无行 → open
本轮有锚、库内 closed → reopen
该 symbol 未现算 / gaps=None → touch（只刷 last_seen）
```

预算 `_GAP_ROW_BUDGET={bar_daily:5000, bar_minute:50000}`（1624）：超阈 ⇒ **整 scope 不主张** + 告警 + 判据不过门。

## 6. 缺陷（带证据）

### D1 空帧/低覆盖＝成功，游标越过未发布日
`_pull_day` 空帧 `(0,0)`（2865）；无异常即更新 `last_success_date`（2884）；`sync()` 推 `end_date`（450）。
**实证**：
```
10-14 09:43  etf_daily  start=20261013 end=20261014 rows=2161 success exp=2 act=2
10-14 09:43  cb_daily   start=20261013 end=20261014 rows=314  success exp=2 act=1
10-14 21:03  etf_daily  start=20261015 end=20261014 rows=0    success exp=0 act=0
10-15 16:35  etf_daily  start=20261015 end=20261015 rows=2167 success exp=1 act=1
```
`etf_daily` 两日窗口仅拉到一日量；`act` 两族口径不同（日线批＝窗口长−异常数；cb＝expected−gap_dates），故 `act=2` 只能证明「未抛异常」，不能证明「有数据」——这正是缺陷本身。`cb` 的 `act=1` 说明它**已发现** 10-14 缺，但 `sync()` 只看 `failed_dates`。
**至今**：10-14 基金/转债仍 0 行。

### D2 窗口外锚被 closed（洞被遗忘）
closed 分支不看窗口（2066-2074）；per-date 现算集只含本轮窗口 ⇒ 10-14 的 open 行次日被 closed。
**实证**：`etf_daily`/`cb_daily` 的 10-14 行 `state=closed`、`closed_at=10-15 16:35`、`pull_count=0`。
**注**：`listed_fund_daily` 10-26 的 gap 行 10-27 闭合是**合法**（窗口覆盖且补了 4346 行），不可作反例。
**真因补充**：`_repullable_map` 读的是写前 `prev_map`（2501），touch 不会饿死重拉；窗口外 open 既不关闭也不修复，根因是「无跨窗口修复出口」+ `pull_count>=3` 停手。

### D3 A 股日线族无 per-symbol 对账
`_RECONCILE_SYMBOL_SCOPE`（1581）无 `astock_daily`/`listed_fund_daily`/`cb_daily` ⇒ 单日多数标的缺不可见。

### D4 读取无界
`_local_dates_map`（1814）无下界、无 DISTINCT、`fetchall()` 全拉；`_local_dates`（1795，per-date）同样无下界。stock 5,577 只 → 13.88M 行（dev 实测），worker `MemoryMax=1600M`。

### D5 预算整 scope 抑制
首轮全史窗口 29,853 段 > 5,000 ⇒ 整 scope 不主张。**且 5,000 < stock 5,577 只**——即便只缺一天，stock scope 也必然超阈（结构性失效）。

### D6 日线族无可用修复原语
`_repull_symbol`→`fetch_supply`，`_SUPPLY_PULL` 无 bar_daily（`base.py:577`）⇒ `UnsupportedFeature`；consume 面可逐标的但**复权口径不同**，不可混写。

### D7 退市后仍算缺
`_sm_universe`（2347）只取 `list_date`；转债 827/1176 有退市日 ⇒ 假缺口；listed_fund `delist_date` 全 NULL（`_sync_etf_list` 写 None，780）。

### D8 停牌未剔除
长停牌股（000002.XSHE 2015-12~2016-07）恒 ~96%。

### D9 `retention_days` 未进窗口
清道夫按 `(table,source)` 删（同表多配置取**最短** N），窗口不读该列 ⇒ 可能主张已删区间。

### D10 「修复成功」不可证
`save_bars*` 返回 `len(rows)`（校验后、冲突前）。

### D11 空窗口早退＝成功
`start > end_date` 直接返回 0/0（3033）；`sync()` 走 else 分支按 `cursor_upto or end_date` 推进 ⇒ 游标**可能回退**到 end_date。

### D12 无锁并发写
`_reconcile_symbols`（周日）与 `data_continuity_check`（每小时）直接写 bar 表。

### D13 consume 口径污染 `bar_1D`
`data_continuity_check` 用 `pull_daily`（默认无复权）→ `to_bar_rows` → `save_bars`（tasks.py:600-630）；`save_bars` 是 DO NOTHING ⇒ 先写的 NULL `adj_factor` 永久锁死同键。**dev 实测 10-13：全表 8,946 行中 8,943 行 `adj_factor IS NULL`**。

### D14 退役 id 的孤儿缺口行
`etf_daily` 已正名（`listed_fund_daily`，迁移 0150），`sync_gap` 仍留其 10-14 行；无迁移/清理路径。

## 7. 第一批（171a）的精确设计——**只做「不遗忘」与「不越界」**

> 本批**不改检测范围、不改修复能力、不动预算**。目标：让系统不再自己涂掉证据。

### 7.1 A1 窗口化状态迁移（修 D2/I2/I4）

`_sync_gap_sync` 增加必填参数 `scope_map: {symbol: (win_lo, win_hi)}`（复用现有 `win_map`），并对**三个分支**统一夹取：

| 分支 | 现行为 | 改为 |
|---|---|---|
| 对齐 | 一律更新 | 仅当锚 ∈ 窗口才更新；窗口外**不写** |
| closed | 一律关闭 | 仅当 `win_lo ≤ 锚 ≤ win_hi` 才关闭；窗口外**不写** |
| uncertain | 全部 live 行转 uncertain | 仅窗口内行转；窗口外**不写** |
| touch | 刷 last_seen | 仅窗口内行刷；窗口外**不写** |

跨窗口合并：若窗口内缺口段与某窗口外 live 行区间**相交或相邻**，则对齐该行并取 `gap_end = max(旧, 新)`，不新开锚（防重复行、防缩窄）。

### 7.2 A2 deferred 通道（修 D1/I1）

**语义**：`deferred`＝数据未就绪的日期，既不是成功也不是缺口。

1. **迁移**：`sync_log` 增列 `deferred_dates text[]`（默认 `{}`）。
2. **handler**：逐日批与整段拉取（`cb_daily` 按返回 frame 的日期分组）都按日评估——行数 0 或 `count(distinct symbol) < 本轮其他成功日中位数 × 50%`（单日轮次取 `sync_log` 最近成功日均值）⇒ 记入 `deferred_dates`，**不计入 `failed_dates`**。
3. **游标**：`sync()` 计算 `advance_to = min(deferred_dates) 的前一交易日`（无则用 `last_success_date`/`end_date`）；有 deferred ⇒ 状态记 `partial`、游标停在该日之前，**绝不越过**。
4. **对账**：`_reconcile_dates` 新增 `deferred` 参数——deferred 日**从 expected 剔除**，同时作为 `skip_anchors` 传给 `_sync_gap_sync`（这些锚本轮**既不 open 也不 close**，只保持原状），避免「剔 expected ⇒ 误 close」（上一稿的坑）。
5. **K 轮退出**：Valkey 键 `defer:<sid>:<yyyymmdd>`，按**交易日**计数（同日重复不增，`INCR` + `EXPIRE NX 7d`，成功 `DEL`）；>3 个交易日仍 deferred ⇒ 移入 `failed_dates`（进入 expected ⇒ 产生缺口与告警），防上游永久停更导致静默冻结。
6. **失效方向**：Valkey 不可用 ⇒ **fail-loud**（按 failed 处理并告警），不得静默 deferred。

### 7.3 A3 对账持锁（修 D12）

`_reconcile_symbols` 逐 scope 持 `SyncLock(sync_id)`（取不到即跳过该 scope 并记录）；`data_continuity_check` 同样按 scope 持锁。**本批不改 `data_continuity_check` 的取数口径**（D13 属 171c）。

### 7.4 明确不并入 171a

| 项 | 原因 |

| R5 修复原语（按日批） | 需同时切 `data_continuity_check` 的 consume 口径（D13），否则修复即污染 |

## 8. 171a 验收（可证伪）

1. **不遗忘**：造 `listed_fund_daily` 在 10-14 的 `open` 行（或迁移 D14 的孤儿行）→ 跑次日窗口对账 ⇒ 该行仍 `open`、`last_seen` **未变**、`closed_at` 为空；连跑 3 日仍 `open`。
2. **不越界推进**：把 `last_sync_date` 重置为 10-13、造 10-14 空帧 → 跑增量 ⇒ `last_sync_date` **仍为 10-13**，`sync_log.status='partial'`、`deferred_dates=['20261014']`；恢复数据后次日自动补齐、游标推进。
3. **cb 路径**：同一场景对 `cb_daily`（整段拉取）复测，行为一致。
4. **K 轮退出**：连续 4 个交易日空帧 ⇒ 第 4 日转 `failed_dates` 并告警（证明不静默）。
5. **不误关**：`sync_gap` 中窗口外的既有 open 行，跑一轮后状态与 `last_seen` 均不变（SQL 前后快照比对）。
6. **并发**：`_reconcile_symbols` 与 16:30 增量同时触发 ⇒ 一方 `skipped`，无重复写。
7. **守门**：`test_batch109_sync_gap.py`（如需改断言，在任务文件逐条列明）、`test_layering.py`、`test_route_auth_gate.py` 全绿。
