# D28 · 数据收敛与对账

> 立 2026-11-05；**两轮双盲审后整篇重写（v3）**。v1 被否＝另造状态机（换皮）；v2 被否＝把既有三层能力当成零散启发式，重写了一遍并写错事实（状态名/唯一键/窗口/接线）。
> 一句话：**收敛能力不是新建一套对账，而是把既有对账体系的覆盖范围补齐 + 把修复粒度从「按标的」补成「同日聚批」。**

## 一、事实基线（既有能力，全部复用，不重写）

| 能力 | 位置 | 说明 |
|---|---|---|
| 缺口状态机（五态） | `sync_gap` / 迁移 0140 / `SYNC_GAP_STATES` | `open`（待补）`closed`（补齐）`unreachable`（源不可达）`policy_discard`（主动不保留）`uncertain`（期望集不可信）；`hit_rounds/last_hit_round/pull_count` 支撑「连续 N 轮」判据 |
| 视图式集合差同步 | `_sync_gap_sync`（scope 级，一次读 live 行 + 内存集合运算 + executemany） | 成本＝O(scope 数)，与标的数无关；**禁止 ON CONFLICT 盲合并**（会污染命中计数） |
| 按日对账（内联） | `_reconcile_dates`（`sync()` 收尾） | 逐**交易日**差集——只能发现「这一天整体没数据」 |
| 按标的对账（旁路） | `_reconcile_symbols`（周日 beat） + `_RECONCILE_SYMBOL_SCOPE` | 逐标的下界＝`_window_floors`（inception/retention/source_earliest 取 max）、上界＝`end − publish_lag`；含 uncertain 两道门（inception 未知 / SM 快照过期）、预算、限频重拉、聚合告警 |
| 连续性巡检（小时） | `data_continuity_check` | 近期逐标的检测 + 逐标的补采 |
| 写路径 | `save_bars`（跳过）/ `save_bars_overwrite`（覆盖）/ `validate_bars` | — |
| 并发 | `SyncLock(sync_id)` | 同步/回补互斥 |

## 二、真实缺口（只有三条）

1. **A 股日线族不在 per-symbol 对账 scope 里**。`_RECONCILE_SYMBOL_SCOPE` 只有加密 perp 与 A 股分钟线；`astock_daily` / `listed_fund_daily` / `cb_daily` / `index_daily` 缺席 ⇒ 单日「多数标的缺」这类事故（2026-10-14：2470 只缺 1 天、当日仅 11 只真停牌）**只有按日对账能看见「这天有数据」，看不见「这天有 2470 只没有」**。
2. **修复粒度是 per-symbol**。同一交易日 2470 只缺 ⇒ 2470 次请求（daily 档 0.5s/次 ≈ 20 分钟），限速下跑不完——这正是现有小时巡检「检测到、补不完」的原因。而引擎**已有**按日全市场批量原语（`_pull_day` → `fetch_supply(symbols=(), start=day, end=day)`），只是没接进修复路径。
3. **期望集缺两类边界**：①停牌/上市前/退市后未剔除（把「合法没有」报成缺）；②A 股上界缺「最近已收盘交易日」语义（`publish_lag` 基类默认 0 ⇒ 盘中/盘后立刻跑会把当日算缺）。

> 结论：**不改状态机、不改表（只增 `suspend_event`）、不新增分层与调度档**。改动集中在「scope 一行行加」「上界函数」「修复前的同日聚批」「期望集减豁免」。

## 三、方案（四个最小改动，逐条可独立上产）

### 改动 1：scope 扩到 A 股日线族（检测能力）

`_RECONCILE_SYMBOL_SCOPE` 增加：

```
astock_daily        (bar_daily, None, '1D', 'bar_1d', 'Asia/Shanghai', 'stock')
listed_fund_daily   (bar_daily, None, '1D', 'bar_1d', 'Asia/Shanghai', 'etf')
cb_daily            (bar_daily, None, '1D', 'bar_1d', 'Asia/Shanghai', 'convertible')
```

- `index_daily` **暂不纳**：`security_master` 无「指数」category（0092 只有 stock/etf/convertible/fund/reits/perp），无 universe 就无法判定「应该有谁」——强纳＝假缺口。
- 上界：新增 `_session_end(today, tz, close='15:30')`——A 股取「最近已收盘交易日」；加密仍用现有 `_crypto_end`（D-1 口径）。盘中/收盘后立刻跑都不会把当日算缺。
- 下界沿用 `_window_floors`（不二算）。

### 改动 2：期望集减豁免（精度）

新增 `suspend_event(ts_code, trade_date, suspend_type, suspend_timing)` + 同步项 `suspend_cal`（tushare `suspend_d`，按 `trade_date` 日增量，回补按日期分片 ≤5000 行/次）。

期望集 = 交易日 ∩ [下界, 上界] − 全天停牌日 − 上市前/退市后。

- 停牌只剔除**全天**（`suspend_timing IS NULL`）；半天停牌当日仍有 bar，不剔除。
- 豁免数据缺失的标的域（场外基金等无 suspend 覆盖）⇒ 契约声明 `degraded_exempt`，报告中显式标注「该族未接豁免」，不静默。
- **不需要新状态**：豁免日在期望集里就不存在 ⇒ 不产生 gap 行，天然不告警、不重拉。

### 改动 3：修复前「同日聚批」（效率）

修复候选 = `sync_gap` 中 `open` 且可重拉的段。执行前先做一次编译：

1. 按 `(sync_id, trade_date)` 聚合：同一交易日有 ≥K 只标的缺 ⇒ 合并成 **1 次按日批**（`_pull_day`，全市场一次拉）。
2. 剩余（长区间、单标的）⇒ 沿用现有 `_repull_symbol`（按标的区间）。
3. 批次数受既有 `_GAP_REPULL_MAX` 与 `_GAP_ROW_BUDGET` 约束；超出部分留待下轮（gap 行仍是 `open`，状态不丢）。

修复写入：缺日补写用 `save_bars`（跳过已存在）；覆盖场景（污染行）用 `save_bars_overwrite`；两者都以**实际影响行数**记账（`save_bars` 现返回 `len(rows)`，需一并改为 `cur.rowcount`——独立小改，放 171c 前置）。

### 改动 4：只报不修的观察档（安全）

新增开关 `system_config.reconcile_repair_enabled`（默认 `false`）：关时只写 `sync_gap` 与轮次摘要（沿用既有 `_log_scope_summary`），不调用任何取数。用于：①新 scope 首轮观察；②事故期避免与增量抢配额。

## 四、明确不做

- 不新建缺口表/状态（`sync_gap` 五态唯一；`reconcile_run` 不建，轮次摘要沿用既有 `sync_log` 与 `_log_scope_summary`）。
- 不新写取数（复用 `_pull_day` / `_repull_symbol` / `fetch_supply`）。
- 不新建调度档（复用周日 `data_gap_reconcile`；A 股日线族随该轮次跑）。
- 不做跨源逐值比对、复权因子收敛、流式对账。
- `index_daily`、场外基金暂停纳入（缺 universe / 缺豁免源）。

## 五、验收（可证伪）

1. **检测**：dev 删除 `2026-10-14` 全市场 A 股日线 → 周日轮（或手动触发）报告该 scope `new_open` 段数 ≈2470 只/1 天；`reconcile_repair_enabled=false` 时**零取数**（请求计数为 0，业务表行数不变）。
2. **修复**：开开关后同一场景 → 请求数 **1**（同日聚批）、该日补齐、`sync_gap` 对应行转 `closed`；再跑一轮 `new_open=0`（幂等）。
3. **停牌不误报**：`000002.SZSE` 2015-12~2016-07 停牌段在 `suspend_event` 覆盖后不产生 gap 行。
4. **不打架**：与增量同时跑不死锁；`SyncLock` 互斥生效。
5. **守门**：`test_batch109_sync_gap.py`（禁跨模块写 gap）、`test_batch110_reconcile_scale.py`（读取规模）、`test_layering.py`、`test_route_auth_gate.py` 全绿。
