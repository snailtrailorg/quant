# D31 · 窗口模型统一（地板 / 增量 / 回补三态）

> **性质**：模块设计（纯知识，D 系列编号）。批 171 阶段③下一条（2026-11-06 用户裁定立项：171c 腿 2/3 吸收进本设计）。
> **依据**（引用 ≤2）：`docs/design/D30-同步缺陷账本.md`（DEF-02 空窗 success/DEF-16 日历覆盖门）、`docs/design/D29-同步机制事实清单.md` §五（窗口/地板机制）。
> **状态**：v1 待双盲审。
> **前置（步 0）**：trade_cal 全史回补（1990-12-19 → 今）——本设计的空洞检查/覆盖感知全以交易日历为坐标，prod 现仅 2026 年（历史窗 freq=B 退化实证，suspend 回补实测）。

## 0. 问题与目标（一句话）

窗口语义散落三处（地板=任务级 retention / 增量=游标+overlap / 回补=backfill_from 全段重拉），三者**从未对齐成一个模型**——静默截断、游标与数据分叉、回补无空洞感知、冷启动一次惊险马拉松。本设计统一为「**一个窗口函数，三种参数**」，并把用户五条裁定落为结构。

**用户裁定原文要义**（2026-11-06 午后讨论，全部采纳）：
1. 地板可设置、全局、对所有任务类型生效；回补段早于地板的部分不回补（地板优先级最高）
2. 稀疏事实表（无可回补判据）与稠密族**分别处理**——稀疏族回补＝整窗幂等重放
3. 尾巴＝上次同步到当前的缺口；**同步自身必须保数据-游标一致**（上次失败 ⇒ 下次正常同步自愈补齐，不能丢了就丢了）；只查最后数据点，中间空洞靠显式回补（每轮全面检查不可接受）
4. 「最后数据点当同步依据、不设单独游标」——按族分轨采纳（稠密=派生、稀疏=外置+成功闸，见 §3）
5. 单轮最大跨度配置（如 1 年）——冷启动分 N 轮平稳跑完，放缓脚步换稳定

## 1. 统一窗口函数（§2~§5 的骨架）

```
窗口 = [max(地板..., 起点), min(终点, 起点 + 最大跨度)]

起点：增量轮 = 游标+1−overlap；回补轮 = backfill_from
终点：增量轮 = 数据就绪日；回补轮 = 请求终点（默认=数据就绪日）
```

一个纯函数、三种参数组合——冷启动（地板远+跨度切轮）、增量（尾巴小窗）、回补（显式段+空洞检查）**同机制不同参数**，不是三套代码。所有窗口计算收敛到 `_window_floors`（engine.py:1141，已是三方取 max 的单一真源）+ 本设计新增的跨度夹取——**禁第二处窗口算式**（判定单源纪律的窗口版）。

## 2. 地板全局化（裁定 1）

- **模型**：`system_config` 新键 `sync_floor_default`（全局默认日期）＋ `sync_config.retention`（任务级覆盖，**现列不动**——为空 ⇒ 回落全局默认；非空 ⇒ 胜出）。
- **取值链**：`任务 retention ?? 全局 sync_floor_default ?? kind 默认（现状）`——已有 `_window_floors` 的 retention 臂加一层回落，其余两臂（inception/source_earliest）不动。三方取 max 语义不变：**全局地板是第四块地板，不是替换**（per-symbol 的 inception 更晚时仍胜出——标的晚上市不该被全局地板拖到更早）。
- **配置面**：设置页（运行配置 tab）可改全局键（`system_config` 既有读写口）；任务级 retention 维持迁移层变更（策略列不入 Web 白名单——批 108 裁定延续，但见 §5 显性反馈消其暗坑）。
- **迁移**：无需新表——一列 system_config 行 + 首值建议 `1990-12-19`（最深的源界；各任务实际地板仍由自身 retention/源界顶住，全局键只兜「未声明」的）。

## 3. 尾巴自愈与游标分轨（裁定 3+4）

**统一纪律**：数据落后于游标＝错误态；每轮增量**必须**自愈尾巴，不依赖显式回补。

- **稠密族**（bar/按日快照——有「应有而未有」判据）：
  - **游标派生化**：`last_sync_date` 不再独立存储推进，改为 `游标 = max(local date)` 派生读值（数据即真相，结构上消灭分叉——裁定 4 对稠密族完全成立）。
  - **尾巴检查**＝每轮窗口内日期差集（`_reconcile_dates` 现机制，非全表扫——裁定 3 的效率边界）；差集命中 ⇒ 内联重拉（现有）；重拉仍缺 ⇒ 落 sync_gap 主张 + 游标（=max local）天然不越过缺口（**D1 cursor_cap 语义被结构吸收，Valkey cap 退役**——稠密族不再需要）。
- **稀疏事实表**（suspend/st_list 型——0 行/日是正常态，`max(local)` 推不出扫描进度）：
  - **外置游标保留 + 成功闸**：游标推进条件从「拉完」收紧为「**窗口内期望日全部成功**」（failed_dates 空）；有失败 ⇒ 游标停在最后连续成功日（D1 cap 语义的稀疏版，但无 Valkey——纯游标不推）。
  - **尾巴检查退化**为整窗幂等重放（overlap 即尾巴，宽 overlap=3 天现有）；中间「空洞」无判据、不检查——回补靠显式重放（§4）。
- **分轨声明表**（设计内显性列出哪些 sync_id 走哪轨——评审防「一刀切」）。

## 4. 回补与空洞检查（裁定 2）

- **稠密族**：`backfill_from` 到请求终点的**日期差集**驱动重拉（expected 来自 trade_cal——步 0 前置的原因）；已有行不动（幂等）。走 `_GAP_ROW_BUDGET` 预算闸（bar_daily 5000/bar_minute 50000 行/轮，engine.py:1673 现值）——超阈告警不硬冲。
- **稀疏族**：无空洞概念——回补＝`backfill_from` 起的**整窗逐日重放**（suspend 13 年回补即此形态，幂等验证过）。同样受跨度切轮（§5）。
- **地板截断**：请求起点 < 有效地板 ⇒ **执行被夹部分**（地板优先，裁定 1）＋ §5 显性反馈。

## 5. 单轮最大跨度（裁定 5）

- **配置**：`system_config` 键 `sync_max_span_days`（全局默认，建议 366）＋ `sync_config` 新列 `max_span_days`（任务级覆盖，NULL=回落全局；迁移加列，配置页可见）。
- **夹取**：`终点 = min(请求终点, 起点 + 最大跨度)`——§1 统一函数的一臂。轮次衔接：本轮游标推到「实际终点」⇒ 下轮自动从断点续（增量轮天然；回补轮由用户/任务重复触发，返回体带 `truncated: true + next_from` 供链式续跑）。
- **收益**（冷启动稳定性）：全量时限预算可配（2400s 软限 × 分轮 ≈ 每轮 1 年窗），失败半径=单轮；**成本**＝一个夹取参数＋一列配置。

## 6. 显性截断反馈（今天踩坑的直修）

- 任何窗口被地板/跨度夹取 ⇒ 返回体与 sync_log note 必带 `clamped: {floor: "20140101", span: true}` 类结构；前端触发回补时若被夹，**提示而非静默**（现状静默夹取——suspend 回补被 retention 坑的根因）。
- fail-open 留痕纪律（批 171 教训）适用于本设计所有容错路径。
