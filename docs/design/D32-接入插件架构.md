# D32 · 接入插件架构（可插拔 · 端口 · 五维规格 · 部署分片）

> **定位**：接入面的目标架构（"应该是什么"）。取代 D26 §3.2 的「扁平 provider 插件」，并补其缺口。
> **状态**：架构定稿（2026-11-11 四审后重写）。**实施须独立立项、按批展开、每批双盲审**；D32 只定架构与契约，不改代码。非结构化研究子域纳入统一规划、实现记待办。
> **重写说明**：本稿是四审（架构正确性 / 可实施性 / 一致性 / 红队）后的整篇重写，非增量补丁。审报告见 `flow/审计/2026-11-11-D32四审并帧.md`。原稿的 `market_spec`/`instrument_spec` 新表、`build(account)` 单入口、`REGISTRY` 并列注册、热插拔承诺均已撤销。
> **与既有文档关系**：A02（外部接口配置）、A03（数据供给总线）、D25（三层能力模型）、D26（账号级 hub 拓扑）、A06（部署管道）。**结构化数据供给归 A03，D32 引用不重造**。

## 零、决策与裁定

### 0.1 用户裁定（2026-11-10，硬约束，不变）

1. **vnpy 收进插件内部**：`vnpy` / `vnpy_xtp` / 任何第三方 SDK 只允许出现在 provider 插件包内部；通用层（应用/编排/端口/规格/注册表）不得 import vnpy，也不得出现 vnpy 数据结构。
2. **交易规则用声明式数据**：市场制度与品种规则是数据，运营可改、不发版。代码只保留「插件实现（协议/连接）」与「规则消费方」。

### 0.2 本稿裁定（2026-11-11，用户确认）

3. **可插拔，不是热插拔**。插件随 release 交付；「可插拔」的验收定义是 **新增 provider = 加一个目录 + 一行注册 + 一次发布，核心文件零改动**。不承诺运行中动态装卸。理由：证券交易需要慎重决策与长期稳定，行业无热插拔需求；本仓部署单元是 release（A06 版本树不可变、venv 跨 release 共享），进程不重扫插件。
4. **五维**：Market × Instrument × Provider × Risk × **Account**。Account 承载「这个账号能做什么」（准入/资金/授权/停牌态），与 Risk（「策略想做什么」）正交。
5. **部署可分片**：一个部署只装载若干市场。边界由**市场**定义，不由插件定义。

## 一、为什么重做（现状问题，证据锚点）

1. **provider 被劈成三截**：凭证=`Broker`（`broker.py`）、装配/建连=`td_registry._build_xtp_runtime`、执行=`ExecutionAdapter`。账号相关功能没有封装在一个实体里。
2. **同一 provider 概念有 8 处注册点**：`data_source._REGISTRY`、`adapters/base._ADAPTERS`、`interfaces/base._PROVIDER_MODULES`、`md_gateway._REGISTRY`、`td_registry.TD_BUILDERS`、`broker._REGISTRY`、`create_adapter` 映射、`markets` 四张能力表。`data_source.py` 的报错文案自己写着「加新源须三处各注册一类」——这就是「现在不可插拔」的实证。
3. **越过插件边界**：`vnpy_xtp.__all__=["XtpGateway"]`，项目却直接 `from vnpy_xtp.gateway.xtp_gateway import XtpTdApi`（内部类）+ 自写 `ThinTdGateway` 壳——依赖非公开 API，升级即炸。
4. **品种规则错放在 provider 维度**：171s 把 `close_action/close_reference_price/has_limit_band/...` 放在 `ExecutionAdapter`（provider 维度），但涨跌停/T+1/最小价位是**品种维度**——同一 XTP 下股票/ETF/可转债规则不同。
5. **规则分散且无退役计划**：涨跌停有 `band_rules` 表，T+1 有 `security_master.trade_phase`，定价有 `system_config close_policy.*`，费用有 `fees.py` 常量，时段有 `market_hours` + `MARKETS` 骨架。五处各有消费者，互不知情。

## 二、目标与非目标

**目标**：任一「账号 × 标的」的能力，由「插件实现 + 声明式规格」组合得到；新增市场 = 加插件包，新增品种/规则 = 加数据行；通用层零 `if provider/品种` 分支；vnpy 不外泄。接入骨架横向统一覆盖数据平台、实时行情、交易、非结构化研究四类。

**非目标**（首批不实现，只留扩展位，且**不夹带代码**）：期货/期权的组合保证金/平今平赎/交割/行权；跨境结算；撮合级仿真；**跨市场组合策略**（分片部署后市场间互不可见）；非结构化研究子域的落地实现。

## 三、范围与邻域边界

**四个纵向子域，各自独立建模/消费链/UI；共享一套横向接入骨架。**

| 子域 | 归属 | 领域模型 | 消费链 | UI 面 |
|---|---|---|---|---|
| 结构化数据供给（历史/基本面/参考） | **A03** | `DataKind × symbol × ts` | Pull 同步/质量/血缘/双时态/Watermark | 数据管理 |
| 实时行情 | **D26 hub** | `Tick/Bar` 流 | 订阅/聚合/断流/水位 | 行情监控 |
| 执行（交易） | **D32** | `Order/Trade/Position/AccountState` | 下单/撤单/回报/认领/审计 | 交易台/实盘/风控/对账 |
| 非结构化研究 | **D32（规划）** | `Document/Chunk/Claim` | 抓取→解析→去重→切分→embedding→检索/抽取 | 研究/文档库/问答 |

**横向共享（四域同一套）**：provider 注册 · manifest · 端口能力 · 凭证/config schema · 配置面 · 健康 · 审计 · 生命周期。

**三条边界**：
1. D32 只定执行 + 实时行情 + 研究三域的端口/规格；结构化数据供给归 A03。
2. 基本面数值（`fundamental_daily`）是 A03 的 `DataKind`，不是研究域；研究域只装非结构化文档/文本/结论。
3. 各域 UI 必须分开；统一的是「集成中心接入配置面」。

**与 A03 的从属关系（2026-11-11 用户裁定）**：A03 是本文 `data_source` 子域的详细设计（DataKind/双时态/路由/水位/质量），**不是并列的第二套接入架构**。

- **D32 = 接入总纲**：端口、注册表、规格、插件、部署分片。
- **A03 = 数据域深设计**：L1 契约 / L3 路由 / L4 水位与质量仍由 A03 定义，实施走 A03 自己的批次，**D32 不接管**。
- **门面 vs 实现**：A03 的 `DataBus`/`TradeBus` 是**调用方门面**（含风控前置、WAL、时序纪律），内部调 D32 的端口；`ExecutionPort`/`MarketDataPort`/`HistoryPort` 是**插件实现契约**。二者是两层，不是二选一。
- **注册表只有一张**：A03 的 `@adapter` 注册进本文 `REGISTRY`（域 = `data_source`），不再自建第二处。

## 四、分层

```
应用层     strategy / risk / scheduler / web / IM / research
   │  只依赖 Ports + Registry

   │
```

**依赖规则**：`应用→端口`、`编排→端口+注册表`、`插件→端口+规格`；`端口/规格` 不 import `插件/第三方`；`应用/编排` 不 import `第三方`。`providers/` 必须进 LAYER 表并配守门（§十四 S1/S2）。

## 五、五个正交维度 + 两个组合器

| 维度 | 问题 | 承载 | 形态 | 真源 |
|---|---|---|---|---|
| **Market** | 日历/时段/竞价阶段/结算日锚 | `MarketSpec` | 声明式数据 | `market_hours` + `MARKETS` 骨架 |
| **Instrument** | 涨跌停/tick/lot/T+/可卖/订单类型/申报范围 | `InstrumentSpec` | 声明式数据 | `security_master` + `band_rules` + 缺列 |
| **Provider** | 协议/连接/字段映射/重连 | `ProviderPlugin` | 代码插件 | 插件包 |
| **Risk** | 仓位/回撤/频次/熔断 | 风控层 | 代码+配置 | `risk_control` |
| **Account** | 品种准入/资金/保证金/行情授权/停牌态 | `AccountSpec` | 数据+运行时 | `perms` + `trading_account` + 停牌表 |

**Account 维的边界**：只回答"能不能"，不回答"该不该"。品种/板块/ST/可转债权限（`perms.account_allows`）、`market_op`、可用资金/保证金、行情授权等级、当日停牌/临停态都在此。仓位上限、回撤阈值属 Risk。

`data_license`（行情授权等级）落在 `trading_account.params`，消费点是 hub 订阅 diff——无授权的标的跳过订阅并告警。**P2 只定义 AccountPermSpec.data_license 字段；订阅过滤门归 P3**（md_hub 生命周期面本就在 P3）。

### 5.1 两个组合器（生命周期不同，必须分开）

```
# 冷：进程启动一次，绑定到编排层，改则重启
get_runtime(account_row, role: md|td, need, task_ctx) -> Runtime
    slot   = SessionSlotAllocator.acquire(account_id, provider, role, task_ctx.tid)
    plugin = REGISTRY.get(DOMAIN_TRADING, account_row.provider)
    require(plugin.manifest.port_caps, need)        # 不足 → UnsupportedCapability
    return plugin.build(account_dto, role, slot)    # Runtime 只暴露该 role 的端口

# 热：每笔单读，带版本与快照
resolve_rules(account, symbol) -> RuleSet
    ms  = MarketSpec.of(account.market)          # market_hours + 代码骨架
    ins = InstrumentSpec.of(symbol)              # security_master + band_rules + 缺列
    acc = AccountSpec.of(account.id, symbol)     # 准入/资金/授权/停牌
    return RuleSet(ms, ins, acc)                 # 单笔内冻结，validate/price/sellable 共用
```

**slot 的作用域**：`(account, provider, terminal_id)`，**不是每账号一个**。同账号可以有 hub MD 会话 + N 个任务各自的 TD 会话；`terminal_id` 由 `(role, tid)` 派生（`XTP=(tid-1)%98+2`、`EMT=(tid-1)%100+20` 保持现行公式，见 §9.5），`tid` 来自 `live_task`。slot 内容是 `{terminal_id, order_prefix, window_open, tid}`。

**caps 不进 RuleSet**：能力协商发生在 `get_runtime`（选插件），规则快照只含市场/品种/账户三维——两件事的生命周期不同，混在一起会让"换实现"触发"换规则"。

**关键约束**：
- `place()` **不建连**。连接在 `get_runtime`（进程启动时）；`place()` 只取规则快照并调用已绑定端口。
- `resolve_rules()` 的结果在**一笔单内冻结**——validate 与 reference_price 必须消费同一对象，禁止两次读取（防运营盘中改 spec 导致"校验通过但定价用新值"）。
- 缓存失效用**版本号 + 懒加载**（复用 `CFG_VERSION_KEY`），TTL 只做兜底；写侧任何规则变更必须 bump 版本。

## 六、端口契约

端口只描述**能力**，不描述连接与装配（那是 Runtime 的事）。

```
class ExecutionPort(Protocol):
    # 生命周期
    def connect(self) -> None: ...
    def close(self) -> None: ...
    @property
    def connected(self) -> bool: ...
    # 交易
    def send(self, order: Order) -> OrderReceipt: ...
    def cancel(self, client_order_id: str) -> None: ...   # 平台侧稳定身份；provider 内部解析为券商委托号
    # 推送（替代轮询作为主路径；查询保留作对账/恢复）
    def subscribe_order(self, cb: Callable[[OrderState], None]) -> None: ...
    def subscribe_trade(self, cb: Callable[[Trade], None]) -> None: ...
    # 查询（同步返回，插件内部完成异步→同步）
    def query_positions(self) -> list[Position]: ...
    def query_account(self) -> AccountState | None: ...   # 0/1 账户；多行由实现取首并告警
    def query_orders(self) -> list[OrderState]: ...       # client_id 为 best-effort；cancel 前必须解析为 vt
    def query_trades(self) -> list[Trade]: ...
    def resolve_vt_order_id(self, client_order_id: str) -> str | None: ...

class MarketDataPort(Protocol):
    def connect(self, credentials: dict, params: dict) -> None: ...
    def close(self) -> None: ...
    @property
    def connected(self) -> bool: ...
    def start_ready(self) -> bool: ...          # hub 主循环启动闸
    def set_context(self, ctx: dict) -> None: ...   # 账号/市场上下文（hub 主循环注入）
    def poll_supervise(self, trading_day: bool) -> None: ...   # 窗内 renew / 窗外 suspend
    def event_threads_healthy(self) -> bool: ...
    def set_on_tick(self, cb: Callable[[Tick], None]) -> None: ...
    def subscribe(self, symbols: list[str]) -> None: ...
    def unsubscribe(self, symbols: list[str]) -> None: ...     # 订阅 diff 用
    def snapshot(self, symbol: str) -> Tick | None: ...

class HistoryPort(Protocol):
    """A03 DataBus 的薄门面——不是第二套拉取契约。"""
    def fetch(self, req: DataRequest) -> ContractFrame: ...

class ResearchPort(Protocol):
    def fetch(self, req: ResearchRequest) -> list[Document]: ...
    def search(self, query: str, filters: dict) -> list[ChunkHit]: ...
    def health(self) -> Health: ...

class AccountPort(Protocol):
    """账号健康与授权态。凭证解析不在此（见 §3.1）。"""
    def health(self) -> Health: ...
    def entitlements(self) -> AccountSpec: ...
```

- **不支持能力**：`Runtime` 按 role 只暴露合法端口，越界访问抛 `UnsupportedCapability`（禁空实现 no-op）。
- **领域模型**（`quant_common/domain`）：`Order/OrderReceipt/Position/AccountState/OrderState/Trade/Tick/Bar/Instrument` + 研究域 `Document/Chunk/Claim`；纯数据、无第三方依赖。字段对齐现 `adapters.py` 的 `Order`（6 字段）/`Position`（7 字段），**不引入 `offset/reference`**（A 股现货 `Offset.NONE` 恒值、`reference` 在 `client_order_id` 前缀里，均非独立字段）；`OrderState`/`Trade` 末位各增 `client_id`（best-effort：P1b 由 `_vt2cid` 当前值反填，P3 由插件填；`trade_log` 认领与 `cancel` 解析均以它为首选键，解析不到必须显式失败）。
- **事件语义**：交易链主路径是推送（`EVENT_ORDER`/`EVENT_TRADE`），查询只用于对账与恢复。领域状态枚举由端口定义，不暴露 vnpy `Status`。

### 6.6 与既有「6 大接口抽象」的关系（修正版）

| 6 大抽象 | 去向 | 说明 |
|---|---|---|
| **Broker**（凭证/连接测试） | **不并入端口**，下沉共享层 `credentials.py` + 插件 manifest 的 `config_schema` | Broker 只有 `get_credentials/test_connection`，不是执行面 |

| MessageChannel | 不变 | D19 |

## 七、声明式规格（复用既有表，不新建）

**原则**：规格层是既有表的**字段映射与覆盖层**，不是第二套表。缺字段走迁移加列，不建 `market_spec` / `instrument_spec`。

### 7.1 MarketSpec ← `market_hours`

| Spec 字段 | 来源 | 状态 |
|---|---|---|
| `sessions`（phase/start/end/scope） | `market_hours.sessions`（jsonb）**直接引用** | 已有 |
| `tz` / `calendar` / `anchor` | `market_hours.tz/calendar/anchor` | 已有 |
| `channels`（bar/depth/trade_tick/order_tick） | `MARKETS[market]["channels"]`（代码骨架，运营不改） | 已有 |
| `order_price_range`（有效申报范围） | `band_rules.order_range_*`（交易所×板块）；symbol 级覆盖见 §7.2 | **缺列** |

`MARKETS` 保留为**代码缺省骨架**（时区/日锚/通道），`market_hours` 为运营真源；二者冲突以表为准。

**申报范围只有一份**：`band_rules` 加 `order_range_mode`（`pct_of_ref|abs|venue|none`）、`order_range_lower_pct`、`order_range_upper_pct` 三列，参考价取 tick 的最新成交价。合成顺序：`security_master.order_range_override`（symbol 覆盖）> `band_rules`（exchange×board，阶段取 `market_hours.sessions` 当前 phase）> 缺配按 §7.4 分流。**不设** `InstrumentSpec.price_range` 独立字段——那会与 `band_rules` 形成第二真源。

### 7.2 InstrumentSpec ← `security_master` + `band_rules` + 缺列

| Spec 字段 | 来源 | 状态 |
|---|---|---|
| `category` / `board` / `exchange` | `security_master` | 已有 |
| `tick_size` / `multiplier` / `trade_phase`（T+N） | `security_master` | 已有 |
| `price_band`（normal/st/ref） | `band_rules(exchange×board)` | 已有 |
| `lot_size` | `security_master.multiplier` 派生 | 已有 |
| `sellable_rule` | 迁移加列（缺省 `volume_minus_frozen`） | **缺** |
| `order_types` | 迁移加列（jsonb 数组） | **缺** |
| `position_side` | 迁移加列（缺省 `long_only`） | **缺** |
| `order_range_override`（symbol 级申报范围覆盖） | 迁移加列（jsonb，可空） | **缺** |
| `venue_flags` | 迁移加列（jsonb） | **缺** |
| `effective_from` / `source` / `version` | 迁移加列 | **缺** |

**优先级**：`symbol 覆盖 > (exchange,board,category) > (category) > 代码缺省`。注意：`security_master` 目前只有 symbol 行，`(exchange,board,category)` 级没有独立存储——P2 若需要板块级差异，须显式加覆盖表；否则该级只由 `band_rules` + 代码缺省承担，**不做隐式继承**。

**品类枚举以 `ASSET_CATEGORIES` 为基集**（stock/listed_fund/fund/convertible/reits/perp），扩展项（future/option）须显式声明并同步守门，禁止两处各写一套。`etf` 已正名为 `listed_fund`（批 127），不得回退。

### 7.3 RuleSet 与三层规则

**承认三层，各有归宿**：

| 层 | 内容 | 形态 | 变更代价 |
|---|---|---|---|
| **静态规格** | 涨跌停/tick/lot/T+/可卖口径/申报范围上下界 | 数据行 | 运营改，即时生效 |
| **动态机制** | 可转债临停（±20%/30% 触发 30 分钟）、以最优价为基准的申报范围、券商口径差异 | **规则层代码**，`register_dynamic_rule(category, fn)` | 发版（交易所机制，极少变） |
| **交易所态** | 该标的当前是否停牌/临停/无行情 | 停牌表（日频）+ 行情新鲜度（bar ts）+ 插件连接态 | 运行时 |

```
class RuleSet:
    def validate(intent, tick, mode: Literal["open","reduce"]): ...
    def reference_price(intent, tick): ...   # 171s 定价族迁此
    def sellable(pos): ...
    def pre_trade_checks(intent, tick): ...  # 含停牌/临停/行情新鲜度

# 动态机制扩展位（规则层，不在插件内）
register_dynamic_rule("convertible", convertible_halt_rule)
```

**关键区分**：运营可调的**参数**进数据（`price_band`、`tick_size`）；交易所**机制**（触发条件与时间窗）进代码。前者满足决策 2，后者不满足但可接受——监管规则年度级变化，发版成本远低于把监管逻辑做成 DSL 的成本。

**停牌态怎么到 worker**：worker 不接 hub 的 tick 状态位（它只消费 `hub:bars`）。判据用两个可得源——① 停牌表（`suspend` 日历，日频，DB 直读）；② 行情新鲜度（该标的最近 bar 的 ts 与当前时间差，超阈值仅告警不拒单）。实时临停由 `register_dynamic_rule` 按 category 的机制判定（基于 bar 价格序列），**不依赖跨进程状态推送**。

**RuleSet 与 RiskRule 分工**：RuleSet = 合规（交易所允许什么）；RiskRule/`check_order` = 策略风控（我想不想）。执行序列：`check_order`（风控+准入）→ WAL → `RuleSet.validate`（合规）→ 定价 → `send`。`place()` 只是合规阶段，不改前两步。

**资金/保证金硬门**：现 `check_order` 无现金前置（现金只在选量时读 `available_cash`）。P2 在 `check_order` 内、`RuleSet.validate` 之前补 `cash/margin` 门，口径取 `AccountSpec`；D32 只声明归属，不改执行序列顺序。

### 7.4 失败语义三分（资损防线）

| 情况 | 开仓 | 平仓/减仓（`reduce_only` 或 `emergency_close_all`） |
|---|---|---|
| **规则行缺失** | fail-closed 拒单，UI 标「规则未配置」 | fail-open，走兜底链（下） |
| **读失败**（DB 抖动/超时） | 有快照→用快照 + 告警；无快照→同「缺失」 | 有快照→用快照 + 告警；无快照→兜底链 |
| **规则非法值** | fail-closed 拒单 + 告警 | 兜底链 + 告警 |

理由：平仓的代价是持仓暴露，拒单的代价是错过交易——不能用同一语义。现行为（`close_policy` 缺省回落）已是 fail-open，本稿把它显式化而非推翻。

**平仓兜底链**（逐级降级，每级留痕）：

1. 跌停线（`band_rules` + `security_master.price_band` 可得时）；
2. 对手价 × `aggression`（tick 可得时，即 171s 现行为）；
3. **最新价本身**，钳到涨跌停带内（**不乘让价**——跌停时乘 0.9 必越下界，全部废单、10 轮耗尽转人工）；`order_types` 含市价档时优先市价；
4. 无 tick、无最新价、无任何参照 → 转人工 + 页面高优告警（此时挂单必然被拒，挂出去只制造废单日志）。

第 3 级只保证「价在带内且挂得出去」，可能产生废单——急停重试循环会再试，可接受。**禁止把「无规则」直接变成「不动作」**：那是持仓暴露，不是风险控制。

**启动预检**：worker 启动时对全部在跑标的做一次规则完整性检查，缺失即告警（防 09:30 才发现批量拒单）。

### 7.5 旧规则源退役清单（P2 必做）

| 旧源 | 退役动作 |
|---|---|
| `system_config close_policy.*`（0175 五键） | **删 `has_limit_band` / `price_tick` 两键**——品种事实已有 `band_rules` / `security_master.tick_size`，留则双源（且 `price_tick`=0.001 与股票 tick=0.01 冲突会产生非法价）；其余 `opponent_depth` / `aggression` / `max_order_qty` 留 provider 维，迁 `trading_account.params`。删键 + 读侧切换断言 |
| `band_rules` | 保留为涨跌停与申报范围的唯一真源；`price_band`/`order_price_range` 只引用不存值 |
| `MARKETS` 的时段/日锚 | 保留为代码缺省；`market_hours` 为准 |
| `fees.py` 常量 | 保留（费用非交易规则，属回测摩擦） |

`close_policy.*` 里混了两类东西：`has_limit_band`（有没有涨跌停）与 `price_tick`（最小价位）是**品种事实**，归 `band_rules` / `security_master`；`opponent_depth` / `aggression` / `max_order_qty` 是**执行策略**，归 provider 维。前者**删**，后者**迁**，不整体搬迁。

任何一项未退役，P2 就是第三套真源。

## 八、非结构化研究子域

**定位**：研报/新闻/公告/分析/结论——文档/文本/结论，不是时序数值。与 A03 的 `DataKind` 模型不同，单列子域。

**能力**：`research` 是**端口能力**，进 `PORT_CAPS`（§十），**不进** `CAPABILITIES`——后者是 `DataKind` 的派生归类视图（值域断言 `set(KIND_CAP_CLASS.values()) == set(CAPABILITIES)`），硬塞必破守门。

**领域模型**：`Document`（id/provider/source_type/symbols/title/published_at/url/lang/hash/raw_ref）、`Chunk`（id/document_id/seq/text/embedding/meta）、`Claim`（可选结构化结论）。

**流水线**：抓取 → 解析 → 去重（hash/URL）→ 切分 → embedding → 索引（pgvector）→ 检索/抽取。

**存储**：`research_doc` / `research_chunk`（含 vector 列）/ `research_claim`；`doc↔symbol` 多对多。

**质量口径**：抓取成功率、解析成功率、去重率、时效、覆盖率——不是连续性/缺口。

**隔离**：独立健康分域（`domain='research'`），抓取失败**不得**进 critical 交易页，不进 hub 缺席判定。

**实现**：不在 P1–P5，记待办另立项。LLM 调用走 D01。

## 九、Provider 插件契约

### 9.1 manifest（唯一声明面）

```
id: "xtp"
domain: trading_account             # 三域：data_source / trading_account / research
roles: [md, td]                     # 一个包可提供多个角色
port_caps: [execution, market_data] # ⊆ PORT_CAPS；数据能力由 @adapter 派生，不在此声明
markets: [astock]
transport: "vnpy_xtp"
config_schema: [ {key, label, type, sensitive, required, default, validate} ]
session_policy: { mode: window|always, window_ref: "system:xtp_session", reconnect: {backoff} }
terminal_id: { md_domain: [1, 1], td_domain: [2, 99] }   # 只声明合法域
version_lock: "vnpy_xtp==2.2.32.2.3"
```

- `port_caps` 是端口协商用；`data_capabilities` **不在 manifest 声明**——它由 A03 的 `CapabilityDecl(kind, scope)` 经 `KIND_CAP_CLASS` 派生，写入 DB 配置列（防第二真源）。
- `domain` 单值：数据源 provider（tushare/binance）由 A03 的 `@adapter` 注册到 `(data_source, provider)`；同一 tushare 若也提供研究，则以 `domain: research` 另注册一条——两条独立条目，不共享。
- `terminal_id` 只声明合法域与 MD 预留号，**分配在编排层**（§3.1）。

### 9.2 插件包结构

```
server/src/providers/<id>/
  __init__.py        # 导出 plugin（一行注册）
  manifest.py
  plugin.py          # build(account, role, slot) -> Runtime
  translate.py       # 第三方 SDK 对象 ↔ 领域模型（P3 起；P1b 迁移期在 strategy_runner/legacy_translate.py）
  _transport.py      # 私有：vnpy/SDK/字段映射/重连
```

**无 `requirements.txt`**：依赖统一进全局 lock（`quant-pip-wrapper` 单 lock + `--require-hashes`）。插件升级 = 一次完整发布。

### 9.3 生命周期

```
class ProviderPlugin(Protocol):
    manifest: Manifest
    def build(self, account: AccountDTO, role: Literal["md","td"], slot: SessionSlot) -> Runtime: ...
    def health(self) -> Health: ...

class SessionSlot:                      # 编排层构造，插件只读
    terminal_id: int
    order_prefix: str
    window_open: bool
    tid: int

class Runtime:
    # 按 role 只暴露合法端口；其余属性访问抛 UnsupportedCapability
```

`AccountDTO` 由共享层构造：`{row_id, provider, market, impl, credentials(已解密), params, capabilities, md_only}`。插件不读 DB、不解密。

编排层持有：role、连接窗判定、terminal_id、order_prefix、tid。插件持有：连接原语、重连、字段映射。

### 9.4 vnpy 内化原则

- 通用层零 `import vnpy`（迁移期用基线棘轮，见 §十四 S1）。
- 插件内部可自由用 `vnpy_xtp`；`_transport.py` 封装 TD-only 入口，声明依赖内部 API + 版本锁。
- 建议自维护 fork（同 `vnpy-4.5.0+nogui` 做法），须写「fork 基线提交 + 每季度对照上游 diff」运维条目。
- 领域模型与 vnpy 解耦：插件边界做 `Order ↔ OrderRequest` 转换。

### 9.5 号段 / 连接窗 / 重连

- **唯一域 = `(account_id, provider, terminal_id)`**。同账号同时存在 hub MD 会话 + 每任务一个 TD 会话（一标的一进程）；`terminal_id` 由 `(role, tid)` 派生，保持现行公式：XTP `(tid-1)%98+2`、EMT `(tid-1)%100+20`、MD 用账号行预留号。**不是每账号一个槽**。
- **分配真源 = DB 表** `provider_session_slot(account_id, provider, terminal_id, holder, boot_epoch, heartbeat)`，唯一约束 `(account_id, provider, terminal_id)`；Valkey 只做进程内缓存。
- **acquire 必须单语句原子**（禁 SELECT→判断→INSERT：两机并发会 TOCTOU 双取 → 双会话）：

  ```sql
  INSERT INTO provider_session_slot (account_id, provider, terminal_id, holder, boot_epoch, heartbeat)
  VALUES ($1,$2,$3,$4,$5,now())
  ON CONFLICT (account_id, provider, terminal_id) DO UPDATE
    SET holder=$4, boot_epoch=$5, heartbeat=now()
    WHERE provider_session_slot.heartbeat < now() - interval '45 seconds'
  RETURNING (holder = $4) AS acquired;
  ```

  无返回行 = 有主，不得"读一下再决定"。
- **三种失败态**：有主（心跳新鲜）→ `EX_TEMPFAIL(75)` 退避；`terminal_id` 越界/号段耗尽/配置非法 → `EX_CONFIG(78)` 停（重启无意义）；**DB 不可用 → 不建连、退避**（`EX_TEMPFAIL`），**绝不 fail-open 裸跑**——裸跑即撞号双会话。
- **续租**：心跳 15s、TTL 45s。续租语句同样带 `holder` 条件：返回 0 行 = 被抢 → 立即断开并退出（继承 hub lease-lost 语义）；抛异常 = DB 错 → 重试，重试耗尽才退。**不把「DB 错」当「被抢」**。
- **两类互斥不重复**：hub 的 MD 互斥用本机 Valkey（一台机器只跑本机账号的 hub，账号归属唯一市场，跨机不会争同一账号）；TD 的跨机互斥由上面的 DB slot 负责。
- **order_prefix**：`t{tid}:e{boot_epoch}:`，编排层生成经 `slot` 传入；插件照用不改。
- **连接窗**：编排层算 `in_session`（读 `system_config` 的 `xtp_session_lead_min/lag_min` + 交易日历），经 `slot.window_open` 传入；插件执行 connect/suspend。
- **重连/退避**：插件内部。

### 9.6 可插拔的验收定义（核心）

新增一个 provider，**只允许**：

1. 新增 `server/src/providers/<id>/` 目录（含 manifest + plugin + transport）；
2. 在 `providers/__init__.py` 加一行注册；
3. 配置文件里加一行账号/数据源记录。

**不允许**修改：`quant_common/`、`ports/`、`registry/`、`strategy_runner/`、`strategy_framework/`、`md_hub/`、`web_api/` 的任何文件。守门见 §十四 S3。

## 十、注册表（单表 + 投影）

- `REGISTRY: dict[(domain, provider_id), Plugin]` —— **唯一声明处（执行/实时/研究）**。
  - **域词表**：`DOMAIN_DATA = "data_source"`、`DOMAIN_TRADING = "trading_account"`、`DOMAIN_RESEARCH = "research"`（与 `markets.py` 同词法）。**三域同一张表**——数据源 provider 由 A03 的 `@adapter` 在 import 时注册到 `(data_source, provider)`；执行/实时/研究由 `providers/*/__init__.py` 注册。这样「第 9 处注册表」才真正消掉。
  - 键必须是 `(域, provider)` 复合：`binance`（数据源）与 `binance_perp`（交易通道）是两把键、**同一个 registry**，混用会静默拉错源。
- **legacy 投影（P1 只读）**：8 处旧注册点降为只读投影，P3/P4 逐项删除（数据侧 4 处归 P7，见 §十二）。守门：`REGISTRY` 与投影的能力集必须相等，或显式标 `legacy_only`。
- **签名统一**（三处一致，不得再出现 `get(provider, role)` 这类写法）：
  - `REGISTRY.get(domain, provider) -> Plugin`
  - `REGISTRY.pick(domain, provider, need, impl) -> Plugin`
- **能力协商**：`pick` 校验 `port_caps ⊇ need` **且** DB `enabled ∧ capabilities` 硬过滤；不足 → `UnsupportedCapability`。
- **排序**：不按 manifest 优先级（偏好住 DB）。多插件择一由 `routing_policy` + 账号行 `position` 决定。
- **启动校验**：manifest 完整性（id 唯一、能力 ⊆ 合法集、schema 合法）；**单个 provider 不可用只标 unavailable，不拖垮进程**（EMT SDK/.so 可能缺）。
- **`PORT_CAPS`**：`{execution, market_data, research, history, account}`——端口域词表，与 `CAPABILITIES`（数据域）分离。

## 十一、部署分片

**目标**：一个部署只装载若干市场（如国内机只跑 astock，加密机只跑 crypto）。

**边界由市场定义，不由插件定义**。插件是代码组织，市场是部署组织。

- **配置**：`/etc/quant/deploy.toml` 的 `deploy_markets = ["astock"]`——**release 树外**的机器级文件，由 Ansible inventory 的 host_vars 生成。不放 systemd `Environment=`（单元随 release 树发布、artifact 跨机同版，装不了 per-host 值），也不入库（两机共库会冲突）。这是第三个配置作用域：业务配置（DB）/ 密钥（加密入库）/ 部署形态（`/etc` + Ansible）。
- **缺失或非法 = 78**：不得默认全市场（默认会让分片机同时拉起两个市场的 hub，把租约与授权费一起放大）。文件不存在、字段拼错、市场名不在 `MARKETS` → `EX_CONFIG(78)` 拒启。
- **留证**：渲染后的值 + md5 写入 `releases/<id>/deploy-market.txt`，回滚可比对；A06 §11 输入表加一行。
- **进程过滤**：SA4 期望态按 `trading_account.market ∈ deploy_markets` 过滤；worker 只拉起同市场任务。
- **订阅面**：`_desired_symbols` 的候选标的按 **`deploy_markets`（市场维）** 过滤，不再无差别全局查 `live_task`——否则分片机白订阅他市场标的。D26「各 hub 全量复制订阅」的**账号级口径不变**（同市场内仍全量复制，这是已接受的 L1/L2 成本）；D26 只需加一句「候选集先按本机市场筛」。
- **租约跨机**：`provider_session_slot` 在共享 DB，两机互斥成立（§9.5）。
- **Web 可见范围**：同一过滤器收窄账号/任务/策略列表。
- **DB**：可同库不同行，也可分库（`server-info` 已有多库形态）。

**三条约束（拆分能否优雅的判据）**：

1. **插件无全局状态**——不得有模块级单例连接/缓存，必须按账号实例化（§9.3 的 `build(account, role)` 保证）。
2. **REGISTRY 只读**——import 时静态注册，插件不感知自己在哪台机器。
3. **过滤在编排层**——插件代码里不得出现部署市场配置。

**实施与权限**：`/etc/quant/deploy.toml` 的写入属系统层——由 Ansible host_vars 生成、走现有特权通道（michael；bernard 无 sudo）。本项须作为**独立小批**进待办，不得当作 D32 迁移的隐式副产物。

**非目标**：跨市场组合策略（分片后互不可见）；跨机聚合视图（属监控层）。

### 12.2 契约冻结清单（P1a 确定后不得单方面改）

| 对象 | 位置 | 冻结内容 |
|---|---|---|
| 领域模型字段 | `quant_common/domain` | `Order`（`symbol/action/volume/price/order_type/client_id`）、`OrderReceipt`、`Position`（`symbol/volume/avg_price/pnl/direction/frozen/yd_volume`，`available` 为派生属性）、`OrderState`/`Trade`（末位 `client_id`——best-effort 稳定身份；`query_orders` 尽量填，`vt_orderid` 始终为券商侧对账键）、`Tick`（核心平铺 + 五档元组）、`Bar`（BAR_COLUMNS 11 字段）、`AccountState`、`Health`；枚举 `Action/OrderType/Direction/OrderStatus` 取值与现有代码逐字一致 |
| 端口签名 | `ports/` | §六 全部方法名与参数（含 `connect/connected/subscribe_order/subscribe_trade/poll_supervise(trading_day)`、`query_account() -> AccountState | None`）；`cancel(client_order_id)` 必须先解析为 vt 再撤，解析失败显式失败（不得静默放弃） |
| 注册表键与域词表 | `registry/` | `(domain, provider)` 形状；`DOMAIN_DATA="data_source"`、`DOMAIN_TRADING="trading_account"`、`DOMAIN_RESEARCH="research"`；`PORT_CAPS` 五词 |
| 会话槽 | `SessionSlot` | 字段 `{terminal_id, order_prefix, window_open, tid}`；唯一域 `(account, provider, terminal_id)` |
| RuleSet | `rules/` | 四方法签名（`validate(intent,tick,mode)` / `reference_price` / `sellable` / `pre_trade_checks`） |
| manifest | `providers/*/manifest.py` | §9.1 字段集（`id/domain/roles/port_caps/markets/transport/config_schema/session_policy/terminal_id/version_lock`）；不含 `data_capabilities`（派生） |

**两类内容的判据（防两个方向的退化）**：

- **形状类**（领域对象的字段名 / 枚举值 / 单位 / 派生关系）：**以现有代码为准**。迁移期必须能零转换承载现有数据，否则 P1b 的「行为等价」不成立。
- **能力类**（端口方法名 / 端口集合 / 域词表 / 批次顺序 / 出口条件）：**以本稿为准**。这是架构的价值所在，不因现状而收缩。

两者冲突按此分流，属**事实对齐**，不算架构变更、不触发重审。若发现的是**能力缺失**（例如将来期货需要 `offset` 而现在没有），则不属此列，须按 §12.3 回 D32 立项。

**改动流程**：需要改上面任何一项 → 先改 D32 对应章节 → 双盲审 → 各未开工批同步引用。**禁止**在某批实现里顺手改签名再"以后补文档"。

### 12.3 变更控制（防反复）

1. **只有两类输入能改契约**：用户裁定；审出的 P0 级缺陷（有代码/真库证据）。口味、风格、"顺手优化"一律不改。
2. **每批开工前重读**本节 + D32 对应章节，任务文件「引用」写明 D32 的 commit。
3. **批中发现契约不足** → 停止编码，回 D32 改 + 双盲审，再继续。**不允许**批内私改后"下批一起改文档"。
4. **每批一个焦点**：不合并批次（P1a 不顺手做 P2 迁移），哪怕看起来省事。

### 12.5 双轨防双写（P3/P4 期间）

- `trading_account` 加 `impl TEXT NOT NULL DEFAULT 'legacy' CHECK (impl IN ('legacy','plugin'))`——账号级，不放任务级（任务级会让同账号两套并存）。
- `account_key` 部分唯一：**先 `DROP INDEX ix_trading_account_account_key`**（0116 建），再 `CREATE UNIQUE INDEX ... ON trading_account (market, account_key) WHERE account_key IS NOT NULL AND enabled`。带 **market 维**避免跨市场同名被误阻，**不带 provider**——同一资金账号在 `xtp`/`emt_emq` 下必须视为同一账号，这是防双下单的本意；旧索引不删则目标不可达（旧 `(provider, account_key)` 仍会放行 xtp/emt 双行）。
- **互斥租约不另设一套**：就是 §9.5 的 slot 租约，同 `(account, provider, terminal_id)` 抢不到 → 75 退避（有主）/ 78 停（配置非法）。不靠"人不会同时起两个"，也不引入第二套键。
- 切换点是**代码路径**，但 `impl` 列让"这条任务走的是旧还是新"可审计。
- **回滚粒度 = 整 release**（A06 原生能力）。不做 provider 级回滚——venv 跨 release 共享，插件级回滚不存在。

## 十三、边界、风险与扩展位

- **期货/期权**：首批不实现。不留 `derivative_flags` 代码逃逸口；扩展须用新规则形态（公式声明/交易所参数表）立项。
- **vnpy_xtp 内部 API 依赖**：版本锁 + `_transport.py` 隔离 + fork 基线。
- **部署模型**：插件随 release；盘中禁止插件升级（`deploy_trading_windows` 已拦）。
- **回测/paper**：`BacktestExecutionPort` / `PaperExecutionPort` 与实盘同接口。`paper` 是**内置 provider 插件**（`port_caps=[execution]`，无连接），否则 S3 能力协商会误杀。
- **研究域**：解析/向量成本、版权合规、来源可信度，P6 立项时评估。
- **规则数据来源**：`InstrumentSpec` 由 `security_master`/交易所公告生成，最终以表为准（人工覆盖 + 审计）。
