# D32 · 接入插件架构（端口 · 注册表 · 声明式规格 · 插件）

> **定位**：接入面的目标架构（"应该是什么"），替代 D26 §3.2 的"扁平 provider 插件"并补其缺口。
> **状态**：架构定稿（2026-11-10 用户决策确认）。**实施须独立立项、按批展开、每批双盲审**；D32 只定架构与契约，不改代码。非结构化研究子域**纳入统一规划、具体实现记待办**。
> **与既有文档关系**：A02（外部接口配置：行=账号/列=能力集）、A03（数据供给总线：DataKind/Pull/双时态/路由）、D25（三层能力模型）、D26（账号级 hub 拓扑/进程模型）。D32 承接 D26 的"provider 插件"意图，**新增两个正交层：声明式规格（MarketSpec/InstrumentSpec）与端口契约**，并回答"vnpy 放哪、规则放哪、三类接口（数据/行情/交易）与非结构化资料如何共存"。

## 零、两项核心决策（用户裁定 2026-11-10，硬约束）

1. **vnpy 收进插件内部**：`vnpy` / `vnpy_xtp` / 任何第三方 SDK 只允许出现在 provider 插件包内部；通用层（应用/编排/端口/规格/注册表）**不得 import vnpy**，也不得出现 vnpy 数据结构。
2. **交易规则用声明式数据，不用代码实体**：市场制度（MarketSpec）与品种规则（InstrumentSpec）是**数据/小表**，运营可改、不发版；代码只保留「插件实现（协议/连接）」与「规则消费方（组合器）」。规则变化不应触发代码发布。

## 一、为什么重做（现状问题，证据锚点）

1. **provider 被劈成三截**：凭证=`Broker`（`broker.py`）、装配/建连=`td_registry.py` 的 `_build_xtp_runtime`/`_build_emt_runtime`、执行接口=`ExecutionAdapter`。账号相关功能没有封装在一个实体里。
2. **抽象重复**：vnpy `BaseGateway`（`send_order` 返 `vt_orderid`）与项目 `ExecutionAdapter`（`send_order` 返本地 `client_id`）两套并发抽象，外加 `_cid2vt` 映射成本。
3. **越过插件边界**：`vnpy_xtp.__all__=["XtpGateway"]`，项目却直接 `from vnpy_xtp.gateway.xtp_gateway import XtpTdApi`（内部类）+ 自写 `ThinTdGateway` 壳——依赖非公开 API，升级即炸。
4. **品种规则错放在 provider 维度**：171s 把 `close_action/close_reference_price/has_limit_band/...` 定价规则放在 `ExecutionAdapter`（provider 维度），但涨跌停/T+1/最小价位是**品种维度**——同一 XTP 下股票/ETF/可转债规则不同。
5. **规则硬编码/散落**：涨跌停幅度有 `band_rules` 表，但 T+1、可卖口径、订单类型、持仓方向、申报范围散在 `strategy.py`/`trading.py`/`risk.py`，改一处要发版。

## 二、目标与非目标

**目标**：任一「账号 × 标的」的能力，由「插件实现 + 声明式规格」组合得到；新增市场=加插件包，新增品种/规则=加数据行；通用层零 `if provider/品种` 分支；vnpy 不外泄。接入骨架（注册/能力/凭证/健康/审计）**横向统一覆盖数据平台、实时行情、交易、非结构化研究四类**。

**非目标**（D32 首批不实现，只留扩展位）：期货/期权的组合保证金/平今平赎/交割/行权；跨境结算；撮合级仿真；**非结构化研究子域的落地实现**（本稿只定规划与契约，实现记待办）。

## 三、范围与邻域边界（D32 管什么、不管什么）

**四个纵向子域，各自独立建模/消费链/UI；共享一套横向接入骨架。**

| 子域 | 归属文档 | 领域模型 | 消费链 | UI 面 |
|---|---|---|---|---|
| 结构化数据供给（历史/基本面/参考） | **A03** | `DataKind × symbol × ts` | Pull 同步/质量/血缘/双时态/Watermark | 数据管理 |
| 实时行情 | **D26 hub** | `Tick/Bar` 流 | 订阅/聚合/断流/水位 | 行情监控 |
| 执行（交易） | **D32** | `Order/Trade/Position/Account` | 下单/撤单/回报/认领/审计 | 交易台/实盘/风控/对账 |
| **非结构化研究（研报/新闻/公告/分析/结论）** | **D32（规划）** | `Document/Chunk/Claim` | 抓取→解析→去重→切分→embedding→检索/抽取 | 研究/文档库/问答 |

**横向共享（四域同一套）**：provider 注册 · manifest · **能力集** · 凭证/config schema · 配置面 · 健康 · 审计 · 生命周期。

**三条边界（防 D32 变成大一统）**：
1. D32 **只定**执行 + 实时行情 + 研究三域的端口/规格；**结构化数据供给归 A03**（D32 引用，不重造数据总线）。
2. **基本面数值**（`fundamental_daily`）是 A03 的 `DataKind`（结构化），**不是**研究域；研究域只装非结构化文档/文本/结论。
3. 各域 **UI 必须分开**（数据管理 / 行情 / 交易 / 研究）——强行统一 UI 是错的；统一的是「集成中心接入配置面」（A02 按能力集筛 provider）。

## 四、分层（依赖只向下，无反向）

```
应用层     strategy / risk / scheduler / web / IM / research
   │  只依赖 Ports + Registry（不认 provider、不认 vnpy）
编排层     hub(MD) / worker(TD) / 命令通道 / 研究流水线 / 生命周期调度
   │  零 provider 分支
端口层     ExecutionPort · MarketDataPort · ResearchPort · AccountPort · HistoryPort
   │
规则层     RuleSet = MarketSpec × InstrumentSpec × ProviderCaps        （声明式数据组合）
   │
注册表     REGISTRY: provider_id → Plugin(manifest + factory)
   │
插件层     providers/xtp/ · providers/emt/ · providers/ctp/ · providers/tushare/ · providers/jq/ · providers/research_*/ …
   │  每包自包含：凭证解析/连接/号段/连接窗/重连/字段映射/vnpy 适配
第三方     vnpy_xtp · XTP-SDK · tushare/jq SDK · binance-ws · okx …（仅插件内部可见）
```

**依赖规则（守门）**：`应用→端口`、`编排→端口+注册表`、`插件→端口+规格`；`端口/规格` 不 import `插件/第三方`；`应用/编排` 不 import `第三方`。静态扫描：除 `providers/` 外零 `import vnpy`。

## 五、四个正交维度 + 组合器

| 维度 | 问题 | 承载 | 形态 |
|---|---|---|---|
| **Market** | 日历/时段（日盘/夜盘/24×7）/竞价阶段/结算 | `MarketSpec` | 声明式数据 |
| **Instrument** | 涨跌停/tick/lot/T+/可卖/订单类型/持仓方向/申报范围 | `InstrumentSpec` | 声明式数据 |
| **Provider** | 协议/连接/字段映射/号段/连接窗/重连 | `ProviderPlugin` | 代码插件 |
| **Risk** | 仓位/回撤/频次/熔断 | 风控层 | 代码+配置 |

**组合器**（唯一把维度拼起来的地方）：

```
resolve(account, symbol, need) ->
    prov = REGISTRY.pick(account.provider, need)        # 能力协商
    ms   = MarketSpec.of(prov.market, symbol)
    ins  = InstrumentSpec.of(symbol)
    rules = RuleSet(ms, ins, prov.caps)
    driver = prov.build(account)                         # 插件装配（含连接/号段）
    return driver, rules

place(account, symbol, intent):
    driver, rules = resolve(...)
    rules.validate(intent, tick)          # 涨跌停/tick/lot/T+/申报范围/订单类型/方向
    px = rules.reference_price(intent, tick)   # 定价（§7.3）
    return driver.send(intent.with_price(px))
```

**关键**：定价/校验属 `RuleSet`（品种/市场维度），**不属 provider**——修正 171s 维度错位。

## 六、端口契约（Ports，抽象；插件实现子集）

```
class ExecutionPort(Protocol):
    def capabilities(self) -> set[str]: ...
    def send(self, order: Order) -> OrderReceipt: ...
    def cancel(self, client_order_id: str) -> None: ...
    def query_positions(self) -> list[Position]: ...
    def query_account(self) -> AccountState: ...
    def query_orders(self) -> list[OrderState]: ...
    def query_trades(self) -> list[Trade]: ...
    def order_id_map(self, client_order_id: str) -> str | None: ...

class MarketDataPort(Protocol):
    def subscribe(self, symbols: list[str]) -> None: ...
    def snapshot(self, symbol: str) -> Tick | None: ...
    def stream(self) -> Iterator[Tick]: ...

class ResearchPort(Protocol):
    def fetch(self, req: ResearchRequest) -> list[Document]: ...   # 抓取（标的/时间/来源）
    def search(self, query: str, filters: dict) -> list[ChunkHit]: ...  # 语义检索
    def health(self) -> Health: ...

class AccountPort(Protocol):
    def credentials(self) -> dict: ...
    def health(self) -> Health: ...

class HistoryPort(Protocol):
    def fetch(self, req: HistoryRequest) -> list[Bar]: ...
```

- **不支持能力**：`capabilities()` 不含即不调用；调用未实现方法抛 `UnsupportedCapability`（禁空实现 no-op）。
- **领域模型**（`quant_common/domain`）：`Order/OrderReceipt/Position/AccountState/OrderState/Trade/Tick/Bar/Instrument` + 研究域 `Document/Chunk/Claim`；纯数据、无第三方依赖。
- **异步查询同步化**由插件内部完成（XTP 事件缓存等）；端口对上层恒同步返回。
- **能力集扩展**：研报/分析需新增第 6 能力 `research`。A02/D25 现为 5 token（`hist_quote/rt_quote/trading/ref_data/inst_event`，`markets.py:51`），实施时须同步扩 `CAPABILITIES` 与 `KIND_CAP_CLASS`（`markets.py` 的"两集互斥且并集=CAPABILITIES"守门一并改）。

## 七、声明式规格（本架构核心）

### 7.1 MarketSpec（市场制度）

```
market: astock | hk | us | futures | crypto
trading_day_anchor: natural | utc0 | night_open
sessions: [ {name, begin, end} ]
auction_phases: [open_call, continuous, close_call, after_hours]
settlement: T+0 | T+1 | T+2
currency: CNY | HKD | USD | USDT
channels: [bar, depth_snapshot, trade_tick, order_tick]
```

### 7.2 InstrumentSpec（品种规则）

```
instrument_key: (exchange, category, board) | symbol(覆盖)
category: stock | listed_fund | convertible | perp | future | option
board: main | chinext | star | bse | null
price_band: { mode: pct|none|venue, normal, st, ref: pre_close|prev_settle }
tick_size: decimal
lot_size: int | contract
t_plus: int
sellable_rule: volume_minus_frozen | yesterday_only | any
order_types: [limit, market_best5, market_fak, ...]
position_side: long_only | long_short | net
price_range: { mode: venue|pct|none, lower, upper }
venue_flags: { convertible_halt, after_hours_fixed, ... }
effective_from, source, version
```

- **优先级**：`symbol 覆盖 > (exchange,category,board) > (category) > 缺省`。
- **复用雏形**：`security_master.category/board` + `band_rules(exchange×board)` 直接并入，不另起炉灶。
- **存储**：`market_spec` / `instrument_spec` 表（含 `effective_from/source/version`），运营可改、即时生效（缓存 TTL）。

### 7.3 规则合成（RuleSet）

```
class RuleSet:
    def validate(order, tick):         # 价带/tick_size/lot/T+1/申报范围/订单类型/方向
    def reference_price(intent, tick): # 有跌停线→跌停价；无→对手价按方向让价（171s 定价族迁此）
    def sellable(pos): ...
    def pre_trade_checks(...): ...
```

- **跨维度耦合显式合成**（如"有效申报范围"= 品种 `price_range` × 交易所实际规则）。
- **不臆造**：规则缺失 → **fail-closed 明确报错**（不是静默缺省），UI 标"规则未配置"。

## 八、非结构化研究子域（Research，统一规划 · 实现待办）

**定位**：研报 / 新闻 / 公告 / 分析 / 结论——**文档/文本/结论**，不是时序数值。与 A03 的 `DataKind`（bar/fundamental 等结构化时序/截面）**模型不同**，单列子域。

**能力**：`research`（第 6 token，见 §六）。provider 如 `tushare`（研报/公告）、`jq`、专用爬取源，只声明 `research`（可叠加 `ref_data`）。

**领域模型**：
```
Document: id, provider, source_type(report|news|announcement|analysis),
          symbols[], title, published_at, url, lang, hash(去重), raw_ref
Chunk:    id, document_id, seq, text, embedding(vector), meta
Claim:    id, document_id, chunk_id, subject(symbol), predicate, object, confidence, as_of  # 可选结构化结论
```

**流水线（研究编排）**：`抓取(provider.fetch) → 解析(PDF/HTML/OCR→text) → 去重(hash/URL) → 切分 → embedding → 索引(pgvector) → 检索(RAG)/抽取(Claim)`。

**存储**：`research_doc` / `research_chunk`（含 `vector` 列，复用 pgvector）/ `research_claim`；`doc↔symbol` 多对多，支持按标的检索。

**质量口径**（与 A03 不同）：抓取成功率、解析成功率、去重率、时效（最新文档年龄）、覆盖率（标的有无研报）——不是"连续性/缺口"。

**UI**：研究域独立（文档库 / 检索问答 / 覆盖与质量），与数据管理/行情/交易并列。

**与 D01 关系**：摘要/问答/结论抽取等 LLM 调用走 **D01 LLM gateway**（DeepSeek/GLM）；D32 只定"抓取/解析/存储/检索"契约，不实现 LLM。

**实现**：**不在 P1–P5 批次**，记待办（单独批次，需评估文档解析/向量/成本）。

## 九、Provider 插件契约

### 9.1 manifest（唯一声明面）

```
id: "xtp"
capabilities: [trading, rt_quote, hist_quote, ref_data]
markets: [astock]
transport: "vnpy_xtp" | "sdk" | "rest_ws" | "http_sdk"
config_schema: [ {key, label, type, sensitive, required, default, validate} ]
session_policy: { mode: window|always, window_ref: "system:xtp_session", reconnect: {backoff} }
client_id: { mode: range, min: 2, max: 99 }
version_lock: "vnpy_xtp==2.2.32.2.3"
```

### 9.2 插件包结构

```
server/src/providers/<id>/
  __init__.py        # 导出 plugin 实例（注册）
  manifest.py
  plugin.py          # ProviderPlugin.build(account)->Runtime（含各端口实例）
  _transport.py      # 私有：vnpy/SDK/连接窗/号段/字段映射（全部私有）
  requirements.txt   # 该插件专属依赖（可选）
```

### 9.3 生命周期

```
class ProviderPlugin(Protocol):
    manifest: Manifest
    def build(self, account) -> ProviderRuntime: ...
    def start/stop/health(self): ...
class ProviderRuntime:
    execution / market_data / research / account / history   # 按 capabilities 提供
```

编排层只调 `start/stop/health` + 端口方法；连接窗/号段/重连全在插件。

### 9.4 vnpy 内化原则（决策 1）

- 通用层零 `import vnpy`（静态守门）。
- 插件内部可自由用 `vnpy_xtp`；TD-only 拆分封在 `_transport.py`，并**声明依赖内部 API + 版本锁**；建议自维护 `vnpy_xtp` fork（同 `vnpy-4.5.0+nogui` 做法），固化 TD-only 入口。
- 领域模型与 vnpy 解耦：插件边界做 `Order ↔ OrderRequest` 转换。

### 9.5 号段 / 连接窗 / 重连归属

- **号段**：manifest 声明策略、插件内部实现（XTP 1–99、EMT 1–127、加密无）。
- **连接窗**：`session_policy`（window/always）插件内部判定。
- **重连/退避**：插件内部。

## 十、注册表与动态发现

- `REGISTRY: dict[provider_id, ProviderPlugin]`；`discover()` 扫描 `providers/`（或 entry points）自动注册。
- **能力协商**：`pick(provider, need)` 校验 `capabilities ⊇ need`；不足 → `UnsupportedCapability`。
- **优先级**：同能力多插件按 `manifest.priority` 排序（A03 路由思想落点）。
- **热插拔边界**：新增/升级插件只影响其包，通用层零改；版本锁在包内。
- **启动校验**：manifest 完整性（id 唯一、capabilities ⊆ 合法集、config_schema 合法），失败 fail-fast。

## 十二、边界、风险与扩展位

- **期货/期权**（保证金/组合/平今平赎/交割/行权）：`InstrumentSpec` 留 `derivative_flags` + 插件子规则扩展位；首批不实现，需独立验证。
- **vnpy_xtp 内部 API 依赖**：版本锁 + 私有模块隔离；建议自维护 fork。
- **迁移期双轨**：新旧并存须"同账号单套生效"，由 `REGISTRY` + 账号行唯一 provider 保证。
- **回测/paper**：`BacktestExecutionPort`/`PaperExecutionPort` 与实盘同接口（复用现有 BacktestEngine/paper_mode）。
- **研究域**：文档解析（PDF/OCR）与向量检索的成本、版权/合规、来源可信度，需 P6 立项时评估。
- **规则数据来源**：`InstrumentSpec` 可由 `security_master`/交易所公告生成，最终以表为准（人工可覆盖 + 审计）。

## 十三、验证（守门，行为级）

- **S1 解耦**：除 `providers/` 外 `server/src` 零 `import vnpy/vnpy_*`；端口/规格层零第三方依赖。
- **S2 零分支**：编排/端口层源码无 `provider ==` / `if "xtp"` / `if category ==` 字面量（AST 扫描）。
- **S3 能力协商**：请求不支持能力 → `UnsupportedCapability`；多插件按 priority 选中。
- **S4 声明式规则**：改 `instrument_spec` 一行 → 行为随之变、代码零改（真库+行为断言）；规则缺失 fail-closed。
- **S5 组合器**：股票/ETF/可转债/加密/期货 五品种矩阵各断言正确（含 171s 定价族迁移等价）。
- **S6 动态插拔**：新增假插件包 → `discover()` 自动注册可被路由命中；删包即消失。
- **S7 迁移等价**：XTP 插件化后与旧路径同输入同结果（订单字段/号段/回报逐项对比）。
- **S8 生命周期**：连接窗/号段/重连由插件决定，编排层无感知（断言无相关字段）。
- **S9 研究域**：`research` 能力协商；文档去重/切分/检索契约（mock provider）；研究域不混入 DataKind/ExecutionPort。
