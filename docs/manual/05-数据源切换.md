# 05 · 数据源切换操作册

> 前向注记：本册记录现行 M5 切换操作；D26 终态=换行语义（无切换命令），D26-B 批实施后本册重写。

> 适用场景：把平台的实时行情从当前账号换到备用账号（如券商账号变更、第二个中泰 XTP 账号启用）。全程在服务器上操作，人工要做的只有三件事：配账号、测连通、跑切换命令。
> 状态：正式册，依据批 60 M5 落地实现整理（2026-09-22）。

## 一、三原则（2026-09-21 用户裁定，原话入档）

1. **「傻逼才在一章中间换主播」**——数据源切换必须在非交易时段做（或确认没有实盘策略在运行时）。盘中切源会打断实时行情，实盘任务断粮。
2. **「该是人负责的事情要人负责，该系统负责的才要系统负责」**：
   - **人的职责**：决策切换时机、做必要的准备工作（配置新源、验证新源健康）。
   - **系统的职责**：在「已准备好」的前提下稳定完成切换（不双写、不双开、切换原子）。
3. **「简洁即是完美」**：系统只做原子切换一个动作，不做影子流自动化预热等复杂机制——验证新源是人的手动操作。

## 二、动手前先确认三件事

1. **时间对不对**：交易日 15:10 之后到次日 9:15 之前，或非交易日全天。集合竞价 9:15 起、盘中、收盘前——一律不许切。
2. **前一交易日的盘后数据回补跑完了没有**：没跑完就等跑完再切。回补是数据完整性的兜底，切换前它必须在位。
3. **新源账号是什么类型**：当前只支持**第二个中泰 XTP 账号**。如果是其他券商的账号（如东财），见第九节——账号和接入模块都就绪前，切换用不了。

## 三、切换前的准备（人负责，系统不代劳）

1. **配置新源账号**：在「集成中心」为新账号建一行（行情账号信息照开户资料填）。
2. **验证新源连通**：在服务器上用新账号行跑连通测试脚本 `scripts/test_xtp_connect.py`。它会登录新账号、订阅行情、等 20 秒看有没有收到数据，**绝不下单**。收不到合约和行情数据就是账号配错或连不上——这一步由你亲自排除，系统不会替你验证。
3. **首次启用第二个实例的注意**：如果备用实例（quant2）是第一次启用，管理员还需在服务器上完成一次实例与账号的绑定（服务端配置，一次性操作，做完后续切换不用再动）。
4. **确认切换时点**：等你方便的非交易时段。

> 不要用「起一次 Hub 试运行」来验证新源——Hub 一起来就会和现任抢写行情的权限，这个旧做法已作废。只用上面的独立测试脚本。

## 四、执行切换

在服务器上运行（参数填你要切到的实例名：`quant` 或 `quant2`）：

```bash
setsid python -m src.md_hub.switch confirm quant2
```

- **加 `setsid` 的原因**：confirm 是阻塞式的，从几秒到 2 分钟出结果。期间 SSH 断了、终端关了，切换会被打断。加 `setsid` 后关终端不影响它跑完。
- **期间不要离开终端**：等命令自己返回结果，中途不要另开一个再跑一次（同一条命令可安全重跑，但要等前一次结束）。
- 命令返回 0 只说明新源接过了写行情的权限，**还不算验收完成**，见第五节。

**退出码对照**（看到非 0 先对这张表）：

| 退出码 | 意思 | 你该做的 |
|---|---|---|
| 0 | 切换成功，新源已接管 | 做第五节的验收 |
| 2 | 有实盘任务在跑，系统拒切 | 先停实盘任务，或改到盘后再切 |
| 3 | 等旧源让位超时（60 秒） | 跑 `check` 看状态（见第七节），查旧源日志，排除后重跑 confirm |
| 4 | 等新源接管超时（30 秒） | 查新源日志（常见原因：账号行配错），排除后重跑 confirm |
| 5 | 实例名写错了（只能是 quant 或 quant2） | 改正参数重跑 |

## 五、切换完成判据（两步验收，缺一不可）

confirm 返回 0 只是第一步。**以下两步都过了，这次切换才算验收完成**：

1. **次日开盘看首根分钟行情**：9:31 前后应出现第一根 bar。系统会在 9:16 起监控首根 bar，你开盘后到行情页确认一下即可。有 bar → 消费行情的实盘任务会自动完成数据暖机，不需要你动手。
2. **当日盘后跑口径比对**：收盘数据回补完成后（约 15:10 之后），运行：

```bash
python -m src.md_hub.switch diff <切换当日日期>   # 例如 2026-09-22
```

   它把新源写的分钟行情和独立来源的回补数据做全量比对，收盘价或成交量相对偏差超过 2%、或有缺失都会列出明细。**没有告警（退出码 0）才算切换验收完成。**

**如果次日 9:33 还没有首根 bar**：按第六节切回旧源，不要等。

## 六、切回旧源

切回没有单独的回滚流程——**同一条命令，参数填旧实例名**，和正切完全对称：

```bash
setsid python -m src.md_hub.switch confirm quant
```

推荐动作顺序（次日开盘无行情时）：
1. 停掉在跑的实盘任务；
2. 跑上面的命令切回；
3. 等切换成功后重启实盘任务；
4. 排查新源为什么收不到行情（连通测试脚本 + 新源日志），问题解决后再择机重切。

## 七、出问题怎么办

先跑状态检查命令，看当前处于什么状态：

```bash
python -m src.md_hub.switch check
```

输出里的四个状态键（配合下表看）：

| 键名 | 白话 |
|---|---|
| `hub:active_instance` | 现任：现在写行情的是哪个实例（quant 或 quant2） |
| `hub:switch:intent` | 切换意图：存在说明正在切换中（5 分钟没走完会自动作废） |
| `hub:gen` | 世代号：每切一次或重启一次就 +1 的计数 |
| `hub:lease` | 写权持有者：同一时刻只允许一个实例写行情 |

常见情况速查：

| 现象 | 判断与处理 |
|---|---|
| check 显示「稳态：现任=…」且无 intent | 一切正常，不在切换中 |
| check 显示「切换中」 | 切换没走完。目标还没接管 → 可跑 `python -m src.md_hub.switch abort` 中止，回到现状；目标已接管 → abort 会拒绝，直接走第六节切回 |
| confirm 返回 3 | 旧源 60 秒没让位。查旧源日志；确认卡死后人工停掉旧源服务，新源会自动接管 |
| confirm 返回 4 | 新源 30 秒没接管。查新源日志，常见是账号行配错；排除后重跑 confirm |
| 切换后次日无行情 | 按第六节切回旧源 |
| 输出里出现「疑似假接管」提示 | 当天先观察，次日开盘无行情就切回；有告警及时报管理员 |

**兜底原则**：切换安排在盘后，当天数据完整性由盘后回补独立保证——切换出问题**不会丢数据**，最多影响次日开盘的实时性（分钟行情晚到，开盘后自动补齐，不是丢失）。

## 八、系统自动做的事（不用你管，但要知道）

- 有实盘任务在跑时，confirm 自动拒切（退出码 2），想误切都切不了。
- 切换后，旧源的残留消息会被自动拒收，不会污染新源的数据。
- Hub 进程出故障时，系统约 30 秒内自动重拉（术语表里的「看门狗重启码」）——**这是正常自愈，不是事故**，不需要人工干预。

## 九、关于新券商数据源（重要前置）

切换协议本身不挑数据源，但**当前平台的行情接入层只支持中泰 XTP**。所以：

- 现在能做的切换：**第二个 XTP 账号**（quant → quant2）。
- 如果新源是其他券商（如东财）：需要先开发该券商的行情接入模块（东财测试账号申请中）。**账号和接入模块都就绪之前，这类切换做不了**——到时本册会随接入能力更新。

## 十、命令速查表

| 命令 | 作用 |
|---|---|
| `setsid python -m src.md_hub.switch confirm <quant\|quant2>` | 执行切换（参数=要切到的实例名；阻塞式，期间别离开终端） |
| `python -m src.md_hub.switch check` | 查切换状态（稳态/切换中） |
| `python -m src.md_hub.switch abort` | 中止切换（仅限目标还没接管时） |
| `python -m src.md_hub.switch diff <YYYY-MM-DD>` | 切换当日的口径比对（盘后回补完成后跑，无告警=验收完成） |

## 十一、术语表

| 术语 | 白话 |
|---|---|
| 数据源 | 实时推送行情的账号（当前=中泰 XTP） |
| 切换 | 把写行情流的账号从 A 换成 B |
| 实例（quant / quant2） | 服务器上两份行情服务的名字，各自绑一个行情账号。quant=A 实例，quant2=B 实例 |
| 现任 / 继任 | 现任=当前写行情流的实例；继任=要切过去的那个 |
| 世代号（gen） | 每次切换或重启就 +1 的计数器，系统靠它拒收旧源的残留消息 |
| 写权（lease） | 写行情流的权限。同一时刻只有一个实例持有，防止两个源同时写 |
| bar | 一根分钟行情 |
| 口径比对（diff） | 把新源写的行情和独立来源的回补数据逐根对数，偏差超 2% 即告警 |
| 看门狗重启码 | 进程失败后系统 30 秒内自动重拉的机制，属正常自愈，不是事故 |
| 盘后回补 | 收盘后用独立数据源把当日分钟数据补齐，是数据完整性的兜底，与用哪个实时源无关 |
