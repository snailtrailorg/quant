## 一、核心原则（用户裁定 2026-09-21，原话入档）

1. **「傻逼才在一章中间换主播」——数据源切换必须在非交易时段做**（或确认没有实盘策略在运行时）。盘中切源会打断实时行情，实盘任务断粮。
2. **「该是人负责的事情要人负责，该系统负责的才要系统负责」**：
   - **人的职责**：决策切换时机、做必要的准备工作（配置新源、验证新源健康）。
   - **系统的职责**：在「已准备好」的前提下稳定完成切换（不双写、不双开、切换原子）。
3. **「简洁即是完美」**：系统只做原子切换一个动作，不做影子流自动化预热等复杂机制——验证新源是人的手动操作。

## 二、你（操作者）必须了解的规则

### 2.1 什么时候允许切换
- **非交易时段**：交易日盘后（15:05 之后）。此时无实时行情流动、无实盘策略消费，切换最安全。
- 或：盘中但**确认没有任何实盘任务在运行**（系统也会自动拦：有 running 实盘任务时拒绝切换）。
- **禁止盘中带实盘任务时切换**。

### 2.2 切换前你必须做的准备（人职责，系统不代劳）
1. **配置新源账号**：在「集成中心」为新数据源账号建一行（external_interface，如第二个 XTP 账号或其他券商的行情账号）。
2. **手动验证新源健康**：用新账号起一次 Hub 试运行（盘中做，观察日志/心跳确认能正常收到行情），验证完停掉。**系统不做影子流自动验证**——配错账号、连不上、收不到行情这类问题，在这一步由你亲自确认排除。
3. **确认切换时点**：等你方便的非交易时段。

### 2.3 怎么执行切换
- 盘后运行切换命令：`switch.py confirm`（编排器 CLI，具体命令名以实施为准）。
- 系统自动完成：查实盘任务（有 running 拒切）→ 置切换标记 → 推进世代号 → 旧源让位 → 新源接管 → 清理标记 + 写审计日志。
- 切换本身是**一个原子动作**（秒级），你在旁边不用做任何事。

### 2.4 切换后观察什么
- **次日开盘**：新源第一根 bar 出现，worker 自动重暖机（当天数据盘后权威回补已就位，切换不影响数据完整性）。
- 若次日开盘迟迟无行情：查新源连接/日志（参照启动排错手册）。

### 2.5 出问题怎么办（人工介入速查）
切换涉及的三个状态键（Valkey）：`hub:switch_intent`（切换意图）/ `hub:gen`（世代号）/ `hub:lease`（当前写权持有者）。异常时按下表判断：

| 现象 | 判断 | 处理 |
|---|---|---|
| confirm 后一直没切过去（旧源还在写） | 旧源让位慢（≤5s 轮询）或卡死 | 等 5s；仍不动→查旧源进程日志，必要时人工停旧源（新源会自动接管） |
| 新源接管后没有行情 | 新源账号/连接问题 | 查新源日志；不行就人工切回旧源（重新 confirm 旧账号） |
| 切换中进程崩溃（半切状态） | 三键组合见方案集 §六判定表 | 按判定表冷切或人工介入 |

**兜底原则**：切换发生在盘后，任何异常都有盘后权威回补兜底，**不会丢数据**——最多影响次日开盘的实时性。

### 2.6 系统自动做的事（你不用管，但要知道）
- 切换前自动拦截 running 实盘任务（防误切）。
- 切换后旧源的消息会被 worker 自动拒收（世代号机制，防旧源残留消息污染）。
- 当日数据完整性由盘后权威回补（Tushare/腾讯）保证，与用哪个实时源无关。

## 三、术语对照
- **数据源（源/主播）**：实时推送行情的账号（当前=中泰 XTP；将来可接其他券商）。
- **切换（换主播）**：把写行情流的源从 A 换成 B。
- **世代号（gen）**：每次切换/重启 +1 的计数器，系统靠它拒收旧源的残留消息。
