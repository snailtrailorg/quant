## 一、ts aware 化（防御性，前置已确认无数据迁移）

**前置（已实测）**：生产 `SHOW timezone` = Asia/Shanghai，现有 naive 数据存储正确。ts aware 化 = 消除对 PG 会话时区/DB 默认的隐性依赖，**不改存储语义**（naive 写 Asia/Shanghai 与 aware +08:00 写，最终 timestamptz 内部值一致）。

**helper（放 data_platform，A 股专用，非 quant_common）**：
```python
SHANGHAI = zoneinfo.ZoneInfo("Asia/Shanghai")   # IANA，非固定 offset（1986-1991 DST 期，盲审 B-P2）
def as_shanghai(dt: datetime) -> datetime:
    """naive → Asia/Shanghai aware；已 aware → astimezone 归一（盲审 B-P2 不原样返回）。"""
    return dt.replace(tzinfo=SHANGHAI) if dt.tzinfo is None else dt.astimezone(SHANGHAI)
```

**范围**（grep 全部 `to_pydatetime()` 逐点纳管，实际生产写入点 3 个）：
- `base.py TushareAdapter.to_bar_rows`（日线 trade_date + 分钟 trade_time）——覆盖 bar_1D/1min/5min/index 全部 K 线写入

**兜底**：`db.py _db_session_options` 追加 `-c TimeZone=Asia/Shanghai`（pin 死，防 DB/server 默认漂移）。
