## 一、背景与需求

### 1.1 一句话锚点

> 一个策略绑一个交易账号；行情来自该账号所属市场、下单走该账号柜台，成交/持仓/资金与该账号对得上。

### 1.2 真实需求

用户持多个交易账号（券商/交易所），每个账号品种权限不同（创业板/北交所/主板等）。多账号并存：一个策略绑一个账号，选标的校验该账号的品种权限，成交/持仓/资金按账号隔离。

### 1.3 同源的准确边界（分市场）

**「同源」的价值是「口径一致」，不是「消除滑点」——且分市场含义不同：**

| 市场 | 同源的真实含义 | 架构含义 |
|---|---|---|
| A 股 | **TD 同源**（成交/持仓/资金必须来自实际交易的券商）；MD 本就全市场同源（L1 各券商转发同一份快照），**无需 MD per-venue** | MD 单 hub，TD per-venue |
| 加密永续 | **MD+TD 都同源**（行情、账户、资金费率都交易所特定，不同所不一致） | MD+TD 都 per-venue |

> 为什么 A 股 MD 不 per-venue：L1 快照内容各家一样，per-venue 换来的只是毫秒级转发时延差（对分钟级策略无意义），却要付出 N 个 hub 实例的租约/心跳/自愈/监控改造面 + N-1 个故障点 + N 份订阅额度。A 股 MD 单 hub 由 doc 14 的「单活双实例」保证高可用。

## 二、核心抽象：Venue = 交易账号

### 2.1 定义

**Venue = 一个 `external_interface` 行 = 一个交易账号**，不是「券商」——同券商多账号 = 多个 Venue。

- 加密 venue：provider=binance_perp/okx_perp，MD+TD 同该交易所，需 per-venue hub。
- A 股 venue：provider=xtp/emt_emq，TD 走该券商柜台（per-venue），MD 用单 hub（L1 同源）。
- `emt_emq.py` FIELD_SCHEMA 已是多凭证段（emq_* 行情 + emt_* 交易），「一行一账号」成立。

### 2.2 品种权限模型（三正交维度）

| 维度 | 取值 | 数据来源 | 生效范围 |
|---|---|---|---|
| 品种 category | stock/etf/convertible/fund/reits/perp | `security_master.category`（单一真源） | 品种判定只用 category，不用代码前缀 |
| 板块 board | main/star/chinext/bse（CDR→star） | `security_master.board` 列，同步 Tushare market+exchange 落库 | 仅 stock 生效 |
| 风险警示 ST | is_st（布尔） | `security_state`（kind='st'，时变） | 仅 board=main 生效（科创/创业/北交 ST 风险已含于板块适当性；**北交所 ST 口径待核实**） |

**校验规则（category 先于 board）**：stock → board∈allowed_boards + ST 校验；convertible → 可转债权限（10万+2年）；etf/fund/reits → 跳过板块；perp → 加密分项 gate。

**校验时点（三级）**：①建任务拒绝 ②worker 启动 fail-fast ③下单前拦截。权限人工配置（非实时），**券商柜台兜底**（柜台侧独立校验权限）。

### 2.3 同源锚点 schema 化

```python
live_task.venue_id BIGINT NOT NULL REFERENCES external_interface(id) ON DELETE RESTRICT
```

- NOT NULL + RESTRICT（删 venue 前须显式解绑所有引用任务）；FK 迁移与删除守卫同版本。
- **venue_id 语义键（量化 P1-4）**：row_id 删行重建会换号断历史，资金账/持仓/成交历史不可接受。**加稳定语义键**（券商账号号 user_id，UNIQUE），row_id 仅作内部 FK——换凭证/重注册不改语义键，历史不断。

## 三、数据设计

### 3.1 账户身份线统一

`venue_id` 取代散落的身份线（代表性清单，完整经 §八 grep 识别）：`live_task.account_id`/`position_snapshot.account_id`/`position_refresh.account_id` → venue_id；`strategy_account` 退役目标；`accounts` 表待决。**含对账路径（量化 P1-3）**：`trade_log`/`order_log`/`/api/reconcile` 收盘对账（doc 12 四账对账）也要 per-venue 化——否则 A 任务成交被归因到 B 账户。

### 3.2 `account_snapshot` 现状修正

`account_snapshot` 无 account_id 列（单账户**单行**全局表），需**改为多行** + venue_id 列 + 读写方 venue 过滤（下单量 `strategy.py:317/327/338/351`、敞口 `risk.py:158-173`、资金基线读方**必须 per-venue**，否则混仓）。这是交易正确性决策，非视图选择。

### 3.3 流与键（A 股单 hub 无 venue 维度，加密 per-venue）

| 键 | A 股 | 加密 | 读方 |
|---|---|---|---|
| 流前缀 | `hub:bars:{symbol}`（单 hub，无 venue） | `hub:bars:{venue_id}:{symbol}` | worker |
| 心跳 | `quant:hb:md-hub`（单 hub，无 venue） | `quant:hb:md-hub:{venue_id}` | worker buy 闸、监控 |
| 租约 | `hub:lease`（M5 单活双实例保留） | `hub:lease:{venue_id}` | hub boot、SA4 |

> **M5 保留（量化 P1-5）**：A 股单 hub 的高可用靠 doc 14 的「单活双实例 + active_instance 仲裁」，**不退役 M5**。加密 per-venue hub 各自独立（无 A/B 切换），租约按 venue 分。

## 四、模块设计

### 4.1 MD：A 股单 hub（单活双实例），加密 per-venue

```
A 股：quant-md-hub@quant  → XTP L1 行情 → hub:bars:{symbol}（单活双实例，M5 仲裁）
加密：quant-md-hub@7      → 币安 WS     → hub:bars:7:{symbol}
      quant-md-hub@8      → OKX WS      → hub:bars:8:{symbol}
```

- A 股单 hub 沿用 doc 14（不拆、不退役 M5）；加密才 per-venue。
- 订阅：A 股单 hub 订阅全部 A 股标的（额度按 XTP 单账号）；加密 per-venue 订阅各所标的。

### 4.2 worker：TD per-venue（A 股/加密都 per-venue）

```python
venue = get_venue(venue_id)
adapter = create_adapter(venue.provider, make_td_gateway(venue))  # TD 走该账号柜台
stream  = f"hub:bars:{venue.id}:{symbol}" if is_crypto(venue) else f"hub:bars:{symbol}"
if is_live() and is_stub(adapter): raise SystemExit(78)             # 加密 stub 硬闸
if not venue_allows(venue, symbol): raise SystemExit(78)             # 权限三级校验
```

- TD 硬编码 XTP → 按 venue.provider 动态建网关（EMT/加密不套用 XTP 每日连接窗）。
- 同源保证：TD 侧（venue_id 决定柜台，成交/持仓/资金同源）是核心；加密 MD 流带 venue_id，A 股 MD 单 hub 无 venue 维度。

### 4.3 自愈/监控

- A 股单 hub：沿用现有 SA4/health_monitor 单实例（不改造多 hub）。
- 加密 per-venue hub：SA4 期望态按「加密 venue 行 → 实例集」；租约/维护键按 venue 分。

## 五、流程设计

### 5.1 源生命周期（仅加密 venue 有 hub 实例生命周期）

```
注册加密源（加 quote 能力的行）  → 先 DB commit → 后 systemctl enable --now
停用/删除加密源                 → 先改行/打维护键 → 后停实例（防 SA4 300s 反拉起）
A 股账号注册                   → 只加 external_interface 行（不建 hub 实例，MD 走单 hub）
```

### 5.2 worker 启动流程

读 venue → 权限校验（三正交）→ create_adapter → 消费 MD 流（A 股单 hub 流 / 加密 per-venue 流）。

### 5.3 建任务流程

建任务选标的：①标的 category/board/ST ∈ venue 权限（否则 400）；②venue 收窄到 enabled+trading。

## 六、金融面（交易可靠性技术面）

| # | 面 | 设计 |
|---|---|---|
| F1 | 资金隔离 | 每 Venue 独立资金账户，按 venue 记账；A 股当日卖出 T+1 提现，加密保证金不可跨所互抵 |
| F2 | 账户级敞口控制 | 同 Venue 同标的同向合并敞口（读写方 per-venue）；同标跨账户反向做技术性拦截（防策略打架，可配置豁免，默认开+落审计） |
| F3 | 费率对账 | 股票印花税卖出 0.05%+过户费 0.001% 双边+佣金（全佣，最低 5 元）；场内基金免印花免过户；可转债免印花；加密资金费+maker/taker+USDT→CNY 折算。以现行标准为准，实施前逐项核对 |

**出界（平台不做，选标的排除/告警，非权限校验）**：退市整理期股票、港股通 ETF、两融账户、可转债转股/强赎·回售、举牌/一致行动人/减持/要约线、增值税/企税、红利税、程序化报备（券商侧办理）、反洗钱/外汇、加密合规（用户自担）。

## 八、改造方向与识别方法

**架构文档交付「改造方向 + 识别方法」，不交付完整改动清单。**

### 8.1 改造方向

| 域 | 改造 |
|---|---|
| MD | A 股不变（单 hub）；加密 per-venue hub |
| TD | 硬编码 XTP → per-venue 动态网关 |
| 数据供给 | venue_id 取代散落身份线（含对账路径）；board/category 数据字段化 |
| 风控/自愈/部署 | A 股不变；加密 venue 化 |

### 8.2 识别方法（编码阶段 grep 双轨，不穷举）

- grep 辅助：全局键（`hub:`/`quant:`）、单例（`quant-md-hub@quant`）、TD 硬编码（`XTPAdapter`/`xtp_session` 等）、**前缀判断**（`_board_of`/`_market_of`/`detect_category`/竞价判定 → 迁 category/board 字段）、单市场假设（`in_astock_session` 等）、自由文本（`account_id`）、对账路径（`trade_log`/`order_log`/`reconcile`）。
- 人工审计兜底：缺失的 venue 维度、缺失的 polkit 动作面、缺失的 FK 列、缺失的会话模型分支。

## 十、风险与验收

### 风险
1. 权限错配 → 三级校验 + 券商柜台兜底。
2. 数据链 fail-open（ST/北交所/退市整理识别）→ 批 A 数据字段化落地识别字段。
3. 删行重建断历史 → 稳定语义键。
4. 加密 stub 假单 → is_live stub 检测。
5. 前缀判断迁移不彻底 → 编码 grep 双轨回写。

### 验收
1. A 股单 hub 正常出 bar（沿用 doc 14）；加密源注册→起实例→出 bar。
2. 同源：TD 侧 venue_id 决定柜台，成交/持仓/资金 per-venue 隔离。
3. 权限三级校验：无创业板权限账号建创业板任务被拒、越权下单被拦。
4. 多账号并存：两个 XTP 账号 TD 各走各柜台，成交/持仓/资金不混。
5. 金融面：资金按 venue 隔离、敞口 per-venue、费率对账按品种、对账 per-venue。
