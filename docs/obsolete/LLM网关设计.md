# LLM Gateway 代码改进建议

## 核心决策：移除过度设计
- **移除 `tier` 机制**：模型能力分级是主观且动态的，容灾应基于 `priority` 全局排序而非人工标签。
- **移除语言自动注入**：大模型天然根据输入语言回复，额外注入系统指令不仅多余，还可能干扰模型判断。

---

## 一、P0：必须立即修复

### 1. 移除 `tier` 机制
- **改动**：
  - 删除数据库表 `llm_model_config` 的 `tier` 字段。
  - 删除代码中的 `Tier` 类型定义。
  - 删除 `chat()` 和 `chat_stream()` 的 `tier` 参数。
  - `_load_models_from_db()` 返回按 `priority` 排序的全局模型列表。
  - `_resolve_model()` 改为 `_get_primary_fallback()`，直接取列表前两个。
- **收益**：逻辑简洁，模型管理按实际优先级而非人为分级。

### 2. 补全 Token 限制逻辑
- **问题**：数据库已存 `context_window` 和 `max_tokens`，但调用 API 时未使用。
- **改动**：
  - 调用前估算输入 token（用 `tiktoken`），若超过 `context_window` 的 90% 则截断或报错。
  - API 调用时显式传入 `max_tokens=conf.get("max_tokens", 2048)`。
  - 入口增加最大字符数限制（如 50 万字符）做快速过滤。
- **收益**：防止 API 报错，控制成本，保障 SLA。

### 3. 修复工具过滤权限漏洞
- **问题**：`_filter_tools()` 若传入 `tools` 则完全覆盖白名单，导致角色权限失效。
- **改动**：
  - 先基于角色构建允许的工具名集合。
  - 与传入 `tools` 取交集，并剔除 `FORBIDDEN_TOOLS`。
  - 不允许传入工具绕开白名单。
- **收益**：修复越权风险。

### 4. 熔断状态并发安全
- **问题**：`_failed_counts` 和 `_last_fail_time` 多线程下数据竞争。
- **改动**：使用 `threading.Lock` 保护读写。
- **收益**：避免数据错乱。

### 5. 移除语言自动检测与注入
- **理由**：大模型会根据输入语言自动选择回复语言，无需注入 `[language: zh]` 或 system 指令，该功能不仅多余且可能干扰模型判断。
- **改动**：删除 `_inject_lang()` 方法及其调用，`chat()` 移除 `lang` 参数。
- **收益**：减少无意义逻辑，提升响应速度。

---

## 二、P1：重要建议实施

### 6. 全局默认模型可配置
- **改动**：`config.yaml` 增加 `default_model_id`，未配置则取 `priority` 最小的模型。
- **收益**：运维可灵活切换默认模型。

### 7. 复用 HTTP 客户端
- **改动**：缓存 `OpenAI`/`AsyncOpenAI` 实例，以 `(base_url, api_key)` 为键。
- **收益**：减少连接开销，提升性能。

### 8. 统一配置源
- **改动**：删除 `config.yaml` 中未被使用的 `tiers`/`providers` 段，仅保留 `failover`、`default_model_id` 等。
- **收益**：降低运维混淆。

### 9. 优化重试与熔断
- **改动**：重试改为指数退避；熔断增加“半开”状态探测。
- **收益**：提升自愈能力。

---

## 三、P2：按需优化

### 10. 增加可观测性埋点（Prometheus）
- **记录**：请求总数、成功率、延迟分位数、熔断状态。

### 11. 结构化日志（JSON）
- **包含**：`trace_id`、`provider`、`model`、`latency_ms`、`status`、`tokens_used`。

### 12. 预计算主备指针
- **改动**：`reload_models()` 时缓存主备模型，调用时直接返回。

---

## 四、P3：长期架构演进

### 13. 工具执行与网关解耦
- **改动**：网关仅返回 `tool_calls`，由上层执行，移除 `handler`。

### 14. 插件化路由策略
- **改动**：抽象 `Router` 接口，允许自定义选模型逻辑。

### 15. 流式工具调用支持
- **改动**：预留流式返回 `tool_calls` 增量的能力。
