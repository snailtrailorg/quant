# 02 · 角色与旅程：quant 平台的业务底座

> 设计优化的出发点不是"哪个页面好看"，而是"用户在策略生命周期里怎么移动、在哪里做决策、决策需要什么信息"。

## 一、用户角色（从平台角色体系反推：admin / trader / analyst）

### 1. 策略研究员（analyst）
- **日常**：早盘前看数据完整性 → 筛选标的入池 → 迭代因子/策略 → 跑回测 → 对比参数
- **决策点**：这个因子组合的信号质量是否值得上实盘？
- **高频页面**：筛选器、股票池、因子、策略、回测
- **关注指标**：回测年化/回撤/夏普、信号覆盖度、因子分布

### 2. 交易员/实盘运营（trader）
- **日常**：开盘前检查实盘任务与数据健康 → 盘中盯订单/持仓/PnL/风控 → 收盘后对账 → 处理异常
- **决策点**：现在要不要熔断？这笔账实分离怎么处理？
- **高频页面**：Dashboard、实盘任务、交易、监控、风控、对账
- **关注指标**：今日盈亏、持仓敞口、风控阈值水位、对账差异

### 3. 管理员（admin）
- **日常**：账号/邀请、数据源与券商通道、IM 推送、LLM 配置、审计
- **决策点**：通道切换、权限收敛、成本控制（LLM 用量）
- **低频但高危**：密钥类配置、删账号

> 注意：本平台当前实际是 **Bernard 一人三角色** 的个人量化工作台，但角色体系已存在（邀请制、三角色）。设计要同时满足"单人快"与"多人不乱"——信息架构按角色分可见性，但单人模式下要允许一屏纵览。

## 二、策略生命周期（平台的灵魂流程）

```
数据准备 → 标的筛选 → 因子研究 → 策略构建 → 回测验证 → 实盘上线
    ↑                                                        ↓
数据补采 ←—— 复盘分析 ←—— 风控对账 ←—— 盘中监控 ←—————————————┘
```

每个环节的产出是下一环节的输入，**UI 必须让这个链条可以顺着走完**：

| 环节 | 页面 | 输入 | 产出 | 下一步 |
|---|---|---|---|---|
| 数据准备 | 数据管理/完整性 | 数据源 | 完整的行情库 | 补采缺失 |
| 标的筛选 | AScreen/CBScreen/ETFScreen | 行情+基本面 | 股票池 | 入池 |
| 因子研究 | 因子 | 因子表达式/Python | 可复用因子 | 被策略引用 |
| 策略构建 | 策略 | 因子+权重+聚合器 | 策略定义 | 发起回测 |
| 回测验证 | 回测 | 策略+区间+标的 | 净值/回撤/交易明细 | 通过→实盘 |
| 实盘上线 | 实盘任务 | 策略+账户+资金 | 运行中任务 | 监控 |
| 盘中监控 | 交易/监控 | 实时行情+订单 | 持仓/PnL/风控水位 | 异常→处置 |
| 风控对账 | 风控/对账 | 券商快照+trade_log | 账实一致性 | 差异→处理 |
| 复盘分析 | 分析/AI对话 | 全历史数据 | 归因结论 | 反哺因子/策略 |

## 三、已观察到的流程断点（证据见 01-体验审计）

1. **告警无去处**：通知中心收到 critical 级"三账对账异常"，body 是无结构多行文本，点击跳转映射含错误（email→/logs），到对账页后差异也是纯文本列表，无法下钻到持仓/订单
2. **研究链路断裂**（研究效率最大出血点）：策略⇄回测双向断链——策略页无"发起回测"入口、策略行无回测战绩、回测列表只显裸 strategy_id；因子"被引用"是死数字不可点；三级开关（代码校验→回测证据→实盘门禁）黑箱化，实盘任务下拉静默过滤未验证策略，被拦用户无法自助定位差哪一级
3. **首页不承担指挥中心职能**：4 个数字 + 1 张 4 列表，无权益曲线、无实盘任务状态、无风控水位、无数据健康、无待办告警
4. **回测列表接口 500**（2026-08-29 实测），核心验证环节不可用
5. **数据展示未结构化**：券商 params、策略 factors/aggregator 等以双重 JSON 字符串裸露；选股 conclusion 是拼接的长文本

## 四、设计原则（由此推导）

1. **生命周期优先于功能分类**：导航与页面组织按"研究 → 验证 → 实盘 → 复盘"的流水线，而不是按技术模块
2. **每个数字可下钻**：KPI → 曲线 → 明细 → 处置动作，三层内到达
3. **异常是一等公民**：critical 告警全局常驻（顶栏/侧栏状态灯），点进去必须有结构化的差异表和处置按钮
4. **中国市场语义**：红涨绿跌、万元/亿元单位、交易时段感知（盘中实时/盘后静态的 UI 状态区分）
5. **单人工作台效率**：高频操作 ≤2 跳，支持全局命令面板（⌘K）直达任何策略/标的/因子
6. **危险操作分级**：启停实盘、熔断/恢复、删数据源——不同破坏等级不同确认强度
