# 10 · 多维权限体系设计

> 需求（Bernard，2026-08-29）：最终权限机制为**多维权限**——菜单/页面权限、API 权限、数据权限；每个维度既可按**用户级别（角色）**设置，也可按**单个用户**设置。个人中心入口钉死顶栏右上角（菜单可能被权限屏蔽导致无入口）。

## 1. 模型总览

```
主体 Subject                     维度 Dimension          资源 Resource（粒度）
──────────────                  ─────────────          ──────────────────────────
角色 role（模板）                ① 菜单/页面 nav         16 菜单项 + 页面（含 profile 等
  admin / trader /                                        隐藏页）→ 三态：隐藏 / 只读 / 读写
  analyst / viewer               ② API api              端点组（factors·strategy·backtest·live·
                                                          orders·risk·reconcile·data·integrations·
                                                          users·logs·system…）× 读/写
用户 user（继承+覆盖）            ③ 数据 data            · 市场域：A股 / 场内基金 / 转债 / 加密
                                                          · 账户域：可见账户 ID 集合
                                                          · 敏感级：risk_log 明细↔计数、持仓
                                                            明细↔聚合、成本价可见性
```

**求值规则**（deny 优先，用户层覆盖角色层）：

```
最终权限 = 角色默认 ⊕ 用户授予(grant) ⊖ 用户回收(deny)
优先级：用户 deny > 用户 grant > 角色 deny > 角色 grant > 默认拒绝
```

**系统内置安全策略**（优先于矩阵，不可被 grant 覆盖降权）：
- 熔断：所有可登录角色均可触发（安全方向动作低门槛）
- 恢复：仅 admin（与 IM 侧同门槛）
- 对账豁免/清零：仅 admin（执行守护者不能抹平自己的差异）
- 末位 admin 保护：不可注销/降级自己

## 2. 与 03 v2.1 矩阵的关系

03 §3.4 的角色×页面 RW 矩阵 = 本模型 nav+api 两维在四角色上的**默认值**；本文件把它数据化并扩展 api/data 两维。trader 数据健康由顶栏健康灯承接的方案不变（nav 维度对 trader 隐藏"数据中心"，data 维度给摘要级）。

## 3. 存储与运行时

```
permission 表：
  subject_type: role | user
  subject_id  : 角色名 | user_id
  dimension   : nav | api | data
  resource    : 菜单键 | 端点组 | 域键（market:astock / account:{aid} / sensitive:risk_log）
  effect      : allow | deny
  note / updated_by / updated_at（全量审计）
```

- 登录时把 (role 默认 + user override) 编译为**权限指纹**，随 /auth/me 下发；前端三处消费：菜单渲染 / 路由守卫 / 按钮 v-if——**显性化层，非安全边界**
- 后端每个端点挂依赖注入 enforcement（端点→端点组→查指纹）——**唯一安全边界**
- 数据维度在查询层生效：市场域进 WHERE、账户域进过滤、敏感级决定字段投影（明细↔计数）
- 权限变更：即时生效（指纹重编译）+ 审计 + （可选）踢下线刷新

## 4. 管理界面（设置 → 权限管理，仅 admin）

```
┌ 权限管理 ────────────────────────────────────────────────┐
│ [角色: admin▾] [用户: bernard▾]（用户视图=角色+override） │
│ ① 菜单/页面   16 项 × 隐藏/只读/读写 三态点选             │
│ ② API         端点组 × 读/写 开关（系统策略项锁定🔒）     │
│ ③ 数据        市场域勾选 · 账户勾选 · 敏感级三档          │
│ 顶部常驻：后端强制 · 菜单只是显性化 · 变更全程审计        │
└──────────────────────────────────────────────────────────┘
```

配套：**"我的权限"玻璃盒**（个人中心下拉第三项）——用户随时可见自己被授予/拒绝的依据，被拒操作指明规则来源（呼应三级开关去黑箱化哲学）。

## 5. 入口设计原则（Bernard 指令）

**个人中心入口钉死顶栏右上角**（头像下拉：个人资料/修改密码/语言主题/我的权限/退出）——菜单/页面权限可把任意菜单项隐藏，但顶栏入口不属于任何菜单维度、不可被权限屏蔽，保证每个已登录用户永远能触达自助功能（改密/注销/查看自己的权限）。

## 6. 渐进落地（对齐 09"先两档后四角色"）

| 阶段 | 内容 |
|---|---|
| A | permission 表 + 后端 enforcement，编译档位= admin/非 admin 两档（单开关替换散落硬编码） |
| B | 四角色默认矩阵数据化上线（03 v2.1 矩阵导入），前端菜单/路由/按钮三处消费指纹 |
| C | per-user override 编辑器 + "我的权限"玻璃盒 + 数据敏感级脱敏（viewer 持仓聚合/risk_log 计数） |
| D | 账户域细粒度（多账户多人归属）、市场域按用户分配（如只做转债的分析员） |

## 7. 现状与差距（2026-08-29 源码检索）

**现状基线**（比预期好的起点）：
- 角色：viewer/analyst/trader/admin 四级（users.role，默认 viewer）
- 后端已有**双轨鉴权**：`require_role(*roles)` 白名单 + `require_perm(perm)` 查 13 个权限键（auth.py:51，**硬编码 Python 字典**）——策略写/实盘启停=strategy_control(analyst+trader+admin)、熔断 halt=trader+admin、**resume 仅 admin（与 IM 已对齐）**、用户管理仅 admin；JWT 24h + Valkey 黑名单 + 禁用检查（fail-closed）
- 前端三层：路由守卫（仅 meta.admin 二值）/菜单 v-if（分组级）/按钮 v-if（全站仅 4 处）
- IM 侧：im_bot_users 行→bot default_role→拒绝（fail-closed）；LLM 工具三层（READ 全员/TRADER/ADMIN）

**六项差距**（对照多维目标）：
1. **单用户维度全线缺失**：无权限表/用户级覆盖/黑白名单——需建 permission 表（§3）
2. **数据权限零基础**：docs 08 明示"数据共享不加 user_id 隔离"，策略/回测表无 owner 字段，viewer 可见全部持仓盈亏——需 owner 字段+查询层过滤+敏感级投影（§1③）
3. **权限配置硬编码**：13 权限键在代码字典，改权限要发版——迁移为 DB 权限表+管理面（§4），require_perm 接口不变、底层换查表
4. **菜单粒度粗**：路由仅 admin 二值、按钮级仅 4 处——按 §1① 三态菜单映射表重做（现状 trader/analyst 页内操作全靠后端 403 兜底，用户撞墙无解释——配"我的权限"玻璃盒）
5. **前后端不一致实例**：数据删除后端 data_sync=analyst+admin，前端按钮仅 admin 显示——统一以权限指纹驱动后，此类漂移自然消除
6. **JWT role 24h 不刷新**：改角色后旧 token 权限滞留——§3"权限指纹随 /auth/me 即时下发+变更重编译"解决；顺带修邀请注册硬编码 viewer（邀请应可预设角色，现状与用户管理参考文档不符）

**现状宽于设计的两处迁移**（03 矩阵为准收紧）：
- 实盘任务启停删：现状 analyst 全权（strategy_control）→ 目标 analyst 仅创建落灰度、启停删收 trader/admin
- 数据删除：现状 analyst 可删 → 目标收 admin（analyst 保留触发同步/回补）
