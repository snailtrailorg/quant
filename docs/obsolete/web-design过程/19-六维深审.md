## 7. 工具统一专项方案（批一第 3 条的展开设计）

### 7.1 monaco 三包装收敛（CodeEditor/PythonEditor/DslEditor → 一基座两预设）

**目标架构**：
```
components/editor/MonacoEditor.vue  —— 唯一 monaco 挂载点：生命周期/dispose/worker 配置/暗色主题/--font-num 字体，全部单点
components/editor/CodePython.vue    —— 薄预设：language=python + python 校验回调
components/editor/CodeDsl.vue       —— 薄预设：quant-dsl 高亮/补全注册 + /factors/validate 校验回调
```
- **统一校验协议**：基座暴露 `validate: async () => ({ok, message})` prop，行内 ✅/❌ 状态条一套 UI——消灭三处各写的校验反馈
- **迁移映射**：PythonEditor→CodePython（改名）；DslEditor→CodeDsl（吸收现实现）；**CodeEditor 删除**；Strategy/StrategyEdit 的 `plaintext` 场景改用 CodeDsl——策略表达式本来就是 DSL，用 plaintext 是能力降级（无高亮无补全无校验）
- **风险**：低——行为等价迁移；一次 commit 完成，冒烟覆盖三个入口（因子试算/策略 DSL/策略 Python）

### 7.2 图表双栈定界（echarts vs klinecharts）

**真问题不是"两栈并存"，是"同一种图用了两栈"**：StockDetail 的 K 线用 echarts candlestick、KlineDialog 的 K 线用 klinecharts——交互（十字线/复权切换/指标叠加）随入口漂移。
- **立法**：K 线类（蜡烛+分时）**统一归 klinecharts**（专业能力：副图指标/十字线/数据精度）；统计类（净值/回撤/柱状/饼/水位）**统一归 echarts**。StockDetail 的 echarts 蜡烛图迁移至 klinecharts（与 KlineDialog 共用一个包装组件）；KlineDialog 内混引的 echarts 用途归位清理
- **补一个 `useEcharts` composable**：主题注册/resize 监听/dispose 统一——消灭各页手写 init 样板（04 号 §4.6"统一 ECharts 主题"的落地件）
- 判据写进 DESIGN.md 工具章节，新图不得再混栈

### 7.3 表格双轨判据成文（el-table vs el-table-v2）

现状 Risk/Reconcile 用 v2、其余 el-table——**不需要全面统一，需要判据成文**：
- 默认 **el-table + 服务端分页**（50/页）
- 仅"千行级单屏滚动、不宜分页的长流"（risk_log/审计类）用 **el-table-v2 虚拟滚动**
- 判据写入 DESIGN.md，避免下次"顺手用 v2"或"顺手用 el-table 直渲 500 行"
