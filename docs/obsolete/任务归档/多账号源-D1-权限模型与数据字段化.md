# 多账号源 D1 · 权限模型与数据字段化（详细设计）

> 上级：`docs/architecture/A05-多账号源架构设计.md` §三/§四/§五契约4·5。状态：详细设计（待双盲审）。
> 方法：先框架后详细；本件是 D1，自包含 8 字段。

## 一、目标

把三维权限（category/exchange/board）+ ST 子布尔（仅主板）从「代码前缀判断」迁到「数据字段」，补 venue 侧权限存储，产出 `venue_allows(venue_id, symbol) -> bool` 供三级时点（建任务拒绝/worker 启动 fail-fast/下单前拦截）调用。

## 二、现状（已核实，file:line）

- `security_master`：有 `category` 列（stock/etf/convertible/fund/reits/…）、`market` 列（astock|crypto）、**`exchange` 列（SHSE/SZSE/BSE，迁移 0092 填充链已落）**；**无 `board` 列**（`security_master.py:72` SELECT 列清单）。board 需新增枚举列；exchange 已有（股东户维度），无需新增。
- 前缀判断三函数算三维度：`security_master.py:246 _board_of`（板块，仅被竞价/时段调用）、`risk.py:175 _market_of`（分项 market_op，check_order gate）、`factor.py:719 detect_category`（品类，因子路径）——三者非同一维度，本次只退役 `_board_of`/`detect_category`。
- Tushare 板块中文文本落 `asset_static_info.market`（`data_sync/engine.py:456/462`，值=主板/创业板/科创板/北交所/CDR）。
- `security_state`：`(vt_symbol, effective_from, kind, value)`，`kind='st'` 由 namechange 曾用名派生（`engine.py:1070/1133`，戴帽/摘帽滞后）。
- 权限现状：market_op 五键（`perm_registry.py:56` = convertible/etf/astock/binance_perp/okx_perp），无 board 维度、无 per-venue 维度。

## 三、设计决策（已裁定 2026-09-23）

### D1-1 board 字段化：新增枚举列（否决复用 market 列）+ exchange 复用已有列
- **✅ 新增 `security_master.board` 枚举列**（main/star/chinext/bse），从 `asset_static_info.market` 中文文本归一化回填（主板→main / 创业板→chinext / 科创板→star / 北交所→bse / CDR→star）。
- **✅ exchange 复用已有 `security_master.exchange` 列**（SHSE/SZSE/BSE，迁移 0092 填充链已落，非前缀判断），**不新增不重填**。board=main 横跨沪/深，需 exchange 兜底细分（venue 有沪股东户无深股东户时，只放行沪主板）。
- 理由（board）：「market」名在本仓三语义（`security_master.market`=astock|crypto / `asset_static_info.market`=中文板块 / `external_interface.market`=astock|crypto），当键有漂移风险；枚举列单一真源，消费方（`venue_allows`/涨跌停 `band_rules`）直接取枚举。理由（exchange 复用）：股东户是独立于板块的维度（标准开户给沪/深一对，但可能只开一方），board=main 单维度分不出沪/深；标的侧 exchange 列已存在（0092 填充链落库），缺的是 venue 侧 `venue_permission` 的 exchange 允许集合（D1-2）。

### D1-2 venue 侧权限存储：新表（否决加列/扩 live_trading_config）
- **✅ 新表 `venue_permission`**（venue_id FK → 允许 category 集合 + **允许 exchange 集合（SHSE/SZSE/BSE，股东户维度）** + 允许 board 集合 + is_st 允许 + convertible 权限 + perp 分项）。
- 理由：权限是「账号×交易所×品种×板块」关系、集合型，天然独立关系表；与 `capabilities`（能力=代码真源）语义不同不该混；`live_trading_config` 是 RBAC role 级下单卡口，维度都不对。

### D1-3 is_st 判定（board=main 子布尔，非独立维度）
- **✅ ST 不是独立权限维度**，是 board=main 的子状态：涨跌幅由 `band_rules.pct_st` 覆盖（主板 ±5%），适当性=venue_permission 的 is_st 允许布尔（仅主板），退市风险=选标的排除提示。
- **✅ `security_state.kind='st'` 判定布尔改官方名单（交易所公告）**，失效兜底 fail-closed（无档视为「需人工确认」，宁拒勿错下）。现曾用名派生保留作滞后兜底并标注。

## 四、契约

- `venue_allows(venue_id: int, symbol: str) -> bool`：判定顺序 **category → exchange → board →（board=main 且 is_st 时）ST → 分项**（etf/fund/reits 跳过 exchange+board；convertible→可转债权限；perp→加密分项 gate）。**方向语义：③下单前拦截时点仅拦 BUY/开仓，SELL/减仓完全豁免**（ST/board/强赎/退市是准入维度非退出维度，对齐 risk.py F-31 先例——否则持仓戴帽/强赎后被锁死无法止损）。①建任务/②启动两时点非方向性，不适用豁免。
- **board↔exchange 一致性约束**：board=star 必属 SHSE、chinext 必属 SZSE、bse 必属北交（board=main 横跨沪/深，需 exchange 兜底细分）。venue_permission 允许 board=star 但 exchange 集合不含 SHSE = 矛盾配置，`venue_allows` 校验 fail-closed（宁拒勿错）。
- category 填充现状：`etf_basic_info` 回填全标 category='etf'，无 fund/reits 行——venue_permission 的「允许 category 集合」若含 fund/reits 将永不命中（LOF/封基/REITs 全是 'etf'）。本件判定只认 etf；fund/reits 数据填充归属另批，不在 D1。
- 数据列：`security_master.board`（新增枚举，归一化回填）+ `security_master.exchange`（已有列 SHSE/SZSE/BSE）；`security_state.kind` 扩 `st`/`forced_redeem`/`delist_phase`（强赎/退市整理期，见 31 号 §四）。
- 三级时点接入位：建任务拒绝（`web_api` 建任务端点）、worker 启动 fail-fast（`strategy_runner` 启动）、下单前拦截（`risk_control.check_order` 前置）。

## 五、限定范围

只做（本件交付）：`security_master` 加 board 列 + 回填迁移、`venue_permission` 表（含 exchange 维度 SHSE/SZSE/BSE + is_st 布尔）、`venue_allows` 函数（**读侧**）、退役 `_board_of`（迁移到读 board 列）+ 退役 `detect_category`（迁移到「读 category 列 + 品类→因子类派生映射 `CATEGORY_TO_FACTOR_CLASS`」，单源化因子兼容类）。**`_market_of`（分项 market_op 五键）不退役**——是分项维度非板块维度，其替换映射（category 分组→分项 + perp→venue.provider）不在本件。

**挂账（接线批 D5 前置——2026-09-24 代码双盲审 B-P0 确认；写路径已交付：seed 迁移 0098 + GET/PUT 端点）**：①**三级时点接入调用**（建任务/worker 启动/下单前——依赖 D2 的 `live_task.venue_id`）②**board 回填完整性闸**（接线前断言 stock 全量 board 非空，满足 31 号 §四「回填先于校验闸」）③**ST 官方名单 fail-closed**（现 namechange 派生、无档=非 ST fail-open，官方名单另批）。
不碰：D2（venue_id 锚点/快照多行化）、D3（流协议）、D4（金融面）、D5（TD 网关）、D6（hub 部署）。

## 六、验收标准（编码阶段定，行为级）

- 迁移 upgrade/downgrade 双向绿（加 board 列 + 回填 + venue_permission 建表）。
- `venue_allows` 覆盖：主板创业板权限错配拒绝、**沪/深股东户错配拒绝（venue 无深股东户拒深主板/创业板）**、ETF 跳过 exchange+board、可转债无权限拒绝、ST 拒绝、CDR→star。
- 退役后 `_board_of`/`detect_category` 不再被调用（grep 断言）；`detect_category` 的因子兼容类改由 category 真源 + `CATEGORY_TO_FACTOR_CLASS` 派生（`validate_strategy_factors` 走 `SMClient.get` 而非前缀）。
- `pytest tests/ -q` 全绿 + 分层绿 + pyflakes 零新增。
