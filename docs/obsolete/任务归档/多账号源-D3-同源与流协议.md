# 多账号源 D3 · 同源与流协议（详细设计）

> 上级：`docs/architecture/A05-多账号源架构设计.md` §二·2.2/2.3/§五契约2·3。状态：详细设计（待双盲审）。

## 一、目标

钉死 A股「MD 单 hub + TD per-account」、加密「MD+TD per-account」的流键、同源运行时校验、加密历史暖机 per-account，防止「吃错行情→信号错→下错单」。

## 二、现状（已核实）

- A股 MD 单 hub：流键 `hub:bars:{symbol}`，无 account 维度（`md_hub` 单活双实例，doc14 M5 + 批60 M5 协议）。
- 加密尚无 per-account hub（多账号源未落地前是单实例）。
- 历史暖机：worker 读 PG bar_1min 全局表（A股 market-wide 无同源问题；加密若 per-account 后仍是全局表=币安数据喂 OKX 任务）。

## 三、设计决策

- **无首决**。方向在 31 号 §2.2 已定（A股单hub/加密per-account），本件是把方向落成流协议契约。

## 四、契约

- 流键：A股 `hub:bars:{symbol}`（单 hub，无 account 维度）；加密 `hub:bars:{account_id}:{symbol}`（per-account）。
- 心跳/租约：A股 `quant:hb:md-hub` / `hub:lease`；加密 `quant:hb:md-hub:{account_id}` / `hub:lease:{account_id}`。
- **同源运行时校验**（per-account 流）：hub 写流带 `"account_id"` 字段；worker `int(fields["account_id"]) == account.id`（decode_responses 读出是 str，须 int 转换 + try/except fail-fast，否则每条 bar 误判跨源 exit 78）。
- **加密历史暖机 per-account**：历史 bar 数据源按 account 分源（与实时流同源），暖机/回放取本 account 数据，不吃别的 account。**落点：bar 表已有 `source` 列区分数据源，加密 account 按 `source=该 account provider`（binance_perp/okx_perp）过滤即可，无需新增 account 列**（A股单 hub 无此问题）。
- **分源键 = account_id（=external_interface.id）**：运行时 hub/worker 拿到的就是行 id。语义键 account_key 用于「防重复建行 + 删行重建稳定」，但**换凭证必须走 update 保 account_id（禁 delete+insert 重建）**，否则流键/暖机/order_log 归因与历史脱钩（delete_interface 守卫扩展见 D2）。

> **编码实施补充（2026-09-24，AB 双盲审后）**
> - **D6 强制标注**：加密 per-account hub（D6）的 `msg_of` **必须补 `"account_id"` 字段**——否则 worker 侧 `_account_mismatch` 对缺 account_id 字段 fail-closed，所有加密 bar 静默全丢（仅 dropped_cross 计数 + error log，无升级告警）。A股 md_hub（单 hub）不写 account_id 是对的（无 account 维）。
> - **就绪死代码边界**：加密流键 `bar_stream_key`/同源校验 `_account_mismatch`/暖机 source 过滤，当前 D6 落地前**均不生效**（A股路径 100% 行为不变；`data_platform/adapters/` 现无任何加密 bar 写入者，加密暖机 source 过滤恒空）。加密运行时 D5/D6 落地后直接可用。
> - **单源债**：`_crypto_provider`（symbol→provider）是 `.BINANCE`/`.OKX` 映射的第三处（与 `risk.py _market_of`、`quant_common/markets.py MARKET_OP_DECOMP` 同源）；`databus.subscribe` 仍是裸键（A股单标的）。未来加密接入时考虑下沉 quant_common/markets 单源 + subscribe 同步流键契约。

## 五、限定范围

只做：加密 per-account 流键、同源运行时校验（account_id 字段 + worker 比对）、加密历史暖机 per-account。
不碰：D1（权限）、D2（身份/快照）、D4（金融面）、D5（TD 网关）、D6（hub 部署拓扑——本件只钉「键格式」，实例生命周期归 D6）。

## 六、验收标准（编码阶段定，行为级）

- 加密双 account：worker A 只消费 `hub:bars:{A}:{symbol}`，收到 account_id=B 的消息 fail-fast（不落地）。
- A股单 hub：流键无 account 维度、worker 不做 account_id 比对。
- 加密历史暖机：币安 account 的暖机数据不喂 OKX account。
