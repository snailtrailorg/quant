# 批 106 · release 交易窗门接交易日历（控制器侧查 `trade_cal` + fail-open）

## 目标

`release.yml` 的发布禁启窗**只认「周一~五 + 钟点」，不看交易日历** ⇒ 法定假日（周一~五）照样拦发布，操作者须人工 `-e force=true` 绕过（playbook 会留痕告警）。本批把门接上 `trade_cal`：**非交易日直接放行**（无交易即无重启风险），且**禁止让日历本身成为新的发布阻断点**。

## 现状（事实清单）

- 门在 `deploy/playbooks/release.yml` pre_tasks（批 3 落地）：
  - `now_raw`（`TZ=Asia/Shanghai date +%u%H%M`，`u`=ISO 周几 1..7；`deploy_fake_now` 供确定性测试）；
  - `in_window = (钟点落任一月禁窗) and (周几 ≤ 5)`；窗来自 `inventory/group_vars/all.yml::deploy_trading_windows`（`{855,1135}` / `{1240,1505}`）；
  - `deploy_trading_window_enforce`：prod=true / staging=false / sandbox=false。
- **活例**：`2026-10-06` 是**周二**但 `trade_cal.is_open=0`（国庆休市）⇒ 那一刻落窗内即被拒，纯属误拦（当天实际无任何交易）。待办原行即以此为证。
- `trade_cal` 表：`(exchange, cal_date) PK` + `is_open integer`（1 开市 / 0 休市）+ `pretrade_date`；dev 库仅 `SSE`，覆盖 `1990-12-19 ~ 2026-12-31`。
- **prod 无任意 SQL/Python 通道**（刻意边界）⇒ 门只能**控制器侧**查本机 dev 库（`delegate_to: localhost`）。
- 非强制环境（staging/sandbox）本就不拦 ⇒ 新查询只在 `enforce=true` 时执行（零副作用）。

## 裁定（威廉姆 2026-10-06 交办助手拍板）

**通道＝控制器侧 `delegate_to: localhost` 查 dev 库 `trade_cal`；查库失败 / 无当日行 ⇒ fail-open 放行 + 响亮告警**（禁止 fail-closed 误拦发布）。
（三通道对比：扩 `quant-dbro` wrapper＝要 michael 重装位、staging+prod 各一次；仓内静态交易日表＝零装位但每年要更且是第二真源；控制器侧查库＝真源、零装位，代价是耦合本机 dev 库 —— 已用 fail-open 把耦合代价压到「仅告警」。）

## 产出（实现）

1. **新增 `preflight —— 交易日判定`**（`release.yml`，`tags: [tradegate]`）：控制器侧 shell 取日期（`deploy_fake_date` 可注入，缺省 `TZ=Asia/Shanghai date +%F`）→ `psql -w -h 127.0.0.1 -U quant -d quant -X -tA -c "select is_open from trade_cal where exchange='SSE' and cal_date='$D'"`；`failed_when: false`（查库失败不得失败本 play）、`changed_when: false`、`check_mode: false`、`when: enforce`。
   - **`-w` 是硬要求**：非交互 psql 若走密码输入会挂在 `/dev/tty`（本仓踩过：裸 psql 假死 3h43m）。
2. **新增 `交易日判定事实`**：`trade_cal_known = stdout ∈ {'0','1'}`、`is_trading_day = (stdout == '1')`。
3. **改 `交易窗口判定`**：`in_window = (钟点落窗内) and (周几 ≤ 5) and (is_trading_day)`。
4. **新增 `交易日历不可用告警`**：`enforce and not trade_cal_known` ⇒ 打印 fail-open 说明（留痕，不阻断）。
5. **`tags: [tradegate]`** 加在上述及 `now_raw`/断言/告警共 **7 个任务**上 ⇒ `--tags tradegate` 可**单跑门**（免跑整条发布链），让门可被快速回归。
6. **`tests/run_scenarios.sh`**：A0 补注 `deploy_fake_date=2026-09-28`（周一且开市——否则真实日期跑测试会因假日假绿）；**新增 A0b**「假日放行」负例（`40930` + `2026-10-01`）。
7. **🔴 连带修复：沙箱场景套件自 2026-09-29 起全红（本批实跑暴露，属「验证工具自己坏了」类）**：
   - **根因**：`3980c0c`（2026-09-29「requirements.lock 上锁 + 部署链 `--require-hashes`」）把 `requirements.lock` 加进 `deploy_sync_whitelist` 并把 `quant-pip-wrapper` 的输入从 `requirements.txt` 改为 **`requirements.lock`**——但**没同步**沙箱基线：`fixtures/baseline/` 只有 `.txt`，`make_sandbox_root.sh` 也不补 ⇒ **基线 seed 发布在 rsync 处 code 23 中止**，整套六场景跑不过第三步（与批 63 加 `vendor` 切片那次**同款**，脚本里已有先例注释）。
   - **第二处连带**：S1「坏 requirements」场景仍往 **`.txt`** 注入坏包，而 pip 现在读 **`.lock`** ⇒ 即便 seed 能过，S1 也**永远拦不住＝假绿**。
   - **修法**：`make_sandbox_root.sh` 补 `STAGE/requirements.lock` 占位（**注释-only**）；`run_scenarios.sh` S1 注入点改 `.lock`。
   - **占位内容取据（实测）**：注释-only lock → `pip install --dry-run --require-hashes` **rc=0**（空装成功、不引网络）；坏包无 hash 行 → **rc=1**（S1 能正确拦）。

## 接口契约

- `in_window` 语义**收紧而非放宽**：新增「且为交易日」合取项；未触及其余判据与 `force` 逃生门。
- 非 `enforce` 环境行为**完全不变**（查询被 `when` 短路 ⇒ `in_window=false`，与既有「不强制」等价）。
- **prod 零部署**：`release.yml` 是**控制器侧**文件（`ansible-playbook -i inventory/quant-prod.yml playbooks/release.yml` 在本机执行）⇒ **merge 即生效**，下次任一 release 自然走新逻辑；本次改动**不进** prod 部署树。

## ⛔ 本批不含

- **把日历做成层 1 能力 / 前端可维护**：控制器侧直接用 `psql`，不经应用层（发布门是部署基础设施，不该依赖应用进程）。
- **多交易所**：dev 库现仅 `SSE`；若日后引入多所，判据改 `exchange='SSE'` 为显式选择或聚合（守卫：`bool_or(is_open)`），届时再改。
- **日历存量超期（>2026-12-31）**：超出覆盖即「无当日行」⇒ 当前落 fail-open + 告警。若需 fail-closed 语义（过期=硬拦），属另一裁定。
