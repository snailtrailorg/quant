## 目标

一句话：把供给面**剩余 7 个「字面量」handler** 的拉取从「`_get_pro(prov).xxx()` / 直连 `tushare_adapter` 的 `pull_*`」迁到 **`adapter.fetch_supply(kind, sub_kind)`**——做完 `sync_config.provider` 对那 7 项才**真生效**；并借 `astock_list` 打通**首个「非 bar 多源」样板**（聚宽 `ref_data` 能真切）。

## 现状（事实清单）

- 分派：`sync()` → `_HANDLERS.get(sync_id)`。**7 个字面量 handler** 的拉取仍是 tushare 独占：
  - `_sync_astock_basic`：`_sync_by_trade_date(pro.daily_basic, save_daily_basic, …)`；
  - `_sync_astock_list` / `_sync_cb_basic` / `_sync_etf_list` / `_sync_static_list`：`_get_pro(prov).stock_basic|cb_basic|fund_basic(...)`；
  - `_sync_trade_cal`：直连 `tushare_adapter.pull_trade_cal(year)`（**函数内部自己写库**）；
  - `_sync_convertible_terms`：直连 `pull_convertible_bonds()` + 逐只 `pull_cb_basic(ts_code)`。
- **`_get_pro` 返回「源客户端对象」而非 adapter**（`data_source.get_client()`），且 handler 调用语汇是 tushare 的（`pro.*`）⇒ 给聚宽声明 `astock_list` 后真切抛 `ProviderConfigError`（**响亮**失败，非静默串源）——即 103b §三「插件边界不完整」。
- **列形状真源立法已存在**（`base.py::fetch_supply` docstring）：落库列形状真源＝**`sync_kind_config` 的 `pk_cols/float_cols/text_cols` + 目标表**；全契约化（adapter 侧 `KIND_SPECS` + `ContractFrame`）留后续小批，**正是为避免列形状双真源**。
- **但双真源实际已在**：`engine.py` 内联 `_TIER1_BATCH`（pk）/`_TIER1_FLOAT_COLS`/`_TIER1_TEXT_COLS` 与 `sync_kind_config` 重复；现有对账测试（`test_batch100`）**只对 `(kind, sub_kind)`，不查列**。
- `sync_kind_config` 实际结构：`sync_id PK` + `kind/sub_kind/pg_table/pk_cols/float_cols/text_cols/rebuild`（**列形状已在表内**）。
- 两个边角：`static_symbols` / `convertible_terms` **无 `sync_kind_config` 归置行**（只有 `sync_config` 行）。
- 既有测试钉：`test_collected_beats` 直接 patch `tushare_adapter.pull_convertible_bonds` / `pull_cb_basic`（改路径必连带改）。

## ⚖ 关键设计裁定：列形状「单一真源」（批 107 拍板，助手代裁）

**裁定**：`sync_kind_config`（`pk_cols/float_cols/text_cols/pg_table`）＝**唯一真源**（已是 `fetch_supply` 立法）。**不做 Option A**（adapter 侧 `KIND_SPECS` + `ContractFrame`）——那会把列形状**再声明一遍**，正是要避免的第二源。维持 **Option B（裸 df 端口）**。

**多源下的落地**：adapter 的 `fetch_supply` **输出归一化为「目标表列形状」**（canonical 形状＝目标表列，由 `sync_kind_config` 声明；adapter 负责源侧→canonical 的映射）——沿用批 103b B 步 `_normalize_frame` 既有先例。→ **单一真源成立**：目标列只声明一次（`sync_kind_config`），adapter 只是翻译层。

**要消除的双源**：`engine.py` 内联 dict 与 7 字面量 handler 里**硬编码的 INSERT 列清单**。
- 内联 dict **保留作注册骨架**（engine import 时不得触库），但**加对账门**：把现有 `(kind, sub_kind)` 对账**扩到 `pk/float/text`**（漂移即红）。
- 7 字面量 handler 的归置键集中到 `_LITERAL_SUPPLY` 单一注册表（供对账门 + 调用点集中），**保留**各自写入（含 SM 侧效应）——不追求「统一到通用 upsert」（那会丢 SM 侧效应）。
