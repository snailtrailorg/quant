# 批16 · 列宽数据评估（设计时权重依据）

> 2026-09-12。方法：`scripts/eval-col-widths.py`（本地库只读，char_length p50/p90/max）。
> 局限与对策：本地 dev 库业务配置类样本少（1-5 行）但**固定格式列（时间/代码/枚举/数字）样本 1 即定**；
> 自由文本列以长期运行的表为分布参照（风控日志 3007 行、同步日志 1446 行、同步配置 17 行、用户组 4 行）。
> prod 采样不可行（quant-dbro 固定 SQL 内封，扩 wrapper 不值）。

## 档位制（数据支撑的权重档）

| 档 | min-width | 适用 | 数据依据 |
|---|---|---|---|
| A | 80 | 布尔/≤4 字符枚举 | enabled(4)/mode(4) p90=4 |
| B | 100 | 数字列（≤8 字符） | 数量/百分比/金额 p90≤8 |
| C | 120 | 代码/短枚举（≤11 字符） | symbol 恒 11；status p90≤7 |
| D | 140 | 中枚举/接口名（12-17 字符） | issue_type 12；tushare_api p90=15 |
| E | 160 | 时间列（前端 str[:19] 显示到秒） | 原始 29 字符截 19；同步/风控日志全样本一致 |
| F | 200 | 名称列（p90 7-11 字符） | 任务名 11、策略名 p90=7、strategy_id 18→F+ |
| G | 240 | 描述列（p90 18-37 字符）+ tooltip | 同步配置 description p90=18；用户组 p90=37 |
| H | flex | 长文本列（p90 ≥40 字符）+ tooltip | 风控日志 detail p90=58；error/reason/note 同类 |
| 操作列 | 按钮数×72+32 | — | 单按钮 110 / 双 180 / 三 250 / 兜底"编辑"收编后恒 110-180 |

## 关键实测发现

1. **时间戳列原始 29 字符含微秒+时区**，前端普遍 str[:19] → 档 E 160 即可（当前站内普遍写 150-200，基本合理但应统一 160）
2. **detail 类长文本 p90=58 max=58**（风控日志 3007 样本）——flex+tooltip 无争议；当前 Risk v2 表写死 400 偏挤
3. **用户组 description p90=37**——G 档 240 足够（当前 min-200 略窄）
4. **同步配置 description p90=18 max=28**——G 档
5. 名称类 p90 均 ≤11 字符 → F 档 200 覆盖（当前 name 列 min 120-160 偏窄，中文 11 字符 ≈190px）
6. 短枚举类当前普遍 80-100 合理；数字类 80-100 合理

## 逐页套用规则

- 每列按上表映射档位；一表内 H 档列至多 1 个（flex 吸收）
- selection/expand 列固定 44/60；id 列 B 档（数字短）
- sortable 列 +20（排序图标已计入档位冗余）
- v2 三表（Risk 日志/Reconcile/SymbolManage）：同档位换算为 width 数字，末列不设吃剩余

## 复现

```bash
server/venv/bin/python scripts/eval-col-widths.py            # 全部四组
server/venv/bin/python scripts/eval-col-widths.py research   # 单组
```
