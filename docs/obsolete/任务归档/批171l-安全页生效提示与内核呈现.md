## 0. 契约（自包含）

### 件一：待下次扫描生效角标
- **现象**：探测/采集代码修上产后，snapshot 仍是旧一轮产物（06:00 beat 周期）——页面显示旧值无解释，运维空等一个周期（2026-11-06 valkey 案实证；手动 `POST /api/security/scan` 即时坐实也实证有效）。
- **判定（服务端单源，v2 时区锚修正）**：snapshot API 增 `stale_after_deploy: bool`——`snapshot.created_at < 最近部署时刻` 时 true。锚=**本进程 cwd**（`os.readlink('/proc/self/cwd')` 解析 release 目录名前 12 位 `YYYYMMDDHHMM`——**控制机 Asia/Shanghai 墙钟**）；created_at=PG now() 会话 pin UTC（aware）。**比较前目录时间戳 attach +08:00**（naive→aware）——裸墙钟对墙钟在盘后部署窗（15:05+ 主场景，deploy 20:00 CST vs 扫描 06:05 CST）恒判反（A-P0）；naive-vs-aware 直接比较=TypeError 500。**dev 无 releases 布局**（uvicorn cwd=工作树）⇒ 12 位解析失败 **fail-open false**（A-P1-1——dev 角标永不可见属预期；验收走单测 monkeypatch readlink+staging）。`created_at is None` 同 fail-open false（A-P2-2）。deploy 未重启窗（阶段 6→7 分钟级+6.5 钉版探针收口）不覆盖——已声明取舍。
- **FE**：A 区状态卡（status 卡头）条件渲染「待下次扫描生效」角标（el-tag warning）——`stale_after_deploy && !scan_running`；正文提示「页面数据为上一轮快照（{scan_date}）；新代码已上产，等待 06:00 例行扫描或手动触发」。`scan_running` 时显示扫描中（既有）不叠加。

### 件二：内核安全更新呈现（能力面）
- **数据**：`snapshot.dnf` 分区 `{status, checked_at, pending_count, packages:[{name, errata}], updates}`（wrapper :56 契约）——**kernel 包在 packages 里以 name 前缀 `kernel`/`kernel-core` 出现**；另「已安装待重启」= `dnf needs-restarting -k` 语义（wrapper 未采——**本批不加**：kernel 待重启的权威判定需 root 命令，走 wrapper 扩面=管道改动，炸半径不合小批比例。呈现面先覆盖「kernel 安全更新待装」）。
- **FE**：SecurityTab A 区与组件卡之间加**条件卡**（`dnf.pending_count>0` 时显示）：「系统安全更新 N 项」+ 明细行（name+errata）；**kernel 行高亮**（critical tag「需重启生效」）——**精确匹配**：name 剥 `.arch` 尾后 ∈ {kernel, kernel-core}（A-P1-2：前缀匹配误伤 kernel-tools/headers/devel——dev 实证 19 项 kernel*，仅 2 项真需重启）。`pending_count=0` 或 degraded ⇒ 整卡不渲染（零噪音）。errata 键语义注记（A-P2-1）：al8=公告号、Fedora=版本串——FE 明细行键名用「更新标识」中性词。
- **明确不做**：①`needs-restarting` 采集（root 面——若未来需要，走 quant-dnf-security wrapper 扩展子命令+管道评审）②dep_health 汇总口径改动（kernel 不进 component 汇总是既有口径——呈现层独立卡足矣）。
