## 0. 用户裁定（2026-11-09，全部为硬约束，按裁定顺序归并去重）

1. **行情/交易必须同源**：平仓定价只用 XTP/EMT 同源 hub tick（`hub:latest_tick:{account_id}:{symbol}`）。腾讯 `market_snapshot.get_quote`（外部网页快照、无保障、非同 SDK）、成本价、陈 `bar_1min` 一律禁用。
2. **定价规则全部下沉 Adapter 接口，主流程零硬编码分支**：
   - 有跌停线 → 跌停价挂卖；无跌停线 → **实时可见最优对手单价格**（非昨收）再让一定幅度保证成交；「×0.9」只是示例、不一定恰当（用户点名反例：加密币**空单**平仓是买入，让价方向相反）；
   - 「有无跌停线判定 / 对手价档位 / 让价方向与幅度 / 拆单上限 / 最小价位取整 / **平仓买卖方向**」等所有针对账号与标的种类的特异性，一律由注册进来的实体（`ExecutionAdapter` 子类）提供接口实现，**不得在主流程写 `if 品种/板块` 分支判断**；
   - 平仓方向由持仓 `direction` 派生（见件二），**不得写死 `SELL`**。
3. **撤单重试后必须重新获取参考价**再挂，绝不能复用同一个价格反复尝试；若仍不能成交（剧烈波动/踩踏），暂接受该规则、不无限兜底。
4. **重试编排**：先将账号下所有持仓平一轮（XTP 无批量下单原语 ⇒ 一个请求=一个标的，故循环逐标的发单），再对不成功的在同一线程里循环重试（每轮重新取价）；次数/间隔可配、**有绝对上限**；到上限仍未平 = 告警 + `order_log` + 处置时间线 + FE 渲染 `pending/no_quote`（**全链可见**）。
5. **线程**：账号间复用现有 per-account runner 进程并行（已达标，核查结论=合适直接用，不新增进程/线程池）；**每个 runner 进程内开一个专用 daemon 线程**承载整轮急停，主循环拍只做「取命令 → 投递 → 回执」，不得在主循环内 sleep / 长循环（卡心跳/bar/断流=僵尸）。紧急处置事务不能串行排队。
6. **实体粒度 = provider 单维复用 `ExecutionAdapter`**：特异性以可覆写方法 / 配置属性加在 XTP/EMT/Crypto 子类；不新建二维注册表、不新增品种实体类。
7. **品种规则 = Adapter 的配置属性**：有代码缺省值、**界面可配、落库**（不写死在分支里）。
8. **持仓标的进 hub 订阅真相源**（根本保证「有持仓 ⇒ 有同源行情 ⇒ 能平仓」）。
9. **急停单写 `order_log`**（审计缺口），并修认领链（`client_id` → `vt_orderid`）。

### 件二：Adapter 定价与规则接口（provider 单维，改 `strategy_framework/adapters.py`）
`ExecutionAdapter` 基类新增可覆写方法（**主流程只调接口，零 `if 品种` 分支**）：
```
def close_action(self, pos) -> str:                          # 平仓方向：pos.direction=="direction_short"→"BUY"（买回平空），否则→"SELL"（卖平多/NET）
def close_policy(self) -> dict                              # 本 provider 的品种规则（件三配置属性）
def opponent_price(self, tick: dict, action: str) -> float  # SELL→bid[0]（卖给买一），BUY→ask[0]（向卖一买）；子类按 category 可覆写
def has_limit_band(self, tick: dict, sym: str) -> bool     # 有无跌停线判定（缺省 lower_limit>0）
def close_reference_price(self, tick: dict, pos, action: str) -> float:
    # 缺省：has_limit_band → 跌停价；否则 opponent_price(tick,action) 按 action 方向让价
    #   SELL（平多）→ 对手价 ×(1-aggression)；BUY（平空）→ 对手价 ×(1+aggression)
    # 子类整体覆写（例：加密空单平仓 BUY → 卖1 ×(1+aggression)；场内基金/可转债按各自规则）
def max_close_order_qty(self, sym: str) -> int             # 拆单上限（缺省 100000）
def round_close_price(self, px: float, tick: dict) -> float # 最小价位取整（防跌破/越界）
```
- **方向派生是硬约束**：`action = adapter.close_action(pos)` 只算一次，**同一个值**喂 `close_reference_price(tick,pos,action)`、`Order(action=action)`、`order_log.action`、`check_order`，禁止主流程写死 `"SELL"`（用户点名的加密空单反例：短仓 `direction_short` → BUY、取 `ask[0]`、`×(1+aggression)`）。
- 方向感知让价：不硬编码 `*0.9`；`aggression` 是幅度，方向由 `action` 决定上下。
- `has_limit_band / opponent_price / 让价 / 拆单上限 / 取整 / 方向` 全在 Adapter 内，`trading._close_all_positions` 只调接口。
- 无可用价 / 无对手单 → 返回 `0.0` → 调用方按 `no_quote` 处理（fail 留痕，不静默降级）。
- `order_type="limit"`（XTP 市价单仍带 price 字段、实测同样越界拒）。
- **派生方向必须贯通风控 `check_order`（P1-B，根本修）**：`_close_all_positions` 构造的每笔 order 已带 `reason="emergency_close_all"`（`trading.py:425` 现状）。但 `risk_control/risk.py` 的熔断放行(`:292`)、operator 校验(`:315`)、总回撤/日亏「禁止开仓·平仓放行」(`:351/:355`)、单笔金额豁免(`:418`) 五处一律以 `action=="SELL"` 作「平仓放行」判据（`:290` 注释自认「crypto 永续 SELL≠平仓，届时须换判据」），`trading.py:57 frozen_allows` sticky 亦只放 SELL。⇒ 派生出的加密空单平仓 **BUY 会被风控当开仓拒、平不掉**，S2「短仓驱动整链」若靠 mock 风控绕过真拒单即守门自失效。
  - 修法：**风控判据单源化**——在 `risk_control/risk.py` 新增纯函数 `is_flat_or_reduce(order) -> bool` = `action=="SELL" OR order.get("reason")=="emergency_close_all"`（急停平仓单是 reduce-only，方向不可作唯一凭据），上述五处 SELL 判据与 `frozen_allows` 改调此函数。既有 A 股 SELL 行为不变、普通 BUY 开仓仍全拒（不放松风控），仅急停 BUY 平空放行。落 `risk_control/risk.py` + `trading.py:57`（§3 补列两文件）；S2 增「halted 态下短仓 BUY 平仓经真实 `check_order` 放行」行为级 gate（不 mock 风控）。
