## 一、A · `screen_factor_cache`：ts_code → vt

**现状**：键 `(category, ts_code, factor, trade_date)`，写侧在 SQL 里用 `CASE split_part` 把 vt 转成 `.SH/.SZ/.BJ`；读侧 4 处按 ts_code join（`data_platform/screen._CACHE_JOIN`、`routes/stock.py` astock 端点 f20/f250）。

**改法**
1. 迁移 **0183（expand）**：加 `vt_symbol TEXT`；一次性回填（`CASE split_part(ts_code,'.',2)` 四值，仅此一次数据迁移）；建 `idx_sfc_vt (vt_symbol, category, factor, trade_date)`；`ts_code` 保留（NOT NULL 仍在，双写期兼容旧读者）。
2. 写侧：SQL 去掉 `CASE`，直接选 `symbol`（本即 vt）+ 值；Python 侧 `to_ts_code(vt)` 补 ts_code（双写），`vt_symbol` 落原值。
3. 读侧：`_CACHE_JOIN` 改 `{alias}.vt_symbol = {cache_col}`；stock 基表 `cache_col=d.vt_symbol`（`daily_basic.vt_symbol` 已有且全非空），非 stock 基表无因子字段、保留原 ts 列；`routes/stock.py` astock 两处 join 改 `d.vt_symbol`。

**契约**
- 表：`screen_factor_cache(category, ts_code NOT NULL, vt_symbol, factor, trade_date, value)` 主键不变（过渡）；`vt_symbol` 对 stock 行恒非空。
- 后续 contract（另批）：`vt_symbol` 置 NOT NULL、主键换 `(category, vt_symbol, factor, trade_date)`、删 `ts_code`。

## 二、B · `reconcile_issue`：裸码 → vt

**现状**：`symbol` 列存三种值——position_diff 存**裸码**（比对前 `split_part` 砍后缀）、funding_diff 存 `account#N`、cross_account_reverse 已是 vt。比对 SQL 两侧都砍裸码，是 171/175 之前"沪市双写"时代的补丁。

**改法**
1. 比对 SQL：仍按裸码做**比对键**（兼容 trade_log 历史行），但新增 `sym_vt` 输出——position 侧取 `min(symbol)`（快照已是 canonical），trade_log-only 行用 `LATERAL` 查 `security_master(category='stock')` 补 vt；`WHERE` 差异过滤后只对差异行做该 lookup。
2. 写入/豁免判断：插入与 `NOT EXISTS(exempt)` 一律用 `sym_vt`；`detail` 也显示 vt。
3. 迁移 **0184（expand/数据）**：仅回填形如 `^[0-9]{6}$` 的行（`account#N` 等不动）——按 `security_master` `category IN ('stock','listed_fund','convertible')` 反查 vt；**先删"同 issue_type 已有 vt 孪生 open 行"的裸码 open 行**（否则撞 `ux_reconcile_issue_open`），再 UPDATE。downgrade 声明 no-op（不可逆，同 0181 口径）。

**契约**：`reconcile_issue.symbol` 恒为「vt 或 `account#N`」；不再出现 6 位裸码。
