## 20C 邮箱修改（验证成功才改）

- **email 规范化**：`new_email = body.new_email.strip().lower()` 全链使用（唯一约束区分大小写——
  User@X.com/user@x.com 并存=假空闲）。
- `POST /api/user/email-change`（require_authenticated，body: `{new_email, current_password, lang}`——
  lang 载体=请求体对齐 InviteReq/ForgotReq，中文用户不得收英文邮件）：
  ①**频控先置**：`_RATE_RULES["emailchg"] = (3, 3600)`（须先注册桶——现表只有 login/forgot，
  直接调=KeyError 500；发信有成本取宽窗）②密码验证 ③格式校验 ④占用校验（`SELECT id FROM users
  WHERE email=%s AND deleted_at IS NULL` 他人占用→EMAIL_TAKEN；等于本人现邮箱→SAME_AS_CURRENT）
  ⑤`create_token(new_email, "email_change", user_id, hours=1)`（邮件正文标注 1 小时有效）
  ⑥后台任务 `send_email_change_email(new_email, token, base, lang)`（EMAIL_CHANGE_TPL 新模板，
  品牌前缀沿用站内邮件现行封面名）。返回 `{status:"sent"}`。
- `POST /api/user/email-change/confirm` {token}（**免登录**——token 即凭证）**单事务四防线**：
  ```
  verify_token(kind="email_change") 且 t["user_id"] 判空（invite 场景 token 无 user_id——防串）
  → BEGIN:
      复核占用  SELECT 1 FROM users WHERE email=%s AND id<>t.user_id AND deleted_at IS NULL → 有=409 EMAIL_TAKEN
      UPDATE users SET email=%s WHERE id=t.user_id AND deleted_at IS NULL AND enabled=true
             RETURNING username, (CASE WHEN ...)   -- **WHERE 钉死 id=user_id 勿抄 reset 的 email 定位**
      rowcount=0 → 410 GONE（发起后被注销/停用——软删行 email=NULL 脱敏不得写回）
      UPDATE user_tokens SET used=true WHERE id=%s AND used=false   -- 原子防重放（原 _mark 无条件）
      COMMIT + audit_log(actor=RETURNING 的 username, "email_change", old→new)
  → 捕 UniqueViolation(pgcode 23505) → 409 EMAIL_TAKEN（窗口竞态兜底）
  ```
- **不建 email_verified 列、不存 pending 新邮箱**——确认前库中无任何痕迹（用户裁定原样）。
- 前端：邮箱行加「修改」→ 弹窗（新邮箱+当前密码）→ 提交后提示查收新邮箱（含垃圾箱/稍后再试兜底）；
  新路由 `/email-confirm`（**name:'email-confirm' + router.js publicPages 数组追加**——免登录点击是
  常态场景，漏白名单=邮件链接全断）+ `EmailConfirm.vue`（verifying/success/failed 三态+去登录按钮）。

## 安全边界（方案自带）

- token 绑定 user_id+new_email 双因子：盗 token 只能改到「请求者当时指定」的邮箱，而请求需密码前置
- 新邮箱收信即所有权证明；旧邮箱不参与（用户未要求旧邮箱确认——密码已足）
- 邮件走 outbox 队列（既有），发送失败不影响 API 返回
