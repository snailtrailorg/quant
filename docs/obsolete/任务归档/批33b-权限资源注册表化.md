## 方案 v1（阶段一=显示面配置化；阶段二挂账裁定期）

### 33b-1 注册表壳（data_platform 层，36b-α 协同约定三原则）

新 `server/src/data_platform/perm_registry.py`：
- **代码注册表=缺省底座**（typed dict，条目 `{id, kind: nav|api|market_op, group_key, order, label_key}`）——三清单收编：NAV_ITEMS 17+all_keys 14（admin 字典改引注册表键集）+_MARKET_OP_KEYS 5（引用常量不改语义）
- **DB 覆盖层**：新表 `perm_resource`（迁移 0083：id/kind/group_key/sort_order/label_override/enabled）——管理页改动只写覆盖行，代码底座不动（缺省零行=全走代码）；载入=代码底座⊕DB 覆盖（60s 缓存+invalidate 联动，perms.py 先例）
- **防漂移闸**：启动/测试断言 `require_perm 全站键集 ⊆ 注册表`（测试钉 + `verify_schema` 告警——新增键忘注册=显式暴露）

### 33b-2 供形与下发

- GET `/api/permissions` 的 keys/nav.items 改由注册表供形（**同形向后兼容**——PermMatrix/Profile 零逻辑改动）；`valid_res` 白名单查注册表（等价替换）
- 新 GET `/api/perm-resources`（system_config 门控）：注册表全量（含覆盖状态）——管理页+PermMatrix 分组数据源共用

### 33b-3 管理页（落位=Settings 新 tab「资源注册表」——勘察选项 a 最省）

- 表格：kind 分组×条目（id/当前分组/排序/显示名覆盖/enabled）+行内编辑弹窗（改 group_key/sort_order/label_override——**只影响显示分组与名称**）
- 写端点 POST `/api/perm-resources/{id}`（audit_log 对齐批27-22 先例）——**不可新增/删除资源条目**（id 集仍代码单源——阶段一红线，防幽灵资源）
- PermMatrix 分组数据源切注册表（permGroupsOf 兜底保留——未知键 other）

### 33b-4 阶段二（用户裁定=两阶段一起做；深度=可读+校验，绑定不可改）

- **绑定关系自动注册表**：`require_perm` 返回闭包携带 `_perm_key` 属性（零调用点改动）；启动 lifespan walk `app.routes` 依赖树提取 `{path, method, perm_key}` 全息绑定——**全自动零手工**（173 处不逐个维护）；管理页反查表展示+可导出（键→端点清单，审计/文档面）
- **启动一致性校验**：绑定键集 ⊆ 注册表 api 键集——违例启动 warning+日志（新增 require_perm 键忘进注册表=显性暴露，防漂移闸落地）
- **ROUTE_TO_NAV 同源收编**：注册表 nav 条目加 `aliases` 字段（11 别名并入）；GET nav.items 附带下发；前端 MainLayout ROUTE_TO_NAV 改读下发数据（本地硬编码表退役）+router 守卫与 navReadonly 走同一张归一表（两套映射合一）
- **锁键/地板永久钉死代码**（用户裁定底线——提权面不可配置；管理页只读展示 🔒 标注）

### 33b-5 管理页（用户裁定=独立菜单页）

系统管理组新页「资源注册表」（/perm-resources）：三 kind 页签（API 键/菜单/市场）+绑定反查段。**接入五处同步自身吃狗粮**：NAV_ITEMS 新条目/注册表 nav kind+MainLayout 模板/router+locales nav 段+admin meta——新页的菜单接入即注册表驱动示范。行内编辑=分组/排序/显示名覆盖（33b-3）；条目集不可增删；绑定段只读。
