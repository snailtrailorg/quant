# 批43 · 短信多服务商容灾（2026-09-18 用户裁定——表格+优先级 failover）

## 用户裁定（三轮）

短信凭证页改**服务商表格**（每行一个短信接口，可增删改）；每行**优先级 0-9**（数字小者优先）；不可用顺位 fallback；**同级按行序**（=id 序，无需拖拽——数字可跳级更灵活）；编辑弹窗两页签（基本参数/短信模板——模板内容参考 popover 随行保留）；删除无保护提示（不可用行留着无用）；表格列不含签名（名称/服务商/优先级/状态/操作）。容灾哲学=LLM 网关 priority 主备同构。

## 方案 v1

### 43-1 迁移 0086：sms_provider 表

`id/name/provider('aliyun' CHECK)/access_key_id/access_key_secret(Fernet 加密)/sign_name/alert_template_code/verify_template_code/priority INT CHECK 0-9 DEFAULT 0/enabled DEFAULT true/created_at/updated_at`。
存量迁移（幂等）：system_config `alert_sms_*` 五键有值 → 建默认行（priority=0 enabled=true，密文直搬同 ENCRYPTION_KEY 零解密）+ 五键 DELETE（双源消灭）；零值环境零行。

### 43-2 后端 sms.py 改造

- `_available_providers()`：enabled+ak_id+secret+sign_name 齐 → 按 (priority ASC, id ASC) 返回（解密 secret）。
- `_send_with_failover(phone, template_kind, params_builder)`：逐行尝试，任一成功即 ok；全败=最后行 reason。
- `send_sms/send_sms_code` 改走 failover（模板键 per 行 alert_/verify_template_code）；`sms_configured()`=存在任一可用行（告警面判定语义不变）；验证码模板缺失行**不进验证码候选**（可发告警不能发验证码的行——告警/验证码独立候选集）。
- 旧 `_sms_config`（五键读）退役。

### 43-3 端点（alerts.py）

- GET `/api/alerts/sms-providers`：列表（secret/ak_id 不回显，credentials_set 布尔）。
- POST `/api/alerts/sms-providers`（新建）/ `POST /{id}`（编辑全量：密钥对留空=不改——批38 三段语义移植；明文四字段空=清空）/ DELETE `/{id}`（无保护）。
- 门控 alerts_config；audit_log。
- 旧 `/api/alerts/sms-config` GET/PUT **退役**（唯一消费方 SmsCard 同批重写）。
- `/api/alerts/test` sms 分支：走 failover 最优行（真实验证）。

### 43-4 前端 SmsCard 重写

表格（名称/服务商/优先级/状态=启用✓✗+凭证完整 tag/操作=编辑+删除图标钮）+header 添加图标钮；编辑弹窗两页签（基本参数=AK ID/AK Secret/签名；短信模板=两编号+popover 正文参考）+取消/保存。词条走文案师。

### 43-5 测试

failover 三钉（最优败→次行成/全败 reason=最后/排序 priority+id）/独立候选集钉（缺验证码模板行不进验证码候选）/sms_configured 新判定/CRUD 三段语义/迁移幂等（零值零行+有值一行+五键消失）。

## 方案 v2（双盲审 A P0×1+P1×4 / B P0×2+P1×4 全吸收 + 用户裁定改纯拖拽单层）

- **[用户裁定] 优先级列删除，纯拖拽单层**：行序即 failover 顺序（position 列，HTML5 原生拖拽 ~60 行零新依赖；每行配拖拽手柄）。候选排序=`position ASC`。
- **P0 时序预算（A/B 双抓）**：failover 循环 per-row 超时收紧 `(2,5)` + **尝试行数上限=3**（单次发送最坏 3×7=21s）+ `alert_tasks.py:87` send_sms `soft_time_limit` 15→30（email :83 先例对齐）+ 发码链 `phone_request_api` 失败退还冷却已有（B 核实 :457 失败退——但 timeout 模糊结局需裁定见 P1-2）。
- **P1-2 timeout 不 fallback（B——双发计费先例回归）**：仅**确定性失败**（阿里云业务 Code≠OK/HTTP 4xx 5xx）才切次行；**timeout（结局模糊——可能已送达）不 fallback**，直接返回 timeout（防同码双发打扰/计费）。批7「单次尝试」铁律保持。
- **P1-1/A-2 候选集对称补全**：告警候选=enabled+ak+secret+sign+**alert_template_code**；验证码候选=enabled+ak+secret+sign+**verify_template_code**（不含 alert 模板——两集独立对称）；`sms_configured()`=**告警候选集非空**。
- **A-P1-3 迁移种子条件钉死**：四核心键齐（ak_id+secret+sign+alert_tpl）才建行，verify_tpl 有则带上；任何残留 `alert_sms_*` 键一律 DELETE（含 partial 态孤儿键消灭）；幂等守卫 `WHERE NOT EXISTS (SELECT 1 FROM sms_provider)`；downgrade=best-effort 回填（首行密文平移回五键+drop 表——批39 先例外升级版）。
- **B-P1-3 schema_expectations 三处修**：+sms_provider、-channel_config（0085 残留）、+alert_user_sub（0080 漏册）——重跑链生成。
- **B-P1-4 回滚面声明**：0086 删五键后整版本回滚=旧代码 sms 不可用直至新版重配/手工回插——部署风险声明进方案。
- **B-P1-4 测试适配**：`test_sms_config_three_semantics`（batch36a :288）随端点退役改打新端点；`sms_configured`/`send_sms_code` mock 面签名不变兼容存活。
- **A-P2 采纳**：name 必填非空 400/credentials_set=ak+secret 成对齐/test 响应带成功行 name（可观测验收）/system.py alert_sms_* 封堵守卫保留（注释更新）+通用面回写守卫不删/decrypt 失败跳行+warn/reason token 契约保持零新码/升级秒级窗口注明。
- **A-P2-3 纠偏**：chips 不联动 sms_configured（批34 资料面裁定）——方案文字已正。
- **[契约钉] `send_sms(phone,level,title)`/`send_sms_code(phone,code)` 签名不动**——dispatch CHANNEL_PROFILES/alert_tasks/test 端点/phone 链零改动。

## 方案 v3（第三轮 A/B 双盲审 P0×2+P1 共识全吸收——定稿）

- **P0-1 迁移笛卡尔 bug 修**：verify 键改标量子查询（原 CROSS JOIN 形态 verify 无行=批30 前配的凭证环境→零建行+删五键静默丢失——双员独立同抓）；补迁移第三态钉（四键齐+verify 缺→建行 verify=''）。
- **P0-2 reorder 端点**：`POST /api/alerts/sms-providers/reorder`，body=`{"ids":[3,1,2]}` 全量有序数组，单事务按数组下标重编号 position=0..n-1；**id 集合=现有全集校验**（防并发丢行/幽灵 id）；audit_log；幂等（同数组重发同结果）；并发=后写赢（低频管理操作声明）。
- **P1 新行 position=COALESCE(MAX(position),-1)+1**（追加末尾非抢首——迁移 server_default=0 仅供种子）；删除出洞不紧缩。
- **P1 失败分类表**（新增 1 枚稳定枚举 `unreachable`——"零透传原文"承诺不变，新枚举允许）：`ALIYUN_*` 业务错/HTTP 4xx 5xx/**ConnectError（未送达）→切次行**；`TimeoutException/ReadError/WriteTimeout（结局模糊——可能已送达）→不切防双发计费`；`_aliyun_send` timeout 常量 (3,10) 参数化→failover 传 (2,5)。
- **P1 排序兜底三处统一** `ORDER BY position ASC, id ASC`：GET 列表/_available_providers/前端渲染。
- **P1 拖拽落点**：SmsCard **列模板内**实现（手柄列 IconBtn draggable+行 dragover/drop）——**TableShell 零改动**（54 表共享壳不动）；row-key=id；drop 后本地 splice 即时重排→POST reorder→失败重拉。
- **P1 43-5 回写**：排序钉改 position+id；新增 timeout 不 fallback 钉/reorder 钉（顺序落库/幂等/幽灵 id 拒/丢 id 拒）/迁移第三态钉。
- **P2 修笔**：send_sms soft_time_limit 15→**30**（依据=最坏 21s+余量；email 实为 70 非 30——v2 措辞纠）/schema_expectations 三处修（编码时落）/updated_at 应用层 UPDATE 自带 now()/词条清单（复用 14+新增 ~14——文案师）/验收文字 position 化（两行不同 position→停首行→试发走次行）。
