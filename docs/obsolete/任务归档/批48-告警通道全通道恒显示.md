## 一、问题(dev 复现实锤)

1. **null 态 tooltip 吞 chip**:`AlertSettings.vue` null 全通道分支把 `v-for` 多个 el-tag 塞进**单个 el-tooltip**——EP tooltip 只认第一个触发子元素,后续 bot chip 不渲染(用户"量化交易助手没显示"根因;后端 avail 实测两 bot 都返回,无罪)。**全站唯一一处**(B 员 awk 扫描实证)。
2. **已选态不可用通道消失**(#8):else 分支 `v-if="row.channels_avail.email"`(47-52 行)不可用即整个不渲染——null 态恒显灰 chip("未配置"),两态不一致(用户"改选后灰掉的邮箱短信不见了")。
3. **停用 bot 无处显示+勾选 400 错报**(#7):后端 `_users_with_channels` bots 查询 `WHERE enabled`(alerts.py:43);且 `_validate_channels:162-167` own_disabled **死分支**(与第一查同条件 owner+enabled,停用恒 count=0 落第三查 exists=1→**400"该机器人不属于该用户"错报**——生产不可达 mock 形态掩盖)。
4. **hub_shadow_symbols 词条缺**(#9):Hub 额外订阅清单运维键(md_hub/main.py:199 消费),生产手工 INSERT 无种子无词条,运行配置页说明列空白。

## 二、方案(v2)

### A 后端 `server/src/web_api/routes/alerts.py`

1. `_users_with_channels`:bots 查询**去 enabled 过滤**,条目带 `"enabled": bool` 标志(owner 语义不变)。
2. `_strip_dead_keys`:**零代码**(bot_ids 只看 id 集,avail 含停用后停用键自动保留)——仅改 docstring 注明"停用保留=实体在"防后人"修复"。
3. `_validate_channels` **判定段重构**(A-P1-1):第一查改 owner 集**不分 enabled** `SELECT id FROM im_bot_config WHERE owner_user_id=%s`(一次查询);逐键:email/sms 语义不变;`im:bid` → 自有(含停用)→**保留 out.append**(dispatch:223/:376 enabled 过滤双保险,天然不发;复启自动恢复)/非自有但实体在→400/实体已删→剥离;own_disabled 死分支整体删除。
4. **dispatch.py 零改动**(A/B 双员核过双保险)。

### B 前端 `web/src/views/AlertSettings.vue`——四态渲染立法(A-P1-2+B-P1-1)

通道列三态(null/已选/静音)**共用 chipsOf(row) 统一构造**,每通道恒渲染一个 chip+独立 el-tooltip:

| 态 | 视觉 | 语义 |
|---|---|---|
| on | success 亮 | null 态可用 / 已选态已勾(会发) |
| off | info 灰(chipSkipTip) | 已选/静音态可勾未勾(不发) |
| disabled | info 灰(chipDisabled/chipBotOff) | email/sms 未配置 / bot 停用未勾 |
| **on_disabled** | info 灰+勾标(专属 tooltip) | **已勾选但 bot 停用**(不发,复启自动恢复)——亮色会误导"会发"故不亮 |

- 静音态 `[]`:全通道 chip=off 态+**保留"暂不接收"总提示**(列尾小标,词条沿用)。
- 已勾色统一:bot 已勾 primary→**success**(与 email/sms 一致,B-P2-3 顺手)。
- `allKeysOf`(全勾归一 null 判定+onUserPicked/edit 回显):只含**可勾**通道(enabled bot+有资料 email/sms)。
- 弹窗停用 bot checkbox:显示+disabled(**已勾停用回显冻结**——EP disabled 保留 v-model 值随提交,P2 注记)。
- 通道列 `min-width` 260→**300**(4+ chip 恒显,顺手;#3 列宽双语批统一处理其余)。
