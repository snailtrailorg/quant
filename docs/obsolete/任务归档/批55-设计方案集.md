## 方案一「能力视图」:统一接口配置+两页签(激进统一)

### 概念定义(维度词典·quant_common/markets.py 注册表)

```python
MARKETS = {           # 市场=交易结算域(货币/监管/时段体系)
  "astock": {"name": "A股", "timezone": "+08:00", "account_default": "SSE"},
  "crypto": {"name": "加密", "timezone": "UTC"},
}
EXCHANGES = {         # 交易所=场所(市场内)——SHSE/SZSE/BSE/BINANCE/OKX
  "SHSE": {"market": "astock"}, "SZSE": {"market": "astock"}, "BSE": {"market": "astock"},
  "BINANCE": {"market": "crypto"}, "OKX": {"market": "crypto"},
}
DATA_CATEGORIES = {"daily": "日线", "minute": "分钟", "snapshot": "实时快照", "quote": "实时行情"}  # 数据品类
ASSET_CATEGORIES = {"stock", "etf", "convertible", "fund", "reits", "perp"}                        # 资产品类
CAPABILITIES = {"daily", "minute", "snapshot", "quote", "trading"}                                  # 能力枚举
# 权限五键无损映射:astock→(astock,stock) etf→(astock,etf) convertible→(astock,convertible)
#                  binance_perp→(crypto,perp,BINANCE) okx_perp→(crypto,perp,OKX)
```

### 数据设计

- **一张 `external_interface` 表**(合并 data_source_config+broker_config+新实时):
  id/name/provider/market/exchange(可空)/credentials_encrypted/params(jsonb)/**capabilities**(text[] 如 `{daily,minute}` 或 `{trading,quote}`)/position/enabled/updated_at
- 存量迁移:tushare→(provider,'astock',NULL,'{daily}');腾讯攒行→'{minute,snapshot}';XTP→market='astock' capabilities='{trading,quote}'(params 原样);币安/OKX→crypto '{trading}'
- realtime_source_config 不建(并入);data_source_usage 键改引 interface id

### 系统设计

- 端点:一族 CRUD+reorder(`/api/interfaces`);GET 支持按 capability 过滤(`?cap=daily|trading`)
- 前端**两页签**=同一表过滤视图:「数据源」(cap∩{daily,minute,snapshot,quote}≠∅,列=名称/供应商/市场/能力/状态/操作)、「交易账号」(cap∋trading,列=名称/供应商/市场/状态/操作)
- XTP 单份配置两处可见;能力差异(腾讯分钟无 BSE)以 params 内 `excluded_exchanges:['BSE']` 标注+前端徽标
- 引擎适配(浅):`_load_ds_params`(mgmt.py:100)改 `ORDER BY position`;sync 任务级 provider 路由不变(position=同 provider 多行时的选行序)——**深水区(sync 全局选源/hub 源切换)另批**

### 当前适配(改动面)

- 迁移:新表+存量合并(data_source 1 行 tushare/broker 1-2 行——数据量极小,合并零风险)+旧表 drop(0090)
- 破坏:data_source/broker 全端点族重写(mgmt.py 326 行重排);前端 DataSources/TradingAccounts 全重写;batch27 限流管理面(data-source-usage 键)随迁;测试 ~20 例改写
- 风险:一次到位改动大;但外部接口数量个位数,回归面可控

## 方案二「三页签修正」:维持三页签+品类重赋义(原案修正)

### 概念定义

同方案一注册表(market/exchange/两品类枚举),但**不建统一能力模型**——三域各表:

### 数据设计

- `data_source_config` 加 position/market(存量 tushare→astock)/**data_category**(枚举 daily/minute——真语义:tushare=daily/腾讯攒=minute)
- `realtime_source_config` 新表(同构):provider 现仅 tencent(snapshot)——白名单校验
- `broker_config` 加 position/market(xtp→astock/币安→crypto);**exchange 错位字段退役**(前端孤立字段删)
- 品类列(category)按域:历史=数据品类/实时=快照·行情/交易=**无品类列**(五列)

### 系统设计

- 三族端点(扩二+新一)各自 CRUD+reorder;三前端组件(重构二+新一)拖拽六列(交易五列)
- XTP 归交易账号页签(实时页签纯数据快照源)——**无双栖重复**(实时页签不含 XTP 行情)
- 引擎适配同方案一浅案(position 选行序)

### 当前适配

- 迁移:两表加列+一表新建(比方案一小);旧端点扩字段(不重写)
- 破坏:中等(端点扩展+两组件重构);页签 key sources 不动(词条改"历史数据")深链不断
- 风险:三套配置三处形态漂移依旧(第四/五/六份复制);实时页签内容薄(仅腾讯一行)

## 方案三「注册表先行」:概念底座+最小页签(最小切口)

### 概念定义

同方案一注册表**全量建立**(含 CAPABILITIES 映射)——概念层一次立法。

### 数据设计

- **不动现有两表结构**(data_source_config/broker_config 零 DDL);仅新建 `realtime_source_config`(position/market 天生)
- market/category 对历史/交易域=**运行时注册表推导**(provider→market 映射在注册表,不入库)——展示层 GET 时动态注 market 字段

### 系统设计

- L0+注册表+LIVE_TRADING 单源化
- 页签:数据源改名"历史数据"(词条)+新增"实时数据"(realtime 表 CRUD 拖拽)+交易账号**仅改列**(市场列=注册表推导显示,拖拽不加)
- 历史数据源表**不加拖拽**(position 无处存)——三页签交互不完全一致(历史/交易无拖拽)

### 当前适配

- 迁移:仅一表新建;端点一族新;破坏最小
- 风险:**用户核心诉求(三页签统一拖拽 CRUD)只完成 1/3**;注册表推导 market=展示层假象(库里无真值,未来查询按市场过滤仍无据)
