# 批55:集成中心三页签统一化(历史数据/实时数据/交易账号)

> 2026-09-19 用户裁定:①数据源页签改为「历史数据」②新增「实时数据」页签③交易账号不变——三页签统一为**可增删改+拖拽排序**表格,列统一=**名称/供应商/市场/品类/状态/操作**。

## 一、现状(勘察)

- 页签:mail/sms/llm/**sources(数据源)**/**trading(交易账号)**。
- `data_source_config`(provider/name/credentials/params/usage_limit/enabled)——无 position/market/category;前端 DataSources=用量统计区+配置表两段。
- `broker_config`(provider/name/credentials/params/enabled)——无 position/market/category;前端 TradingAccounts 列=ID/名称/交易所/Key 提示/状态/创建时间。
- **实时数据无配置面**:唯一实现=腾讯 HTTP 快照(`market_snapshot.get_quote` 硬编码),hub 周期拉。
- 拖拽 CRUD 通道表格模式=批43/47/50 四连复刻(SmsCard/SmtpCard/LLMModels)。

## 二、方案

### A 迁移 0090

1. `data_source_config` 加 `position`(物化=provider,name 序)+`market`(text default 'astock')+`category`(text default 'stock')。
2. `broker_config` 同款三列(market 现值从 params.exchange 迁?——broker 的 params JSON 内有 exchange:存量物化 `params->>'exchange'`→market, default 'astock')。
3. **新表 `realtime_source_config`**:id/name/provider/market/category/credentials_encrypted/params/position/enabled/created_at/updated_at(与 data_source_config 同构)。
4. schema_expectations 三行同步。

### B 端点(mgmt.py)

- 三族统一:GET(列表+credentials_set)/POST/PUT/DELETE/**reorder**(批43/47 同款全集校验+路由前移)。
- data_source 现端点扩三字段;broker 现端点扩三字段+reorder;realtime 新族。
- 权限:data_source/broker=现键(system_config/account_keys);realtime=system_config。
- **消费接线=浅案(裁定点①)**:position 本期=管理面排序+GET 下发;**运行时选源接线(历史 sync 选源序/实时 hub 源切换/交易多账户序)另批**——涉及 sync/hub 运行行为,风险隔离。realtime 页签消费校验:provider 现仅支持 `tencent`(POST 白名单校验,其它 400 "未实现"——诚实而非摆设)。

### C 前端(三组件统一)

1. **HistorySources.vue**(DataSources 重构):拖拽 CRUD 六列(名称/供应商/市场/品类/状态/操作);**用量统计区去留=裁定点②**(推荐保留为表下方折叠区——调用量/失败数是运维刚需,不占表格列)。
2. **RealtimeSources.vue 新**(六列同款):弹窗(name/provider 单选 tencent/market/category/凭证)。
3. **TradingAccounts.vue 改造**:六列统一(名称/供应商/市场/品类/状态/操作;Key 提示收进弹窗;创建时间删)。
4. 三组件拖拽/弹窗/词条全套(文案师);列宽按批53 角色三分(名称弹性/其余固定)。
5. 页签更名:sources→历史数据(tabs.sources 词条改);新增 tabs.realtime。

### D 词条(文案师)

页签名/六列表头/市场枚举(astock/crypto)/品类枚举(stock/etf/convertible/fund)/三组件弹窗全集。

## 三、测试钉

- 三族 CRUD+reorder(全集/幽灵 id 拒);realtime provider 白名单拒;broker market 物化往返;迁移双向。
- 前端:build+守门+dev 手测(三页签拖拽+六列)。

## 四、裁定点(等用户)

1. **消费接线深浅**:A=浅(管理面先行,运行时另批——推荐)/B=深(本期接 sync/hub 选源)。
2. **历史数据源用量统计区**:A=保留表下折叠区(推荐)/B=整个删除。

## 五、流程

方案双盲审 A/B→裁定①②→编码→代码盲审→钉+build+dev 实测→staging→prod。
