### b-3 pool_data 拉取循环包上下文（pool_data.py）

**模块级 import**（B-P1-3 修——patch 点要求模块级绑定）：
```python
from .engine import _get_rate_ds
from src.data_platform.rate_limit import rate_limit_context
```
循环内：
```python
with rate_limit_context(ds, table):          # 键=表名=api 名=档键
    df = getattr(pro, spec["api"])(**kwargs)
```
ds 在 `_sync_pools_data_inner` 头部 `ds = _get_rate_ds("tushare")` 取一次。
- **限速实效口径（代码审 B-P1-1 如实回写）**：循环形态=「标的→10 表轮转」，同键相邻两次调用自间隔 ≈3-5s（9 次其它表调用+DB 写）≫ 0.3s 档值 → 稳态 acquire 等待 ≈0。**本批对 pool_data 的真实行为变化=失败计入熔断记账 + 每键首过突发帽**；档表完备的意义=循环形态变化（加表/改单表模式）时立即生效。真 pacing（provider 级共享 pacer）**挂账另批**（per-API 键模型不支持跨键共享节奏）。
- **熔断共享拓扑（代码审 B-P1-2 如实回写）**：`_BREAKERS`/`_LIMITERS` 为进程内 dict（rate_limit.py:153 立法「单实例内存计数」）——pool_data 与 engine 熔断互见**仅在同子进程内成立**；prod celery prefork 并发 2 + `--max-tasks-per-child=100` 回收下大概率互不可见且记忆例行清零。D2「账号级封禁」在 prod 被拓扑稀释=**预存属性非本批引入**；跨进程真共享需 Valkey 层，另批立法（挂账）。
- 限速等待在 with 内、timebox 检查在循环头（:182）——等待使单轮略超软盒可接受。

## 风险面

- **tier1 七键 0.5s→0.3s 提速**：回补 365 交易日 = 365 次×节省 0.2s ≈ 73s 缩短，方向有利；日增量 1-2 次无感
- **四裸调点首接限速**：cb_basic/fund_basic 单次全量拉取（各 1 次调用/轮）加 0.3s 等待无感；namechange/concept full_rebuild 同
- **pool_data 限速化容量账（代码审 B-P1-1 修正）**：轮转自间隔（3-5s/键）≫0.3s 档值 → 稳态无附加等待，timebox 不因限速收窄；真实等待仅每键首过一次性 ≈3s/轮。**prod 部署前仍用 ansible 查 pool_symbols 计数**确认现状吞吐，并同查 `external_interface.params->'rate_limits'`（代码审 A-P3-1：若存 `{"daily": X}` 覆写会随 tier1 键化静默失效，有则先迁 per-API 键）
- **熔断共享**：见 64b-3 注明——预期行为变化非缺陷
- **SYNC_ID_CAP_MAP 扩键**：provider_capabilities 归一不变（全 ref_data）✅；SYNC_ID_CAP_MAP 键与 sync_kind_config 行集 30=30 同车（漂移=守门测试键数断言抓）
- **迁移安全**：纯 INSERT/UPDATE 无锁风险；与 0105 无交互
