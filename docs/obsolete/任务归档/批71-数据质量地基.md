- **改法（勘察推荐 A）**：
  1. **删** `engine.py:691-698` 坏调用（_save_bars 内的 try 块）；
  2. 调用挪到**持有原生 df 的两处**：`_daily_to_save_fn`（:703-706，to_bar_rows 之前）+`_sync_cb_daily`（:496-500）——pro.daily/fund_daily/cb_daily 均含 pre_close+YYYYMMDD，四类检查中三类直接可用；

- **观察期语义**：修复后校验**首次生效**——issues 输出日志（「数据质量校验」），2-3 交易日观察甄别存量问题（属预期非回归）。

### 件 2 · H8 版本真源 seed（消键/列漂移）

- **现状**：唯一读侧 `store.py:27-40` `Store.cur_version(kind)` 读 `dataset_version:{kind}` 缺省 1/读失败 1（docstring 自记挂账）；列 DEFAULT 漂移源=0092 十表 DEFAULT 1+0095 bar_1min/5min SET DEFAULT 2；批 62a `_merge_run_lineage`（tasks.py:35-72）max(bar 表) 绕开（0109 注释明言不依赖未 seed 键）。
- **改法**：迁移 **0113** seed 三键（0054 形态先例）：
  - `dataset_version:bar_daily=1`（bar_1D）
  - `dataset_version:bar_minute=2`（**立法注释：bar_minute 版本=bar_1min 口径**——一键盖 7 表，1min/5min=2 其余=1，取 canonical 表口径；downgrade DELETE）

  - daily_basic 无精确 DataKind（fundamental_daily 最近）——**挂账不 seed**
- **读侧收口**：编码时核验 `_merge_run_lineage` 的 ver 来源——若已走 cur_version 则 seed 即生效；若恒走 max() 则同批改为「cur_version 有值优先」（最小收口）。
- **钉**：迁移后测试断言 `system_config 键值 == 对应表列 DEFAULT`（pg_attrdef 对账——防未来 0095 式推进再忘 seed）；`cur_version("bar_minute")==2` 不再走缺省。

### 件 3 · L4 LLM 用量计数（同表记账）

- **现状**：`gateway.py:429-443` `_log_usage`=chat/chat_stream/成败**全路径唯一汇点**（:343/:351/:392/:399 四处调用，t0/latency 已算）→ INSERT llm_usage（token 粒度独立表）；data_source_usage 表（0019+0090）=数据源用量真源，读面 `/api/data-source-usage`（sync.py:318-346）by provider 聚合。
- **改法（最小侵入=1 处覆盖全路径）**：`_log_usage` 内追加一行 data_source_usage INSERT——provider=conf.provider、api_name=`"llm:chat"`、calls=1、success、latency_ms、interface_id=NULL（0090 裸构造合法，批 55a 先例）；DB 失败静默（对齐 record_usage 语义，不阻 chat 主流程）。

### 件 4 · apiErr 插值通道（{param} 占位）

- **现状**：`api.js:29-38` apiErr 无参数传入；**插值先例现成**（api.js:36 `common.httpError` 命名插值）；后端 269 处 ApiError 中 64 处 f-string 动态 detail；**硬伤实锤**：`im_bots.py:223` BOT_QUOTA `f"每用户最多 {uq} 个"`（uq 可配）vs 词条 zh:1209/en:2622 **硬编码 5**；`im_bots.py:226` BOT_PLATFORM_LIMIT {pq} vs 词条硬编码 10。
- **改法**：
  - 后端：`errors.py` ApiError 加可选 `params: dict | None` → 响应体顶层带 `params`（与 extra 同一合并通道，批 12A 先例）；
