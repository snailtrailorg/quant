# 批 77 · 权限矩阵与实盘面分离（`live_control` 键）

> 立项 2026-10-01。**起因**：批 76 二次裁定把解冻挂 `strategy_control` 后，用户提出原则
> 「**analyst 只能进行回测和实盘测试，不能执行实盘交易，这是最基础的权限设置**」，要求
> 据此推演 analyst 是否应有解冻权限 → 推演结论=**不该**，且暴露出 `strategy_control`
> **键粒度太粗**（把「编辑策略资产/回测」与「启动实盘执行」混在一个键）。

> ⚠️ **术语澄清（防误读，2026-10-07 补）**：用户原则里的「**实盘测试 ≠ `live_task`**」。
> 「实盘测试」指**研究面**的策略验证（`strategy_control` 域：建回测 / 实盘测试任务），**不是** `live_task`
> （实盘执行任务，归 `live_control`）。analyst 权限＝`{read, strategy_control, data_sync}`（`0056` seed，
> `0074` 已删其越权的 `system_config`）——**analyst 从无 `live_control`，也建不了 `live_task`**。
> 本文件把「`POST /api/live-task` 及起停/删除/解冻」全判 analyst ❌，与此澄清一致。

## 一、推演（从原则出发，不是从现状出发）

**原则**：analyst = 研究角色（回测 + 实盘**测试**），**不执行实盘交易**。

**逐动作归类**：

| 动作 | 面 | analyst 应有 | 依据 |
|---|---|---|---|
| `POST /api/backtest` 等回测 | 研究 | ✅ | 回测＝历史模拟，不触真实资金 |
| `POST /api/pool` / `DELETE` 因子池 | 研究 | ✅ | 投研资产 |
| `POST /api/factors` CRUD / `preview` / `validate` | 研究 | ✅ | 因子/策略资产 |
| `POST /api/strategy` CRUD / `validate-python` / `validate-params` | 研究 | ✅ | 写策略＝回测前置 |
| `POST /api/strategy/{sid}/verify` | 研究 | ✅ | 标记「已通过回测验证」——纯元数据 |
| `POST /api/chat` / `POST /api/stock/{s}/analyze` | 研究 | ✅ | 只读工具直执 |
| `GET /api/runbook` | 通用 | ✅ | 只读 |
| **`POST /api/live-task`**（建实盘任务） | **实盘** | ❌ | 建真实盘任务 |
| **`POST /api/live-task/{tid}/start` / `stop` / `delete`** | **实盘** | ❌ | `systemctl start quant-live-task@N`＝起真实盘进程 |
| **`POST /api/live-task/{tid}/unfreeze`**（+ `unfreeze-request` 预览） | **实盘** | ❌ | **解冻＝恢复 BUY 放行**（`frozen_allows`：sticky 期 BUY 拒/SELL 放；解冻后 `buy_ok_check` 才可能过）——这是交易面动作 |
| **`POST /api/strategy/{sid}/start` / `stop`** | **实盘** | ❌ | `systemctl start quant-strategy@N`＝同款真实盘进程（**最易漏：它在 strategy.py 里，名字像研究面**） |

**关键发现（`strategy_control` 一键两域）**：

| 域 | 动作 | 特征 |
|---|---|---|
| **研究面** | 写策略/因子、回测、验证标记、AI 分析 | **只写资产、不起进程**；错了可重跑 |
| **实盘面** | 起停实盘任务、起停策略进程、解冻 | **起 systemd 进程 / 改真实盘执行状态**；错了下真单 |

⇒ analyst 持 `strategy_control` = 同时拿到两域 ⇒ **越界**（本批前就已存在，
批 76 的解冻只是显化了它）。

## 四、权限矩阵（立法：新增端点/工具时按此归类）

| 面 | 键 | viewer | analyst | trader | admin | 判据（一句话） |
|---|---|---|---|---|---|---|
| 读 | `read` | ✅ | ✅ | ✅ | ✅ | 不改任何状态 |
| 研究 | `strategy_control` | ❌ | ✅ | ✅ | ✅ | 只写**投研资产**、不起进程、不碰实盘 |
| 数据 | `data_sync` | ❌ | ✅ | ❌ | ✅ | 行情同步（非交易） |
| **实盘（单任务）** | **`live_control`** | ❌ | **❌** | **✅** | ✅ | **起/停 systemd 实盘进程、建删实盘任务、解冻——粒度=单任务/单策略** |
| **实盘总闸（市场级）** | `live_trading_control` | ❌ | ❌ | **❌** | ✅ | **市场级分项开关——影响半径=全市场，admin 独占（见 §七）** |
| **风控（全站）** | `halt` / `resume` | ❌ | ❌ | **❌** | ✅ | **全站熔断/恢复——影响半径=全站，admin 独占（见 §七）** |
| 下单 | `trade` | ❌ | ❌ | ✅ | ✅ | 直接下单 |
| 系统 | `system_config` 等 | ❌ | ❌ | ❌ | ✅ | 配置/凭证/用户 |

**新增受控动作时的判据**（先归类再选键，别从「谁该有」倒推）：
1. 它**起不停进程**？起 systemd/改实盘执行状态 ⇒ `live_control`；只写库 ⇒ 研究面。
2. 它**能不能导致真实成交**？能 ⇒ 至少 `live_control`；直接下单 ⇒ `trade`。
3. 它**改不改全站/全市场闸**？⇒ `halt`/`resume` 或 `live_trading_control`——**这两个都是 admin 独占**。
4. 都不沾 ⇒ `read` / `strategy_control` / `data_sync`。

> **粒度是分档的第一依据**（批 77 续确立）：单任务（`live_control`）→ 全市场（`live_trading_control`）
> → 全站（`halt`/`resume`）。**越粗的档，持有者越少**：trader 只到「单任务」，更粗的两档收归 admin。

## 七、续：全站/全市场闸收回 admin 独占（2026-10-01，同批追加）

**起因**：批 77 主体收官后追问「`live_trading_control` 该不该在 trader 手里」，顺带照出
`halt` 同样越界，用户裁定：**`halt` 与 `live_trading_control` 都只挂 admin**。

**判据（粒度分档）**：
| 档 | 键 | 影响半径 | 持有者 |
|---|---|---|---|
| 单任务 | `live_control` | 一个任务/一个策略进程 | trader + admin |
| **全市场** | `live_trading_control` | **整个市场所有任务** | **admin 独占** |
| **全站** | `halt` / `resume` | **全站所有市场** | **admin 独占** |

逻辑：**越粗的档越危险，且「开」比「停」更危险** → 与既有的 `resume` 仅 admin 同源。

**关键连带（同型病的又一例）**：`_filter_tools` 修前条件
```python
if "trade" in perms or "halt" in perms:   # ← halt 靠 trade 连坐放行
    allowed += TRADER_TOOLS
```
**「收回 halt」若只改 `perms.PERMISSIONS` 就是假的**——trader 仍有 `trade`，连坐照样放行
`emergency_halt`。必须**同时断开连坐** → 改为 `if "halt" in perms:`。这是批 76 P1「同动作多面
各判各的」的另一形态：**同动作多键连坐**。

**落点性质**：本次改的是**缺省种子**（`perms.PERMISSIONS`）——线上真相在 `permission` 表，
用户已在界面删除 trader 的 `halt`/`live_trading_control` 行。改种子的目的是防**新环境**
（表空回落字典）复活该权。要恢复 trader 的急停权＝**建显式角色赋键**（如 `live_operator`），
而非改回缺省——这也印证了「缺省收权 ≠ 堵死路径」。

**前端连带**：`Risk.vue` 三按钮补权限显隐——熔断（`halt`）、恢复（`resume`）、市场分项开关
（`live_trading_control`）。此前该页**完全无权限判据**（连 `navReadonly` 都没接），
任何进得来的角色都看得到按钮、点了才 403。

**闸门**：`TestGlobalGatesAdminOnly`（5 钉）+ `test_filter_trader_no_halt_no_resume`（反转原钉）
+ `test_filter_trader_halt_requires_halt_key_not_trade`（连坐守卫）。
**逆转实证**：① `halt` 放行条件加回 `trade` 连坐 → `test_filter_trader_halt_requires_halt_key_not_trade` 红；
② `halt` 加回 trader 集 → `test_trader_lacks_global_gate_keys` 红。

## 八、【补】`live_control` 表行漏种 P0（2026-10-02 批 76b 发现并修复）

### 8.1 病灶

批 77 把实盘面 8 端点从 `strategy_control` 迁到新键 `live_control`，**只改了
`perms.PERMISSIONS`（缺省字典）**，**没有改 `permission` 表**。

而 `load_role_permissions` 的语义是（`perms.py:174-178`）：

```python
tab_allow = tab.get("allow") or set()
allow = (tab_allow if tab_allow else base) - tab.get("deny", set())
#      ↑ 表有该角色的 allow 行 ⇒ 全量以表为准，base（字典）被完全盖住
```

`0056` seed 给四角色都写了 api 行 ⇒ **表恒有行 ⇒ 字典永不生效** ⇒
`live_control` 在**任何角色下都不存在**。8 端点全 403：

| 端点 | 文件 |
|---|---|
| `create_live_task` / `start_live_task` / `stop_live_task` / `delete_live_task` | `trading.py` |
| `unfreeze_live_task` / `get_unfreeze_request` | `trading.py` |
| `start_strategy` / `stop_strategy` | `strategy.py` |

**即：建不了实盘任务、启停不了、解不了冻——连 admin 自己也一样。**
批 76b 刚做好的解冻按钮在 UI 上是**死按钮**（点了几何 403）。

### 8.2 为什么全闸门绿

批 77 建的 `TestToolGatingContract`（`test_batch76_unfreeze_surface.py:181+`）
**只扫源码字面量**：`re.search(r'require_perm\(\s*"([^"]+)"\s*\)', inspect.getsource(fn))`。
它断言「**代码声明一致**」，**从不解析 DB 生效权限集**。全部既有测试都是绿的——
`test_permissions_w4.py` 的矩阵测试甚至明确用**空表**跑（表空 ⇒ 走字典 ⇒ 恰好掩盖了本 P0）：

```python
conn.execute.return_value.fetchall.return_value = []   # permission 表空→字典回退
```

**这就是本 P0 的测试盲区**：整套测试架构建立在「表空回落字典」的假设上，
而 prod/staging 的表**从来不空**。

### 8.3 为什么用户「在界面删了」救不回来

用户删的是 `halt`/`live_trading_control` 的**行**。PermMatrix 保存走
**全量重写**（`auth_routes.py:262-273`）：

```python
conn.execute("DELETE FROM permission WHERE subject_type='role' AND subject_id=%s AND dimension='api'", (role,))
for k in out: conn.execute("INSERT INTO permission ... VALUES ('role', %s, 'api', %s, 'allow', %s)", ...)
```

写入集 = **前端提交集**。而前端 `permGroups` 当时**还没有** `live_control` 可勾
（批 77 才加进 `trading` 组）⇒ **无论怎么勾都写不出 `live_control` 行**。
⇒ 必须由**迁移**补行。

### 8.6 立法（本批新增通用律）

> **加键 ≠ 加行。** `permission` 表有行时，`perms.PERMISSIONS` 字典被**完全盖住**。
> 任何「新增 perm 键 + 给角色赋键」的动作，**必须同时**：
> ① 改 `perm_registry.API_PERM_KEYS`（注册表）；② 改 `perms.PERMISSIONS`（**仅新环境兜底**）；
