# 批 8 · 变更感知发布（web-only 快车道，业界对齐）

> 2026-09-02 凌晨立项（用户裁定"干了"）。痛点实证：release.yml:337 波次循环无条件全量重启 7 组单元+固定 dwell 30s——纯前端变更（09-01 三次上产）也白重启 web_api/worker/beat/hub/飞书；单循环 staging+prod ≈12-15min，其中波次占大头。业界默认即变更感知（k8s 同 spec 零动作/Ansible handler changed 触发/RHEL needs-restarting）——本批对齐。

## 目标

server 四切片指纹（src/migrations/scripts/systemd/requirements.txt+**alembic.ini 补入**）与上一版一致且单元未变 → **快车道**：跳过阶段 3（导入冒烟）/阶段 5（pip 预检+freeze×2+alembic）/阶段 7（波次重启），只走同步+双链 flip+postverify（healthz/probe/MainPID/pinned=旧版断言）。web-only 发布 ~10min → **~2min**。`-e force_full=true` 逃生门恒走全量。

## 设计要点

1. **指纹完备性（命门）**：server 全部输入必须入指纹——alembic.ini 现在同步白名单有、指纹没有（本批补）；web/dist 不入 server 指纹（快车道正是"server 无关变更"的判据）。
2. **server_changed 判定**（阶段 2 切片变更判定处 set_fact）：prev_release_id 空（首发布）∨ 任一 server 切片指纹不同（含空指纹=视为变更的既有防御语义）∨ force_full。
3. **双链 flip 保留**：server 符号链接照切（原子零成本），进程不重启=钉旧版目录（GC 被钉项保护既有）；回滚时 waves_touched 空=只翻链零重启，语义自洽。
4. **postverify ③ 收敛断言改三元**：expected_pinned = server_changed ? {release_id} : {prev_release_id}（快车道不重启=钉旧版是**期望态**，非混合态故障）；①②（指向/MainPID）与 healthz/probe 恒跑。
5. **DDL 门（阶段 4）恒跑**：无新迁移时自平凡通过，expand-only 不变量不断言；导入冒烟/pip/alembic 在指纹一致时结果必然与上一版相同（同内容）→ 跳过无损。
6. dwell 参数化本就存在（`deploy_dwell_seconds`，`-e` 覆盖原生支持）——只文档化不编码。
