# 批 92 · 同步游标语义根因与静默缺失

> 立项：2026-10-04（与批 91 同批上产）。状态：实现完成，待上产。
> 写法：单任务流程见 `flow/规范/工作流程.md` §二；本文件只写**契约**（免翻代码），
> 设计背景引用上游不复制（`flow/方案/数据同步验证L5-界面走查表-20261004.md`）。

## 一、问题（症状 → 根因）

**症状**（prod 只读实查，2026-10-04）：数据管理界面 24 行 sync 配置表里 `margin_detail_sync`
（融资融券明细）长期无成功、目标表 `margin_detail` **零行**；池数据 `pool_data` 每 5 分钟一轮
全量重写（100 轮日志全「成功 / 4470 条重写」）。

**根因一 · 窗口上界取「今天」，而数据在「今天」不可得**
`engine.sync()` 以 `date.today()` 作 end_date；`_make_tier1_handler` 的逐日循环
`pd.date_range(start=last+1, end=today)` 把**当日数据尚未发布的「今天」**也纳入窗口。
`margin_detail` 是 T+1 数据（cron `0 9 * * 1-5`，描述即「次日 09:00 拉昨日」）⇒ 拉「今天」恒 0 行。

**根因二 · 入库 0 行也推进游标 ⇒ 前沿日永不复访**
`sync()` 对不返回 `last_success_date` 键的 handler 走 `_advance = (end_date, saved, "idle")`
——**无条件**推到 today。于是「今天」这一天，在它唯一可能被拉到的那一轮（恰恰是它不可得的
那一轮）之后被**永久跳过**。两根因叠加 ⇒ `margin_detail` 全表恒空——不是「少一天」，是
「一天都没有」。

**根因三 · 池数据调度频率与数据粒度错配**
池内 10 表＝财务四表（季报、按公告日增量）+ 筹码/股东/事件表（季频/事件驱动），却配
5 分钟 beat ⇒ API 配额空转 + 逐轮 4470 行 upsert 写放大。

## 二、契约（改后行为，唯一真源＝代码）

| 项 | 契约 |
|---|---|
| 增量窗口上界 | ＝`_data_ready_end_date(lag_trade_days)`：最近一个「已可用」的 SSE 交易日（真库 `trade_cal`）；lag=1 ⇒ **严格早于今日** |
| 表级延迟声明 | `engine._TIER1_LAG_TRADING_DAYS`：`margin_detail_sync: 1`；未声明＝0（盘后当日可得） |
| 游标推进 | `sync()`：`_advance = (r.get("cursor_upto") or end_date, saved, "idle")`——handler 回传 `cursor_upto` 时以它为准（可窄于 today）；缺省仍 `end_date`（未声明者零回归） |
| 回看重叠 | tier1 `_TIER1_OVERLAP_DAYS=3`（自然日）；池数据 `_POOL_OVERLAP_DAYS=7`——幂等 upsert 兜上游迟发布 |
| 池数据窗口 | 上界＝**昨日自然日**（cron 改每日 02:00 后当日公告尚未发布）；下界＝cursor−7 |
| 池数据调度 | `sync_config.pool_data.schedule`：`*/5 * * * *` → `0 2 * * *`（迁移 0130）；全量校准 `7 4 * * 0` 不动 |
| fail-open | trade_cal 缺表/读失败 ⇒ 自然日回退（lag=0 保 today＝旧行为），绝不抛 |

## 五、边界与挂账（本批不做）

- **不修**：`_sync_by_trade_date` 系与 bar 族——它们已有 `last_success_date` 三态 +
  「连续成功末日」语义，本批不动（避免与既有精细机制叠加出新行为）。
- **挂账**：`forecast`（ann_date 驱动）的逐日循环用 `freq="B"`（排除周末）⇒ 周末公告永久漏；
  改真交易日历需另立一批。
- **连带**：池数据 cron 属配置面变更，随本批迁移落；上产后界面即显新调度，无需另改前端。
