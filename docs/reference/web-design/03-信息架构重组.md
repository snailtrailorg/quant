# 03 · 信息架构重组方案

## 1. 现状导航（线上实测还原）

```
首页
交易          → 交易 / 监控 / 任务
策略实验室     → 策略 / 实盘任务 / 回测 / 股票池 / 因子
数据分析       → A股筛选 / 可转债筛选 / ETF筛选 / 分析 / AI对话
风控          → 风控 / 对账 / 风控规则
运维(admin/analyst) → 数据管理 / 数据完整性 / 系统健康 / 帮助 / 日志
设置(admin)    → 账户 / 审计 / LLM模型 / IM机器人 / 系统配置 / 数据源 / 通道 / 券商
```

## 2. 核心问题（按用户心智，不是按代码模块）

1. **"实盘任务"住在"策略实验室"里**。用户心智：实验室=沙盒安全，实盘=真金白银。把执行环节塞进研究分组，模糊了危险边界——研究员视角的页面排序（策略→实盘→回测）也与生命周期相悖（回测在前，实盘在后）
2. **三个筛选器占三个菜单位**。A股/可转债/ETF 筛选是同一个心智动作（"选标的"），导航噪音 ×3；且"数据分析"分组名与筛选、AI 对话的混合内容不符
3. **风控被低估**。风控/对账/规则蜷缩在倒数第二组，但"三账对账异常"是平台上唯一的 critical 通知（实测）。风控是实盘的生命线，不是侧栏尾注
4. **"任务"歧义**。交易组的"任务"（调度任务 TaskManager）与"实盘任务"（LiveTask）在同一导航里两个"任务"，用户必须靠位置记忆区分
5. **设置组 8 项平铺**。账户/审计/LLM/IM/系统配置/数据源/通道/券商——数据源与券商是"外部连接"，账户与审计是"人与安全"，混在一层
6. **帮助藏在运维组**，发现性为零；顶栏左侧整块留白（实测 MainLayout header 左侧为空），无面包屑、无全局搜索
7. **通知路由映射错误**：email→/logs、system→/logs（实测代码），告警无去处

## 3. 菜单架构 v2 —— 双环模型（系统设计推演）

### 3.1 组织公理（先立规矩，再排菜单）

| # | 公理 | 含义 |
|---|---|---|
| P1 | **一屏一帽** | 分组名对应用户此刻戴的"帽子"（角色场景），不是技术模块名。单人三角色的平台，菜单服务"同一个人在不同时间换帽子"，而非"不同部门各取所需" |
| P2 | **组内即流程** | 组内条目按业务流程顺序排列（上→下=时间先后），菜单本身就是操作教程 |
| P3 | **危险分区** | 真金白银的操作（实盘+风控处置）聚成连续区域并做视觉标识；研究与实盘之间必须有清晰边界——这是三级开关在导航层的投影 |
| P4 | **裁剪成章** | 任何角色看到的菜单必须是语义完整的"工作台"，不允许挖洞式残缺（如支撑层只露半项）。做不到完整就整体隐藏，用顶栏轻量入口补偿 |
| P5 | **支撑下沉** | 数据/集成/可观测/设置是基础设施，沉到菜单底部并做视觉弱化，不打断业务主线 |

### 3.2 核心洞察：系统不是一个线性流程，是**两个环 + 一个支撑层**

```
      ┌─────────── 研究环（慢环：天/周尺度，探索性，沙盒安全）───────────┐
      │  选股 → 入池 → 研究因子 → 构建策略 → 回测验证 → 研判信号 → 反哺    │
      └────────────────────────────────△───────────────────────────────┘
                                       │ 验证证据（三级开关）
      ┌─────────── 运营环（快环：日/分钟尺度，守成性，真金白银）───────────┐
      │  晨检 → 上线任务 → 盘中执行/监控 → 风控熔断/对账 → 复盘 → 反哺研究  │
      └────────────────────────────────△───────────────────────────────┘
                                       │
      ┌─────────── 支撑层（低频：管理员帽子，基础设施）───────────────────┐
      │  数据中心 · 集成中心 · 可观测性 · 系统设置                        │
      └────────────────────────────────────────────────────────────────┘
```

- **风险轴是唯一成立的分组依据**（二轮盲审修正：初版"时间尺度"论证被 05"回测是最高频页"自证伪，撤回）。两环是**资本隔离而非资源隔离**（二轮业务盲审）：研究侧无本金代价，但共享限流积分/LLM 预算/hub 订阅——研究重操作应透出配额水位，重度消耗可波及实盘行情链
- 两环通过 **backtest_verified 证据链**衔接（研究环的出口=运营环的入口）
- 风控内嵌于运营节奏（晨检水位→盘中熔断→盘后对账），但拥有独立"否决权"帽，独立成组；**熔断入口长在火场**——顶栏常驻急停+盯盘页头就地按钮（红队#5），风控组保留审计与规则

│ 面包屑  ⌘K全局搜索   [A股●开盘中] [数据健康●]   🤖AI助手  🔔通知  ?帮助  头像 │

总览
  └ 指挥中心                    每天的起点：告警/风控水位/实盘状态/权益/今日事件/每日研判卡

**16 项 5 组**（v2.1，二轮盲审后定稿）。"环"退为本文档的论证语言，不上 UI——界面组名统一四字：策略研究/实盘交易/风险控制/系统管理（组名与菜单项同字号 13.5，父子层级靠字重+色阶区分，不靠字号倒置）。复盘对比（回测 vs 实盘）不设菜单项：回测报告内嵌"同窗实盘净值"对照线 + 实盘任务详情加 vs 回测 tab（红队#3：两环接缝即对比之家）。

### 3.4 权限矩阵（角色裁剪的显性设计）

原则：**熔断人人可触发**（安全方向动作低门槛），**恢复仅 admin**（对齐 IM 契约）；支撑层整组裁剪保证"成章"（P4）；trader 的数据健康诉求由**顶栏数据健康灯**承接（点开抽屉看各市场完整度摘要），不需进入支撑层。

| 组 | 条目 | admin | analyst | trader | viewer |
|---|---|---|---|---|---|
| 总览 | 指挥中心 | RW | RW | RW | R |
| 研究 | 选股器/股票池 | RW | RW | R | R |
| 研究 | 因子库/策略/回测 | RW | RW | R（了解在跑配方的证据） | R |
| 研究 | 研判信号 | RW | RW | R | R |
| 运营 | 实盘任务 | RW（含删除） | R+创建落**灰度态**（转正式需 admin，复用 F-EXE-004；删除仅 admin——证据生产者不能一人走完"出证据→上线"） | RW | R |
| 运营 | 交易台 | RW | R | RW | R |
| 运营 | 运行监控 | RW | R | RW | R |
| 风控 | 风控总览 | RW | **W 仅熔断**/R | **W 仅熔断**/R | R |
| 风控 | 三账对账 | RW（豁免/清零=admin） | R | R+重跑+暂挂（**豁免/清零移 admin**——执行守护者不能抹平自己的差异） | R |
| 风控 | 风控规则 | RW | R | R | 隐 |
| 支撑 | 数据中心 | RW | R+触发同步/回填（Cron 编辑仅 admin） | 隐+**"按标的回补"单动作**（冻结处置第三步需要） | 隐 |
| 支撑 | 集成中心 | RW | 隐 | 隐 | 隐 |
| 支撑 | 可观测性 | RW | R | 隐 | 隐 |
| 支撑 | 系统设置 | RW | 隐 | 隐 | 隐 |

**裁剪后的四个完整工作台**（二轮修正后）：
- admin：全 16 项（单人三角色=默认视图）
- analyst：14 项——总览+研究RW+实盘R（创建落灰度）+风控R+数据中心——"研究员工作台"
- trader：13 项——总览+研究R+实盘RW+风控R+豁免清零不可——"交易员工作台"
- viewer：12 项只读（备字段级脱敏开关：持仓聚合/risk_log 计数，防策略意图泄漏）——"观察席"

落地路径（二轮盲审）：先按 **admin/非 admin 两档**实现，四角色做数据标记——单人平台矩阵是护栏设计不是当期工程；扩到 3-5 人时，灰度激活与豁免清零两处拆分正是届时接缝。"角色模拟预览"延后到真有第二人再做。

**Web/IM 同门槛声明**：IM 侧各操作（熔断/启停/重启/恢复）的角色门槛并入本矩阵同一标准——飞书是"权限更宽的平级入口"指交互形态，不指权限上限。

**深链权限感知**（红队#3/导航盲审#4）：任何跳转到当前角色不可见页面的链接（如回测失败"去日志"）不产生死链——降级为"无权查看+摘要+原因+申请入口"；顶栏健康灯抽屉**自含诊断**（哪个源/断多久/影响面+动作），不跳页。

### 3.5 备选方案与取舍（为什么是双环）

| 方案 | 形态 | 落选原因 |
|---|---|---|
| A 按业务域（v1） | 研究/策略/实盘/风控/系统 | "研究 vs 策略"边界靠备注解释（盲审已抓）；无流程感；风控与实盘的危险关联未表达 |
| B 按生命周期直线 | 数据→选股→因子→策略→回测→实盘→监控→复盘 | 8 组过碎；"数据准备"对 trader/viewer 无关却占首位；系统实际是两个转速不同的环，不是一条线——直线模型会把运营环的每日循环拆散到三四个组里 |
| D 按对象 | 策略/因子/任务/账户/数据 | 工程视角，用户不按对象思考 |
| **C 双环+支撑（采纳）** | 研究环/运营环/风控/支撑 | 两个环对应两顶帽子与两种风险等级（P1/P3 天然成立）；组内流程排序（P2）在环内成立；支撑层整组裁剪（P4/P5） |

一个刻意的非对称：**研判信号放研究环末位而非运营环首位**——它虽每日产出，但其生产资料是因子模型（研究资产），trader 以只读方式消费它；若放运营环，analyst 反而要进危险区。

### 3.6 导航的三层体系

菜单只是第一层。完整导航=菜单（发现）+ 跨页跳转（流程捷径）+ ⌘K（直达）：

```
因子库 ──被引用列表──→ 策略（筛选：引用该因子）
策略 ─[保存并回测]→ 回测表单（预填）
回测 Run ─[标记已验证]→ 策略 ✓ 证据链（可点回看）
回测 View ─[创建实盘任务]→ 任务表单（带证据，三级门禁第③级绑标的/账户）
实盘任务 ──点击──→ 交易台（该任务过滤视图）──代码──→ 个股详情
对账差异行 ──[查看持仓]→ 交易台定位
通知/健康灯 ──精确路由──→ 风控总览/数据完整性/调度任务
选股器勾选 ──[加入股票池]→ 池选择弹窗（不跳页）
⌘K：策略/因子/标的/池/任务/回测/页面 八类索引，回车直达
```

**三级开关在导航层的投影**（对齐 06"勿误修"）：①代码校验、②done 回测证据展示在研究环（因子/策略/回测），③绑标的/账户发生在运营环（任务创建）——环的边界=门禁的位置，菜单结构与权限结构同构。
