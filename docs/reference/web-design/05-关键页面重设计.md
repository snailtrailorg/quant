# 05 · 关键页面重设计方案

> 每页含：设计目标（业务）→ 布局线框 → 关键交互定义。视觉规范见 04-设计系统，此处不重复。

## 5.0 全局补充规范（盲审三补充）

1. **空态/冷启动**：每个页面必须设计零数据首访态——Dashboard 无任务时显示"三步上实盘"引导（建因子→写策略→跑回测）；表格空态给"新建"主按钮+说明，不用裸"暂无数据"
2. **通知中心本体重设计**：body 结构化（差异表/错误摘要折叠展示），每条通知带精确路由+**runbook 链接**（"每告警一条 runbook"是 06 B#14）；盘后报告作为通知类型落地页；宽度 380→480px 抽屉替代 popover
3. **降级显式标识**：行情降级链（hub→腾讯→null）部分降级时页面顶部显示黄色横幅"部分标的降级为腾讯快照"（06 宝藏 #6）；fail-closed 触发时风控水位卡显示"风控数据源陈旧，已拒新 BUY 单"
4. **响应式立场**：桌面优先（≥1280px），不做移动端适配——小屏仅保证不破版；移动场景由 IM（飞书）承接告警与查询，这是平台已有架构
5. **多显示器**：所有 tab/筛选状态写入 URL（`?tab=&status=&symbol=`），支持并排比对与深链分享
6. **色盲安全**：涨跌必配 ± 号/箭头（04 已定）；状态除颜色外加形状（点/叉/冻结❄/⛔）

## 5.1 总览 Dashboard —— 从"统计卡"到"指挥中心"

**设计目标**：交易员早晨打开 30 秒内回答四个问题——钱安全吗？任务活着吗？今天赚亏？数据正常吗？

```
┌────────────────────────────────────────────────────────────────┐

│    三账对账异常 15 项 · 数据缺失 2 项 · 1 个任务 error  [处理→]   │
├──────────┬──────────┬──────────┬──────────┬───────────────────┤
│ 总资产    │ 今日盈亏  │ 总盈亏(成立│ 风控水位  │ 可用资金/占用      │
│ ¥10.00亿 │ +12.4万   │ 以来)+3.2%│ 回撤▂▃▅░ │ 320万/680万        │
│ +sparkline│ ↗+0.12% │ 基准注明  │ 40%/15%  │                    │
│ 实盘任务 ●2运行○3停 + 今日事件 ⚠转债强赎登记×2/除权×5 [→]│
```

**要点**（盲审仲裁后修订）：
1. 每个模块 = 一个下钻入口（KPI→明细三层内到达），数字全部业务格式化
2. 风控水位用双进度条（当前回撤/阈值、当日亏损/限额），颜色随水位 绿→黄→红——**标注：引擎无预警语义，两档变色纯 UI 可视化**（初版暗示了不存在的约束，盲审三指出）
3. 删除"回测策略 X/Y"这个语义不明的 KPI；总盈亏必须带时间基准（成立以来/近一年切换）
4. **今日事件**模块（盲审一补充）：除权除息/转债强赎登记日/财报披露——强赎直接打爆 double_low 类策略，转债在产平台这是晨检硬项
5. 盘中状态感知：顶栏市场状态灯；盘中权益曲线 5s 轮询起步（WS 推送 /ws/pnl 属 [C] 未实现，为目标态），盘后静态
6. 告警条聚合 notifications 未读 critical/warn，点击精确路由
7. 1440 屏密度控制：数据健康/最近回测正常态折叠为状态点，异常时展开

## 5.2 交易台 —— 从"三列持仓表"到"看盘运维台"

**设计目标**：盘中不切页即可回答"我现在持有什么、赚多少、今天成交了什么、冻结多少"。

```
┌──────────────────────────────────────────────────────────────┐
│ 账户摘要: 总资产 | 可用资金 | 占用保证金 | 今日盈亏(红涨绿跌)   │
├──────────────────────────────────────────────────────────────┤
│ tabs: [持仓(12)] [今日订单(3)] [成交(1)] [盈亏曲线] [资金流水]  │
├──────────────────────────────────────────────────────────────┤
│ 持仓表:                                                        │
│ 代码  名称  方向  持仓量  可用  成本价  现价  浮盈  浮盈%  市值  操作│
│ 300888 新产业 NET  600    600  73.321  75.2  +1,128  +2.55% 4.5万 详情│
│ （现价来自行情快照；浮盈实时着色；代码可点击→个股详情）          │
│ 订单表: 委托号 时间 代码 名称 方向 数量 价格 状态 失败原因 操作  │
└──────────────────────────────────────────────────────────────┘
```

**要点**：
1. **补齐 API 已有但不展示的字段**：direction/frozen/cost_price/pnl——这是现状最大的浪费
2. 现价/浮盈由行情快照联动，5s 轮询（盘中）/60s（盘后），表格顶部显示"最后更新 HH:MM:SS + 手动刷新"
3. 订单方向/状态中文化+着色 tag（BUY→买入 红 / SELL→卖出 绿；submitted→已报 橙 等），补委托号与失败原因
4. 从个股详情返回交易台：个股页头部加"← 返回持仓"上下文
5. 盘后自动展示当日成交汇总（笔数/费用/净盈亏）
6. **SELL 保底明示**（06 宝藏 #3）：冻结/盲视期横幅"风控冻结中：BUY 已拒，SELL 正常放行"——这是用户风控安全感的来源
7. "成交/资金流水"两个 tab 依赖后端端点（当前无），原型预留位
8. **人工单登记**（红队#4 二轮）：底仓/场外手动单真实存在，赶去券商 App 做会回流成对账噪音——交易台收编"人工单登记"入口，登记后进对账豁免基准
9. **顶栏常驻急停 + 盯盘页头就地熔断**（红队#5 二轮）：火警时不该先找消防栓在几楼——熔断主入口长在交易台/指挥中心/实盘任务页头，风控总览保留审计与规则

## 5.3 风控总览 —— 从"只读阈值"到"水位仪表 + 决策审计"

**设计目标**：不点任何东西就知道"现在离熔断多远"；每次拒单/覆写都有据可查；要熔断时一步到位。吸收 06 差距 B#1/B#2/B#3（盲审三指出初版脱节：重设计后最黑的箱还黑着）。

```
┌──────────────────────────────────────────────────────────────┐
│ ⛔ 总闸关闭红警条(.env 级)：所有分项开关当前无效 [说明→]         │  ← B#1
│ 状态: ● 正常运行 / ⛔ 已熔断(原因)          [熔断] [恢复]      │
├───────────────────────────────┬──────────────────────────────┤
│ 水位仪表                       │ 生效规则                       │
│ 最大回撤   ▓▓▓▓▓░░░░░ 8.2/15% │ global: 回撤15% 日损5%         │
│ 当日亏损   ▓▓░░░░░░░░ 1.1/5%  │ etf_conv: 单仓15% 日20笔 …     │
│ 杠杆       ▓░░░░░░ 1.2/5x     │ [编辑规则→]                    │
│ ⚠快照陈旧 32s (阈值300s)       │ fail-closed: 陈旧>300s 拒BUY   │  ← B#3
├───────────────────────────────┴──────────────────────────────┤
│ 风控决策日志 risk_log（B#2，07号文档明写"供Web展示"）            │
│ 时间 | 动作(拒单/覆写/放行) | 规则 | 详情 | severity            │
│ 14:32 拒BUY 600000 单仓15%超限 截断→adjusted vol 300→45 [审计]  │
├──────────────────────────────────────────────────────────────┤
│ 市场实盘开关（每行: 市场 | 挂单数 | 状态 | [启停按钮+确认])       │
│  A股 ● 运行中 [暂停]    ETF ● 运行中 [暂停]   可转债 ○ …       │
│  （加密两个市场显示"未开通"占位——外部 gate，见 06 降级）         │
└──────────────────────────────────────────────────────────────┘
```

**要点**（盲审仲裁后修订）：
1. **总闸红警条置顶**（B#1）：.env 总闸关闭时市场开关全部禁用+红条解释，消除"拨了没用且不知情"
2. **risk_log 决策面板**（B#2）：拒单原因/覆写记录/severity 可筛选——风控页最有审计价值的数据，文案明示"SELL 永放行"
3. **fail-closed 可见**（B#3）：快照年龄>300s 时水位卡显示"风控数据源陈旧，已拒新 BUY"
4. 水位进度条=核心，但**75%/90% 变色是纯 UI 可视化**（引擎无预警语义，不暗示约束）
5. 市场启停从 el-switch 改为按钮+确认弹窗（显示影响："将停止 A股所有策略下单，挂单 3 笔将被撤销，确认？"）
6. **熔断=轻确认**（一键急停+确认弹窗；慢半拍=真实亏损）；**恢复=输入确认**（重新暴露风险才是强确认该在的地方——盲审一驳回初版"输入 CONFIRM"方向）

## 5.4 三账对账 —— 从"文本列表"到"差异处置台"

**设计目标**：把 15 条"账实分离"从日志文本变成可定位、可处置、可关闭的差异单。

```
┌──────────────────────────────────────────────────────────────┐
│ 汇总: ⚠ 15 项差异 (持仓 15 · 资金 0 · 成交 0)  [重新对账]      │
│      最后对账时间 08-29 15:30                                  │
├──────────────────────────────────────────────────────────────┤
│ 差异表:                                                        │
│ 标的   差异类型  券商持仓  系统推导  差额   首次发现   状态   操作  │
│ 300058 持仓不符  3,900     0        -3,900  08-20    待处理  ▾ │
│   ▾ 展开明细: 该标的最近订单流 / 券商快照时间 / [查看持仓]      │
│   处置: [标记已核实] [重新同步] [登记豁免] [忽略本次]            │
│ [手动登记场外单] [次日开盘前清零 ▾确认]                          │
└──────────────────────────────────────────────────────────────┘
```

**要点**（盲审一/三仲裁后闭环化）：
1. 后端把 `issues` 字符串数组结构化为 `{symbol, type, broker_qty, derived_qty, diff, first_seen, status}`——**差异处置状态后端持久化**（前端存储会跨设备失同步、与通知中心脱节）
2. 差异行展开即见证据链（订单流+快照时间），一键跳转交易台持仓定位
3. 四处置动作：**登记豁免**须登记 symbol+数量+生效期+原因并留审计（粗粒度"按类型豁免"会把真实漂移藏进豁免类——盲审一驳回初版粒度）；差异较豁免基准扩大须重新告警
4. **清零入口显式化**：次日开盘前清零=接受差异为新基线，须显式确认+留痕（初版线框漏画）
5. 手动登记场外单（豁免差异的主要来源）
6. critical 通知在全部处置完前不清除；对账结果推送 IM

## 5.5 因子库（研究环第 3 站）—— 让因子成为可验证、可复用的资产

**设计目标**：回答研究员三个问题——这个因子是什么行为（试算）、谁在用它（引用）、我能不能改（影响面）。

```
┌──────────────────────────────────────────────────────────────┐
│ 因子库  [搜索名称/描述] [分类▾] [类型▾ 自定义|预设]  [+ 新建因子] │
├──────────────────────────────────────────────────────────────┤
│ 名称   分类  类型  动/静  被引用            描述   参数    操作   │
│ ma_dev 趋势  预设  动(20) 3 个策略 ↗       均线偏… n=20   试算   │
│ dsl    自定义 预设  静    —               受限DSL… —     编辑 删│
│ （被引用可点：弹出策略列表，可跳转；参数渲染为 chip 而非裸 JSON）│
└──────────────────────────────────────────────────────────────┘
新建/编辑（右侧抽屉 720px，非弹窗——保留长上下文）:
  基本信息区: 名称/分类/描述
  定义区: [DSL 表达式|Python 代码] ← DSL 也要有入口（现状只有 Python）
     DSL: 带因子名自动补全 + 语法高亮 + 即时校验（后端已有 /factors/validate）
     Python: 现有 PythonEditor + 校验按钮（保留）
  试算区: 标的(搜索) | 频率(1D/1min/5min) | 窗口根数 | [试算]
     → 内嵌 mini 图 + 统计（min/max/最新/IC 若可得）
```

**要点**：
1. **试算三参数放开**（现状硬编码 600000/1D/60 根）——因子在不同标的/频率的行为差异正是研究内容
2. **DSL 与 Python 平权**：dsl 预设因子的文档明说支持 Web 端受限表达式，新建入口却只有 Python；DSL 编辑器做因子名补全（下拉数据已有）
3. **被引用列可点**（现状是死数字）：弹引用策略列表 + 各策略当前权重——改因子前先看影响面，这是"因子是资产"的关键一步
4. 参数列渲染 `n=20` chip，不再 JSON.stringify 裸输出；操作列恒在（现状无自定义因子时整列消失）
5. 表格分页 + 搜索 + 分类筛选

## 5.6 策略编辑 —— 从"超长表单"到"策略工作台"

**设计目标**：把"写策略→配因子→定参数→发起回测→看结果→迭代"缩进一个连续上下文。

```
列表页:
│ 名称  类型  模式  标的示例  状态  验证✓(带证据)  最近回测   操作      │
│ 实盘测试 astock DSL  600000 ●运行  ✓ 08-28 年化+12%↗ [回测][编辑][⋯]│
  · "验证✓"独立成列：hover 显示"由 08-28 回测 #23 验证，收益+12%/回撤8%"，点击跳该回测
  · "最近回测"列直接显示战绩摘要，点击进 Run 页
  · 操作: [发起回测](主按钮) [编辑] [⋯→ 复制|删除]
  · 行点击 → 策略详情（只读概览 + 各区块）

编辑（**独立路由 /strategy/:id/edit**，非弹窗/抽屉——960px 抽屉装五节+DSL编辑器+锚点是在抽屉里重造页面，且丢浏览器后退/深链，盲审三修正；抽屉仅留给列表内微调）:
  ①基本信息: 名称/类型/启用
  ②信号定义: [DSL|Python] 切换（保留）
     DSL: 因子行(下拉带 tooltip 显示因子描述) + 权重 + 表达式编辑器(补全/校验)
     Python: PythonEditor(保留) + 校验
  ③参数定义: select 类型补选项编辑器；number 用 input-number 并校验 min<max
  ④执行规则: 仓位/价格/有效期（保留）
  ⑤账户绑定（保留，补: 未保存时禁用按钮的提示文案）
  底部常驻: [保存] [保存并回测] ← 关键新增
```

**要点**：
1. **保存并回测**把"策略→回测"从 5 步跨 3 页压缩为 1 步；回测表单预填本策略
2. **验证状态证据链**：✓ 可点回看验证回测——三级开关从黑箱变玻璃盒（配套：实盘任务下拉显示"未验证策略"灰项+原因 tooltip，而非静默过滤；标记验证按钮仅对 done run 可点，分钟因子因"日线回放"被拦截时给出解释）
3. **尊重既有领域建模**（06 差距审计确认）：策略是"配方"——**不放启停开关**（批次 3 已刻意移除，运行与否唯一入口=实盘任务）；`symbol:""` 是"配方不绑标的"契约而非 bug。补删除（confirm+FACTOR_IN_USE 保护提示）/复制（改名副本）
4. **快照隔离提示**：编辑已上线策略时提示"N 个运行中任务仍用旧配方快照，修改不生效于存量任务"——防止"改了以为生效"
5. DSL 编辑器是重点投资项：因子名补全 + 括号高亮 + 实时校验（后端 validate 已存在）
6. 执行规则文案方向感知：ALL_IN 显示为"BUY=全部资金 / SELL=清仓持仓"而非对称的"满仓"

**设计目标**：全站使用频率最高的页面，从"最薄的一页"变成信息最厚、自动化最高的一页。

```
│ 回测中心  [策略▾] [状态▾] [日期▾]        [+ 发起回测]           │
│ 运行中 1 · 今日 3 · 失败 1 (badge 摘要，running 5s 自动轮询)   │

│ #24 实盘测试    1年   1     并行  —      —     —    ⟳running 详情 终止│
│ （列表行直接给指标摘要——不用点进 Run 页才知道成绩；500 时给重试按钮+诊断链接）│
```
