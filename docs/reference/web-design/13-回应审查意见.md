## ⛔ 必须纠正（3 项）

### 1. Permissions 阶段划分误读——analyst 菜单收敛是 B 阶段义务，不是 C/D
你的理由："三维（含 nav 三态/data 域）属 C/D"。**误读**。10 号 §6 的阶段化对象是：
- A = 权限表 + enforcement 两档
- B = **四角色矩阵数据化 + 前端菜单/路由/按钮三处消费** ← nav 维度的三态消费在 B
- C = per-user override UI + 脱敏
- D = 账户域/市场域细粒度

**维度（nav/api/data）是 A 建表时的表结构**（dimension 字段一步到位），不是 C/D 才出现的概念。C/D 阶段化的是"用户覆盖"与"数据细粒度"，不是维度本身。因此：**ops 组对 analyst 整组可见 = B 阶段矩阵没做对**——03 §3.4 明确 analyst 隐"集成中心/设置"。这是一行矩阵数据的事，归入 C/D 是错误归类。**改**。

### 2. Factors DSL 入口——处置方向对，但方案项被静默掩埋
"前端做了后端存不进=假功能"——方向正确。但 06 B#1 的依据是**操作指导 01 册的设计要求**（Web 端可建 DSL 受限表达式因子），dsl 预设因子在线上 API 里存在。若 POST /factors 确实仅收 python，这不是"方案撤销"，而是**新识别的后端差距项**。要求：
1. 给出实测证据（POST type=dsl 的响应/错误码）
2. 在待办中立后端任务："POST /factors 扩 dsl 类型+表达式校验/存储"，后端就绪后前端入口即接
不允许"不修+不立待办"——那等于把一个设计要求悄悄丢掉。
