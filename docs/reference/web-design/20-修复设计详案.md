## 1. 批零 · P0 主流程抢修详案

### 1.1 策略 CRUD 恢复（弹窗复活路线）

**现状**：Strategy.vue 弹窗有完整实现但 openEdit(:343) 无调用；"编辑"跳 /strategy/:id/edit 白页；新建无 ID 输入被 :400 校验拦死；needs_daily/minute 被丢弃。

**步骤**：
1. 列表操作"编辑"改 `@click="openEdit(row)"`（复活现成实现）；编辑态弹窗内 ID 输入 `:disabled="true"`
2. 新建弹窗表单头部加 `el-input v-model="editForm.id" :placeholder="t('strategy.idHint')"`（仅 `!isEdit` 时显示）；后端 POST 契约 id 必填——校验保留，输入补齐
3. router 删除 `/strategy/:id/edit` 路由（及 StrategyEdit.vue 整文件——二期若做整页编辑再重建，不留烂尾壳）；Screener 等处若有深链一并清
4. `editForm.params.needs_daily / needs_minute` 双 checkbox 绑定，saveEdit 时随 params 序列化提交
5. i18n：新增 id 提示键 zh/en 双份

**验收断言**：新建（填 ID）→保存→列表出现；编辑→改因子权重→保存→重开值在；needs 勾选保存后 round-trip 不丢；操作指导 02 册逐步走通；`grep -c "strategy/:id/edit" router*` = 0。

### 1.2 验证门（"标记验证"死按钮）

**现状**：读不存在的 run.days/start_date → 90 天门槛恒真拦截。

**方案（后端派生，前端不再各自算）**：run 响应加派生字段 `span_days`（由 params 区间或 created_at→finished_at 计算，`routes/backtest.py` 序列化处单点）；前端门槛判断改：
```js
const gate = run.span_days >= 90 && (run.total_trades ?? 0) >= 10  // 阈值常量提至文件头注释
```
门槛未达标时按钮可点但弹说明（"区间 X 天/交易 Y 笔，未达 90 天/10 笔最低证据门槛"）——**可解释的拦，不是死按钮**。

**验收**：短区间 run 点标记→弹门槛说明；达标 done run→标记成功且策略列表 ✓ 出现。

### 1.3 回测成绩单（后端写入方+前端键归一）

**后端**：
- run 落 done 的位置（状态机切换处）计算并写 `summary_metrics`：`{total_return_pct, max_drawdown_pct, sharpe, win_rate, trade_count}`——从已有 metrics/trades 计算，一个函数单点
- `scripts/backfill_summary.py`：分批扫历史 done run 回填（LIMIT/OFFSET 或 id 游标，跑批窗口执行）

**前端**：新建 `utils/backtestSummary.js`：
```js
export const bs = (run) => {
  const m = run.summary_metrics || {}
  return { ret: m.total_return_pct ?? null, dd: m.max_drawdown_pct ?? null,
           sharpe: m.sharpe ?? null, win: m.win_rate ?? null, n: m.trade_count ?? run.total_trades ?? null }
}  // 旧数据 null → '—'，键名归一消灭三处（列表/策略页/首页）各自拼写
```

**验收**：新跑 run 列表出真实数字；回填后旧 run 有值；`grep -rn "total_return[^_]" web/src` = 0。
