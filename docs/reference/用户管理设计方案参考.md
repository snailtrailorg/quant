# 用户系统完整方案设计（邀请制版本）

## 1. 方案概述

本系统为邀请制注册模式，用户无法自行公开注册，须持有有效邀请码方可创建账户。系统基于 Vue 3 + Python Flask/Django + Pillow 技术栈实现。

**核心设计原则：**
- 邀请码为注册唯一入口，杜绝垃圾账号
- 用户角色在邀请时预设，注册后自动分配
- 头像支持自定义上传与默认卡通头像
- 管理员权限隔离，支持完整的用户生命周期管理


## 2. 技术选型

| 层级 | 工具/库 | 用途 |
| :--- | :--- | :--- |
| 前端框架 | Vue 3 | 页面渲染与组件管理 |
| 前端裁剪组件 | vue-cropper | 提供可视化裁剪框，用户拖拽选取头像区域 |
| 前端HTTP请求 | axios | 与后端API通信 |
| 后端框架 | Flask 或 Django | 提供RESTful API |
| 后端图像处理 | Pillow (PIL) | 缩放、裁剪、格式转换、质量压缩 |
| 认证方式 | JWT | 双Token机制（Access + Refresh） |
| 存储服务 | 本地文件系统 / OSS | 存储头像文件 |
| 数据库 | PostgreSQL / MySQL | 存储用户信息与邀请码记录 |

## 4. 注册与邀请流程

### 4.1 邀请码生成（管理员操作）

1. 管理员登录后台，进入"邀请码管理"页面
2. 填写生成参数：
    - 生成数量（如10个）
    - 预设角色（Trader/Analyst/Viewer，不可生成Admin角色邀请码）
    - 过期时间（可选，默认永不过期）
3. 系统批量生成邀请码，格式为随机8位字母数字组合
4. 管理员可复制或导出邀请码，通过邮件/内部系统发送给受邀用户
5. 邀请码存入 invitations 表，status = 0，关联 inviter_id

### 4.2 用户注册流程

1. 受邀用户访问注册页面，填写：
    - 邀请码（必填）
    - 用户名（4-20位字母数字，唯一）
    - 密码（8位以上，含大小写字母+数字）
    - 昵称（可选）
    - 邮箱（可选，如填写则需唯一）
    - 手机号（可选，如填写则需唯一）
2. 前端提交注册请求到 POST /api/auth/register
3. 后端校验流程：
    - 校验邀请码是否存在且 status = 0 且未过期
    - 校验用户名/邮箱/手机号唯一性
    - 密码进行 bcrypt 哈希
    - 创建用户，role = 邀请码预设的角色，status = 1（正常）
    - 记录 invited_by = inviter_id，invite_code_used = code
    - 更新邀请码：status = 1，used_by = 新用户ID，used_at = NOW()
4. 返回注册成功信息，用户自动跳转登录

### 4.3 邀请码状态流转图

```
管理员生成 → status=0（未使用）
↓ 用户注册使用
status=1（已使用）→ 不可再次使用
↓ 管理员撤销
status=2（已撤销）→ 不可使用（即使未使用）
```

## 6. 头像处理方案

### 6.1 默认卡通头像

- 使用 DiceBear API 在线生成：`https://api.dicebear.com/7.x/bottts/svg?seed={seed}`
- seed 使用 username 或 user_id 作为输入，保证同一用户始终显示相同头像
- 备选方案：本地预置12个PNG文件，存放于 /static/default-avatars/
- 兜底方案：CSS生成带背景色的用户首字母

### 6.2 自定义头像上传

- 前端使用 vue-cropper 裁剪为 1:1 正方形
- 文件大小限制：≤ 2MB
- 支持格式：JPG、PNG、GIF、WebP
- 后端使用 Pillow 生成三种尺寸：
    - 16x16（右上角图标）
    - 64x64（列表/个人中心）
    - 256x256（高清备份）

### 6.3 头像显示规范

| 使用场景 | 尺寸 | 说明 |
| :--- | :--- | :--- |
| 右上角导航栏 | 24x24 或 32x32 | 小尺寸，与昵称并列显示 |
| 用户管理列表 | 40x40 | 管理员后台列表 |
| 个人中心 | 64x64 | 用户详情展示 |
| 用户详情页 | 64x64 | 放大展示 |

### 6.4 头像更新缓存控制

- 每次更新头像时，avatar_updated_at 字段记录当前时间戳
- 头像URL添加查询参数：`/static/avatars/user_123.jpg?t=1700000000`
- 前端检测到 avatar_updated_at 变化时强制刷新图片

| 生成邀请码 | ✓ | ✗ | ✗ | ✗ |
| 查看邀请记录 | ✓ | ✗ | ✗ | ✗ |

### 7.2 权限约束规则

- **规则1**：Admin 可以修改其他用户的角色，但不能修改自己的角色
- **规则2**：Admin 不能将自己降级或删除自己（防止系统无管理员）
- **规则3**：生成的邀请码预设角色不能是 Admin（仅后台直接创建Admin账号）
- **规则4**：Viewer 是默认最低权限角色，不可删除该角色定义


## 8. 用户状态管理与状态机

### 8.1 状态定义

- **1 = 正常（active）** ：可正常登录使用
- **2 = 冻结（frozen）** ：管理员操作，无法登录，界面提示"账号已被冻结，请联系管理员"
- **3 = 注销（deactivated）** ：用户主动操作，不可登录

### 8.2 状态流转规则

```
注册成功 → 状态=1（正常）
状态=1 → 管理员操作 → 状态=2（冻结）
状态=2 → 管理员操作 → 状态=1（解冻）
状态=1 → 用户发起注销 → 状态=3（注销）
状态=3 → 不可逆（如需重新启用须管理员后台手动恢复）
```

### 8.3 注销账号数据处理

用户注销时触发以下操作：

1. 用户状态置为 3（注销）
2. 敏感信息脱敏：
    - username → username + "_deleted_" + 随机后缀
    - email → NULL
    - mobile → NULL
3. 头像处理：删除所有自定义头像文件，avatar_url 置为 NULL
4. 昵称保留不变（用于数据展示区分）
5. 操作日志保留（不删除）


## 9. 会话管理

### 9.1 Token 策略

- 使用 JWT 做身份认证
- Access Token 有效期：7天
- Refresh Token 有效期：30天
- Refresh Token 存储于 Redis，key: `refresh_token:{user_id}:{token_id}`
- 每次刷新时生成新的 Refresh Token，旧Token自动失效

### 9.2 JWT Payload 结构

``` json
{
"sub": 123,           // user_id
"username": "john_doe",
"role": "viewer",
"exp": 1700000000,
"iat": 1700000000,
"jti": "uuid"         // token唯一标识
}
```

### 9.3 登录限制（可选）

- 同一用户同一时间可配置只允许一个有效会话（可选功能）
- 新登录时，将旧 Refresh Token 加入黑名单
- 黑名单存于Redis，有效期至Token过期

## 12. 前端核心组件设计

### 12.1 头像组件 Avatar.vue

**功能**：统一管理所有页面的头像显示

**Props：**
- `user`: Object `{ id, username, avatarUrl }`
- `size`: String (`'sm'` | `'md'` | `'lg'`)
- `showName`: Boolean
- `namePosition`: String (`'right'` | `'bottom'` | `'left'`)

**核心逻辑：**
- 计算属性 `displayAvatar`：user.avatarUrl 有值则返回自定义URL，否则调用 getDefaultAvatar(user.id)
- 计算属性 `displaySize`：sm=24px, md=40px, lg=64px
- 图片加载失败时，显示基于 username 首字母的CSS备用头像

### 12.2 头像上传弹窗 AvatarUpload.vue

**模板结构：**

``` html
<el-dialog title="更换头像" v-model="dialogVisible">
  <!-- 图片选择 -->
<input type="file" accept="image/*" @change="handleFileChange" />
  <!-- 裁剪区域 -->
<vue-cropper
ref="cropper"
:img="uploadImage"
:autoCrop="true"
:fixedNumber="[1, 1]"
:centerBox="true"
:highQuality="true"
:info="false"
outputType="png"
/>
  <!-- 操作按钮 -->
<el-button @click="confirmCrop">确认裁剪</el-button>
<el-button @click="reset">重新选择</el-button>
<el-button @click="dialogVisible = false">取消</el-button>
  <!-- 预览区域 -->
  <div class="preview">
    <img :src="previewUrl" alt="预览" />
  </div>
</el-dialog>
```

**关键方法：**

``` javascript
handleFileChange(event) {
const file = event.target.files[0];
if (!file) return;
// 校验文件大小
if (file.size > 2 * 1024 * 1024) {
this.$message.error('图片大小不能超过 2MB');
return;
}
// 校验文件类型
if (!['image/jpeg', 'image/png', 'image/gif', 'image/webp'].includes(file.type)) {
this.$message.error('仅支持 JPG、PNG、GIF、WebP 格式');
return;
}
// 读取为DataURL
const reader = new FileReader();
reader.onload = (e) => {
this.uploadImage = e.target.result;
this.dialogVisible = true;
};
reader.readAsDataURL(file);
}

confirmCrop() {
this.$refs.cropper.getCropData((data) => {
this.uploadAvatar(data);
});
}

async uploadAvatar(base64Data) {
try {
const response = await axios.post('/api/user/avatar', {
avatar_base64: base64Data
});
this.$message.success('头像上传成功');
this.dialogVisible = false;
this.$emit('avatar-updated', response.data.data.avatar_url);
} catch (error) {
this.$message.error(error.response?.data?.message || '上传失败，请重试');
}
}
```

## 13. 默认头像实现方案

### 13.1 主方案：DiceBear API（在线生成）

``` javascript
// utils/getDefaultAvatar.js
const DICE_BEAR_STYLES = ['bottts', 'avataa', 'thumbs', 'gridy'];

export function getDefaultAvatar(userId, username, style = 'bottts') {
const seed = username || String(userId);
// 根据用户ID确定性选择风格，增加多样性
const hash = hashCode(seed);
const styleIndex = Math.abs(hash) % DICE_BEAR_STYLES.length;
const selectedStyle = DICE_BEAR_STYLES[styleIndex];
return `https://api.dicebear.com/7.x/${selectedStyle}/svg?seed=${encodeURIComponent(seed)}`;
}

function hashCode(str) {
let hash = 0;
for (let i = 0; i < str.length; i++) {
hash = ((hash << 5) - hash) + str.charCodeAt(i);
hash |= 0;
}
return hash;
}
```

### 13.2 备选方案：本地预置PNG

- 准备24个卡通角色PNG，按尺寸分类存储
- 目录结构：

```

default_01.png ~ default_24.png
md/     # 40x40
default_01.png ~ default_24.png
lg/     # 64x64
default_01.png ~ default_24.png
```

- 选择逻辑：hash(userId) % 24 + 1

### 13.3 兜底方案：CSS字母头像

``` html
<div class="fallback-avatar" :style="{ backgroundColor: getColor(username) }">
  {{ getInitial(username) }}
</div>
```

``` javascript
function getColor(str) {
const colors = ['#FF6B6B', '#4ECDC4', '#45B7D1', '#96CEB4', '#FFEAA7', '#DDA0DD', '#FF8A5C', '#A29BFE'];
return colors[Math.abs(hashCode(str)) % colors.length];
}
function getInitial(str) {
return str ? str.charAt(0).toUpperCase() : '?';
}
```

## 15. 安全措施清单

### 15.1 密码安全

- 使用 bcrypt 哈希，salt rounds = 12
- 密码长度最少8位，至少包含大小写字母和数字
- 旧密码修改时必须校验

### 15.2 会话安全

- JWT存储在 HttpOnly Cookie 或 localStorage（需考虑XSS防护）
- Refresh Token 存储在 HttpOnly Cookie 中（推荐）
- 每次请求校验 JWT 签名和过期时间
- Token 黑名单机制（退出登录时销毁）

### 15.3 文件上传安全

- 前端限制文件类型和大小
- 后端二次校验：MIME类型、文件大小、图片宽高
- 文件名使用 user_id + timestamp + UUID，禁止使用原始文件名
- 头像存储目录禁止执行脚本（如 .htaccess 或 nginx配置）

### 15.4 权限安全

- 所有 /admin/* 路由前置中间件校验 role == 'admin'
- 管理员修改用户角色时校验：target.id != current_admin.id
- 管理员不能生成 role='admin' 的邀请码
- 敏感操作记录审计日志

### 15.5 输入校验

- 用户名：4-20位，仅允许字母、数字、下划线
- 邮箱：标准邮箱格式正则
- 手机号：E.164格式（+区号+号码）
- 昵称：1-20位，支持中文、英文、数字
