## B. 每日连接窗

### 目标
XTP/A 股日窗:默认 **9:05 建连**(锚 9:15 集合竞价,lead 10min)/**15:10 断开**(锚 15:00 收盘,lag 10min),午休 11:30-13:00 不断;盘中保活/反应式自愈**全部保留**(双层:盘外预防+盘中反应)。加密市场不适用(键 xtp_ 前缀即隔离)。

### 产出(限定范围)
- 配置:`system_config` 两键 `xtp_session_lead_min`(默认 10)/`xtp_session_lag_min`(默认 10),**0=禁用日窗**(永久连接,旧行为逃生门);读取走 get_param 族(缓存友好)
- MD 侧 `strategy_framework/md_session.py`+`runtime/mdlink.py`:RENEW_HM 硬编码 (9,10) → 由 lead 配置推导(9:15−lead);新增盘后断开(15:00+lag 后 supervisor 判定→官方序列 Logout→停 MD,窗关态阻止反应式重连;次日窗开恢复)。**租约 fencing 不动**(启动仍抢租约,窗只管 MD 会话)
- TD 侧(hub 模式 worker):`strategy_runner/main.py` hub 模式段 ThinTdGateway 连接套同窗(窗开 connect/窗关 logout);direct 模式不动(6b 退役)
- 心跳 schema 不动(断开期进程心跳照写;断流告警已时段作用域盘外静默)
- 附带收益:15:10 后发布→hub 启动即窗关态不连 MD(发布让位 30s 空窗的体验改善,租约语义不变)

### 已知边界(评审必读)
- **交易日历(用户提醒,08-28 补)**:窗的"当日是否交易日"判定复用 `md_session.is_trading_day`,但**失败语义 fail-open 到自然日**——本体加可选参 `fail_open=True`(读日历失败→当交易日→连,错误方向=白连无害;绝不漏连真交易日)。本体默认 False 不动(续航窗现有回退=工作日,现状保持)。**窗沿判定走 supervisor.tick 每步轮询(5s 定时器)**,非一次性判定——日历盘中修复/配置变更最迟次日生效(与本体缓存口径一致)
- 15:01 收盘根 flush(15:01:05-30)先于 15:10 断开 ✓;TD 收盘回报即刻,15:10 足够
- 9:05 建连失败→L2 反应式自愈兜底(重试+告警),与现状等价
- 窗关期间 hub 心跳照写(8 字段,进程级);latest_tick TTL 65s 自然过期→详情页降级腾讯源(既有设计)
- 周一验证:9:05-9:15 建连日志属本批;09:31 首根/TD 终证属批 6a——验证清单分项不混淆

### 验收

## 双盲审修订(08-28 傍晚,A/B 双同"需修后进")
- **B-P0 单原语互锁**:窗开沿建连**不做独立 connect**,复用 `schedule_due→renew→relogin`(relogin 在 CREATED 态=直登,g md_api_guard.py:107-118 已证)——单原语无双跑;`_renewed_date` 当日去重天然置位,重演 08-25 churn 的路径消失
- **A-P1-2/B-P0 冷态**:guard.connect 加 `defer_login` 参数(窗关期启动只 createQuoteApi→CREATED,不 login)——保证 relogin 永不遇 IDLE 态抛错;hub main 启动套窗(窗开=完整 connect/窗关=defer)
- **TD 分级(工程决策)**:XtpTdApi 无 logout,断开只能 close=exit(C 销毁)——TD 无 guard、exit 循环无实证(SEGV 风险区)。本批 TD 只做①启动套窗(窗关期启动不 connect)②窗开沿 connect(幂等 if not connect_status);**盘后 TD 不断开**(闲置=现状非回归)。MD 侧完整窗(建+断)。TD 断开二期观察 MD 效果后再定
- **B-P1-1 启动对账条件化**:worker 启动序列 `_reconcile()` 在 TD 未连(窗关启动)时跳过,窗开沿 connect 后由 `_td_reconnect` 沿触发 reconcile(既有路径)
- **B-P1-2 窗开失败告警**:当日首次建连(renew)未确认时 alert 一次(既有 _alert 通道)——补"9:05-9:31 零告警"洞(反应式被 in_session=False 灭是常态,不可依赖)
- **A-P1-3 哨兵定义**:任一键=0 → 日窗禁用(永久连接,旧行为);lead/lag 域 [1,600] 分钟,越界钳 600
- **日历(用户终裁 08-28,推翻 A 补充点①零改动建议)**:`is_trading_day` 失败回退 weekday<5 → **True(自然日)**——weekday 计算自身是新故障源(时区/时钟错→判错日→漏连);fail-open 到自然日后该故障点消失,错误方向统一"白连无害"。影响面=仅日历读取失败场景(DB 挂),正常时日历表照常生效;zombie/续航等既有调用方语义随之统一
- **配置读取(B-P2-1)**:main 层启动读一次 system_config(裸 SQL,与 md_mode 同式)传纯参给 session/TD——session 层零 DB 依赖,层次不破;改动重启生效(文档注明)
- **B-P2-4 多任务同刻风暴**:现状单任务不加抖动,任务文件记"多任务时窗开沿加抖动"
- 验收增:窗开沿 relogin 后 `schedule_due` 当日假(互锁断言)/CREATED 态 relogin 直登/R4 于断开后 10min 静默(周二验)/15:00 整分钟窗仍开(防误用 in_session)/TD 窗套单测/lead 越界钳制
