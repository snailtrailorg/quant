# 多账号源 D1 · 权限模型与数据字段化（详细设计）

> 上级：`docs/architecture/31-多账号源架构设计.md` §三/§四/§五契约4·5。状态：详细设计（待双盲审）。
> 方法：先框架后详细；本件是 D1，自包含 8 字段。

## 一、目标

把四维权限（category/exchange/board/ST）从「代码前缀判断」迁到「数据字段」，补 venue 侧权限存储，产出 `venue_allows(venue_id, symbol) -> bool` 供三级时点（建任务拒绝/worker 启动 fail-fast/下单前拦截）调用。

## 二、现状（已核实，file:line）

- `security_master`：有 `category` 列（stock/etf/convertible/fund/reits/…）、`market` 列；**无 `board` 列、无 `exchange` 列**（`security_master.py:72` SELECT 列清单）。exchange（沪 shse/深 szse/北 bse）可从 vt_symbol 后缀（SHSE/SZSE/BSE）可靠提取，非前缀判断——但为单一真源仍落 `exchange` 枚举列。
- 前缀判断三函数算三维度：`security_master.py:246 _board_of`（板块，仅被竞价/时段调用）、`risk.py:175 _market_of`（分项 market_op，check_order gate）、`factor.py:719 detect_category`（品类，因子路径）——三者非同一维度，本次只退役 `_board_of`/`detect_category`。
- Tushare 板块中文文本落 `asset_static_info.market`（`data_sync/engine.py:456/462`，值=主板/创业板/科创板/北交所/CDR）。
- `security_state`：`(vt_symbol, effective_from, kind, value)`，`kind='st'` 由 namechange 曾用名派生（`engine.py:1070/1133`，戴帽/摘帽滞后）。
- 权限现状：market_op 五键（`perm_registry.py:56` = convertible/etf/astock/binance_perp/okx_perp），无 board 维度、无 per-venue 维度。

## 三、设计决策（已裁定 2026-09-23）

### D1-1 board/exchange 字段化：新增枚举列（否决复用 market 列）
- **✅ 新增 `security_master.board` 枚举列**（main/star/chinext/bse），从 `asset_static_info.market` 中文文本归一化回填（主板→main / 创业板→chinext / 科创板→star / 北交所→bse / CDR→star）。
- **✅ 新增 `security_master.exchange` 枚举列**（shse/szse/bse，股东户维度），回填从 vt_symbol 后缀（SHSE/SZSE/BSE）提取——后缀可靠非前缀判断。board=main 横跨沪/深，需 exchange 兜底细分（venue 有沪股东户无深股东户时，只放行沪主板）。
- 理由（board）：「market」名在本仓三语义（`security_master.market`=astock|crypto / `asset_static_info.market`=中文板块 / `external_interface.market`=astock|crypto），当键有漂移风险；枚举列单一真源，消费方（`venue_allows`/涨跌停 `band_rules`）直接取枚举。理由（exchange）：股东户是独立于板块的维度（标准开户给沪/深一对，但可能只开一方），board=main 单维度分不出沪/深。

### D1-2 venue 侧权限存储：新表（否决加列/扩 live_trading_config）
- **✅ 新表 `venue_permission`**（venue_id FK → 允许 category 集合 + **允许 exchange 集合（shse/szse/bse，股东户维度）** + 允许 board 集合 + is_st 允许 + convertible 权限 + perp 分项）。
- 理由：权限是「账号×交易所×品种×板块」关系、集合型，天然独立关系表；与 `capabilities`（能力=代码真源）语义不同不该混；`live_trading_config` 是 RBAC role 级下单卡口，维度都不对。

### D1-3 is_st 真源
- **✅ `security_state.kind='st'` 改官方名单（交易所公告）**，失效兜底 fail-closed（无档视为「需人工确认」，宁拒勿错下）。现曾用名派生保留作滞后兜底并标注。

## 四、契约

- `venue_allows(venue_id: int, symbol: str) -> bool`：判定顺序 **category → exchange → board → ST → 分项**（etf/fund/reits 跳过 exchange+board；convertible→可转债权限；perp→加密分项 gate）。**方向语义：③下单前拦截时点仅拦 BUY/开仓，SELL/减仓完全豁免**（ST/board/强赎/退市是准入维度非退出维度，对齐 risk.py F-31 先例——否则持仓戴帽/强赎后被锁死无法止损）。①建任务/②启动两时点非方向性，不适用豁免。
- **board↔exchange 一致性约束**：board=star 必属 shse、chinext 必属 szse、bse 必属北交（board=main 横跨沪/深，需 exchange 兜底细分）。venue_permission 允许 board=star 但 exchange 集合不含 shse = 矛盾配置，`venue_allows` 校验 fail-closed（宁拒勿错）。
- category 填充现状：`etf_basic_info` 回填全标 category='etf'，无 fund/reits 行——venue_permission 的「允许 category 集合」若含 fund/reits 将永不命中（LOF/封基/REITs 全是 'etf'）。本件判定只认 etf；fund/reits 数据填充归属另批，不在 D1。
- 数据列：`security_master.board` + `security_master.exchange`（枚举，归一化回填）；`security_state.kind` 扩 `st`/`forced_redeem`/`delist_phase`（强赎/退市整理期，见 31 号 §四）。
- 三级时点接入位：建任务拒绝（`web_api` 建任务端点）、worker 启动 fail-fast（`strategy_runner` 启动）、下单前拦截（`risk_control.check_order` 前置）。

## 五、限定范围

只做：`security_master` 加 board + exchange 列 + 回填迁移、`venue_permission` 表（含 exchange 维度）+ 读写、`venue_allows` 函数、三级时点接入调用、退役 `_board_of`/`detect_category` 前缀判断（迁移到读 board/category 列）。**`_market_of`（分项 market_op 五键）不退役**——是分项维度非板块维度，其替换映射（category 分组→分项 + perp→venue.provider）不在本件。
不碰：D2（venue_id 锚点/快照多行化）、D3（流协议）、D4（金融面）、D5（TD 网关）、D6（hub 部署）。

## 六、验收标准（编码阶段定，行为级）

- 迁移 upgrade/downgrade 双向绿（加 board + exchange 列 + 回填 + venue_permission 建表）。
- `venue_allows` 覆盖：主板创业板权限错配拒绝、**沪/深股东户错配拒绝（venue 无深股东户拒深主板/创业板）**、ETF 跳过 exchange+board、可转债无权限拒绝、ST 拒绝、CDR→star。
- 退役后 `_board_of`/`detect_category` 不再被权限/订单闸路径调用（grep 断言）。
- `pytest tests/ -q` 全绿 + 分层绿 + pyflakes 零新增。
