# 多账号源 D1 · 权限模型与数据字段化（详细设计）

> 上级：`docs/architecture/31-多账号源架构设计.md` §三/§四/§五契约4·5。状态：详细设计（待双盲审）。
> 方法：先框架后详细；本件是 D1，自包含 8 字段。

## 一、目标

把三维权限（category/board/ST）从「代码前缀判断」迁到「数据字段」，补 venue 侧权限存储，产出 `venue_allows(venue_id, symbol) -> bool` 供三级时点（建任务拒绝/worker 启动 fail-fast/下单前拦截）调用。

## 二、现状（已核实，file:line）

- `security_master`：有 `category` 列（stock/etf/convertible/fund/reits/…）、`market` 列；**无 `board` 列**（`security_master.py:72` SELECT 列清单）。
- 板块前缀判断散布 4 路径：`security_master.py:246 _board_of(vt_symbol)`、`risk.py:175 _market_of`、`factor.py:719 detect_category`（权限/订单闸/因子/竞价）。
- Tushare 板块中文文本落 `asset_static_info.market`（`data_sync/engine.py:456/462`，值=主板/创业板/科创板/北交所/CDR）。
- `security_state`：`(vt_symbol, effective_from, kind, value)`，`kind='st'` 由 namechange 曾用名派生（`engine.py:1070/1133`，戴帽/摘帽滞后）。
- 权限现状：market_op 五键（`perm_registry.py:56` = convertible/etf/astock/binance_perp/okx_perp），无 board 维度、无 per-venue 维度。

## 三、设计决策（已裁定 2026-09-23）

### D1-1 board 真源：新增枚举列（否决复用 market 列）
- **✅ 新增 `security_master.board` 枚举列**（main/star/chinext/bse），从 `asset_static_info.market` 中文文本归一化回填（主板→main / 创业板→chinext / 科创板→star / 北交所→bse / CDR→star）。
- 理由：market 是中文文本非枚举，且「market」名在本仓已双语义（顶层 astock/crypto + 板块），当键有漂移风险；枚举列单一真源，消费方（`venue_allows`/涨跌停 `band_rules`）直接取枚举。

### D1-2 venue 侧权限存储：新表（否决加列/扩 live_trading_config）
- **✅ 新表 `venue_permission`**（venue_id FK → 允许 category 集合 + board 集合 + is_st 允许 + convertible 权限 + perp 分项）。
- 理由：权限是「账号×品种×板块」关系、集合型，天然独立关系表；与 `capabilities`（能力=代码真源）语义不同不该混；`live_trading_config` 是 RBAC role 级下单卡口，维度都不对。

### D1-3 is_st 真源
- **✅ `security_state.kind='st'` 改官方名单（交易所公告）**，失效兜底 fail-closed（无档视为「需人工确认」，宁拒勿错下）。现曾用名派生保留作滞后兜底并标注。

## 四、契约

- `venue_allows(venue_id: int, symbol: str) -> bool`：判定顺序 **category → board → ST → 分项**（etf/fund/reits 跳过 board；convertible→可转债权限；perp→加密分项 gate）。
- 数据列：`security_master.board`（枚举，归一化回填）；`security_state.kind` 扩 `st`/`forced_redeem`/`delist_phase`（强赎/退市整理期，见 31 号 §四）。
- 三级时点接入位：建任务拒绝（`web_api` 建任务端点）、worker 启动 fail-fast（`strategy_runner` 启动）、下单前拦截（`risk_control.check_order` 前置）。

## 五、限定范围

只做：`security_master` 加 board 列 + 回填迁移、`venue_permission` 表 + 读写、`venue_allows` 函数、三级时点接入调用、退役 `_board_of`/`detect_category` 前缀判断（迁移到读 board/category 列）。
不碰：D2（venue_id 锚点/快照多行化）、D3（流协议）、D4（金融面）、D5（TD 网关）、D6（hub 部署）。

## 六、验收标准（编码阶段定，行为级）

- 迁移 upgrade/downgrade 双向绿（加 board 列 + 回填 + venue_permission 建表）。
- `venue_allows` 覆盖：主板创业板权限错配拒绝、ETF 跳过 board、可转债无权限拒绝、ST 拒绝、CDR→star。
- 退役后 `_board_of`/`detect_category` 不再被权限/订单闸路径调用（grep 断言）。
- `pytest tests/ -q` 全绿 + 分层绿 + pyflakes 零新增。
