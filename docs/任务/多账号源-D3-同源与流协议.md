# 多账号源 D3 · 同源与流协议（详细设计）

> 上级：`docs/architecture/31-多账号源架构设计.md` §二·2.2/2.3/§五契约2·3。状态：详细设计（待双盲审）。

## 一、目标

钉死 A股「MD 单 hub + TD per-venue」、加密「MD+TD per-venue」的流键、同源运行时校验、加密历史暖机 per-venue，防止「吃错行情→信号错→下错单」。

## 二、现状（已核实）

- A股 MD 单 hub：流键 `hub:bars:{symbol}`，无 venue 维度（`md_hub` 单活双实例，doc14 M5 + 批60 M5 协议）。
- 加密尚无 per-venue hub（多账号源未落地前是单实例）。
- 历史暖机：worker 读 PG bar_1min 全局表（A股 market-wide 无同源问题；加密若 per-venue 后仍是全局表=币安数据喂 OKX 任务）。

## 三、设计决策

- **无首决**。方向在 31 号 §2.2 已定（A股单hub/加密per-venue），本件是把方向落成流协议契约。

## 四、契约

- 流键：A股 `hub:bars:{symbol}`（单 hub，无 venue 维度）；加密 `hub:bars:{venue_id}:{symbol}`（per-venue）。
- 心跳/租约：A股 `quant:hb:md-hub` / `hub:lease`；加密 `quant:hb:md-hub:{venue_id}` / `hub:lease:{venue_id}`。
- **同源运行时校验**（per-venue 流）：hub 写流带 `"venue_id"` 字段；worker `int(fields["venue_id"]) == venue.id`（decode_responses 读出是 str，须 int 转换 + try/except fail-fast，否则每条 bar 误判跨源 exit 78）。
- **加密历史暖机 per-venue**：历史 bar 数据源按 venue 分源（与实时流同源），暖机/回放取本 venue 数据，不吃别的 venue。

## 五、限定范围

只做：加密 per-venue 流键、同源运行时校验（venue_id 字段 + worker 比对）、加密历史暖机 per-venue。
不碰：D1（权限）、D2（身份/快照）、D4（金融面）、D5（TD 网关）、D6（hub 部署拓扑——本件只钉「键格式」，实例生命周期归 D6）。

## 六、验收标准（编码阶段定，行为级）

- 加密双 venue：worker A 只消费 `hub:bars:{A}:{symbol}`，收到 venue_id=B 的消息 fail-fast（不落地）。
- A股单 hub：流键无 venue 维度、worker 不做 venue_id 比对。
- 加密历史暖机：币安 venue 的暖机数据不喂 OKX venue。
