## 1. 背景（实证摘要）

- web-api 启动即载 pandas+numpy：`sys.meta_path` spy 实证唯一载体 `main.py:94 → routes/stock.py:6`，全部用途为 K 线路由两个 `pd.notna()`（stock.py:142-144）。本地实测 import pandas RSS +57MB（64292 vs 7280 KB）。
- K 线路由本质「SQL 行 → JSON records」，现状绕道 `fetchall → DataFrame → to_numeric 逐列 → to_dict("records")`——pandas 纯搬运工。
- `iterrows()` ×14（grep 实数）：每行构造 Series，比 `to_dict("records")` 慢 5-10× 且费内存。
- worker 无 `--max-tasks-per-child`：大任务峰值后 RSS 高水位永久驻留（Python arena 不还 OS）。

## 2. 改动清单

### A · P1 web-api 去 pandas（2 文件）

**A1 `server/src/data_platform/db.py` 新增 `get_kline_records`**（紧邻 `get_bars` 后）：

```python
def get_kline_records(symbol: str, freq: str, start, end) -> list[dict]:
    """K 线 records 直查（零 pandas）——web-api 常驻不载 pandas 的关键路径（批10）。

    get_bars 的 DataFrame 版面向分析/回测；K 线图表只要 JSON records，
    DataFrame 往返是纯常驻开销（+57MB）。语义对齐 BAR_TABLE_SELECT（ORDER BY ts ASC）。
    """
    assert freq.lower() in _VALID_FREQS, f"非法 freq: {freq}"   # 盲审 A/B 同判：对齐 save_bars 写路径标准
    ensure_table(freq)
    with get_conn() as conn:
        with conn.cursor() as cur:
            cur.execute(
                "SELECT ts, open, high, low, close, volume FROM bar_{freq} "
                "WHERE symbol=%s AND ts >= %s AND ts <= %s ORDER BY ts ASC".format(freq=freq),
                (symbol, start, end))
            rows = cur.fetchall()
    def _num(v):
        return float(v) if v is not None and not v.is_nan() else None   # Decimal('NaN')→None（盲审同判）
    out = []
    for r in rows:
        out.append({
            "ts": r[0].strftime("%Y-%m-%d") if r[0] is not None else None,
            "open": _num(r[1]), "high": _num(r[2]), "low": _num(r[3]),
            "close": _num(r[4]), "volume": _num(r[5]),
        })
    return out
```

要点（v2 双盲审修订）：
- ①`assert freq.lower() in _VALID_FREQS` 在前——**ensure_table 只是 to_regclass 存在性探测+告警放行，不构成注入屏障**；本函数是 web 层公开可达的新入口，标准须对齐同文件写路径 save_bars（`assert freq.lower() in _VALID_FREQS`）。freq 现由路由字面量 "1D" 传入。
- ②`_num` 防 `Decimal('NaN')`：PG numeric 可存 NaN，现状 DataFrame 路径 `to_numeric→pd.notna=False→None`，裸 `float(Decimal('NaN'))` 会向 FastAPI 产出非法 JSON `NaN` 字面量（前端 JSON.parse 崩）。`Decimal.is_nan()` 一行防御对齐现状语义（写入路径 `_safe_float` 已兜底，此为边缘防御）。
- ③ts 类型链（盲审 A 核实）：`bar_1d.ts = DateTime(timezone=True)`（迁移 0001）+ 连接 pin `TimeZone=Asia/Shanghai`（db.py）→ psycopg 返回 aware datetime → `strftime('%Y-%m-%d')` 与现状 `pd.to_datetime→strftime` 同日历日，等价成立。
- ④列只取 6 列（K 线图表不需要 symbol/freq/amount/adj_factor/source）；`ORDER BY ts ASC` 走 `idx_bar_1d_symbol_ts(symbol, ts DESC)` 反向扫无性能回归；空结果返回 `[]` 对齐现状。
- ⑤`Decimal→float` 与 get_bars 的 `to_numeric`→float64 目标一致。

边界备注（代码盲审 A P2-5/B P3-5 在案）：等价性隐含「df 含 str 列或循环体 float() 化」前提——
纯数值 int64 列上 iterrows 会把 int 提升为 np.float64 而 to_dict 保 int，`str()` 落库会得 `'1.0'` vs `'1'`。
本批 14 处均不可达（tushare 返回必带 ts_code/trade_date 等 str 列；trade_cal int64 走显式 int()）。

兼容性核对（双盲审 A/B 逐处独立核实**全部通过**）：`.get()`/`[]`/`.items()`（pool_data raw_json）dict 同形 ✓；`pd.notna` 作用于两形态标量均兼容 ✓；NaN truthiness 两形态同 quirk 不新增 ✓；本地 venv 实验实证混合 dtype df 上 `to_dict("records")` 与 iterrows 元素类型**完全一致**（int64→int、float64→float、datetime64→Timestamp、object None 保持）✓。

### C · P2-b worker 高水位回收（1 单元）

`server/scripts/systemd/quant-celery-worker@.service` ExecStart 追加 ` --max-tasks-per-child=100`：
- prefork 语义（双盲审核实）：任务**完成计数**后回收、不打断执行中任务。
- **暖状态边界（盲审 A P1 修订，v2 论断）**：父进程 import 期加载的模块不重付（fork 继承）；但批 9 lazy 化后重库（pandas/tushare）恰是**任务函数内函数级 import，发生在子进程内**并跨任务常驻——`tushare_adapter._pro`（进程缓存）与 `db._engine`（连接池）同理。回收后新子进程首个 data 类任务要重付 pandas+tushare import（~1-2s）+DB 连接+pro 客户端重建。
- **回收频率核算**：beat 密度（risk_sweep 60s + email_outbox 60s + crypto 900s + sync_scheduler 300s）≈ 每分钟 2-3 任务、worker_concurrency=2 → 每子进程约 **90 分钟**攒满 100 任务。回收损失秒级——可行。
  - **解读要点（代码盲审 A P2-3/4）**：worker@ 的 -Q 含 risk 且无显式 -c（默认=CPU 核数），risk 队列双消费者分流 + 核数漂移都会改变实际回收频率——**观察日按实测回收间隔解读，勿按预算推**；预期上限 ~45-60 分钟一次回收。
- **观察日预期（防误判回滚）**：上产后 data 类任务**偶发慢 1-2s 属本改动预期行为**，非回归。
- `quant-celery-risk@`（轻任务，已配 `MemoryMax=512M` 兜底）与 beat 不动。
- **挂账（盲审 B）**：`--max-tasks-per-child` 对「单个大任务吃 1.5G 峰值」无效（攒不齐 100 任务回收不发生）——`--max-memory-per-child` 更对症；且 worker@ **无 MemoryMax** 与 risk@ 不对称。另立待办评估（OOM 杀 vs Restart 对数据同步任务的语义）。

### 不做项（理由在案）

- **P3 get_bars to_numeric 逐列循环**：剩余消费者（分析/回测/strategy_runner）要 DataFrame，to_numeric 是 Decimal→float64 正确性转换非浪费主体，收益微小，避免无谓改动面。
- **KSM/prefork 跨单元共享**：对 Python 负载性价比低（审查报告附录结论）。
