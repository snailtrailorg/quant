# 批13 · 钉钉/企微接入（平台页签 + 双 Provider 实现）v2

> 任务基线：只读本文 + `docs/architecture/19-IM统一接入设计.md` + `docs/architecture/模块契约/im_bot.md`。
> 协议核实依据：`docs/reference/IM扫码中级方案.md` 核实附录（2026-09-10 源码级核实）+ `docs/reference/企微智能机器人协议参考.md`（帧协议全表）。
> 用户裁定（2026-09-10）：①平台=页签，页签存在与否看动态注册；②页签内容由注册信息动态生成；③自助向导飞书只支持扫码（form 方式砍除），钉钉/企微手填凭证。
> **v2 = 方案双盲审 A/B 全吸收**（A：P0×3+P1×6+P2×9；B：P0×1+P1×4+P2×8；三条独立同判：route_key/企微 send_text 桩/页签状态机接线）。

## 1. 目标与范围

**目标**：钉钉、企业微信两个新平台全链接入——Provider 注册 → 表单建 bot → pool 子进程长连接 → 收消息 → 身份绑定 → LLM 会话（读类工具+文本回复）。

**范围外**（后续批）：
- 告警分发（alert_notify）到钉钉/企微——企微跨进程推送通道+chatid 留存设计归告警批（B-P1-1/A-P1-2 裁定）
- 操作类工具卡片确认（钉钉 ActionCard/企微模板卡片）——本批降级文本拒答
- 企微流式回复多帧打字机/媒体上传/文件解密、msgid 去重——MVP 单帧 finish=true；去重挂账（与飞书现状平齐）
- 企微私有部署自定义 ws 地址；三平台"统一二维码"（已证伪）

## 2. 设计

### 2.1 注册层（后端）

| Provider | MODE | ONBOARDING_METHODS | FIELD_SCHEMA |
|---|---|---|---|
| feishu（改） | hybrid | `{qr: interactive}`（**form 条目删除**——裁定A，自助向导扫码唯一路径） | 不变（admin 编辑面继续渲染，零迁移） |
| dingtalk（新·批13A） | websocket | `{form: manual}` | `app_key`(text) + `app_secret`(secret) |
| wecom（新·批13B） | websocket | `{form: manual}` | `bot_id`(text) + `secret`(secret) |

- **wecom Provider 批13A 不注册**（A-P1-4：避免"可建可启但 pool skip"的静默死 bot——页签注册驱动，不注册页签自然不出现，13B 随实现一起上）。
- **registry 引导改遍历**（A-P1-1）：`base.py` 的 `get_im_provider`/`list_providers` 引导从单 import feishu 改为遍历 import 已安装 Provider 模块（feishu/dingtalk/wecom 显式名单，import 失败 log skip 不炸——13B 未实现时自然跳过）。`test_layering.py` 同步登记 runners/wecom_ws/handlers 模块。
- admin 面 ImBots.vue 的飞书表单=FIELD_SCHEMA 凭证录入（不依赖 ONBOARDING_METHODS），**保留**——裁定③语义=自助向导单方式，admin 凭证管理不受限（B-P2-7 明示）。

**route_key 单点推导（P0，A-P0-2/B-P0-1 双判）**：现三处硬编码白名单 `app_id/client_id/corp_id`（`im_bots.py:52` admin 建、`im_bots.py:357` 自助建、`credentials.py:46` 凭证补录）——钉钉 `app_key`/企微 `bot_id` 不在名单→route 恒空→第二只 bot 撞 `uq_imbot_provider_route` 唯一索引（迁移 0051）+补录把存量非空 route 改写为空。修法：三处收口单点函数 `im_bot/routing.py: route_key_from(provider, creds)`，字段名单扩展 `app_key`/`bot_id`；企微凭证键 `bot_id`（str）与平台 bot id（int）在函数内不混淆（键名查 creds dict）。测试断言：同平台两只 bot 可建+补录不丢 route_key。

### 2.2 消息通道层

**钉钉 runner**（`im_bot/runners/dingtalk.py`）：
- 官方 SDK `dingtalk-stream`（requirements 显式 pin；同显式 pin `websockets`——B-P2-4 传递依赖不自显）。
- **凭证预检 fail-fast（P0，A-P0-3）**：SDK `start()` 主循环 `except Exception` 无限重试不退出——凭证错=僵尸子进程（pool 退避挂在进程退出上永不触发）。runner 起 SDK 前先拉 accessToken（复用 test_connection 逻辑），失败即 `SystemExit(1)` 交 pool 退避。
- Handler 用 SDK 自带 `AsyncChatbotHandler`（A-P2-9：内置 ThreadPoolExecutor(8)+立即 ACK，天然满足"起线程不阻塞"）；`process()` 解析 `ChatbotMessage` → `handle_incoming` → `self.reply_text()`（sessionWebhook 同步 requests.post，免 token）。
- 身份键 senderStaffId；单聊 conversationType=='1'；群聊 @ 前缀实测 strip；`caller="dingtalk"`。

**企微 runner**（`im_bot/runners/wecom.py` + `im_bot/wecom_ws.py` 自实现）：
- 自实现理由不变（非官方第三方不用/协议简单已核清/依赖零新增）。协议逐帧按 `docs/reference/企微智能机器人协议参考.md`。
- 连接 `wss://openws.work.weixin.qq.com`；认证帧 errcode≠0=凭证错**fail-fast SystemExit**（不进重连循环）；心跳 30s ping、missedPong≥2 断开；重连指数退避 1s→30s 封顶。
- **跨线程桥接（A-P1-6）**：ws 收发活在 asyncio loop，工作线程 reply 必须 `asyncio.run_coroutine_threadsafe` 桥接；同一 req_id 回复帧串行队列等回执（对齐官方 SDK）；未知帧（含 `aibot_event_callback`）=log 忽略不断连。
- **日志纪律（B-P2-4）**：认证帧 body 含 secret——禁整帧打印（对齐 bindcode 码禁日志）。
- 回复=`aibot_respond_msg` 流式帧（`msgtype:'stream'`, finish=true 单帧, content=Markdown）；MVP 非 text 消息类型回「暂不支持」。

### 2.3 通用处理链抽取（`im_bot/handlers.py`，核心重构）

```python
def handle_incoming(provider: str, bot_id: int, im_user_id: str, text: str,
                    reply, chat_type: str, *, confirm_card=None) -> None
    # reply: Callable[[str], bool]  各平台构造（截断规则下沉各平台 reply 闭包——B-P2-2/A-P2-6）
    # confirm_card: 操作确认卡片回调 | None=降级（读类执行完后再拒答操作类——与飞书行为对齐，A-P2-2）

```

- **bindcode 段留飞书薄壳**（A-P2-3）：验证码绑定是 qr onboarding 特例，不进通用层——`feishu_client.process_message_async` 保留原签名薄壳：先 bindcode 分支（p2p+码），未消费再构造 feishu reply/confirm_card 调 `handle_incoming`。webhook/ws 双路径零改动。
- **execute_read_tool 随迁 handlers.py**（A-P2-4：内容平台无关，留 feishu_client 会让通用层反向依赖平台实现）。
- `gateway.chat(caller=provider)` 参数化（A-P2-1/B-P2-1 双判，arch-19 §4 要求）。
- 未绑定拒答文案身份标识参数化（staffId/userid，不写死 open_id——B-P2-7）。

### 2.4 身份解析按 bot 收口（P0，A-P0-1 安全）

`resolve_im_identity(im_user_id, bot_id)`——**按收消息 bot 收口**，不是 provider 级：企微 userid 是企业自设字符串、钉钉 staffId 是企业内命名空间，多企业自助共存下 provider 级 join 会跨企业同名串号（B 企业用户继承 A 企业账号权限）；per-bot 收口后飞书零行为损失（open_id 跨 app 本不重合）。多义 fail-closed 语义保留在 per-bot 内。个人中心 pending/一键绑本就 per-bot，链路自洽。调用点（webhook/card/bindcode/dispatch）全仓 grep 改齐。

### 2.5 pool 通用化（`im_bot/pool.py`）

- `_desired()`：去 `provider='feishu'` → `{bid: (provider, fingerprint)}`；spawn 入口映射 `{'feishu': 'src.feishu_bot.ws_client', 'dingtalk': 'src.im_bot.runners.dingtalk', 'wecom': 'src.im_bot.runners.wecom'}`；未注册 provider→log skip（配合 2.1 的 13A 不注册 wecom，skip 仅为前向兼容兜底）。
- 对账/退避/指纹重启语义不变；feishu 入口不动（存量零迁移）。

### 2.6 Provider 行为实现

- **企微 `send_text`/`send_card` 本批一律返回 False 诚实桩**（A-P1-2/B-P1-1 双判：ws 连接活在 runner 子进程，web/告警进程无连接可推帧；主动推送需 chatid 而身份面只存 userid）——跨进程推送通道+chatid 留存归告警批。真机联调清单加「runner 活连接时 test_connection 是否踢连接」用例。
- 钉钉 `send_text`：accessToken + `/v1.0/robot/oToMessages/batchSend`；**robotCode=app_key**（钉钉企业内部机器人约定，编码时以官方文档复核——A-P2-5）；`send_card` 返回 False（二期）。
- `test_connection`：钉钉=accessToken 拉取；企微=同步 ws 握手+认证帧（超时 10s）。
- **建/启校验 required_fields**（A-P2-8）：create/start 端点校验 FIELD_SCHEMA secret 字段非空——防空凭证 bot 直接进 pool 退避循环。
- `verify_callback`：长连接型无 webhook 回调→基类默认 None。

### 2.7 前端（页签化，批12A 状态机接线三条写死——A-P1-3/B-P1-2 双判）

**Profile.vue 添加 IM 通道 dialog（自助面）**：
1. **tab-change=新触发源，完整复刻 `onImProviderChange→onImMethodChange` 全链**：离开扫码页签→stopPoll+码区复位；切回→`resumeActiveSession()`（三轮修复成果，只删 radio 渲染不删逻辑）
2. **默认页签=feishu**（活会话的 provider 优先；不按字母序落 dingtalk）
3. **`resumeActiveSession`/轮询仅在 interactive 页签可见时启动**；`guardClose`/`isTerminalQr` 仅扫码页签生效；sessionStorage ticket 键绑 provider
- 页签内容=该平台唯一 method：manual→FIELD_SCHEMA 动态表单+名称+post_steps 指引；interactive→现有扫码向导整段（qrSession/poll/barWatch 状态机不动）
- **barWatch pending 判定按当前会话 bot_id 过滤**（B-P2-5：多平台后其他 bot 首见留痕会阻塞 bound 庆祝态）

**ImBots.vue（admin 面）**：create dialog 同构页签化（form 平台纯表单；feishy 页签=表单+扫码按钮）；用户绑定弹窗占位符 provider 感知（挂账 i18n 批）。

**i18n**：dingtalk/wecom 页签名、字段词条、post_steps（钉钉：开放平台开发者后台→企业内部应用→机器人→Stream 模式→AppKey/AppSecret；企微：管理后台→安全与管理→管理工具→智能机器人→手动创建→API 模式+长连接→BotId/Secret）、降级文案。en+zh 同步。

## 7. 验收标准

1. `list_providers()` 三平台（13A 后 dingtalk/13B 后 wecom）methods/field_schema 正确；飞书无 form
2. 同平台两只钉钉 bot 可建（route_key 推导）+补录凭证不丢 route_key
3. Profile/admin 页签注册驱动渲染；钉钉表单建 bot 落库+凭证加密+空凭证建/启被拒
4. pool 对账 spawn；凭证变更指纹重启；坏凭证（预检失败）退避不传染
5. 真机钉钉：私聊→拒答回显 staffId→个人中心绑定→读类问答通（企微同链 13B）
6. **飞书回归**：webhook+ws 双路径消息链四态等价（未绑定拒答/bindcode 自动绑/读类问答/操作类卡片）+ 批12A 向导 E2E 六项复跑（含活会话切换恢复/BUSY 恢复）
7. pytest 全绿（含改断言套件）+ smoke 三平台断言
