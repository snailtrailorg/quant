# 批15 · 市场操作权限（market_op）

> 2026-09-11 用户裁定立项。背景：sensitivity 脱敏对单用户系统无价值，**按市场控制"是否允许操作"才是真实风控粒度**。
> 三项裁定：①自动单 owner 追溯做（live_task 加列）②data 维 markets UI 退役替换③binance/okx 拆两键。
> 附带修正：permission 表 analyst 越权行（system_config）+ 垃圾测试组清理。

## 设计要点（任务作者必读）

- **卡口唯一**：所有真实下单（策略 runner 自动单 + LLM 聊天下单工具）都汇到 `RiskControl.check_order`（web 交易台**没有**直接下单端点，`/reconcile/manual-order` 只是补录不真实发单）。market_op 挂 `_check_order_inner` 步骤 2（实盘开关）之后。
- **operator 服务端钉死**：order dict 的 `operator` 字段只能由 runner（=live_task.owner_user_id）或 gateway（=聊天登录用户/IM bot owner）在构造点填；Signal/策略参数里的同名字段一律剥掉（构造点显式覆盖，防策略代码自报绕过）。**operator 必填**：check_order 遇空 = 拒单 critical（正常链路必有值，空=异常路径，告警面可见）。
- **市场键五枚**：`convertible/etf/astock/binance_perp/okx_perp`——与实盘分项开关同键（`risk.py:161 _market_of` 现成映射，直接复用）。
- **内置组默认**（seed）：admin/trader 全 allow（10 行）；**analyst/viewer 零行=自动全拒**；自定义新组零行=天然零权限（对齐"新组零权限起步"，无需建组插行）。
- **全链 fail-closed**（2026-09-11 用户裁定修正，原"无行=allow/owner=NULL 放行"两处 fail-open 弃用）：**无行=deny**（新市场键漏配=默认锁死）；读库失败=deny；operator 空=拒单。存量 live_task 由迁移回填 owner（归 admin）。
