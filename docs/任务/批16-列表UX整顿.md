## 通用方案框架（逐页套用）

### 列宽机制（2026-09-12 用户裁定：路线一 + 设计时数据评估权重）

**定稿**：M1 权重分配（v1 表去死 px 改 `min-width` 权重 + 长文本列 `show-overflow-tooltip`）；v2 三表用 M3 估宽。**权重不拍脑袋——设计阶段用真实数据评估**：对每表数据源测各列 char_length 的 p50/p90/max，换算建议 min-width（表头宽与 p90 内容宽取大 + padding + 排序图标；数字列窄右对齐/时间列固定/长文本 flex+tooltip）。评估脚本 `scripts/eval-col-widths.py`，产出 `docs/任务/批16-列宽数据评估.md`，逐页确认按数据拍板。运行时不做内容测量（M2 弃）、不做拖拽记忆（路线二件套不采用）。

| 机制 | 适用 | 做法 |
|---|---|---|
| M1 权重分配 | v1 表默认 | 列去 `width` 改 `min-width`（**数据评估值**），长文本列配 `show-overflow-tooltip`；窗口伸缩自动重排 |
| M3 估宽函数 | v2 虚拟表（3 张：Risk 日志/Reconcile 差异/SymbolManage） | `width = max(label, 采样行内容) + padding + 排序图标`，末列弹性 |

### 操作列模式
```
常用操作（≤2-3 个）→ 行内直接按钮
其余全部 → 「编辑」（或更贴切名）按钮 → 弹窗内展示完整选项（含低频/危险操作）
```
每页确认：哪些进按钮、哪些进弹窗、弹窗叫什么。

### 已知方案边界
- v2 表（3 张）不适用 M1/M2，只能 M3
- Dashboard 为卡片列表范本，默认跳过（单列口径）

## 必修 bug（v2 修法升级——盲审 B 实测病情更重）
1. **Audit.vue 三重 bug**：后端 `/api/audit` SELECT 漏 `target`（表里有列）；`exportCsv` 引用未定义 `auditData`（实为 logs）；CSV 取 `a.username` 而后端返回 `actor` → 修=后端补列+前端两处
2. **DataManage 同步日志死列**：`sync_log` 表有 `failed_dates/expected_days/actual_days` 三列且前端渲染代码已写好——**纯后端 SELECT 漏三列**，补上即活（92% 行 '-' 是正确语义，列头 tooltip 说明）
3. **BacktestRun 两卡**：年化=后端 `_agg` 补 annualized（span_days 短窗防爆口径统一）；盈亏比无原料（引擎无 avg_win/avg_loss）→ **换卡 benchmark_return**
4. **Pool 回补分钟=404**：前端 URL 打到不存在的 `/sync/pool-data`（后端只有 `/trigger`）；且端点不收 pool_id → 修=后端 trigger 加 pool_id（查池标的传 symbols，celery 任务已支持）+前端 URL 修正

## v2 通用纪律（盲审新增）
- **时间列统一 fmtTime**：新加时间列后端多返回 29 字符原始串——统一前端 fmtTime（或后端 [:19]），否则档位 E 被击穿
- **v2 表估宽**：对**渲染后文本**采样（枚举映射成中文后的宽度）+末列 `flexGrow:1`+minWidth（v2 无"不设 width 自动 flex"语义）；三表 columns 已是 computed，数据到达自动重算
- **删除分界明规则**：需输入名/强确认的删除进弹窗（任务/策略/回测），轻确认删除留行内（通道/池/规则）——全站统一
- **est_px 逐字符估宽**（中文 15/ASCII 8）重跑档位（G/H 档中文现低估一半，靠 tooltip 兜底但账要实）
- `/account` redirect 改指 `/integrations?tab=trading`；`backfillMinute` 英文残留顺手修
- 委托表策略列：显示 strategy_id+tooltip（无名称 join，18 字符 C 档截断）
