# 批22 系统监控页

> 立项 2026-09-14（用户设计裁定）。把「健康与日志」页重构为「系统监控」页；把散落的监控循环（组件健康 30s + 磁盘告警 6h）统一成一个监控服务，扩展采集系统资源（内存/磁盘/swap）并留时间序列；标题栏铃铛改作告警入口（角标=活跃告警数）。
> 核心心智：**告警（health_event，有状态的沿事件）与指标（system_metric，连续采样时间序列）是两张表、一个循环、两条落库路径**。异常走 health_event+通知，数值走 system_metric 留趋势。
> 设计原则：**每个卡片 = 一个告警源 + 一个告警状态（正常/告警/恢复）**；不产生告警的信息不花资源监控（故 zram 不纳入）。

## 一、目标

1. 统一监控循环（扩展现有 `health_monitor_check`，30s）：采集「组件（units/deps/hub/tasks）+ 资源（内存/磁盘/swap）」→ 判定（现有 R1-R7 + 新增资源阈值）→ 沿检测 → health_event + notify；资源数值**降采样落 `system_metric`**（见 §三A3），超阈值时额外触发告警+通知。
2. 系统监控页：三组卡片（系统指标/服务状态/实时连接）+ 底部页签（通知/日志/审计）。系统指标卡显示当前值 + 趋势 sparkline + 阈值线。
3. 标题栏：铃铛改告警图标（**admin-only**，角标=活跃告警数，点击进系统监控页），删健康 Warning 图标 + 通知抽屉。

## 二、依赖（就绪 / 需补）

- 就绪：`health_monitor.collector`（units/deps/hub/tasks 采集）、`monitor.run_check`（30s beat，沿检测+health_event+notify）、`notifications` 表、`health_event` 表、`/api/health/events`、Observe.vue/Logs.vue/Audit.vue、IconBtn、echarts 5.6 + vue-echarts 7（sparkline 无缺依赖）。
- 需补：**psutil 依赖**（内存/swap 采集；requirements.txt + 服务器 venv 同步，随 Ansible pip 通道）。**psutil 采集须 fail-soft**：延迟/局部 import + try/except（缺失依赖不炸 /metrics、/readyz、run_check），swap `total==0` 时 pct 除零守卫。

## 三、产出

### A. 后端（统一监控 + 资源采集 + 指标表 + 端点）

1. `health_monitor/collector.py`：`collect()` 加资源快照 `snap["resources"] = {mem, swap, disk}`（psutil.virtual_memory/swap_memory + shutil.disk_usage）。采集失败（psutil 异常/缺依赖）**fail-soft**：`snap["resources"]` 缺省（None），不抛、不阻断快照其余部分。`render_prometheus` 补资源指标族（既有族不动，仅增量）。pct 在 collect 单源算好（下游同源消费）。
2. `health_monitor/monitor.py`：`evaluate()` 加资源阈值规则——**磁盘/内存 used% >90% critical、>80% warn；swap used% >80% warn**（`rule_id`：mem_high/disk_high/swap_high，`component`：memory/disk/swap）。沿检测复用现有状态机，但**state 键值改存 severity**（`r.set(state_key, f["severity"], ex=7200)`），解决「warn→critical 升级」与「静态映射恒标 critical」的矛盾。恢复扫描**加 `resources_evidence` 守卫**（`"resources" in snap`，psutil 异常时跳过资源恢复判定，对标现有 units_evidence，防假 recovery）。
3. 新增 `system_metric` 表（迁移，宽表）：`ts timestamptz PK, mem_total/used bigint, swap_total/used bigint, disk_total/used bigint`。**采样计数器用 epoch 取模 `int(snap["ts"]) % 300 < 30`**（每 5min 落一行，对标 `_prune_events` 的 `% 86400`，重启免疫、免状态键、无多 worker 重复）；新增 **`_prune_metrics`**（DELETE system_metric < 30 天）并挂 run_check 日清（复用 `_prune_events` 的 epoch 日清位）。
4. 退役 `disk_monitor`（`scheduler/app.py` beat_schedule 摘除 + tasks.py 删）。磁盘监控路径 = **system_config 设置项 `disk_monitor_paths`**（缺省 `/`，可改 `:` 分隔多挂载点，如 `/:/var/lib/postgresql`），collector 带 TTL 缓存读取（配置驱动非硬编码）；原 disk_monitor 的 PG 库大小信息**不保留**（非告警源）——阈值 80/90 取代原 85%。前端 `Settings.vue` 加该设置项（admin 可改）。
5. `web_api/routes/system.py` 加端点（**均 `require_perm("system_config")`**，对齐既有 /health/components、/health/events）：
   - `GET /api/system/metrics`：返回 `{now, resources:{mem/swap/disk 当前值+阈值}, thresholds, series:{<kind>:[{ts,used,total}]}}`。resources 当前值取**最新 system_metric 行**（与 series 同源同口径）；series 默认近 7d、空表返回空数组（前端容错）。
   - `GET /api/system/alerts`：扫 Valkey `quant:hm:state:*` 键 → `{count, items:[{rule_id, component, severity}]}`，**severity 读 state 键值**（非静态映射；state 键值为 critical/warning）。
6. `requirements.txt` 加 `psutil`。

### B. 前端（系统监控页 + 标题栏）

1. `MainLayout.vue`：铃铛（Bell）改**告警**（`v-if="role === 'admin'"`，admin-only）——`el-badge` 角标=活跃告警数（`/api/system/alerts` count，30s 轮询刷新），`@click` → `router.push('/observe')`；**删**健康 Warning 图标 + 通知抽屉 + `loadHealth/healthLevel/healthBtnType` + `loadNotifs/notifCount/onAckAll` + SSE 订阅。角标按最高 severity 着色（critical 红 / warning 橙）。
2. 新增 **`NotificationList` 组件**（收编现铃铛抽屉的列表渲染 + runbook chip + ack-all + goCategory），Observe「通知」页签复用；`MainLayout` 的 `ensureRunbook/runbookOf` 随迁。
3. `Observe.vue` 重构（改名系统监控）：顶部三组卡片（组件化）——
   - `SystemMetricsCards`（新组件）：内存/磁盘/swap 三卡，每卡=**状态徽标（正常/告警，取自 `/api/system/alerts` 的 rule_id）+ 当前值（百分比+字节）+ sparkline（echarts 折线，`/api/system/metrics` series）+ 阈值参考线（warn 80%/crit 90% 双线）**。
   - `ServiceStatusCards`：遍历 `/health/components` 的 `units`，每 unit 一卡（名称/状态徽标 ActiveState active·inactive/NRestarts）。
   - `ConnectionCards`：hub（gen/subs/bars/tick_age + 状态徽标）+ 每任务（md/lag/frozen + 状态徽标）一卡。
   - 底部 `TabsShell`：`通知`（NotificationList，active 列表）/ `日志`（Logs.vue）/ `审计`（Audit.vue）。
   - **废弃 `Health.vue`**（组件矩阵被卡片取代；健康事件流历史由「通知」页签的 notifications 已含——monitor 触发/恢复都发通知，code=health.component/recovery）。
4. 移除 **Dashboard 告警条**（el-alert + `alerts` ref + `onHandleAlert` + `dashboard.alertBar`/`handleNow` 词条；**保留 `todayEvents` 分支**——它和告警条共用同一 `getNotifications` 调用，只删 alerts 分支不删整个调用）。
5. `router.js`：**删除 `/health`、`/help` 两个 legacy redirect 路由**（历史别名指向已删的 health 页签，无需保留）；`MainLayout` ⌘K `searchIndex` 的「健康与日志」改「系统监控」（走词条）。
6. `locales`：nav `healthLogs` 改「系统监控」/「System Monitor」；新增系统监控页词条（系统指标/服务状态/实时连接/通知/阈值等，经文案师）；清孤儿词条（`layout.healthWarn`、`notify.title/ackAll/empty`、`tabs.health`、`dashboard.alertBar/handleNow`）；菜单图标 `FirstAidKit` 改 `Monitor`/`Odometer` 对齐"系统监控"语义。

## 五、接口契约

**表 `system_metric`**（迁移）：宽表，见 §三A3。查询：`SELECT ts, mem_used, mem_total FROM system_metric WHERE ts > now() - interval '7 days' ORDER BY ts`。

**`GET /api/system/metrics`** → `{now: iso, resources: {mem:{used,total,pct}, swap:{...}, disk:{...}}, thresholds: {mem:{warn:0.8,crit:0.9}, disk:{warn:0.8,crit:0.9}, swap:{warn:0.8}}, series: {mem:[{ts,used,total}], disk:[...], swap:[...]}}`（series 近 7d，空表返回空数组）。

**`GET /api/system/alerts`** → `{count: int, items: [{rule_id, component, severity}]}`（severity ∈ critical|warning，**读 Valkey state 键值**；扫 `quant:hm:state:*`，key 形如 `quant:hm:state:<rule_id>:<component>`）。

**collector.resources 结构**：`{"mem":{"total":B,"used":B,"pct":0.0},"swap":{...},"disk":{...}}`（采集失败为 None）。
