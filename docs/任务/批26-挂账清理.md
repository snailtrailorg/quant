### 26-5 扫码频控 per-user 索引键 + TOCTOU 关闭（v2 重设计：状态机三分支）
- **目标**：请求路径全键 scan（O(N)）改 O(1)；scan 与写 ticket 非原子→并发双活 ticket 绕过"每用户 1 个"；**不改现状恢复语义**（done 后立即可再发起）
- **键设计（v2）**：`im:onboarding:owner:{uid}` ——**避开** `feishu:session:*` 前缀（sweep_stale_sessions 的 scan 模式，tasks.py:276，键值若被 sweep 误解析会污染）。键值 JSON `{"ticket": "<id>", "status": "<状态>"}`（existing_ticket 恢复需 ticket id）。TTL 随调用方 expire（**代码审 A-P2-3 勘误：scanning 态=SDK expire_in 可达 ~1h，非固定 900s**）
- **状态机三分支（v2，防"done 后被 429 到 TTL 过期"）**：
  1. **pending 首建**：`SET key val NX EX ttl` —— NX 只在此处（并发第二请求 NX 失败→读键判活→429 existing_ticket）
  2. **中态刷新**（scanning/confirming，tasks.py:99/110/129/139/205/217/233 多次调 `_set_session`）：`SET key val EX ttl` 覆盖写（不带 NX）
  3. **终态**（done/error）：`DEL key` —— 立即放行下一次发起（等价现状语义）

- **频控查询改**（im_bots.py:93-103）：单次 GET → 键存在且 status 非终态 → 429 existing_ticket；无键 → 放行
- **落点**：`_set_session`（feishu_bot/tasks.py:29-44）按 session 状态分流三分支；**不动** `sweep_stale_sessions`（前缀已避开）
