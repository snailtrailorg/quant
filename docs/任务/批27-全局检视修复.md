### 27-1 邮件 sending 黑洞（v2：回收计次防无限循环）
- **位置**：`email_service/__init__.py:119-158` + `sweep()` :166-178
- **修法（v2 四件）**：①claim UPDATE 加 `next_attempt_at=now()+interval '10 min'`（认领超时锚）；②sweep 开头回收 `UPDATE email_outbox SET status='pending', attempts=attempts+1 WHERE status='sending' AND next_attempt_at<=now() RETURNING id`——**attempts+1**（盲审 A：防"已发送成功但写库前死"→每 10 分钟无限重发；attempts>=MAX 的行直接标 `failed` 走 _final_failure_notify 可见终态）；③回收 UPDATE 后**显式 conn.commit()**（盲审 B：sweep 现结构 SELECT-only 无 commit，with 退出=回滚）；④成功/失败回写 UPDATE（:140/:146/:151）WHERE 加 `AND status='sending'`（防回收-重领重叠双发）
- **验收**：新测——sending 过期行回收且 attempts+1；attempts 达上限回收即 failed；回写在非 sending 态不落

### 27-3 对账差异单永不落库（v2：逐单 commit+rollback）
- **位置**：`scheduler/tasks.py:294-309`（v2 注：编码时按语义定位——G1 先于 G4 施工防行号漂移）
- **修法（v2）**：**逐单 commit**（循环内 execute 后即 `conn.commit()`），内层 except 加 `conn.rollback()`——循环外单 commit 在任一 INSERT 失败后=aborted 事务上 commit 实为 rollback 全批丢弃（盲审 A：含成功行）；单条失败只丢自己且终止 aborted 态保住后续比对 SELECT
- **验收**：新测——mock conn 断言每 INSERT 后有 commit；单条失败后续 INSERT 存活

### 27-4 飞书操作确认卡（v2 重写：官方同款 ws patch+卡 2.0）
- **实证链**：lark SDK 1.7.1 本地源码+1.7.3 wheel 解包+双盲审三重确认 `ws/client.py _handle_data_frame` `elif message_type == CARD: return` 丢弃卡片帧；`EventDispatcherHandler.register_p2_card_action_trigger`（dispatcher_handler.py:224）注册的 processor 只服务 HTTP；**官方 openclaw-lark（ByteDance）`src/core/lark-client.ts:381-396` 对 node SDK 打同款 patch**（wrap handleEventData 把帧头 type:"card" 改写 "event" 交原 handler 路由）——monkey-patch 是官方工程实践
- **修法三件**：
  1. **ws patch**（学官方）：`ws_client.py` 建 Client 后 wrap `_handle_data_frame`——CARD 帧改写 message_type 为 EVENT 再交原方法（dispatcher 的 `_do_without_validation` 会路由到 `p2.card.action.trigger` 的 callback processor）；**版本探针**：patch 前 assert lark_oapi 版本在已验证集合（防 SDK 升级静默失效——探针失败降级文本模式+日志告警）
  2. **确认卡迁 CardKit 2.0**：`build_confirm_card` 改 2.0 构建（SDK `api/cardkit/v1`，创建卡片实体+消息引用卡 id）；按钮 action.value 带 {action, tool, args, nonce}——1.0 interactive 卡是否触发 2.0 事件不确定，**直接用 2.0 消不确定性**
  3. **handler**：`register_p2_card_action_trigger` 消费（扁平 `operator.open_id`/`action.value`）→ 复用 router.py 三道闸中适用的两道（event_id 去重 `feishu:card:{event_id}` 跨通道同值域/60s 时效）+ resolve_im_identity 身份解析（**签名闸不适用 ws**——鉴权=连接级 app_secret 凭证握手，注释写明）→ execute_confirmed_tool 链（actor=username，见 27-13）
- **HTTP 面去留（裁定）**：router.py `/lark/card/callback` **保留**——降级备用通道（若未来切 HTTP 回调即用），去重键同域兼容双通道防双执行；nginx 不加路由（探针外封不变）
- **验收**：新测——patch 后 CARD 帧（mock）路由到 callback processor；event_id 重复拒/过期拒/身份未解析拒；版本探针失败降级路径。**真机验证一轮**（用户配合：飞书发急停→确认卡→点确认→执行+回复）——2.0 卡构建+回调全链唯一可信验证
- **风险声明**：SDK 升级时 patch 可能碎（官方同款风险）——版本探针+降级文本兜底+升级 checklist 注明
