# 批29b · 卡片终态化

> 2026-09-16 立项。起因：批29 上产后用户真机验收通过（27-4 全链路闭环），但发现 UX 尾巴——点击取消/确认后按钮短暂 disable 又复活可反复点。用户指令："点击后把卡片更新成终态——这个要修"。

## 一、根因

- 回调（CARD 帧→patch→_card_gates）处理完 **ACK 200 空体**，卡片本体不更新；卡片 `update_multi: true` 允许多次交互 → 按钮回到可点态。
- 功能安全（60s 时效+event_id 去重+exec 卡级去重三闸兜底，同卡只执行一次），但两个真洞：**①点过取消后仍可点确认且真会执行**（取消在服务端无记忆）；**②60s 过期后点击零反馈**（闸门静默拒，用户不知道为什么没反应）。

## 二、设计

**任一被处理的点击 → 卡片进入终态**（PATCH `/open-apis/im/v1/messages/{mid}` 原地更新：摘按钮+状态文案）。选 PATCH 而非回调响应内联更新：不依赖 SDK ws 响应管线（我们的 on_card 返回 None=ACK 空体，改造回传链路风险高）；mid（open_message_id）已在回调上下文提取（exec 去重键主成分），现成。

| 点击场景 | 现行为 | 批29b 行为 |
|---|---|---|
| confirm·闸门全过·执行成功 | 执行+文本回执"✅ 已执行熔断" | 同左 **+ 卡片终态"已执行"**（文本回执保留=已测语义不动） |
| confirm·闸门全过·**执行失败**（A-P1-1：strategy_stop/start 子进程失败=polkit 未配现实路径；原实现吞异常无从分辨） | ⚠️/❌ 失败文本 | 失败文本 **+ 卡片终态"failed"**（盲审 A 裁：不终态化则去重键已置=重试点被"已经执行过"拦死，用户锁进假状态） |
| cancel | 静默 no-op（闸门开头 return） | **卡片终态"已取消"**（不执行；仅 `action == "cancel"` 终态化，未知 action 维持静默——A-P2-2 防御性精确） |
| 时效外（>60s/无 ts） | 静默拒（仅日志） | **卡片终态"已过期"** |
| 身份解析失败 | 静默拒 | **卡片终态"账号不可用"** |
| 权限键不足 | 静默拒 | **卡片终态"权限不足"** |
| exec 去重命中（重复点确认） | 文本"已经执行过" | 同左 **+ 据伴生结果键 `feishu:card:execres:{mid}:{tool}`（执行后落 ok/fail）重刷 executed/failed**——代码盲审 B-P1-1：无条件刷绿会让首点失败的卡在重点后显示"✅ 已执行"（风险面说谎）；结果键缺失/redis 异常 → 不重刷（保守缺省不赌方向，PATCH 失败态由过期闸兜底） |
| event_id 去重命中（飞书重推） | 静默拒 | **不终态化**（A-P2-3：重推≠用户点击） |
| mid 缺失（理论回退态） | — | 不尝试更新（update 跳过，闸门行为不变——fail-soft） |

实现注记：cancel 终态化**精确命中 `== "cancel"`**，未知 action 维持静默（A-P2-2 防御性精确——不替脏数据圆谎）；cancel 分支在 tool 提取之前 → tool 传空串（§八 cancelled 文案不带 tool）；**cancel 先于时效闸**——过期卡的取消点击显示"已取消"而非"已过期"（取消本就不执行，无害，B-P2-5 钉死此优先级）。

已知疣（本批不扩治，记录）：①exec 去重键执行前置位——失败后重试点撞"已经执行过"（27-4 并发防护代价；29b-B1 伴生键已让卡面诚实）；②audit_log 不吞异常——halt/resume 已生效后审计 DB 挂 → ❌ 文本+failed 卡（操作实际已触发，文本与卡同源一致地"说失败"；A-P3-3/B-P2-4）。

**PATCH 失败 fail-soft**：update_card 返 False 仅 warning 日志，不影响执行链（去重闸仍兜底复点）；真机若 4xx（权限 scope 不足）→ 用户复测即暴露。

## 三、子项

### 29b-1 `FeishuClient.update_card(message_id, card) -> bool`
- `src/im_bot/feishu_client.py`，httpx.PATCH 同构 send_card 先例（token/超时 10s/响应校验 code==0 落 warning 返 bool）
- URL：`https://open.feishu.cn/open-apis/im/v1/messages/{message_id}`，body `{"content": json.dumps(card)}`（SDK PatchMessageRequestBody 实证 content:str）
- **except 面放宽为 Exception**（盲审 B-P1-2：SimpleNamespace 无 text 属性的 AttributeError 不在 httpx.HTTPError 捕获面=逃逸；fail-soft 声明要求全兜）

### 29b-2 `build_terminal_card(tool_name: str, status: str) -> dict`
- 同文件，CardKit 2.0 结构（schema/config/header/body 与 build_confirm_card 同构，**config 保留 update_multi:true**——官方文档要求 PATCH 前提；终态后原卡 value 消失=无回调可能，自洽）——**无按钮**，body 单 markdown 行
- status ∈ executed/cancelled/expired/denied/unavailable/**failed**（A-P1-1）；header template：**executed=green、余（含 failed）=grey**（文案师裁定：✅ 仅绑成功，无红）；文案六条过文案师（§八，`_TERMINAL_TEXTS` 单源）
- build_confirm_card 不动（发卡面零变更；PATCH 是整卡 content 全量替换，无需改原卡结构）

### 29b-3 `_card_gates` 接线
- `src/feishu_bot/ws_client.py`：mid 已入参；各拒答/执行分支后调 `get_feishu_client(fid).update_card(mid, build_terminal_card(...))`（mid 空则跳过）
- cancel 分支从"开头 return"改为"终态化后 return"
- **execute_confirmed_tool 改返 bool**（文案师随审+A-P1-1 双判：原实现吞异常——strategy_stop/start 失败与未知工具分支发 ⚠️ 文本后正常返回 None）。各分支显式 return：成功路径（halt/resume/stop ok/start ok+审计）=True；stop/start 子进程失败、未知工具、外层 except（❌ 执行失败文本）=False。签名兼容零破坏（现无调用方消费返回值）
- ws 侧：True → 终态"已执行"；**False → 终态"failed"**（不更新则去重键已置=重试点被"已经执行过"拦死，用户锁进假状态——A-P1-1 裁定）
- 闸门顺序/去重/权限判定零变更。**已知既有疣不扩治**（记录不入本批）：exec 去重键在执行前置位——失败后重试点会撞"已经执行过"（27-4 语义，并发双击防护的代价）

## 八、文案（✅ 文案师终审 2026-09-16，中英同步——卡片无语言感知，跟发卡面现状一致用中文）

1. executed：**✅ 已执行**｜"你确认的操作（{tool}）已执行。"（英文标识符入括号当标签——卡片更新后 {tool} 是"执行的是哪项"的唯一线索）
2. cancelled：**已取消**｜"你点了取消，这次操作没有执行。"
3. expired：**已过期**｜"这张确认卡只在发出后 60 秒内有效，你点击时已过期，这次操作没有执行。需要的话请重新发一次指令。"（数字入规则+注明起算点；"重新发起"落成具体动作）
4. denied：**未执行**｜"你的账号没有这项操作的权限。如需开通，请联系管理员。"
5. unavailable：**未执行**｜"你的账号当前不可用，这次操作没有执行。请联系管理员处理。"
6. failed（✅ 文案师补审 2026-09-16）：**执行失败**｜"你确认的操作（{tool}）没有执行成功，具体原因见刚发的那条失败消息。需要的话，重新发一次指令即可重试。"（无 emoji——✅ 仅绑成功；template 归 grey 组；失败原因指向 ⚠️/❌ 详情文本不重复报错）

随审裁定：①失败诚实性→execute_confirmed_tool 返 bool + failed 终态（已入 29b-3，A-P1-1）；②工具名中文映射（gateway 描述复用）=可选优化，**不采纳**（文案已在纯英文标识符前提下终审通过，避免 im_bot→llm_gateway 新增耦合）。
