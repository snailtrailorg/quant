## 接口契约（设计核心）

### 目标布局
```
/data/websites/snailtrail.cc/quant/
  server -> releases/20260826-1930-a1b2c3d/     # 符号链接（原子切换点）
  releases/<ts>-<gitsha>/                        # 不可变版本树（纯代码：
                                                 #   src/ migrations/ scripts/ vendor/ tests/
                                                 #   docs/ requirements.txt alembic.ini）
  shared/                                        # 共享层（数据，永不出入版本树）
    .env  venv/  runtime/  static/avatars/
  bin/run-current                                # 版本解析包装器
```
**rsync 只写 releases/<新 id>/（全新目录），从此零 exclude、无 --delete 风险面。**

### run-current（包装器语义）
```bash
run-current <python-module-args...>   # 如：run-current -m src.md_hub.main
  CUR=$(readlink -f …/quant/server)   # 解析真实版本目录
  cd "$CUR" && exec …/shared/venv/bin/python "$@"
```
进程的 cwd/sys.path 钉死在**启动时**的版本目录——切换后新重启的进程用新版本，已在跑的进程
继续旧目录（其文件不可变）——"文件新+进程旧"从"混乱态"变成"明确且无害的过渡态"。

### quant-release.sh 八阶段（每阶段成功才进下一）
| 阶段 | 动作 | 失败规则 |
|---|---|---|
| 1 preflight | 交易闸门**二次**校验+磁盘空间+四切片指纹（吸收批 5 挂账：切片排 `__pycache__`、空兜底真实现——任一切片空输出即 CODE_CHANGED=1） | 中止，零触碰 |
| 2 stage | rsync 本地 server/ → releases/<ts-sha>/（排除 shared 化的 .env/venv/runtime/avatars——**白名单式，不再依赖黑名单**） | 删 staged，零触碰 |
| 3 verify | staged 内 py_compile 全量 + 导入冒烟（六个入口模块，带 shared/.env 环境） | 删 staged，零触碰 |
| 4 deps | requirements 指纹变化才 pip（装 shared/venv；失败不再有"文件新进程旧"——还没切换） | 删 staged，零触碰 |
| 5 migrate | 从 staged 目录用 shared venv 跑 `alembic upgrade head`（expand-contract：新 schema 容忍旧代码跑满切换间隙） | 删 staged，零触碰 |
| 6 switch | `ln -sfn <新版本> server.tmp && mv -T server.tmp server`（rename(2) 原子） | **flip 回上一 release+重启受影响波** |
| 7 waves | web-api → celery → feishu → md-hub → live-task 分波重启（每波 stabilize+心跳复现；吸收盲审 P1：任一波失败**降级告警续行**，不杀链跳过后续波——实盘任务不再滞留旧码） | 同上回滚 |
| 8 postverify | /healthz /readyz + hub 心跳 gen 递增 + 8 字段 + （盘中）bar 流 / postverify 脚本 | 同上回滚 |

### 失败注入矩阵（沙箱，六场景全过才准上真机）
pip 失败→未切换 ｜ migrate 失败→未切换+exit 非零（批 0 教训回归锁）｜ 切换后 web crash-loop→自动回滚 ｜ postverify 失败→自动回滚 ｜ SIGINT→清理 staged（已切换则回滚）｜ 仅单元文件变更→只 daemon-reload+受影响服务（指纹切片回归锁）

### 验证矩阵规约（写进 12 号，管道内置触发）
| 变更类型 | 必过门（谁执行） |
|---|---|
| 代码 | 单测 +（涉 C/网络/进程）真机冒烟（开发者）→ 导入门（管道） |
| 交付 | verify_imports + postverify + 盘外窗口（管道强制） |
| schema | alembic 迁移 + expand-contract 评审 + 阶段 5 实跑（管道） |
| systemd/配置 | daemon-reload + 受影响波 stabilize（管道） |
| 部署脚本自身 | 沙箱注入矩阵（开发者，改则必跑） |

1. 沙箱六场景全绿（`bash scripts/test_release_failinject.sh`）

4. `grep -c 'exclude' scripts/quant-release.sh` ——黑名单逻辑归零（白名单式 stage）
5. `git grep -l 'strategy_framework.runtime'` 归零（改名完成，层表同步）
6. 明早一交易日无事故（完成定义）
