## 接口契约（v3 修订核心）

### 1. 权限矩阵（表格化——v2 的"属 quant 600"是坏模式且四处死角）

**前置事实**：`/data/websites/snailtrail.cc/quant` 为 750 quant:quant → deploy 用户
**必须入 quant 组**（组位 r-x 穿越用），否则连 releases/ 都走不进（michael 2026-08-17 同款墙）。

| 路径 | 属主/权限 | 说明 |
|---|---|---|
| `quant/`（父） | quant:quant 750 | deploy 经 quant 组穿越 |
| `releases/` + 子目录 | deploy:deploy 755 | 版本树，deploy 全权 |
| `server`（符号链接） | — | **沿用现路径单链接**（零单元/文档路径改动；不另设 current 名）。\n      机制点透：所在父目录 quant/ 750 组位 r-x **无 w**——deploy 无法自行建/改链接，\n      唯一修改通道=root 属主 quant-flip-server wrapper（这正是权限独立的实现，非仅约定） |
| `shared/` | quant:quant **700** | 目录 700（非 600——无 x 位 quant 自己都进不去）；内部文件 600 |
| `shared/.env` | quant:quant 600 | deploy **不可读** |
| `shared/venv/` | quant:quant 755 | 服务以 quant 只读执行；**pip 由 wrapper 以 quant 跑**（见 sudoers） |
| `shared/runtime/`、`shared/static/avatars/` | quant:quant | 运行时数据 |
| `var/`（deploy 状态） | deploy:deploy | 指纹文件/部署状态/pip freeze 快照 |

### 2. sudoers 规格（v3：修三处照抄即翻车）

- **无 `|` 交替符**——逐动词逐行；**`*` 通配匹配含空格**——凡带参命令一律 wrapper 化
- 全部白名单命令=**root/quant 属主、deploy 不可写的 wrapper 脚本**（改 wrapper 内容=提权）
- wrapper **严参校验**：release_id 正则 `^\d{12}-[a-f0-9]{7,}$` 且限定 releases/ 下（无参校验的 wrapper 等于允许任意 cwd 以 quant 跑 alembic）

```
Cmnd_Alias QUANT_DEPLOY_ROOT = /usr/local/sbin/quant-flip-server, /usr/local/sbin/quant-install-units   # root 属主；内部 ln -sfn tmp + mv -T（唯一入口，锁 target 前缀 releases/）
Cmnd_Alias QUANT_DEPLOY_SYS  = /usr/local/sbin/quant-svc
# quant-svc <verb> [unit]：root 属主 wrapper 严参校验——verb ∈ restart|start|stop|status|
# is-active|daemon-reload；unit 匹配 ^quant-[a-z-]+(@[A-Za-z0-9_-]+)?\.service$。
# 复核 A-1 修：systemctl 族不再裸列白名单——sudoers `*` 吃空格，
# `systemctl restart quant-web sshd` 整行匹配 `quant-*` = 任意 unit DoS 面
Cmnd_Alias QUANT_DEPLOY_QUANT = /usr/local/sbin/quant-alembic-wrapper, \
                                /usr/local/sbin/quant-importsmoke-wrapper, \
                                /usr/local/sbin/quant-pip-wrapper
deploy ALL=(root)  NOPASSWD: QUANT_DEPLOY_ROOT, QUANT_DEPLOY_SYS
deploy ALL=(quant) NOPASSWD: QUANT_DEPLOY_QUANT
# quant-install-units：root 属主 wrapper（cp 单元到 /etc/systemd/system + daemon-reload）——场景 6 的执行通道
```
落盘前 **`visudo -cf`** 校验；**禁用 authorized_keys `command=`**（与 Ansible 多命令冲突——写明禁防后人好心加）；authorized_keys 加 `no-port-forwarding,no-agent-forwarding,no-pty`；`from=` 限源 IP **与用户确认出口 IP 固定性后再加**（家宽自锁风险）；bootstrap 检查 sudoers 无 `requiretty`。

### 3. release.yml（v3：rescue 语义 + 波次判别式修死）

```yaml
- hosts: quant-prod
  vars: { release_id: "{{ ts }}-{{ git_sha }}", tz: Asia/Shanghai }
  pre_tasks:
    - assert: 交易窗口（TZ 显式；force 需 -e force=true 且打印自担风险）
    - assert: 磁盘余量 ≥ 500M
    - assert: 目标机 rsync 在位；四切片指纹采集（排 __pycache__；空输出=视为变更）
  tasks:
    - block:                                  # 阶段 2-5：未切换
        - synchronize → releases/{{release_id}}/（白名单清单）
        - script: py_compile 全量+六入口导入冒烟（quant-importsmoke-wrapper，带 shared/.env）
        - shell: grep 本版新增迁移的破坏性 DDL（DROP COLUMN|DROP TABLE|ALTER COLUMN.*TYPE）
          → 命中即 fail（除非 -e allow_contract=true，此时禁用自动回滚走人工 runbook）
        - quant-pip-wrapper: pip freeze 经 stdout 返回（quant 不写 var/），ansible 会话落 var/（deploy 写权）
          + pip --dry-run 预检（指纹变化才真装）
        - quant-alembic-wrapper {{release_id}}: upgrade head
      rescue:
        - file: absent releases/{{release_id}}/
        - fail: msg="发布中止于未切换阶段（staged 已清理，线上未触碰除 venv 依赖追加——见部署日志）"
    - block:                                  # 阶段 6-8：已切换
        - quant-flip-server {{release_id}}     # 内部 ln -sfn target server.tmp && mv -T server.tmp server
        - quant-install-units（本版单元文件有变更时） # 场景 6：仅单元变更走此通道+受影响波
        - block: 波次（web→celery→feishu→hub→task，每波）
            - systemd: restart（**命令层失败**=register 告警续行——续行只为编排完整+信息收集）
            - wait_for: dwell 窗口 is-active 持续 ≥30s + healthz 200/心跳复现
          rescue:
            - register wave_failed=true（**含验证层失败**）
            # 语义修死（复核 B-3）：续行≠维持混合态运行——任何波未达新版，
            # 由 postverify 版本收敛断言终判 fail→统一回滚。「钉旧版人工补作」态不存在；
            # 续行的价值=让后续波跑完（回滚时信息完整/受影响面全量）
        # 波次实例清单真相源= DB（live_task active / feishu_config enabled），不收 active 单元（幽灵前科）
        - postverify: /healthz /readyz + hub gen+8 字段 + **版本收敛断言**：
          readlink -f server == /proc/<MainPID>/cwd（9 单元全查；实现注意：前者解析后无尾 /
          后者为进程实际 cwd，均应等于 releases/<id>——**前缀/规范路径比较**，字面 == 会因
          尾斜杠翻车。降级续行留下的旧版进程在此终判 fail→回滚）
      rescue:
        - include_tasks: rollback.yml          # flip 回上一 release + 重启受影响波 + 复验 + 告警
        - fail: msg="发布失败已自动回滚（代码已回旧版；schema 已前进不回滚——expand-only 前提经 DDL 门保证）"
  post_tasks:
    - 清理旧 releases：保留 N=5（按 release_id 字典序），**跳过 readlink -f server 指向项
      与任何 /proc/*/cwd 钉住项**；GC 孤儿 staged（中断残留，下次部署顺带）
```

**实现注记（复核 A-5）**：①"本版新增迁移"=staged 与上一 release（`readlink -f server`）的
migrations/versions/ 目录 diff；②wait_for 无原生 dwell——循环实现（until+sleep 2，is-active
连续 ≥30s，或直查 unit 进 Failed/StartLimit 即刻判死）；③波次内层 rescue 须按 failed 任务
的 registered 结果判型：命令层失败吞没续行、验证层失败 re-raise 穿透外层（防验证失败被吞）。

**退出码语义（修死）**：rescue 路径一律以 `fail:` 收尾——中止/回滚=**非零退出+告警**，CI 门不吃假绿（v2 的 `meta: end_play` 作废）。六场景验收**断言退出码**非只看文本。

**rollback.yml**：不吃交易窗口硬闸（紧急回滚恰发生在盘中——改告警+`-e confirm=true` 显式确认）；flip 前 assert 目标 release 存在；尾附 pip freeze diff 报告（venv 漂移可见）。

### 4. run-current 规格（v3：钉死实现约束）
- 固定路径 `/data/.../quant/bin/run-current`，**不经 server 链接自举**（避免"切链接导致下次 run-current 自身变化"耦合）
- 内部：`CUR=$(readlink -f …/quant/server) → cd "$CUR" → exec shared/venv/bin/python "$@"`
- 9 单元 WorkingDirectory 指 shared（**不得指穿过 server 链接的路径**——lazy import 会解析到新版本=同进程混合代码，教训 4 变体）；ExecStart 统一 `run-current -m src.…`（web 单元的 uvicorn 形态一并统一）；**推论写明**：crash 后 systemd 重启=解析新版本（钉住仅进程存活期有效）
- 运行期经 server 链接字符串读盘的代码=钉版本旁路，3b 前排查一句
- fix-venv：**每次部署退役**（路径恒定 shared/venv），一次性迁移时做**最后一次** shebang 修正

### 5. 切换编排（v3 新增——本批最高危手术，v2 空白）
**两步切（每步单变量、每步有回退）**：
- **步骤 1（数据外置，旧链继续用）**：建 shared/ 与 var/ → 停服窗口内迁 .env/avatars/runtime（celery-beat 的 schedule 路径**单元内硬编码**，随改）→ **venv 不可搬，重建**：`python3.11 -m venv shared/venv + pip install -r`（磁盘 assert ≥1.5G 余量先行）+ 最后一次 fix-venv → 旧 bash 链改指 shared 并跑一轮全验证（旧链=回退通道）
- **步骤 2（工件形态）**：bootstrap deploy 用户/sudoers/密钥 → 建 releases/ + server 链接 → 装 run-current + 9 新单元 → 首次 release 真跑 → postverify 三证 → 旧 server/ 目录保留一个回滚周期
- 迁移全程盘外；michael root 通道保留为 **break-glass**（runbook 写明）

### 6. 沙箱（v3：道具清单，不假装全覆盖）
- **可真验**（local+道具）：场景 1 坏 requirements（本地 pip）、场景 5 中断残留（+GC 逻辑）
- **道具化真验**：场景 2 坏迁移=开发机本地 PG（`scripts/dev-init-db.sh` 已有，DB URL 参数化）；场景 3 crash-loop/场景 6 单元变更=开发机装 `quant-sbx-*` 假单元（RestartSec=1/StartLimitBurst=2 压缩时间尺度，**真 systemctl 交互**——polkit/拒载类踩过的真坑 stub 验不出）
- **诚实改判 3b**：场景 4 postverify 失败回滚=服务器盘外彩排（一次性沙箱实例名，不碰真单元）
- `--syntax-check`+`--check` 为常规门；验收断言**退出码**

### 7. 前置与版本矩阵（v3 定案）
控制机：python3.10 venv + ansible-core **pin 具体版本（3a 实测定案，不引文档记忆）** + `ansible-galaxy collection install ansible.posix`（vendor 进 deploy/collections/）；inventory 显式 `ansible_python_interpreter`；服务器：`dnf install python39 rsync`（rsync 已在位仍 assert）；交易窗口判断 `TZ=Asia/Shanghai` 显式。
