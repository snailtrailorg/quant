## 接口契约（设计核心）

### 权限模型（服务器侧，bootstrap.yml 一次建成）
```
deploy@quant：
  sudoers（原子白名单，其余全拒）：
    (root)  NOPASSWD: /usr/bin/systemctl restart|start quant-*, \
                      /usr/bin/systemctl daemon-reload, \
                      /usr/bin/ln -sfn /data/.../releases/* ...（current 切换专用包装脚本更佳）
    (quant) NOPASSWD: /data/.../shared/venv/bin/alembic upgrade head（限定 cwd wrapper）,
                      /data/.../shared/venv/bin/python -c import 冒烟 wrapper
  目录权：releases/ 属 deploy 可写；shared/（.env/venv/凭证）属 quant 600——deploy 不可读
  ansible 连接：ControlPersist + connect as deploy，become 按任务（become_user: root/quant）
```

### release.yml 结构（八阶段 → 幂等 plays；失败语义=block/rescue）
```yaml
- hosts: quant-prod
  vars: { release_id: "{{ lookup('pipe','date +%Y%m%d%H%M') }}-{{ git_sha }}" }
  pre_tasks:                       # 阶段 1 preflight
    - assert 交易窗口（周-五 0915-1135/1255-1505 拒绝，force 覆盖需显式 -e force=true）
    - assert 磁盘余量；四切片指纹采集（排 __pycache__；空输出即视为变更——v1 教训）
  tasks:
    - block:                       # 阶段 2-5：未切换，失败=清理 staged 即回滚（线上零触碰）
        - synchronize: 白名单式同步（显式列出进版本树的清单）→ releases/{{release_id}}/
        - script:    阶段 3 verify=py_compile 全量+六入口导入冒烟（带 shared/.env，以 quant 跑）
        - pip:       阶段 4 deps=requirements 指纹变化才装 shared/venv
        - command:   阶段 5 migrate=alembic upgrade head（staged 目录+shared venv，become quant）
      rescue: [ file: state=absent releases/{{release_id}}/, meta: end_play（exit 非零）]
    - block:                       # 阶段 6-8：已切换，失败=自动回滚
        - command: ln -sfn+mv -T 原子切 current（阶段 6 switch）
        - systemd:  阶段 7 waves=web→celery→feishu→hub→task 分波 restart
                    + 每波 wait_for（is-active 双确认/healthz 200/心跳键复现）
                    + 任一波失败**降级告警续行**（盲审 P1：不杀链跳过后续波）
        - uri/shell: 阶段 8 postverify=/healthz /readyz/hub gen+8 字段/（盘中）bar 流
      rescue:
        - include_tasks: rollback.yml   # flip 回上一 release+重启受影响波+复验+告警
  post_tasks: 清理旧 releases（保留 N=5）；部署记录（git sha/时间/结果）落 shared/deploy.log
```

### 沙箱与失败注入（验收门）
- `inventory` sandbox 组：`ansible_connection=local` + vars 指向 /tmp 沙箱目录——**同一 playbook 换目标**，测试不削弱生产路径（v1 的 `_remote()` 单函数思想同款）
- `ansible-playbook --syntax-check` + `--check` 干跑为常规门
- 六场景（playbook 级注入，全绿才准碰 prod）：坏 requirements→阶段 4 中止未切换 ｜ 坏迁移→阶段 5 中止未切换+exit 非零 ｜ 切换后坏入口 crash-loop→rescue 自动回滚 ｜ postverify 失败→自动回滚 ｜ 中断（Ctrl-C/断连）→残留清理 ｜ 仅单元文件变更→指纹切片只重载受影响服务

### 验证矩阵规约（同 v1，写进 12 号+playbook 内置触发）
| 变更类型 | 必过门（谁执行） |
|---|---|
| 代码 | 单测+（C/网络/进程）真机冒烟（开发者）→ 导入冒烟（playbook 阶段 3） |
| 交付 | 阶段 3+8+盘外窗口（playbook 强制） |
| schema | alembic+expand-contract 评审+阶段 5 实跑 |
| systemd/配置 | daemon-reload+受影响波 stabilize（playbook 阶段 7） |
| 部署逻辑自身 | --syntax-check+--check+六场景注入（改则必跑） |

1. 六场景注入全绿；`--check` 干跑零变更报告正确

3. 服务器首次真实发布成功（盘外 runbook），`readlink -f server` 指向新版本，全部服务稳定，postverify 三证过
4. 手动回滚演练一次（rollback.yml 实跑，服务恢复）
5. `git grep -l 'strategy_framework.runtime'` 归零（enginekit 改名完成）
6. 一交易日无事故（完成定义）；旧 bash 链退役封存
