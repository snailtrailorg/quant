# 批34 · 告警通道页用户清单化+通道级选择（2026-09-17 用户口述思路）

## 背景

批30 后订阅=用户维度（选用户→dispatch 自动全通道展开：邮箱有就发/手机有+凭证就发/名下 bot 全发）。用户 09-17 口述重设计思路：

> 不想要独立于用户管理之外的告警通道配置感——直接选**用户**接收告警，再选**该用户名下哪个通道**接收，可多个。一行一用户，可编辑（=勾通道）可删除，用图标按钮（创建也是）。

核心增量=**通道级选择粒度**（现状无：选用户=全通道）。UI 机制全走既有样例（RiskRules/批35：header Plus 图标钮+行内 Edit/Delete IconBtn+编辑弹窗）。

## 用户补充裁定（2026-09-17 方案盲审期间口述）

1. **勾选自由三态**：「可以都选，也可以不选」——全勾=存 `null`（全通道自动，此后新增通道自动纳入）；部分勾=存数组；**一个不勾=存 `[]`=该用户零通道静音**（合法态非错误）。原方案"空数组 400"废弃。
2. **失效勾选自动清除**：「通道删除，则本处也要删除」——用户删邮箱/手机/bot 后，勾选里对应键：GET 返回剥离失效键（不显示无灰 chip）+PUT 保存自动剥离落库（懒清理）；dispatch 侧失效通道天然不发。
3. **行永不静默删除**：「即使通道一个没选/选中的通道全部被删，用户行也要保留」——占位供以后增加；静默删行会造成误解和审计缺失。任何链路不联动删行（删除行=用户显式点删除钮）。

## 现状底子（勘察 2026-09-17）

- `AlertSettings.vue` 已是一行一用户表格（username/channels chips=**可用性**展示/categories/min_level/enabled/actions 图标钮 Edit/VideoPlay/Delete ✓）
- 唯文字钮：「新增订阅」「短信凭证」两枚（:55-56）
- 新增弹窗=用户**多选**循环建行；编辑=用户只读+类别/级别/enabled（无通道勾选）
- `alert_user_sub` 表：user_id 唯一/categories/min_level/enabled（**无通道列**）
- `dispatch.py _load_channels`（:292-336）：subs JOIN users → email 有则发/sms 有+凭证配则发/名下 enabled bot 全发
- `alerts.py`：GET /api/alerts/config 拼 subs（行 channels=**可用性**）+users（channels 可用性 email bool/sms bool/im count）；_validate_sub_body 校验 categories/min_level/enabled
- test 端点三通道各试发（不感知通道选择）

## 方案 v2（双盲审 A P0×1+P1×2+P2×6 / B P1×3+P2×4 全吸收 + 用户三裁定）

### 34-1 迁移 0081（号已钉死：34=0081、33a=0082 后编码；两批串行编码，后编码者 down_revision 对齐实际已合 head）

`alert_user_sub ADD channels JSONB NULL`。NULL=全通道自动（存量行零迁移行为不变）；非空=按勾选；**`[]`=零通道静音**（用户裁定 1）。PG18 ADD COLUMN 无 default=瞬时锁无 rewrite（表 ≤10 行）；downgrade drop_column 对称。

### 34-2 后端 alerts.py

- `_users_with_channels` 扩：`users[].channels` → `{email: bool(有邮箱), sms: bool(有手机), bots: [{id, name}...]}`（名下 enabled bot 清单）。**语义变化**：sms 可用性不再 `and sms_configured()`——勾选面=资料面，凭证未配由发送侧跳过+日志兜底（后配凭证已勾即生效）。GET :81 fallback 形状同步 `{email:false, sms:false, bots:[]}`
- `_subs_from_db` SELECT 加 `s.channels`；GET 行：`channels_sel`=**剥离失效键后**的勾选值（用户裁定 2——失效键不进前端）+`channels_avail`=该用户可用性
- `_validate_sub_body` 保持纯 body 校验不动；新增 `_validate_channels(uid, channels)`（用户确定后、写库前调；POST 用户存在性 SELECT 顺带取 email/phone 零成本，im 键按需查 bots）：
  - body **缺 channels 键=沿用行现值不重校**（与 categories/min_level partial 语义一致——**开关注 toggle 不带 channels 不重置勾选**，盲审 A-P0-1 炸点 b/B-P1-2）
  - 校验仅作用提交值：**实体已消失的键=自动剥离落库**（im:bid 查无此 bot/email/phone 资料已空——审计 detail 注 stripped 键，盲审 A-P0-1 解法+用户裁定 2）；400 `ALERT_CHANNEL_INVALID` 仅留"实体在但不属该用户"（bot 属他人/无邮箱勾 email/无手机勾 sms/畸形键——API 误用信号）
  - `[]` 合法（静音态）；全勾前端归一提交 null
### 34-3 后端 dispatch.py

`_load_channels`：SELECT 加 `s.channels`；`_ch_ok(sel, key) = sel is None or key in sel`（**禁 `not sel` 写法**——`[]` 必须零通道不能假值全开，盲审 A/B 双抓 P1）；email key='email'/sms key='sms'/im key=f'im:{bid}'，append 前过滤。NULL 路径与现状逐行等价。`_ch_ok` 落 dispatch.py 导出（test 端点同源 import——两份谓词防漂移，盲审 A-P2-3）。`alert_tasks._still_enabled` 不动（known-limit：在途任务按入队快照发，窗口秒级可接受——与 categories/min_level 快照语义一致）。
