# 批52:表格列宽双语全局测量(反馈池 #3)

> 2026-09-18 用户反馈:表格各列初始宽度按中英文双语测量,多余空间尽量均分,全局重测一遍(含弹窗内表格)——提升多语言环境兼容性。

## 一、现状(勘察)

- **v1(54+ 表,el-table via TableShell)**:列 `min-width`/`width` **静态值 360 处**(233 min-width+~127 固定 width)——批17 人工定档,按**中文**单语估宽。切英文环境:表头词条变英文(如"当前值"→"Current Value"更宽)→现值不足→折行/省略。
- **v2(三表)**:`colwidth.js` estColWidth 动态估宽(textPx 中文 15/ASCII 8)——**仅 v2,内容采样含表头**;v1 未受益。
- **多余空间均分**:EP el-table 对 `min-width` 列在容器富余时按比例均分剩余——**现状已均分**(批17 后主力 min-width);固定 `width` 列不参与。用户"尽量均分"痛点=部分列仍是固定 width(不参与弹性)或 min-width 值失衡。

## 二、方案(离线测量+清单修——用户澄清 2026-09-18:评估在系统外做,只算缺省值,不挂守门不过度设计)

### A 离线测量脚本(一次性工具,不进 prebuild/不挂守门)

1. 解析 `views/*.vue`+`components/*.vue` 全部 `el-table-column`:提取每列 `min-width|width` 值+表头文本(`:label="t('xx')"` 解析词条键→读 zh/en 双语文本;裸字符串直接用)。
2. **双语预算**=max(textPx(zh), textPx(en))+padding 24+图标列修正(手柄/操作列图标 3×28)。textPx 复用 colwidth.js 同算法(node 端拷贝或 import)。
3. 输出清单:①**现值 < 预算**的列(双语破版候选)②**固定 width 可转 min-width** 的弹性候选(纯展示列)③预算富余过大列(现值≫预算,可收紧)。
4. 输出**建议缺省值清单**(不自动改码)——人工/半自动修。

### A2 余量策略(用户裁定 2026-09-18)

- **固定型列**(时间/状态/ID/金额/枚举):内容宽度十分固定——预算=精确值**适当上浮**(≈+15%,美观留白)。
- **变长列**(名称/描述/路径等):**尽量多留**(≈+30~50% 或就高归档)——避免不够用(宁宽勿紧,截断/tooltip 兜底不美)。
- 列型判定:prop 语义(at/time/ts=时间戳固定型;name/desc/path/label/remark=变长;status/type/state=枚举固定型;金额数字列=固定型)+人工清单复核。

### B 清单修复(全站)

- 逐表按清单调 min-width(以双语预算为基准+内容列按数据采样抽验);固定 width 列评估转 min-width(参与均分)。
- 弹窗内表格同覆盖(components/*.vue 已含)。
- v2 三表不动(已动态)。

### C 词条联动

- 修列宽时若词条文本可精简(如"Current Value"→"Value")优先精简词条而非加宽列(列宽省空间)——逐处裁定。

## 三、验收

- 中英双语逐表目验:表头无折行/省略、列宽均衡、富余均分;守门脚本绿(破版 0)。

## 四、快审吸收(2026-09-18 v2)

- **A-P2**:内容型列(prop 含 at/time/ts/id/金额)叠加**类型模板下限**(时间戳 176+24/ID 72/金额 120)防收紧误伤;图标列公式 `n×24+(n-1)×8+24`(IconBtn small=24px 实证);**两段式守门**(首跑 report 出 baseline 豁免清单→挂守门带 baseline→修一条删一条→清零后机制保留防回归);批17 键失配回落=双语安全值(加分项)。

## 六、批53 角色化修正(2026-09-18 晚——用户抓批52 缺陷)

**缺陷实锤**(用户质问链):批52 工具把列宽当独立标量(文本预算+余量→min-width),**没建模 EP 布局竞争**——富余按各列 min-width 比例分给弹性列→固定型列(时间/枚举/操作)以大 min-width 参与竞争即吸走富余。实测:Logs Time=600(需 200)/Content=217;Audit Time=428/Detail=155;Analysis Conclusion=130;Strategy Action=450。

**修正=角色三分**:固定型(时间/枚举/操作/数值)→`width` 固定**退出弹性**;变长型(名称/用户名)→min-width 参与弹性;内容型(消息/详情/结论/描述)→无宽**独占 flex**。

- 六表修正(实测复验:Logs Time=220/Content=**910**;Conclusion=528;Strategy Action=260):Logs/Audit/Analysis/Strategy/Pool coverage+主表 actions/Factors(含 Name 固定 200)。
- 快审 B 补修四处同款:BacktestView ts/TaskManager 三时间列/Trading 委托 ts/LiveTask actions 260。
- 快审 A 修:Factors/Pool 主表 actions 漏改+SmtpCard 运营商列 180。
- **两卡列序**(用户裁定):SMTP/短信=名称/运营商/状态/操作——服务器地址收进运营商列不占表宽(SmtpCard host:port 列删→运营商列显 host);smsProvVendor 词条 服务商→运营商(Carrier)。
- **工具检讨**:measure-colwidth.mjs 模型缺陷(无角色维度/无渲染实测)——修正方向:输入加列角色+输出按结构(width/min-width/flex)+渲染实测复验;扫描器排除 `type="expand|selection"` 假阳性(B-P2)。
- 窄屏 1280 算术核过(A 员):各表固定底线总和<容器(Pool 主表 1090≈1080 临界注记)。
