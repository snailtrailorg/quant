# 批 60 方案集 · M5 流协议（v8 极简 —— 全 Valkey 三键，零新表；v8.1 吸收七盲审 A 修正）

> v8 缘起：七轮盲审轨迹证明——每引入一个复杂机制（DB lease_token / 切换会话表 / 影子流自动化 / dataset_version 轴 / 拉取型源），就引出一批新缺陷。用户裁定（2026-09-21）：**简洁即是完美**——影子预热砍掉（准备=人职责），系统的 stream_registry 表也砍掉。M5 收敛为**全 Valkey 三键 + 14 号既有机制的组合**。
> v8.1 修正（七盲审 A）：intent 绑定目标 gen 值 + TTL（防残留×冷重启假切换）、boot 前置闸（防复活 A 竞速）、surrendered 键 Valkey 化（可观测）、systemd 依赖钉死进验收、from_watermark 未达断言+显式挂账 M7、行为级验收标注 B 账号依赖。

## 一、设计总纲（一句话）

**M5 = 「人配好 B 源并验证后，盘后 confirm，系统做 INCR gen 原子切换：A 让位、B 接管、worker 重暖机」。全部状态在 Valkey 三个键，零新表、零跨存储、零新协议格式。**

## 二、人机分工（用户裁定）

| 职责 | 谁 | 动作 |
|---|---|---|
| 配置 B 源 | 人 | `external_interface` 加 B 账号行（27 号既有配置面） |
| 验证 B 健康 | 人 | 盘中用 B 账号手动起一次 Hub 试运行（观察日志/心跳确认能收行情），验证后停掉——**不引入系统的影子流自动化** |
| 切换时机 | 人 | 非交易时段（盘后）执行 `switch.py confirm`（切前自动查 live_task running，有则拒切） |
| 原子切换 | 系统 | SET intent → INCR gen → A 让位 → B 抢 lease 接管（下述） |
| 真空/缺口兜底 | 系统（已有） | 盘后权威回补（28 §8.4，tencent_minute/Tushare 既有） |

## 三、Valkey 三键（全部状态，零 DB）

```
hub:gen             世代计数器（14 号已有）——INCR 单调推进，真源
hub:lease           写权租约（14 号已有）——SET NX + Lua CAS，防双活
hub:switch_intent  切换意图标记（本批新增）——confirm 时 SET，收尾 DEL；冷重启不设
```

**为什么不需要 stream_registry 表**：砍掉 DB lease_token（v4）与影子预热（v8）后，该表只剩「审计」用途——切换审计记入 sync_log（已有日志表）即可；gen 真源在 Valkey；切换进度三键可判（见 §六）。**零新表 = 零迁移**（迁移 0096 取消）。

## 四、切换时序（5 步，全 Valkey）

```
T0 稳态：A 持 hub:lease(uuid_A) + hub:gen=G，写主流（auto-id，消息带 gen/seq/ts——14 号现状）。
T1 切前闸（编排器 switch.py，人执行 confirm 时）：
    查 live_task WHERE status='running'，有则拒切（fail-fast）；无 → 继续。
T2 原子切（Valkey 两键顺序）：
    SET hub:switch_intent = G+1 EX 300      ← 值=目标 gen（非裸 confirm）+ TTL 300s
    INCR hub:gen → G+1
    （intent 先落且绑值：B/A 只认「gen == intent 声明值」，冷重启 INCR 出的代数与声明值不符即拒）
T3 让位与接管（A/B 各自轮询，复用 EngineLoop 5s 步）：
    A 轮询见 intent==gen 推进值 → surrender：
        SET hub:surrendered:{uuid_A}（Valkey，可观测；_lease_renew 每续期前查此键，见则跳过续期+不误告警）
        → Lua CAS DEL hub:lease → 停订阅 → os._exit(0)
    B 轮询见 gen 推进 → 接管：
        SET NX 抢 hub:lease（不 INCR）→ 单次 GET hub:gen 冻结为写 gen
        → 校验 == intent 声明值（G+1）：不等（如复活 A 抢回致 G+2）→ 拒绝接管+告警人工介入
        → 写主流（gen=G+1）
T4 收尾（编排器，超时=lease TTL 30s+B 两轮轮询≈40s）：
    DEL hub:switch_intent + DEL hub:surrendered:{uuid_A}；写 sync_log（切换审计）。
    abort 路径（T2 后任一步放弃）：同样 DEL intent（残留 intent×后续冷重启 INCR 会组合出假切换）。
    次日开盘：B 首根 bar → worker gen_jump → 重暖机（盘后 PG 已回补当日）。
```

## 五、关键不变式（铁律）

1. **gen 单调永不回退**：推进 = INCR hub:gen（切换 T2 / 冷重启 boot）。无 DECR、无补偿。
2. **切换意图绑定目标 gen**：`hub:switch_intent` 值 = 目标 gen（G+1，非裸 confirm）+ EX 300s；A/B/reaper 只认「gen == intent 声明值」——冷重启 INCR 出的代数与声明值天然可区分，残留 intent 无法与后续推进组合成假切换。abort 与收尾路径都 DEL intent。
3. **boot 前置闸**：boot 时先读 `hub:switch_intent`，存在（切换窗内）→ exit(3) 拒启——拦死「让位 A 崩溃后 systemd 30s 拉起复活，在切换窗内竞速抢租约」（复活 A 的现行 `_lease_acquire` 无任何检查，赢 NX 即 INCR 污染 gen；boot 闸把这条路径整体关死）。
4. **B 写 gen = 抢 lease 后单次 GET hub:gen 冻结 + 校验 == intent 声明值**：不等（复活 A 抢回致 G+2 等场景）→ 拒绝接管 + 告警人工介入。
5. **A 让位自退，无外部特权**：SET `hub:surrendered:{uuid_A}`（Valkey，可观测）→ CAS DEL lease → exit(0)。`_lease_renew` 每续期前查 surrendered 键（本 uuid），见则跳过续期不误告警。
6. **systemd 依赖钉死（写进验收）**：`quant-md-hub@.service` 必须 `Restart=on-failure`（exit(0) 正常让位不拉起）且 `RestartPreventExitStatus` 不含 0——A 自退语义系于这一行 unit 配置，改 unit 必须过本批验收的 diff 检查。
7. **worker fencing 完全基于消息**：gen/seq 从消息读。前进=权威放行+adopt seq；回退=stale_gen 拒。warmup 加 gen 过滤（冷启动 state.gen=0 不过滤）。
8. **单租约防双活**：hub:lease（SET NX + Lua CAS）。任一时刻至多一个写主流。

## 六、崩溃恢复（三键判定，简单穷举）

编排器/A/B 任一崩溃后，按三键判定（无 DB，无需对账表）。**表边界：仅覆盖切换窗**（confirm 起至收尾 DEL intent 止）；收敛后的常规崩溃（无 intent）回归 14 号现行机制（lease TTL + 冷启抢锁），不在本表。

| hub:switch_intent | hub:gen | hub:lease | 判定 → 动作 |
|---|---|---|---|
| 无 | G | A 持有 | 稳态/未切换 → 无动作 |
| 无 | G | 无主 | A 崩溃 → 冷重启 A（boot 无 intent，闸放行）或等 systemd 拉起 |
| **=G+1（残留，gen 未到）** | G | A 持有 | **torn T2**（SET intent 成功、INCR 未做/编排器崩）→ 编排器/reaper 清 intent + 告警重来（A 不误退：A 的条件是 gen 推进） |
| =G+1 | G+1 | A 持有 | 切换已推进、A 未让位 → 等 A 轮询 surrender（≤5s）；**超时 40s**（lease TTL 30s+两轮 poll）人工冷切 |
| =G+1 | G+1 | 无主 | A 崩于让位前 → B 轮询会抢 lease 接管（校验 gen==intent 值）；**复活 A 被 boot 闸拦死**（intent 在即 exit(3)） |
| =G+1 | G+1 | B 持有 | 切换已生效 → 编排器 DEL intent + 写审计 |
| 无 | G+1 | B 持有 | 已收尾 → 稳态（B 新写者） |

**裁决原则**：intent（切换意图 + 绑定的目标 gen）→ gen（推进与否、是否等于声明值）→ lease（谁在位），三键顺序判定，确定性。intent 的 300s TTL 是残留兜底（无人清理也会过期）。

## 七、水位线衔接（databus.subscribe，最小实现）

- **XADD 保留 auto-id**（14 号现状，不回归）。
- `subscribe(sub, sink)`：`xrevrange count=240`（现状 `_warmup_from_stream` 同款）+ from_watermark（ts）截断 + (vt_symbol,ts) 去重 + gen 过滤。
- **未达断言**（七盲审 P1 修正）：worker 暖机语境 count=240 恰好自洽（A股全天分钟=240 根，缺口由 PG 覆盖），但 DataBus.subscribe 的「按水位线重放」语义不同——固定条数不是寻址，水位线距流头 >240 条时静默漏。本批加断言：**重放后最老回放条 ts ≤ watermark + 1 bar，不满足 → 告警 + 降级 get_bars fetch-on-miss**。精确按 ts 寻址（XREVRANGE (ts-slack) + 消息字段过滤）**显式挂账 M7**。
- `_watermark` 连续无缺：交易时段边界锚（段内 freq 连续、段间段首 bar）。

## 九、验收判据

1. **原子切**：confirm 后 A 让位 + B 接管，不双活（单租约）。
2. **fencing 负例**：切后 A 旧 gen 消息被拒（live + warmup 双路径，单测注入）。
3. **误抢防护**：A 冷重启（无 intent）B 不误判；**复活 A 在切换窗内 boot 被闸拦（exit 3）**；B 冻结 gen ≠ intent 值时拒绝接管（单测注入 G+2 场景）。
4. **worker 次日重暖机后水位线连续**（PG 已回补，无混源）；subscribe 重放未达断言触发告警（单测注入深水位）。
5. **崩溃恢复**：三键判定 7 行实测（含 torn T2 / A 崩于让位前，失败注入）。
6. **人机衔接**：confirm 命令 + 切前闸（live_task running 拒切）。
7. **systemd 单元 diff 检查**：`Restart=on-failure` + `RestartPreventExitStatus` 不含 0（A 自退语义的前提，改 unit 必须过此验收）。
8. 全量 pytest 绿（无新迁移）。

> **行为级验收边界（铁律 handoff-no-shortcuts）**：判据 1/2/3/5 的**真实双源行为级实证依赖 B 账号到位**（第二 XTP/其他券商）。到位前仅 mock 单测绿，**不可作为收官依据**——批 60 交付时逐条标注「等 B 账号补验」。
