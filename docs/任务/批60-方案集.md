# 批 60 方案集 · M5 流协议（v16 —— staging 实证修正：exit(3) 回归重启码）

> v13 缘起：v12 两轮终审（opus 正确性 + 一致性）抓出 4 P0 + 4 P1。根子：①反切对称性砍丢（guarded Lua 只给 B，反切 A 无原语 SET active_instance）；②exit(3) 双语义 + 30s 重拉打穿 StartLimit；③boot 放行后 dispatch 分叉未指定；④surrendered 键与 parts.py 现有 `hub:surrender` 撞名。v13 修：砍 surrendered 键（intent 闸已兜崩溃竞速）、exit 码独立（6=闸拦截进 Prevent）、guarded Lua 归「切换目标」通用、boot 单判定显式 dispatch 分叉。

> **v14 缘起**：v13 两轮终审（砍 surrendered 竞速 + 一致性）总判「可进编码，但落实明确性」。v14 收口：退出码矩阵补全（1/4/5 重启码 + 78 补 hub 出口 + B 凭证 fail-fast 禁 .env fallback）、HUB_UUID 生命周期（confirm 内生成回写 drop-in）、normal 冷启 SET active_instance、guarded -1/-2 处理、hub:surrender 保留明说、A 让位 CAS DEL、T2d≤2s/60s。

> **v15 缘起**：编码落地时砍 HUB_UUID，根因链三段：①v14 用 HUB_UUID（switch.py 生成注入 B）校验「抢 lease 的是 B 非复活 A」；②终审①焦点4.2 已论证 guarded Lua 把「抢 lease+INCR gen+SET active_instance=target」做成一条原子脚本，故 **`active_instance==target` ⟺ 目标 guarded 成功 ⟺ 目标持 lease** 三等价——active_instance 是等强度代理，switch.py 无需知道 B 的 uuid；③「回写 drop-in 的 HUB_UUID」无特权通道（quant-svc 白名单仅 systemctl verb，无文件写）。v15：uuid 运行时 token_hex（A/B 同），正切/反切 holder 校验统一用 active_instance==target，drop-in 只留 HUB_INTERFACE_ROW。

> **v16 缘起（staging 实证，2026-09-22）**：首次上产彩排红——部署波重启 hub 时旧 lease 未过期（SIGTERM 不 DEL lease，TTL 剩 ~30s），新进程真让位 exit(3)，v15 把 3 放进 RestartPreventExitStatus 导致 systemd 不再重拉 → hub 永久死 → dwell 判死自动回滚。修正认知：exit(3) 的「切换窗复活拦截」职责在 v15 已由 boot 闸 exit(6) 独立承接；exit(3) 剩下的唯一常态路径恰是「正常重启 30s lease 滞后窗」，**必须保留 on-failure 重拉自愈**。v16：Prevent=0 6 78（去 3）。

## 一、设计总纲（一句话）

**「人配好 B 源 + 连通测试 → 盘后 confirm（setsid 绝缘）→ SET intent{snapshot,target} → A 让位（DEL lease exit 0）→ 启动 B（guarded Lua 接管 → SET active_instance）→ worker 次日 gen_jump 重暖机」。全 Valkey 四键，零新表，无待命态。**

## 三、Valkey 键（四键，全部状态，零 DB）

```
hub:gen                       世代计数器（14 号已有）——INCR 单调；推进=guarded 首接 / 冷重启 normal
hub:lease                     写权租约（14 号已有）——SET NX + Lua CAS，防双活
hub:switch:intent            切换意图——Lua SET={snapshot:G, target:目标实例名}，EX 300s
hub:active_instance          现任实例名（quant/quant2，无 TTL）——重启仲裁
```

> **砍 `hub:switch:surrendered:{uuid}`**：原作用「先 surrendered 后 DEL lease」防 A 崩溃竞速，但 boot 单判定（intent.target≠自己→exit 6）已兜住崩溃重启，且与 parts.py 现有 `hub:surrender`（真让位）撞名。砍掉后 A 让位=见 intent → CAS DEL lease → exit(0)，T2c 只轮询 lease 空。
>
> **`hub:surrender` 保留不删**：它是 14 号真让位标记（`_lease_acquire` 发现 lease 被他人持有 → 写 `hub:surrender` → exit(3)，parts.py:240-245），非切换协议状态键。「四键」仅指**切换协议新增状态键**（gen/lease/intent/active_instance），非 Valkey 键全集——实现者勿误删 `SURRENDER_KEY`。

## 四、A/B 实例模型

- **A（现任）**：`quant-md-hub@quant`，无 env，现行行为。
- **B（继任）**：`quant-md-hub@quant2`，drop-in 注入 `HUB_INTERFACE_ROW=<B行id>`（账号选择）。uuid 运行时 `secrets.token_hex(8)`（同 A）——**holder 校验用 `active_instance==target`（guarded 原子绑定的等强度代理），无需预定 uuid**。
- **实例名来源**：base unit 加 `Environment=INSTANCE_NAME=%i`（A/B 同模板一次覆盖）。main.py 读 INSTANCE_NAME 供 boot 单判定比对。
- **uuid 来源**：`secrets.token_hex(8)` 运行时生成（A/B 同）——不再需要预定 uuid，holder 校验由 active_instance==target 承接。
- **boot 单判定 + dispatch 分叉**（读 intent + active_instance + INSTANCE_NAME，**必须插在 `_lease_boot`（main.py:84）之前**——load-bearing，放后则 A 复活先 INCR 污染 gen）：

```
intent 存在:
    intent.target == INSTANCE_NAME → 放行，走 _lease_acquire_guarded（切换目标接管）
    intent.target != INSTANCE_NAME → exit(6)（被切走者拦截，不 INCR 不抢 lease）
intent 不存在:
    active_instance 存在 且 active_instance != INSTANCE_NAME → exit(6)（非现任不抢回）
    否则 → 放行，走 normal `_lease_acquire`（非切换冷启），并 SET active_instance=INSTANCE_NAME（bootstrap，仲裁从首启成立，不退化）
```

- **exit 码矩阵**（完整，systemd `RestartPreventExitStatus=0 6 78`）：
  - `exit(0)`：优雅让位（A 见 intent 主动让位）——Prevent 冗余防御（on-failure 本就只拉非 0）
  - `exit(1)`：vnpy 缺失 / EngineLoop fatal / 未捕获异常——**重启码，不进 Prevent**（on-failure 重拉；重拉不愈则 5 次打穿 StartLimit 进 failed 黑洞，switch.py T2f 超时告警——这是「明确失败态」，非静默）
  - `exit(3)`：真让位（lease 被他人持有，14 号）——**重启码，不进 Prevent**。双触发路径：①切换窗复活实例（v15 已由 boot 闸 exit(6) 独立承接，此路径不再走 3）；②**正常重启的 30s lease 滞后窗**（SIGTERM 不 DEL lease，旧 lease TTL 内新进程 NX 失败 exit(3)，30s 后重拉即愈——历史部署过 dwell 的机制）。staging 实证（2026-09-22）：把 3 放进 Prevent 会把部署波重启打成永久死。
  - `exit(4)`：租约重试耗尽（`_lease_acquire` 3 次网络失败，14 号）——重启码，不进 Prevent
  - `exit(5)`：续租丢（`_lease_renew` CAS 失败，14 号）——重启码，不进 Prevent
  - `exit(6)`：boot 闸拦截（intent.target≠自己 / active_instance≠自己）——进 Prevent（被切走者/非现任 stay dead）
  - `exit(78)`：EX_CONFIG（配置错）——进 Prevent。**新增 hub 出口**：B 凭证按 row_id 取数失败（HUB_INTERFACE_ROW 坏行）→ `build_xtp_setting` **抛异常 fail-fast exit(78)，禁 .env fallback**（否则 B 静默跑在 A 的 XTP 账号上）

## 五、切换时序（confirm setsid 绝缘、幂等可重跑）

```
T0 稳态：A 持 hub:lease + hub:gen=G + active_instance=quant，写主流。
T1 准备（人）：配 B 行 + B 单元 drop-in（HUB_INTERFACE_ROW）+ 连通测试。
T2 confirm（switch.py，setsid 绝缘，阻塞到出结果，幂等可重跑）：
    (a) 切前闸：live_task running 拒切（退出码 2）
    (b) 校验 target ∈ {quant, quant2}（非法 → 退出码 5 fail-fast，防错填让现任下台）
    (c) 单 Lua：G_cur = GET hub:gen；SET hub:switch:intent = {snapshot: G_cur, target: target} EX 300（只 SET 不 INCR）
    (d) 等 A 让位：轮询 hub:lease 为空（**≤2s 间隔**；A 让位 CAS DEL 或 A 崩 30s TTL 过期；**≤60s 超时**→告警退出码 3，盘后无成本放宽）
    (e) 启动目标：经 quant-svc wrapper start quant-md-hub@quant2（drop-in 的 HUB_INTERFACE_ROW 已由人预配，无需 switch.py 回写）
    (f) 等目标接管：hub:gen > G_cur 且 hub:active_instance == target（guarded 原子绑定：抢 lease+INCR+SET 现任，等强度代理）（≤30s 超时→告警退出码 4）
    (g) 数据流证据：读 quant:hb:md-hub 心跳 gen 字段 == G_cur+1（B 真在写，非假接管）
    (h) 收尾：校验 hub:active_instance == target（guarded Lua 接管时已 SET）；DEL intent；审计 audit_log
    (i) 返回：成功打印「切到 target，gen G→G+1」（退出码 0）
T3 A 让位（T2d 窗口）：A 轮询见 intent 存在且 target≠自己 → CAS DEL lease（lease 值==my_uuid 才 DEL）→ 退订 → os._exit(0)
T4 次日开盘：B 首根 bar → worker gen_jump → 重暖机（bar 延迟非丢失）
```

## 六、切换目标接管原子 Lua `_lease_acquire_guarded`（正切 B / 反切 A 共用）

guarded Lua 归「切换目标实例」所有（不是「B」），读 intent 得 expected_gen=snapshot+1、target：

```lua
-- KEYS[1]=hub:gen  KEYS[2]=hub:lease  KEYS[3]=hub:active_instance  ARGV[1]=uuid  ARGV[2]=expected_gen  ARGV[3]=target
local g = tonumber(redis.call('GET', KEYS[1]) or '0')
if g == ARGV[2] then
    -- 重启场景：gen 已是 snapshot+1（上次 INCR 过），只抢 lease 不 INCR
    local ok = redis.call('SET', KEYS[2], ARGV[1], 'NX', 'EX', 30)
    if not ok then return -2 end
    redis.call('SET', KEYS[3], ARGV[3])   -- 现任=target（接管即现任，原子绑定）
    return ARGV[2]
elseif g == ARGV[2] - 1 then
    -- 首接场景：gen 还是 snapshot，INCR + 抢 lease + SET 现任（原子绑定）
    local ok = redis.call('SET', KEYS[2], ARGV[1], 'NX', 'EX', 30)
    if not ok then return -2 end
    redis.call('INCR', KEYS[1])
    redis.call('SET', KEYS[3], ARGV[3])
    return ARGV[2]
else
    return -1   -- gen 既非 snapshot 也非 snapshot+1（被污染）→ 拒接管，零污染
end
```

**关键**：校验在 INCR 前，失败零污染；gen 推进+抢 lease+SET 现任三者原子。guarded Lua 只用于「intent.target==自己」的切换目标（正切 B/反切 A 对称）；**非切换窗冷启**（intent 不存在）走 normal `_lease_acquire`（无条件 INCR）。

**返回值处理**（main.py 调用侧）：
- `-1`（gen 污染，被复活 A 抢在 B 前 INCR）→ 拒接管，log + 退订 + exit(1)（systemd 重拉；重拉不愈进 failed，switch.py T2f 超时告警——明确失败态）
- `-2`（lease NX 被旧化身 lease 挡）→ **3 次重试（sleep 5s，同 `_lease_boot` parts.py:236 吸收旧 lease TTL 30s 未过期的边界）**，超时 exit(1)

**反切**：confirm SET intent={target:"quant"} → B 让位 exit(0) → A boot 读 target==自己 → guarded Lua（expected_gen=snapshot+1，SET active_instance=quant）→ 收尾校验 active_instance==quant。与正切完全对称。

## 七、关键不变式（v13 铁律）

1. **gen 单调**：推进 = guarded 首接 INCR / 冷重启 normal INCR。无 DECR。B 重启（intent 存在时）走 guarded「只抢 lease」分支不 INCR；**intent 过期后冷启走 normal INCR=冗余代，worker 重暖机兜（无害）**。
2. **切换意图 = {快照 G, 目标实例}**；guarded 的 expected_gen = intent.snapshot + 1。**target 建模切换方向**，boot 闸据此放行目标/拦截被切走者。
3. **切换目标接管校验在 INCR 前**（guarded Lua g==ARGV[2]-1 分支），失败零污染。
4. **A 让位靠 intent 存在且 target≠自己**（T2 不 INCR）；让位 = **CAS DEL lease（lease 值==my_uuid 才 DEL，防删掉 B 已拿到的 lease）** → exit(0)。
5. **active_instance 重启仲裁**：现任唯一标记，boot 读它 ≠ 自己 exit(6)。**guarded Lua 接管即 SET active_instance=target（原子绑定，不依赖 switch.py 收尾）**；反切同理 SET 回 quant；**normal 冷启也 SET active_instance=INSTANCE_NAME（bootstrap）**。
6. **boot 单判定插在 `_lease_boot` 之前**（load-bearing）；dispatch：target==自己→guarded，无 intent→normal。
7. **exit 码矩阵**：0 优雅让位 / 1 vnpy缺失·fatal（重启码）/ 3 真让位（**重启码**——切换窗拦截由 6 承接，3 留给正常重启 30s lease 滞后自愈）/ 4 租约重试（重启码）/ 5 续租丢（重启码）/ 6 闸拦截 / 78 EX_CONFIG；**Prevent=0 6 78，1/3/4/5 重启码不进 Prevent**。
8. **worker fencing 基于消息**（stale_gen + (symbol,ts) 去重）；warmup 无 gen 过滤。
9. **单租约防双活** + 收尾校验 active_instance == target（正切/反切统一，guarded 原子绑定=等强度代理）；**B 凭证按 row_id 取数失败 → exit(78) fail-fast，禁 .env fallback（否则 B 静默跑在 A 账号上）**。
10. **confirm setsid 绝缘 + 幂等可重跑 + target 校验 fail-fast**。
11. **类型契约**：gen/intent.snapshot/心跳 gen 比较两侧强制 int()。

## 八、崩溃恢复判定表（gen 单点推进，intent=快照 G）

> 表按**正切方向**（现任=quant，继任=quant2，intent.target=quant2）列写；**反切镜像**（A/B 互换，target=quant）对称适用。「目标」=intent.target 实例。

## 十、验收判据

1. 原子切：confirm 后 A 让位 + B 接管，不双活。
2. fencing 负例：切后 A 旧 gen 消息被拒（stale_gen）。
3. 原子 Lua 三态：首接（INCR+抢 lease）/重启（只抢 lease）/污染（拒，零污染）——单测注入三态。
4. 重启仲裁：SET active_instance 后服务器重启，A 单元不抢回（active_instance 闸 exit 6）。
5. **反切镜像**：正切→反切→正切往返，active_instance 每次正确翻转（guarded 通用化验证）。
6. 盘中 hub 崩溃重启后运行中 worker history 连续。
7. confirm 返回契约（五退出码 + stdout 四态）+ setsid 绝缘 + 幂等重跑 + target 非法 fail-fast。
8. systemd 单元 diff（INSTANCE_NAME=%i + RestartPreventExitStatus）+ 重暖机 bar 延迟非丢失。
9. 口径 diff：switch.py diff 全量比对 + 超阈值告警。
10. 全量 pytest 绿。
