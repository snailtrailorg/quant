# 批 60 方案集 · M5 流协议（v10 —— 砍待命模式，gen 单点推进）

> v10 缘起：opus 两轮深审（A 焦点①②/B 焦点③④⑤）**独立命中同一 P0**——v9 砍 no_incr 时 T2 也 INCR 了，B 接管再 INCR → G+2≠intent+1 校验恒失败。深审 A 进一步发现「待命模式」是伪命题：main.py 单遍初始化、`_lease_boot` 在一切初始化之前，待命循环只能插在初始化前，「解除静默」实为「接管=全量重启」——故**砍掉待命模式**，B = A 让位后按需启动的正常 hub。

## 一、设计总纲（一句话）

**「人配好 B 源 + 连通测试验证 → 盘后 confirm → 编排器 SET intent → A 让位 → 启动 B（正常 hub，INCR gen 接管）→ worker 次日 gen_jump 重暖机」。全 Valkey 四键，零新表，无待命态。**

## 二、人机分工

| 职责 | 谁 | 动作 |
|---|---|---|
| 配置 B 源 | 人 | `external_interface` 加 B 账号行 |
| 验证 B 连通 | 人 | 独立连通测试（`test_xtp_connect.py` 形态：登录+订阅收数，**不起 hub、不碰三键**） |
| 切换时机 | 人 | 仅非交易时段：交易日 15:10 后 ～ 次日 9:15 前 + 全天非交易日 |
| 原子切换 | 系统 | switch.py confirm（阻塞式）→ A 让位 → 启动 B → B INCR gen 接管 |
| 口径兜底 | 系统 | 盘后腾讯回补（bar_1min 唯一权威）+ **B 首日口径 diff 告警**（见 §八） |

## 三、Valkey 键（全部状态，零 DB）

```
hub:gen                     世代计数器（14 号已有）——INCR 单调，唯一推进=B 接管/冷重启
hub:lease                   写权租约（14 号已有）——SET NX + Lua CAS，防双活
hub:switch:intent          切换意图（本批新增）——Lua SET=切换前快照 G，EX 300s
hub:switch:surrendered:{uuid} A 已让位标记（本批新增）——SET EX 600
```

## 四、A/B 实例模型（v10 砍待命态）

- **A（现任）**：`quant-md-hub@quant`，无 env，现行行为。
- **B（继任）**：`quant-md-hub@quant2` + env `HUB_INTERFACE_ROW=<B 行 id>`——**不是提前待命的进程，而是 confirm 后、A 让位后由编排器按需启动的正常 hub**。启动走完整 main() 流程（`_lease_boot` 抢 lease → 连接 MD → 订阅 → 写主流），无任何特殊状态机。
- **boot 前置闸**：**无 env 进程**（=A 复活）boot 时若 `hub:switch:intent` 存在 → exit(3) 拒启（A 是被切走的，切换窗内不许回来）；**有 env 进程**（=B，被指定继任）→ 正常启动，不受闸拦。
- **心跳**：B 启动后写主键 `quant:hb:md-hub`（与 A 相同，单键语义不变——B 只在 active 时存在，无 `:2` 后缀）。hbcheck/worker `_hub_alive` 不受影响。
- **systemd**：模板 `Environment`/`ExecStart` 用 `%i` 注入 `HUB_INTERFACE_ROW`（冲突审②落地卡点）。

## 五、切换时序（confirm 阻塞式，switch.py 单进程完成）

```
T0 稳态：A 持 hub:lease(uuid_A) + hub:gen=G，写主流（auto-id，消息带 gen/seq/ts）。
T1 准备（人，切换日前）：external_interface 配 B 行；test_xtp_connect 验 B 连通。
T2 confirm（switch.py，阻塞到出结果）：
    (a) 切前闸：live_task WHERE status='running'，有则拒切退出（退出码 2，stdout 报错）
    (b) 单 Lua 设意图：G_cur = GET hub:gen；SET hub:switch:intent = G_cur EX 300（只 SET 不 INCR）
    (c) 等 A 让位：轮询 hub:lease 为空 或 hub:switch:surrendered:* 出现（超时 40s → 告警+人工冷切，退出码 3）
    (d) 启动 B：systemctl start quant-md-hub@quant2（B 正常 main()：抢 lease→INCR gen→连 MD→订阅→写主流）
    (e) 等 B 接管：轮询 hub:gen > G_cur 且 hub:lease 非空（超时 30s → 告警，退出码 4）
    (f) 收尾：DEL intent + surrendered:*；校验 hub:lease 持有者 uuid 是 B（非 B → 静默回退告警）；审计写 audit_log
    (g) 返回：成功打印「切到 B，gen G→G+1」（退出码 0）
T3 A 让位（T2c 窗口内）：A 轮询见 intent 存在 → SET surrendered:{uuid_A} EX 600 → Lua CAS DEL lease → 退订 → os._exit(0)
    （顺序 load-bearing：先 surrendered 后 DEL——先 DEL 则中途崩溃被 on-failure 拉起竞速）
T4 次日开盘：B 首根 bar → worker gen_jump → 重暖机（bar 延迟非丢失：max_ts 去重保留，gen_jump 那根仍驱动 on_bar）
```

## 六、关键不变式（v10 铁律）

1. **gen 单调、单点推进**：唯一推进 = B 接管的 `_lease_acquire` INCR（G→G+1）或冷重启 boot INCR。**T2 不 INCR**、A 让位不 INCR、无 DECR。B 校验「INCR 后 == intent+1」确立唯一写者身份。
2. **切换意图 = 切换前快照 G**：intent 值 = T2 时读到的 hub:gen；B INCR 后须 == intent+1，否则拒接管（复活 A 经 TOCTOU 抢在 B 前 INCR 的场景）。
3. **A 让位靠 intent 存在**（非 gen 推进——T2 不 INCR，gen 不因切而变）。
4. **abort 仅限启动 B 前**；一旦 B 启动，只能走完收尾。
5. **A 让位顺序 load-bearing**：surrendered 键先于 DEL lease。
6. **B 无待命态**：正常 hub 启动，数据面从头初始化（无静默/解除静默）。
7. **worker fencing 基于消息（live 路径）**：stale_gen 拒旧 + (symbol,ts) 去重。**warmup 无 gen 过滤**（盘后切换无同分钟双源 bar；gen 过滤是回归——盘中崩溃即触发 history 空洞）。
8. **单租约防双活 + 收尾校验 lease 持有者 == B**。
9. **systemd**：`Restart=on-failure` + `RestartPreventExitStatus=78`（不含 0）+ `%i` 注入 env（判据 7）。
10. **类型契约**：三键比较两侧强制 `int()`。

## 七、崩溃恢复判定表（gen 单点推进，intent=快照 G）

| intent | hub:gen | hub:lease | 判定 → 动作 |
|---|---|---|---|
| 无 | G | A 持有 | 稳态 → 无动作 |
| 无 | G | 无主 | A 崩溃 → 冷重启（14 号现行） |
| 有=G | G | A 持有 | confirm 已发、A 未让位 → 等 A 让位（T2c 轮询中，40s 超时告警） |
| 有=G | G | 无主 | A 已让位 → 编排器启动 B（T2d） |
| 有=G | G+1 | B 持有 | B 已接管 → 收尾（T2f） |
| 有=G | G+1 | 无主 | B 崩溃于接管后 → 冷重启 B（boot 有 env，闸放行）或等 systemd |
| 有=G | G+1 | 非 B（复活 A） | 复活 A 抢回（boot 闸漏网）→ 收尾校验告警 + 人工介入 |
| 无 | G+1 | B 持有 | 收尾完成 → 稳态（B 新写者） |

**表边界**：仅切换窗；收敛后回归 14 号现行机制。reaper = `switch.py check`（手动）+ intent TTL 300s 兜底，无常驻进程。**关键**：gen 单点推进后，切换窗内 gen 只有 G/G+1 两档（+1 只来自 B 的 INCR 或复活 A 的 TOCTOU），无 G+2 混乱。

## 八、水位线衔接 + 口径 diff（v10 内建）

- **XADD 保留 auto-id**；warmup 无 gen 过滤。
- `subscribe`：`xrevrange count=240` + from_watermark（ts）截断 + (vt_symbol,ts) 去重 + 未达断言（告警+降级 get_bars）。精确 ts 寻址挂账 M7。
- `_watermark` 连续无缺：交易时段边界锚。
- **口径 diff（深审 B P1-3 内建，M7 对账引擎雏形）**：切换次日盘后，`switch.py diff` 命令比对「B 首日流写 bar vs 腾讯回补 bar_1min」全量（非抽 N 只），超阈值（字段级容差）→ 告警；无告警才算切换验收完成。确认「日内策略消费 B 实时 bar」（hub_worker on_bar 吃 Valkey 流），B 口径偏差影响实时决策，故首日 diff 是必做非可选。

## 十、验收判据

1. **原子切**：confirm 后 A 让位 + B 接管，不双活。
2. **fencing 负例**：切后 A 旧 gen 消息被拒（stale_gen）。
3. **唯一写者校验**：注入「复活 A 经 TOCTOU 抢在 B 前 INCR」场景，B 校验失败拒接管。
4. **盘中 hub 崩溃重启后运行中 worker history 连续**（warmup 无 gen 过滤回归）。
5. **崩溃恢复**：判定表 8 行实测（失败注入）。
6. **confirm 返回契约**：四退出码 + stdout 四态可脚本化（可测）。
7. **systemd 单元 diff**（`%i` 注入 env + Restart 语义）+ **重暖机 bar 延迟非丢失**。
8. **口径 diff**：`switch.py diff` 全量比对 + 超阈值告警实测。
9. 全量 pytest 绿。

> **行为级验收边界**：判据 1/2/3/5 依赖 B 账号到位，到位前 mock 绿不可作收官依据——逐条标注「等 B 账号补验」。切换次日 9:16 首根 bar 告警列为 B 到位后首个运维项。
