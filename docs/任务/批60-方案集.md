# 批 60 方案集 · M5 流协议（v9 —— 四审四角色定稿）

> v9 缘起：v8.1 后发四角色交叉评审（金融专家/软件专家/金融小白加压两轮/软件小白）。两个 P0 的修复恰好都是**继续砍**：砍 `no_incr` 原语（B 自行 INCR，复用现行 NX+INCR）、砍 warmup gen 过滤（空集担忧且是回归）。B 实例显式角色化补上结构缺口。人验证 B 用独立连通测试（不碰三键）。

## 一、设计总纲（一句话）

**M5 = 「人配好 B 源并用独立连通测试验证后，盘后 confirm，系统原子切换：INCR gen、A 让位、B（待命进程）自行 INCR 接管、worker gen_jump 重暖机」。全部状态在 Valkey，零新表。**

## 二、人机分工（四审修订）

| 职责 | 谁 | 动作 |
|---|---|---|
| 配置 B 源 | 人 | `external_interface` 加 B 账号行（集成中心配置面） |
| **验证 B 连通** | 人 | **独立连通测试**（`test_xtp_connect.py` 形态：登录+订阅收数，**不碰 Valkey 三键、不起 hub 进程**——四审金专 P0-1：单租约下起 hub 试运行会被 `_lease_boot` NX 失败 SystemExit(3) 拦死，根本收不到行情，不可执行） |
| 切换时机 | 人 | **仅非交易时段**：交易日 15:10（XTP 会话关）后 ～ 次日 9:15（集合竞价）前 + 全天非交易日（四审金专 P2-7：竞价 9:15 起禁切——竞价快照聚齐口径是 58b 契约；周末可切，B 周一首次出 bar） |
| 原子切换 | 系统 | T2 单 Lua（读 gen→SET intent→INCR）→ A 让位 → B 接管 |
| 真空/口径兜底 | 系统 | 盘后权威回补（腾讯 15:20 beat，当日 bar_1min 唯一权威） |

## 三、Valkey 键（全部状态，零 DB）

```
hub:gen                        世代计数器（14 号已有）——INCR 单调，真源
hub:lease                      写权租约（14 号已有）——SET NX + Lua CAS，防双活
hub:switch:{stream_id}:intent  切换意图（本批新增）——Lua 原子设值=切换前快照 G，EX 300s
hub:switch:surrendered:{uuid} A 已让位标记——SET EX 600（改名单键化，避免与既有 hub:surrender 撞名）
```

## 四、A/B 实例模型（四审 P0-1 修复：B 显式角色）

- **A（现任）**：现行 `quant-md-hub@quant`，无特殊参数。
- **B（待命继任）**：unit 实例 `quant-md-hub@quant2` + env `HUB_INTERFACE_ROW=<B 的 external_interface 行 id>`（hub 侧新增实例→行绑定参数，现状 `get_broker` 只取第一行不可用于双实例）。
- **B 的待命模式**（复用一个 main.py，按 env 分角色）：
  - `_lease_boot` NX 失败**不退出**（区别于 A 的 SystemExit(3)），进入待命循环：每 5s 轮询 intent；
  - **数据面全静默**：不 XADD、不写 `hub:latest_tick:*`、不起 `_PGWriter`、**心跳键加实例后缀**（`quant:hb:md-hub:2`——现心跳是单键，待命 B 若写会让 worker 误判 A 活着）；
  - boot 前置闸修订：**只拦无角色进程**（A 复活无 env → intent 存在即 exit(3)）；B 有角色 env → 待命模式，不受闸拦。
- **人验证 B**（切换前）：独立连通测试（§二），不起 B 的 hub 进程——**B 待命进程在 confirm 前是否需要先起**：是（confirm 前起 B@quant2 待命，见 T1），但「验证 B 能收行情」不依赖 B 待命进程（连通测试独立做）。

## 五、切换时序（T2 单 Lua 原子化——四审软专 P1 修复）

```
T0 稳态：A 持 hub:lease(uuid_A) + hub:gen=G，写主流（auto-id，消息带 gen/seq/ts）。
T1 待命（人发起，切换日前任意时刻）：起 B@quant2（HUB_INTERFACE_ROW env）→ 待命模式
    （NX 失败不退、数据面全静默、每 5s 轮询 intent）。人用独立连通测试验证 B 账号可登录可收数。
T2 切前闸 + 原子切（人执行 switch.py confirm）：
    (a) 闸：查 live_task running，有则拒切（TOCTOU 窗盘后风险低，接受）
    (b) 单 Lua 原子：G_cur = GET hub:gen → SET intent = G_cur（记切换前快照）EX 300 → INCR hub:gen
        （单脚本消解 torn/双 confirm——双 confirm 第二次读到新 G_cur，自洽再切一代）
T3 让位与接管（A/B 各自轮询，5s 步）：
    A 轮询见 intent 存在且 gen > intent 值 → surrender：
        SET hub:switch:surrendered:{uuid_A} EX 600 → Lua CAS DEL hub:lease → 停订阅 → os._exit(0)
        （顺序 load-bearing：先 surrendered 再 DEL——先 DEL 则中途崩溃会被 on-failure 拉起竞速）
        （_lease_renew 每续期前 GET surrendered:{本uuid}，见则跳过续期）
    B 待命循环见 intent 存在且 gen > intent 值 → 接管：
        SET NX 抢 hub:lease（**现行原语，含 INCR**）→ gen 跳到 G+1
        → 校验 INCR 后 == intent 值 + 1（即「我是从快照 G 推进的唯一写者」：
           若复活 A 经 TOCTOU 已用 G+1 写过，B 的 INCR 得 G+2，校验失败 → 拒接管 + 告警）
        → 冻结写 gen = INCR 结果 → 解除静默（启 _PGWriter、心跳切主键）→ 写主流
T4 收尾（switch.py，超时 40s = lease TTL 30s + 两轮轮询）：
    DEL intent + DEL surrendered:{uuid_A}；核验 lease 持有者 uuid == B（防静默回退无标记）；
    核验并记录上一交易日 tencent_minute sync_log 状态进 sync_log 审计（回补检查点，金专 P1-6）。
    abort 约束：仅 INCR 前可 abort（DEL intent 即可）；gen 已推进后不可 abort 只能走完收尾
    （防 abort-DEL 与 A 让位在途竞态 → 双零写者）。
    次日开盘：B 首根 bar → worker gen_jump → 重暖机（**bar 延迟而非丢失**：max_ts 去重保留，
    gen_jump 那根仍驱动 on_bar——金专 P2-9 语义写明）。
```

## 六、关键不变式（v9 铁律）

1. **gen 单调永不回退**：推进 = INCR hub:gen（切换 T2 / 冷重启 boot / **B 接管 T3**——三处都用现行 NX+INCR，无 no_incr 新原语）。无 DECR。
2. **切换意图 = 切换前快照 G**（非目标 gen）：intent 记「从哪代切」，B 校验「INCR 后 == intent+1」确立唯一写者身份；intent EX 300s TTL 兜底残留。
3. **T2 单 Lua 原子**：读 gen→SET intent→INCR 一个脚本完成——torn/双 confirm/并发死锁全部消解。
4. **abort 仅限 INCR 前**；gen 推进后只能走完收尾。
5. **A 让位顺序 load-bearing**：surrendered 键先于 DEL lease；`_lease_renew` 前置查键。
6. **B 实例显式角色**：`HUB_INTERFACE_ROW` env + 待命模式数据面静默 + 心跳实例后缀；boot 闸只拦无角色进程。
7. **worker fencing 完全基于消息（live 路径）**：stale_gen 拒旧 + (symbol,ts) 去重。**warmup 不做 gen 过滤**（四审金专 P0-2 修复：盘后切换无同分钟双源 bar，混流担忧空集；且 gen 过滤是回归——盘中 hub 崩溃重启即触发 history 空洞，比切换更常见）。
8. **单租约防双活** + **收尾校验 lease 持有者 == B**（静默回退有标记）。
9. **systemd 依赖钉死**（验收 diff 检查）：`Restart=on-failure` + `RestartPreventExitStatus=78`（不含 0）——软专核验现状即满足；**A 进 failed 即终态**（StartLimitBurst=5/RestartSec=30 → ~150s 进 failed，早于 intent TTL；intent 过期后 unit 不自愈需人工 reset，写明）。
10. **类型契约**：三键比较两侧强制 `int()`（INCR 返 int、GET 返 str，`"5" != 5` 恒真——写进判据）。

## 七、崩溃恢复（intent 快照语义，简单穷举）

| intent | hub:gen | hub:lease | 判定 → 动作 |
|---|---|---|---|
| 无 | G | A 持有 | 稳态 → 无动作 |
| 无 | G | 无主 | A 崩溃 → 冷重启（现行 14 号机制）或 systemd 拉起 |
| 无 | G+n | B 持有 | 已收尾 → 稳态 |
| 无 | G+n | **非 B 的 uuid** | **静默回退**（收尾后 B 崩、A' 抢回）→ reaper 告警（收尾校验已挡大多数） |
| 有(=G) | G | A 持有 | torn（理论残留，单 Lua 后基本不可达）→ `switch.py check` 清 intent 或 TTL 过期 |
| 有(=G) | G+1 | A 持有 | 切换已推进、A 未让位 → 等 5s；超时 40s 人工冷切（**人此时不许离开终端**——手册写明） |
| 有(=G) | G+1 | 无主 | A 崩于让位前 → B 待命循环会抢（校验唯一写者）；复活 A 被闸拦 |
| 有(=G) | G+1 | B 持有 | 切换已生效 → switch.py 收尾 |

**表边界**：仅切换窗（T2 起至收尾止）；收敛后回归 14 号现行机制。reaper = `switch.py check`（手动命令）+ intent TTL 300s 兜底，无常驻进程。

## 八、水位线衔接（简化：warmup 不动，subscribe 最小实现）

- **XADD 保留 auto-id**；**warmup 不做 gen 过滤**（铁律 7——比 v8.1 更简）。
- `subscribe(sub, sink)`：`xrevrange count=240` + from_watermark（ts）截断 + (vt_symbol,ts) 去重 + 未达断言（最老回放条 ts ≤ watermark+1bar，否则告警+降级 get_bars）——精确 ts 寻址挂账 M7。
- `_watermark` 连续无缺：交易时段边界锚。
- **数据双时态声明**（四审金专 P2-8 落地）：日内策略消费 B 口径实时 bar，日终腾讯回补统一口径写 bar_1min——`bar.source` 列天然区分（A 段/B 段/回补段各记其源，切换日三段可溯——金小白第 5 条的机制本来就有，写清楚）。

## 十、验收判据

1. **原子切**：confirm 后 A 让位 + B 接管，不双活。
2. **fencing 负例**：切后 A 旧 gen 消息被拒（live 路径 stale_gen）。
3. **误抢防护**：复活 A（无角色 env）被闸拦；**B 唯一写者校验**（注入复活 A 已写 G+1 场景，B INCR 得 G+2 校验失败拒接管）。
4. **盘中 hub 崩溃重启后运行中 worker history 连续**（金专 P0-2 负例——warmup 无 gen 过滤回归验证）。
5. **崩溃恢复**：判定表 8 行实测（失败注入）。
6. **人机衔接**：confirm 命令 + 切前闸 + B 连通测试可独立执行。
7. **systemd 单元 diff** + **重暖机 bar 延迟非丢失**（gen_jump 那根仍驱动 on_bar）。
8. 全量 pytest 绿。

> **行为级验收边界**：判据 1/2/3/5 依赖 B 账号到位，**到位前 mock 绿不可作为收官依据**——批 60 交付时逐条标注「等 B 账号补验」。**切换次日首根 bar 延迟告警**（9:16 无集合竞价 bar 即响，金小白条件①）列为 B 到位后的首个运维项。
