# 批 60 方案集 · M5 流协议（v12 —— intent 记 target 修 boot 闸正切/反切矛盾）

> v11 缘起：v10 复审①（opus 正确性）抓出 5 个 P0。根子在两处：①「B 用现行 `_lease_acquire` + INCR 后校验」顺序错——`_lease_acquire` 先抢 lease 再 INCR，校验在 INCR 后则「拒接管时已污染 gen/lease」，且 B 崩溃重启落切换窗内就是 G+2、无法区分首接/重启；②v10 引入双实例却没处理「服务器重启后谁接管」（A 单元未 disable、无持久现任标记）。v11 用「原子 Lua 条件推进」+「active_instance 持久键」修这两根，并补 switch.py 权限/绝缘/假接管判据。

> **v12 缘起**：v11 的「boot 双重闸」自相矛盾——正切时 B（quant2）被 active_instance 闸拦（active_instance=quant≠quant2）、反切时 A（quant）被 intent 闸拦（无 env+intent 存在）。根因「切换方向」没建模。v12 修：intent 记 {snapshot, target}，boot 合并为单判定（intent.target 放行目标/拦截被切走者，active_instance 只兜「切换完成后服务器重启」）。

## 一、设计总纲（一句话）

**「人配好 B 源 + 连通测试 → 盘后 confirm（setsid 绝缘）→ SET intent{snapshot,target} → A 让位 → 启动 B（原子 Lua 条件推进接管）→ SET active_instance → worker 次日 gen_jump 重暖机」。全 Valkey，零新表，无待命态。**

## 二、人机分工（同 v10，仅补 confirm 绝缘）

| 职责 | 谁 | 动作 |
|---|---|---|
| 配置 B 源 | 人 | `external_interface` 加 B 行 + B 单元 drop-in 写 `HUB_INTERFACE_ROW=<B行id>` |
| 验证 B 连通 | 人 | 独立连通测试（不起 hub、不碰三键） |
| 切换时机 | 人 | 非交易时段（15:10 后 ~ 次日 9:15 前 + 全天非交易日） |
| 原子切换 | 系统 | switch.py confirm（setsid 绝缘、幂等可重跑）→ A 让位 → 启动 B → B 原子 Lua 接管 → SET active_instance |
| 口径兜底 | 系统 | 盘后腾讯回补 + B 首日口径 diff（`switch.py diff`） |

## 三、Valkey 键（全部状态，零 DB）

```
hub:gen                       世代计数器（14 号已有）——INCR 单调；推进=B 首接原子 Lua / 冷重启
hub:lease                     写权租约（14 号已有）——SET NX + Lua CAS，防双活
hub:switch:intent            切换意图——Lua SET={snapshot:G, target:目标实例名}，EX 300s（snapshot=切换前快照 gen，target=正切 quant2/反切 quant）
hub:switch:surrendered:{uuid} A 已让位标记——EX 600
hub:active_instance          现任实例名（quant/quant2，无 TTL）——重启仲裁：boot 读它 ≠ 自己则 exit
```

## 四、A/B 实例模型（v11 补重启仲裁 + 预定 uuid）

- **A（现任）**：`quant-md-hub@quant`，无 env，现行行为。
- **B（继任）**：`quant-md-hub@quant2`，drop-in 注入 `HUB_INTERFACE_ROW=<B行id>`（**不用 %i，避免实例名≠行id 命名空间错位**）+ `HUB_UUID=<switch.py 生成的 uuid>`（**B 抢 lease 用此 uuid，switch.py 由此知道 holder 是谁**——修 P1「holder==B 不可实现」）。
- **实例名来源**：main.py 由 systemd `%i` 注入 `INSTANCE_NAME` env 得知本实例名（quant/quant2），供 boot 单判定比对 intent.target / active_instance（账号选择仍走 HUB_INTERFACE_ROW，与实例名解耦）。
- **boot 单判定**（读 intent + active_instance + 本实例名）：
  1. **intent 存在**：`intent.target == 本实例名` → 放行（我是切换目标，正常启动）；`!= 本实例名` → exit(3)（切换窗内，被切走的实例复活，拦截）。**target 字段区分正切/反切：正切 target=quant2（拦复活 A、放行 B），反切 target=quant（拦复活 B、放行 A）——靠 target 不靠 env，A 无 env 但反切时是目标照样放行。**
  2. **intent 不存在**：`hub:active_instance` 存在且 ≠ 本实例名 → exit（切换已完成，非现任不抢回）；否则放行（正常冷启/首启）。**active_instance 只负责「切换完成后服务器重启」的兜底仲裁，不拦「切换窗内的目标实例」——正切 B 读 intent.target=quant2==自己 先放行，不会落到 active_instance 闸被 quant 误拦。**
- **B 无待命态**：切换时按需启动的正常 hub，全量初始化。
- **心跳**：B 写主键 `quant:hb:md-hub`（带 gen 字段，供假接管判据）。

## 五、切换时序（confirm setsid 绝缘、幂等可重跑）

```
T0 稳态：A 持 hub:lease + hub:gen=G + active_instance=quant，写主流。
T1 准备（人）：配 B 行 + B 单元 drop-in（HUB_INTERFACE_ROW + HUB_UUID）+ 连通测试。
T2 confirm（switch.py，setsid 绝缘，阻塞到出结果，幂等可重跑）：
    (a) 切前闸：live_task running 拒切（退出码 2）
    (b) 单 Lua：G_cur = GET hub:gen；SET hub:switch:intent = {snapshot: G_cur, target: "quant2"} EX 300（只 SET 不 INCR；反切时 target="quant"）
    (c) 等 A 让位：轮询 hub:lease 为空（A 让位 DEL 或 A 崩 30s TTL 过期；≤40s 超时→告警退出码 3）
    (d) 启动 B：经 quant-svc wrapper start quant-md-hub@quant2
    (e) 等 B 接管：hub:gen > G_cur 且 lease 非空 且 hub:lease 持有者 uuid == HUB_UUID（≤30s 超时→告警退出码 4）
    (f) 数据流证据（修 P0-5）：读 quant:hb:md-hub 心跳 gen 字段 == G_cur+1（B 真在写，非假接管）
    (g) 收尾：校验 hub:active_instance == quant2（B 原子 Lua 接管时已 SET）；DEL intent + surrendered:*；审计写 audit_log
    (h) 返回：成功打印「切到 B，gen G→G+1」（退出码 0）
T3 A 让位（T2c 窗口）：A 轮询见 intent 存在 → SET surrendered:{uuid_A} EX 600 → Lua CAS DEL lease → 退订 → os._exit(0)
    （顺序 load-bearing：先 surrendered 后 DEL）
T4 次日开盘：B 首根 bar → worker gen_jump → 重暖机（bar 延迟非丢失）
```

## 六、B 接管原子 Lua（修 P0-1/2 —— gen 推进+校验+抢 lease 绑定）

B 首接/重启共用一个 Lua `_lease_acquire_guarded(expected_gen)`（expected_gen = intent.snapshot + 1）：

```lua
-- KEYS[1]=hub:gen  KEYS[2]=hub:lease  KEYS[3]=hub:active_instance  ARGV[1]=uuid  ARGV[2]=expected_gen  ARGV[3]=target
local g = tonumber(redis.call('GET', KEYS[1]) or '0')
if g == ARGV[2] then
    -- 重启场景：gen 已是 G+1（上次 INCR 过），只抢 lease 不 INCR
    local ok = redis.call('SET', KEYS[2], ARGV[1], 'NX', 'EX', 30)
    if not ok then return -2 end
    redis.call('SET', KEYS[3], ARGV[3])   -- 现任=target（接管即现任，原子绑定）
    return ARGV[2]
elseif g == ARGV[2] - 1 then
    -- 首接场景：gen 还是快照 G，INCR + 抢 lease + SET 现任（原子绑定）
    local ok = redis.call('SET', KEYS[2], ARGV[1], 'NX', 'EX', 30)
    if not ok then return -2 end
    redis.call('INCR', KEYS[1])
    redis.call('SET', KEYS[3], ARGV[3])
    return ARGV[2]
else
    return -1   -- gen 既非 G 也非 G+1（被复活 A 污染）→ 拒接管，零污染（不 INCR 不抢 lease 不写 active_instance）
end
```

**关键**：校验在 INCR **之前**，失败不污染 gen/lease；gen 推进（INCR）与抢 lease（SET NX）绑定同一 Lua，无「INCR 后校验」的窗口。B 崩溃重启后 gen 已是 G+1，走「只抢 lease 不 INCR」分支，不再推进。

**A 冷重启**仍用现行 `_lease_acquire`（无条件 INCR），但 active_instance 闸（≠自己 exit）+ intent 闸（切换窗内 exit(3)）双重先拦。

## 七、关键不变式（v11 铁律）

1. **gen 单调**：推进 = B 首接原子 Lua INCR / 冷重启 boot INCR。无 DECR。B 重启（gen 已 G+1）不 INCR。
2. **切换意图 = {快照 G, 目标实例}**；B 的 expected_gen = intent.snapshot + 1。**target 建模切换方向**——正切/反切靠 target 区分（不靠 env），boot 闸据此放行目标/拦截被切走者。
3. **B 接管校验在 INCR 前**（原子 Lua 的 g==ARGV[2]-1 分支），失败零污染。
4. **A 让位靠 intent 存在**（T2 不 INCR）；顺序 surrendered→DEL lease load-bearing。
5. **active_instance 重启仲裁**：现任唯一标记，boot 读它 ≠ 自己 exit。**B 原子 Lua 接管即 SET active_instance=target（与 gen INCR+抢 lease 原子绑定，不依赖 switch.py 收尾——confirm 半途死也不影响现任标记）**；反切同理 SET 回 quant。
6. **worker fencing 基于消息**（stale_gen + (symbol,ts) 去重）；warmup 无 gen 过滤。
7. **单租约防双活** + 收尾校验 holder uuid == HUB_UUID。
8. **confirm setsid 绝缘 + 幂等可重跑**（半途死，重跑从判定表续）。
9. **systemd**：Restart=on-failure + RestartPreventExitStatus=78 + B 单元 drop-in（不用 %i）。
10. **类型契约**：gen/intent/心跳 gen 比较两侧强制 int()。

## 八、崩溃恢复判定表（补 G+2 与无主可达组合）

> 表按**正切方向**（现任=quant，继任=quant2，intent.target=quant2）列写；**反切镜像**（A/B 互换，target=quant，active_instance 反向）对称适用。「启动 B」=启动 intent.target，「非 B」=lease 持有者 uuid ≠ intent.target 实例的 uuid。

| active_instance | intent | hub:gen | hub:lease | 判定 → 动作 |
|---|---|---|---|---|
| quant | 无 | G | A 持有 | 稳态 |
| quant | 无 | G | 无主 | A 崩溃 → 冷重启（active_instance=quant 放行，INCR G+1） |
| quant | 无 | G+1 | 无主 | A 冷重启后崩（gen 已推、未写）→ 再冷重启（INCR G+2，worker 重暖机兜） |
| quant | 有=G | G | A 持有 | confirm 已发、A 未让位 → 等 A 让位（T2c，40s 超时） |
| quant | 有=G | G | 无主 | A 已让位 → 启动 B（T2d） |
| quant | 有=G | G+1 | B 持有 | B 已接管 → 收尾（T2g：校验 active_instance=quant2，B 原子 Lua 已 SET） |
| quant | 有=G | G+1 | 非 B | 复活 A 抢回 → 收尾校验告警 + 人工介入 |
| quant | 有=G | G+2 | B 持有 | B 重启后接管（gen 已 G+2，boot 用 expected_gen=G+1 走「只抢 lease」分支——见 §六注） |
| quant2 | 无 | G+1 | B 持有 | 收尾完成 → 稳态（B 新写者） |
| quant2 | 无 | G+1 | 无主 | B 崩溃 → 冷重启 B（active_instance=quant2 放行，boot 闸放行，只抢 lease 不 INCR 因 gen 已 G+1） |

> §六注：B 重启时 expected_gen=intent.snapshot+1=G+1，而 gen 若因 A 冷重启已到 G+2，则原子 Lua 的 `g==ARGV[2]-1` 不成立（g=G+2≠G+1）、`g==ARGV[2]` 也不成立（G+2≠G+1）→ 走 else 拒接管。**此态（gen=G+2 且 intent 残留）由「intent EX 300s TTL 过期 + active_instance 已=quant2 + B 重启走 normal `_lease_acquire`」收敛**：intent 过期后 B 不再走 guarded（expected_gen 无意义），走 normal `_lease_acquire`（无条件 INCR 继续推进），worker 重暖机兜底。**「有=G|G+2|*」的收敛终局=回归 active_instance=quant2 稳态，中间态由 worker 重暖机 + 盘后回补兜，不要求判定表逐格覆盖 G+2（那是 gen 单点推进被 A 冷重启打破后的冗余代）**。

## 十、验收判据

1. 原子切：confirm 后 A 让位 + B 接管，不双活。
2. fencing 负例：切后 A 旧 gen 消息被拒（stale_gen）。
3. 原子 Lua 三态：首接（INCR+抢 lease）/重启（只抢 lease）/污染（拒，零污染）——单测注入三态。
4. 重启仲裁：SET active_instance 后服务器重启，A 单元不抢回 lease（active_instance 闸）。
5. 盘中 hub 崩溃重启后运行中 worker history 连续。
6. confirm 返回契约（四退出码 + stdout 四态）+ setsid 绝缘 + 幂等重跑（半途杀 confirm → 重跑续）。
7. systemd 单元 diff（B 单元 drop-in，不用 %i）+ 重暖机 bar 延迟非丢失。
8. 口径 diff：switch.py diff 全量比对 + 超阈值告警。
9. 全量 pytest 绿。
