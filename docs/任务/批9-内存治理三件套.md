## B. zram（OS 层压缩内存换页，michael 执行）

### B1 现状（2026-09-07 23:47 实测）
- `/swapfile` 2G file，priority **-2**，已用 615MB；`vm.swappiness=0`（**来源待查**，见 B4 前置）
- 内核 `5.10.134-19.8.al8` 含 `zram.ko` ✓；EPEL8 有 `zram-generator-1.1.2-2.el8` ✓（未装）

### B2 方案
1. 装 `zram-generator`，配置 `/etc/systemd/zram-generator.conf`：
   ```ini
   [zram0]
   zram-size = min(ram / 2, 1536)
   compression-algorithm = zstd
   swap-priority = 100
   ```
   （1.87G 机器 → zram ~935M；swapfile 保底 -2 不动，溢出兜底。键名/表达式经 A 盲审对照官方 man v1.1.2 核实无误；swap-priority 缺省本就 100，显式写无害）
2. `/etc/sysctl.d/99-quant-zram.conf`：
   ```ini
   vm.swappiness = 100
   vm.page-cluster = 0
   ```
   （swappiness：当前 0=near-OOM 才猛换——正是本次「30 分钟 54MB 突发换出」的行为；zram 换页=内存内解压 μs 级，高 swappiness 是官方推荐用法。page-cluster=0：zram 随机访问禁 swap 预读——A 盲审 P2-3；混合 swapfile 场景预读对磁盘侧略有损失，此机磁盘 swap 仅兜底，取 0）

### B3 风险
- swappiness 100 是行为变化：换页更积极，但目标是 zram（无磁盘 IO）；极端压力仍溢 swapfile（保底语义不变）。
- zstd 压缩 CPU 开销 <1%（5.10 内核实测普遍值；此机 CPU 空闲 90%+）。
- **存量 615MB 磁盘 swap 页不主动清理**（B 盲审 P2）：zram 只接新换页，既有换出页仍驻磁盘直到被访问换入。不做 `swapoff/swapon /swapfile` 清存量——available 仅 274M，回灌 615MB 有 OOM 风险，得不偿失。**验收 3 的改善可能滞后**（热页逐次回内存后趋稳）。
- 不影响 PG/服务进程任何配置；纯内核层。

### B4 命令五要素（michael 执行）
- 【机器】quant-prod 120.24.235.98（ssh michael@）
- 【账号】michael（sudo，密码指针见记忆 server-info / 部署机制，禁明文）
- 【前置】①盘后或非交易时段 ②先跑来源查证（A 盲审 P1-2）：
  ```bash
  grep -r swappiness /etc/sysctl.conf /etc/sysctl.d/ 2>/dev/null   # 记录 0 的来源；无输出=临时设置
  grep -r zstd /lib/modules/$(uname -r)/modules.builtinmodinfo 2>/dev/null | head -1 || modinfo zram | grep -i parm   # zstd 可用性预检（不可用则 conf 改 lzo-rle）
  ```
- 【命令】
  ```bash
  sudo dnf install -y zram-generator
  sudo tee /etc/systemd/zram-generator.conf <<'EOF'
  [zram0]
  zram-size = min(ram / 2, 1536)
  compression-algorithm = zstd
  swap-priority = 100
  EOF
  sudo systemctl daemon-reload          # v2：generator 只在 boot/daemon-reload 读 conf（双盲审同判 P1）
  sudo systemctl start systemd-zram-setup@zram0
  echo -e 'vm.swappiness = 100\nvm.page-cluster = 0' | sudo tee /etc/sysctl.d/99-quant-zram.conf
  sudo sysctl --system
  ```
- 【验证】`swapon --show`（zram0 prio 100 在列、swapfile -2 保留）+ `zramctl`（algo zstd）+ `cat /proc/sys/vm/swappiness` 与 `/proc/sys/vm/page-cluster` 实值
- 【可选彩排】（B 盲审 P2）本地 Fedora 彩排副本先跑一遍同命令序列验证流程（zram-generator 语法两机同源）

### B5 验收
1. zram0 生效 prio 100，swapfile 保持 -2
2. 观察日：`zramctl` 压缩比 ≥2.5:1；swapfile 占用不再单边增长（新换页进 zram）
3. 症状回归验证：DataManage 刷新服务器侧 <3s（journal 时间戳法；**存量页滞后预期见 B3**，观察窗放宽至 1-2 个交易日）
4. 无 OOM、服务零重启（quant-hbcheck gen 对账）

### B6 回滚
```bash
sudo swapoff /dev/zram0 && sudo systemctl stop systemd-zram-setup@zram0
sudo dnf remove -y zram-generator && sudo rm -f /etc/systemd/zram-generator.conf /etc/sysctl.d/99-quant-zram.conf
sudo systemctl daemon-reload          # v2：清残留 unit（B 盲审 P2）
sudo sysctl -w vm.swappiness=<B4 前置查得的来源值>   # v2：显式恢复非 --system（A 盲审 P1-2：0 若无持久化来源，--system 会落内核默认 60）
```
（换出的页 swapoff 时自动回内存；若 available 不足先确认无压力时段执行）
