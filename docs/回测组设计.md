# 回测组设计（多标的并行/串行 + 两层级展示）

> 回测既可单只跑，也可一组（多只）并行/串行。两层级：回测任务（组）级 + 标的回测级。组完有汇总展示。单只是组的特例（N=1）。
>
> **平台化集成（2026-08-08 PT1）**：回测组纳入统一 `tasks` 表（PT1 后台任务管理）。`backtest_runs.task_id` 关联 `tasks.id`（task.type='backtest'，tasks 管 status/progress/heartbeat/logs，backtest_runs/symbols 管回测业务：symbols/mode/summary/result JSON）。回测任务卡死检测 + 失败告警（PT7 notify_on_failure）复用 tasks 机制。

## 1. 概念与层级

| 层级 | 实体 | 说明 |
|---|---|---|
| **任务级（run）** | `backtest_run` | 一次回测请求：1 策略 + N 标的 + 参数 + 执行模式 |
| **标的级（symbol）** | `backtest_symbol` | run 内单只标的的回测（BacktestEngine 跑一次）|

- **单只**：run 含 1 标的
- **组并行**：run 含 N 标的，Celery group 并发
- **组串行**：run 含 N 标的，Celery chain 顺序

## 2. 数据库

### 2.1 标的池（Pool，复用现有 Pool.vue 前端）
```sql
-- pools：标的池
CREATE TABLE pools (
  id TEXT PRIMARY KEY,           -- 如 "etf_top10"
  name TEXT NOT NULL,
  category TEXT,                 -- etf/cb/astock
  description TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);
-- pool_symbols：池内标的
CREATE TABLE pool_symbols (
  id BIGSERIAL PRIMARY KEY,
  pool_id TEXT REFERENCES pools(id) ON DELETE CASCADE,
  symbol TEXT NOT NULL,          -- vt_symbol 510050.SSE
  UNIQUE(pool_id, symbol)
);
```

### 2.2 回测任务（两层级，替代之前单表 backtest_tasks）
```sql
-- backtest_runs：任务级（组）
CREATE TABLE backtest_runs (
  id BIGSERIAL PRIMARY KEY,
  strategy_config_id TEXT,       -- 策略
  symbols JSON NOT NULL,         -- ["510050.SSE","159801.SZ"]（手选或从 pool 展开）
  params JSON NOT NULL,          -- {start,end,capital,period,commission,slippage}
  mode TEXT NOT NULL DEFAULT 'single',  -- single/parallel/serial
  status TEXT NOT NULL DEFAULT 'pending',  -- pending/running/done/error
  summary_metrics JSON,          -- 汇总指标（平均+排名，所有标的完算）
  created_at TIMESTAMPTZ DEFAULT now(),
  finished_at TIMESTAMPTZ
);
-- backtest_symbols：标的级（单只结果）
CREATE TABLE backtest_symbols (
  id BIGSERIAL PRIMARY KEY,
  run_id BIGINT REFERENCES backtest_runs(id) ON DELETE CASCADE,
  symbol TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',  -- pending/running/done/error
  result JSON,                   -- {bars,trades,positions,equity,metrics,logs}
  created_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(run_id, symbol)
);
```

## 3. 后端功能

### 3.1 标的池端点
- `GET /api/pool` 列池
- `POST /api/pool` 建池（id/name/category/description）
- `PUT /api/pool/{id}` 改
- `DELETE /api/pool/{id}` 删
- `GET /api/pool/{id}/symbols` 池内标的
- `POST /api/pool/{id}/symbols` 加标的（body: {symbols: [...]})
- `DELETE /api/pool/{id}/symbols/{symbol}` 删标的

### 3.2 回测端点
| 端点 | 说明 |
|---|---|
| `POST /api/backtest` | 启动 run（body: `strategy_config_id, symbols/pool_id, params, mode`）-> `{run_id}` |
| `GET /api/backtest` | 列 run（任务列表）|
| `GET /api/backtest/{run_id}` | run 详情（标的列表 + 各状态 + 汇总）|
| `GET /api/backtest/{run_id}/{symbol}/stream` | SSE 单标的实时推送 |
| `GET /api/backtest/symbol/{symbol_id}` | 单标的完整结果 JSON（历史复看）|

### 3.3 Celery 任务设计
```
backtest_run_task(run_id):
  读 backtest_runs（策略+标的+参数+mode）
  写 backtest_symbols（N 行 pending）
  按 mode 分发：
    single: backtest_symbol_task.delay(run_id, symbol)
    parallel: group([backtest_symbol_task.s(run_id, s) for s in symbols])()
    serial: chain(*[backtest_symbol_task.s(run_id, s) for s in symbols])()
  更新 run.status=running

backtest_symbol_task(run_id, symbol):
  读 run（策略+参数）+ PG bars（symbol）
  BacktestEngine.run(config, bars, on_bar_callback=publish_valkey)
    每bar: publish Valkey backtest:run:{run_id}:{symbol} = {progress,bar,trade,position,equity,log}
  完: 存 backtest_symbols.result + status=done
  检查 run 所有 symbol 完 -> 算 summary_metrics + 更新 backtest_runs.status=done
```

### 3.4 Valkey pub/sub 通道
- 单标的实时：`backtest:run:{run_id}:{symbol}`（每bar 帧）
- run 级状态：`backtest:run:{run_id}:status`（symbol 状态变化 + 汇总完）

### 3.5 SSE 端点（web-api）
```
GET /api/backtest/{run_id}/{symbol}/stream:
  EventSource 订阅
  web-api subscribe Valkey backtest:run:{run_id}:{symbol}
  收到帧推前端（data: {progress,bar,trade,position,equity,log}）
  标的完推最终 result + close

GET /api/backtest/{run_id}/status/stream（可选）:
  run 级 SSE（symbol 状态变化 + 汇总）
  或前端轮询 GET /api/backtest/{run_id}
```

## 4. 线程/同步设计

### 4.1 执行线程
- **run 任务**：Celery worker（1 个任务，分发 N 子任务）
- **symbol 子任务**：Celery worker（N 个并发或串行）
- **BacktestEngine.run**：子任务内同步跑（每bar回调 publish）
- **web-api SSE**：独立请求线程（FastAPI StreamingResponse），subscribe Valkey

### 4.2 同步
- run 启动 -> 写 backtest_symbols pending -> 分发子任务 -> run.status=running
- 每子任务完 -> 更新 backtest_symbols.status=done + result
- 最后一个子任务完 -> 算 summary_metrics + run.status=done（Celery chord 回调 or 子任务内检查计数）
- 前端 SSE 订阅单标的实时 + 轮询/SSE run 状态

### 4.3 并发控制
- parallel：Celery worker_concurrency 限制（服务器 2 核，并发 2-4）
- serial：chain 顺序
- 单只：1 子任务

## 6. 流程

### 6.1 启动回测
1. 前端选策略 + 标的（手选 or 选标的池展开）+ 参数 + 模式
2. `POST /api/backtest` -> run_id
3. 写 backtest_runs + backtest_symbols（N pending）
4. Celery backtest_run_task 分发子任务

### 6.2 执行 + 推送
5. 子任务跑 BacktestEngine，每bar publish Valkey
6. 前端 SSE 订阅选中标的 + 轮询 run 状态
7. 每标的完存 backtest_symbols
8. 全完算 summary_metrics + run.status=done

### 6.3 复看
9. `GET /api/backtest/{run_id}` -> 标的列表 + 汇总
10. 点标的 -> `GET /api/backtest/symbol/{id}` -> 完整结果静态渲染

## 8. 检查与推演

### 推演 1：单只回测
1. 选策略A + 1 标的 510050 + 参数 + mode=single
2. POST /api/backtest -> run_id=1，backtest_runs(mode=single, symbols=["510050"])
3. backtest_symbol_task(1, "510050") 跑 BacktestEngine
4. 每bar publish `backtest:run:1:510050`
5. 前端 SSE 订阅 -> 实时图
6. 完存 backtest_symbols + run.summary_metrics（单只指标）
7. ✅ 单只是组 N=1，流程一致

### 推演 2：组并行（5 只 ETF）
1. 选策略A + 标的池 etf_top5（5 只）+ 参数 + mode=parallel
2. POST -> run_id=2，backtest_runs(mode=parallel, symbols=[5 只])
3. Celery group 5 子任务并发（worker_concurrency 限制 2-4 实际并发）
4. 每子任务跑 BacktestEngine + publish per symbol
5. 前端 run 详情看 5 标的进度 + 选中某只看实时
6. 每完存 backtest_symbols
7. 5 只全完 -> summary_metrics（平均+排名）+ run.done
8. 前端 run 详情汇总显示 + 选任一看结果
9. ✅ 流程无矛盾

### 推演 3：组串行
- 同并行但 Celery chain 顺序跑（前一个完再下一个）
- ✅ 流程一致，只是执行顺序
