# 多市场混合量化交易平台 — 项目需求与解决方案书（定稿）

> 本文为共创定稿的需求与方案。模块级详细设计见 `docs/architecture/`（00–11），以架构文档为权威实现依据。

## 1. 项目概述

本项目搭建一套**私有化部署、多资产覆盖、读写权限隔离、多模型并行、AI 辅助、带 Web 可视化管理后台与飞书移动干预通道**的个人量化交易平台。平台同时支持 A股人工分析决策、场内 T+0 资产自动化交易、加密货币永续合约自动化交易，全程部署于私有云服务器，支持策略热更新、风控统一管控、数据自主存储，满足长期迭代、多模型扩展、安全可控的量化交易需求。

平台核心差异化：**A股仅分析、不自动下单；可转债/ETF/数字货币全自动交易**，严格区分风险层级，兼顾主观研判优势与程序化执行优势。

**定位声明**：本平台为**单系统多用户 RBAC**（Admin/Operator/Viewer 共享同一套数据与交易系统，仅权限分层），**非多租户**。多组织/多租户需求的产品形态是**售出独立实例**（一套软件 / 配置好的主机 / 配置好的 VPS），而非单系统内隔离。

## 2. 需求梳理

### 2.1 交易标的范围

- **A股个股**：仅做日级别、分钟级别数据分析、选股、行情研判、输出操作建议，**禁止任何自动交易**，仅辅助人工决策
- **国内 T+0 资产**：可转债、场内 ETF，支持全自动程序化 T+0 交易、波段策略、网格策略
- **加密货币**：币安、OKX 主流大币种（BTC/ETH）永续合约，支持自动化 CTA、网格、对冲等策略交易
- 可扩展性：支持后续新增各类金融标的与交易模型

### 2.2 运行与部署需求

- 运行环境：**Amazon Linux 2023** 云服务器，7×24h 常驻运行
- 架构要求：多模型独立运行、互不干扰、单独启停、独立参数配置
- 数据能力：统一接入行情数据、历史数据回存、实时行情推送
- 运维能力：Web 管理后台 + 飞书移动干预，可视化管控所有策略、账户、风控、日志、盈亏
- AI 能力：国内模型辅助分析（研报/公告/可转债条款解读、盘后报告、自然语言查询），**不握交易决策权**
- **多语言国际化**：Web 前端按浏览器语言自动切换中/英文；LLM 回复/飞书回复/告警推送按用户语言偏好输出；日志统一英文。检测依据：Web 端 `navigator.language`，服务端 `LANG` 环境变量，飞书用户 locale，DB 可配用户偏好覆盖默认检测。

### 2.3 核心功能约束

- 权限隔离：A股模块**只读无交易权限**，三重保障（代码层注销下单函数 / Adapter 永久 raise / AI 工具白名单不含下单）
- 自动交易：可转债、ETF、加密合约完全自动化开仓、平仓、止损、调仓
- 多策略隔离：不同标的、不同策略独立进程运行，单点故障不扩散
- 安全要求：API 密钥加密存储、服务器私有化部署、无第三方托管数据与资金
- 风控要求：全局总风控 + 分市场独立风控双层防护
- 访问控制：单系统多用户 RBAC（Admin/Operator/Viewer），非多租户

## 3. 最终技术选型（定稿）

结合需求，摒弃自研底层、摒弃商用付费平台，采用国内最成熟、适配度最高、二次开发成本最低的开源组合 + 自建抽象/AI 层。

### 3.1 整体架构选型

**底层交易内核：VNPY（VeighNa）**
- 原生自带多引擎、多策略隔离、交易网关、风控、日志、订单管理
- 原生支持实盘、回测、模拟盘，适配国内券商规则与币圈 API 规则
- 回测引擎 `CtaBacktestingEngine` 与实盘 `CtaTemplate` 共用模板，策略代码回测/实盘同构

**场内 T+0 实盘通道：中泰证券 XTP + vnpy_xtp**
- 国内唯一**原生 Linux**证券极速交易 SDK，不用 Windows 机器
- 支持可转债、ETF、股票、债券、回购
- 个人户接入，需开户 + 签 XTP 协议（资产门槛以中泰营业部为准，待确认）；Linux 版 SDK 必须在 Amazon Linux 2023 上验证/构建

**加密合约实盘通道：vnpy 加密网关（币安/OKX）**
- REST + WebSocket，Linux 原生无障碍
- 永续合约开平仓、杠杆、止盈止损、资金费率

**Web 管理后台：自建 FastAPI + Vue3 + Element Plus**
- vnpy-webstrader 仅作参考，自建定制更灵活
- 支持策略启停、参数在线修改、持仓看板、盈亏曲线、日志、风控面板、自然语言查询

**飞书/Lark 移动干预通道：自建对接层**
- 飞书机器人做 AI 动态查询 + 紧急处理（一键熔断/停策略），带交互确认
- 与 Web 共用工具集，操作类工具仅飞书开放且需确认

**AI 层：自建 LLM 网关 + 国内模型**
- 模型只用国内：DeepSeek（常规/复杂）+ GLM（备/复杂），**不接 Anthropic/OpenAI 运行期**
- 自建薄网关做路由 + 容灾 + 用量 + 工具白名单（约 150 行 Python，两家 OpenAI 兼容接口）
- 嵌入/RAG 用 bge-m3，跑独立 worker 进程 + 盘后批量，不进交易热路径
- 向量库用 pgvector（复用 PostgreSQL，不引 Milvus）

### 3.2 数据层选型

- **数据源**：Tushare Pro（主，分钟线需 2000 积分，一次性购买可接受）+ AkShare（免费补缺与实时增量）+ 币安/OKX WebSocket
- **存储**：PostgreSQL（业务 + 中低频时序 K 线 + pgvector 向量）+ Valkey（Redis 协议兼容，实时盘口/分钟K/策略状态/队列）
- **弃用**：QUANTAXIS（停更 + 兼容坑，改为 Tushare/AkShare + 自建清洗层）；弃用 TimescaleDB 与重型向量库（轻量化）
- **关键设计**：回测历史数据 schema 现在就和未来 XTP 实时行情对齐，20 天等待期回测结果零迁移切 live

### 3.3 技术栈明细

- 开发语言：Python 3.10（venv，不用 3.14，vnpy/vnpy_xtp 无预编译 wheel）
- 后端：FastAPI + VNPY
- 前端：Vue3 + Element Plus
- 数据库：PostgreSQL 18 + pgvector + Valkey
- 任务调度：Celery + Valkey（定时选股、数据更新、盘后报告）
- 部署：Python venv + systemd 进程守护，**Amazon Linux 2023**（开发机 Fedora，同 dnf/RPM 系），无 Docker

## 4. 系统整体架构（五层解耦）

分层自上而下：前端展示层 → 调度网关层（含 AI 网关/飞书/告警）→ 策略模型层 → 风控中心 → 数据中台层 → 基础设施层。模块级设计见 `docs/architecture/00-总体设计.md`。

### 4.1 前端 Web 可视化层（08）
账户管理、策略管理（启停/参数在线改/因子选择+权重+DSL）、A股分析看板、实盘交易看板、风控中心、日志告警、AI 助手（自然语言查询，只读）。

### 4.2 调度与网关层
- **调度层（09）**：Celery + beat，定时选股/数据增量/盘后报告/分时休眠/任务限流，时区 Asia/Shanghai
- **LLM 网关（01）**：国内模型统一入口，路由+容灾+用量+工具白名单分层（读/操作仅飞书带确认/永不注册下单）
- **飞书/Lark 对接层（11）**：移动干预通道，AI 动态查询 + 紧急处理（带确认），3s 异步回复
- **告警/通知（10）**：企业微信群机器人 + Discord 为主，Server 酱备用，分级路由 + 配额聚合

### 4.3 策略模型层（02 统一框架 + 03/04/05 引擎）
统一 `Strategy` 基类 + `Factor` 注册制 + `SignalAggregator` + `ExecutionAdapter`（A股 raise / XTP / 加密），配置驱动（Web 选因子+权重+DSL），非硬编码。
- **A股只读分析引擎（03）**：日线选股 + 分钟级研判，输出建议存库，三重禁下单
- **可转债/ETF T+0 引擎（04）**：vnpy + vnpy_xtp，双低轮动/网格/均值回归
- **加密永续合约引擎（05）**：vnpy + 币安/OKX，CTA/网格/对冲，专属风控（杠杆/逐仓/插针/断线冻结）

### 4.4 风控中心（07）
全局总风控 + 分市场独立风控双层。所有自动交易下单前必过 `check_order`；一键熔断状态存 Valkey（禁止内存缓存，多进程/重启不丢）；Operator+Admin 可 halt，resume 仅 Admin。

### 4.5 统一数据中台层（06）
Tushare/AkShare 拉取 + 清洗复权/停牌/异常过滤 + PostgreSQL（含 pgvector）+ Valkey 实时。统一 `vt_symbol` 编码，回测与实盘 schema 对齐。交易日历用 Tushare `trade_cal`。

### 4.6 基础设施层
Amazon Linux 2023 / Python3.10 venv / systemd 守护 / 定时备份。

## 5. 核心风控体系（三层防护）

- **系统级全局风控**：一键熔断（任何人 Operator+ 可触发）、总回撤、单日亏损（仅平不开）
- **场内资产风控**：单标的仓位上限、单笔最大亏损、日内交易次数限制、严格止损
- **加密合约专属风控**：固定低杠杆上限、逐仓隔离、插针行情自动撤单、爆仓预警、单日亏损熔断、断线策略冻结
- **A股安全兜底**：代码层 + Adapter + AI 工具白名单三重禁下单，物理无任何触发可能

## 6. 访问控制（RBAC，单系统多用户）

单系统多用户，三角色共享数据，仅权限分层，**非多租户**：

| 角色 | Web | 飞书 | 系统 |
|---|---|---|---|
| Viewer | 只读 | 读类工具 | 无 |
| Operator | 读+策略启停+熔断 | 读+操作类（带确认） | 无 |
| Admin | 全部+密钥+风控规则 | 全部（操作带确认） | 全部 |

API 密钥系统级托管，仅 Admin 管理；halt 任何人可（安全冗余），resume 仅 Admin；所有 mutation 写 `audit_log(actor)`；LLM 工具按角色 per-request 过滤。

## 7. 分阶段落地

### 阶段1：服务器基础环境（1-3 天）
Amazon Linux 2023 配置防火墙/SSH；Python3.10 venv + 全套依赖；部署 PostgreSQL+pgvector + Valkey；申请券商/币安/OKX/Tushare 凭证。

### 阶段2：数据中台（3-5 天）
Tushare/AkShare 数据服务（A 股日线/分钟线/基本面/可转债条款/交易日历）；vnpy 数据服务（可转债/ETF/加密实时）；清洗复权/历史回灌；schema 对齐 XTP 实时。

### 阶段3：交易网关与权限隔离（5 天）
部署三市场网关；禁用 A 股所有下单接口；调试可转债/ETF/加密查询/下单/撤单；XTP SDK 在 amzn2023 上编译验证；API 密钥加密存储 + IP 白名单。

### 阶段4：策略开发与回测（10-20 天）
A 股选股+分钟级分析模型；可转债/ETF T+0 策略回测+参数优化；BTC/ETH 永续策略+风控调参；策略独立进程注册，后台启停管控。

### 阶段5：Web 后台 + 飞书 + AI 层（7 天）
自建 FastAPI+Vue3 前后端；定制 A 股分析看板；调试策略/账户/风控/日志面板；飞书机器人 + LLM 网关 + RBAC；全站联调。

### 阶段6：灰度试运行与长期迭代
小资金试运行自动交易模块，验证滑点/手续费/实盘稳定性；持续优化策略与风控；配置数据备份/自动重启/异常告警；按需新增标的与策略。

## 8. 扩展性

- 标的扩展：新增商品期货、美股、国债等，仅需新增网关与策略
- 模型扩展：支持机器学习/AI 预测接入分析与交易体系
- 算力扩展：支持多服务器分布式部署（数据/策略/Web 节点拆分，vnpy 原生 RPC + Valkey 队列）
- 多租户扩展：**不内建**，以售出独立实例形态满足

## 9. Amazon Linux 2023 轻量化部署方案（无 Docker）

### 9.1 venv 与容器的区别
- **venv**：仅隔离 Python 依赖，代码层级隔离，无虚拟化开销，极致轻量
- **Docker**：系统级隔离，有虚拟化冗余，对低配资源不友好，本项目全程舍弃
- 所有框架（VNPY/vnpy_xtp/加密网关/自建层）原生支持 venv 裸机部署

### 9.2 分布式能力
- **VNPY**：内置 RPC 分布式通信 + 多进程策略隔离，支持多节点拆分（行情/策略/交易/Web 节点），单策略故障不扩散
- **Celery**：分布式任务队列，数据/选股任务可拆分多节点并行
- **自建 Web/飞书/LLM 网关**：前后端分离 + 进程内模块，可独立部署低配节点

### 9.3 资源占用评估（裸机 venv 生产实测，无容器冗余）

**硬盘**：系统+依赖 ≤10GB；A 股/可转债/ETF 日线+分钟线 1 年 ≤15GB；币圈 K 线 ≤5GB；业务数据 ≤5GB；**最低 40GB SSD，推荐 60GB**。

**CPU/内存两档：**

| 档位 | CPU/内存 | 适配 | 占用 |
|---|---|---|---|
| 最小投产 | 2核/4GB | A股分析+低频T+0+低频CTA/网格 | 空载1.2-1.8GB，峰值≤3GB |
| 标准稳定 | 4核/8GB | 全模型并行+全量行情+多策略 | 空载2-2.5GB，峰值≤6GB |

**各模块**：数据中台 500-800MB；vnpy 三市场网关 300-500MB；单策略进程 200-500MB；Web+FastAPI 200-300MB；PG+Valkey+pgvector ≤1GB；LLM 网关进程内；bge-m3 独立 worker（盘后批量，不占交易期资源）。

### 9.4 分布式拆分（资源不足扩容）
1. **数据节点**：数据中台 + PG + Valkey，专职数据采集/清洗/存储
2. **交易策略节点**：vnpy 核心 + 三市场策略 + 风控，专职行情运算/信号/执行
3. **Web 管控节点**：最低配，可视化+配置+日志+一键风控
跨节点用 RPC + Valkey 队列，无代码改造。

### 9.5 低配资源优化
轻量化数据库（PG 统一，弃 TimescaleDB）；行情按需订阅（关非必要 Tick）；分时休眠（A 股/场内非交易时段暂停运算，仅增量+风控）；日志分级+过期清理；Celery 限流；嵌入模型独立进程盘后批量。

### 9.6 生产级部署规范
全程 venv 隔离；systemd 开机自启+异常重启+崩溃告警；API 密钥本地加密 + 交易所 IP 白名单 + 防火墙仅必要端口；数据库定时备份 + 日志持久化 + 异常熔断。

### 9.7 vnpy_xtp 编译踩坑（Amazon Linux 2023）
```bash
sudo dnf install -y gcc-c++ make openssl-devel python3.10-devel
# XTP .so 必须在 amzn2023 上验证；中泰 SDK 若分 CentOS/Ubuntu 版，选 CentOS 版（amzn2023 与 RHEL 系兼容）
# 报 GLIBCXX_3.4.XX not found → 换匹配版本 .so 或在 amzn2023 重编 vnpy_xtp
export LD_LIBRARY_PATH=/opt/xtp/lib   # 或写进 systemd Environment=
```
XTP SDK 具体分发形态待中泰确认后回填。

## 10. 方案总结

本方案基于**成熟开源生态（VNPY + vnpy_xtp + vnpy 加密网关 + VeighNa 回测）+ 自建抽象/AI/飞书/RBAC 层 + 轻量化无容器部署**，适配 Amazon Linux 2023 云服务器。依托 venv 环境隔离、systemd 进程守护实现稳定运行，无重复造轮子、资源占用极低、支持分布式扩展。完美匹配「A股纯分析、场内 T+0 + 币圈合约全自动交易、云服务器部署、Web + 飞书双通道管理、多模型隔离、AI 辅助、单系统 RBAC」的全部核心需求。系统架构分层清晰、风控完善、权限三重隔离、可长期迭代扩展，是个人私有化量化平台的最优落地适配方案。
