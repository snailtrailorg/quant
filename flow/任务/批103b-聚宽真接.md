### 0.1 ⚠️ SDK 边界检查**不对称**（设计级发现 → handler 自夹 start）

实测钉死规则：**只检查 `end_date ∈ [权限起, 权限止]`，`start_date` 完全不检查。**

```
2020-01-01 ~ 2026-01-01  →  放行！返回 1455 行（自 2020-01-02 起，无视权限起点）
2026-06-25 ~ 2026-07-15  →  拒（end > 权限止）
2025-05-01 ~ 2025-06-20  →  拒（end < 权限起）
```

⇒ 「靠 SDK 硬拒兜底」是错的。`_sync_astock_daily_jq` 必须**自夹 `start` 到窗口起点**，否则一次
`start=2019-01-01` 静默拉回全史（5537 标的 × 数千行 = **额度炸弹**），且与 config `start_floor` 不符。
`end` 同理夹到窗口止（否则整轮被 SDK 拒）。两条都落测试。

### 0.2 ⚠️ 返回形状**按入参分叉**（实现分两路）

| 调用 | 返回 |
|---|---|
| 单标的 `panel=False` | **DatetimeIndex**（日期）+ 字段列，**无 `code` 列** |
| 多标的 `panel=False` | **RangeIndex** + `time`/`code` 列 + 字段列 |

`_normalize_frame` 统一两路 → `(ts_code, trade_date, open, high, low, close, vol, amount)`，
`trade_date` 输出 **YYYYMMDD 字符串**（下游 `to_save_rows`/`validate_bar_quality` 均按此解析）。
停牌行（OHLC 缺失）在归一化时 drop（不写 0 价污染 `bar_1d`）。

### 0.3 符号与单位（实测，**推翻批 103 注释的「÷100」**）

- 聚宽 `XSHE`(3077) + `XSHG`(2460) = 5537 只，**无北交所**（见 §0.5 的整批拒后果）。
- 归一：`000001.XSHE ↔ 000001.SZSE`、`600000.XSHG ↔ 600000.SHSE`（**内部是 `.SZSE/.SHSE`，不是 `.SZ/.SH`**）。
- **单位：无需换算**。同键逐位对照（2026-10-06 dev，4 标的 × 4 交易日 = 16 组）：

  | 字段 | 结论 |
  |---|---|
  | open/high/low/close/**volume** | **16/16 逐位相同**（如 000001@2026-06-01：volume 95,459,569 两侧一致） |
  | `amount` | 同单位（元），仅**上游四舍五入**差 <1 元（tushare 由千元 ×1000；JQ 直给 2 位小数。例：943,329,311 vs 943,329,311.39） |

  ⇒ 内部 `bar_1d.volume`=**股**、`amount`=**元**；聚宽同单位。**批 103 注释「volume=股 ⇒ ÷100」错误**
  （误以为内部是手；实际 tushare 侧 `to_save_rows` 的 `vol×100` 才是手→股）。

- ⚠️ **落库时间键约定（验证时最易踩）**：A 股日线 ts = `as_utc(trade_date)` = **本地 00:00+08**
  = **UTC 前一日 16:00**。用 `ts::date = '<date>'` 在 UTC 会话下过滤会**错位一天**（2026-10-06 实踩，
  一度误判「写入未生效」）。正确键：`ts = as_utc(pd.Timestamp(d))`。

### 0.4 复权因子：**跨源锚点不同（不是错误）**；系统已有独立因子通道 ⇒ **零代码改动**

聚宽 `factor` 语义**跟着 `fq` 变**（实测 000001）：

| 调用 | close | factor |
|---|---|---|
| `fq=None`（不复权） | 10.99（原始价） | **1.0** |
| `fq='post'`（后复权） | 1608.50 | **146.360309** |
| `fq='pre'`（前复权） | 10.41 | 0.947276 |

`fq=None` 的 1.0 **不是 bug**：`factor` 的定义是「**作用于返回价的因子**」，不复权时无因子可言。

**与 tushare 的对照（同键、多日期）——比值逐标的恒定**：

| 标的 | tushare `adj_factor` | JQ `fq='post'` factor | 比值 | 极差 |
|---|---|---|---|---|
| 000001.SZSE | 131.7878 / 134.5794 ×3 / 139.008 | 143.324313 / 146.360309 ×3 / 151.176553 | 0.919507 | 0.0000% |
| 600519.SHSE | 8.305 / 8.4464 ×3 / 8.6463 | 7.901292 / 8.035840 ×3 / 8.226000 | 1.051091 | 0.0003% |
| 000002.SZSE | 181.704 ×5 | 168.875961 ×5 | 1.075961 | 0.0000% |

⇒ 两者是**同一复权序列、不同归一化锚点**（比值恒定 + 除权日同步跳变）——**JQ 因子正确**。

**系统已有的独立因子通道（「其他机制」的答案）**：`engine.backfill_adj_factor` 明确定裁定
「`adj_factor` 是 **Tushare 独有接口**（`pull_adj_factor`）」，`_get_kline_adapter({})` 硬绑 tushare，
并**自动扫描** `bar_1d WHERE adj_factor IS NULL AND symbol ∈ A股静态表` → **以 tushare 补齐**。

**故处理方式＝「不声明 / 不提供」，零代码改动**：

1. `JoinQuantAdapter.capability_decls` **只声明 `bar_daily`**，**不声明 `adj_factor`**（tushare 两者皆声明）。
2. `to_bar_rows` 对 `adj_factor` 写 `None`（＝不提供该列值，非"转换"）。
3. 落库侧既有 `COALESCE(EXCLUDED.adj_factor, bar_1d.adj_factor)`（F-F2）保 tushare 已回填值；
   若为 JQ 独有行（tushare 缺）→ 因子 NULL → **被 `backfill_adj_factor` 自动以 tushare 补齐**
   （两源 OHLCV 一致，故 tushare 因子对该行正确）。

**可选、本批不做**：若将来 JQ 需自带因子，可按**逐标的常数 k＝tushare/jq**（实测恒定）换算；
代价是引入跨源标定依赖，当前无必要。

### 0.5 ⚠️ 不覆盖北交所 + SDK **整批拒**（2026-10-06 实测抓到的真缺陷，已修）

`_list_static_ts_codes("astock")` 取自 `static_symbols`（tushare `stock_basic`）⇒ **含 `.BJ` 北交所**；
聚宽只有 XSHE/XSHG ⇒ `920000.BJ` 等 **348 只**必然无效。而 jqdatasdk 对**含无效标的的批次整批拒绝**：

```
聚宽 get_price 失败（2026-06-01..2026-06-01，772 只）: 无效的证券代码 '920000.BJ'
```

⇒ 原始实现（单层 `try/except + continue`）**一只坏标的连带丢掉整批 772 只**，且 adapter 只打一行
warning、编排层 `failed_dates` 为空 = **静默数据洞**（实测：pulled 4772，而非应有的 ~5187）。

**修法（两层）**：

1. **发请求前剔除**非 `XSHE/XSHG` 标的（`_JQ_EXCHANGES`），记入 `adapter.last_skipped` 并打
   **WARNING（含只数与样例）**——不静默，也不误报为`failed`（北交所是聚宽静态能力边界）。
2. **单批失败二分降级**（`_fetch_chunk`）：递归二分直至隔离出坏标的（单只仍失败则记
   `last_skipped` 后返回 None），**其余标的照常投递**——防未来出现的非北交所类无效代码再次整批灭。

修后复测：`pulled 4772 → 5187`（丢掉的批次回来了），且 `last_skipped=348` 行 WARNING 可见。

## 三、A 步（ref_data）——**未开始，阻塞点已定性**

`_sync_astock_list`（`engine.py:561`）走 `_get_pro(prov).stock_basic(...)`。两层耦合：

1. **`_get_pro` 返回「源客户端对象」而非 adapter**（`data_source.get_client()`）：对 tushare 就是
   tushare `pro` 对象。
2. **handler 的调用语汇是 tushare 的**（`pro.stock_basic` / `pro.cb_basic`），**绕过**了
   `BaseDataAdapter` 的 `pull_*` / `fetch_supply` 接口。

⇒ 非 bar 同步项（静态清单/日历/三档，约 15 个）**结构上 tushare 独占**。给聚宽声明 `astock_list` 后，
`_get_pro('joinquant')` → `get_data_source('joinquant')` **抛 `ProviderConfigError`**
（joinquant 在 `_ADAPTERS`/`_REGISTRY` 皆已注册，DB 无行时返回 None → adapter 走 `.env` 兜底；而
`_get_pro` 那条路径**不吞不回落**）⇒「**可切换但一用就炸**」＝「清单有·实现无」家族（**响亮**形态）。

**正面结论：不存在静默串源**（three-registry law 把它挡成响亮失败）。真问题是**插件边界不完整**：
「多数据源」目前只覆盖 **bar 族 + 供给面（`fetch_supply`）**；A 步要做的正是把其中一个非 bar 项
打通到 adapter 接口，成为**首个「非 bar 多源」样板**。

对照：**B 步路径原生支持** —— `_get_kline_adapter(cfg)` 直接 `get_adapter(provider)` 走 adapter 接口，
聚宽实现 `pull_daily` 即零侵入（本批实证）。

## 五、字段映射（实测 API 形状）

- `get_price(security, start_date, end_date, frequency='daily', fields=["open","close","high","low","volume","money"], fq=None, panel=False, skip_paused=True)`
  —— **三个参数都必须显式传**：默认 `fq='pre'` 会改价（破坏「未复权价」契约）；`panel=True` 是已废弃 Panel 返回。
- **不取 `factor`**（§0.4）：`fq=None` 下 `factor` 恒 1.0 无意义，故 `fields` 不含它、不做二次调用。
- 单位：**无需换算**（§0.3）。
- 形状：按入参分叉（§0.2）。
- 分批：`_SYM_BATCH = 800`/请求；批内单只无效走二分隔离（§0.5）。
- 符号：覆写 `to_source_symbol`（§0.3）。
- **auth 门**：jqdatasdk **所有**调用（含本地的 `normalize_code`）前置 `auth` ⇒ `get_client()` 返回已 auth 模块句柄。
- 凭证：DB 密文（JSON `{account,password}`）优先 → `.env JQDATA_USER/JQDATA_PASSWORD` 兜底；
  **两者皆缺 ⇒ 抛 `ProviderConfigError`**（响亮；静默回落 tushare = 串源）。

## 六、资源约束（试用规则 → 硬契约，含实测修正）

- 每日 **100 万条**（按返回行数计）⇒ `JoinQuantDataSource.DEFAULT_RATE_LIMITS = {}`（**间隔制模型对本源无意义**，
  行预算由 handler 管）。全窗口 A 股日线 ≈ 5537 × ~250 日 ≈ **138 万行** ⇒ 需**分 2 天**（首日约 72%）。
- **连接数 = 1** ⇒ provider 级互斥（§四）。
- 账号 3 个月有效期（`expire_time` 实测）⇒ 过期＝**可见停红**，禁静默失败。
- 窗口动态取（§0.1）。
