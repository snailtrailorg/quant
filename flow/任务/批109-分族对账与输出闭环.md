# 批 109 · 分族对账 ＋ 输出闭环（步 4）

> 母设计：`flow/方案/同步窗口与参数分层-设计.md` §7.1/§7.2/§5.3/§5.4/§八.4。
> 前置：批 108 已上产（`202610070625-a51eb02`）。本批完整走八步法。

## 目标（一段话）

对账若只产报告、无消费者＝等于没做（母设计双盲审① P1）。本批给缺口装上**输出闭环**：
per-date 族在同步收尾做**日期级差集 → 内联重拉 → 仍缺落 `sync_gap` ＋ 告警**；per-symbol 族
**低频标的级差集 → 落 `sync_gap` ＋ 告警 ＋ 限频重拉**；批 108 只记日志的 `excluded`
（`policy_discard`/`unreachable`）升级为**落表终态**。`sync_gap` 是**派生视图非第二真源**
（可随时重建；**禁止**窗口/期望集计算读取它）。

## 产出

1. **迁移 `0140_sync_gap.py`**（expand-only，`CREATE TABLE IF NOT EXISTS` 仓例）：

   ```sql
   CREATE TABLE IF NOT EXISTS sync_gap (
       id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
       sync_id     text        NOT NULL,
       symbol      text        NOT NULL DEFAULT '',   -- ''=整日缺口（per-date）；非空=标的级
       gap_start   date        NOT NULL,
       gap_end     date        NOT NULL,
       state       text        NOT NULL,
       reason      text,
       pull_count  int         NOT NULL DEFAULT 0,
       first_seen  timestamptz NOT NULL DEFAULT now(),
       last_seen   timestamptz NOT NULL DEFAULT now(),
       closed_at   timestamptz,
       CONSTRAINT sync_gap_state_chk CHECK (state IN
           ('open','closed','unreachable','policy_discard','uncertain')),
       CONSTRAINT sync_gap_ident UNIQUE (sync_id, symbol, gap_start)
   );
   CREATE INDEX IF NOT EXISTS idx_sync_gap_open ON sync_gap (state) WHERE state = 'open';
   ```

   - **五态**：`open`＝已检出未补齐（**合法持续态**，存量缺口指标＝`state='open'` 行数）；
     终态四 `closed`（重拉补齐）/`unreachable`/`policy_discard`（§5.3 排除段）/`uncertain`
     （§5.4 期望集不可信，`reason` 区分 `stale_source`/`inception_unknown`）。
     「每行必须终结于其一」＝**不再重拉**的出口四态；`open` 行每轮对账续跑直至 closed 或人工裁定。
   - `symbol DEFAULT ''` 而非 NULL：运维手插行/跨版本无害（dev PG 18.6 虽支持 `NULLS NOT DISTINCT`，不依赖）。
   - **🔴 锚键与闭合语义（步 2 双盲审 P0-1 修正；复审 R2 措辞统一，v3）**：UNIQUE 为
     `(sync_id, symbol, gap_start)`——**锚＝缺口起点，非整区间**。每轮对账对该 sync_id
     （per-symbol 对账对该 symbol 范围）做**视图式全量重同步**，唯一算子＝**以本轮现算为唯一真源，
     对 scope 内全部非终态行（`open`＋`uncertain`）做集合差**：
     ① 从真源（数据表 vs 期望集）**现算**当前缺失区间集合（fresh，禁读旧行）；
     ② `open` 行 `gap_start` ∉ 现算起点集 ⇒ **置 `closed`**（`closed_at=now()`）；
     ③ `gap_start` ∈ 现算 ⇒ `UPDATE gap_end / last_seen`（**gap_end 整值对齐本轮现算，不是「收缩旧值」**
     ——复审 R2：v2 的「收缩」措辞与 ② 冲突，字面实现会回潮 P0-1）；
     ④ 现算有而无行 ⇒ INSERT `open`。**中段补齐**由现算自然产出新 `gap_start` ⇒ 走 ④。
     - **uncertain 恢复路径（复审 R1，双同）**：`uncertain` 行同入集合差——本轮期望集**可信**
       （日历覆盖恢复 / inception 已知）⇒ 该行置 `closed`（reason 保留），真实缺口由下一轮现算
       正常产出 `open`；仍不可信 ⇒ `UPDATE last_seen`。**杜绝「fresh 库首跑全 uncertain 后
       覆盖恢复永不翻正」的历史永久盲区**。
     - **缺口重开（复审 P1-α/R3 合并裁定）**：同键行已 `closed` 而现算再现 ⇒ 视为**新缺口事件**：
       `UPDATE state='open', pull_count=0, last_seen=now(), closed_at=NULL`（`sync_gap` 不承诺
       事件历史——真源是数据表本身）。**实现用读-改-写**（SELECT 现状 → 集合分类 → 逐行
       UPDATE/INSERT），**不走 ON CONFLICT 盲合并**（盲合并会把旧行 pull_count/last_seen 带进
       无关的新缺口，污染批 110 的「连续 N 轮同缺口」判据——该判据的形式化定义挂账批 110）。
     「派生视图可随时重建」由此落地：每轮局部重建，`sync_gap` 永远只是「上一轮对账时真源的投影」。
   - **往返用例接进 `scripts/test-migration-roundtrip.sh`**（新用例：建表幂等/复跑/CHECK 拦非法态/
     UNIQUE 锚语义/离线渲染）。

2. **per-date 对账（主路径＝同步收尾步骤，非独立任务）**——四处站点收尾接同一助手：

   | 站点 | 表 | 本地日期存在性 |
   |---|---|---|
   | `_sync_via_kind_daily_batch`（astock_daily/etf_daily） | `bar_1d` | distinct ts 日期，symbol 后缀 `.SZSE/.SHSE` |
   | `_sync_via_kind_cb_daily`（cb_daily） | `bar_1d` | 同上，symbol 前缀 `('11','12','13')`（转债；股票 60/00/30/68 无碰撞） |
   | `_sync_astock_daily_jq` | `bar_1d` | 同 astock_daily |
   | `_make_tier1_handler`（TIER1 全体） | 专用表 | `SELECT DISTINCT trade_date` |

   流程：本轮窗口 `[start, end]` 的期望集**只走覆盖感知函数** `_trade_dates_in_range`
   （步 2 双盲审 P0-2 修正，双同：`_expected_trade_dates` 的 `freq="B"` 静默回退**禁入对账**——
   那会把节假日当期望日产出**假缺口**；拉取侧 fail-open 保留，**对账侧 fail-closed-to-uncertain**）：
   - 返回 `None`（日历未覆盖/覆盖度守卫触发）⇒ 该窗口落 `uncertain`，**不主张缺口、不重拉**；
   - 差集 → **内联重拉**（逐缺日调本站点拉取路径，upsert 幂等，受同一 rate_limit/budget 语义；
     **各站 repull 显式定义**：daily_batch/jq 逐日 `fetch_supply(bar_daily, sub, (day,day))`；
     cb_daily 同型——`_fetch_supply(kind="bar_daily", sub_kind="convertible", start=day, end=day)`
     → `_save_bars`（其主拉取是整段单 fetch，缺日重拉走单日区间，**不依赖既有逐日循环**）；
     TIER1 逐日 `fetch_supply(kind, sub_kind, trade_date=day)`）
   → 补齐＝当轮收尾；**仍缺 ⇒ 视图式同步落 `sync_gap(state='open')` ＋ 聚合告警（新 code `sync.gap`）**。
   - 查询成本已实测：`idx_bar_1d_ts` 在 dev 1750 万行上 17 天窗口 distinct＝**28ms**。
   - handler 返回体新增 `gap_dates`（仍缺清单）；`sync()` 侧透传进日志与告警。
   - ⚠️ **重拉预算**：缺日数 ≤ 本轮 `expected_days`（有界），不新增预算维度；超过 budget 余量时
     剩余缺日直接落 `open`（下轮续补）。

3. **per-symbol 对账（旁路＝低频调度）**——crypto bar 族（`binance_perp_daily`/`okx_perp_daily`/

   - 期望集：下界＝`_window_floors`（复用批 108，**同一真源不二算**——§5.3-1「不许各算一套」）；
     上界＝`end − publish_lag`；crypto 按自然日、A 股按交易日。
   - **uncertain 触发**：该标的 `inception` 未知（裁定 F，Binance）⇒ 不主张缺口，落/更新
     `uncertain`（reason=`inception_unknown`）；快照 stale（SM 更新时间超阈，阈值 7 天）⇒
     `reason=stale_source`。
   - 落 `open` 行；**限频重拉**：`open` 行 `pull_count < 3` 且距 `last_seen ≥ 1 天` ⇒
     按缺口区间重拉（幂等）→ 成功走视图式同步置 `closed`。
   - **转债宇宙（Q3 裁定，双同不同意前缀法）**：cb 相关标的集一律取
     `security_master WHERE category='convertible'`（**单一真源**；实测前缀 `11/12/13` 会漏
     `10/13 只 + 14/5 只` 共 18 只）。
   - 调度（Q2 裁定）：`scheduler/app.py` beat 独立条目**每周日 03:33**——**对账类维护任务走 beat
     有仓内先例**（`sm-reconcile` 周一 16:05，同为对账性质）；批 83b 的「收编进 sync_config」

     与该决策无冲突。周日 03:33 与既有条目无撞车（实测 beat_schedule）。
   - **告警聚合（P1 处置）**：整轮至多 **1 条**聚合告警（总数＋样本前 5），且只对**本轮新 open**
     （first_seen＝本轮）响铃——已知 open 不重响，防首跑全史场景告警风暴。
