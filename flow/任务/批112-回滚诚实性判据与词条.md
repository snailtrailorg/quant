# 批 112 · 回滚诚实性·判据与词条

> 立项 2026-10-09（主会话补决策后立项）。来源＝批 84 拆批声明（`flow/任务/批84-回滚诚实性与schema一致性.md` 头部「拆批」）。
> 关联：批 84（母）/ 批 111（开关+门语义，已上产）/ `docs/architecture/A06-部署管道架构.md` §7.1 回滚

## 目标

管道任一回滚路径（rescue(6-8) 自动回滚、`rollback.yml` 手工回滚）都**校验「回滚后代码 ↔ 当前 schema」兼容**；不兼容报固定词条 `SCHEMA_CODE_SPLIT` + rc≠0，绝不输出「已自动回滚」的假话。

## 现状（已实证）

| # | 事实 | 锚点 |
|---|---|---|
| 1 | 回滚路径无兼容校验：回滚后「代码 ↔ schema」撕裂无人察觉 | `deploy/playbooks/rollback-tasks.yml:138,163`（复验之后无兼容任务） |
| 2 | 回滚文案说「已自动回滚」，但 schema 迁移不回退 → 假话 | `deploy/playbooks/release.yml` rescue(6-8) 文案 |
| 3 | 回滚目标 release 树**自带** `src/data_platform/schema_expectations.txt`，且已是运行时列级校验真源 | `server/src/data_platform/db.py:417 verify_schema()` 消费，四入口上报 `health.schema-drift` |
| 4 | 静态扫部署链闸门先例已立 | `server/tests/test_deploy_blast_radius.py`（2026-09-30） |

`deploy/playbooks/{release,rollback,rollback-tasks}.yml` ✅｜`quant-hbcheck`/`quant-dbro` psql 通道 ✅（属主 quant、PG peer 免密）｜沙箱场景套件 ✅。

## 产出

1. **兼容探针**（批 84 步 1 勘定已简化）：`quant-hbcheck compat` 动作——读**回滚目标 release 树**的
   `src/data_platform/schema_expectations.txt`，与 `information_schema.columns` 做 `expected ⊆ actual` 比对，
   逐行 `ok|miss <表>.<列>`、有 miss 即 rc≠0。**零新增 artifact**（不再生成 `deploy/compat/<release_id>.json`——
   生成第二份 JSON＝制造第二真源，与判据相反）。
2. `deploy/playbooks/rollback-tasks.yml`：回滚复验后新增兼容复验任务；失败输出 `SCHEMA_CODE_SPLIT` + rc≠0 + 告警 + 「须人工」。
3. `deploy/playbooks/release.yml`：① rescue(6-8) 复用同一兼容复验；② 诚实词条（**无条件做**）——「已自动回滚」→「已回滚代码、schema 未回退」+ 打印实际 alembic 版本。
4. 新闸门 `server/tests/test_release_rollback_honesty.py`：静态断言 ① rescue(6-8) 与 `rollback.yml` 都含兼容复验；② 失败词条含 `SCHEMA_CODE_SPLIT`。

## 限定范围

只改 `deploy/playbooks/{release,rollback,rollback-tasks}.yml`、`deploy/wrappers/quant-hbcheck`、`server/tests/test_release_rollback_honesty.py`。
**不碰**：`server/src/**` 业务代码、`server/migrations/**`、`web/**`、`auto_rollback_disabled` 语义（已随批 111 落地）。

## 接口契约

- 新增：`quant-hbcheck compat [--target <release_dir>]` → stdout 逐行 `ok|miss <table>.<column>`；有 miss 则 rc≠0。保持无参行为不变（不得破坏阶段 8）。
- 不改：`/healthz`（liveness）、`/readyz`（可达性）。

## 验收标准

- `cd server && ./venv/bin/python -m pytest tests/test_release_rollback_honesty.py -q` → 全绿
- `cd deploy && .venv/bin/ansible-playbook playbooks/release.yml --syntax-check`（+ `rollback.yml`）→ 通过
- 行为级：scratch schema 构造「清单 ⊄ 当前 schema」→ 断言 `SCHEMA_CODE_SPLIT` 且 rc≠0；兼容场景 rc=0（正反两例）
- 反证钉：撤掉兼容复验任务 → 闸门变红；恢复即绿
- 全套不回归：`cd server && ./venv/bin/python -m pytest tests/ -q`

## mock 方式

闸门＝静态文件断言（`yaml.safe_load` 后遍历任务名，不连环境）；行为级＝scratch schema + 真 wrapper（`PGHOST`/`PGOPTIONS` 驱动），与批 83a 双态回归同手法。
