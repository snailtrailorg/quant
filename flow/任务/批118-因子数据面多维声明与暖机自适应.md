# 批 118 · 因子数据面——多维度声明 + 暖机自适应 + ctx 扩展 + 回测一致

> 立项 2026-10-10（用户裁定）。来源＝用户提问「因子需要更长历史怎么办」「同一策略要日线+分钟线+L1/L2+静态数据，支持吗」——一手核实发现：契约层 27 种 DataKind 完备、供给层就绪，但**暖机单频写死 100 根 1min、因子 ctx 只有单 bar 单频一扇窗**，多维需求无门可入。
> 关联：D27-暖机与切换（机制背景）；`decisions.md` 2026-10-10 两条立法（判据可见/静默错误必须消灭——本批「窗口不足静默算 0」正是其形态）。

## 目标

因子/策略**声明**自己的数据依赖（哪些维度、各需多长窗口），运行时按声明供给；维度不足或窗口不足时**响亮告警/拒启**，消灭 `h.get("close", 0)` 式静默错误；回测与实盘**同一套喂法**。

## 产出（四件套 + L2 占位）

1. **声明语法（策略/因子侧）**：
   - `@register_factor(..., needs={"bar_minute": 20})`——`needs_history: int` 升级为 `needs: dict[kind, int]`（int=窗口长度；`needs_history` 保留为糖：`needs_history=N` ≡ `needs={"bar_minute": N}`，向后兼容存量因子定义）；
   - 策略侧聚合：live_task 启动时收集该策略全部因子的 `needs`，按 kind 取 **max**（叠加策略自身声明）。
2. **暖机自适应（运行时侧）**：
   - 分钟窗＝`max(100, needs["bar_minute"])`；**两处硬编码单一真源化**（`main.py:80` 与 `hub_worker.py:256` 读同一常量来源）；
   - 日线暖机（新管道）：`needs["bar_1d"]` > 0 时从 `bar_1d` 表拉窗口（对齐 `KIND_TEMPORALITY["bar_daily"]=historical`）；
   - 静态数据暖机：`needs["static"]` 声明表名列表（如 `stk_limit`），启动时一次性查询入 ctx。
3. **ctx 扩展（因子接口）**：
   - `BarContext` 加字段：`daily_history: list[dict]`、`static: dict[str, Any]`（按表名分组）；`history` 保持=分钟序列（别名不动，存量因子零改动）；
   - **供给不足响亮化**：声明窗 > 实际供给 ⇒ 因子首算前告警一次 + `ctx.degraded=True`（策略可读）；启动时实际供给 < 声明 ⇒ **拒启**（EX_CONFIG，对齐权限 fail-fast 范式）。
4. **回测一致性**：回测引擎喂 ctx 按**同一 needs 声明**取数（同一暖机函数复用或同构实现）——验收含「同一因子回测/实盘首算值逐位一致」钉。
5. **L2 占位（不实装）**：`needs` 语法允许 `"depth"/"stream_tick"` 键（streaming 类），运行时遇到 ⇒ 明确报「L2 未实装，见待办挂账」拒启（不静默忽略）；实装单独立项（订阅推送模型 vs 暖机拉取模型，形态待设计）。

## 限定范围

只改：因子注册/ctx（`strategy_framework/factor.py`）、策略装载聚合（`strategy.py`）、暖机（`strategy_runner/main.py` + `hub_worker.py` 常量真源化）、回测喂数侧、`bar_1d` 暖机读通道。
**不碰**：hub 流协议（bar 消息形态不变）、冻结体系（复用不改）、L2/depth 实装（占位即止）、选股面（动态因子不得选股的既有约束不变）。

## 接口契约

- 改：`register_factor(name, *, needs: dict[str, int] | None = None, needs_history: int = 0, ...)`（双参并存，糖映射）。
- 改：`BarContext.__init__(..., daily_history: list[dict] | None = None, static: dict | None = None, degraded: bool = False)`。
- 改：`_warmup_history(symbol, n=100)` → `n` 由 needs 聚合传入；新增 `_warmup_daily(symbol, n)`、`_warmup_static(symbol, tables)`。
- 新增：`needs 聚合函数`（live_task 装载时：策略 needs = max over 因子 needs，逐 kind）。
- 不改：bar 消息协议、Valkey 流、`BarContext.history` 语义。

## 验收标准

- `pytest tests/ -q` 全绿（基线 2529+）；新用例覆盖：needs 糖映射、聚合 max、日线/静态暖机、degraded/拒启三分支（足/不足/超声明）、L2 占位拒启、回测-实盘首算一致钉
- 行为级：`needs_history=250` 的因子启动 ⇒ 暖机拉 250 根（日志数字实证）；`needs={"bar_1d": 60}` ⇒ `ctx.daily_history` 长 60；`needs={"depth": 1}` ⇒ 拒启且报 L2 未实装
- 反证钉：撤掉聚合（回退常量 100）⇒ 250 窗因子用例红；撤掉拒启 ⇒ 超声明用例红
- 兼容：存量因子（`needs_history=N`）与不声明的策略（默认 100）行为零漂移——全量回归即证
- ruff 零新增
