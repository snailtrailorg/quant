# 批 120 · 安全态势页——持续采集 + 基线 diff + AI 摘要

## 背景

2026-10-11 手工完成安全评估（5 项闭环）+ 组件盘点/CVE 排查（Redis 6.2.22 中危唯一行动项）+ Python 组件清零（6 包 34 漏洞）。用户裁定：将一次性排查转为**持续自动化**——采集组件/配置信息，定时更新，AI 定时分析风险，前端安全页展示。入侵检测（AIDE/文件完整性）放二期另立。

## 目标

1. 组件版本与关键安全配置**每日自动快照**入库；
2. 漏洞比对自动化（pip-audit OSV + `dnf --security`）；
3. **基线 diff 告警**：新增监听端口/新增包/安全配置翻转（如 PasswordAuthentication）⇒ 飞书告警（判据可见——静止绿不扰民）；
4. AI 每日摘要（llm_gateway 复用）：结构化结果→人话风险摘要+长期不动高危项置顶；**AI 只做摘要员，判定必须是确定性规则**（AI 误判不得改变告警语义）；
5. Observe.vue 加「安全」Tab：组件版本表/漏洞计数/最近 AI 摘要/历史趋势。

## 现状锚点（2026-10-11 一手核实）

1. `health_monitor/collector.py`：定时采集框架已有（CPU/mem/disk/Valkey 写入），beat 调度成熟——新增 security 采集项全复用此模式；
2. `llm_gateway/`：DeepSeek/GLM 双通道（.env 已配 key）——AI 摘要直接调；
3. pip-audit 已装（本机 venv）且 OSV 比对验证可用；`dnf check-update --security` prod 实证返回 0；
4. Observe.vue 为现有监控页——加 Tab 而非新建页；
5. 告警通道（飞书 `sync.local_unreadable` 等告警码模式）成熟可复用。

## 产出

1. **采集器** `security_collector`（health_monitor 同目录）：每日（建议 06:00 盘前）采——
   - 组件版本：pip freeze 全量、`nginx -v`、`sshd -T` 摘要（passwordauthentication/permitrootlogin）、openssl rpm 版本、pg/redis 版本、`dnf --security` 待更新计数；
   - 暴露面快照：`ss -tlnp` 非 127.0.0.1 监听清单、nginx 安全头探针（4 头 curl）；
   - 漏洞面：pip-audit 输出（包/版本/PYSEC id/修复版）。
2. **存储** `security_snapshot` 表（日期 PK + jsonb 各分区快照）+ `security_finding` 表（漏洞/偏差行：来源/pkg/cve/severity/fix_version/first_seen/last_seen）。
3. **基线 diff**：与前一日快照比——新增监听端口/新增 pip 包/安全配置翻转 ⇒ `_alert(code="security.baseline_change")`（飞书，含具体 diff 项）；漏洞项 first_seen 告警一次（去重）。
4. **AI 每日摘要**：扫描完成后把 finding 表 + 快照 diff 喂 llm_gateway，产出 ≤300 字摘要（风险趋势/置顶高危/建议动作）落 `security_snapshot.ai_summary`；LLM 不可用 fail-soft（摘要空，不影响采集与告警）。
5. **前端**：Observe.vue 安全 Tab——顶部当日 AI 摘要卡 + 组件版本表 + 漏洞列表（severity 排序，含 first_seen 停留天数——「长期不动」可见）+ 基线 diff 时间线。
6. **调度**：sync_config 加 `security_scan` 行（每日 06:00，`supports_backfill=false`）。

## 限定范围

- **不做**：入侵检测/文件完整性（AIDE，二期另立）、外部渗透扫描、WAF；
- AI 摘要仅中文文本展示，**不产生任何自动动作**（不自动升级/不自动改配置）；
- 不重复造 CVE 库——pip-audit(OSV) 与 dnf --security 为唯一真源（OpenSSL backport 教训：版本号比对不可信）。

## 接口契约

- 新增：`GET /api/security/snapshot?date=`（read 权限）——当日快照+findings+ai_summary；
- 新增：`GET /api/security/history?days=30`（read）——趋势（漏洞计数/组件变更计数按日）；
- 不改既有端点。

## 验收标准

- 手动触发 security_scan：快照入库、findings 与当日 pip-audit/dnf 输出一致（抽验 3 条）；
- 基线 diff 反证钉：构造「新增端口/翻转配置」两次快照 ⇒ 告警行含具体项；无变化日零告警；
- AI 摘要：LLM mock 下生成且 fail-soft（LLM 异常不阻断扫描）；
- 前端 Tab 渲染当日快照+30 天趋势；
- pytest 全绿 + 新增用例覆盖采集解析/diff 判据/fail-soft。

## mock 方式

- 采集：命令输出 fixture（ss/rpm/freeze 样本文件）注入解析函数；pip-audit 结果 mock JSON；
- LLM：gateway mock 返回固定摘要/抛异常两分支；
- 前端不连真后端快照接口以外的任何服务。
