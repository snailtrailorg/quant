# 批123：漏洞源重构——grype+syft 统一采集 + severity + 组件台账 + 前端修正

- **立项**：2026-10-14（用户裁定「grype + syft 重构方案」，源起安全页连续追问链：
  层级列无意义→severity 才是正道→变更日期应入库→CVE 途径应统一）
- **性质**：架构级小批（表结构变更+新外部工具引入+采集器重构+前端修正）
- **教训铭刻**：「精品」经不起追问——每项展示都必须能回答"用户拿它做什么决策"；
  数据层正解优先于代码层补丁（反查 30 天窗口 vs 台账直读）。

## 一、现状与根因（全部实测）

1. **三源异构**：pip-audit（OSV，无 severity 输出）/ dnf --security（errata 有
   severity 未采集）/ baseline（非 CVE）——schema 各异，severity 缺位。
2. **单点依赖**：OSV 断连 ⇒ vulns 分区降级（2026-10-14 本机实证）。
3. **组件版本只活在快照 jsonb**——无一等表，「距上次变更」只能 30 天窗口反查。
4. **前端拼凑**：层级列（渲染冗余信息）/「见各分区详情」指向不存在的东西
   （degraded_reason 前端从未渲染）。
5. **探查实证（prod）**：Grype DB 源可达（listing 1.1s / v5 296MB 106s）；
   GitHub 不可达（二进制装机须本机中转）；dnf 仓库无收录。

## 二、方案

### 1. 装机通道（与施工解耦——grype 二进制不阻塞其余项）

**通道按序三备选**（2026-10-14 实测：GitHub 对本机+prod 全断 22/443/https；
gitee 200；mirrors.aliyun 通；anchore DB 源 prod 侧通）：
- a. **网络恢复窗口**：就绪判据 `curl -sI -m 10 https://github.com` = 200 →
  本机下载 grype/syft linux_amd64 tar.gz → ansible copy 推 /tmp →
  root install `/usr/local/bin/`（root:root 755，michael 一次性）。
- b. **gitee 镜像**：查 anchore/grype 官方或可信同步仓——非官方同步
  **须校验 checksum**（官网公布值比对），不裸信。
- c. 都不通：**装机步无限期挂起，其余项照常施工上产**（解耦立法：
  迁移 0146/dnf 补采/台账/前端修正零依赖 grype 二进制；GrypeScanner
  available 探测不过=插件退场，pip-audit/dnf 照跑=现状零回退）。
- DB 日更：grype 首跑+`grype db update` 前置于扫描（anchore 源已验
  296MB/106s；v5 无增量=每日全量——06:00 任务 600s timeout 内 106s 下载
  +扫描 ~60s+五分区 ~50s 余量足，预算账入 A07）；失败=fail-soft 退场。
- **alinux3 识别=装机后第一闸**（返工前移）：装机即跑 syft 冒烟——SBOM
  distro 字段是否识别 Alibaba Cloud Linux 3 + rpm 包计数正常，不过则
  OS 层留 dnf 源（方案退化仍净收益），表/前端零返工。
- 版本升级走同通道（变更⇒重装位，同 wrapper 生命周期规约）。

### 2. 采集器插件化（register 范式——对齐仓内 md_gateway/data_source 先例）

- **注册机制**（md_gateway.py:115-130 同款）：`_VULN_REGISTRY: dict[str, type]`
  + `@register_vuln_scanner` 装饰器 + 工厂/枚举函数。
  每插件三要素：`name`（→finding.source，词表自然收敛）/ `available`（探测：
  二进制+DB 在不在——**每轮扫描时探测**，失联即跳不 fail 整轮；三插件全退
  ⇒ vulns 分区 degraded——0145「绝不静默空表=假绿」立法）/ `scan() ->
  list[Finding]`（统一返回 pkg/vuln_id/severity/fix_version）。
- **插件优先级=显式顺序元组**（§二.6——dict 注册表无序，同 im_bot 惯例）。
- **三个插件**（真实多实现，故配抽象——准入判据：现有实现 ≥2）：
  - `GrypeScanner`：syft 扫描目标=**shared/venv/**/site-packages**
    （dist-info 实证 172+——release 树只含声明不含安装，扫它=SBOM 语义失真，
    返工裁定）+ rpmdb（默认）→ grype 匹配 → severity 原生。运行身份=
    celery worker（quant）——shared/ 0700 quant 属主恰好可读，零特权扩张。
  - `PipAuditScanner`：现 _collect_vulns 迁入（回退=available 探测自动退场）；
    **alias 归一同步改造**（vuln_id 优先取 CVE 号——pip-audit 输出含 aliases）。
  - `DnfErrataScanner`：现 _collect_dnf 增补 errata severity 迁入。
- **注册表一致性**（data_source 先例）：插件 name ↔ finding.source ↔ 前端
  来源筛选（allSources 数据驱动）——一处注册三处消费，拼写分叉 fail-fast 拦。
- baseline 源**不入插件**（漂移检测≠CVE 扫描，语义不同不硬塞同接口）。
- severity **单词表**：Critical/High/Medium/Low/Negligible/Unknown（grype
  CVSS 词表基准）。dnf errata RH 词表（Important/Moderate…）**写入侧归一**
  （collector 内映射：Important→High/Moderate→Medium/Low→Low——词表在
  代码=0145「写入侧单源」立法延续，DB 不存第二词表）。
- 组件台账 UPSERT：`security_component`（见 3）——SBOM 顺带产出，零额外扫描。

### 3. 表变更（迁移 0146，expand-contract 两步走）

```sql
-- security_finding 加列
ALTER TABLE security_finding ADD COLUMN severity text;      -- 单词表（§二.2 归一后），NULL=未评级
-- 组件台账（一等表——版本变更史入库，动态数据入库原则）
CREATE TABLE security_component (
    id          bigserial PRIMARY KEY,
    source      text NOT NULL,           -- 'pip' | 'rpm' | 'system'（归源规则见下）
    name        text NOT NULL,
    version     text NOT NULL,
    first_seen  date NOT NULL,           -- 组件首次入库日
    last_changed date NOT NULL,          -- 版本上次变化日（新装组件=与 first_seen 同日）
    last_seen   date NOT NULL,           -- 最后扫到日（防未变更长滞留误判在库）
    CONSTRAINT uq_security_component UNIQUE (source, name)
);
```
- UPSERT 语义：版本没变 → 只推 last_seen；变了 → version+last_changed 同步；
  **新组件** → 三日同值入库（last_changed=first_seen=当日——新装即当前版本的
  变更日，语义自洽非冗余）。
- **归源规则**（返工补——防双计数）：rpm 库的 python3-* 包归 'rpm' 源
  （系统包视角）；pip 装的归 'pip'（syft site-packages 扫描产出）；name 冲突
  信任 pip 域（venv 里才是运行时真身）——两域各自台账不互删，D 区展示
  pip 域优先。'system' 源=8 个点名系统组件（_collect_components 既有清单，
  非 rpm 非 pip 的身份明确者如 python 解释器/nginx）。
- 暴露时长 = 台账 last_changed + finding 存在 ⇒ C 区可精确展示
  「暴露 Xd（发现 Yd）」。
- **台账验收口径**（返工降级——冷启动无真实变更样本）：机制验证=人工
  UPDATE 一行版本模拟变更→下轮扫描 last_changed 正确推移即过；真实样本
  留观察期自然产生。

### 4. dnf 分区 severity 补采（双源并存期）

quant-dnf-security wrapper 增采 `dnf updateinfo --security` 的 errata severity
（现成元数据），写入 finding（source='dnf' 行补 severity）。

### 5. 前端修正（SecurityTab）

- **删**：D 区层级列（冗余——行序已表达优先级；severity 才是行动依据）。
- **删**：D 区「距上次变更（天）」→ 改「上次变更日期」直读台账（>30 天前不再 `—`）。
- **加**：C 区严重度列（Critical 红/High 橙/Medium 黄/Low 灰——色语义走
  tokens 既有 critical/warn/fill）；暴露时长副信息。
- **加**：A 区状态卡 degraded 时列降级分区+原因（快照 degraded_reason 现有
  数据，纯渲染）。

### 6. 切换策略（不裸切）

- **并存期**：grype 与 pip-audit+dnf 双跑。**去重=采集侧 alias 归一**（返工
  裁定：唯一键含 source 不跨源去重——grype 报 GHSA/pip-audit 报 PYSEC 同一
  漏洞两行并存且 A 区双计）：写入侧 vuln_id **优先取 aliases 中的 CVE 号**
  （无 CVE 才保留原生 ID），pkg 归一 lowercase——键不动零迁移，跨源同漏洞
  自然同键。切换日基线变化属预期（**重叠度未知，观察期实测**——学术研究
  曾报扫描器间一致率极低但那是容器镜像场景；我们的实测数据届时入 A07，
  不预写未发生的记录）。
- **插件优先级=显式顺序元组**（返工裁定：dict 注册表无序——同 im_bot
  base.py 惯例，`_SCAN_ORDER = ("grype", "pip-audit", "dnf")`，首个
  available 且产出非空者为该 (pkg,vuln_id) 的归属 source，后者只回退不并行
  双写——从根上免双计）。
- **观察一周期（7 天）**：grype 覆盖 ⊇ 双源？DB 更新稳定？→ 是则降双源为
  fail-soft 回退（grype 失败时兜底），否并修。
- **插件注册制**（2026-10-14 用户二次裁定，升级本项）：register 范式
  （md_gateway 同款）——归一点仍是表 schema，插件注册只是采集端的组织方式；
  A07 记录两段演进（先裁定不建→追问后升级插件制，准入判据同步立）。

## 三、验收

1. prod 一轮扫描：grype findings 入库（severity 非全 NULL）、severity 词表
   覆盖率报告（grype 内 vs 未评级）。**grype 未装机期间本项挂起；连带挂起：
   验收 2 的 pip 域入库（SBOM 顺带产出）与验收 6 的 syft 冒烟（依赖二进制）；
   其余（台账 system 域/dnf 补采/前端）不阻塞**（复审精化解耦口径）。
2. security_component 台账：pip 域 172+（实测 179——A 区快照 pip 键计数
   锚点）+system 8 组件全量入库；**机制验证**：人工 UPDATE 一行版本模拟
   变更 → 下轮扫描 last_changed 正确推移（冷启动无真实变更样本，返工
   降级口径）。
3. 前端：层级列无、严重度列有色、degraded 明细可读、暴露时长=台账口径。
4. 双源并存：pip-audit/dnf 通道仍绿（回退路径活着）。
5. 全套 pytest；迁移往返（scratch schema）0146 过。
6. **alinux3 识别闸**（装机后第一件事——零编码成本）：syft 冒烟 SBOM 的
   distro 字段识别 Alibaba Cloud Linux 3 + rpm 计数正常；不过则 OS 层
   留 dnf 源（方案退化），表/前端零返工。

## 四、不做（防拼凑复发）

- 不做全组件抽屉/搜索（172 包清单在 lock 里，页只做关注面）；
- 不做 E 区历史明细回填（存储成本>价值，A07 既有裁定不变）；
- 不建"按发行版分叉"的 Provider（SBOM 工具天然跨生态——换发行版 grype
  自适应，无需 apt/apk 预写分支）；**但建扫描器插件注册**（register 范式=
  仓内惯例；三真实实现成立，准入判据=现有实现 ≥2 才配接口）；
