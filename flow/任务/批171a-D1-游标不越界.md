## 0. 契约（一句话）

handler 返回体新增**可选键 `cursor_cap`**（`YYYYMMDD`）：**本轮游标推进不得越过它**——`sync()` 两分支的推进值与 `cursor_cap` 取 min，**且钳制不倒退**（不低于旧游标）；cap 只由**稠密白名单族**在 handler 尾部出具，出具条件＝`sync_id ∈ _CAP_EMIT_IDS` 且对账 `gap_dates` 非空且 `uncertain is None` 且 **handler 非全失败** ⇒ 空帧日记成功也**不再把游标推过缺口**，下轮窗口必含缺口日，缺口自愈窗口永不关闭。

**为什么是对账侧出 cap 而不是 sync() 重算**：对账（`_reconcile_dates`）是唯一同时知道「期望集/本地已有集/本轮拉回集」的角色；`sync()` 只做纯收口（min+clamp），无新查询、无第二真源。

## 2. 改动规则

### A. `sync()` 游标收口（engine.py:434-466）

```python
_cap = r.get("cursor_cap")            # None=未声明 ⇒ 逐字现状
def _clamp(v: str) -> str:            # min 收口 + 旧值钳制（绝不倒退）
    if _cap and _cap < v:
        v = _cap
    return max(v, cfg["last_sync_date"] or "") if _cap else v   # clamp 仅在 cap 生效时参与
```
- 三分支落点：部分失败 `(_clamp(r["last_success_date"]), saved, "partial")`；无失败 `(_clamp(end_date), saved, …)`；无键 `(_clamp(r.get("cursor_upto") or end_date), saved, _term)`。
- **终态词通则（三分支统一，v3 补齐）**：收口实际改值（推进值 ≠ 未收口原值）且原词为 `idle` ⇒ `_advance[2]` 改 `partial`；原词 `partial/failed` 保持。**无键分支（9 键白名单中 7 键的主通路：cb_daily/jq/tier1 五族）同样适用**——被 cap 冻住游标的轮次 `last_status=partial` 而非 `idle`，前 6 轮（逃逸闸第 7 轮才响）的可见性就靠这个词。`sync_log.status` 仍按 failed_dates 取原口径（success）——两表分叉是**承载正确性**的（tier1 新鲜度告警与 health_monitor 只认 `sync_log.status='success'`，tasks.py:436/462、collector.py:334；`last_status` 消费面仅 `=="running"` 僵尸判定 tasks.py:1113 与展示，partial 无碰撞）。
- `_cap is None` ⇒ `_clamp` 恒等 ⇒ 既有 handler（`_HANDLERS` 字面 18 键＋工厂注册 10 键）**逐字零漂移**。
- **全失败分支（436-444）不收口**：游标本就不动（写回旧值/起点前一日）；**异常路径（495-499）不收口**：同；**回补 `_advance=None`（466）与 cap 无关**。
- min 比较基于 YYYYMMDD 等宽串字典序（gap_dates 元素＝紧凑 YYYYMMDD，`_trade_dates_in_range` 346 同源）。
- **`_log`（403）先于游标段（428-466）——实现顺序钉死**：error 留痕须在调用 `_log` **前**预算 cap 效果（此时 `r`/`cfg` 均已就绪，收口是纯函数可先算后用），`_log` 位置不动（duration_ms 口径不变）。

### B. cap 出具＝**稠密白名单**（handler 尾部，四处装配点共用一个 helper）

```python
_CAP_EMIT_IDS: frozenset[str] = frozenset({
    "astock_daily", "listed_fund_daily", "cb_daily", "astock_daily_jq",   # bar 族（jq 含 10-14 事故）
    "stk_limit_sync", "moneyflow_sync", "margin_detail_sync", "st_list_sync", "cyq_perf_sync",  # tier1 稠密（prod 实证）
})
def _cursor_cap(sync_id: str, rec: dict, failed_dates: list) -> str | None:
    """出具条件四连：白名单 ∧ gap 非空 ∧ 非 uncertain ∧ 非全失败。"""
    if sync_id not in _CAP_EMIT_IDS:
        return None
    if rec.get("uncertain") is not None or not rec.get("gap_dates"):
        return None
    if failed_dates and len(failed_dates) >= (rec.get("expected") or 0):   # 全失败（tier1 全窗炸）
        return None                                                        # ⇒ 不出 cap，游标走原语义（G-S1）
    _g = min(rec["gap_dates"])
    return (date(int(_g[:4]), int(_g[4:6]), int(_g[6:8]))
            - timedelta(days=1)).strftime("%Y%m%d")   # 紧凑串拆段，同 440-443 先例
```
- **全失败守卫（v3 补，v2 §0 有而草图漏——两真源矛盾已消）**：tier1 五族无 `last_success_date` 键，全失败轮 `failed_dates`=全窗 ⇒ 对账 `gap_dates`=全期望日 ⇒ 若无守卫会出 cap ⇒ `cursor_upto=end_date`（3267）被压回旧游标——**G-S1「无键族无条件推进」语义（429-433 注释）被静默改变**。守卫后：全失败轮不出 cap，走原语义（终态词已如实 failed/partial，ts 恒刷新无重试风暴）。含键族（astock_daily 等）全失败走 436-444 分支结构性不收口；jq 全失败时 `cursor_upto=reached or start-1`＝旧游标，clamp 恒等价——漂移面精确限于 tier1，守卫堵死。
- **白名单外一律不出 cap**：`forecast_sync`/`top_list_sync`/`block_trade_sync`（稀疏本性，排除）；`index_daily`/`astock_basic`/静态族/加密族天然无 reconcile 不可达。装配点可达族全集＝12（daily_batch 2 + cb 1 + jq 1 + `_TIER1_BATCH` 8，注册 3398-3407）＝白名单 9 + 显式排除 3。
- **白名单漂移守门**：新测试断言 `_CAP_EMIT_IDS ⊆ 装配可达族` 且 `装配可达族 − _CAP_EMIT_IDS ＝ {forecast_sync, top_list_sync, block_trade_sync}`（显式排除集）。**可达集从 engine 活值推导**：`set(_TIER1_BATCH) ∪ {astock_daily, listed_fund_daily, cb_daily, astock_daily_jq}`（12 键；tier1 轴取自 `_TIER1_BATCH` 注册 3398-3408 联动）——测试内**不得**复制分派逻辑成第二真源，硬编码 12 键全集会让 `_TIER1_BATCH` 增员不红。
- **cap＝min(gap_dates) 前一自然日**：不依赖日历查询、确定性成立、cap 落非交易日无害（各族起点均按自然日 +1 推进，2694/3063-3064/3188-3191）。
- **四处装配点抽 helper**（`_cursor_cap`）防四份漂移。
- **为何 cap 挡的是「窗口不越过缺口」**：下轮 start＝游标+1 ≤ min(gap) ⇒ 缺口日重新进窗；期间补齐 ⇒ 对账空 gap ⇒ 不出 cap ⇒ 游标恢复推进。多日缺口：cap 收在首缺口日前 ⇒ 下轮整段自愈。
- **旧值钳制（clamp）阻断 tier1 overlap 倒漂**：tier1 起点＝`last+1-overlap`（3188-3191）⇒ 无钳制时 cap 可低于旧游标 ⇒ 每轮回退 overlap 天、窗口无界膨胀。钳制后：cap 只能收口到旧游标为止；overlap 区内缺口靠每轮 overlap 重覆盖自愈（既有机制），cap 不越俎代庖。**clamp 数学闭环**（v2 审 B 验证）：gap ⊆ expected ⊆ 窗口 ⇒ cap ∈ [start-1, end] 恒成立；dense 族 start=last+1 ⇒ cap ≥ last 恒成立、clamp 永不触发；tier1 由 clamp 兜底 ⇒ 收口后 ∈ [max(旧游标, start-1), end]。
- **逃逸闸（连续 7 轮收口实际生效 ⇒ 告警一次）**：`_alert_generic`（2210），code=`sync.cursor_frozen`，RUNBOOK 注册。
  - **计数通道＝单源 Valkey 键** `sync:cap_freeze:<sid>`：`INCR` **每次续期** `EXPIRE 7d`（经 `business_redis`，`socket_timeout=5`，同 `sync_lock.py:48-53` 模式）；值恰达 7 ⇒ 告警一次（**==7 打点，第 8 轮起不再打**——防告警风暴）。
  - **触键条件（v3.1 正名——一句话真源）**：**sync() 侧触键 ⇔ `_cap is not None`（增量轮）**——收口实际生效 ⇒ INCR+EXPIRE；出具但未生效（含回补轮带 cap 键）⇒ DEL。**恒零触碰轮**＝`_cap is None` 且痊愈条件不成立者（未声明族/白名单外/uncertain/全失败/早退/锁竞争）——既有 22 用例与所有未声明族由此成立。回补轮连续清零计数属知情取舍（回补＝操作员主动介入，冻结告警本应让位）。痊愈轮的 DEL 在 **handler 尾部侧**（见下条），与 sync() 侧触键互不重叠。
  - **痊愈轮清零（v3.1 补——堵二次冻结静默）**：白名单族「对账在场 ∧ 非 uncertain ∧ gap 清空」轮 ⇒ DEL（handler 尾部判定，随 helper 调用点落位——mock handler 不执行尾部 ⇒ 22 用例零触碰仍成立）。情节链：冻结 ≥7 轮已告警 → 愈合数日 → 7d 内再冻结，无此条则计数从 ≥7 续涨、`==7` 永不再真 ⇒ 第二段冻结永久无声。
  - **计数 helper fail-soft（v3.1 补——堵伪失败三连）**：`_cursor_freeze_count` 吞一切异常、异常时返 `None`（计数未知——不出告警、不抛、不清零）。触键点在 sync() try 块内（游标段后、`_update_sync_state` 已执行）——裸抛会：①403 已落 success 行 + 493 再落 error 行（**双日志行**）②496 把刚写的 partial 覆写为 failed ③499 伪失败告警。对照先例：`_alert_generic` 自身就是 try/except 吞异常（2215-2219），同款纪律。
  - **断链语义**：进程重启/TTL 过期/Valkey 不可达 ⇒ 从 0 起计 ⇒ 告警延迟但不误响。
  - **计数 helper 契约（v3.1 钉）**：engine 模块级函数，签名 `(sync_id: str, *, bumped: bool) -> int | None`（bumped=True ⇒ INCR+EXPIRE 返新值；False ⇒ DEL 返 None；异常 ⇒ None）；调用点＝sync() 游标段内、`_advance` 确定后、try 内。
