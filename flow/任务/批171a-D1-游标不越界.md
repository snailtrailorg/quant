## 0. 契约（一句话）

handler 返回体新增**可选键 `cursor_cap`**（`YYYYMMDD`）：**本轮游标推进不得越过它**——`sync()` 两分支的推进值与 `cursor_cap` 取 min，**且钳制不倒退**（不低于旧游标）；cap 只由**稠密白名单族**在 handler 尾部出具（对账 `gap_dates` 非空且非 uncertain 且非全失败）⇒ 空帧日记成功也**不再把游标推过缺口**，下轮窗口必含缺口日，缺口自愈窗口永不关闭。

**为什么是对账侧出 cap 而不是 sync() 重算**：对账（`_reconcile_dates`）是唯一同时知道「期望集/本地已有集/本轮拉回集」的角色；`sync()` 只做纯收口（min+clamp），无新查询、无第二真源。

## 2. 改动规则

### A. `sync()` 游标收口（engine.py:434-466）

```python
_cap = r.get("cursor_cap")            # None=未声明 ⇒ 逐字现状
def _clamp(v: str) -> str:            # min 收口 + 旧值钳制（绝不倒退）
    if _cap and _cap < v:
        v = _cap
    return max(v, cfg["last_sync_date"] or "") if _cap else v   # clamp 仅在 cap 生效时参与
```
- 部分失败分支：`_advance = (_clamp(r["last_success_date"]), saved, "partial")`；无失败分支：`_advance = (_clamp(end_date), saved, "idle"→"partial" 若收口实际改值)`；无键分支：`_advance = (_clamp(r.get("cursor_upto") or end_date), saved, _term)`。
- `_cap is None` ⇒ `_clamp` 恒等 ⇒ **19 个静态 handler 逐字零漂移**。
- **全失败分支（435-441）不收口**：游标本就不动，收口只会把「不动」变「倒退」。
- **异常路径（495-499）不收口**：游标写回旧值，同上。
- **回补 `_advance=None`（466）与 cap 无关**：回补不推游标。
- min 比较基于 YYYYMMDD 等宽串字典序（gap_dates 元素＝紧凑 YYYYMMDD，`_trade_dates_in_range` 346 同源）。

### B. cap 出具＝**稠密白名单**（handler 尾部，四处装配点共用一个 helper）

```python
_CAP_EMIT_IDS: frozenset[str] = frozenset({
    "astock_daily", "listed_fund_daily", "cb_daily", "astock_daily_jq",   # bar 族（jq 含 10-14 事故）
    "stk_limit_sync", "moneyflow_sync", "margin_detail_sync", "st_list_sync", "cyq_perf_sync",  # tier1 稠密（prod 实证）
})
# handler 尾部（四处装配点）：
if sync_id in _CAP_EMIT_IDS and _rec.get("gap_dates") and _rec.get("uncertain") is None:
    _g = min(_rec["gap_dates"])
    r["cursor_cap"] = (date(int(_g[:4]), int(_g[4:6]), int(_g[6:8]))
                       - timedelta(days=1)).strftime("%Y%m%d")   # 紧凑串拆段，同 440-443 先例
```
- **白名单外一律不出 cap**：`forecast_sync`（ann_date 稀疏本性）/ `top_list_sync` / `block_trade_sync`（事件驱动）被排除——它们的「空日」不是缺口，cap 会造成游标逐轮倒漂（审 B P0-1）。`index_daily` 无对账装配、静态族无 reconcile——天然不受影响。
- **cap＝min(gap_dates) 前一自然日**：不依赖日历查询、确定性成立、cap 落非交易日无害（各族起点均按自然日 +1 推进，2691/3058/3186）。**不用交易日回退**：非交易日缺口的前一交易日仍是缺口日前，日历往返不必要。
- **四处装配点抽 helper**（`_cursor_cap(sync_id, rec)`）防四份漂移（审 B P2-1）。
- **为何 cap 挣的是「窗口不越过缺口」而非「重拉重复」**：下轮 start＝游标+1 ≤ min(gap) ⇒ 缺口日重新进窗；若期间已补齐，对账算出空 gap ⇒ 不出 cap ⇒ 游标恢复推进。多日缺口：cap 收在首缺口日前 ⇒ 下轮整段自愈。
- **旧值钳制（clamp）阻断 tier1 overlap 倒漂**（审 A P1-1 / 审 B P1-2）：tier1 起点＝`last+1-overlap`（3186-3190）⇒ 无钳制的 cap 可低于旧游标（overlap 段前缺口）⇒ 每轮回退 overlap 天、窗口无界膨胀。钳制后：cap 只能收口到旧游标为止；overlap 区内缺口靠每轮 overlap 重覆盖自愈（既有机制），cap 不越俎代庖。
- **逃逸闸（审 B P1-1）**：同一 sync_id **连续 7 轮** cap 实际生效（收口改变了推进值）⇒ `_alert_generic`（2210）告警一次（code=`sync.cursor_frozen`，RUNBOOK 注册）——给「永久缺口冻结游标」以可见性，杜绝静默无界重拉。计数通道＝**单源 Valkey 键** `sync:cap_freeze:<sid>`（INCR+EXPIRE 7d，复用 SyncLock 的 Valkey 连接）；cap 未生效即 DEL（清零）；键不存在/Valkey 不可达从 0 起计（进程重启、TTL 过期 ⇒ 告警延迟但不误响）。**不引入进程内 LRU 双通道**——两套计数必漂移，单源足够。
- **终态词**：收口实际改值时 `_advance[2]` 由 `idle`→`partial`。`sync_log.status` 仍按 failed_dates 取原口径（success）——两表分叉是**承载正确性**的（tier1 新鲜度告警与 health_monitor 只认 sync_log.status='success'，tasks.py:436/462、health_monitor/collector.py:334）；`last_status` 消费面仅 =="running" 僵尸判定与展示，partial 无碰撞（审 A P2-8 实证）。

### C. 留痕（审 A P0-1 修法：落 `error` 列，非 note——note 不存在）

收口发生时 `_log(..., error=...)` 的 error 参数追加 `cursor_capped:<cap>`（成功路径恒空串 ⇒ 追加不覆没；先例＝bar_retention_sweep 删除量注记进 error，tasks.py:2172）。API 读侧天然别名 note 返回（sync.py:417）⇒ Web 同步日志页可见。

## 3. 契约细节（自包含）

## 5. 验收（可证伪，mock harness 为主 + dev 真库手工实证）

1. **主判据（DEF-01 复现阻断）**：mock handler 返回 `last_success_date="20261015"` + `cursor_cap="20261013"` ⇒ `_update_sync_state` 收到 `("20261013", …, "partial")`——游标停在缺口前一日。
2. **未声明者逐字现状**：同 fixture 去掉 cap 键 ⇒ 收到原推进值与原终态词。
3. **空缺口/白名单外不出 cap**：helper 单测——`gap_dates=[]` ⇒ None；`sync_id="forecast_sync"` + gap 非空 ⇒ None（稀疏族排除）。
4. **uncertain 不出 cap**：`uncertain="calendar_uncovered"` ⇒ None（真实对账 uncertain 时 gap 恒空，此为防御性守卫用例）。
5. **无键分支同样收口**：mock 返回 `cursor_upto="20261015"` + cap ⇒ 收口至 cap。
6. **全失败/异常不收口**：failed + `last_success_date=None` ⇒ 游标写回旧值（不倒退、不收口）。
7. **clamp 不倒退**：cap < 旧游标（tier1 overlap 场景）⇒ 推进值＝旧游标（clamp 生效），不回退。
8. **error 留痕**：收口发生 ⇒ `sync_log.error` 含 `cursor_capped:20261013`；不收口 ⇒ error 无该串。
9. **逃逸闸**：连续 7 轮收口 ⇒ `_alert_generic` 以 `sync.cursor_frozen` 打点一次（mock `_alert_generic` 断言）。
10. **既有测试零修改全绿**：`test_sync_cursor` / `test_batch109_sync_gap` / `test_batch110_reconcile_scale` / `test_sync_via_kind` / `test_layering` / 全量 pytest。

## 6. 明确不做（本批边界）

- **不改空帧语义**（对账依赖它抓静默洞）；**不改早退分支**（DEF-04 后续条）；**不修既有缺口**（10-14 补数属修复条，观察窗后另立）。
- **不做无界倒退**：clamp 保证游标只收口到旧值为止。若游标已越过缺口（历史遗留），靠修复条 backfill 解，不靠 cap。
- **不覆盖 `astock_basic`**：无对账装配（571-580 无 reconcile）——空帧越界同型风险留存，显式声明不设防，待后续对账扩面条。
- **不做多源多窗协调**；**不新增 sync_log 列**（留痕走 error）。

## 7. 评审要点（复审逐条核）

① 白名单边界：forecast/top_list/block_trade 排除的 prod 证据是否充分；稠密族判定标准（「每日发布」）是否可作为新族加入准则 ② clamp 数学：min(cap) ≥ 旧游标 的保障路径（cap ≥ start-1 ≥ 旧游标？——dense 三族 start=last+1 ⇒ cap ≥ last 恒成立；tier1 start=last+1-overlap ⇒ cap 可低于旧游标 ⇒ clamp 兜底——两段论证是否闭环）③ 逃逸闸计数通道（Valkey TTL 7d）断链语义：进程重启/Valkey 清空 ⇒ 计数归零 ⇒ 告警延迟但不误响——可接受否 ④ 终态词分叉（config=partial/log=success）消费者影响是否已列全 ⑤ 验收 1-10 可证伪性与 fixture 独立性 ⑥ 越界检查（新表列/状态词/模块；动既有测试）⑦ 与 D2 正交。
