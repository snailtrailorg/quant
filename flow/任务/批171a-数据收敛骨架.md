# 批 171a · 数据收敛骨架（目标态 + 区间对账 + 缺失修复）

> 设计依据：**D28《数据收敛与对账》**（分层/契约/算法/表结构/调度/验收全在文档内，此处只写实施与限定）。
> 用户裁定（2026-11-05）：不能头痛医头，要从架构上彻底改，且简洁/分层/高效/可移植/易维护/可追溯。

## 实施步骤
1. **L1 契约**：新增 `src/data_platform/coverage.py`——`CoverageContract` + `CONTRACTS` 注册表（先覆盖 `astock_daily`/`listed_fund_daily`/`cb_daily`/`index_daily` 的 1D 与 `astock_minute` 族的 1min/5min；加密 `axis='continuous'`）。纯数据，零 IO。
2. **L2 对账**：新增 `src/data_platform/reconcile.py` 纯函数 `diff_runs(expected, actual) -> list[Gap]`（区间差集/合并/裁剪），不碰 DB 与表名。
3. **迁移**：`reconcile_run` / `reconcile_item` 两表（D28 §六 SQL 为准；含单测 schema 断言）。
4. **L3 执行**：`src/data_platform/reconciler.py`——两阶段（聚合筛选候选 → 日历反连接取缺失日 → 合并区间 → 按标的调用现有 `adapter.fetch` → upsert），写台账。
5. **L4 调度**：Celery 任务 `data_reconcile`（scope=quick 近 30 交易日；预算与令牌桶复用 D23），增量任务成功后触发。
6. **观测最小集**：`GET /api/data/reconcile/last`（最近 N 轮统计，admin 读）——面板留 171c。

## 限定范围
7 个新/改文件：`coverage.py`、`reconcile.py`、`reconciler.py`、迁移 1 份、`scheduler/tasks.py`（挂任务）、`scheduler/app.py`（调度）、`routes/data.py`（只读端点）。
**不动**：增量同步逻辑、`last_sync_date` 语义、任何现有表结构（只新增两张台账表）。

## 验收（可回归）
- 单测：区间差集 8 例（全有/全缺/头缺/尾缺/中段/跨年/停牌边界/空集）；契约展开 3 市场；批次合并上限。
- 集成（dev）：手工删除 `2026-10-14` 该日 A 股日线 → 跑 `quick` → 该日补齐、`remaining=0`。
- 幂等：同轮连跑 3 次，第 2/3 次 `missing=0, repaired=0`。
- 预算：单轮 ≤2 分钟（近 30 交易日，dev 实测记录）。
