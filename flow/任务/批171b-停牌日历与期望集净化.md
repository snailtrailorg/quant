## 2. 改动规则

### A. 表 `suspend_calendar`（迁移 0168）

```sql
CREATE TABLE suspend_calendar (
    ts_code     TEXT NOT NULL,
    trade_date  DATE NOT NULL,
    suspend_type TEXT NOT NULL,            -- S=停牌 R=复牌（净化只认 S）
    full_day    BOOLEAN NOT NULL DEFAULT true,
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (ts_code, trade_date)
);
```
幂等 upsert；updated_at 无刷新机制（工厂 updates 子句只含 all_cols−pk）——如实降级信息列，验收 2 口径＝「四值列幂等」。注册 `schema_expectations.txt` 一行。

### B. 同步任务 `suspend_d_sync`（注册走 `_TIER1_BATCH` + 扩参边车）

- **注册形态**：`_TIER1_BATCH["suspend_d_sync"] = ("suspend", None, "suspend_calendar", ["ts_code","trade_date"])` ＋ 新增 `_TIER1_BATCH_EXTRA: dict[str, dict] = {"suspend_d_sync": {"transform": ..., "reconcile": False}}`；工厂注册循环改 `_make_tier1_handler(..., **_TIER1_BATCH_EXTRA.get(_sid, {}))`——既有 8 键 `get` 返空 dict ⇒ **逐字零漂移**。
- **工厂两新参**（默认 None/True 零漂移）：
  - `transform: Callable[[DataFrame], DataFrame] | None`——调用点在 `_pull_day` 的 `df.empty` 判空**之后**（空帧 0 行短路在先，transform 只见非空带全列帧）；泛化边界＝仅「源列→落库列」形状适配（布尔派生/列选取），禁业务逻辑。
  - `reconcile: bool = True`——False 时**跳过整个尾部块**（`_reconcile_dates` + `_cursor_cap` 出具 + healed-DEL + 返回体三键 reconcile/gap_dates/cursor_cap 全无）；返回体保留 pulled/saved/failed_dates/expected_days/actual_days/cursor_upto/excluded——无 reconcile ⇒ sync() 的 `r.get("reconcile")` 空、`r.get("cursor_cap")` None ⇒ D1 零交互（双保险：白名单门另挡）。
- **adapter 四注册**：`tushare_adapter.pull_suspend_d(trade_date)`（范式 pull_stk_limit:563-566）；`base._SUPPLY_PULL[("suspend", None)]="pull_suspend_d"`；`base.capabilities` +"suspend_d_sync"；`base.capability_decls` +`CapabilityDecl("suspend","historical",ASTOCK_ALL)`；`markets.SYNC_ID_CAP_MAP["suspend_d_sync"]="inst_event"`；`data_source.DEFAULT_RATE_LIMITS["suspend_calendar"]=0.3`。
- **seed（0168 数据段，0142 模板）**：sync_config——id/name/tushare_api='pro.suspend_d'/pg_table='suspend_calendar'/data_type/sync_mode、**retention='2026-10-01'**、supports_backfill=true、trade_day_filter='trade_day'、enabled=true、16:35 档；sync_kind_config——`(suspend, None) → suspend_calendar`（pk/float/text 列形状）。
- **调度**：交易日 16:35；上游时刻未核实 ⇒ overlap=3 兜底（§6 声明；不稳可后移 18:10，st_list 先例）。

### C. 净化口（integrity.py，出入参恒 vt 形态）

```python
def suspended_on(day: date, vt_symbols: set[str]) -> set[str]:
    """day 当日全日停牌 ∩ vt_symbols（仅 suspend_type='S' AND full_day；返回 vt 形态子集）。"""

def suspend_days_bulk(first: date, last: date, vt_symbols: set[str]) -> dict[str, list[date]]:
    """区间批量：{vt_symbol: [窗内停牌日]}（同 S+full_day 口径；口内 to_ts_code 归一查表、
    返回键 vt 形态——与消费方 risk.py 循环变量 sym 直接 get，防 ts/vt 错位静默失效）。"""
```
- **消费点 1（integrity 面板，risk.py）**：聚合前一次 `suspend_days_bulk` ＋ 一次 SM 批量 `(vt_symbol, delist_date)`；循环内 `expected_bars(..., suspend_days=per_sym.get(sym))`、`last=min(last,delist) if delist else last`；减项 `expected -= len(窗内停牌日) * bars_per_day(freq)`；crypto 显式跳过；外推分支不减。
- **消费点 2（per-symbol 对账）**：`_reconcile_symbols` scope 级一次 `suspend_days_bulk(窗)`（**非逐日 suspended_on**——155 日段=155 查询违批 110 读取契约）＋ 一次 SM delist 批量（`_sm_universe` 保持 3 元组不动，delist 在调用方二次 SELECT，插在 symbols 集建好后、同 category/venue 宇宙）；差集与窗上界两处净化。
- **消费点 4（data_continuity_check）**：改写为 per-symbol 语义——一次 `suspend_days_bulk(week_ago, yesterday, 短缺标的集)`，循环内 `expected_sym = expected − len(该标的窗内停牌日)`（expected 现为全局标量 tasks.py:615）；**副收益＝停牌股不再触发无效补采**（:620-632 pull_daily 循环）。
- **R 行永不净化**（三条件 S+full_day+归一，两口同契约，验收钉）。

## 5. 验收（可证伪）

1. **落库**：dev 触发 suspend_d_sync 单日 ⇒ 10-14 落 13 行（R 2 行原样）、full_day 全 true。
2. **幂等（四值列口径）**：同日连跑 2 次 ⇒ 行数与 (ts_code,trade_date,suspend_type,full_day) 不变。

4. **expected_bars 减项**：直调——1D 减 len(窗内停牌日)、1min 减 ×240；crypto 传参断言不减。
5. **退市截断（v3 重写）**：直调 `expected_bars` + 合成夹具（造 delist 早于窗末样本）⇒ last 截 delist；`_reconcile_symbols` 窗上界截断单测（mock SM delist）；**面板差断言删除**（dev 恒零变化——§1 修正表述，819 只零 bar 标的「不出现在 items」钉现状防回归即可）。

7. **工厂开关**：suspend_d_sync 返回体**无** reconcile/gap_dates/cursor_cap 三键；既有 8 键返回体不变（`_TIER1_BATCH_EXTRA` 缺省零漂移）。
