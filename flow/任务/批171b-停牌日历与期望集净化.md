## 0. 契约（一句话）

新增**停牌登记表 `suspend_calendar`**（tushare `suspend_d` 每交易日增量落库，逐 `(ts_code, trade_date)` 幂等 upsert）＋**期望集净化口 `suspended_on(day, vt_symbols) -> set`**（内存查表）：per-symbol 消费点（对账差集过滤、integrity 减项、退市截断）在算「该标的该日是否应有一根 bar」时先问它——**停牌日不算缺失、退市后不算期望**；族级日集（`_trade_dates_in_range`/`_expected_trading_days`）**不动**（它们无 symbol 维度，剔除须在 per-symbol 口）。

**为什么是新表而不是塞进 trade_cal**：trade_cal 是 `(exchange, cal_date)` 族级粒度（全市场开/休），停牌是 `(symbol, date)` 标的级事实——粒度不同不揉合（实体设计双判据：无继承不抽象成一类）。**为什么不并入 sync_gap 排除段**：排除段（unreachable/policy_discard）是**对账结论**，停牌是**输入事实**——上游事实先于对账，混进结论表会造成「停牌被当缺口检出的那段历史无法区分输入与判定」。

## 1. 现状（指针，不复述事实）

- **suspend_d 实测**（2026-11-06 本地真调）：4 列 `ts_code/trade_date/suspend_timing/suspend_type`；每交易日 7~15 行；`suspend_timing IS NULL`＝全天停牌（样本全 NULL）；`suspend_type`：`S`=停牌/`R`=复牌（复牌行只登记「当日恢复」，仍属停牌登记流的同一接口输出）。
- **DEF-09**：SM `delist_date` 列在（转债 827/1176 有值）但 `_sm_universe` 只取 `vt_symbol, updated_at, list_date`（engine.py:2361）；integrity/对账期望均不减退市段。
- **DEF-10**：期望集＝trade_cal 全市场交易日，无停牌减项——`000002.SZSE` 被误记缺 155 日 12 段（实为停牌，2016-02~06 最长段）。
- **三消费点**：① 对账 `_reconcile_dates(expected=...)`→差集→`_to_segments`（族级 expected + where 过滤子集）；② `_expected_trading_days`（sync_log 展示计数，族级）；③ `integrity.expected_bars`（面板，per-symbol、`bisect` 开市日）。
- **既有先例**：迁移表命名/列形状单一真源 `schema_expectations.txt`（test_batch109:105-110 钉）；tushare 按日族 handler 工厂 `_make_tier1_handler`（拉取-落库同构）；`_upsert_sync_gap` 排除段语义（engine.py:1867-1895）。

## 2. 改动规则

### A. 表 `suspend_calendar`（迁移 0168）

```sql
CREATE TABLE suspend_calendar (
    ts_code     TEXT NOT NULL,             -- 源格式 000016.SZ
    trade_date  DATE NOT NULL,
    suspend_type TEXT NOT NULL,            -- S=停牌 R=复牌（源语义原样保留）
    full_day    BOOLEAN NOT NULL DEFAULT true,  -- suspend_timing IS NULL ⇒ true
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (ts_code, trade_date)
);
```
- 幂等 upsert（ON CONFLICT (ts_code,trade_date) DO UPDATE SET suspend_type/full_day/updated_at）。
- 注册 `schema_expectations.txt` 一行（仓规）。

### B. 同步任务 `suspend_d_sync`（tier1 按日族工厂）

- `_make_tier1_handler(kind='suspend_d', sub=None, table='suspend_calendar', pk=['ts_code','trade_date'], ...)`——**不走通用 upsert 列映射**：suspend_timing→full_day 布尔转换属拉取侧适配，工厂参数带 `row_transform`（或本批单独小 handler，见 §2.B' 取舍）。
- 窗口：增量 `last_sync_date+1 ~ _data_ready_end_date(0)`；**回补**支持（backfill_from 按日重拉）。
- 调度：交易日 16:35（A 股数据齐后、17:10 jq 前——停牌事实先于对账消费）。
- **日历覆盖门**：`_trade_dates_in_range` 返回 None ⇒ 本轮不拉（fail-open 回自然日会多打无意义日期）。

### B'. 取舍：工厂 vs 单独 handler

工厂列映射（float_cols/text_cols）做不了 `suspend_timing IS NULL → full_day` 的布尔转换。两个方案：
- **方案一（选）**：`_make_tier1_handler` 加 `transform: Callable[[DataFrame], DataFrame] | None = None` 参数（默认 None 零漂移；suspend_d_sync 传 `df.assign(full_day=df['suspend_timing'].isna())` 后按通用列映射落库，text_cols=['suspend_type']）。改动集中在工厂一处，未来同类接口（如 sys_suspend 全史版）直接复用。
- 方案二（弃）：单独手写 handler——与工厂拉取/限速/窗口/回补逻辑重复，两套语义。

### C. 净化口 `suspended_on(day: date, vt_symbols) -> set[str]`（data_platform/integrity.py）

```python
def suspended_on(day, vt_symbols) -> set[str]:
    """day 当日全日停牌 ∩ vt_symbols 的子集（源码归一 vt 形态后返回）。"""
    # SELECT ts_code FROM suspend_calendar WHERE trade_date=%s AND full_day
    #   AND src_to_vt(ts_code) = ANY(%s)  —— 或全取当日后内存 ∩（≤15 行/日，内存口便宜）
```
- **消费点 1（对账）**：`_reconcile_dates` 差集后、`_to_segments` 前——`missing = [d for d in missing if vt(symbol_set) not in suspended_on(d, ...)]`。⚠️ `_reconcile_dates` 是族级（无 symbol 参数）——净化在 **per-symbol 消费侧**（`_reconcile_symbols` 的 gaps 计算、`data_continuity_check`），per-date 族（拉全市场）当日停牌标的**没有 bar 本属正常**但差集口径按日不按标的 ⇒ **per-date 族不净化**（当日整族拉回时停牌标的无行 ⇒ 差集抓不到 per-symbol 粒度 ⇒ 停牌标的在 per-date 族的缺口本就不产生——见 D29 §四 per-date 差集=日期级）。**净化的真实受益者是 per-symbol 对账与 integrity 面板**。
- **消费点 2（integrity 面板）**：`expected_bars` 增可选参 `suspend_days: list[date] | None`（该 symbol 的停牌日列表，调用方 risk.py:358 一并批量查）——`expected -= count(s in [first,last])`；**退市截断**同处：`last = min(last, delist_date)`（SM 批量取，见消费点 3）。
- **消费点 3（退市日）**：`_sm_universe` 补取 `delist_date`（SELECT 加一列，返回元组扩为 4 元）——`_reconcile_symbols` 期望窗上界 `min(end, delist_date)`；integrity `risk.py` 聚合循环同截断。**加密/股票 delist 全 NULL 不受影响**（NULL ⇒ 不截断）。

### D. 对既有行为的净化边界

- **只减期望、不删历史**：既有 `sync_gap` 的误报 `open` 行（000002 的 155 日段等）——本批**不主动清**（修复出口属后续条）；但**下一轮对账自然消解**：期望窗截断后差集不再含停牌日 ⇒ per-symbol `_sync_gap_sync` 把窗外/消失锚 closed（D2 window_guard 语义下窗内正常闭合）。
- **suspend_calendar 覆盖窗内查不到行 ≠ 不停牌**：历史窗（如 2016 年）suspend_d 未回补 ⇒ 净化不生效、期望照旧——**如实保留**（宁多报不漏报），回补 suspend_calendar 后自然净化。

## 3. 契约细节（自包含）

- **表**：`suspend_calendar (ts_code, trade_date, suspend_type, full_day, updated_at)` PK `(ts_code, trade_date)`；迁移 0168 + schema_expectations 注册。
- **任务**：`suspend_d_sync`＝`_make_tier1_handler(transform=...)` 首个消费者；`sync_config` 建行（enabled、调度 16:35）；`sync_kind_config` 归置行（kind=suspend_d）。
- **净化口**：`suspended_on(day, vt_symbols) -> set[str]`（integrity.py，全日停牌口径）；`expected_bars(..., suspend_days=None)`（可选参，默认 None 零漂移）；`_sm_universe` 返回 4 元组——**调用方 grep 实证仅 engine.py:2573 一处**（`_reconcile_symbols` 内批量预取；risk.py 聚合走自己的 SELECT 不经它），扩元组无外部破坏面。
- **不新增状态词/模块**；`_gap_judge`/`window_guard`/`cursor_cap` 不动；分层：suspend_calendar 读取在 data_platform（层 1）⇒ engine（层 1 同层）/risk.py（层 2 消费）合法。
- **与 D1/D2 正交**：净化改变「期望集内容」，不触碰游标/状态机——D1 的 cap 出具条件（gap 非空）在净化后 gap 变小 ⇒ cap 更少出现 ⇒ 自然受益。

## 5. 验收（可证伪）

1. **落库**：dev 触发 `suspend_d_sync` 单日 ⇒ `suspend_calendar` 当日行数＝API 实测行数（10-14=13 行，全 full_day=true）。
2. **幂等**：同日连跑 2 次 ⇒ 行数不变、updated_at 刷新。
3. **净化口单测**：`suspended_on(date(2026,10,14), {'000016.SZSE',...})` ⇒ 含 000016（实测它在 10-14 停牌 S）、不含未停牌标的；非停牌日 ⇒ 空集。
4. **integrity 减项**：dev 造 000002 于 2016-02-15~06-08 缺行（或直查真库——dev 已有此形态）⇒ 净化前 expected 含该段、净化后 `expected_bars(..., suspend_days=该段)` 恰减该段开市日数。
5. **退市截断**：转债样本（delist_date=2025-10-27 的 110059 类）⇒ `expected_bars` 的 last 被截到 delist_date ⇒ 该标的从「missing」转「complete/partial（按截断后口径）」。
6. **per-symbol 对账净化**：`_reconcile_symbols` 窗内含停牌日 ⇒ 该日不进缺口差集（单测 mock suspended_on 返回集）。
7. **既有测试零修改全绿** + 全量 pytest。
8. **suspend_d_sync 回补**：`backfill_from=20261001` ⇒ 10 月窗逐日落库（dev 真调 API）。

## 6. 明确不做（本批边界）

- **不做全史回补**：suspend_d 按日拉全史（2010~）需 ~4000 次调用，另立运维动作（上产后手动触发回补窗，不入本批代码面）。
- **不清既有 sync_gap 误报行**（下轮对账自然消解，见 §2.D）。
- **不动 per-date 族对账**（差集=日期级，停牌标的无 bar 不产生缺口——净化无对象）。
- **不做盘中 suspend_timing（半日停牌）口径**——样本全 NULL，等真出现半日数据再议（`full_day` 列已预留语义）。
- **不做加密停牌**（无此概念）。

## 7. 评审要点

① 表粒度选择（symbol×date 独立表 vs 塞 trade_cal/sync_gap）② 工厂 `transform` 参数的泛化边界（会不会被误用成拉取侧大杂烩）③ `suspended_on` 放 integrity.py 的分层归属（engine 消费层 1 内部依赖方向）④ `_sm_universe` 4 元组的调用方完备性（grep 实证仅 engine.py:2573 一处——risk.py 聚合独立 SELECT 不经它；评审复核此 grep）⑤ per-date 族「不净化」论证的反例排查（停牌标的当日无 bar，差集按日不按标的——有没有路径让它仍产缺口）⑥ 验收 4/5/6 可证伪性 ⑦ 迁移 seed 与 schema_expectations 仓规 ⑧ 与 D1/D2 正交性。
