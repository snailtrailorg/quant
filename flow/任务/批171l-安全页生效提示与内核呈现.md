## 0. 契约（自包含）

### 件一：待下次扫描生效角标
- **现象**：探测/采集代码修上产后，snapshot 仍是旧一轮产物（06:00 beat 周期）——页面显示旧值无解释，运维空等一个周期（2026-11-06 valkey 案实证；手动 `POST /api/security/scan` 即时坐实也实证有效）。
- **判定（服务端单源）**：snapshot API 增 `stale_after_deploy: bool`——`snapshot.created_at < 最近部署时刻` 时 true。最近部署时刻源=**release 目录名**（`releases/<YYYYMMDDHHMM>-<sha>` 按字典序 max 的目录名前 12 位解析——ansible 通道读不可得，改**落库锚**：部署时刻在 release 时由管道写 system_config `last_deploy_ts`？**不扩管道**——零后端新查询原则下的可行锚=前端已持有的 `build_info`？无。**裁定：服务端从 `readlink server` 软链名解析**——uvicorn 进程 cwd 即 release 目录（`os.readlink('/proc/self/cwd')` 免 shell）⇒ 目录名时间戳 vs snapshot.created_at 比较。**deploy 后未重启的场景**（flip 但未重启）不覆盖——接受（波次重启是管道八阶段必经，未重启=未完成部署）。
- **FE**：A 区状态卡（status 卡头）条件渲染「待下次扫描生效」角标（el-tag warning）——`stale_after_deploy && !scan_running`；正文提示「页面数据为上一轮快照（{scan_date}）；新代码已上产，等待 06:00 例行扫描或手动触发」。`scan_running` 时显示扫描中（既有）不叠加。

### 件二：内核安全更新呈现（能力面）
- **数据**：`snapshot.dnf` 分区 `{status, checked_at, pending_count, packages:[{name, errata}], updates}`（wrapper :56 契约）——**kernel 包在 packages 里以 name 前缀 `kernel`/`kernel-core` 出现**；另「已安装待重启」= `dnf needs-restarting -k` 语义（wrapper 未采——**本批不加**：kernel 待重启的权威判定需 root 命令，走 wrapper 扩面=管道改动，炸半径不合小批比例。呈现面先覆盖「kernel 安全更新待装」）。
- **FE**：SecurityTab A 区与组件卡之间加**条件卡**（`dnf.pending_count>0` 时显示）：「系统安全更新 N 项」+ 明细行（name+errata）；**kernel 行高亮**（critical tag「需重启生效」——kernel 更新装后须重启，静态提示不判当前重启态）。`pending_count=0` 或 degraded ⇒ 整卡不渲染（零噪音）。
- **明确不做**：①`needs-restarting` 采集（root 面——若未来需要，走 quant-dnf-security wrapper 扩展子命令+管道评审）②dep_health 汇总口径改动（kernel 不进 component 汇总是既有口径——呈现层独立卡足矣）。
