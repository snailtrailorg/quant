> **淘汰**：上产后归档。

## 0. 契约（自包含）

### 件一：「扫描报告」卡（合并原 扫描状态+快照日期 两卡——名词用户裁定：「数据快照」是讨论过程词非信息本名；卡内容=一份报告的属性〔哪天/什么质量/哪些降级/重扫〕，「扫描报告」四字自含来源+形态，与「最近上产」卡对仗）
- 结构：大字=快照日期 + status tag（ok/degraded）+ 次行=上次扫描完成时刻 + degraded 分区明细（原状态卡内容全量迁入）+ 「立即重扫」按钮（动作与数据同卡）。
- **171l stale 角标+解释文案退役**（用户裁定：`页面为上一轮快照；新代码已部署，等待 06:00 例行扫描或手动触发`——机制自白费解且不重要；两卡并排时间自明，用户自行推断）。`stale_after_deploy` API 键**保留**（FE 只是不再渲染文案——机制可能还有消费方；删键是接口破坏）。
- 原「漏洞库日期」卡（vulnDb）不动——grype 库新鲜度是另一维度。

### 件二：「最近上产」卡（新增）
- 首行=当前运行版（时间+commit 短 SHA+双链一致性标记：server=web ✓绿 / 分裂 ⚠黄——免费送的部署健康检查）。
- 次列最近 5 版（时间+SHA，当前版高亮）。
- 数据源（零新查询零特权，快核提示收编）：API 读 `/proc/self/cwd`（当前 server 版——与 stale 判定同锚）；`releases/` 路径从 cwd 剥 `/releases/<id>` **派生**（非硬编码——dev 布局天然 fail-open）；listdir 按 `^\d{12}-` **过滤**（批 128 GC 保护名单含 web-legacy 等非常规条目，裸尾 5 会混入）后字典序尾 5。web 链 readlink（同 release id=✓；0755 world-readable 快核已证）。
- snapshot API 响应加 `deploy` 块：`{"current": "202611081549-8027942", "web_same": true, "recent": ["202611081549-8027942", ...]}`。

### 布局（用户裁定：漏洞库卡不动——没有任何卡被删）
现状四卡=活跃漏洞/扫描状态/快照日期/漏洞库。改造后仍四卡：
**活跃漏洞 / 数据快照〔扫描状态+快照日期两卡合并〕/ 最近上产〔新增，占合并腾出的位〕/ 漏洞库〔原样保留〕**。
「扫描报告」卡内容=原状态卡全部信息（status/上次扫描时刻/degraded 明细/重扫钮）+原日期卡的快照日期大字与**依赖滞后小字**（快核③裁定：dep_outdated 一并迁入——同属「这份报告的元信息」；D 区不重复）。
