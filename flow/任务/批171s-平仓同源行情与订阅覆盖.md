## 0. 用户裁定（2026-11-09，全部为硬约束，按裁定顺序归并去重）

1. **行情/交易必须同源**：平仓定价只用 XTP/EMT 同源 hub tick（`hub:latest_tick:{account_id}:{symbol}`）。腾讯 `market_snapshot.get_quote`（外部网页快照、无保障、非同 SDK）、成本价、陈 `bar_1min` 一律禁用。
2. **定价规则全部下沉 Adapter 接口，主流程零硬编码分支**：
   - 有跌停线 → 跌停价挂卖（价带内、以对手最优价成交）；
   - 无跌停线 → **实时可见最优对手单价格**（非昨收——并非所有标的都有昨收），再让一定幅度保证成交；「×0.9」只是示例、不一定恰当（用户点名反例：加密币**空单**平仓是买入，让价方向相反）；
   - 「有无跌停线判定 / 对手价档位 / 让价方向与幅度 / 拆单上限 / 最小价位取整」等**所有针对账号与标的种类的特异性**，一律由注册进来的实体（`ExecutionAdapter` 子类）提供接口实现，**不得在主流程写 `if 品种/板块` 分支判断**。
   - 用户举例：A 股平仓看买1；加密多单看买1、空单方向相反；场内基金 / 可转债按各自规则确定。
3. **撤单重试后必须重新获取参考价**再挂，绝不能复用同一个价格反复尝试；若仍不能成交（剧烈波动/踩踏），暂接受该规则、不无限兜底。
4. **重试编排**：先将账号下所有持仓平一轮（XTP 无批量下单原语 ⇒ 一个请求=一个标的，故循环逐标的发单），再对不成功的在同一线程里循环重试（每轮重新取价）；次数/间隔可配、有上限；到上限仍未平 = 告警 + `order_log` + 处置时间线 + FE 渲染 `pending/no_quote`（**全链可见**）。
5. **线程**：账号间复用现有 per-account runner 进程并行（已达标，核查结论=合适直接用，不新增进程/线程池）；**每个 runner 进程内开一个专用 daemon 线程**承载整轮急停，主循环拍只做「取命令 → 投递 → 回执」，不得在主循环内 sleep / 长循环（卡心跳/bar/断流=僵尸）。紧急处置事务不能串行排队。
6. **实体粒度 = provider 单维复用 `ExecutionAdapter`**：特异性以可覆写方法 / 配置属性加在 XTP/EMT/Crypto 子类；不新建二维注册表、不新增品种实体类。
7. **品种规则 = Adapter 的配置属性**：有代码缺省值、**界面可配、落库**（不写死在分支里）。
8. **持仓标的进 hub 订阅真相源**（根本保证「有持仓 ⇒ 有同源行情 ⇒ 能平仓」）。
9. **急停单写 `order_log`**（审计缺口），并修认领链（`client_id` → `vt_orderid`）。

## 1. 现状与根因（已实证，勿重排查）

- **定价全错**：`_close_all_positions` 依次用过 `avg_price`(成本价)、`bar_1min`(陈价)、腾讯 `get_quote`。prod 实测 510010 种子持仓成本 1.000，当日 `pre_close=1.760 / lower_limit≈1.584 / last≈1.761`，按成本价挂卖恒被 XTP 拒 `The price goes beyond the limit of rise and fall`（真实账号同理）。
- **同源 hub tick 落地**（`src/md_hub/parts.py:282-294`）：主键 `hub:latest_tick:{account_id}:{symbol}` 含 `last/open/high/low/pre_close/upper_limit/lower_limit/bid[5]/ask_v[5]/ask[5]`，TTL 65s，盘中秒级刷新、盘后过期。`symbol`=`_project_symbol`=项目口径（SSE→`.SHSE`），`account_id`=`trading_account.id`。公共键 `hub:latest_tick:pub:{symbol}` 只有 `ts/last/volume`，**不含涨跌停/五档，平仓不得用**。审官 A 已实证 `to_vt_symbol("600000.SSE")`→`600000.SHSE` 与写入键逐字符相等。
- **网关插件齐**：`md_gateway.py` 有 `XtpMdGateway` / `EmqMdGateway` / `_BaseCryptoMdGateway`，统一产出 vnpy `TickData`（含 `limit_up/limit_down/bid_price_1..5`），同一套 SDK = 行情/交易同源。加密网关 tick 是否填五档 = 上产前必须真连核（写进 §4 S10 边界）。
- **账号间并行已达标**：web `_dispatch_risk_cmd`（`risk.py:301-307`）一次给所有账号写 `risk:cmd:{tid}`，各账号 runner 进程并行消费（`hub_worker.py:718`），TD 会话在各自进程内构造（`td_registry.build_td_runtime`）——不同账号 = 不同进程 + 不同会话，天然隔离。**不需要新增进程/线程池。**
- **不适配点（本批核心）**：`consume_risk_cmd` 挂在 `EngineLoop` **单线程主循环拍**里（`risk-cmd-poll` period=1s，`hub_worker.py:715`），同步执行且 `close-all` 分支有 `time.sleep(2)`（`:90`）、`_close_all_positions` 内有 `_t.sleep(1.5)`。把「一轮全平 + 循环重试」放这里会卡死心跳（5s）/bar 消费/断流检测/喂狗 → 被误判僵尸。
- **XTP 无批量下单**：SDK 唯一原语 `InsertOrder(XTPOrderInsertInfo*, session_id)` 单结构单 `ticker`（`xtp_trader_api.h:720`），vnpy `send_order(OrderRequest)` 亦单笔。「一轮全平」= 在账号专用线程里循环逐标的发单（N 次 `send_order`），非一次请求。
- **认领链 P0（审官 A 真库实证）**：`send_order` 返回的是 **client_id**（`adapters.py:232`），却被写进 `order_log.vt_orderid`，且 INSERT 不写 `client_order_id` → `write_order_status` 两条认领路全落空，急停行永久卡 `submitted`；拒单回执 `od.vt_orderid in ids` 里装 client_id → 交易所拒单永不计数、虚报成功。
- **现成真源（复用，不新建）**：`security_master.category`=`stock/listed_fund/convertible/perp`、`board`=`main/chinext/star/bse`、`band_rules`(exchange×board→pct)；`perms.py:121-168` 已有 `category→exchange→board` 规则表范式（「不硬编码分支」的先例）。
- **配置范式（复用）**：`system_config(key,value,value_type,description,updated_at,updated_by)` + `RunConfig.vue` 通用编辑（按 `value_type` 渲染 input）+ `require_perm("system_config")`；迁移最新 `0174_live_task_account_guard.py`。`strategy_framework.md_session.load_xtp_window_cfg` 已有「层 2 读 system_config」先例，分层合法。
- **回执窗实为 5s**（`risk.py:310`，docstring 写 10s 是错的）：补发/重试结果在窗后发生，必须有独立可见通道（件五/件八）。

## 2. 契约（自包含）

### 件一：同源行情读取（新 `src/data_platform/hub_quote.py`，下沉数据层）
```
get_hub_tick(account_id: int, symbol: str) -> dict | None
```
- `business_redis(decode_responses=True, socket_timeout=2)` 读 `hub:latest_tick:{account_id}:{to_vt_symbol(symbol)}`；返回解析后的 dict（`last/pre_close/upper_limit/lower_limit/bid/ask/ts`）。
- 键缺失 / JSON 坏 / Valkey 不可达 → `None`（never-throw，调用方按「无同源行情」处理）。`account_id is None` 硬拒（防 `hub:latest_tick:None:*` 全仓 no_quote）。
- **显式超时**（审官 A P1-5）：默认 client 无 `socket_timeout` 会在钩子内挂起；本函数 2s 上限 + decode。
- 不读腾讯 / bar / 成本价（三个出口本批全部退役）。

### 件二：Adapter 定价与规则接口（provider 单维，改 `strategy_framework/adapters.py`）
`ExecutionAdapter` 基类新增可覆写方法（**主流程只调接口，零 `if 品种` 分支**）：
```
def close_policy(self) -> dict                              # 本 provider 的品种规则（件三配置属性）
def opponent_price(self, tick: dict, action: str) -> float  # 可见最优对手单：SELL→bid[0]，BUY→ask[0]；子类按 category 可覆写（场内基金/可转债看规则）
def has_limit_band(self, tick: dict, sym: str) -> bool     # 有无跌停线判定（缺省 lower_limit>0）
def close_reference_price(self, tick: dict, pos, action: str) -> float:
    # 缺省实现：has_limit_band → 跌停价；否则 opponent_price × 让价系数（方向感知，见下）
    # 子类整体覆写（例：加密空单平仓=BUY → 卖1 ×(1+aggression)；A 股 SELL → 买1 ×(1-aggression)）
def max_close_order_qty(self, sym: str) -> int             # 拆单上限（缺省 100000，见件三配置）
def round_close_price(self, px: float, tick: dict) -> float # 最小价位取整（防跌破/越界）
```
- **方向感知让价**：不硬编码 `*0.9`。规则给 `aggression`（幅度，如 0.10），由 `opponent_price` 的 `action` 决定上下（SELL 往下让、BUY 往上让），加密空单反例由此消解。
- `has_limit_band / opponent_price / 让价 / 拆单上限 / 取整` 全部在 Adapter 内，`trading._close_all_positions` 只调 `adapter.close_reference_price(tick, pos, "SELL")` 与 `adapter.max_close_order_qty(sym)`。
- 无可用价 / 无对手单 → 返回 `0.0` → 调用方按 `no_quote` 处理（fail 留痕，不静默降级）。
- `order_type="limit"`（XTP 市价单仍带 price 字段、实测同样越界拒）。

### 件三：品种规则 = Adapter 配置属性（落库 + 界面可配 + 缺省）
- 每个 Adapter 实例一组 `close_policy` 配置属性：`has_limit_band`(bool) / `opponent_depth`(int，缺省 1=最优) / `aggression`(float，缺省 0.10，方向感知) / `max_order_qty`(int，缺省 100000) / `price_tick`(float，最小价位) / `retry_interval_s`(5) / `retry_max`(10)。
- **落库**：`system_config` 键 `close_policy.{provider}[.{category}].{attr}`（**每个标量一条，`value_type=int/float/bool`**——与 `RunConfig.vue` 现成控件逐一对齐；不引入该页无编辑器的 `json` 类型），**迁移 0175 种子**插入缺省行（与 `alert_*`/0173 同款）。
- **缺省值**：代码常量（Adapter 类属性）——缺行 / DB 读失败 / 值非法 → 回落代码缺省并 `logger.warning`（fail-open 到缺省，**留痕非静默**）。
- **界面可配**：复用 `RunConfig.vue` 通用编辑（按 `value_type` 渲染）+ `require_perm("system_config")`；**FE 零新增页面**，新增种子行即可编辑。
- 分层：读 `system_config` 走 `data_platform` 封装（同 `md_session` 先例），Adapter 不 import web_api。

### 件四：账号进程内专用线程（改 `strategy_runner/hub_worker.py` + `web_api/routes/risk.py`）
- 主循环拍 `_risk_cmd_poll`（1s）只做：GETDEL 取命令 → `queue.Queue` 投递给该 runner 的 `EmergencyWorker` daemon 线程 → **立即返回**（不 sleep、不循环、不发单）。
- `EmergencyWorker`（每 runner 一个 daemon 线程，随 loop 启动）：
  - `cancel-all`：保持现状单发 `_cancel_working_orders`。
  - `close-all`：撤在场单 →（撤→平稳定窗，sleep **在专用线程内**，不卡主循环）→ **一轮全平**（对所有持仓逐标的调件二接口发单）→ 收集未成功项 → **循环重试**（每轮：撤未成交单 + **重新 `get_hub_tick` 取新参考价** + 重新定价 + 重挂，绝不复用旧价）→ 到上限。
  - 回执：第一轮完成即写 `risk:cmd:result:{req_id}`（带 `pending`/`no_quote`/`retrying` 清单）；重试终局另写 `risk:cmd:result:{req_id}:final`（TTL 10min）+ 时间线/告警，**不占用 5s 回执窗**。
- **TD 会话线程安全**：同账号的 send/cancel/query 由该账号**唯一专用线程**串行调用（不并发），账号间不同进程天然隔离 ⇒ 不引入同会话并发风险（用户「不同线程操作不同账号接口」在此已满足）。
- 回执窗 `risk.py:310` 5s 不变；`_dispatch_risk_cmd` 返回增 `pending`/`no_quote`/`retrying` 字段。

### 件五：重试终止 + 全链可见

### 件六：持仓标的进订阅真相源（改 `src/md_hub/main.py:_desired_symbols`）

- **S10 真库实证（上产盘中）**：hub 有持仓标的 tick、平仓单以同源定价发出、不再出现 `beyond the limit`、终态回写成功；**盘后 `hub:latest_tick:*` 为空属预期（TTL 65s）**。加密实盘 gate 未开（币安/OKX API ⛔）：加密 Adapter 平仓规则只定义接口 + 单测，不做 prod 真连验收（边界如实记录）。

## 5. 不做的事（边界）

- 不做腾讯 / 成本价 / 陈 bar 的任何静默降级（不同源=不合规，宁可留痕未平）。
- 不做同账号内**多标的并发**发单（TD 会话并发安全未实证；专用线程内串行，账号间靠进程并行）。
- 不做平仓时临时订阅（用户已否，属动作内补丁）。
- 不新建二维注册表 / 品种实体类（provider 单维复用 Adapter）。
- 不改 XTP 连接窗、不改 hub 进程模型、不改账号间并行机制。
- 不做无上限重试、不做自动反复重跑整轮 close-all。
- 不改 `risk:cmd:*` 命令通道语义（GETDEL 幂等单消费保留）。
