# 批 171s · 平仓同源行情定价 + 持仓标的订阅覆盖 + 急停审计

> **依据**（引用 ≤2）：`docs/architecture/A03-数据供给总线设计.md`（行情/交易同源）；`src/md_hub/parts.py` `_write_latest_tick`（hub tick 落地契约）+ `src/strategy_runner/trading.py`（急停链现状）。
> **性质**：架构级修复。前序批 171n/171o/171r 的 e2e 连坐暴露——平仓用成本价/陈分钟线/腾讯外部行情定价，被交易所按涨跌停拒单；且 hub 只订阅任务标的、存量持仓标的无同源行情。
> **淘汰**：上产后归档。

## 0. 用户裁定（2026-11-09，四条，均为硬约束）

1. **行情/交易必须同源，禁用腾讯**。`market_snapshot.get_quote`（腾讯网页快照）是外部数据、无保障、且与 XTP 交易柜台不同源 —— 不得用于平仓定价。系统内已有 XTP 行情 hub（`quant-md-hub@{account}`，`XtpMdGateway`），其 tick 由 XTP 行情 API 产出、与交易同 SDK，自带涨跌停价与五档。
2. **持仓标的进订阅真相源**（根本保证）：hub `_desired_symbols` 增加「账户持仓标的」一源，使「有持仓 ⇒ 有同源行情订阅 ⇒ 能平仓」，与既有 running 任务标的/白名单/临时订阅三源并列。
3. **定价规则**：同源 hub tick 有 `lower_limit`（跌停价）→ 用跌停价挂卖（必然在价带内、以对手方最优价成交）；**无 `lower_limit` 的标的 → 按 `last × 0.9` 平仓**（用户 15:30 补充）。
4. **无同源行情时 fail 明确留痕、不阻塞、定时重试**：该标的记 `no_quote` + 告警，不静默降级到任何替代价、不阻塞其他标的/主循环；后台定时重试，重试间隔与次数做配置项，缺省 **5 秒 / 10 次**。

## 1. 现状与根因（e2e 实证，勿重排查）

- `trading.py:_close_all_positions` 依次用过 `avg_price`(成本价)、`bar_1min`(陈价)、腾讯 `get_quote` —— 全错。prod 实测 510010 种子持仓成本价 1.000、当日 `pre_close=1.760 / lower_limit≈1.584 / last≈1.761`，按成本价挂卖恒被 XTP 拒 `The price goes beyond the limit of rise and fall`（真实账号同理）。
- hub tick 落地（`src/md_hub/parts.py`）：
  - 主键 `hub:latest_tick:{account_id}:{symbol}` —— 完整字段 `last / open / high / low / pre_close / upper_limit / lower_limit / bid[5] / ask[5]`，TTL 65s，盘中秒级刷新、盘后过期（15:05/15:30 实测键为空属正常）。
  - 公共键 `hub:latest_tick:pub:{symbol}` —— 仅 `ts/last/volume`（stock_detail 用），**不含涨跌停，平仓不得用**。
  - `symbol` = `_project_symbol(tick)` = 项目口径（SSE→`.SHSE`）；`account_id` = hub 实例号 = `trading_account.id`。
- 订阅真相源 `src/md_hub/main.py:_desired_symbols` = `live_task(running).symbol` ∪ `system_config.hub_shadow_symbols` ∪ `hub_transient_subs`，**不含持仓标的**。
- worker（`quant-live-task@{tid}`）主循环 `EngineLoop` 是单线程钩子：`risk-cmd-poll` 每 1s 同步调 `consume_risk_cmd`。**任何 `sleep` 重试都会卡死心跳/bar 消费/断流检测**（50s 级），必须做成非阻塞后台钩子。

## 2. 契约（自包含）

### 件一：同源行情读取（下沉 data_platform 层，分层铁律）
新模块 `src/data_platform/hub_quote.py`：
```
get_hub_tick(account_id, symbol) -> dict | None
```
- 读 `business_redis().get(f"hub:latest_tick:{account_id}:{vt}")`，`vt = to_vt_symbol(symbol)`（`.SSE`→`.SHSE`，与写入口径一致）。
- 返回解析后的 dict（`last/lower_limit/upper_limit/pre_close/bid/ask`），键缺失/JSON 坏/Valkey 不可达 → `None`（调用方按「无同源行情」处理，never-throw）。
- **不读腾讯、不读 bar_1min、不读成本价**（这三个出口在本批全部退役）。

### 件二：定价（改 `trading.py:_quote_price`，删腾讯）
```
close_price(tick) -> float:
    lo = tick.get("lower_limit") or 0
    if lo > 0: return round(float(lo), 3)          # 跌停价卖
    last = tick.get("last") or 0
    if last > 0: return round(float(last) * 0.9, 3) # 无涨跌停标的：行情 90%
    return 0.0                                      # 无同源行情 → 走 pending
```
- `order_type="limit"`（**不用市价单**：XTP 市价单仍带 price 字段、实测同样越界拒）。
- 拆单 `XTP_MAX_ORDER_QTY=100_000` 保留（超百万股实测 `Parameter quantity invalid!`）。
- `skipped_t1`、风控 `check_order`（熔断态 SELL 放行）、`rejected` 汇总保留。

### 件三：无行情 = 留痕 + 后台定时重试（新增）
- 触发：`get_hub_tick` 返回 `None` 或 `close_price==0`。
- 即时：该标的**不发单**，写入 pending 队列 + `_alert` 告警 + `order_log` 记 `no_quote`（fail 明确留痕）；**不抛异常、不 sleep、不阻塞**其余标的发单与 `consume_risk_cmd` 回执。
- pending 队列：`risk:close-pending:{account_id}`（Valkey hash，field=symbol，value=json `{volume, frozen, avg_price, tries, next_ts}`）——跨进程可见、worker 重启不丢、可审计。
- 后台钩子：worker 主循环新增 `loop.every("close-pending-retry", interval, hook)`；每 tick 对 `now>=next_ts` 的项重读同源 tick：
  - 取到 → 按件二定价补发卖单 + order_log 审计 + 从 pending 移除；
  - 仍取不到 → `tries+1`，`next_ts=now+interval`；`tries>=max` → 最终 `_alert`（明确「N 次重试后仍无同源行情，未平」）+ 移除。
- 配置项（`system_config`，缺省读，DB 不可达用缺省，改动重启生效——照 `md_session.load_xtp_window_cfg` 范式）：
  - `close_all_retry_interval_s`（缺省 `5`）、`close_all_retry_max`（缺省 `10`）。
- **不新增强制订阅动作**：订阅由件四根本保证常驻；重试只兜「订阅刚生效/行情断流」窗口。

### 件四：持仓标的进订阅真相源（改 `src/md_hub/main.py:_desired_symbols`）
- 新增一源：`SELECT DISTINCT symbol FROM position_snapshot WHERE volume > 0`，经 `to_vt_symbol()` 归一为项目口径后并入 `rows`。
- 读失败沿用既有 `logger.warning` 降级（不炸 hub）。
- 时序提示（如实记录）：`position_snapshot` 60s 快照 + hub 订阅 diff 15s / 全量重放 60s ⇒ 持仓变化到订阅生效最多 ~1-2 分钟；缺省 5s×10=50s 可能短于该窗，配置项可调。常态下持仓标的常驻订阅，平仓时直接有 tick。

### 件五：急停审计缺口（保留工作区已有实现）
- `_close_order_open(sym, volume, price, account_id, operator)`：发单前写 `order_log`（`strategy_id='emergency-close'`, `status='submitting'`）。
- `_close_order_mark(order_id, status, vt_orderid, error)`：发单成功→`submitted`+vt_orderid；失败→`send_failed`；此后由既有 `write_order_status` 按 vt_orderid 认领终态（`all_traded/cancelled/rejected`，SQL `<> ALL` 已修）。

## 4. 验收 / 守门（mock 库 + 真库双证）

- **S1 同源**：`_quote_price` 测试断言**不再出现** `market_snapshot`/`get_quote`/腾讯字样；`get_hub_tick` 命中 `hub:latest_tick:{account_id}:{vt}` 且 `.SSE→.SHSE` 归一正确。
- **S2 定价**：有 lower_limit → 用跌停价；无 lower_limit 有 last → `last×0.9`；两者皆无 → `0`（转 pending），三态断言。
- **S3 不阻塞**：`_close_all_positions` 内**不含 sleep**（inspect.getsource 断言）；缺行情标的返回 `pending`/`no_quote` 且其余标的照常 `send_order`。
- **S4 重试**：钩子按 interval/max 驱动；tries 达 max 触发最终告警并从 pending 移除；补发命中定价与审计。配置项缺省 5/10、DB 覆写生效。
- **S5 审计**：急停单落 `order_log`（submitting→submitted→终态可由 vt_orderid 认领）——真库插入/删除回滚验证。
- **S6 订阅真相源**：mock `position_snapshot` 返回 `.SSE` 标的 → `_desired_symbols` 含归一后 `.SHSE`。
- **S7 真库实证**（上产后盘中）：hub 有持仓标的 tick、平仓单以同源定价发出、不再出现 `beyond the limit`；盘后 `hub:latest_tick:*` 为空属预期（TTL 65s）。

## 5. 不做的事（边界）

- 不做「平仓时临时订阅」（用户已否，属动作内补丁）。
- 不做腾讯/成本价/陈 bar 的任何静默降级（不同源=不合规，宁可留痕未平）。
- 不做分标的选择性平仓、不做自动反复重跑整轮 close-all。
- 不改 XTP 连接窗、不改 hub 进程模型、不改现有三源语义。
