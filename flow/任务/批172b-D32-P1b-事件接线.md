## 目标

把 worker 交易链、任务入口的事件消费从 vnpy 对象/EventEngine 切到 `ports.ExecutionPort` 的领域对象与推送回调；**判定语义零变更**，每处配「旧 vs 新」等价测试。P1b 只切**事件推送**边界；查询/撤单仍走 `ExecutionAdapter`（P3 由插件端口替换），但 `trading.py` 内部统一读 domain。

## 接口契约

### A. 领域字段（形状类，零转换）

```python
@dataclass(frozen=True)
class OrderState:
    orderid: str
    vt_orderid: str
    symbol: str
    direction: Direction
    status: OrderStatus
    volume: float
    traded: float
    price: float
    datetime: datetime | None = None
    client_id: str = ""      # best-effort；P1b 由 _vt2cid 反填，P3 由插件填

@dataclass(frozen=True)
class Trade:
    tradeid: str             # 存 vt_tradeid（trade_ref 唯一键）
    orderid: str             # 存 vt_orderid
    symbol: str
    direction: Direction
    price: float
    volume: float
    datetime: datetime | None = None
    client_id: str = ""
```

### B. `strategy_runner/legacy_translate.py`

```python
def status_of(d: Any) -> OrderStatus: ...
# SUBMITTING→SUBMITTED；NOTTRADED→NOT_TRADED；PARTTRADED→PARTIAL；
# ALLTRADED→ALL_TRADED；CANCELLED→CANCELLED；REJECTED→REJECTED；
# 缺失/None/未知 → raise ValueError（fail-closed：不得默认成在场态）

def to_domain_order(d: Any, client_id: str = "") -> OrderState: ...
def to_domain_trade(d: Any, client_id: str = "") -> Trade: ...
# **只取 vt 键，不回落裸 id**：tradeid = getattr(d,"vt_tradeid","") or ""；
# orderid = getattr(d,"vt_orderid","") or ""（基线只查 vt，裸 id fallback 留 P3）
# direction=None → Direction.NET（保住 legacy「非 LONG 即 SELL」语义）

def to_domain_position(p: Any) -> Position: ...
def to_domain_account(a: Any) -> AccountState | None: ...
# 0 行→None；多行→warning + 取首（per-account adapter 预期 0/1）
# available = balance - frozen（vnpy AccountData 同式）
```

### C. `strategy_runner/legacy_exec_port.py`

```python
class LegacyExecutionPort:
    def __init__(self, event_engine, adapter_getter: Callable[[], Any],
                 guard_factory: Callable[[str], Callable[[Callable], Callable]],
                 event_order: str, event_trade: str,
                 connected_getter: Callable[[], bool] = lambda: False): ...
    # guard_factory 形状=仓内 _guard：self._guard(name)(fn)
    # main 传 _guard；hub_worker 传 lambda n: make_guard(n, _alert)
    # event_order/event_trade 由 main 传 EVENT_ORDER/EVENT_TRADE（本文件零 vnpy import）

    # 唯一注册点=subscribe_*；__init__ 不注册；按原始 cb 键去重（防双回调）
    # wrapper = guard_factory("legacy_port.on_order")(fn)：翻译+cb 全在守卫内
    #   fn(event) -> adapter=adapter_getter(); cb(translate(event.data, cid_of(adapter, data)))
    def subscribe_order(self, cb): ...
    def subscribe_trade(self, cb): ...

    # send：每次调用 getattr(adapter,"send_order")（禁止缓存 bound method，保 _gated_send 咽喉）
    #       domain.Order → legacy adapters.Order；空 cid → OrderReceipt(accepted=False)
    # cancel：cid → get_vt_orderid → query_orders 缓存按 client_id/vt 反查；
    #         解析失败 raise LookupError（不得静默放弃）
    # query_orders/query_trades：逐条 translate；单条失败 warning+跳过（不外抛整批）
    # query_positions/query_account/resolve_vt_order_id：委托/翻译
    # @property connected：返回 connected_getter()（默认 False=fail-closed，P1b 不消费）
    # adapter 未绑定（None）时 send/cancel/query_* raise RuntimeError；connect/close=no-op
```

`adapter_getter` **必须永不抛**（未绑定返回 `None`）。main 用可变 holder：`_adapter_holder={"a":None}`，`adapter_getter=lambda: _adapter_holder["a"]`，build 返回后赋值；**cb 也从 holder 取 adapter**（禁止闭包未绑定局部量）。早到事件照常翻译，`client_id=""`，靠 `vt_orderid` 认领；adapter=None 时写库函数不得抛 AttributeError。

**零新 vnpy 依赖**：`legacy_translate.py` / `legacy_exec_port.py` 不得 import `vnpy`（S1 只减不增）。事件类型由调用方注入（`order_event=EVENT_ORDER`、`trade_event=EVENT_TRADE`）；状态/方向用 `getattr(x, "name", None)` 字符串映射，不 import vnpy 常量。

### D. 消费面

```python
trading.write_order_status(d: OrderState, adapter, sid: str, symbol: str) -> None
trading.write_trade_log(d: Trade, adapter, sid: str, symbol: str) -> None
trading.reconcile_orders(adapter, sid, symbol=None) -> None
trading.halt_edge_cancel(adapter, halt_state: dict, sid) -> None
trading._cancel_working_orders(adapter) -> dict
```

身份键与写库硬契约（与基线逐条对齐）：

- **cid 读取时刻**：若 adapter 非空且有 `_vt2cid`，用**当前值**（`adapter._lock` 下）；仅当 adapter 为 None 或无该属性（P3 端口）才用 `d.client_id`。禁止「domain 快照优先」。adapter=None 时不得抛 AttributeError。
- **write_order_status**：`d.status` 仅 PARTIAL/ALL_TRADED/CANCELLED/REJECTED 回写；`SUBMITTED/NOT_TRADED` 直接 return；查询顺序固定为 **vt 先、无行再 cid**（与基线 `:86-104` 一致）；SQL/`<> ALL`/`ORDER BY id DESC LIMIT 1` 原样。两写函数的查询顺序**故意不同**（order=vt 先，trade=cid 优先互斥），禁止「统一化」。
- **write_trade_log**：`action = "BUY" if d.direction == Direction.LONG else "SELL"`；查询顺序**互斥**——cid 非空只查 cid，查不到**不回落** vt；cid 空才查 vt；`trade_ref = d.tradeid or None`（NULL 保留）；`ON CONFLICT DO NOTHING` 原样。
- **_cancel_working_orders**：**不整对象 translate**——每单只用 `status_of(od)` 判工作态 + `getattr(od,"vt_orderid","")` 撤单（基线只读这两字段，避免缺字段漏撤）；工作态 `{SUBMITTED, NOT_TRADED, PARTIAL}`；`status_of` 失败 → `untranslatable += 1` + warning + 继续（不增 requested）；`cancel_order` 异常 → `requested += 1; failed += 1`；返回键 `{requested, failed, untranslatable}`（前两键语义不变，第三键为新增可观测项）。
- **reconcile_orders**：在场委托用 `status_of` + `getattr` 原始字段判（不通读全对象）；**告警方向直接用原始对象 `getattr(o.direction,"value","?")`，不经过 domain**（当前 locale 下为 `Long/Short/Net`；避免 `direction_long`，也与基线逐字一致）。成交逐条 `to_domain_trade`；单条失败 warning+skip，**该条不计入 n_new**。在场委托只告警不撤。

### E. 知情差异（P1b 有意变更，逐条记档）

| # | 形态 | 处理 |
|---|---|---|
| 1 | 未知/缺失状态：基线静默 return | 新链 `status_of` raise → guard 告警（fail-closed）；等价矩阵按「告警码 `runtime.guard` + 事件跳过」比对，不要求静默 |
| 2 | `query_account` 多行/负可用：基线 `snapshot_cycle` 逐账户 `max(0,b-f)` 再求和 | P1b 不切 `snapshot_cycle`；ACL 取首行 + warning，仅供端口完整性，P3 复用前须复核折叠口径 |
