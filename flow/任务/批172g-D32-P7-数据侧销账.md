# 批 172g · D32 P7 — 数据侧 legacy 销账

> 立项 2026-11-11（D32 分批）。前置＝批172d ✅ + P1a 统一注册表。
> 关联：批172a/172d · `docs/design/D32-接入插件架构.md` §3.1/§十/§十二
> **口径（批177 起）**：adapter 产出的 symbol 恒为 MIC；源格式转换只走 `to_source_symbol`/`to_ts_code`。

## 目标

把数据源侧的 4 处旧注册点收归 **D32 统一 `REGISTRY`（`data_source` 域）**，由 A03 的 `@adapter` 注册进去，删除 D32 内的 legacy 只读投影，使「同一 provider 概念只有一处注册」在数据侧也成立。

```python
    def fetch(self, req: FetchRequest, acct: AccountRef) -> ContractFrame | AsyncContractFrame: ...

class StreamCapability(Protocol):
    kind: ClassVar[DataKind]

# D32 侧保持的投影（删除前）
def legacy_projection(domain: str, provider: str) -> set[str]: ...
```

## mock 方式

- 假 adapter 注册一条，断言 `registry.get` 与旧 `data_source.get_data_source` 返回同一实现。
- 删除投影后，断言旧调用路径抛 `ImportError`/`AttributeError`（证明真删了，不是留着不调用）。
