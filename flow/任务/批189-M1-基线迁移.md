## 2. 执行通道与停服编排

> 通道只有一条：**release.yml 阶段 4（DDL 门）→ 手工停服 → 继续 release（阶段 5 跑 `quant-alembic-wrapper`）→ 阶段 6–8 拉起**。禁止单独手工执行 alembic（会绕过门与留痕）。

1. 停服（逐实例，`quant-svc` 不收通配）：枚举 `systemctl list-units "quant-live-task@*"` 等 → 逐个 `quant-svc stop <unit>`，顺序 live-task → td-exec → md-hub → celery(worker/beat/risk) → web-api；
2. 反向拉起（失败时）：web-api → celery → md-hub → td-exec → live-task。

## 3. 迁移步骤（单事务，`lock_timeout=5s`）

| # | 步骤 | 要点 |
|---|---|---|
| 1 | 快照与预计数 | `CREATE TEMP TABLE _b189_src AS SELECT id,provider,market,account_key,capabilities,exchanges,is_virtual,quote_account_id FROM trading_account`；`_b189_counts` 记录 6 表非空 `account_id` 数、usage 非空数 |
| 2 | 生成 code 双表 | `_b189_md(old_id,code,login_key)`（`rt_quote` 行）；`_b189_td(old_id,code,login_key)`（`trading` 或 `is_virtual` 行）；code=`replace(lower(provider), '_', '-')` 加 `md-`/`td-` 前缀；login_key=`provider || '|' || coalesce(account_key, case when is_virtual then 'virtual' else null end)`——**非虚拟且空 key 直接 RAISE** |
| 3 | 删依赖 | 6 条业务 FK（M0 §2.4）+ `DROP TRIGGER trg_live_task_account_guard` + `DROP FUNCTION live_task_account_guard()`；`position_snapshot`/`position_refresh`/`account_permission` 旧 PK（清单驱动） |
| 4 | 建新表 | `market_interface`/`trade_interface`（M0 §2.1 全列）+ `td_md_map`；`data_source`：`RENAME TO data_source_old` → 建新表（附录§2 列 + `code` + `impl`）+ **先 DROP 旧索引/PK 避免同名冲突** |
| 5 | 灌接口行 | `INSERT ... SELECT FROM _b189_md/_b189_td JOIN _b189_src`（md 带 `exchanges`，td 带 `is_virtual`；`enabled` 原样，虚拟行已为 false）；`data_source` 按 provider 生成 `ds-*`（`capabilities` 原样保留、`impl` 默认 `legacy`） |
| 6 | 映射初值 | `INSERT INTO td_md_map SELECT t.code, m.code, 1 FROM _b189_td t JOIN _b189_md m ON m.old_id = t.quote_id WHERE t.is_virtual IS NOT TRUE` |
| 7 | 业务列 | 6 表 `ADD account_code varchar(32)` + `UPDATE ... FROM _b189_td`；`live_task`/`account_snapshot` 回填后 `SET NOT NULL`；`freeze_event ADD account_code` + 回填；`data_source_usage ADD interface_code` + 按 provider 关联新 `data_source`（无匹配→NULL 留证） |
| 8 | 权限表重建 | 新建 `account_permission_new(login_key text PRIMARY KEY, allowed_categories/exchanges/boards text[] NOT NULL, is_st_allowed bool NOT NULL, convertible_allowed bool NOT NULL, created_at, updated_at)`；`INSERT ... DISTINCT ON (login_key) ... ORDER BY updated_at DESC`（旧行 join `_b189_td`）；换名 |
| 9 | 重建约束 | 新 PK：`position_snapshot(account_code,symbol,direction)`、`position_refresh(account_code)`；7 条 FK（6 业务 + `data_source_usage→data_source`）；UK `(market,account_key) WHERE ...` **仅 md/td**；普通索引 |
| 10 | 触发器 | 按 `account_code` 重建：`SELECT is_virtual FROM trade_interface WHERE code=NEW.account_code`；`BEFORE INSERT OR UPDATE OF account_code, mode` |
| 11 | 租约表 | 旧行 `COPY` 留证 → `DROP TABLE provider_session_slot` → 建新 PK 表（M0 §2.3），空表 |
| 12 | 删旧 | 删 `account_id`/旧列（`quote_account_id` 随表）；`DROP TABLE trading_account, data_source_old`；删旧索引 |
| 13 | 自检 | §4 断言 + `schema_expectations.txt` 重生成校验 |

## 4. 断言（V1–V12，全部只读临时表或新表）

| # | 断言 |
|---|---|
| V1 | `market_interface` 行数 = `_b189_md` 行数；`trade_interface` = `_b189_td` 行数 |
| V2 | 三表 code 全过 `~ '^[a-z][a-z0-9-]{1,30}$'`，无重复 |
| V3 | 6 表 `account_code` 非空数 = `_b189_counts`（逐表比对；NULL 行单独计数一致） |
| V4 | `account_code IS NOT NULL` 的反连接为空；`account_permission.login_key` ∈ 两表 login_key 并集 |
| V5 | `data_source_usage.interface_code` 非空数 = `_b189_counts.usage`（无匹配行已留证）；`freeze_event` 回填率 100% |
| V6 | 非虚拟 td：有 `quote_id` 的 100% 有映射；虚拟行 0 映射且留证 |
| V7 | FK `confdeltype` = r,c,c,c,n,n,n；UK 存在且谓词含 `account_key IS NOT NULL`（仅 md/td） |
| V8 | 触发器定义含 `account_code` 与 `UPDATE OF account_code, mode`；函数体不含 `trading_account` |
| V9 | 旧对象清零：`trading_account`/`data_source_old`/`account_id` 列/`quote_account_id`/旧索引 |
| V10 | slot 空表且 PK=`(login_key,provider,role,terminal_id)` |
| V11 | `pg_constraint`/`pg_index`/`pg_trigger` 定义文本中残留 `account_id` = 0 |
| V12 | Redis 六族旧键清理条数留证 |
