# 批189-M1 基线迁移（实施规格）

> 状态：**方案稿（待双盲审）**。上游真源：`flow/方案/批189-M0-契约.md`（C1–C7）+ `批189-总体实施架构.md`（§3 上线单元/§5 失败判据）。
> 本文件只写「怎么做」；契约不在此复制，冲突以 M0 为准。

## 0. 范围

**做**：单文件迁移 `0192` —— 建三表（code PK）+ `td_md_map` + 租约表重建；存量行拆分；8 处引用回填；PK/UK/触发器/FK 重建；删旧表旧列；wrapper `TRANSITION-0189` 块；备份/恢复 runbook。
**不做**：不切读路径、不改业务代码（M2–M5）、不做双写、不写 downgrade（不可逆，回滚=快照）。

## 1. 前置（缺一不得进窗）

1. **staging 实测**：生产 dump 恢复到独立库，跑 0192 全量计时（目标 ≤40 min）+ 恢复一次计时（红线依据）。
2. **备份产物校验**：`quant_<ts>.sql.gz` 存在且 ≥900 MB、时间戳为本次（实测 998 MB / 4.5 min）。恢复路径已演练过（用户确认），不再单独演练。
3. **wrapper 装位**：`quant-dbro`/`quant-hbcheck` 的 `TRANSITION-0189` 块 + 闸门哨兵列表（当前硬编码 0115）先上，未装位不得发布。
4. **`account_key` 回填**：4 行全空 → 凭证内资金账号优先、运营补录；空值行 preflight 阻断（公开行情 MD 例外）。
5. 确认无 running `live_task`；确认时间窗=**盘后窗**（15:05 后）。

## 2. 迁移 0192 的步骤（单事务）

> alembic 单文件、单事务：**全成或全不成**，不留半态。锁模式：服务全停，无需并发 DDL；设置 `lock_timeout=5s`、`statement_timeout=0`。

| # | 步骤 | 要点 |
|---|---|---|
| 1 | 建三表 | `market_interface` / `trade_interface` / `data_source`：`code varchar(32) PRIMARY KEY`、前缀 CHECK、列见 M0 §2.1 |
| 2 | 建 `td_md_map` | 双 FK + `ON DELETE CASCADE`，PK `(td_code, md_code)`，`priority` 非空 |
| 3 | 建租约表 | `provider_session_slot` 新 PK `(login_key, provider, role, terminal_id)`；旧行按 §4 回填后切换 |
| 4 | 拆分存量行 | 每旧行：`rt_quote` → `md-<provider>`；`trading` → `td-<provider>`；`is_virtual`→td；`exchanges`→md；`capabilities` 不落表 |
| 5 | 填映射 | 若旧 `quote_account_id` 指向同 id → `td_md_map(td_code, 对应 md_code, 1)`；跨行按 quote_account_id 解析 |
| 6 | 业务表加列回填 | 7 表 `account_code`（+`data_source_usage.interface_id`→`code`）：`UPDATE … FROM` 旧 id→code 映射（一次性，允许百万行） |
| 7 | 重建约束 | PK/UK（含 `(market, account_key) WHERE …`）/ FK（RESTRICT/CASCADE/SET NULL）/ `0174` live_task 触发器改引用 `trade_interface` |
| 8 | 删旧 | 删 `trading_account`、`quote_account_id` 列、旧 SLOT 表；删旧索引 |
| 9 | 自检 | 执行 §3 全部断言，任一失败 → `RAISE EXCEPTION` 回滚整事务 |

**拆分口径**（钉死，防歧义）：
- 一行旧行最多生成 2 行（md + td）；`code` = `<role>-<provider>`，同 provider 多行时按 id 升序加 `-2/-3` 后缀**仅迁移期**（新行由用户命名）。
- `login_key` = `provider + '|' + account_key`；为空且 `has_credentials=false` 且仅行情 → `provider + '|public'`；其余空 → 迁移失败。
- 租约回填：`role` 由旧 `holder` 前缀判定（`md-hub`→md、`td-exec`→td，无法判定→td 并记 warning）；`terminal_id` 沿用现值。

## 3. 校验断言（迁移末尾 + 事后抽样）

| # | 断言 |
|---|---|
| V1 | `market_interface` 行数 = 旧表 `rt_quote` 行数；`trade_interface` = 旧表 `trading` 行数 |
| V2 | 三表 `code` 无重复且前缀正确（CHECK 已保证，抽样复核） |
| V3 | 7 张业务表：`account_code IS NOT NULL` 的行数 = 迁移前 `account_id IS NOT NULL` 行数 |
| V4 | 所有业务表 `account_code` ⊂ `trade_interface.code`（反连接为空） |
| V5 | 每张交易接口至少有 0..N 条映射；映射 md_code ⊂ `market_interface.code` |
| V6 | FK/UK/索引/触发器存在性（`pg_constraint`/`pg_indexes`/`pg_trigger`） |
| V7 | 旧对象已消失（`to_regclass('trading_account') IS NULL`） |

## 4. 失败与回滚

- **单事务**：任一步失败自动回滚，库保持迁移前状态（最理想）。
- **事务外失败**（备份/恢复/部署）：恢复快照 + 旧版代码（人工）；本批无自动 rollback。
- **基线重置**（授权兜底）：判据见总体架构 §5；重置后接口行重建、凭证重录、键族清理。
- `downgrade()` **显式 raise**（不可逆），禁止伪造可逆假象。

## 5. 验收（一条可执行证据）

```
# staging（迁移后库）
psql -d scratch_189 -tAc "select count(*) from market_interface"        # = 旧 rt_quote 行数
psql -d scratch_189 -tAc "select count(*) from trade_interface"         # = 旧 trading 行数
psql -d scratch_189 -tAc "select count(*) from live_task where account_code is null"  # 0
psql -d scratch_189 -tAc "select to_regclass('trading_account')"        # 空
```
> 注意：**验收不等于上产**——M1 与 M2–M5 同一 release（总体架构 §3），单独部署会让旧代码读不到旧表。

## 6. 时间预算（待实测校准）

| 阶段 | 目标 |
|---|---|
| 备份 | **实测 4.5 min / 998 MB**（2026-11-19，prod 9.5 GB 库） |
| 迁移 0192（步骤 1–9） | **≤10 min**（红线；实测业务表仅 516 KB/千级行，原 40 min 估值作废；0192 落地后复测） |
| 冒烟 E1–E9 | 15 min |
| 观察窗 | 10 min |
| 合计 | ≤40 min（盘后窗无上限，仅受次日 8:55 约束） |

**实测记录（2026-11-19，prod）**：库 9.5 GB（其中 11 张迁移相关表 dump 仅 516 KB）；`backup_db` 998 MB / 4.5 min；迁移相关表数据量为千级 → 迁移本体预计秒级，红线定 10 min 留余量。**待补**：全库 restore 实测（回滚下限），需先 GC 腾出 ≥11 GB。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 回填 UPDATE 锁表过久 | 服务全停；按表分批 + 单事务内可回滚；实测校准 |
| 拆分口径歧义（capabilities 异常值） | preflight 统计 `capabilities` 非 `{rt_quote,trading}` 的行并阻断 |
| 触发器重建遗漏 | V6 断言 + `0174` 触发器专项检查 |
| wrapper marker 误判 | marker 依赖 0192 单文件；wrapper 先装位；未知态 rc=1 |
