# 批189-M1 基线迁移（实施规格 v2）

> 状态：**方案稿 v2（按双盲审 A/B 修订）**。上游真源：M0 契约 §1/§2 + 总体架构 §3/§5。
> **M1 不可单独发布**：与 M2–M5 同一 release（总体架构 §3）。

## 0. 范围

**做**：单文件迁移 `0192`——**改造**既有 `data_source`/`provider_session_slot`；新建 `market_interface`/`trade_interface`/`td_md_map`；拆存量行；**9 处**引用回填；PK/UK/FK/触发器重建；删旧列旧表；wrapper 0189 新态。
**不做**：不改业务代码（M2–M5）、不双写、不写 downgrade。

## 2. 停机与迁移步骤

**停机顺序（release.yml 无停服阶段，必须手工前置）**：`quant-live-task@*` → `quant-td-exec@*` → `quant-md-hub@*` → celery（worker/beat/risk）→ `quant-web-api`。失败恢复：按反向顺序 `quant-svc start` 旧单元。

**单事务**（alembic 默认）：`lock_timeout=5s`、`statement_timeout=0`；全部索引用普通 `CREATE INDEX`（禁 CONCURRENTLY）。

| # | 步骤 | 要点 |
|---|---|---|
| 1 | 删旧约束 | 删 9 处引用的旧 FK/PK（`position_snapshot`/`position_refresh`/`account_permission` 的 PK 含 account_id；`live_task` 先 DROP TRIGGER） |
| 2 | 建新表 | `market_interface` / `trade_interface`（code PK + 前缀 CHECK + 全列）+ `td_md_map`（双 FK CASCADE） |
| 3 | 改造 `data_source` | `ADD code`；按 provider 生成 `ds-<provider>`（`impl` 默认 `legacy`、`account_key` NULL）；UNIQUE(code) |
| 4 | 拆行 | `rt_quote`→md；`trading` **或 `is_virtual`**→td；`exchanges`→md；`is_virtual`→td；`capabilities` 不落表；code 规范化 |
| 5 | 映射初值 | 仅当 quote 目标确有 md 行时插 `td_md_map(td,md,1)`；虚拟/无 md → 不插 |
| 6 | 加列回填 | 6 表 `account_code`；`account_permission.account_id`→`login_key`；`data_source_usage.interface_id`→按 provider 派生 `ds-*`；`freeze_event.account_id`→`account_code` |
| 7 | 重建约束 | 新 PK/UK/FK（RESTRICT/CASCADE/SET NULL 按 M0 §2.3）；**0174 触发器**：DROP FUNCTION/TRIGGER → 按 `account_code` 重建函数体与 `UPDATE OF account_code, mode` |
| 8 | 租约表 | `TRUNCATE provider_session_slot` → 改列/换 PK `(login_key,provider,role,terminal_id)`（不猜 role；由进程注册时写入） |
| 9 | 删旧 | `trading_account`、`quote_account_id`、旧索引、旧列；旧 `data_source` 的 id/capabilities 列 |
| 10 | 自检 | 执行 §3 全部断言，任一失败 `RAISE EXCEPTION` 回滚整事务 |

## 3. 校验断言（迁移末尾）

| # | 断言 |
|---|---|
| V1 | `market_interface` 行数 = 旧 `rt_quote` 行数；`trade_interface` = 旧 `trading` ∪ `is_virtual` 行数 |
| V2 | 三表 code 唯一且满足前缀 CHECK（抽查 5 行打印） |
| V3a | 6 表（live_task/position_snapshot/position_refresh/account_snapshot/order_log/trade_log）：`account_code IS NOT NULL` 数 = 迁移前 `account_id IS NOT NULL` 数（**迁移前先落临时计数表**，避免加列后自证） |
| V3b | `account_permission.login_key` 全非空，且 ∈ `trade_interface.login_key` 或 `market_interface.login_key` |
| V3c | `data_source_usage.interface_id` 映射覆盖率 = 100%（未覆盖数=0）；`freeze_event.account_code` 回填率 = 100% |
| V4 | 上述列反连接为空（无孤儿 code） |
| V5 | **有 `trading` 且 `quote_account_id` 非空 ⇒ 该 td 映射 ≥1 条**（0 条仅限虚拟/无 md 目标，且须在 preflight 清单内） |
| V6 | 约束存在且语义正确：`pg_constraint.confdeltype` ∈ {r,c,n} 与 M0 一致；`pg_get_triggerdef` 含 `account_code` |
| V7 | 旧对象清零：`trading_account`、`quote_account_id` 列、旧 slot PK、旧索引均不存在 |
| V8 | slot 表空且 PK 为新四列 |
| V9 | Redis 旧键清理条数留证：`quant:hb:md-hub:*`、`td:exec:*`、`hub:bars:<int>:*`、`hub:latest_tick:<int>:*`、`td:cmd:<int>`、`hub:worker:max_ts:<int>:*` |

## 4. 失败与回滚

- 单事务：任一步失败自动回滚，库回到迁移前。
- 事务外失败：恢复快照 + 旧代码（用户手动，已演练）；旧单元按反向顺序拉起。
- 基线重置：判据见总体架构 §5。
