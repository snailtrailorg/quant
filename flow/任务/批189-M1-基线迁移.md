## 2. 停机与迁移步骤（单事务）

**停服顺序**（附录§5：release.yml 无停服阶段，必须手工）：`quant-live-task@*` → `quant-td-exec@*` → `quant-md-hub@*` → celery(worker/beat/risk) → `quant-web-api`。失败按反向 `quant-svc start` 拉起。

**事务参数**：`lock_timeout=5s`、`statement_timeout=0`；索引一律普通 `CREATE INDEX`（0180 的 CONCURRENTLY 只能活在 `autocommit_block`，本迁移禁用，附录§3）。

| # | 步骤 | SQL 要点（对象名来自 §1.1 清单，不硬编码猜测） |
|---|---|---|
| 1 | 删依赖 | 删 7 条 FK（附录§3 名称表）+ `DROP TRIGGER trg_live_task_account_guard` + `DROP FUNCTION live_task_account_guard()`；删 `position_snapshot/position_refresh/account_permission` 的 PK（清单驱动） |
| 2 | 建新表 | `market_interface`/`trade_interface`：`code varchar(32) PRIMARY KEY` + 前缀 CHECK + 附录§2 列集（md 侧含 exchanges，td 侧含 is_virtual）；`td_md_map(td_code,md_code,priority)` 双 FK CASCADE |
| 3 | 拆 `data_source` | `ALTER TABLE data_source RENAME TO data_source_old`；新建 code PK 表（列=附录§2 的 data_source 列 + `code` + `impl DEFAULT 'legacy'`）；`INSERT ... SELECT 'ds-'||provider, ...`；`ALTER TABLE data_source_usage ADD interface_code text` |
| 4 | 拆行 | `INSERT INTO market_interface SELECT 'md-'||replace(provider,'_','-'), ... WHERE 'rt_quote'=ANY(capabilities)`；`trade_interface ... WHERE 'trading'=ANY(capabilities) OR is_virtual`；`login_key = provider||'|'||coalesce(account_key, case when is_virtual then 'virtual' else 'public' end)` |
| 5 | 映射初值 | `INSERT INTO td_md_map SELECT t.code, m.code, 1 FROM trade_interface t JOIN ... ON t.quote_src=...`（仅当目标 md 行存在；不可达者已在 §1.7 清单） |
| 6 | 建映射表 | `CREATE TEMP TABLE _b189_map(old_id bigint PRIMARY KEY, code text)`：旧 id → td code（虚拟行同样映射） |
| 7 | 业务列 | 6 表 `ADD account_code text` 并 `UPDATE ... FROM _b189_map`；`account_permission ADD login_key text` 回填（join _b189_map → trade_interface.login_key）；`data_source_usage.interface_code` 按 `provider` 关联新 data_source；`freeze_event ADD account_code text` 回填 |
| 8 | 重建约束 | 新 PK：`position_snapshot(account_code,symbol,direction)`、`position_refresh(account_code)`、`account_permission(login_key)`；7 条 FK 按附录§3 的 ON DELETE 语义；UK `(market,account_key) WHERE ...` 三表各一份；普通索引 |
| 9 | 触发器 | 按 `account_code` 重建函数体（`SELECT is_virtual FROM trade_interface WHERE code=NEW.account_code`；不存在→RAISE；`mode=live` 且虚拟→RAISE）+ `BEFORE INSERT OR UPDATE OF account_code, mode` |
| 10 | 租约表 | `DROP TABLE provider_session_slot` → 新建 `(login_key,provider,role,terminal_id)` PK（附录§2 列 + role）；不迁移旧行（holder 格式无 role 语义，附录§6） |
| 11 | 删旧 | `account_permission`/6 表删 `account_id`；`freeze_event` 删旧列；`data_source_usage` 删 `interface_id`；`DROP TABLE trading_account, data_source_old`；删旧索引/`quote_account_id`/`is_virtual` |
| 12 | 自检 | §3 断言；任一失败 `RAISE EXCEPTION` 回滚 |

## 3. 断言（V1–V12）

| # | 断言 |
|---|---|
| V1 | md 行数 = 旧 `rt_quote` 行数；td 行数 = 旧 `trading` ∪ `is_virtual` 行数 |
| V2 | 三表 code 唯一且过 C1 正则（SQL 用 `~` 校验，不靠肉眼） |
| V3 | 6 表 `account_code` 非空数 = 迁移前计数（**先落 `_b189_counts` 临时表**，防加列后自证） |
| V4 | 6 表 `account_code` 反连接 `trade_interface` 为空；`account_permission.login_key` ∈ 两张接口表的 login_key 集合 |
| V5 | `data_source_usage.interface_code` 覆盖率 = 100%（`interface_id` 非空的行）；`freeze_event.account_code` 同 |
| V6 | 旧 `quote_account_id` 非空的 td 行中，映射 ≥1 的比例 = 100%（例外清单来自 §1.7，且为空） |
| V7 | 约束语义：7 条 FK 的 `confdeltype` = r/c/c/c/n/n/c；3 张 UK 存在且 `pg_index.indpred` 含 `account_key IS NOT NULL` |
| V8 | 触发器：`pg_get_triggerdef` 含 `account_code` 与 `UPDATE OF account_code, mode`；函数体不含 `trading_account` |
| V9 | 旧对象清零：`trading_account`、`data_source_old`、`account_id` 列、`quote_account_id`、旧 slot PK 均不存在（`to_regclass`/`information_schema`） |
| V10 | `provider_session_slot` 空且 PK = `(login_key,provider,role,terminal_id)` |
| V11 | 残留 `account_id` 引用 = 0：扫描 `pg_constraint`/`pg_index`/`pg_trigger` 的表达式与定义文本 |
| V12 | Redis 旧键清理条数留证（附录§7 六族） |

## 4. 失败与回滚

- 单事务：任一步失败自动回滚。
- 事务外失败：恢复快照 + 旧代码（用户手动，已演练）；旧单元反向拉起。
- 基线重置：判据见总体架构 §5。
