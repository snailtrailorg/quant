# 批189-M3 进程与部署（实施规格 v2）

> 输入：M0 v2（C3/C4/C6/C7）· 总体架构（§3/§5）· 事实附录 §5/§9 · 审核裁决 `flow/审查/批189-M3审-裁决.md`。
> 依赖：M1（三表）+ M2（API/数据层）。**与 M1/M2/M4/M5 同一 release**（读路径切换是原子上线的一部分）。
> v2 改写缘由：单审 9×P0 全部成立——wrapper 时序、unit 兼容、空转语义、L3 int()、心跳字段集、波次首跑、hbcheck 装位。

## 0. 范围与身份分工
做：unit 名=code；期望集=有载体接口（不看 enabled）；常驻+空转；心跳换族与读侧全量改接；告警 code 化；波次两段切换；**13 文件 + ≥24 测试读路径切换**。
不做：订阅模型（M4）、取价（M5）、UI（M6a）。

**唯一身份（D10/V4，不可动摇）**：`code` = **系统唯一身份**——接口主键、业务表外键、unit、Redis 键（`hub:bars`/`hub:latest_tick`/`td:cmd`/心跳）、payload 的 account、API、日志、UI 全部用 code。**没有第二套数字身份**；M0 C4 退役清单已列 `hub:bars:{int}`/`td:cmd:{int}`。

> 审核 A 的 P0-11 曾建议「code=进程身份、id=数据面身份、进程同时持有两者」——**用户驳回**：与 V4 直接冲突，且 0192 后新表连 id 列都没有，无从解析。该建议基于当前代码现状、非冻结契约，属审核方事实错误（裁决文档已记）。数据面的 bars/tick/cmd/payload 在 **M4/M5 同批切 code**，与 M3 原子上线，不存在双身份中间态。进程只持有 code。

## 1. 单元与实例名（P0-2）
| 项 | 现状（附录§9） | 目标 |
|---|---|---|
| md/td unit | `@...@<id>`，env `ACCOUNT_ID=%i`（非数字即 exit 78） | `@...@<code>`；**env 只有 `INTERFACE_CODE=%i`**（code 即身份，无数字 env） |
| 入口解析 | 只认数字 id | **按 `INTERFACE_CODE` 查三表**（code→行）；无 code → exit 78。**不做 code→id 解析**（V4 下没有第二身份） |
| 回滚 | 旧代码读 `ACCOUNT_ID=%i` 数字 | **扩展 `rollback-tasks.yml` 形态闸**（补审 B5：现闸只认 66b `@quant` concrete，不认 code 模板）→ 回滚时把 code unit 渲染回 `@<id>` 旧模板 → 环境变回 `ACCOUNT_ID=%i`，旧代码能起。**不在 code unit 里塞数字 id** |

> 关键：用户明确驳回"在 code unit 里注入数字 `LEGACY_ACCOUNT_ID`"——那是双身份补丁。回滚是**部署面**行为（恢复旧 unit 模板 + 旧代码 + DB 快照），不是运行期身份设计。**但既有形态闸不够用**——B5 核实后，扩展它已登记为 §6.5 交付物（不是"无需新机制"）。

## 2. SA4 期望集（P0-4/P0-10）
- md：`SELECT code FROM market_interface WHERE provider = ANY(md_providers)`（**不看 enabled**）；
- td：`SELECT code FROM trade_interface WHERE provider = ANY(exec_providers)`（全量，**禁复用 `enabled_exec_accounts`**——否则空转 td 成非期望被停）；
- provider 白名单 = registry 声明 ∪ legacy 载体（C6）；
- **L3 熔断/停用判定全改字符串**：`int()` 全部移除，按 desired 集比对 unit 名；code 实例的启停单测必须补。

## 3. 常驻 / 空转 / 懒加载（P0-3）
| 状态 | 行为 |
|---|---|
| enabled=true | acquire slot、订阅、执行；心跳 working=true |
| enabled=false | **不建券商连接、不 acquire slot、不加载 SDK**；心跳 working=false |
| 无载体 | 不进期望集→无进程 |

- `get_interface_row` 返回**含 enabled、code、id**（现状不含 enabled，P0-3）；td_exec 见 `enabled=false` **不 raise**，改为「只维持心跳、不建会话」；md_hub 同款。
- 配置/凭证变更：`_poll_iface_switch` 比对 provider + credentials 摘要 + updated_at → exit 9 重建。
- 空闲释放 slot：停用 release，启用重新 acquire。

## 4. 心跳与读侧（P0-5/P0-6/P0-13；v3 按用户裁定修正）
- **单一键族，无双写**（D10/V4 + C4 + D15「不做双写」）：只写新键 `iface:hb:<md|td>:<code>`，**M1 起不写不读旧键**（`quant:hb:md-hub:*`/`td:exec:*` 已在 M1 窗内 SCAN+DEL）。A 审 P0-5 的「双写旧键兼容 R6/hbcheck」被驳回——它与 C4 退役清单、D15 直接冲突，属审核方拿现状当目标的事实错误（同双身份、polkit 两例）。
- **新键字段集必须包含旧消费方需要的全部字段**：C4 基础集 `enabled/working/provider/market/conn/subs/bars/reset_cnt/ts/seq` **+ R6 所需** `sess_ticks` / `last_tick_ts` **+ hbcheck/readyz 所需** `pid` / `gen` / `ticks` / `dropped_pg`。字段搬进新键，不是把旧键留着。M0 C4 的字段清单同步补齐。
- 写口下沉 `quant_common/hb.py`（td_exec 不再 import strategy_runner）。
- 读侧全量改接（**全部改读新键**）：collector、readyz（去 isdigit、按 code）、hub_worker._hub_alive、monitor 期望集（去 enabled、int→str）、run_hub_postverify、**`routes/risk.py`**（td:exec 在线判定）、R6 `hub_tick_stalled`、**`quant-hbcheck` wrapper（键前缀 + 字段断言同步改，随 release 装位）**。
- **删 `legacy_transition` 豁免**（读侧去旧键后恒 false；无旧键残留，无需部署窗抑制 R4）。切换顺序：先起 code 实例（新键就绪）→ 再停旧数字实例，避免两轮误报。

## 5. 告警
- `hub_hb_lost`/`td_exec_down`/`hub_tick_stalled`（R6）：期望集改 code、比较改字符串、**`evaluate` fail-loud**；字段从旧键搬进新键 `iface:hb`（见 §4），R6/hbcheck/readyz 同批改读新键。
- 新增（M7）：`subscription_fail`/`mapping_missing`/`iface_idle_dispatch`。

## 6. 波次与 wrapper（P0-1/P0-8/P0-9）
- **时序铁律**：preflight 在阶段 5 迁移前跑 → dbro **必须双态自适应**（旧表 trading_account / 新表 market_interface，按 `to_regclass` 或 marker 选），不能只查新表。
- **波次两段**：①按 desired 起 code 实例 → ②停旧数字实例（`stop+disable`，删 symlink）→ ③hbcheck 放**最后**；否则首跑只见旧实例、阶段 8 立即红并回滚。
- **hbcheck 随 release 装位**（现仅在 bootstrap），或保留两代自适应键分支；变更登记 A06 炸半径。
- 波次对象=`systemctl list-units` 在跑实例；不再走 dbro id|provider 拼名。
