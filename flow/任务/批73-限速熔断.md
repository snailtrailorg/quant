## 一、目标

provider 级 pacer（跨 API 键的供应商总闸）+熔断状态迁 Valkey（跨进程互见+进程回收不丢记忆+web dry-run 根治恒 closed）。

## 二、设计（勘察浓缩五点，两处用户裁定见 §六）

### 件 1 · provider 级 pacer（叠加不替代）
- **落点=rate_limit_context 内**（:166-193 进出语义不动，acquire 前插总闸）——一次改动覆盖 22 处调用点。
- 键 `rl:pace:{provider}:{acct}`；间隔=`ds.get_param_float("pacer", "min_interval", default=0)`——**默认 0=关**（机制落地+配置驱动开启；批 74 多源激活时按 provider 配置真值——多源刚性）。
- 与 per-api limiter **叠加**（双 sleep 串行最坏=和——docstring 声明）；总闸天然补 DailyQuotaPolicy「无聚合硬顶」缺口。
- 配置面：rate-limit-override 端点扩 pacer 字段（mgmt.py:424-471 同款式）。

### 件 2 · 四缺口收编（勘察 §二 F——pacer「全链覆盖」的真实敌人）
- `_sync_via_kind_cb_daily`（engine.py:727-736）/`_sync_via_kind_index`（:739-748）/`_fetch_and_save`（:1264-1283）/`backfill_symbol`（:1433-1478）四点补 `with rate_limit_context(...)` 块。
- **行为变化明示**（盲审重点）：cb_daily/index_daily 从无限速变有限速；index 的 `pull_index_daily` 吞异常返空 df——context 记不到失败（挂账：吞异常改透传留批 74 adapter 治理，本批不扩大）。
- 覆盖面勘误（v2 #9）：stock_detail/pool_data/tier1 pull_fns **实锚全在 context 盖内**——批 74 收敛的是 get_pro 散调的注册制归位（结构域非限速域）。

### 件 3 · 熔断 Valkey 化（混合形态——计数/状态只在 Valkey）
- 状态三件 `state/fails/opened_at` 迁 Valkey（HSET `rl:cb:{provider}:{acct}`）；`opened_at` 存 **epoch 秒**（现 monotonic 跨进程不可比——clock 注入面同步改 wall 时钟）；EXPIRE=`reset_timeout×2` 自 GC。
- 半开探测锁=SET NX EX（alert `_throttled` 先例 :166-175）；超时自愈。
- **Closed 态零写**（fails==0 跳过 Valkey 写——防 tier1 日循环写放大；脏标记）。
- **fail-open 全线**：Valkey 故障=闸放行+熔断视为健康（对齐 bulkhead :129-130/quota/throttle 三先例）——路由可用性优先。
- **竞态语义**：单命令原语（INCR/SET NX）实现；check-then-act 窗（达阈值→OPEN）幂等无害；「成功清零 vs 并发 INCR」交错最坏晚一拍——**声明最终一致，不引 Lua**（仓内首例评审成本 vs 单实例低并发收益不匹配；真有多实例高并发再上——挂账）。← 裁定点 A
- 三态语义不变：Open 快速失败不查配置不等待（测试钉 :223-236 保持）。

### 件 4 · 读方升级
- `routing._breaker_open`（:152-158）+`web routing dry-run`（routes/routing.py:63-83）两处直读 Valkey HGET state（一次 RTT；候选≤3 可忽略；不加本地 TTL 缓存——与 bulkhead 每次直读一致）。
- 状态谓词只认 `open`（Half-open 语义只在写侧 allow()——读侧不引入分支）。
- **dry-run 根治恒 closed**（web 侧读 worker 写的 Valkey 状态——勘察 §五 web 恒 closed 真因即进程隔离）。
- 批 74 交互预留：`_breaker_open(c.adapter)` 届时升 (adapter, account["id"]) 复合键——本批只预留键形，读方单段升级。

### 件 5 · _LIMITERS 分期
- per-api limiter 跨进程化**本批不做**（双 worker 失真 2 倍 vs 熔断完全失效——优先级差；键形 `rl:lim:{provider}:{api}:{acct}` 已预留平滑过渡）。← 裁定点 B

## 六、用户裁定点（两处）

- **A. 竞态实现**：单命令原语+声明最终一致（推荐——不引 Lua 首例）vs 一段 Lua 原子合并（仓内首例需评审）
- **B. _LIMITERS 跨进程**：本批只做熔断（推荐——失真 2 倍 vs 完全失效的优先级差）vs 同批连 limiter 一起迁

## 七、风险面与回滚

- 四缺口收编行为变化（cb/index 变有限速）——盲审重点+观察期甄别
- Valkey 故障面：fail-open 全线（三先例同向）——熔断失效窗口=Valkey 不可用窗口（可接受：Valkey 挂=更大问题已告警）
- 时钟系切换（monotonic→epoch）：clock 注入测试面全改——假时钟改造工作量主体
- **OPEN 下游两路径**（v2 #6）：tier1 per-date try 收 CircuitOpenError→failed_dates→partial→**游标照跳**（既有行为，本批放大触发概率——tier1 last_success_date 三态挂账批 74 根治）；cb/index 穿 sync() 外层→整任务 error+游标不动+beat 重试（60s 自愈）——**外层 error 不走 _alert_sync_failure，观察口径=sync_log 非告警面板**
- **交叉污染**（v2 #6）：OPEN 时 web 详情页拉取同被封（D2 账号级共享语义——观察期甄别点）
- 回滚：整版本 revert（Valkey 键残留无害自 GC——cb 键 EXPIRE 2×reset 自 GC+pace 键 TTL 到期）
