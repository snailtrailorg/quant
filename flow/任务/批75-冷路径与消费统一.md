# 批 75 · 冷路径与消费统一（H7 + 缺根豁免 + H9）

> 立项 2026-09-28（总方案 v4），2026-10-01 由 Claude 出方案。批 74 的「冷路径与消费统一」内容顺延到此（74 的多源激活已由批 83b 完成）。
> 三件事：**H7** fetch-on-miss per-symbol 区间拉取 + **缺根豁免** + **H9** 选股/分析/风控快照迁移。
> 批内序（总方案 P2-1 裁定）：**H7 → H9**（H9 迁移后 H7 的 fetch-on-miss 才对三类消费方可达）。

## 目标

DataBus 的「仓即候选①，miss 兜长尾」真正闭环：local_pg 缺数据时，消费面能真拉远端补数（而非降级空帧）；选股/分析/风控三处消费方读行情统一走 DataBus（血缘/路由/对账打通）。

## 三件事范围

| 件 | 内容 | 现状 |
|---|---|---|
| **H7** | adapter.fetch 补 **consume 口径**（bar_daily+stock/etf 的 per-symbol 单标的区间拉取）→ databus 空帧时真拉 | `databus._fetch_on_miss` 降级空帧+告警（`databus.py:148-159`）；`TushareAdapter.fetch` 的 bar_daily+stock 只走 `pull_daily_batch`（按日全市场，`base.py:282`） |
| **缺根豁免** | 冷切换缺根的豁免规则 | 原设计在 **shadow 引擎**（已随批 79 删除）；需重新裁定落点 |
| **H9** | 选股/分析/风控三处读行情统一走 DataBus | 三处读的是快照/SQL 聚合，**不读 bar**（无 `get_bars` 调用点） |

## 方案

### H7 · fetch-on-miss per-symbol 区间拉取（核心件，最明确）

**关键事实**：`DataRequest` 已有 `mode` 字段（`contract.py`，`"consume"`/`"supply"` 两值，默认 consume）；per-symbol 单标的日线拉取 `pull_daily(ts_code, start, end)` 已存在（`tushare_adapter.py:122`）。**无需新写 API 调用，只做口径分派。**

1. `TushareAdapter.fetch` 的 `bar_daily + stock/etf` 分支，按 `req.mode`（或等价信号）分派：
   - **supply（同步引擎）**：`pull_daily_batch`（按日全市场批拉）——现状不变，对齐批 72 已上产的同步路径，零行为变化。
   - **consume（DataBus fetch-on-miss）**：`pull_daily(symbol, start, end)`（per-symbol 单标的区间，**不复权**、逐行 adj_factor——对齐 bar_1D 契约）。
2. `databus._fetch_on_miss`：从「降级空帧+告警」改为真调 `chain.fetch`（复用 `_fetch_via_adapter` 的 routing 链），仅单标的 bar 族生效；其他 kind 维持降级空帧（bar 族外的 consume 口径不在本批）。
3. 附：`bar_minute`/`index_daily` 的 fetch 已是 per-symbol 区间（`base.py:296-314`），本批只补 bar_daily+stock/etf 的 consume 口径。

**判定 consume vs supply**：优先用 `req.mode`；若同步引擎当前构造 DataRequest 未显式传 `mode="supply"`，则本批一并补齐（engine.py 的 `_fetch_supply` 构造点），避免靠 symbols 长度/range 跨度猜测。

### 缺根豁免（✅ 已裁定 2026-10-01）

shadow 引擎已删（批 79，迁移 0114），总方案原文「shadow 引擎加缺根/时间窗模式」的宿主不存在。**裁定（用户确认）：退化为 per-symbol 区间拉取的天然语义，不建单独豁免引擎。** 理由：
- per-symbol 区间拉取（pull_daily）天然容忍缺根——停牌/非交易日/新股未上市，源接口按日返回，缺的那天就是没有 bar，属正常不是错误；
- 数据质量检测已由 `validate_bar_quality`（批 71 单源跳空/断点）承担，消费面 fetch-on-miss 无需再叠一层豁免；
- 「冷切换缺根豁免引擎」原始动机是 shadow 对账白名单，随 shadow 删除而消失。

结论：本批**只做 H7 的 per-symbol 区间拉取**，缺根豁免随其天然成立；不新增任何豁免引擎/白名单。

### H9 · 选股/分析/风控快照迁移（范围需勘察）

现状三处**无 `get_bars` 调用点**（已全仓 grep 证实：选股 `analysis.py:113` 是 SQL 聚合横截面，分析走 `market_snapshot`/`stock_detail` 实时快照，风控读 `position_snapshot`）。故 H9 分两步，**勘察先行**：

1. **勘察（本批第一交付物）**：WorkBuddy 逐点列出三处消费方「读行情/bar 数据」的准确位置（含 file:line + 读什么 + 当前形态 + 是否应迁移）。判据：读的是 bar 序列 → 迁 `get_bars`；读的是可缓存快照 → 迁 `get_snapshot`；读的是 SQL 聚合基本面（非行情）→ **不动**（非数据供给域，强迁是过度设计）。
2. **迁移**：按勘察清单，把「读 bar」的点迁 `DataBus.get_bars`、「读快照」的点迁 `DataBus.get_snapshot`（后者可能需先补 `get_snapshot` 的 Valkey 序列化/反序列化——现为骨架，`databus.py:168-176`）。
