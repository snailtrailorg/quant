# 批 77 · 权限矩阵与实盘面分离（`live_control` 键）

> 立项 2026-10-01。**起因**：批 76 二次裁定把解冻挂 `strategy_control` 后，用户提出原则
> 「**analyst 只能进行回测和实盘测试，不能执行实盘交易，这是最基础的权限设置**」，要求
> 据此推演 analyst 是否应有解冻权限 → 推演结论=**不该**，且暴露出 `strategy_control`
> **键粒度太粗**（把「编辑策略资产/回测」与「启动实盘执行」混在一个键）。

## 一、推演（从原则出发，不是从现状出发）

**原则**：analyst = 研究角色（回测 + 实盘**测试**），**不执行实盘交易**。

**逐动作归类**：

| 动作 | 面 | analyst 应有 | 依据 |
|---|---|---|---|
| `POST /api/backtest` 等回测 | 研究 | ✅ | 回测＝历史模拟，不触真实资金 |
| `POST /api/pool` / `DELETE` 因子池 | 研究 | ✅ | 投研资产 |
| `POST /api/factors` CRUD / `preview` / `validate` | 研究 | ✅ | 因子/策略资产 |
| `POST /api/strategy` CRUD / `validate-python` / `validate-params` | 研究 | ✅ | 写策略＝回测前置 |
| `POST /api/strategy/{sid}/verify` | 研究 | ✅ | 标记「已通过回测验证」——纯元数据 |
| `POST /api/chat` / `POST /api/stock/{s}/analyze` | 研究 | ✅ | 只读工具直执 |
| `GET /api/runbook` | 通用 | ✅ | 只读 |
| **`POST /api/live-task`**（建实盘任务） | **实盘** | ❌ | 建真实盘任务 |
| **`POST /api/live-task/{tid}/start` / `stop` / `delete`** | **实盘** | ❌ | `systemctl start quant-live-task@N`＝起真实盘进程 |
| **`POST /api/live-task/{tid}/unfreeze`**（+ `unfreeze-request` 预览） | **实盘** | ❌ | **解冻＝恢复 BUY 放行**（`frozen_allows`：sticky 期 BUY 拒/SELL 放；解冻后 `buy_ok_check` 才可能过）——这是交易面动作 |
| **`POST /api/strategy/{sid}/start` / `stop`** | **实盘** | ❌ | `systemctl start quant-strategy@N`＝同款真实盘进程（**最易漏：它在 strategy.py 里，名字像研究面**） |

**关键发现（`strategy_control` 一键两域）**：

| 域 | 动作 | 特征 |
|---|---|---|
| **研究面** | 写策略/因子、回测、验证标记、AI 分析 | **只写资产、不起进程**；错了可重跑 |
| **实盘面** | 起停实盘任务、起停策略进程、解冻 | **起 systemd 进程 / 改真实盘执行状态**；错了下真单 |

⇒ analyst 持 `strategy_control` = 同时拿到两域 ⇒ **越界**（本批前就已存在，
批 76 的解冻只是显化了它）。

## 二、裁定（2026-10-01 用户）

1. **拆分方案**：新增 **`live_control`** 键承载实盘面；`analyst` 保留 `strategy_control`（研究面）。
2. **trader 边界一并复核并写进立法**（本文件 §四 权限矩阵）。

## 三、落地设计

### 3.1 键归属（`live_control` 承接「起进程/改实盘执行状态」类）

- 从 `strategy_control` **迁出**到 `live_control`：
  - `trading.py`：`create_live_task` / `start_live_task` / `stop_live_task` / `delete_live_task` /
    `unfreeze_live_task` / `get_unfreeze_request`
  - `strategy.py`：`start_strategy` / `stop_strategy`（起停 `quant-strategy@N`）
- **留在 `strategy_control`**（研究面不变）：backtest 全部、factors 全部、strategy 的 CRUD/validate/verify、
  `pool` 全部、`chat`、`stock/analyze`、`runbook`。
- **不变**：`live_trading_control`（`/api/live-trading/{market}` 市场级实盘开关）——已有独立键，
  语义是「市场总闸」而非「单任务起停」，**不并入** `live_control`（并入会把两个不同粒度的开关压平）。

### 3.2 角色集合（`perms.PERMISSIONS` 字面量子集）

| 角色 | 变更 |
|---|---|
| `viewer` | 不变 `{read}` |
| `analyst` | 不变 `{read, strategy_control, data_sync}` —— **语义已被拆分净化为「纯研究」**，无需改字面量 |
| `trader` | **+`live_control`**（原靠 `strategy_control` 起停实盘；拆分后须显式加） |
| `admin` | 自动派生（`set(API_PERM_KEYS)`）—— 零改动 |

⚠️ **这是本批的关键连带**：`trader` 必须显式加 `live_control`，否则拆分会**削掉 trader 的实盘起停权**
（原经 `strategy_control` 拿到）——**功能回归**。

### 3.3 IM/LLM 档位（批 76 三面契约的延续）

- LLM：`UNFREEZE_TOOLS` 的判定键 `strategy_control` → **`live_control`**（trader+admin 皆可，analyst 不可）。
- IM 卡片：`_need` 里 `task_unfreeze` → **`live_control`**。
- Web 端点：`unfreeze_live_task` → **`live_control`**。
- **三面仍须同键**（`TestToolGatingContract` 照旧钉死，只改期望键）。

### 3.4 前端

- `permGroups.js`：`live_control` 进 `trading` 组；`locales` 加 `key_live_control` 中英。
- 前端 `LiveTask.vue` 按钮显隐：起停/解冻按钮原用 `navReadonly`（nav 维），**未按 perm 显隐**
  ⇒ analyst 进得了页面（`live-task` 页无 `meta.perm`）但后端会 403。**本批须给按钮挂 perm 门**
  （否则 analyst 看到按钮点了报错＝死胡同，正是批 76 P1 同类病）。

## 四、权限矩阵（立法：新增端点/工具时按此归类）

| 面 | 键 | viewer | analyst | trader | admin | 判据（一句话） |
|---|---|---|---|---|---|---|
| 读 | `read` | ✅ | ✅ | ✅ | ✅ | 不改任何状态 |
| 研究 | `strategy_control` | ❌ | ✅ | ✅ | ✅ | 只写**投研资产**、不起进程、不碰实盘 |
| 数据 | `data_sync` | ❌ | ✅ | ❌ | ✅ | 行情同步（非交易） |
| **实盘** | **`live_control`** | ❌ | **❌** | **✅** | ✅ | **起/停 systemd 实盘进程、建删实盘任务、解冻** |
| 实盘总闸 | `live_trading_control` | ❌ | ❌ | ✅ | ✅ | 市场级启停（比 live_control 更粗一档） |
| 风控 | `halt` / `resume` | ❌ | ❌ | halt | ✅ | 全站熔断/恢复 |
| 下单 | `trade` | ❌ | ❌ | ✅ | ✅ | 直接下单 |
| 系统 | `system_config` 等 | ❌ | ❌ | ❌ | ✅ | 配置/凭证/用户 |

**新增受控动作时的判据**（先归类再选键，别从「谁该有」倒推）：
1. 它**起不停进程**？起 systemd/改实盘执行状态 ⇒ `live_control`；只写库 ⇒ 研究面。
2. 它**能不能导致真实成交**？能 ⇒ 至少 `live_control`；直接下单 ⇒ `trade`。
3. 它**改不改全站/全市场闸**？⇒ `halt`/`resume` 或 `live_trading_control`。
4. 都不沾 ⇒ `read` / `strategy_control` / `data_sync`。

## 五、验收

- `analyst`：可回测/写策略/因子/分析；**403** on 建实盘任务、起停实盘任务、启停策略进程、解冻。
- `trader`/`admin`：上述实盘动作**全部 200**（无功能回归——本批最大风险点，须逐条钉）。
- LLM 工具档：analyst 看不到 `task_unfreeze`；trader/admin 看得到。
- IM 卡片面：同键（`live_control`）。
- 前端：analyst 进实盘任务页**看不到**起停/解冻按钮（或页面只读），非「看得到点了报错」。
- 全量 pytest + ruff + 前端 build 绿。
