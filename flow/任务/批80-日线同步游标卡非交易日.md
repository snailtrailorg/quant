# 批 80 · 日线同步游标卡非交易日（节假日落 cron 工作日 → 永久停摆）

> 立项 2026-09-29 盘后（批 79 上产当日，观察自然增量时发现）。
> **根因**：`trade_day_filter=trade_day` 判「非交易日」跳过后游标不推进，`next_run` 恒停在该非交易日 → 日线同步永久卡死。

## 一、根因（已实证）

- 日线 schedule = `30 16 * * 1-5`（工作日 16:30）+ `trade_day_filter=trade_day`。
- 09-24（周四）同步成功，游标 `last_sync_ts`=09-24 16:33。
- 09-25 是**中秋（周五，休市）**，`is_trading_day(09-25)=False`。
- croniter 从游标算 `next_run`=09-25 16:30（cron `1-5` 匹配到周五），`tasks.py:795` 判「非交易日」→ `continue`，**游标不推进**。
- 下次调度 base 仍是 09-24 → `next_run` 仍 09-25 → 永久「非交易日」。

**既有 bug**：`tasks.py:793-797` 逻辑自 08-06（`dd135d2`）存在。普通周末因 cron `1-5` 天然跳过不触发；**节假日恰落 cron 匹配的工作日**（中秋周五）首次触发——故此前未暴露。

**影响**：日线缺 09-28（周一）、09-29（周二）两交易日（09-25 中秋无数据正常）。

## 二、修复方案（滚 `next_run` 到 ≤now 的下一个交易日）

改 `tasks.py` `data_sync_scheduler` 的 cron 解析后（`tasks.py:794` 前），`trade_day` 时把 `next_run` 从非交易日滚到下一个交易日：

```python
tf = trade_day_filter or "none"
if tf == "trade_day":
    # 滚到 ≤now 的下一个交易日：next_run 可能停在节假日（cron 工作日匹配但休市，
    # 如 09-25 中秋周五），跳过不推进游标 → next_run 恒停此日 → 同步卡死（2026-09-29 实测）
    _guard = 0
    while not is_trading_day(next_run.date()) and _guard < 20:
        _nxt = cron.get_next(datetime)
        if _nxt > now.replace(tzinfo=None):   # 下一个交易日还没到，交给下次调度
            break
        next_run = _nxt
        _guard += 1
```

之后原「未到周期」/「非交易日」判断不变（`tasks.py:789/795`）。cron `1-5` 天然跳过周末，本方案只需滚过「落在工作日的节假日」。

**关键语义**：滚过非交易日是**读侧**行为，不写游标——游标推进仍由 `sync()` 成功后内部管理（`engine.py:162`），本批不碰游标写侧（避免 scheduler/sync 双写语义混乱）。

## 三、产出

- `tasks.py`：`data_sync_scheduler` 加「滚 next_run 到交易日」块（约 10 行）。
- 测试：`test_scheduler.py`（或既有 scheduler 测试）补钉：
  1. 游标停在节假日前一天（09-24）→ next_run=09-25（中秋非交易日）→ 滚到 09-28（交易日）→ 触发 sync。
  2. 边界：今天=09-25 中秋，滚到 09-28 > now → break → 判「非交易日」（未来交易日未到）。
  3. guard 耗尽（20 个非交易日，日历异常）→ fail-soft 判「非交易日」不死循环。
