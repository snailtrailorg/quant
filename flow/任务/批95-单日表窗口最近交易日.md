# 批 95 · 单日表窗口（v2 · 步 2 双盲审回炉）

> 立项 2026-10-20。**v2**：A P0×1+P1×3+P2×4 / B P1×3+P2×5 全处置（两审独立撞同一批问题：测试必炸、定性失真、fail-open 静默）。

## 问题（v2 定性·带 DB 证据）

`pool_data._window_of` 对单日表（`_SINGLE_DAY_TABLES={cyq_chips}`）恒返 `(upper, upper)`，upper=「昨日自然日」。

1. **长假边界永久缺口（真危害）**：长假后首轮 upper=最后假日 ⇒ 0 行；次轮 upper=首日（交易日）⇒ **永跳过假前最后交易日**。DB 实证：`cyq_chips` 20261008~20261019 共 8 天，**20260930（国庆前最后交易日）缺失**。
2. **full 校准补不回**：full 只清 cursors，单日分支在 cursors 判断前 return ⇒ staging 清空后 full 校准 6s「成功」0 行。
3. ~~白耗配额~~（v2 删——pool 节奏是每日一轮非 5 分钟，周六 upper=周五仍有数据；0 行只发生在周日/节后首日）。

**A-P0-1 纠正我的定性错误**：单日接口**并非**拿不到深度——**不传 trade_date 时一次回 ~45 个交易日**（A 实测 `pro.cyq_chips('600000.SH')` → 6000 行/45 天；仓内 D17:120 与 stock_detail.py:394 两处独立佐证）。

## 产出（v2）

1. **`_nearest_trade_day(upper_str) -> str`**（pool_data 模块级；用 `_pdb.get_conn`——测试 patch `pool_data._pdb.get_conn` 天然 hermetic）：
   - SQL：`SELECT to_char(cal_date,'YYYYMMDD') FROM trade_cal WHERE exchange='SSE' AND is_open=1 AND cal_date <= %s ORDER BY cal_date DESC LIMIT 1`（A 实测 '20261018'→'20261016' 通过）。
   - **无行/异常分别 warning 后返原值**（A-P1-2 + B-P1-3：原 `fetchone()[0]` 空表会 TypeError 被吞成「日历读取失败」误诊）。
   - **陈旧守卫**：结果与 upper 跨度 > 10 自然日 ⇒ warning「日历陈旧/未覆盖」并返原值（宁要现状 0 行也不要静默拉陈旧日——trade_cal 断更时最近交易日会返 4 天前的旧日，upsert 幂等+done=比 0 行更难发现）。
   - 注释写明**不可**复用 `engine._data_ready_end_date(lag=1)`：它取「≤today 第 2 个交易日」，周六返周四（跳过周五），不等价。
2. **`_window_of(..., *, single_day: str | None = None, single_day_all: bool = False)`**（A-P2-1/B-P2-1 keyword-only）：
   - 单日表 + `single_day_all=True` ⇒ `(None, None)`——**无参=一次 45 天**（A-P0-1 采纳；`_pool_request` 已支持 start=None ⇒ adapter 不传 trade_date，tushare_adapter.py:743-745）。
   - 单日表 + `single_day` 值 ⇒ `(single_day, single_day)`。
   - 默认（None/False）⇒ `(upper, upper)` 现状零漂移。
3. **`run_pool_sync` 每轮算一次并注入**（B-P2-2：循环外 `windows = {t: _window_of(...) for t in metas}`，纯函数不再算 N×M 次）：`single_day_all = (full or bool(symbols))`，`single_day = _nearest_trade_day(upper_str)`。
4. **不做**：不给增量表加游标短路（批 92 上界不动）；不用 `trade_day_filter='trade_day'` 替代（会整轮过滤掉周日 full 校准——A-P2-4 实锤 tasks.py:745/840）。

## 验收标准
1. **纯函数 oracle**（不碰 DB）：`_window_of('cyq_chips', {}, '20261018', single_day='20261016')` == `('20261016','20261016')`；`single_day_all=True` == `(None, None)`；无参 == `('20261018','20261018')`
2. `_nearest_trade_day` 三态单测（mock `pool_data._pdb.get_conn`，`__enter__/execute/fetchone` 链）：命中返交易日 / 无行返原值+warning / 异常返原值+warning / **陈旧（>10 日）返原值+warning**
3. 增量表零漂移：`_window_of('income', {'income':'20261010'}, upper, 7)` 行为不变（就地复用 test_batch130 已有 oracle，不新建重复）
4. **full 轮验真**：`run_pool_sync(full=True)` 时单日表请求 `range_ is None`（A-P1-3：原「断言最近交易日」证明不了 full 与日常轮的差别）；另 dev 实跑断言 saved>0
5. **边界补回**：dev 上 `run_pool_sync(symbols=['600000.SH'])`（45 天路径）后 `cyq_chips` 含 20260930
6. 全量 pytest 绿（含 test_batch130 / test_pool_data_incremental 改后）
