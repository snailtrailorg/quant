# 批188 TD执行进程化 · 双盲审报告（专家A）

**结论：不可开工——3 个 P0（断链/风控旁路/取价失效）、3 个 P1。**

## P0

- **P0-1 事件回写/三账对账链断**：`write_trade_log`/`write_order_status`/`reconcile_orders` 均在 `strategy_runner/trading.py:91/144/555`，靠 `main.py:392-393 exec_port.subscribe_order` 注册回调；形态X 策略无 adapter + TD 会话迁出后 runner 无 exec_port ⇒ 回调不再注册 ⇒ trade_log 不写、终态不流转、F-4 认领断。且"三账靠 signal_id+client_id 关联"错误——`trading.py:173` 实际靠 `vt_orderid` 反查 order_log，`signal_log` 无 client_id/vt_orderid 列。
  修法：把事件消费→write_trade_log/write_order_status/reconcile 与 vt_orderid 回填一并迁进 td_exec，并在 §4.4 改正关联键真源。

- **P0-2 td→quote 取价断链**：`position_snapshot` 由 worker 按 `ctx["account_id"]`（TD 账号）写（`trading.py:222/228`、`hub_worker.py:1028`），而 quote 账号 hub 持仓订阅源按 `account_id=%s`（quote 账号）过滤（`md_hub/main.py:346-347`）。TD账号≠quote账号时 quote hub 看不到该持仓 ⇒ 不订阅 ⇒ `hub:latest_tick:{quote_account}:{vt}` 无 tick ⇒ 清仓取价失败。
  修法：订阅持仓源改读映射后的 quote 账号，或持仓快照在 quote 账号也落一份；§4.6"持仓驱动订阅保证有 tick"须重写并给 td≠quote 的实测验收。

- **P0-3 paper/回测路径自相矛盾（风控旁路风险）**：§7 称"不改 paper/回测（路径不变）"，但 §4.2/§4.3 把 `place_order` 改成"发命令+等回执、删 check_order/WAL/send_order"——这是 paper/回测共用路径（`strategy.py:463-464 paper` 形参；`test_sc_orders.py:86`、`test_d32_p2_wiring.py:52` patch `_log_signal_order`）。paper 无 td-exec 消费、回测无 Redis 通道 ⇒ 命令无人处理；回测对 `_log_signal_order` 的 monkey-patch 因 place_order 不再调它而失效（F-4 顺序断言变空）。
  修法：place_order 显式分支——live 走命令通道，paper/回测保留本地 check_order+WAL+send_order，并在方案中列明两种路径与对应测试。

## P1

- **P1-4 迁移原子性无机制**：方案"先停全部 live_task 再起 td-exec"——live_task 停靠 SIGTERM→`main.py:574-581` finally 释放 session_slot，但 `td_registry.py:84` 明示"XtpTdApi 无 logout"，进程死后连接释放依赖 TCP 断链，与 td-exec 新连接存在重叠窗（D26 同账号双 TD 互踢）；SA4 reconciler 每 300s 按 live_task running 行重拉（`tasks.py:2047-2048`），方案仅说"清 running 行"未给原子顺序保证。
  修法：写明停 unit→确认端口释放→清 DB running 行的原子步骤与 fencing 守卫，逾期告警。

- **P1-5 验收证据不可执行**：方案 `cd .../server`（行155）后，行161-163 的 `grep -rn ... server/src/td_exec ...` 解析为 `server/server/src/...`、行164 `cd web` 解析为 `server/web`，均不存在 ⇒ 静态落点/构建命令必失败；另 §4.7 改动 risk 路由判活，验收未列 `test_route_auth_gate.py`（CLAUDE.md 要求改端点必跑）。
  修法：修正工作目录相对路径，补路由认证守门测试。

- **P1-6 行号事实错误**：方案称"急停 check_order 在 `trading.py:782`"，实际急停判定在 `trading.py:859`（782 为 `saw_positions=True`）；`is_flat_or_reduce` 实为 `risk.py:23` 非 `:31`。
  修法：按实测行号更正（不影响设计但影响实施定位）。
