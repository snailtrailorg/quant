# 紧急处置账号校验 v10 · 独立单审（最后一轮）

结论：**不可开工**——2 P0 + 3 P1。裁定①②方向（无限循环、触发执行解耦、List 持久化）正确，但 v8 的 P0-1/P0-2 在本稿未真闭合，且新增的 uid 缺口使裁定②"web 统一显示"落空。

## P0（阻断）

- **P0-1｜web 同步回执无源 + 前端误判（v8-A P0-1 变体，未闭合）**：现网 `risk_halt`(risk.py:192-210) 同步派 cancel-all 并返回 `{"halted":True,"cancel":cancel_out}`；前端 onHalt(Emergency.vue:250-251) 用 `fmtResult(r.cancel)`，fmtResult(:103-136) 读 `status/results/dispatched`。v10 §3.2:72 删 web `:204` 直接派发后 5s 窗内无 `risk:cmd:result` 可 poll，而 §4③:110 明写"旧 fmtResult 不动"、§0:19 仍称"web 5s 窗保留"——三处互斥：前端拿到空 `cancel` → 显示"已派发 0"/无撤单结果。修法：定义 risk_halt 新同步返回契约（只回 halted+triggered、不再回 cancel），改 onHalt 停用 `fmtResult(r.cancel)`、引导看板，同步改 §4③/§5。

- **P0-2｜统一派发链断：operator_uid 无来源，非 web halt 进不了看板（v8-B P0-2 未闭合）**：§3.2:71-72 三源只传 `emergency_halt(reason)`，risk.py:159 签名仅 reason，`飞书:张三`/`Web:username` 不含 uid；risk_sweep(tasks.py:98-107) 无 web payload，而 `_dispatch_risk_cmd` 强依赖 `payload["username"]`(risk.py:364) 与 `_operator_uid`(risk.py:355/268-276) → KeyError 或 uid=None。又 §3.3:79/§3.6:98,100 的 `active:{uid}` 按查看者 uid 拉，飞书/LLM halt 无 uid 则 active 建不出 → web 永看不到非 web 熔断，裁定②落空。修法：emergency_halt 增 operator_uid 实参且三源真传、event 携可信 uid；定义 risk_sweep 合成 payload 契约；active 改按 halt 权限全局可见（或广播 active 列表端点）；写明 SSE uid 异常态。

## P1（严重遗漏）

- **P1-1｜"LLM:" 第三源无调用点**：gateway.py:65 仅定义工具、:286-290 仅做权限过滤；chat.py:52-94 `_execute_readonly_tool` 未实现 emergency_halt(:94"未实现")；feishu_client.py:399-401 确认路径写 `飞书:` 前缀。无任何 call site 产生 `LLM:xxx` reason，§4⑤⑧/§5 的"三源统一"验收无真源。修法：补 LLM→emergency_halt("LLM:xxx", uid) 真实调用点，否则删第三源及其测试⑧。

- **P1-2｜去抖键 `{ts}` 不成立**：§3.2:74 `risk:halt:dispatched:{ts}`(TTL5min)；risk.py:164 每次 halt 覆盖 halt_ts → 重复点熔断生成新 ts→新键→重复派发；沿兜底(hub_worker.py:1028-1034)不走该键，"防沿兜底重复派发"无效。修法：仅 halted 0→1 翻转生成稳定 dispatched id 并原子 check-and-set；删"防沿兜底"表述或让沿兜底接入。

- **P1-3｜List 派发可靠性未定义**：§3.2:73 称 risk_sweep"每拍消费"，实为 60s cron(app.py:192-196)；§4① 无 trigger List 的 TTL/LTRIM/堆积清理，未定 LPOP vs BLPOP——BLPOP 无超时会阻塞共用 `"risk"` 队列的全部任务(app.py:185-201)。修法：明写非阻塞 LPOP+循环 drain、List 设 EXPIRE/LTRIM、声明 ≤60s 派发延迟由沿兜底兜住并纳入 §5 验收。
