# 模块深度审核 → 失败模式全仓扫描（2026-09-29）

> 命题：「同类问题肯定不止一种，怎么彻底清理？挑一个模块深审，把发现的问题当样本去搜全工程？」
>
> 本文给出方法（§一）、本次实证（§二~§四）、真账清单（§五）与工具（§六）。
> 工具：`scripts/audit-failure-modes.py`（10 个探针，自带反验；反验 10/10 通过）

---

## 一、方法论：你的思路对，但要改一处

「挑一个模块深审 → 样本 → 搜全仓」**方向完全正确**，这是唯一能从「一个栗子」走到「一类问题」的路。
但有一个陷阱必须先破：

### 1.1 陷阱：不能拿**样本代码**去搜，要拿**失败机理**去搜

若直接拿样本代码做模式匹配（例如 `grep 'market=%s'`），你搜到的是**同一个 bug 的其它副本**，
不是**同一类问题的其它形态**。前者顶多 3~5 条，后者 100+ 条。

```
样本：main.py:199 用 provider 查 market 键
  ✗ 拿代码搜：grep "WHERE market=%s"        → 3 处（其中 2 处本就正确）
  ✓ 拿机理搜：跨域同名——A 域的值集被用作 B 域的键
              → 探针：找所有 "WHERE <col>=%s" 且参数名与列名语义不同域的调用点
```

### 1.2 闭环五步（②⑤ 是最容易省的，也是最不能省的）

| 步 | 做什么 | 省的后果 |
|---|---|---|
| ① 深审一个模块 | **逐行读**（不是扫），挖缺陷样本 | —— |
| ② **抽象成形状** | 每个样本问「它与其它样本共享什么机理」 | 只能搜复制体，搜不到同类异形 |
| ③ 形状 → 探针 | 每个形状写一个可机械判定的探针 | 形状停留在纸面，无法反复跑 |
| ④ 全仓跑 + 分诊 | 跑出候选池，逐条人判真账/假阳性/合法重复 | 把候选当结论，报一堆假账 |
| ⑤ **反验** | 把①的样本固化为回归集，探针必须命中 | **探针坏了你不知道，它给你自信的错误报告** |

### 1.3 怎么保证不漏：用**穷举维度**查模式库的完整性

模式库最大的风险是「想到几个算几个」。破解办法是**用正交维度穷举**，
把每个维度下的失败形态列全，再看模式库能不能解释：

| 维度 | 失败形态 | 本次对应模式 |
|---|---|---|
| 数据面 | 多真源 / 跨域同名 / 位置契约 | P1、P9（＋旧扫描器 A-G） |
| 控制流 | 副作用顺序 / 退出路径 / 异常边界 | **P2、P5**、P4、P7、P8 |
| 状态面 | 多读取面 / 反向缺省 / 防线静默 | **P3**、P10、P4 |
| 文档面 | 注释与代码矛盾 | P6 |

**判据：如果某个维度下的形态在模式库里找不到对应模式，那个维度就是盲区。**
本次新增的 P2/P3/P5 三个模式，正是「控制流」和「状态面」两个维度此前完全没覆盖的（旧扫描器只覆盖数据面）。

> **模式库不是一次性产物。** 下次深审别的模块（如 `web_api`、`data_platform`），
> 新样本要么落进已有模式（→ 说明模式够用），要么逼出新模式（→ 模式库扩容）。
> 这是唯一能让「彻底清理」收敛的机制。

## 四、全仓结果与「三类搜索结果」

扫 260 个文件（`server/src` + `migrations/versions` + `scripts`），候选池 1182 条。
**把候选池按模块深审的经验分诊，结论分三类**——这才是「样本搜全仓」真正的输出：

### 类别 1：同类真账，必须一起修（→ 修复清单）

- **P5 退出通道**：`strategy_runner` 挖到 2 处，全仓搜出 **8 处**（`md_hub/main.py:404`、`md_hub/main.py:247,342`、
  `md_hub/parts.py:228`、`loop.py:79`、`xsleeper.py:55`）。**一个模块的问题，扩散到 4 个模块**。

### 类别 2：同类但**已管理**的合法重复（→ 不要动）

- **P10 `connect_status`**：5 处读取、2 种反向缺省（False/True）。核实后**有注释**：
  `adapters.py:385`「默认 True=不挡暖机」、`hub_worker.py:404`「探测导出缺省 False，与重连沿判定缺省 True 目的不同」。
  → **作者已知此风险并写明**，是刻意的设计。**分诊排除了它。**
- **P2 `md_hub/main.py:168`**：副作用、早于业务调用。核实后**有注释**（第 176-179 行「位置钉死…仅拦 agg 喂入——盘前快照照上详情页，心跳字段语义不变」）→ 合法。
- **P1 `risk.py:203` / `web_api/routes/trading.py:209`**：参数与列同域（`market=market`）→ 合法用法。

> **这一类的价值不低于第一类**：它证明「形状相同 ≠ 都是 bug」。
> 没有分诊，你会把这些当成缺陷去改，把有意的设计改坏。

### 类别 3：该模块独有（→ 不扩散，说明不是通用问题）

- **P9 十元组解包（`main.py:361`）**、**P6 docstring 矛盾**、**P8 启动链 fail-open**：
  全仓同类命中都在 `strategy_runner` 自己（或迁移脚本），**没有扩散**。
  → 说明这是该模块的局部选择，不是团队习惯，优先级可降低。

## 五、分诊后的真账清单

### A. 必修（有具体后果，我逐条核实到行）

| # | 位置 | 事实 | 后果 | 严重度 |
|---|---|---|---|---|
| 1 | `hub_worker.py:325-341` | `state.max_ts` 推进 + `r.set` 持久化 → 再调 `strategy.on_bar`；异常被 `@make_guard` **吞掉并返回 None**，`process_batch` 随后无条件 `xack` | bar 被 ACK（不可重放）+ 水位已推进（永久去重）+ `history` 未追加 → **数据洞且无补洞机制**；`last_bar_wall` 已更新 → 心跳仍显示健康 | **P0** |

## 六、工具

```bash
python scripts/audit-failure-modes.py --selftest        # 反验：10 个样本必须命中（当前 10/10）
python scripts/audit-failure-modes.py                   # 全量
python scripts/audit-failure-modes.py -p P2,P4,P5       # 指定模式
python scripts/audit-failure-modes.py --json 基线.json   # 建基线
python scripts/audit-failure-modes.py --baseline 基线.json   # 只报新增（退出码 1 = 有新增）
```

**置信度分区**（输出里自动分开）：

- **高置信（结构性）**：P1 / P2 / P4 / P5 / P6 / P10 —— 形状本身即缺陷，共 161 条
- **低置信（统计性）**：P3 / P7 / P8 / P9 —— 形状相似，需看上下文，共 1021 条

> 低置信那一千条**不是账**，是「值得抽查的池子」。工具的价值在于让抽查有清单，
> 而不是让人相信清单即结论。

### 反验是必须的（本次实测：探针先后 4 次给出自信的错误结果）

| 症状 | 真因 |
|---|---|
| P1 报 0 条 | SQL 正则在**整个源码文件**上跑，`(?i)FROM` 匹配了 Python 的 `from src.xxx import`，把表名抓成 `src` |
| P1 报 `updated_at` | 参数提取从 `WHERE` 往后找，误命中行内逗号（`UPDATE …SET a=%s, b=now() WHERE c=%s`） |
| P5 报 28 条（含 20 条噪音） | 把 `sys.exit` 和 `os._exit` 混报；**`sys.exit` 会走 atexit，不丢日志**，不是本模式的问题 |
| P7 报告无法阅读 | `detail` 只取块第一行 → 满屏 `try:`；改取「非样板行」后又有满屏 `from … import` |

**没有 `--selftest` 这四类错误全都不会被发现**，工具会持续输出看似正常的错误结果。
这与被审代码里的病同源（`trading.py` 那段写了等于没写的 `SELECT 1` 探测）。
