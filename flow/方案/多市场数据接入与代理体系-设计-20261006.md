## §〇 威廉姆裁决记录（2026-10-06）

1. **OKX 必须接入**——否则无法验证「多加密市场共存」。核心原则：A股所有源是同一份数据的复制（可互替），**加密市场每个交易所的 bar 是不同的数据，不可能聚合**。此原则已由存储层主键（§二）结构化保证，102 要做的是把它贯彻到任务命名、读点选域与代理面。

3. **代理体系**——全局可配多个代理；使用处两个选项：①是否启用代理 ②选用全局池中哪一个。理由：有些源用有些不用；同一市场在不同服务器上用法可能不同；需要多个代理，并非一个包打天下。

5. **101b 分钟粒度**（裁决点补拍）：`bar_1min` 与 `bar_15min` **各拉一天**（最坏情况与常规件各验一张）。

## §一 存储模型（重申 · 本设计不改动存储层）

**一个频率一张表，市场/所混存，symbol 后缀分命名空间。** 实测（dev，2026-10-06）：

| 后缀 | 行数 | 标的数 | 说明 |
|---|---|---|---|
| `.SHSE`/`.SZSE`/`.BSE` | 1749 万 | 8935 | A股（tushare） |
| `.BINANCE` | 0 | — | 批 101 已注册未开采 |
| `.OKX` | 0 | — | 批 102b 目标 |

- 三维度各归其位：`symbol` 后缀＝所（**在唯一键 `(symbol,ts)` 内＝物理防混**）；`source`＝数据源出处；`sync_config`+`sync_kind_config.(kind,sub_kind)`＝写入面归属。
- **不分表**（`okx_bar_1d` 之类被否）：加一个所＝加一个命名空间（一条 config 行），零 DDL；分表的隔离收益后缀方案已在主键免费拿到。
- **「不能聚合」的准确语义**：物理上主键已防误混；**语义上所有读点必须显式选域**（`symbol LIKE '%.OKX'`），禁止按 `market='crypto'` 一把捞跨所数据。此条为 102b 的连带检查项（§五.7）。
- `sub_kind='perp'` 维持共享（`MARKET_OP_DECOMP` 立法：两所都→`perp`，venue 是独立第三元）；**不改** `sub_kind='binance_perp'`。

## §二 批 101b · 币安盘中 bar（小时 / 1min / 15min）——功能验证档

**范围（威廉姆 2026-10-06 裁决）**：`binance_perp_hourly` 拉 **7 天**；`binance_perp_1min`、
`binance_perp_15min` **各 1 天**。单轮占用：1h≈17 万行/53MB、1min≈145 万行/450MB、
15min≈10 万行/30MB，合计 <0.6GB。

### 2.1 🔴 存储闸门：`schedule='manual'`（本批的关键决策）

原稿只算了**保留量**（0.6GB）却给了**日调度**——两者叠加是无界的：批量站日频发布、
落库只增不删，1min **每天 +450MB**。prod 实测 `/dev/vda3 40G，已用 29G，可用 8.3G`：

| 项 | 单日增量 | 打满 8.3G 约需 |
|---|---|---|
| `binance_perp_1min` | ≈450MB | **≈18 天** |
| `binance_perp_15min` | ≈30MB | ≈276 天 |
| `binance_perp_hourly` | ≈53MB | ≈160 天 |

⇒ 迁移 0134 三行一律：

- `enabled=true` **+ `schedule='manual'`**。效果：`data_sync_scheduler` 显式跳过
  （`schedule == "manual"`），而 `sync()` 只在 `enabled=false` 时才拒 ⇒ **UI 手动触发 / 回补可用**
  （`enabled=false` 的项点不动，那不是"验证档"该有的样子）。
- `start_floor` 同时给出回补下限（UI `backfillDisabledDate`），把「有界占用」落到实处：
  hourly＝执行日前推 7 天、1min/15min＝前推 1 天（迁移写 `CURRENT_DATE - N`，即执行当日值）。
- 健康面无噪声（已核实）：tier 新鲜度只覆盖 `TIER1_SYNC_IDS`/`TIER2_ALL_TABLES`（本三键不在内）；
  DataManage 状态列对 `enabled` 且未跑的行渲染 `idle`。
- **扩盘后**：把要用的项 `schedule` 改回 `'30 8 * * *'`（同日线刻）并放宽 `start_floor`。
  这两步是**运维显式决策**，迁移不代做。
- **⚠️ 1min/15min 的「首次手动触发」会得到 `skipped`（实测 2026-10-06 确认，非缺陷）**：
  首跑窗口只有 1 天 ⇒ `窗口 = [UTC昨日, UTC昨日]`，而批量站有 >1 天发布滞后 ⇒ 该窗整段
  未发布 ⇒ 0 行 ⇒ 按 §2.4 标 `skipped`（不是失败，不刷告警）。**自愈**：次日再触发即可
  （那时窗口里的那天已发布）；**立即载入**则走 UI **回补**入口选一个已发布日
  （回补走 `save_bars_overwrite`，不受首跑窗口约束）。hourly 因窗口 7 天，首跑即可拿到
  最近 5–6 个已发布日，不受此影响。

### 2.2 数据源与 interval 泛化

- 仍 `data.binance.vision` 批量 ZIP：`klines/{interval}/` 下月包（≥2020-01）+ 日包。
  **实测各 interval 的月包均存在**（1h/1m 月包 200）⇒ `_period_keys` 零改动即可复用。
- **映射真源收敛到 adapter**：`_INTERVAL_BY_FREQ = {1D→1d, 1h→1h, 1min→1m, 15min→15m}`
  （`to_source_freq` 暴露给契约层）。引擎只持**内部 freq**，不持源 interval 词表。
- 抽 `_pull(sym, interval, start, end)`；`pull_daily` = `_pull(...,'1d')`；`pull_minute` 真实现
  （`NotImplementedError` 占位退役）。`pull_minute` **只认内部 freq**：源 interval 名（`15m`）、
  日粒度、未映射值一律 `UnsupportedFeature`——放行会让 `to_bar_rows(df,'15m')` 把 `15m`
  当 freq 写进列、且 `bar_15m` 表不存在（＝把调用方 bug 变成脏数据）。
- **freq 即表名后缀**：`db.save_bars` 的模板是 `bar_{freq}`，故 `bar_{freq.lower()}` 与
  `sync_kind_config.pg_table` 天然同形（`bar_1h`/`bar_1min`/`bar_15min`）。

### 2.3 引擎：`_sync_binance_perp_daily` 泛化为工厂

`_BINANCE_BAR_SPECS: sync_id → (kind, sub_kind, freq, 首跑天数)`，四个 sync_id 共一条实现。
**代码是声明面**（不按 sync_kind_config 行在运行时反推）——理由：运行时读行会把「声明」变成
「数据」，漂移不可在 import 期发现；本仓既有范式是「代码表 + 真库对账测试」
（同 `POOL_TABLE_SPECS`/`_TIER1_BATCH`）。对账钉见 `tests/test_batch101b_*`。

### 2.4 ⭐ 游标契约修正（本批附带修的真缺陷）

原 `cursor_upto = 窗口上界`。实测**批量站发布滞后 >1 天**（10-06 02:46 UTC 时 10-05 在
全部 interval 上仍 404），而调度落在 08:30 北京＝00:30 UTC ⇒ **窗口末日恒未发布**，游标却照推
⇒ 该日**永不重试**（静默数据洞，sync_log 还记 success）。dev 库 `binance_perp_daily` 的
`last_sync_date=NULL / last_status=running` 即此路径从未成功过的痕迹（现有数据是手工回补的）。

修法：**`cursor_upto` ＝ 实际取到数据的最后一日**（多标的取 max）。未发布日 ⇒ 游标停在它前一日
⇒ 下轮 `start` 自动重试；稳态落后 1 天、**零洞**。

配套：整窗都在「未发布尾区」（`UTC今日 - start ≤ 2 天`）时，0 行**不是故障**——
标 `log_status='skipped'`（正常等待），避免每次调度刷假告警；窗口更长却 0 行照旧进 `failed_dates`。

### 2.5 DataKind 名义收窄（记录在案）

27 词 DataKind **没有 hour 粒度词**，故 1h 与 1min/15min 同归 `bar_minute`
（盘中 bar 族，合法时态含 historical），落表靠 `pg_table` 区分。加新 DataKind 是立法动作
（contract 词表 + `KIND_CAP_CLASS` + 三条钉），不搭本批的车。已知副作用一处、当前不可达：
`data_platform/databus.py::_FREQ_BY_KIND` 的「未达水位降级」会把 `bar_minute` 推成 `1min`——
该路径只在**实时订阅暖机**时走，而加密批量站没有实时腿（`rt_quote` 未声明）。挂账到实时批。

### 2.6 迁移与验收

- **迁移 0134**（原稿写 0133，已被批 103b 占用 ⇒ 顺延；102a 相应顺延 0135）：
  sync_config 三行 + sync_kind_config 三行；`(kind, sub_kind) = (bar_minute, perp)`。
- 验收：roundtrip 用例（值级断言三行 + 降级对称）；`batch99` 回补能力表 17→20；

## §三 批 102a · 代理配置体系（全局池 + 按源绑定）

### 3.1 需求（威廉姆原话的工程化）

> 「系统全局可以添加多个代理，然后再需要用它的地方设置两个配置选项：一个是 enable 代理，一个是选择全局代理中的一个。有些源用，有些源不用，同一个市场也有可能不同服务器有的用有的不用。」

> **2026-10-06 追加（威廉姆）**：「服务器设置还是有的，不能硬编码」——各 provider 的服务端点（binance 批量站 S3、OKX www.okx.com、tushare api）也走本配置面，代码只留缺省值。

> **2026-10-06 追加（威廉姆）**：「代理不应只支持 socks，普通 http/https 代理也应该支持」——代理 DSN 的
> **scheme 词表＝{`socks5h`、`socks5`、`http`、`https`}**，不锁死 SOCKS。理由：http/https 代理是更普遍的
> 存在形态（企业出网代理、squid、云 NAT 网关、多数机场双协议），只认 SOCKS 会把大量合法部署挡在门外。
> DNS 解析语义（真正的硬约束在语义、不在 scheme 名字）见 §3.4。

### 3.2 分层归属（「保存在哪一层」的答案）

**存 DB 配置面（新表），不进 .env、不进代码。** 理由：

- dev/staging/prod **各自独立 DB** ⇒ 「同一市场不同服务器不同用法」天然成立（同一份代码读各自库）；
- 与交易凭证（interfaces）同层同模式——本仓已有「凭证落库 + API 掩码」的先例；
- 可 UI 管理、可审计、有权限门。

### 3.3 表设计（迁移 0135，expand-only）

```sql
-- 全局代理池
CREATE TABLE IF NOT EXISTS proxy_config (
    name     TEXT PRIMARY KEY,          -- 人类可读标识，如 'aws-tokyo'
    url      TEXT NOT NULL,             -- 完整 DSN：{socks5h|socks5|http|https}://[user:pass@]host:port
    notes    TEXT,
    enabled  BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- 按消费方绑定（两选项：enable + 选哪个）
CREATE TABLE IF NOT EXISTS proxy_binding (
    consumer     TEXT PRIMARY KEY,      -- 数据源 provider（'binance'/'okx'/'tushare'…）或交易通道（'binance_perp'/'okx_perp'…）
    proxy_enabled BOOLEAN NOT NULL DEFAULT false,
    proxy_name   TEXT REFERENCES proxy_config(name) ON DELETE SET NULL,
    endpoint_override TEXT,        -- 服务端点覆盖（NULL=用代码缺省）；binance S3/okx 域名/tushare api 由此配置化
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT ck_proxy_binding_name CHECK (NOT proxy_enabled OR proxy_name IS NOT NULL)
);
```

- 建表用 **`CREATE TABLE IF NOT EXISTS`**（本仓 16/17 建表迁移的既有惯例，最新 0127 同款）——部署中断后强制复跑幂等。
- **consumer 键空间＝provider 名**：数据面（`binance`/`okx`/`tushare`）与通道面（`binance_perp`/`okx_perp`）同名空间共用一张绑定表——通道面未来（实时腿）免费复用。
- **seed 原则**：迁移**不 seed 个人代理地址**（AWS 那台的 DSN 属运维态，非代码态）；表建好后经 UI/API 配置。dev/prod 各配各的。
- **两条语义约束落在 DB 层**（不是应用层兜底）：
  - `CHECK (NOT proxy_enabled OR proxy_name IS NOT NULL)` ⇒ 「启用了却没选代理」被 DB 拒（路由写入侧另拒一次，双保险）。
  - `ON DELETE SET NULL` ⇒ 删池行时绑定行**不消失**、`proxy_name` 置 NULL；若该绑定是「已启用」，置 NULL 违 CHECK ⇒ **整条 DELETE 被拒**。故「先关绑定再删」由 DB 强制，**不会留下悬空启用态**（路由把它映射成 409 `PROXY_IN_USE`，不是 500）。
- **⭐ `url` 是唯一含凭证的列 ⇒ 写入语义「空串＝留空不改」**：`list_proxies` 只回掩码值，若前端把 `socks5h://***@h:1080` 原样回写就会**静默毁掉代理凭证**（或让认证失败变成难查的运行时错）。故 `upsert_proxy` 收空 `url` ⇒ 只更新 `notes`/`enabled`、保留原 DSN；**新建行缺 `url` ⇒ 响亮拒绝**（不能建一条没有出口的代理）。同批 38 SMTP 密码三段语义。
- **语义**：`proxy_enabled=false`、`proxy_name IS NULL`、池中该行 `enabled=false` 三者任一 ⇒ **直连**。enable 与 select 分立是刻意的（UI 上开关与下拉各自独立，换代理不动开关）。
  - 由此池行的 `enabled=false` ＝**全局停用开关**：一处关掉，所有指向它的绑定同时回落直连（这正是「禁用」应有的语义，不是漏判）。

### 3.4 解析与接线

**三层各管一件事：解析在 engine、注入在 `configure_exit`、使用在 adapter。**

- **解析（层 1，`data_platform/proxy.py`）**：`resolve_proxy(consumer) -> str | None` 读 binding → 满足 §3.3 三条件 ⇒ **返回池中 DSN 原样**（scheme 由运维选定，本层不加工）；否则 None＝直连。`resolve_endpoint(consumer)` 读 `endpoint_override`，**与代理开关正交**（两个独立维）。
- **注入（层 2，`data_sync/engine.py::_apply_exit_config`）**：engine **构造 adapter 时一次**解析，调用 `adapter.configure_exit(proxy=…, endpoint=…)`。两处 adapter 工厂（`_get_kline_adapter` / `_get_supply_adapter`）出口统一 `_apply_exit_config(adapter)`。
  - **为什么解析不放 adapter 里**：放进去＝`exit_config()` 退化成懒解析触库 ⇒ 直接手搓 adapter 的单测（`_pull`/`list_symbols`）与 `test_engine_provider` 会被迫建库，**测试与 DB 耦合成灾**。注入式让「每任务解析一次」与「单元测试零 DB」**同时**成立。
  - **禁进程级缓存**：adapter 每任务新建 ⇒ 天然「每任务一次」；写模块级/进程级缓存会在「测试打桩 DB」后污染后续用例（既有坑，见 MEMORY）。
  - **解析失败＝回落直连 + WARNING**（口径同本文件 `_routing_pilot_on` 的配置回退惯例）：出口代理是**增强**不是前置，一个可选配置的存储异常不该把整个同步任务打挂。**代价明账**：表缺/DB 抖动期代理不生效、且直连可通时，表象与「正常直连」同形 ⇒ 靠 WARNING（`quant-journal` 可查）+ probe 端点实测兜底。
- **能力声明（唯一真源＝adapter 类属性）**：`BaseDataAdapter.supports_exit_config: bool = False`，**只有自己发 HTTP 的 adapter 置 True**（现为 `binance`；102b 的 `okx` 届时自动进集合）。SDK 型（tushare / jqdatasdk 官方客户端不暴露 per-call 代理）保持 False ⇒
  - `configure_exit(proxy=…)` 对它们**响亮抛 `UnsupportedFeature`**（不静默绕过）；
  - 路由写入侧 `_assert_consumer_capable` 直接 **400 `CONSUMER_NOT_PROXYABLE`**（配了不会生效的配置＝本仓禁的死配置）；
  - 引擎 `_apply_exit_config` 对它们**完全不触库**（`test_engine_provider` 类单测零 DB 的保证）。
- **HTTP 栈统一 requests**：现 `_get` 用 urllib 裸连（无代理能力）。统一切 **requests**（已是传递依赖，转显式声明；`requirements.txt` 另加 **PySocks**——仅 socks 路径需要，http/https 不需要）。**行为等价**：404 → `None`（文件不存在＝正常态：未上市/未到账/停牌），其余 4xx/5xx → 抛 `requests.HTTPError`。`http(s)` 是 requests 原生，`socks*` 经 PySocks；两路走**同一个 map** `{"http": url, "https": url}`。
- **⭐ scheme 词表＝{`socks5h`、`socks5`、`http`、`https`}（威廉姆 2026-10-06 裁定不锁死 SOCKS）**：
  - `http://` / `https://`：requests **原生支持**，`proxies={'http': url, 'https': url}` 直用，无需 PySocks。
  - `socks5h://` / `socks5://`：经 **PySocks** 挂 requests。
  - **DNS 解析语义才是硬约束（约束的是语义，不是 scheme 名字）**：`socks5h` 与 `http(s)` 代理**都在代理侧解析目标域名**——http 代理对 https 目标走 `CONNECT host:port`、对 http 目标直接转发绝对 URI，两路都代理解析；**唯 `socks5://`（无 `h`）在本地解析**，遇被污染域名必死。故 prod 上 OKX（域名被污染到 169.254.0.2）**必须用 `socks5h://` 或 `http(s)://`，不得用 `socks5://`**。
  - **表层不硬性拒绝 `socks5://`**（本地 DNS 可用的内网场景合法），由 UI 提示（池列表 `local_dns` 标记） + probe 实测把关——不在 DDL 里武断封杀一个个例。
  - **校验要求**：scheme ∈ 词表 ∧ 有 host ∧ **有显式端口**（代理无端口＝配置残废，缺省端口在不同代理实现上不一致，宁可让运维写明确）。
  - **`https://` 代理的落地注意**：`https://` 作为代理 DSN＝代理链路本身走 TLS；其支持度取决于 urllib3 版本。验收以**真机 probe** 为准；若该版本不支持则回落 `http://`（同端口通常 http/socks 双协议）。
- **端点配置化**：binance adapter 的 `_BATCH`（K 线批量站）、okx 将用的 `www.okx.com`、tushare api
  一律「**代码缺省 + `endpoint_override` 覆盖**」——缺省保证零配置可跑，覆盖应对换域名/换区域。
  **覆盖只作用于 K 线下载基址**；符号枚举走 Amazon S3 的固定入口（`_S3`）**不随覆盖**——换 S3 区域是另一维，挂账待真实需求。

### 3.5 UI / API / 权限

- **UI 落位＝集成中心新增「代理出口」页签**（**不是**设置页）：域上它是数据源/交易账号的**下游配置**（先有源，才轮到给这个源配出口），与 `DataSources`/`TradingAccounts` 同页签族、同 `system_config` 权限门。
  - 两块表：**代理池**（名称 / 掩码地址 / DNS 解析侧标记 / 状态 / 测连通·编辑·删除）＋**按消费方绑定**（消费方 / 启用开关 / 选用代理下拉 / 端点覆盖 / 保存·清除）。
  - 绑定表**行集合＝后端 `capable_consumers()` 派生**（＝ adapter 类声明了 `supports_exit_config`）⇒ 102b 接 OKX 后前端**零改动**自动长出 okx 行，**不硬编码 provider 名单**。已绑定但已不可配的消费方也会列出（防「配了却看不见」）。

  | 方法 | 路径 | 语义 |
  |---|---|---|
  | GET | `/api/proxies` | 池列表（url 掩码）+ `capable_consumers` |
  | POST | `/api/proxies` | 新增/更新一行（`url` 空=不改） |
  | DELETE | `/api/proxies/{name}` | 删一行（被启用绑定引用 ⇒ 409 `PROXY_IN_USE`） |
  | GET | `/api/proxies/capable-consumers` | 可配代理的消费方 |

- **URL 掩码**：只替 userinfo 段（scheme/host/port 原样）：`socks5h://***@host:port` / `http://***@host:port`，与凭证掩码同模式。`probe` 是唯一用未掩码 DSN 的路径，且**不回显 DSN**。
- **权限**：复用配置面既有键（读 `read` / 写 `system_config`），**不新增 perm 键**——避免「新 perm 键四条齐动」（API_PERM_KEYS / PERMISSIONS / seed 迁移 / 前端 permGroups）的连锁。写操作进 `audit_log`。

### 5.1 为什么分两步（试用窗口的定位级约束）

试用窗口＝**绝对值 `2025-06-28 ~ 2026-07-05`**（含前 15 个月、**不含最近 3 个月**）。⇒ 聚宽
**不能**充当 `astock_daily` 的常规替代源：一旦运维把该行 provider 切到聚宽，**最近 3 个月将无人
回补**，数据从「昨日」倒退到「3 个月前」，且是误切造成、不易察觉。故：

- **B 步（已完成）**：以**独立 sync_id** `astock_daily_jq` 承接历史行情回补，**不抢**
  `astock_daily` 的切换位（两行互不相扰）。
- **A 步（待排）**：把**非 bar 项**（`ref_data` 的 `astock_list` 等）打通到 adapter 接口，
  成为首个「非 bar 多源」样板（见 §5.2）。

**「聚宽进 UI」已由 B 步达成**（能力非空 ⇒ 过目录双门），A 步不再承担可见性职责。

### 5.2 A 步：参考数据（ref_data）— 未做，阻塞点已定性

计划：`capabilities` 并入 `astock_list`（经 `SYNC_ID_CAP_MAP` 归一为 `ref_data`），
实现 `get_all_securities(types=['stock'])` → 落 `asset_static_info`。

**真阻塞（批 103b 取证，推翻「A 步最快」原判）**：`_sync_astock_list` 等 ~15 个非 bar 项走
`_get_pro(prov).stock_basic()` —— ① `_get_pro` 返回**源客户端对象**而非 adapter；② handler 的
调用语汇是 **tushare 的**（`pro.*`）。故非 bar 项**结构上 tushare 独占**；给聚宽声明 `astock_list`
后真切会抛 `ProviderConfigError`（**响亮**失败，非静默串源——three-registry law 有效），
即「清单有·实现无」家族。⇒ A 步要先**扩插件边界**（让某非 bar 项走 adapter 接口），
不是加一行 capabilities 的事。

### 5.3 B 步：历史行情（hist_quote）— 独立 sync_id（**已实现**）

- 新 sync_id `astock_daily_jq`；`SYNC_ID_CAP_MAP["astock_daily_jq"]="hist_quote"`；
  ∈ `JoinQuantAdapter.capabilities`。配置行由迁移 **0133** 落（`sync_config` + `sync_kind_config`）。
- **窗口语义 = 动态取 + 自夹**（修正原「上界滞后公式」）：窗口是 `get_account_info()` 给的
  **绝对区间**（非 `今日−15月~今日−3月` 滚动公式），handler 每次启动解析一次并**自夹 start/end**
  —— SDK 的边界检查**只查 `end_date`**，不夹 start ＝ 单次请求静默拉回全史（额度炸弹）。
- 落 `bar_1d`；A 股 symbol 无源后缀 ⇒ 与 tushare 行**同键**（`(symbol,ts)` upsert）。
  语义可接受（威廉姆：「A 股各源是复制同一份数据」；同键 16 组实证 OHLCV **逐位相同**），
  且健康面可见 `source` 归属（互写后为 `joinquant`）。

### 5.4 字段映射与语义（2026-10-06 实测 API 形状）

- `get_price(security, start_date, end_date, frequency='daily', fields=["open","close","high","low","volume","money"], fq=None, panel=False, skip_paused=True)`：
  **`fq`/`panel`/`skip_paused` 三个都必须显式传**——默认 `fq='pre'` 会改价（破坏「未复权价」契约）；
  `panel=True` 是已废弃的 Panel 返回。
- **不取 `factor`**：`fq=None` 下 `factor` 恒 1.0（占位非因子）；JQ 因子虽正确但与 tushare
  **归一化锚点不同**（比值逐标的恒定）⇒ 采取「不声明 / 不提供」，由既有 `backfill_adj_factor`
  （tushare 独有通道）+ 落库 `COALESCE` 兜底（**零代码改动**）。
- **单位：不换算**（修正原「÷100」）。内部 `bar_1d.volume`=**股**、`amount`=**元**；聚宽 `volume`
  =股、`money`=元 ⇒ 同单位直落（同键 16 组实证：OHLCV 逐位相同，`amount` 仅上游四舍五入 <1 元）。
- 形状**按入参分叉**：单标的 = DatetimeIndex（无 `code` 列）；多标的 = `time`/`code` 列平面表。
- 符号：聚宽 `000001.XSHE ↔ 000001.SZSE`、`600000.XSHG ↔ 600000.SHSE`（覆写 `to_source_symbol`）。
- **不覆盖北交所**（聚宽仅 XSHE+XSHG）：发请求前剔除 `.BJ`；且 jqdatasdk 对含无效标的的批次
  **整批拒绝** ⇒ 单批失败必须**二分降级**隔离坏标的（否则一只坏标的丢整批 = 静默数据洞）。
- **auth 门**：jqdatasdk **所有**调用（含纯本地的 `normalize_code`）前置 `auth` ⇒ 每任务先 auth；
  缺凭证**响亮抛 `ProviderConfigError`**（静默回落 tushare ＝ 串源）。

### 5.5 资源约束（试用规则 → 硬契约，含实测修正）

- 每日 **100 万条**，**按返回行数计**（非调用次数）⇒ 间隔制限速表对本源无意义
  （`DEFAULT_RATE_LIMITS={}`）；**行预算**（`spare − 50k 余量`）下沉 handler，逐交易日推进、近预算即止。
  全窗口 ≈ 138 万行 ⇒ 需分 2 天跑完。
- **连接数 = 1** ⇒ **provider 级互斥锁**（跨 sync_id 串行 auth；per-sync_id 锁不够）。
- 账号 **3 个月有效期**（`get_account_info` 实测 `expire_time`）⇒ 过期＝**可见停红**，禁静默失败。

### 5.6 验收（与实证结果）

- **B 步（已完成）**：能力非空且 ⊆ `DOMAIN_CAPS[data_source]`；`astock_daily` 的切换位
  **不含**聚宽（反污染钉）；迁移 0133 离线渲染完整 + dev 真库往返幂等；
  **dev 端到端实证**：行总数不变（纯原地 upsert）、OHLCV 与 tushare 逐位相同、`adj_factor` 逐位保住、
  `source` 翻转、二次跑幂等。
- **A 步（待做）**：`provider_capabilities('joinquant')` 增 `ref_data`；某非 bar 项真走 adapter
  接口（首个「非 bar 多源」样板）；切到聚宽后拉数不再抛 `ProviderConfigError`。
