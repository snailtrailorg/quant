## 一、目标与结果

**目标**：加一个受风控、可审计、异步回执的**手动限价买卖接口**，操作员指定「账号+标的+方向+数量+价格」下真实委托，用于建仓/减仓/验证链路。

**结果**：`POST /api/manual-order`（perm=`trade`）与 `GET /api/manual-order/{req_id}` 已上线；当日 10 只标的建仓完成（详见 §六）。首版只做实盘账号 A 股限价单，一次请求一笔。

## 二、根约束（为什么不能在 Web 层直接下单）

TD 会话随 per-account runner 进程（`quant-live-task@{tid}`）存活，web-api 无 TD 会话。web 内联建会话＝同账号第二会话，与 172d「同账号不得混跑」冲突，且绕过 `_closing` Gate 会与主循环行情链并发写 adapter。

> **决策 D0**：手动单走「web 下发命令键 → 该账号活 runner 内执行」异步链，与 `cancel-all`/`close-all` 同通道；web 层只做参数校验 + 鉴权 + 下发，零 SQL、零 adapter、零 TD。

## 四、接口契约

```
POST /api/manual-order          perm=trade（Depends 包裹）
body: {account_id:int, symbol:str, action:"BUY"|"SELL", volume:int(100 倍数,≤100000),
       price:float(>0), confirm:"CONFIRM", client_order_id?:str}
→ 200 {status:"accepted"|"rejected", req_id, tid, ...result}
→ 202 {status:"dispatched", req_id, tid}
→ 400 参数非法 / confirm 缺失 / 重复 cid
→ 403 PERM_DENIED / 409 MANUAL_NO_ACTIVE_RUNNER（无活 runner，命令未下发）

GET /api/manual-order/{req_id}  perm=trade → {status:"pending"}|{status:"done",...}
```

命令键 `risk:cmd:{tid}` 值：`{id,verb:"manual-order",operator,operator_uid,ts,order:{symbol,action,volume,price,order_type:"limit",client_order_id}}`。

**读写表**：`order_log`（INSERT `submitting` + `write_order_status` 终态回写，`client_order_id` 唯一）、`risk_log`（`check_order` 出口）、`audit_log`（三态）、`trade_log`（既有回报链）。**不建表、不加迁移**。

## 五、执行链

```
Web：参数校验 → _live_runners(accounts=[id])（空→409）→ 写命令键 → 5s 回执窗
Runner（EmergencyWorker）：_closing.set() → submit_manual_order → _closing.clear() → 写主回执
submit_manual_order：
  SELL 可卖截断（query_position 的 volume-frozen，T+1）→ check_order（拒即回）
  → manual_order_open 落 WAL → adapter.send_order → _close_order_mark(submitted/send_failed)
```

`send_order` 返 `None` 或抛异常都记 `send_failed` 且回 `accepted:false`，不虚报成功（171s 审 C P0）。
