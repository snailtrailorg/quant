## 一、目标与边界

**目标**：给平台加一个受风控、可审计、异步回执的**手动限价买卖接口**，让操作员在 Web 上指定「账号 + 标的 + 方向 + 数量 + 价格」下真实委托；用于建仓、减仓、验证链路，不替代策略自动交易。

**成功标准**：① 单笔委托从 Web 发出后落到券商，`order_log` 有完整一行且终态可回写；② 每一笔都过 `RiskControl.check_order`（拒单可见、留 `risk_log`）；③ 无活动 runner / 熔断 / 越权 / 参数非法时明确拒绝，不静默丢单；④ 新增端点通过三条架构守门。

**范围**：首版只做**实盘账号的 A 股限价单**，一次请求一笔；不做市价、撤单、改单、组合单、批量单、paper 手动单、加密合约。

## 三、根约束：为什么不能在 Web 层直接下单

TD 会话随 runner 进程存活（§二-2）。web-api 若自己 `build` 一个 adapter 发单，等于**同账号第二会话**——与 172d「同账号不得混跑（唯一索引 + 审计列）」冲突，且绕过 `_closing` Gate 会与主循环行情链并发写 adapter。因此：

> **决策 D0**：手动单必须走「web 下发命令键 → 该账号活 runner 内执行」的异步链，与 `cancel-all`/`close-all` 同通道；web 层只做参数校验 + 鉴权 + 下发，零 SQL、零 adapter、零 TD。

## 四、架构决策

| 编号 | 决策 | 理由 / 反例 |
|---|---|---|
| D1 | 复用 `risk:cmd:{tid}` 通道，新增 `verb="manual-order"`；不新建第二套命令键 | 现成 GETDEL 幂等单消费 + 5s 回执窗 + audit_log 三态；新键＝第二套轮询钩子，双真源 |
| D2 | 执行链**必须**经 `RiskControl.check_order(order, account_id)`，禁旁路直调 `send_order` | §二-4；旁路＝熔断/开关/权限/资金门全失效，`risk_log` 无痕 |
| D3 | 复用 `_closing` Gate（**短窗**，单笔发单 <100ms 即清位），不新建线程 | `EmergencyWorker` 已覆盖具名钩子链 + `process_batch` 行情链；手动单也是 adapter 写，置位期间零竞态。窗口极短，快照钩子跳过 1 拍可接受 |
| D4 | **不写 `:final`、不发 SSE 终局帧** | `_final` 仅 `close-all` 语义（`hub_worker.py:263`）；否则 `close-result/recent` 的 scan 兜底会把手动单当急停清单上屏（171s P2-b）。手动单终态真源＝`order_log` + `/api/orders`（现成） |
| D5 | 权限键复用 `trade`（`require_perm("trade")`），**首版不加新键** | 加键要补 `permission` 表行 + `perm_resource` + PermMatrix + i18n 三区 + 白名单，爆炸半径大；`market_op`／实盘开关仍由 `check_order` 逐单卡口 |
| D6 | 独立新路由文件 `routes/manual_order.py`（白名单外） | `test_no_sql_in_new_routes.py` 对白名单外新文件禁 `get_conn`/SQL；该文件纯校验 + `business_redis` 下发，天然零 SQL，比往 `trading.py`（基线 28）加端点更干净 |
| D7 | `order_type` 固定 `limit`，**禁市价** | 171n 实证市价 `price=0` 必被 XTP 拒 `INVALID_PRICE`；手动单由操作员显式给价 |
| D8 | 不带 `strategy_id`；`reason="manual_order"`；`operator` 由 auth payload 服务端钉死 | 豁免 `max_trades_per_day`（急停同款）；操作者不可由客户端伪造 |

## 五、接口契约（自包含）

### 5.1 HTTP

```
POST /api/manual-order          perm=trade（Depends 包裹）
body: {
  "account_id": int,            # 必填，交易域账号 id
  "symbol": str,                # 必填，项目口径如 600000.SSE；服务端归一 to_vt_symbol
  "action": "BUY" | "SELL",     # 必填
  "volume": int,                # 必填，正整数；A 股须 100 整数倍，≤ 100000
  "price": float,               # 必填，>0；限价
  "confirm": "CONFIRM",         # 必填，防误触（同 close-all）
  "client_order_id": str?       # 可选幂等键；不传则服务端生成 mo-{req_id}-{sym}
}
→ 200 {status:"accepted", req_id, tid, client_order_id, vt_orderid?}
→ 202 {status:"dispatched", req_id, tid}          # 已下发未回执
→ 400 {detail, code} 参数非法 / 账号不在 running 集 / confirm 缺失
→ 403 PERM_DENIED / 409 MANUAL_NO_ACTIVE_RUNNER（无活 runner，命令未下发）

GET /api/manual-order/{req_id}  perm=trade
→ {status:"pending"} | {status:"done", result:{...}}   # 读 risk:cmd:result:{req_id}
```

错误码统一 `ApiError(status, CODE, 中文兜底)` → `{detail, code}`；前端 `apiErr(e)` 加 `err.<CODE>` 三区词条（CLAUDE.md 铁律）。

### 5.2 命令键（web → runner）

`risk:cmd:{tid}` 值 JSON（在既有 `{id,verb,operator,ts,operator_uid}` 上**增一个 `order` 子对象**）：

```json
{"id":"<req_id>","verb":"manual-order","operator":"<username>","ts":<epoch>,
 "operator_uid":<int|null>,
 "order":{"symbol":"600000.SSE","action":"BUY","volume":500,"price":10.38,
          "order_type":"limit","client_order_id":"mo-..."}}
```

`consume_risk_cmd` 的投递 item 相应增 `order` 字段（当前 `hub_worker.py:79-85` 为 5 字段白名单）；**未带 `order` 的 `manual-order` 命令按非法丢弃并 `logger.warning` 留痕**（禁静默 no-op，171 纪律）。

### 5.3 worker 侧 order dict（喂 `check_order`）

```python
{"symbol": sym, "action": action, "volume": qty, "price": px,
 "reason": "manual_order", "operator": operator, "account_id": account_id}
# 有意不带 strategy_id（豁免日内频次）
```

### 5.4 读写表

| 表 | 动作 | 关键列 |
|---|---|---|
| `order_log` | INSERT 1 行（submitting）后由 `write_order_status` 回写终态 | `client_order_id`(唯一)、`vt_orderid`、`symbol`、`action`、`volume`、`price`、`status`、`strategy_id=NULL`、`account_id`、`operator`、`error` |
| `risk_log` | `check_order` 出口自动 INSERT | `action/rule/detail/severity` |
| `audit_log` | web 侧三态分别 INSERT | `actor=username`、`action="manual_order"`、`detail=参数摘要` |
| `trade_log` | 成交回报由既有 `write_trade_log` 落 | 现成链，零改动 |
| `live_task` / `quant:hb:task:{tid}` | 只读（枚举活 runner） | `config_store.live_running_tasks()` 现成 |

**不建表、不加迁移**（复用 `order_log` 全部列）。

## 六、执行链与时序

```
Web  POST /api/manual-order
  1) 参数校验（纯内存，零 SQL）+ require_perm("trade")
  2) account_id ∈ live_running_tasks() 且心跳新鲜（复用 _live_runners(accounts=[id])）
     └ 空 → 409 MANUAL_NO_ACTIVE_RUNNER（命令未下发，audit_log 落痕）
  3) audit_log；写 risk:cmd:{tid}（ex=10min，同 _dispatch_risk_cmd）
  4) 5s 窗轮询 risk:cmd:result:{req_id}；窗内回执 → 200，逾窗 → 202

Runner（EmergencyWorker 线程）
  5) consume_risk_cmd GETDEL → item 带 order → _handle("manual-order")
  6) _closing.set()（短窗，D3）→ submit_manual_order(...) → _closing.clear()
  7) 写主回执 risk:cmd:result:{req_id}（write_cmd_result，final=False）；不写 :final / 不发 SSE

submit_manual_order(adapter, account_id, operator, req_id, order) -> dict
  a) SELL 可卖截断：query_position() 取该 symbol `volume - frozen`（T+1 冻结口径，
     同 _close_all_positions:592-594 / strategy.place_order:453-462）；sellable=0 → 拒
  b) order dict（§5.3）→ rc.check_order(order, account_id=account_id)
     └ 拒 → 回执 {accepted:false, reason:d.reason}；不落 order_log
  c) 预生成 cid（mo-{req_id}-{sym}）→ INSERT order_log(submitting)（fail-closed：
     写库失败即放弃下单，F-4 时序铁律）
  d) adapter.send_order(Order(symbol,action,volume,price,order_type="limit",client_id=cid))
     └ 返 None → 标 send_failed、回执 not-sent，不虚报成功（§二-6）
  e) get_vt_orderid(cid) 回填；终态由既有 write_order_status 两路认领
  f) 回执 {accepted, client_order_id, vt_orderid, reason}
```

**并发**：`_closing` 期间 `process_batch` 只 xack 不驱动策略、`snapshot`/`halt-edge` 跳过、心跳仍写（`hub_worker.py:998-1009`）——单笔窗口极短，bar 由暖机/gap 补，无新增竞态面。

## 七、审计与幂等

- **幂等**：`client_order_id` 服务端预生成或客户端传入，`ux_order_log_client_oid` 全局唯一兜底；同 `client_order_id` 重复提交 → 400（或返回原单，二选一，任务文件钉）。
- **三态留痕**：409 / 202 / 200 分别 `audit_log`（同 `_dispatch_risk_cmd`）。
- **拒单可见**：`check_order` 出口统一落 `risk_log`；手动单不得绕过（D2）。
- **不虚报**：`send_order` 返 None、`order_log` 写失败、`check_order` 拒，三种都回 `accepted:false` + 原因。
- **operator 服务端钉死**：从 auth payload `username`/`sub` 取，客户端不可传。

## 十、风险与不做的事

- **三级开关缺口**：手动单无策略，`enabled`/`backtest_verified` 第三级不适用；首版只受总闸 + Web 分项（`check_order` 第 2 步）。是否补"手动交易总开关"见 §十一-4。
- **快照 fail-closed**：`_get_global_state` 300s 陈旧会连平仓单一起拒（2026-11-13 实证）；手动单同样依赖快照新鲜，**不改风控**（属既有行为）。
- **熔断**：`halted=True` 时 BUY 被拒、SELL 经 `is_flat_or_reduce` 放行；手动单不绕过。
- **T+1**：当日买入不可卖，SELL 截断到 `volume-frozen`（§六-a）。
- **不做**：市价单、撤/改单、组合/批量单、paper 手动单、加密合约、无常驻 runner 时临时建 TD 会话、新增权限键、新增迁移、改 hub/TD 进程模型、写 `:final`/SSE 终局、绕过 `check_order`。
- **上产纪律**：交易日 15:05 后部署窗，staging 彩排绿先行；命令一律落文件（见 `deploy/DEPLOY.md` 速查节）。
