## 3. 领域模型与判定引擎（v2 重排）

### 3.1 台账行（security_component 扩列，迁移 **0163**——已核空号）


全列 nullable（审B-M6b：rollback 后旧代码 UPSERT 兼容）；NULL 展示语义=unknown（API 层映射，非 SQL 兜底）。

### 3.2 judge 纯函数（归层：quant_common/depjudge.py——零业务依赖纯函数层；os_pkg 常量在 health_monitor，**judge 不 import os_pkg**，审A-B1）

```python
def judge(cur: str, constraint: str | None, latest: str | None,
          in_constraint_max: str | None, requires_python_ok: bool,
          managed_by: str) -> tuple[str, str]:
    """返回 (judge_class, judge_why)。全 str 入参（序列化友好）；异常内部捕获→(unknown,why)。
    in_constraint_max：采集侧预计算的「constraint 内 >cur 的最高非 yanked 版」（无约束/无候选=None）——
    判定零外部命令，7b 数据流自洽（裁定审修复）。"""
```

**规则序（v2——cur 漂移检查前置、比较先于 pinned、无约束显式）：**

```
 1. managed_by=local      → unreachable("本地构建 fork，不与上游比较")
 2. managed_by=none       → unknown("无版本坐标")
 3. cur 不满足 constraint → drift("环境与 requirements 漂移：装 {cur}，约束 {constraint}")   # 审B-H2b；先于 latest 缺——drift 判定不依赖上游（裁定审附注）
 4. latest 缺             → unknown("上游不可达或未登记")
 5. requires_python 不满足→ unreachable("上游需 pyX.Y+")
 6. latest ≤ cur（PEP440）→ current("")
7a. latest>cur 且 latest⊆constraint → actionable("可升级 {cur}→{latest}")
7b. latest>cur 且 latest⊄constraint →
      in_constraint_max 存在 → in_constraint("约束内可升至 {v}；上游 {latest} 受界 {constraint} 挡")
      否则                   → pinned("受上界 {constraint} 策略保持；上游 {latest} 不可达")
```

- **local 先分类后查询（审B-H1 立法）**：采集侧完成 direct_url 检测**之前**不得发起该包 PyPI 请求——local 包零上游请求，规则 1 恒先于任何比较（PEP440 local 段==陷阱根除）。
- **无约束包（审A-B3）**：constraint=None 视作「无上界」——7a 直判 actionable；judge_why 注明「未在 requirements 声明（传递依赖或漏声明）」，同时在 audit errors 面板单列「未声明包 N 个」提示补声明。
- **7b 约束内目标版 v 的取法**：PyPI JSON 一次拉全版本列表（releases 键）成本可控（单包一次请求内含），`packaging` 过滤 constraint 内 max——数据缺口消除（审B-H2 附注），不引入第二次 API 形态。
- **yanked（审B-M1）**：解析 releases 时跳过 yanked 文件对应的版本；全 yanked→回退最近非 yanked；无→unknown(why=yanked)。

### 3.3 约束快照（跨进程，审A-B2）

约束真源=requirements.txt+requirements-dev.txt（packaging.requirements 解析）。**每轮 audit 解析后整体落入缓存契约 constraints 段**（判定只用缓存内快照，不读文件）——05:00 与 06:00 进程解耦，判定可复现，judge_why 引用的 constraint 与当时一致。dev 名单同段落 group=dev。

## 4. 采集与数据流

```
dep_audit（beat 05:00；soft_time_limit=900；幂等可重入）
 ①pip 现状：importlib.metadata.distributions() 全枚举 + direct_url.json 存在→managed_by=local
    （解释器=sys.executable——与扫描同 venv，双 venv 漂移在 E2E 钉中校验 paths 一致）
 ②pip 上游：PyPI JSON /pypi/{name}/json 并发 8（端点=PYPI_INDEX env 可配镜像，默认 tuna——与安装同源，审A-H4）
    30s/包超时；429 退避重试 2（1s/5s）；**错误率>20% 或 pip 段全失败 → ok=false**（审B-M4）
 ③OS：detect_provider()（which('dnf')/which('apt-get') 命令存在性优先，os-release ID 兜底，审B-L1）
    RpmDnf.list_installed: rpm -qa --qf '%{NAME}\t%{EPOCH}\t%{VERSION}\t%{RELEASE}\n'（一次全量，epoch 不丢，审A-H5）
    RpmDnf.upgrade_set: dnf -q repoquery --upgrades --qf（一次=全量可升级集；enabled repos 口径写死）
    DpkgApt.list_installed: dpkg-query -W -f='${Package}\t${Version}\n'（结构化，禁 apt-get -s 文本解析——审A-H6）
    DpkgApt.upgrade_set: apt-get -s upgrade -o Format=json（apt≥2.7 支持；不支持→provider 降级只报现状，latest 缺→unknown，不猜）
    Unsupported: 空集+reason；采集侧强制 degraded
 ⑤缓存契约（Valkey sec:dep_audit）
security_scan(06:00 零外部命令)：读契约→schema/fresh 校验→judge 逐行→台账 UPSERT→快照汇总
```

### 4.1 缓存契约 v1（补齐判定复现字段）

```json
{
  "schema_version": 1, "ts": "Z", "ok": true,
  "errors": [], "constraints": {"pandas": "<3.0", "...": "..."}, "dev": ["ruff", ...],
  "pip": [{"name","cur","latest","in_constraint_max","requires_python","local":false,"group":"runtime"}],
  "os": {"pkg_mgr":"dnf", "installed_n":690,
        "upgrades": {"openssl":"1:1.1.1k-15.el8"}, "latest": {"python3.11":"3.11.13-4.el8"}}
}
```
- ok 语义：pip+os 采集主链成功且错误率≤20%；fresh 线 **30h 单常量**（quant_common/depjudge.py 旁 DEP_AUDIT_FRESH_H，全仓唯一定义，扫描/rescan/前端全读它——B1 根除）
- 三态（审B-M3）：无缓存→degraded「缺失」；ts 过期→degraded「过期」；**audit 进行中（celery active 查询）→旧缓存正常服务+页面标「采集中」**；ok=false 且 fresh→不告警（预期自愈），连续两轮 false→电平告警
- run 世代（审A-U4）：契约带 run_id（utc 时间戳即可），后写覆盖，无新旧歧义

### 4.2 版本源与比较立法：禁人类文本

| 面 | 允许 | 禁止 |
|---|---|---|
| pip 现状 | importlib.metadata | freeze 解析 |
| pip 上游 | PyPI JSON（镜像可配） | pip list --outdated（降级通道保留） |
| OS 现状 | rpm -q --qf（含 EPOCH）/dpkg-query -W -f | *-version 文本 |
| OS 上游 | repoquery --upgrades / apt json | 单包 repoquery max |
| pip 比较 | packaging.version（PEP440；yanked 过滤） | 手写元组 |
| OS 比较 | evr 字典序元组（epoch:int, version, release 逐段 rpm 字母数字序，审B-M5） | PEP440 套 OS 侧 |

OS 判定调用：constraint 恒 None、走 3.2 规则（无 4/7b 分支）；upgrades 集与 latest 取 max 交叉验证不一致时记 error 用 latest。

### 4.3 持久化与滞留

UPSERT 键 (source,name)（B-L2）；version 变推 last_changed；latest/judge/checked_at 每轮覆盖。**滞留天数=今日-last_changed（日期差，B-M9）**。690 行 executemany（D18 规范）。历史=快照 jsonb 汇总+台账现状（两制既有分工）。

### 4.4 API/前端/告警（v2.1 用户裁定：筛选优先、去彩色）

- API：组件行直读台账（+managed_by/latest_version/judge_class/judge_why/stale_days/**has_update**）；汇总 `dep_health:{actionable,in_constraint,pinned,drift,unreachable,unknown,dev_n,checked_at,fresh,pkg_mgr}`；旧字段 outdated[]/n_outdated 保留一个发布周期（deprecate）
- **has_update 派生**（服务端单源）：judge_class ∈ {actionable, in_constraint} → 是；其余（current/pinned/unreachable/unknown/drift）→ 否；NULL → 空。**用户裁定：加列「是否有更新版本：是/否」并进筛选条件；取消一切颜色标示（橙黄/灰全撤）**——分类靠是/否筛选，不靠色觉
- 前端：D 区列=名称/来源/受管通道/当前版本/最新版本/「是否有更新版本(是/否)」/滞留天数；**该列加入既有 RowFilter 筛选组（是/否/全部三档）**；judge_class 细类与 why 进该列 tooltip（hover 可见七分类细节）；A 区卡数值不带色；扫描时间信息由**既有扫描状态卡承载**（采集时刻并入其小字，不新增卡片）；OS 690 行默认按 has_update 分组折叠（「有更新 N · 无 M」点开展开）；dev 组独立折叠
- 告警（电平）：actionable>阈值(默认20)首次 或 0→N 跳变——聚合一条含 checked_at 与样本 5；drift>0 告一条；过期→degraded 告警；pinned/in_constraint/unreachable/unknown 永不告
- rescan 契约（审A-H7）：手动 rescan 仅触发 security_scan 本体；**缓存 fresh 则用之，stale 则顺带 async 派 dep_audit**（同今晚已上产行为），页面显示「采集中」

### 4.4b 执行可靠性与幂等（v2.1 用户立法：所有设计必须可靠执行且幂等）

- **dep_audit 幂等**：无锁竞争（beat 单源 05:00+rescan 派发撞 beat 的窗口内，任务开头读缓存 run_id≥自身则直接退出——后写胜，重入安全）；输出为纯函数式快照（同输入同输出，重跑不产生中间态）；PyPI 逐包独立（单包失败不污染他行）；写缓存原子 SET（Valkey 单键覆盖，无部分写）
- **scan 幂等**：读缓存→judge（纯函数）→UPSERT 键 (source,name)——同日复跑覆盖刷新（scan_date unique 既有语义）；无副作用残留（无 delete-then-insert，无中间表）
- **台账 UPSERT 幂等**：version 变推 last_changed 不变不推；判定列每轮幂等覆盖；checked_at 单调取 max（防时钟回拨回退）
- **迁移幂等**：0163 expand-only，IF NOT EXISTS 语义（alembic 重复执行安全）；downgrade 对称 drop
- **rescan 幂等**：重复点击=重复派 scan（同 scan_date 覆盖），无重复行/重复告警（电平告警天然去重）
- **判定可复现**：约束快照+全部入参落缓存契约，任意时刻重放 judge 结果一致（§3.3）

## 5. 失败模式矩阵（v2 全 12 行）

| 故障 | 行为 | 用户可见 |
|---|---|---|
| beat 未触发 | 无缓存→degraded+告警 | 「依赖审计数据缺失」 |
| audit 崩溃/被 kill（soft 900s） | 旧缓存服务+journal failed | 06:00 扫描用旧值，「采集中」消失后正常 |
| audit 进行中 | celery active 探测 | 旧缓存+页面「采集中」角标 |
| PyPI 限流批量 429 | 退避重试→仍败计入 errors | >20%→ok=false；fresh 不告警，连续两轮才告 |
| PyPI 单包 404/全 yanked | latest=None | unknown+why |
| Valkey 丢 | 同无缓存 | degraded |
| 镜像源同步延迟 | 与安装源同镜像（tuna） | 口径一致，不混源 |
| unsupported OS | degraded | 「无包管理器适配」 |
| 仓库无某包 | latest 缺 | unknown+why=仓库无坐标 |
| cur 违反约束 | drift | 橙红+即时告警 |
| judge 异常 | 该行 unknown | 灰+why=内部错误 |
| audit 与 scan 间隙手动触发失败 | run_id 覆盖语义 | 后写胜，无歧义 |
