# 批184 · 组件台账归一：source=域，pkg_mgr=实现

> 上游：`flow/方案/批183d-组件台账跨源键-评审.md`。
> 本文替代该方案初稿「system 合并进 rpm」的方向——那个方向把**实现**当成了**域**，
> apt 环境会被写死。正确方向见 §二。

## 一、先回答三个问题

**Q1：`system` 现在是抽象层吗？——不是，但抽象层已经存在，只是台账侧绕开了它。**

采集侧（`src/health_monitor/os_pkg.py`）早就有 provider 抽象：

```
detect_provider() → RpmDnf(id="dnf")   # rpm -qa + dnf repoquery --upgrades
                  → DpkgApt(id="apt")  # dpkg-query -W
                  → Unsupported(id="unsupported", reason=...)
接口：list_installed() / upgrade_candidates()
```

但台账写侧完全绕过它：
- `security_collector._os_up`：`("system", name, version, "OS rpm")` —— 源与 origin 写死 rpm；
- `tasks.py` SQL_OS：`source 'system'`、`origin 'OS rpm'` —— 同上；
- `security_collector` 418 行 8 个点名探针：直接 `_run(["rpm","-q",...])` ——
  **apt 环境里 `rpm` 不存在，8 个探针全失败**，这就是「转不动」的具体位置。

所以 `system` 目前是「dnf 判定产物专用源」＋「旧 8 点名的兜底」，两种临时目的拼在
一个值上，**不是抽象层**。

**Q2：如果 `system` 是抽象层，就不该有冲突——正确。**

冲突的本质不是「域」重名，而是**同一个 OS 包被写进了两个域**：
`system`（dnf 判定）与 `rpm`（grype SBOM 台账）各一行，版本与判定分别落在两行。
域层面 `tzdata` 只在 `pip` 与 `os` 各一行，天然不冲突。

**Q3：grype 必装 ⇒ 8 个点名探针的兜底理由消失。**

A07 原文给 `system` 的定位是「8 个点名组件——不依赖 grype，未装机期照常滚动」。
既然 grype 是必装件，这条理由不成立；而 schema2 的全量 OS 行已覆盖这些包的真实包名
（`python3.11`/`nginx`/`openssl`…），8 个**别名**（`python`/`postgres`）不是包名，
留着只会产生同名歧义。⇒ 探针代码与别名行一并删。

## 二、三维模型（正交，不互相冒充）

| 维度 | 回答什么 | 载体 | 值域 |
|---|---|---|---|
| **域** domain | 包属于哪个生态 | `security_component.source` | `pip` / `os` / `binary` |
| **实现** impl | OS 域由哪个包管理器纳管 | `security_component.pkg_mgr`（新列） | `dnf` / `apt`（非 os 域为 NULL） |
| **判定源** judged_by | latest/judge 从哪来 | `latest_source`（已有列） | `pypi` / `dnf` / `apt` / `none` |

唯一转换点（只此三处，禁止别处再推）：

| 上游 | 转换 | 下游 |
|---|---|---|
| SBOM artifact type | `python→pip`，`rpm→os`，`binary→binary` | `source` |
| `detect_provider().id` | `dnf→dnf`，`apt→apt` | `pkg_mgr` + `latest_source` |
| 契约 `os.pkg_mgr` | 同上 | 写侧同值 |

**换 apt 环境时改什么**：什么都不用改域——provider 返 `apt`，`source` 仍是 `os`，
`pkg_mgr=apt`，`origin` 由 provider 派生（`OS apt`）。台账/展示/GC 全不动。

## 三、冲突为什么消失（逐例）

| 实体 | 归一后 | 说明 |
|---|---|---|
| tzdata（PyPI 包） | `(pip, tzdata)` 2026.4 → 2026.6 | pip 生态，judged_by=pypi |
| tzdata（系统包） | `(os, tzdata)` 2026a | rpm 实体，pkg_mgr=dnf，judged_by=dnf |
| python3.11 | `(os, python3.11)` | 真实包名 |
| python（旧别名） | **删除** | 不是包名，是探针别名 |
| PySide6 捆绑库 | `(binary, libQt6Core.so…)` | A07 §「捆绑二进制库」 |

当前冗余：`(system,tzdata)` + `(rpm,tzdata)` 是**同一个** rpm 包的两行；
归一后只剩 `(os,tzdata)` 一行。这就是「system 是抽象层就没有冲突」的具体含义。

## 四、apt 环境推演（能转 / 不能转）

| 环节 | apt 下 |
|---|---|
| 采集已装包 | ✅ `DpkgApt.list_installed` → dpkg-query |
| 台账写入 | ✅ `source='os'`, `pkg_mgr='apt'`, `origin='OS apt'` |
| 判定 | ⚠️ `DpkgApt.upgrade_candidates()` 返回 `{}`（无结构化通道）⇒ 全部 OS 包 `unknown` |
| GC / 展示 / 快照 | ✅ 与实现无关 |
| 8 个点名探针 | ❌ 现状直接崩（`rpm` 不存在）→ 本方案删除 |

`upgrade_candidates` 的 apt 实现是**既有缺口**（os_pkg 里写死返回空，注释「无结构化通道：
latest 缺 → unknown（不猜）」），不是本方案引入，也不阻塞域模型；补齐路径单独立项：
`apt-cache policy` 结构化解析或读 `/var/lib/apt/lists`，产出 `{包名: 候选版本}`。

## 五、迁移 0189

1. **域归一**：`source IN ('rpm','system') → 'os'`；同名冲突（rpm 行与 system 行）合并：
   `version := system.version`（`rpm -q` 权威，apt 下即 `dpkg-query` 权威）、
   `latest*/judge_* := system.*`、`checked_at/last_seen := GREATEST`，删冗余行。
2. **删 8 别名行**（`python/nginx/openssl/postgres/redis/pango/cairo/wqy-microhei`）。
3. **加 `pkg_mgr` 列**并回填：读本机 `detect_provider().id`（迁移内不调外部命令，
   由部署后首轮 scan 覆写；迁移只给 `os` 行填 `'dnf'`？——**不猜**：迁移留 NULL，
   由首轮 scan 按契约 `os.pkg_mgr` 写入，NULL 期间展示为「未知实现」）。
4. **回填 `managed_by`**：pip→`pypi`、os→`repo`、binary→`none`；此后该列只读。
5. **CHECK**：`source IN ('pip','os','binary')`、`pkg_mgr IS NULL OR pkg_mgr IN ('dnf','apt')`。
6. **首轮横扫**：`last_seen < today-7` 三域各删一次（原 `os`/`binary` 无 GC），
   稳定后回 3 天。
7. `binary` 保持原名不改 `bundle`：改名收益低、要动 finding/前端/i18n，词表文档写明
   `binary = 随应用捆绑的原生库` 即可。

**dry-run 必产出两份清单**（迁移前贴日志人工核对）：同名 rpm/system 版本不同者；
仅 system 有而 SBOM 无者（命名差异如 `libcom_err`/`libcom-err`）。

## 七、验收（全部行为断言，不钉字面量）

1. `SELECT DISTINCT source` ⊆ `{pip, os, binary}`；无 `rpm`/`system` 残留。
2. `tzdata` 恰好两行：`(pip,tzdata)`、`(os,tzdata)`；后者 `pkg_mgr='dnf'`。
3. `(os,python3.11)` 存在、`(os,python)` 不存在。
4. 所有 `os` 行 `pkg_mgr = detect_provider().id`（真库断言）。
5. **provider 解耦测试**：monkeypatch `detect_provider` 返回 `DpkgApt()`，跑一轮写侧，
   断言 `source` 仍 `os`、`pkg_mgr='apt'`、`origin` 含 `apt`（证明域不随实现变）。
6. GC 三域各注入 `last_seen=old` 一行，全部被清（原 os/binary 不清理=回归点）。
7. 迁移 0189 在 scratch schema upgrade→downgrade→upgrade，行数与关键列等价。
