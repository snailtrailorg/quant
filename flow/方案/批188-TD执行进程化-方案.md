# 批188 · TD 执行进程化（交易执行与策略任务解耦）· 方案 v1

> 性质：架构级改造——把 TD 会话从"随 live_task 生灭"改为"按交易账号常驻独立进程"，
> 所有交易操作（策略单/撤单/清仓/手工单）经该进程的命令队列+回执统一承接。
> 依据：`D26`（账号级 hub 拓扑）、`D32`（插件 TD builder）、`D12 §2.11`（急停终态）、
> `risk.py`/`strategy.py`/`trading.py`/`hub_worker.py`/`main.py`/`scheduler`/`md_hub` 现状 + codegraph 实证调用图。
> 工作区：批187 已上产、干净；本方案独立开工。**待双盲审通过再编码**。

## 0. 立项背景与目标

**触发**：批187 上产后，prod 点"一键清仓"报 409"没有运行中的实盘任务"——不是 bug，是架构必然：
TD 会话绑在 `quant-live-task@<tid>` 进程（`main.py:397/568`），没有 running 任务就没有 TD 执行载体，
web 层无 TD 会话（批173 铁律），急停无法下发。用户裁定：把 TD 执行能力常驻化，与策略任务解耦。

**目标**：
1. 每个**交易账号**一个常驻独立 TD 执行进程 `quant-td-exec@<account_id>`，持有该账号 TD 会话（唯一连接）。
2. 所有交易操作经**命令队列+回执**统一由执行进程承接；策略任务退化为纯信号计算（形态 X）。
3. 风控收拢到**共同路径单次执行**（执行进程内 `check_order → WAL → send_order → 回执`），消灭双判定点。
4. TD 与行情账号解耦：下单价随命令带；清仓价读行情账号 hub 写的 tick 快照（td→quote 映射 + 持仓驱动订阅）。

## 4. 核心设计

### 4.1 TD 执行进程（systemd + SA4）

- 新单元 `quant-td-exec@.service`（参照 `quant-md-hub@.service`）：`Environment=ACCOUNT_ID=%i`，
  `ExecStart=run-current -m src.td_exec.main`，`WatchdogSec=90`，`Restart=on-failure`，
  `RestartPreventExitStatus=0 78`（优雅退出/配置错不重拉），`MemoryMax=1G`，`OnFailure=quant-task-failed@%n`。
- 进程启动：读 `trading_account` 行（`account_id=%i`）→ 复用 `td_registry.build_td_runtime(provider,...)` 建 TD 会话
  （xtp/emt），号段用**账号级固定号**（见 4.5）；成功后进入命令消费循环 + 喂狗。
- SA4 期望源（`scheduler/tasks.py:2035 _desired_units`）：新增第四源——`trading_account` 中
  `enabled=true` 且 `provider` 属 trading 能力域的行 → `quant-td-exec@{id}.service`（与 hub 源并列，
  同 provider 集合判定逻辑 `tasks.py:2062-2080`）。账号停用/删除 ⇒ 期望移除 ⇒ reconciler 停单元。
- **不兼容旧任务**：切换窗口内先停全部 `quant-live-task@`（清 live_task running 行），再起 td-exec；
  测试环境原子切换，不留双 TD 共存（防同账号双连接）。

### 4.2 命令通道（队列 + 回执，统一承接）

- 每账号一队列 `td:cmd:{account}`（Redis List，LPUSH/BRPOP 或 Stream consumer group——实施定，倾向 List+短轮询）；
  命令 = `{req_id, op: place|cancel|close|manual, order|params, signal_id, operator, operator_uid, account_id, ts, bar_fingerprint}`；
- 回执 `td:result:{req_id}`（TTL30min）= `{accepted, reason, client_id, order_row_id, vt_orderid, adjusted}`；
- 策略 `place_order`（形态 X）：算信号 → 写 `signal_log` 拿 `signal_id` → LPUSH 命令（带 signal_id+order 意图）→
  等回执（2s 超时，`wait_ack`）→ 拿 client_id 返回；**不再调 check_order/WAL/send_order**；
- 撤单/清仓/手工单：同样发命令到本账号队列（web/急停/手工来源统一）；
- 执行进程单线程串行消费命令（保证同账号 adapter 写归一线，零竞态——沿用 `EmergencyWorker` 线程模型，
  从"每 runner 线程"改为"每 td-exec 进程主线程"）。

### 4.3 共同路径单次风控（唯一咽喉）

执行进程内每条下单命令：`check_order(完整 order, account_id)` → 若 reject 发回执 rejected；
若 adjusted 用 adjusted 值 → WAL `order_log(submitting, adjusted, signal_id, bar_fingerprint)` →
`adapter.send_order` → 回填 vt_orderid/send_failed → 发回执。
- `check_order` 仍读 `risk:halted`/开关(PG)/规则(PG)/快照(PG)，不依赖策略进程；
- **策略侧删除 `check_order` 调用**（`strategy.py:463`）与本地 `order_log` 写入——`_log_signal_order` 拆为：
  策略只写 `signal_log`（`:550-555`），TD exec 写 `order_log`（`:556-562` 逻辑迁来），`signal_id` 关联；
- `risk_log` 每单一条（执行侧产出），审计不重复；
- 融断放行 `is_flat_or_reduce`（`risk.py:31`）不变——急停平仓单带 `reason=emergency_close_all` 放行。

### 4.4 WAL 时序与跨进程关联

- 策略进程：`signal_log` 先写（拿 `signal_id`）→ 发命令（带 signal_id）；
- 执行进程：`check_order`（拿 adjusted）→ `order_log(submitting, signal_id=命令带的)` → send_order → 回执带 order_row_id；
- 三账对账（signal_log/order_log/trade_log）靠 `signal_id` + `client_id` 关联，链不断；
- 崩溃窗口：命令已发但未写 order_log ⇒ 回执超时 ⇒ 策略侧记录"未确认"，靠 client_id 启动对账认领（沿用 F-4 机制）。

### 4.5 client_id 账号级号段

- 废 `runner_client_id(task_id)=(tid-1)%98+2`（`broker.py:128`）；
- 新 `td_exec_client_id(account_id)`：账号级固定号（2-99 区间按 account_id 映射），
  `order_prefix=f"a{account_id}:{boot_epoch}:"`（账号级 epoch），cid 全账号唯一；
- XTP 单账号单 TD 连接（独立进程保证），无多任务撞号；D26:68 的任务号段守卫退役。

### 4.6 td→quote 映射与清仓取价

- 新增映射 `td_account → quote_account`（写 `trading_account` 新列或 `system_config`，实施定）：
  默认同号（td==quote，兼容现状），解耦时显式配；
- 清仓取价：TD exec 读 `hub:latest_tick:{quote_account}:{vt}`（`hub_quote.py:39` 现成）；
- **订阅保证**：行情账号 hub 的 `_desired_symbols` 已含"持仓标的"（`md_hub/main.py:341`，171s 件六）——
  有持仓 ⇒ hub 订阅 ⇒ 有 tick（15s diff + 60s 重放窗内到位，平仓无限循环重试等到）；
  纯在途单撤单不需价（cancel_order 只吃 orderid）；
- 取不到价（no_tick/valkey_down）：平仓循环继续重试等订阅生效（批187 无限循环已实现），systemic 才终止。

### 4.7 急停判活适配

- `_dispatch_risk_cmd`（`risk.py:312`）判活从 `live_running_tasks()` 改为"目标账号 TD exec 在场"
  （Redis 键 `td:exec:{account}:alive` = up，进程启动写/优雅退出删）；
- 409 自然消失（常驻执行体永远在）；D12 §2.11 相应重写（判活=执行进程在场）；
- 命令目标从 `risk:cmd:{tid}`（任务维度）改为 `td:cmd:{account}`（账号维度）。

## 7. 一次上产与边界

- 六面同一次提交、同一次上产；禁止"先上执行进程、策略下一轮"——策略发命令与执行进程必须同版生效。
- **迁移原子性**：维护窗内 ①停全部 live_task（清 running 行）②部署含新单元 ③SA4 拉起 td-exec ④验证在场 → 开窗。
  测试环境不兼容旧任务，无双 TD 共存窗。
- 不做：改 D32 插件契约、改回测/paper（无 TD，路径不变）、改风控规则表、加密实盘（外部 gate 未开）。
- **风险兜底**：执行进程崩溃 ⇒ SA4 on-failure 重拉（30s）⇒ 命令队列消息不丢（Redis 持久）⇒ 重启后继续消费；
  下单未确认靠 client_id 启动对账认领（F-4 现成）。
- **判定单源**：风控一次（执行进程）、WAL 一次（执行进程）、号段一函数、映射一配置——禁第二真源。
- **制度符合性**：新增 systemd 单元进 SA4 期望源（非自创常开，不越权）；TD 连接走插件 builder（D32）；
  部署走 Ansible 管道（A06）；无新 sudoers/wrapper（执行进程 User=quant 不需特权）。
