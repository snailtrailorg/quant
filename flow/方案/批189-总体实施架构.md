## 1. 系统不变式（I1–I7）

> 形式：断言 + 违反判据。每条都必须能被一条测试或一条巡检命令证伪，否则不算不变式。

| # | 不变式 | 违反判据（可观测） | 落地 |
|---|---|---|---|
| I1 | **单一身份**：对外可观测的身份只有 `code`（DB PK/FK、unit、Redis 键、API、日志、UI） | 任一键/unit/接口出参出现数字接口 id；或同一接口在两处身份不同 | M1/M2 |
| I2 | **单一写入口**：接口三表与映射只经 `/api/{md,td}-interfaces`、`/api/data-sources` 写；进程对配置表只读 | 进程内出现接口表 INSERT/UPDATE（除心跳/租约） | M2/M3 |
| I3 | **键族唯一**：C4 是唯一键族；旧键（`quant:hb:md-hub:*`、`td:exec:*`、`hub:bars:{id}`）自 M1 起**不再写** | 迁移后仍出现旧键写入 | M1/M3 |
| I4 | **期望=载体**：进程存在 ⇔ 行存在 ∧ provider 声明该角色；`enabled` 不参与起停 | enabled 改动导致 unit 起停；或行存在但有载体却无进程 | M3 |
| I5 | **空转不占资源**：`enabled=false` 不建券商连接、不占 terminal、不订阅、不初始化 SDK | 停用接口仍有 `ss` 到券商端口 / slot 行 / 订阅 | M3 |
| I6 | **映射单源**：TD 取价与 MD 订阅反查都只经 `td_md_map` | 出现 `quote_account_id` 读取、`hub:latest_tick` SCAN、按 market 猜源 | M4/M5 |
| I7 | **失败响亮**：无载体 / 无映射 / 向空闲接口下发 → 明确错误码，不得 200 空成功或静默零结果 | 接口 200 但零命令；日志只有 warning 无状态 | M2/M3/M5 |

## 2. 模块边界与依赖方向

```
层4 入口  web_api / im_bot                     组合根，只编排
层3 应用  scheduler(SA4) / md_hub / td_exec / health_monitor
层2 服务  data_platform(capabilities/config_store/databus) / registry
层1 数据  quant_common(markets/redis_client)    词表与底座
```

- **禁止反向 import**（下层不得 import 上层）；`tests/test_layering.py` 守门，新增例外须在本表登记。
- **跨模块只走三种通道**：HTTP API（同步）、DB 表/视图（读）、Redis 键（异步流 + 心跳）。禁止直接调对方内部函数。
- **入口层零 SQL**：路由不得内联 SQL（`test_no_sql_in_new_routes.py`），查询下沉 `data_platform`。

### 2.1 写入归属（本批新增/变更面）

| 数据 | 唯一写者 | 读者 |
|---|---|---|
| `market_interface` / `trade_interface` / `data_source` | M2 API（web） | hub / exec / SA4 / collector（只读） |
| `td_md_map` | M2 API（web） | hub（订阅反查）/ exec（取价）/ collector |
| `provider_session_slot` | 持锁进程自身（DB 行锁） | SA4 / collector（只读） |
| `iface:hb:<role>:<code>` | 该接口进程自身 | collector / readyz / 前端 |
| `hub:bars/tick:*` | 行情接口 hub | worker / exec / 详情页 |
| `td:cmd:<code>` | 下发方（web / 风控 / IM） | 该交易接口 exec |

### 2.2 本批不整合的已知多写者（明确边界，只保证不新增）

- `order_log` 现有 5 处写点（`strategy_framework/strategy.py`、`strategy_runner/trading.py`×3、`td_exec/main.py`）→ **纸面/回测/实盘共用一张表**，整合属独立技术债。
- `account_snapshot` 现有 2 处写点（`risk_control/risk.py` 基线回填、`trading.py` snapshot_cycle）→ 本批只统一**刷新口径**，不合并回填路径。
- 本批要求：新增写点一律走既有函数，不得再散写 SQL。

## 3. 上线原子单元与发布序列

**原子单元**：`M1–M5` 必须同一次维护窗、同一个 release 上产（schema 与代码同步切）。M6a/M6b/M7/M8 可后续分批。开发仍按模块小步推进，**发布不可拆**。

发布序列（顺序强制）：

1. **wrapper 先装位**（`quant-dbro` / `quant-hbcheck` 带 `TRANSITION-0189` 分支，root/bootstrap）——未装位不得发布；
2. 停 web / celery / hub / exec（维护窗开始，确认无 running live_task）；
3. **全库备份** + 记录校验（大小/可恢复性），保留至冒烟通过；
4. 迁移（建三表 + 映射 + 租约重建 + 8 处身份回填 + 删旧表旧列）；
5. 部署 release（`allow_contract=true` + `auto_rollback_disabled=true`）；
6. 冒烟：见 §4 四条链路 + `/healthz` `/readyz`；
7. 观察窗（≥1 个 SA4 对账周期 + 1 个快照周期），确认 I3/I4/I5 成立；
8. 关闭维护窗，保留快照至下一交易日。

**回滚语义**：本批 schema 不可逆，**自动 rollback 不支持**；唯一路径 = 恢复迁移前快照 + 部署旧版代码（人工 runbook）。发布前必须完成一次「备份→恢复」演练并记录耗时。

## 4. 端到端验收矩阵（跨模块，单模块验收覆盖不到）

| # | 链路 | 期望可观测 | 证据 | 责任 |
|---|---|---|---|---|
| E1 | **清仓取价**：TD → 主 MD → 备 MD | 主有价时读主；主无价自动降级；全无价返回 `MAPPING_MISSING` | 清仓日志出现 `hub:latest_tick:<主code>`，撤主后出现备 code；空映射回执错误码 | M4/M5 |
| E2 | **订阅隔离**（两个 bug） | A 股标的不进加密 hub；OKX 无 `*_SWAP_OKX`；币安 10min 无 reset 且 bars 递增 | 两 hub 日志 + bars 计数 | M4 |
| E3 | **断线重连** | hub 断流后 `working=false`→重连→bars 恢复；exec 重连后 `working=true` | 心跳字段时序 + 日志 | M3/M4/M5 |
| E4 | **停用空转** | `enabled=false`：unit 仍 active、心跳 `working=false`、`ss` 无券商连接、无订阅 | systemctl + redis hgetall + ss 三连断言 | M3 |

**判定**：四条全绿才算上产完成；E1/E2 必须在 prod 实测（staging 只做彩排）。

## 5. 失败判据与决策点

| 情形 | 判据 | 处置 | 决策人 |
|---|---|---|---|
| 迁移超窗 | 超过预算（M1 方案给出） | 中止 → 恢复快照 → 复盘 | 用户 |
| 校验失败 | 行数/FK/触发器计数不符且 30 分钟内不可修 | 恢复快照 | 用户 |
| 冒烟失败（可修） | 四条链路中 ≤1 条失败且原因定位 | 窗内修复后重跑，不二次迁移 | 助手 + 用户确认 |
| 冒烟失败（不可修） | 根因在 schema 设计 | 恢复快照 + 回退本批需求评审 | 用户 |
| **基线重置** | 历史无保留价值 且 已备份 | TRUNCATE 业务表 + 重建 + 重录凭证 + 清旧键 + 重建 slot | 用户（授权兜底，非默认） |

**红线**：未备份不得迁移；快照未验证可恢复不得进入步骤 4；演练未做不得进维护窗。

## 6. 本批明确不做

- `order_log` 多写者整合、`account_snapshot` 写者合并（技术债，见 §2.2）；
- EMT / 币安 / 欧易的 `execution` 插件化（D32 P4）——本期只保证「无载体 → 待接入、不建进程」；
- 行情接口承载 hist/ref/inst_event（D4：历史类留数据源页签）；
- 研究子域（D32 P6）、多市场分片（deploy_markets）改造。
