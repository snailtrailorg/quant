# 小方案：移除「API 密钥账户」卡（AccountsCard / accounts 表）

> 状态：**已确认并实施**（2026-11-23，用户授权强制上产）。范围仅此卡，不动 `account_permission`（login_key 权限）与 LiveTask 绑定。

## 1. 结论

**删除。** 它是 P4-5 遗留的并行账户模型，已被 189 的“接口行 + provider 注册模板 + credentials/params”完全覆盖。

## 2. 事实（评估依据）

- **无人消费**：`accounts` 表只被 `/api/account` 5 个端点自身读写；`live_task.account_id` 直接绑 `trade_interface.code`（`trading.py:149`），前端 LiveTask 下拉用 `getTdInterfaces()`。
- **前端零引用**：`getAccounts()` 无调用方；仅 `AccountsCard.vue` + `TradeInterfaces.vue` 引用。
- **无外键**：迁移与代码中无 `REFERENCES accounts`；无触发器/视图。
- **生产为空**：`GET /api/account` 返回 `[]`（0 行，无密钥可丢）。
- **能力被覆盖**：provider `FIELD_SCHEMA/PARAMS_SCHEMA` 按接口行存凭证/参数；`api_key_hint` 只是提示，不参与任何交易链路。
- **唯一历史包袱**：`accounts` 有 `api_key_enc/api_secret_enc` 两列（0027/0042），但 API 从未使用；表空。

## 3. 改动清单

### A. 代码/UI（可逆，先做）

1. 删 `web/src/components/AccountsCard.vue`；`TradeInterfaces.vue` 去引用。
2. 删 `web/src/api.js` 的 `getAccounts`。
3. 删 `server/src/web_api/routes/trading.py` 的 `/api/account` 5 端点（GET 列表/详情、POST 建/改、DELETE）。
4. 删 `server/tests/test_put_to_post.py` 的 `/api/account/1` 条目。
5. 删 `interfaces` 域 7 个词条 × 三语：`accountsTitle/accountsNote/accountsKeyHint/accountsAdd/accountsEdit/accountsConfirmDelete` 及残留。
6. 文档同步：`批189-TD-MD接口拆分-现状与需求.md` 两处（§63/§64/M6a 表）改为“AccountsCard 退役”；本文件作为依据。

### B. 数据库（不可逆，单独确认）

1. 迁移 `0194_drop_accounts.py`：`op.drop_table("accounts")`；downgrade 重建最小表（仅结构，密钥列不再恢复）。
2. `server/scripts/init-schema.sql` 删 accounts 段（202-214）。
3. 上产前备份：`pg_dump -t accounts`（即使 0 行也留结构证据）；确认全环境 0 行。

## 4. 风险与边界

- **误删真实密钥**：prod 已实测 0 行；staging/dev 上产前再查一次 `SELECT count(*)`。
- **隐性消费者**：已 grep 全仓（前端/后端/测试/迁移）无；`GET /api/accounts/{id}/permission` 属 `account_permission`，**不动**。
- **回滚**：A 步 revert 代码即可；B 步只能恢复结构，数据为空故无损失。

## 5. 验收

- 前端 build 三闸绿；TradeInterfaces 页无该卡；全量 pytest 绿。
- `curl /api/account` → 404；`GET /api/td-interfaces` 与 LiveTask 建任务不受影响。
- 迁移后 `to_regclass('accounts')` 为空；三证 + 关键页面冒烟。
