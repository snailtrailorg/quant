# 批189 订单异步链路改造（OrderGateway/对账/事件账）

> 状态：阶段 1/2 已实施（2026-11-23）。**设计真源=`docs/design/D34-订单执行异步链路.md`**；本文件仅保留阶段进度，不复制设计。

## 1. 问题

- web → td:cmd 队列 → td_exec → XTP SDK 四段异步；本地 submitted 只是“已交给 SDK”，券商受理/成交/拒单全靠回调。
- 回调丢失即永久 submitted；撤单只扫内存缓存；拒单错误用全局 last_reject，匹配不可靠。
- 失败后只有零散日志，无法回答“这单经历了什么”。

## 2. 目标状态机

```
queued → sent → broker_accepted → partial → filled
                         ├→ rejected
                         └→ cancelled
              └→ unknown（超时/无回报，需对账）
```

- 单一所有者：td_exec OrderGateway；策略/手工/清仓统一走它。
- `order_log.status` 是投影；`order_event` 是**唯一事件账**（append-only）。
- 每次转换必有 event：source(web/td_exec/broker/reconciler)、vt_orderid、req_id/cid、error、detail。

## 3. 阶段

### 阶段 1（本次）：事件账 + 关键节点留痕

- 迁移 0195：`order_event(order_id, client_order_id, req_id, ts, stage, status, source, detail jsonb, error)`。
- helper `record_order_event`（never-raise）：手工/策略下单、撤单、清仓、券商回报、成交、对账写入。
- 保留现有 order_log 状态，不改行为；先让每次失败有轨迹。

### 阶段 2：对账器

- td_exec 每 30s 扫 submitted/submitting 超时单；查券商在途/成交（XTP 查询或回调缓存 + 重启对账）。
- 超时无回报 → event `timeout` + 告警（可配置是否取消）；禁止永久 submitted。
- 撤单改为“先对账再撤”，DB 在途 + 券商清单合并。

### 阶段 3：OrderGateway 收敛

- 策略/手工/清仓统一入口；状态机单写点；事务外发单、事务内记账。
- HTTP 202+req_id，订单变化走 SSE/WS；UI 展示逐单时间线。

## 4. 验收

- 任一失败单可查完整事件链（提交→SDK→券商→拒/成/撤/超时）。
- 撤单 requested 与 DB/券商在途一致；close-all 的 skipped_t1/positions_remain 可解释。
- 注入丢回调/迟到/重复事件测试通过；真实仿真环境验限价语义。
