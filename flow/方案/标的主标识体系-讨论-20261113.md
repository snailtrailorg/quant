## 一、结论

项目**已分层**（vt canonical + 供给面映射 + `security_master` 品种字段）。真缺口：① 无 `mic_code`；② vnpy 运行时 `.SSE` 漏进持仓表；③ 仓内已有多处后缀映射——**本批不追求物理消灭它们，只保证不再新增，并逐步收口**。

## 二、现状（实证）

| 层 | 形态 | 例 |
|---|---|---|
| 供给面源格式 | tushare `.SH`；聚宽 `.XSHG` | `600036.SH` |
| **内部 canonical** | **vt `.SHSE/.SZSE/.BSE`** | `600036.SHSE` |
| 运行时（vnpy） | `Exchange.value`：沪 `SSE`、深 `SZSE`；**且 `translate` 取的是裸码 `d.symbol`** | `600036` / `600036.SSE` |
| 持久化 | order_log 沪混用；position_snapshot 沪恒 `.SSE` | — |

`security_master`：vt_symbol(PK)/market/exchange/category/board/multiplier(每手数)/tick_size/...；**无 mic_code**。唯一键 `position_snapshot(account_id,symbol,direction)`（`trading.py:215`）。

## 三、三层模型对照

full_symbol/asset_class/品种字段/每源映射 ✅；`mic_code`/raw_code/surrogate PK ❌（后两个不做）；业务靠后缀判断 ⚠️ 半达标。

## 四、裁定（用户 2026-11-13）

canonical 保持 vt；运行时归一现在做；新增 ISO MIC 列（`XSHG/XSHE/BJSE`）。

## 五、外部资料核实（官方 CSV）

❌ `.SS`≠瑞士（Yahoo 上交所后缀；瑞士 `XSWX`）；❌ "MIC=唯一主键"（MIC 是 venue，证券主键用 ISIN/FIGI）；❌ `XNEE`=新西兰、`XBSE`=罗马尼亚，**北交所=`BJSE`**；❌ `.JP` 不稳（`XJPX/XTKS`）。

## 六、边界归一原则

✅ 防腐层。补：① **vnpy 运行时也是边界**；② "国标"用词不准（ISO MIC[venue]+ISIN[证券]），且不能只统一后缀（分层：venue→MIC、证券→ISIN、业务键→vt）。

## 七、四层落地（v3：expand → contract 两步走）

### 7.1 L0 新增 canonical 单点（**只新增，不改旧 4 处**）
- 新增 `quant_common/symbology.py`：`VT_TO_MIC={SHSE:XSHG,SZSE:XSHE,BSE:BJSE}`、`_VENDOR_ALIASES`（入站，含 `SSE/SH/SZ/BJ/XSHG/XSHE` + **`BINANCE/OKX` 直通**）、`canonical()/to_mic()/split_raw()/aliases()`。
- **`aliases(symbol) -> set[str]` 双向**（`SHSE`↔`SSE`）——保留 171n 修复语义，供 `position_symbol_candidates` 过渡用（**否则现网 `position_snapshot` 仍 `.SSE` 时 SELL 恒截 0，重演 171n**）。
- `canonical` 裸码/未知后缀抛 `ValueError`（禁猜）。
- **不动** `schema.py`/`markets.EXCHANGES`/`strategy._VT_EXCHANGE_ALIASES`/`fees`（175d 收口）；`to_vt_symbol` **不 re-export**（保持宽松语义，零行为变更）。
- **基线棘轮**（不是全仓 AST——会误伤 joinquant/md_gateway 的出站映射）：记录现存 `SSE→SHSE` 字面量位置，**只减不增**。

### 7.2 L1 入站归一（交易侧，2 文件）
- `providers/xtp/translate.py` 三处：**先取 `d.vt_symbol`**（`d.symbol` 是裸码），缺失时 `symbol+"."+exchange.value` 拼，再过 `canonical`。
- 守门：无 `vt_symbol` 的真 vnpy Order 形状不抛；`.SSE` Position → `"600036.SHSE"`。

### 7.3 L3 持久化（**0181 = expand 型，不含 CHECK**）
- `security_master.mic_code`（expand + 回填；crypto NULL）。
- `position_snapshot` 存量：**按 `(account_id, replace(symbol,'.SSE','.SHSE'), direction)` 保 `ts` 最新去重 DELETE → 再 UPDATE**（先选最新再 UPDATE，避免撞唯一键；分组键必须含 symbol）。**用纯 SQL 归一、不调 Python `canonical`**——后者对裸码/未知后缀抛错会让整条迁移 abort；非 vt 行（加密/历史 `.SH`）**原样保留、按原值分组**。
- **不加 `CHECK`**（见 §7.4）：`CHECK ... NOT VALID` **从加上的那一刻就约束新行**，而 `_flush_positions` 60s DELETE+INSERT，stage5 提交后旧 live-task（stage7 最后重启）下一拍写 `.SSE` 就撞约束被 `except` 吞——快照静默冻结；VALIDATE 跨拍则 abort。
- **`order_log` 不加列**（`GENERATED STORED` 会全表重写+ACCESS EXCLUSIVE 锁，且 `migration_policy` 不识别重写）；读侧/对账用 `replace(symbol,'.SSE','.SHSE')` 表达式。
- 显示：`/api/position`、`/api/orders` 读侧输出 canonical。
- downgrade：`DROP COLUMN mic_code`；数据 `.SHSE` **不回写**（不可区分源），docstring 写明。

### 7.4 175d = contract + 收口
- **0182**：加 `CHECK (position_snapshot.symbol NOT LIKE '%.SSE') NOT VALID → VALIDATE`；**downgrade `DROP CONSTRAINT`**（不能 no-op——否则 rollback 后每次快照写批违约束被吞、静默永久停更，roundtrip 假绿）。
- **前置门（0182 必须单独一次 release，不与 175c 同车）**：上产前生产 `position_snapshot` 0 行 `%.SSE`、**所有 live-task 已用 175b/175c 代码重启完毕**、过 ≥1 个 60s 快照周期；空仓场景另用正向控制验证落库口径（否则 0 行天然成立）。
- `.BJ→.BSE` 补齐（`screen.py:200`/`stock.py:236` **现即 bug**）；`markets.EXCHANGES` **保持手写字面量**并补 `SSE` 一行（**不派生**，因 key 含 `SSE` 兼容行而 `VT_TO_MIC` 不含；`mgmt._VALID_EXCHANGES` 需同改）。**仅** `schema.TS_EXCHANGE_MAP`/`strategy._VT_EXCHANGE_ALIASES`/`fees` 声明派生自 symbology——**markets.EXCHANGES 是明确例外**。
- 收口旧 4 处映射（schema/markets/strategy 派生自 symbology、fees 声明并入）；删 `position_symbol_candidates`；基线棘轮只减不增。
- `market_of_symbol` **不改读 SM**（hub N+1），SM 化单独立项。
