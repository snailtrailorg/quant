## 一、结论先说

项目**已经是分层结构**（内部 canonical vt + 供给面 symbology 映射 + `security_master` 存品种/规则），不是"裸放一个字符串"。真正缺口只有两点：**① 没有 MIC 字段；② 运行时 vnpy 的 `.SSE` 漏进持仓表**。用户建议的"surrogate 主键 + raw_code/venue_suffix 拆列"**不必现在做**（收益低、改造面大）。

## 二、现状（实证）

| 层 | 形态 | 例 | 真源 |
|---|---|---|---|
| 供给面源格式 | tushare `.SH/.SZ/.BJ`；聚宽 `.XSHG/.XSHE` | `600036.SH` | 各 `BaseDataAdapter.to_source_symbol` 覆写 |
| **内部 canonical** | **vt `.SHSE/.SZSE/.BSE`** | `600036.SHSE` | 批131 正名：bar PK/Subscription/pool/DataBus 全 vt |
| 运行时（vnpy） | vnpy `Exchange.value`：沪 `SSE`、深 `SZSE` | `600036.SSE` | `providers/xtp/translate.to_position` 取 `vt_symbol` |
| 持久化 | order_log 沪 `.SHSE`/`.SSE` **混用**、深 `.SZSE`；position_snapshot 沪恒 `.SSE` | — | 批173/174 实证 |

`security_master`（0092 建 + 0097/0176 扩）：`vt_symbol`(PK) / `market`(astock|crypto) / **`exchange`**(SHSE|SZSE|BSE) / **`category`**(stock|listed_fund|convertible|perp) / `board`(main|star|chinext|bse) / **`multiplier`(每手数：股 100、转债 10、perp 1)** / `tick_size` / `trade_phase` / `sellable_rule` / `order_types` / `position_side` / `venue_flags` / `order_range_override`。**无 `raw_code` / `mic_code` / `figi`**。

## 四、处理建议（分级）

### P0 现在补（低风险、只增不改）
1. `security_master` 加 `mic_code` 列（expand 迁移，回填 `XSHG/XSHE/XNEE`；crypto 留 NULL）。**`exchange` 词保留不动**，业务判断零改动。
2. 新增单源常量 `EXCHANGE_TO_MIC = {"SHSE":"XSHG","SZSE":"XSHE","BSE":"BJSE"}`（`quant_common/markets.py` 或 `symbology.py`）。**已用官方 `docs/reference/iso/ISO10383_MIC.csv` 逐条核对（2026-11-13）**：`XSHG`=上交所、`XSHE`=深交所、**`BJSE`=北交所**。⚠️ 社区文章的 `XNEE` 实为**新西兰 NZX 期货期权交易所**、`XBSE` 为**罗马尼亚 BVB**（张冠李戴）；国内其余可选值：`CCFX` 中金所、`XSGE` 上期所、`XDCE` 大商所、`XZCE` 郑商所、`GFEX` 广期所、`NEEQ` 新三板、`XCFE` 外汇交易中心、`SGEX` 上海金交所。
3. `InstrumentSpec` 暴露 `mic_code`（读表，随 0176 规格层）。

### P1 值得讨论
4. **运行时归一**：`translate.to_position` 把 vnpy `.SSE` → 项目 vt `.SHSE`；`position_snapshot` 存量一次迁移。收益＝消除沪市双写、删 `position_symbol_candidates` 补丁；成本＝一次迁移 + 读侧核对。
5. **后缀判断收敛**：`market_of_symbol`/`_market_of`/对账 `split_part` 逐步改读 `security_master`（对账可 join SM），减少"字符串后缀做业务判断"。

### 不做（现在）
6. surrogate PK + `raw_code`/`venue_suffix` 拆列：bar PK/Subscription/order_log 全引用 `vt_symbol`，改造面极大；单市场单账户，跨市场串号已由 `account_id`+`category` 隔离。
7. 全面改用 MIC 做路由/主键：MIC 与 vnpy `Exchange`/provider 不直接对应，多一层映射收益低。
8. `figi`：当前无跨源证券对齐需求，按需后加。

## 六、附带发现（批174 可优化）

`security_master.multiplier` 实值＝**每手数**（stock=100、转债=10、perp=1），`_load_instrument` 已映射为 `InstrumentSpec.lot_size`。批174 的截断取整当前用 `category` 硬编码（stock→100/convertible→10），**应改为直接 `InstrumentSpec.of(sym).lot_size`**（配置驱动非硬编码，功能等价）。可随下批顺带，避免再加一次上产。

## 七、外部资料核实备注（2026-11-13，本地可验证范围内）

参考的社区文章**大方向对、细节有错**，不可照抄：

- ✅ **可信**：ISO 10383 MIC 是真实标准（4 位）；`XSHG`=上交所、`XSHE`=深交所（venv 聚宽 adapter 41 处使用，佐证）；`.SH/.SZ/.BJ` 是国内量化约定非 ISO；后缀不区分品种；同代码跨市场存在；每数据源需单独映射层。
- ❌ **错（已用官方 CSV 确认）**：① `.SS`=瑞士 SIX —— **错**：`.SS` 最常见是 Yahoo 的**上交所**后缀（`600000.SS`），瑞士官方 MIC 是 `XSWX`（后缀 `.SW`），斯德哥尔摩是 `XSTO`（后缀 `.ST`）⇒ 无论哪套 `.SS` 都不指瑞士；② **"MIC＝唯一主键"是概念错误**——MIC 标识 venue（交易所），同所全部证券共享，不能做证券主键；证券主键应看 **ISIN（ISO 6166）**/FIGI/surrogate id；③ **`XNEE`=北交所——错**：官方 CSV 里 `XNEE`=**新西兰** NZX 期货期权交易所，北交所是 **`BJSE`**（`XBSE` 亦非北交所，是罗马尼亚 BVB）；④ `.JP`=日本东证不稳（官方 MIC 是 `XJPX`/`XTKS`、Yahoo 后缀 `.T`、Bloomberg `JT`）。
- ⚠️ **拼凑**：国际后缀表混用 Bloomberg（`.LN`）与 Yahoo（`.KS/.TW/.SS`）两套体系；漏 **ISIN**（比 FIGI 更主流的证券国际标识），FIGI「跨数据源对齐神器」属夸大。

## 八、边界归一原则（2026-11-13 讨论）

### 8.1 原则是否合适：合适，但要补两点

✅ **合适**，这就是行业标准的「防腐层 / 端口适配器」：异构只活在 adapter 边界，进核心前归一。项目已部分这么做（批131 vt canonical + `to_source_symbol`）。

补正：
1. **「小区域」不止数据源 adapter——vnpy 运行时也是外部边界**。XTP 经 vnpy，`Exchange.SSE.value="SSE"` 会把 `.SSE` 带进 `position_snapshot`（批173/174 的真实漏口）。边界清单＝{tushare, jq, **XTP-vnpy**, 未来 EMT/crypto, 文件导入}。
2. **「统一成国标」用词不准，且不能只统一后缀**：国内无强制国标；国际标准是 **ISO 10383 MIC（venue）+ ISO 6166 ISIN（证券）**。分层：venue→**MIC**（XSHG/XSHE/BJSE）；证券唯一标识→**ISIN**（未来跨源对齐）/surrogate；内部业务键/展示→**vt**（`.SHSE`）。**只统一后缀字符串＝仍靠后缀做业务判断，等于把问题搬家。**

### 8.2 具体怎么做（四层）

**L0 canonical 单点（新增 `quant_common/symbology.py`，层 0 底座，全层可依赖）**
```python
VT_TO_MIC = {"SHSE": "XSHG", "SZSE": "XSHE", "BSE": "BJSE"}
MIC_TO_VT = {v: k for k, v in VT_TO_MIC.items()}
_VENDOR_ALIASES = {  # 各源/运行时后缀 → vt（含 vnpy 的 SSE）
    "SHSE": "SHSE", "SSE": "SHSE", "XSHG": "SHSE", "SH": "SHSE",
    "SZSE": "SZSE", "XSHE": "SZSE", "SZ": "SZSE",
    "BSE": "BSE", "BJSE": "BSE", "BJ": "BSE",
}
def canonical(symbol: str) -> str:              # 任意形态 → vt；未知后缀大声失败（禁猜）
def to_mic(symbol: str) -> str | None:          # vt → MIC（crypto 返 None）
def split_raw(symbol: str) -> tuple[str, str]:  # → (raw_code, vt_suffix)
```

**L1 入站归一（唯一允许出现「不一致」的地方）**
- 各 provider 在**写 DB 或发布内部总线前**调 `canonical()`：tushare `.SH`→`.SHSE`、jq `.XSHG`→`.SHSE`、**XTP-vnpy `.SSE`→`.SHSE`**、crypto 直通。
- 落点：`BaseDataAdapter` 增 `normalize_symbol()`（默认 `canonical`）；`providers/xtp/translate.py` 的 order/trade/position **三处统一过 `canonical`**（这是当前最大漏口）。

**L2 出站映射（已存在，保持）**
- `to_source_symbol(vt) -> 源格式`（每 adapter 覆写；批131 已立规矩）。

**L3 持久化只存 canonical + 结构化字段**
- `security_master`：`vt_symbol`(canonical) + 新增 `mic_code`（+可选 `raw_code`）。
- `position_snapshot`/`order_log`/`bar_*`：写入前必经 `canonical`。存量 `.SSE` 一次性迁移（position_snapshot 量小）；**order_log 是审计表：加 `symbol_canonical` 列回填、不改历史**。

### 8.3 守门（防退化，必须）
- 持久层 symbol 必须 == `canonical(symbol)`；**禁止 `.SSE` 落 `position_snapshot`/`order_log`/`bar_*`**（正反例都测）。
- `security_master` 每行 `to_mic(vt_symbol) == mic_code`。
- `canonical` 全表双向覆盖（vt↔MIC↔各源别名）；未知后缀抛错（不猜）。
- 新 adapter 注册必须实现 `normalize_symbol`/`to_source_symbol`（AST/注册表校验）。

### 8.4 迁移顺序（低风险）
1. 建 `symbology.py` + 单测（零行为变更）。
2. `translate` 入站归一 `.SSE→.SHSE`（会暴露所有依赖 `.SSE` 的点，逐个改；`position_symbol_candidates` 兼容可随后删）。
3. `security_master` 加 `mic_code`（expand + 回填）。
4. 存量：`position_snapshot` UPDATE；`order_log` 加 `symbol_canonical` 列回填。
5. 守门测试上线，锁死「persist 只存 canonical」。
