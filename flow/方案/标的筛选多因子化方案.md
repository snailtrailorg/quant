## 二、核心机制（三期共用基建）

### 1. 字段注册表（screen_field_registry）——构建器与 DSL 共同的字段单源（v3 补审 P1-6 六元组）
- 品类词表=ASSET_CATEGORIES 单源子集（stock/listed_fund/convertible——双盲 A-P0-1 已改）
- 字段六元组：`{name, label, source('column'|'cache'|'expr'), type('num'|'bool'), nullable, group}`
  - source=cache → 编译器 JOIN screen_factor_cache；column→现库列；expr→内联 SQL（st/上市天数）
  - nullable=True → builder 置灰死字段依据；NULL 立法=比较 op 剔除 NULL 行+percentile 剔 NULL 计母数
- 预计算字段由盘后调度管道生成（15:05 后 T-1 全量，幂等；筛选只读缓存 miss 降级）
- 加品类=加字段集行+测试断言（与 DataKind/SM 注册纪律同构）

### 2. 筛选方案（screen_preset 表）——统一保存面（v3 补审 P0-1/P1-1/P1-2 修订）
- 列：id/name/category/source('builder'|'dsl'|'builtin')/definition(jsonb 含 v 版本键)/created_by/updated_at
- definition：builder 式={v:1, match:'all'|'any', rows:[{field,op,value}]}（**行内无 logic——逻辑唯一真源=顶层 match**，补审 P0-1）；dsl 式={v:1, filter:expression, rank?:expression}
- 读侧宽容解析（P1-2）：死字段跳行+响应标注；source 形状判别单源=definition 有 match 键=builder
- 权限（P1-1）：写面=组层单锁（alerts_config 先例）+admin 地板；builtin 一律拒改删；非 admin 仅本人方案可改删
- 出厂预置=种子数据（builtin）；API：CRUD 分面（读=read 键，写=专键）

### 3. 条件→SQL 编译器（后端）——v3 补审 P0-2 类型矩阵与 NULL 立法
- 字段注册表驱动：field→列/表达式+类型校验；op 白名单（= != > >= < <= in percentile_top percentile_bottom）
- **op×类型矩阵**：num 型配全部比较 op；bool 型仅 =（true/false）；字符串列不注册（无此型字段——注册表即类型单源）；错配=400
- **NULL 三态立法**：比较类 op 遇字段 NULL 行=剔除（不参与匹配）；percentile 母数=剔 NULL 后计数；响应附 nulls_excluded 计数提示
- **value 契约**：数值型收 float；in=数组（≤50 元素）；percentile=0-100 闭区间；非法=422/400 码化
- **全程参数化查询**（op 与列名白名单映射，值绑定）——注入面封死

### 4. 横截面 DSL（期 3）——v3 补审 P1-3/P1-4 修订
- CrossSectionContext：每标的一行（快照列+预计算因子列）；**_safe_eval 求值壳复用，校验链独立**（时序校验 `_preprocess_dsl_tree` 认窗口首参∈OHLCV 且禁嵌套——`rank(pe_ttm)` 必被拦；横截面校验通道：变量词表=品类注册表字段名、函数=rank/zscore/quantile+数值函数、**禁时序窗口函数**）
- 资源面（P1-4）：单表达式横截面函数调用数上限（建议 ≤10）；NULL 传染=该标的表达式判 False 剔除（缓存 miss 标的不进结果）
- 前视防护：统一截至 T-1 收盘口径
- 双页签契约（P1-5）：**不互转**（builder→DSL 语义可编译但 v1 不做单向导出）；两页签独立草稿态；方案列表按当前品类过滤

## 三、三期划分（每期独立可用，编码分三批走八步法）

| 期 | 内容 | 交付 |
