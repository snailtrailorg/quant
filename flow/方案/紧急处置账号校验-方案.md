## 1. 设计真源 vs 实现偏差

| 来源 | 原文裁定 | 现状 |
|---|---|---|
| 171n 归档「端点空态分叉」 | 判活 = `live_task status='running'` **∩ 心跳键新鲜**；僵尸 runner 不收——"命令下发给死进程=静默过期" | `_live_runners()` 符合 |
| 171o 归档「通道账号=复选按钮组」 | 数据源 = `trading_account` **enabled 行**；**默认全选（进页面即全量处置就绪）** | `Emergency.vue:222` 符合。**本方案不改动此交互裁定** |
| 171o 归档「后端改动」 | accounts 过滤；过滤后空集 = 400 `NO_MATCH_ACCOUNT`；无效 account_id = 400 | `risk.py:329` 用 **DB-only** 判"无效"——偏离 171n 口径 |
| 171o 归档「评审要点②」 | 勾选集不含某账号时该账号在途单仍在——**回执明示未处置账号** | 未落实：无任务账号直接 400，无回执 |

两个设计裁定不冲突："默认全选"是交互效率，"无效账号 = 400"是安全。冲突出在实现把
"无效"定义成 DB-only，让"启用但没跑任务"这种常态被误判。裁定 A 把安全面从"拒绝"
改为"静默排除 + 明示"，不动用户的交互裁定。

## 3. 裁定 A 的语义（双盲审校正版）

无任务账号被勾选时**不报 400**：后端用 `_live_runners(accounts)` 一次判定，只对可处置账号下发，
回执列 `skipped_accounts`（含原因）随三态返回。
**前端不改默认勾选**（保留 171o"默认全选所有 enabled"裁定），也不改按钮 disabled 规则；
只把 `skipped_accounts` 在 `fmtResult`/`fmtFinal` 中渲染出来，用户据此知道哪些账号未处置。
Valkey 故障或心跳读取异常时，原因只写"未处置（状态未知）"，**不臆断为心跳死**。

## 4. 实施方案（标准六面 DoD · 裁定 A）

| 面 | 内容 |
|---|---|
| ① 数据/契约 | 无新库字段；回执新增展示态 `skipped_accounts`（`account_id` + reason） |
| ② 写入路径 | **删** `risk.py:326-334` 的 DB-only 预校验；**改** `:337` 的 `live_running_tasks()` 判定为同一 `_live_runners` 结果；扩展 `_live_runners` 返回 per-runner 状态（alive / no_running_row / hb_stale / valkey_unreachable / hb_error），一次判定供三态分叉 + skipped 原因 + audit 共用；per-runner 状态加入 audit_log detail |
| ③ 读取/展示 | `fmtResult`（`Emergency.vue:103-136`）、`fmtFinal`（`:147-168`）渲染 `skipped_accounts`（三语词条）；worker `:final`（`hub_worker.py:290-311`）同步带出，**保证页面刷新/晚开仍可见**；`apiErr` 保留 detail 回退；**不改默认勾选、不改按钮 disabled** |
| ④ 可观测/告警 | `skipped_accounts` 及原因落 `audit_log`（继 `:389-390` 之后）；**不新增告警码**（避免与既有规则重复——告警冻结纪律） |
| ⑤ 测试 | `tests/test_batch187_risk_account_scope.py`（186 已回滚作废，顺延 187）：①无任务账号不阻断、不收命令 ②僵尸账号不收且原因准确 ③Valkey 故障原因不臆断 ④回执 `skipped_accounts` 三路径（三态 + `:final`）⑤三码分流边界 ⑥删除错误码后既有 400 测试仍过 |
| ⑥ 文档 | 171o 归档加"实现修订"注记（不改原裁定）；本方案 v2 定型；两份双盲审报告存档；待办/进展同步 |

**三态分叉重述（一次判定）**：`runners = _live_runners(accounts)` —
空且无任何活 runner → 409 `RISK_NO_ACTIVE_RUNNER`；
空但存在活 runner（勾选集排除了它们）→ 400 `RISK_NO_MATCH_ACCOUNT`；
非空 → 下发 + `skipped_accounts`。无第三个 DB-only 判定。
