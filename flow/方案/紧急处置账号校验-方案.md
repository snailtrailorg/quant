## 3. 核心设计

### 3.1 账号校验（v6 审透，原样纳入）

删 `risk.py:326-334` 预校验；钉 `:335`：`runners=[(tid,a) for tid,a in live_running_tasks() if accounts is None or a in accounts]`（二元组不变，manual-order 不受影响）；`:343` 改"无 status=running 的实盘任务"；三态分叉（409/400/下发+skipped）；skipped 经 cmd 透传（`hub_worker.py:75-90`）写进 progress；文案三语修正、`apiErr` 保留 detail。

### 3.2 触发执行解耦（v10 核心）

- **`emergency_halt(reason)` 改造**（`risk_control/risk.py:159-165`）：置 3 键后 `LPUSH risk:halt:trigger {reason, operator_uid, ts}`（**持久化 List，非 pub/sub**；operator_uid 从 reason 前缀解析或新增可选参数；never-raise）；
- **三源统一**：web `risk.py:199`、飞书 `feishu_client.py:401`、LLM gateway 都只调 `emergency_halt`——删 web `:204` 的直接 `_dispatch_risk_cmd("cancel-all")`（避免双派发）；
- **统一派发消费者**：`risk_sweep`（`scheduler/tasks.py:98`）每拍消费 `risk:halt:trigger` → 调 `_dispatch_risk_cmd("cancel-all")` → 为每个 req_id 建 progress 事务 → 全部来源的熔断都在 web 看板显示（操作者 = reason 原文，`飞书:张三` 已含）；
- **去抖**：同一 halted 翻转只派一次（用 `risk:halt:dispatched:{ts}` 标记，TTL5min），防重复事件/沿兜底重复派发；
- **沿兜底降级**：`halt_edge_cancel`（`hub_worker.py:1031`）保留为"事件派发 → worker 投递"之间的即时止血（每 runner 撤自己单），不承担可见性；其撤单结果随后被统一派发命令的撤单覆盖（幂等）。

### 3.3 增量进度看板（旧链保留）

- **键族**：`progress:{req_id}`（含 `items:[{symbol,kind:cancel|close,status,detail,volume}]`、`phase:running|done|cancelled|systemic`、`operator`(reason)、`round_no`、`ts`、`skipped_accounts`）、`active:{uid}`、`cancel:{req_id}`（TTL30min）；
- **写口** `trading.write_progress`（never-raise，**独立于** `write_cmd_result`）；旧 `write_cmd_result`/`:final`/recent 保留（manual-order + web 5s 窗 + 历史时间线）——两链职责不重叠、各一真源；
- **端点（新增，`Depends(require_perm("halt"))` + 路由守门）**：`GET /api/risk/active`、`GET /api/risk/progress/{req_id}`、`POST /api/risk/cancel`（按 operator+批次取消同批全部 req_id）；旧端点不动。

### 3.4 逐单状态（撤单 + 清仓）

- 撤单：`_cancel_working_orders`（`trading.py:335-368`）增 `items:[{symbol,vt_orderid,result:requested|failed|untranslatable}]`，保留计数；归并为 progress 的 `kind:cancel` 行，**untranslatable 进 status 枚举**（三语补词条）；
- 清仓：`_close_all_positions` 每轮 `pending/no_quote/rejected/skipped_t1/closed_requested`（`trading.py:666-674/689-888`）归一为 `kind:close` 行，各自 status 语义保留（不合并）；
- 三类来源（web/飞书/LLM）经统一派发后都进看板，操作者 = reason（已含 `飞书:张三`）。

### 3.5 无限循环 + 取消（方向反转）

- `next_action`/`retry_due`/`bump`（`trading.py:584-638`）改签名：删 retry_max/deadline/empty_max，仅 systemic/done/cancelled；调用点 `trading.py:866/875` 同步改；`test_batch171s.py:478-489` S5 断言**整段重写**（三终止 → 不因计数停+取消即停）；
- **171s 归档 `:16/:98` 与 D12 相关节整篇重写**（状态文档重写制）：明确"紧急场景无限循环，仅完成/用户取消/systemic 故障终止，界面持续保留状态"的反转理由；
- 循环首行检查取消键（`:689 while True`）；轮间隔 sleep（`:879-880`）分段可中断（≤0.5s）；取消只停后续轮次，halted 保持（不 resume）；
- 取消粒度：按 operator+批次 ts 取消同批全部 req_id（`risk.py:359-367` 一次下发多 id）。

### 3.6 UI 看板

- `Emergency.vue:35` 上方插入"处置状态卡片"：active → 逐 req_id 拉 progress；
  - 一个表两类行（cancel/close），每单 status/detail；显示操作者（reason，如 `飞书:张三`）；
  - onMounted 拉 active + 每 2s 轮询 + SSE 终局帧立即重拉；标题栏取消图标 → `POST /api/risk/cancel`（按批次）；
  - 终局 active 移除 → 卡片消失；历史记录走既有 recent 时间线（不动 loadRecent）；
  - 三语：新增 status + 取消按钮 key，zh/en/zh-TW 全覆盖，`§5` 加 key 集合相等断言。
