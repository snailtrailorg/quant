## 3. 核心设计

### 3.1 账号校验（v6 审透，原样纳入）

删 `risk.py:326-334` 预校验；钉 `:335`：`runners=[(tid,a) for tid,a in live_running_tasks() if accounts is None or a in accounts]`（二元组不变，manual-order 不受影响）；`:343` 改"无 status=running 的实盘任务"；三态分叉（409/400/下发+skipped）；skipped 经 cmd 载荷透传（`hub_worker.py:75-90`）写进 progress；文案三语修正、`apiErr` 保留 detail。

### 3.2 增量进度看板（不退役旧链）

- **键族（新增）**：`risk:cmd:progress:{req_id}`（TTL30min）承载 `{req_id, verb, operator_uid, phase: running|done|cancelled|systemic, items:[{symbol,kind:cancel|close,status,detail,volume}], round_no, ts, skipped_accounts}`；`risk:cmd:active:{uid}`（进行中 req_id 列表）；`risk:cmd:cancel:{req_id}`；
- **写口**：`trading.write_progress(req_id, ...)`（never-raise，**独立于** `write_cmd_result`）——worker 执行时写 progress；**旧 `write_cmd_result`/`:final`/recent 保留**，服务 web 5s 回执 + 历史时间线；
- **双链分工**：progress = 进行中/逐单/取消（本批新增）；`:final`+`:result`+recent = 同步回执+历史（既有，不动）——同一 req_id 两链并存但**职责不重叠**、各有单一真源；
- **端点（新增，均 `Depends(require_perm("halt"))` + 路由守门测试）**：`GET /api/risk/active`、`GET /api/risk/progress/{req_id}`、`POST /api/risk/cancel`；旧 `/api/risk/close-result/*` 不动。

### 3.3 逐单状态（撤单 + 清仓）

- **撤单**：`_cancel_working_orders`（`trading.py:335-368`）返回增 `items:[{symbol,vt_orderid,result:requested|failed|untranslatable}]`，保留计数字段；worker 把 items 归并为 progress 的 `kind:cancel` 行；**`untranslatable` 进 status 枚举**（三语补词条，不塞 failed、不静默丢）；
- **清仓**：`_close_all_positions` 每轮已有 `pending/no_quote/rejected/skipped_t1/closed_requested`（`trading.py:666-674/689-888`）归一为 `kind:close` 行；status 保留各自语义（不合并成单一模糊状态）；
- **熔断**：web 路径（`:204` halt→cancel-all）天然进看板；沿兜底（`hub_worker.py:1031`）无 req_id——**本批明确为已知缺口**（非 web 来源 halted 的撤单不可见），另立批处理；不假称全覆盖。

### 3.4 无限循环 + 取消（方向反转，须重写设计文档）

- `next_action`/`retry_due`/`bump`（`trading.py:584-638`）改签名：删 retry_max/deadline/empty_max 参数，仅保留 systemic/done/cancelled 判定；调用点 `trading.py:866/875` 同步改；`test_batch171s.py:478-489` S5 断言**整段重写**（原钉"三终止"，改钉"不因计数停+取消即停"）；
- 171s 归档 `:16/:98` 与 D12 相关节**整篇重写**（状态文档重写制）：把"绝对上限防永不终止"改为"无限循环 + 用户取消/系统故障为终止条件"，并记录反转理由（紧急场景需持续处置直到成功/人工取消）；
- 循环首行检查取消键（`:689 while True` 内）；轮间隔 sleep（`:879-880`）分段可中断（≤0.5s 检查）；取消只停后续轮次，`risk:halted` 保持（不 resume）；
- **取消粒度**：一次下发多 req_id（`risk.py:359-367`）——取消端点按 `operator_uid + 批次 ts` 取消同批全部 req_id，卡片按操作聚合后一次取消（回应专家 P1-4）。

### 3.5 UI 看板（增量，不动旧渲染）

- `Emergency.vue:35` 上方插入"处置状态卡片"：active → 逐 req_id 拉 progress；
  - 一个表两类行（cancel/close），每单 status/detail；
  - onMounted 拉 active + 每 2s 轮询 progress + SSE 终局帧立即重拉；
  - 标题栏取消图标 → `POST /api/risk/cancel`（按批次）；
  - 终局（done/cancelled）active 移除 → 卡片消失；**历史记录仍走既有 recent 时间线**（不动 loadRecent）；
  - 三语：新增 6 status + 取消按钮 key，zh/en/zh-TW 全覆盖，`§5` 加 key 集合相等断言。
