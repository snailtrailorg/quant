## 1. 设计真源 vs 实现偏差

| 来源 | 原文裁定 | 现状 |
|---|---|---|
| 171n「端点空态分叉」 | 判活 = `live_task status='running'` **∩ 心跳新鲜**；僵尸 runner 不收 | `_live_runners()` 符合 |
| 171o「通道账号=复选按钮组」 | 数据源 = `trading_account` **enabled 行**；**默认全选（进页面即全量处置就绪）** | `Emergency.vue:222` 符合。**本方案不改此交互裁定** |
| 171o「后端改动」 | accounts 过滤；空集 = 400 `NO_MATCH_ACCOUNT`；无效 account_id = 400 | `risk.py:329` 用 DB-only 判"无效"——偏离 171n |
| 171o「评审要点②」 | 勾选集不含某账号时该账号在途单仍在——**回执明示未处置账号** | 未落实：无任务账号直接 400，无回执 |

两个裁定不冲突："默认全选"是交互效率，"无效账号=400"是安全。冲突只在实现把"无效"
定义成 DB-only，让"启用但没跑任务"这种常态被误判。裁定 A 把安全面从"拒绝"改为
"静默排除 + 明示"，不动用户交互裁定。

## 3. 裁定 A 的语义（三轮校正版）

无任务账号被勾选时**不报 400**：后端用**单一判定源**一次算出每个账号状态，只对可处置账号下发，
回执列 `skipped_accounts`（账号 + 原因）随三态返回，并经 cmd → worker `:final` → recent 完整透传，
保证页面刷新/晚开仍可见。
**前端不改默认勾选**（保留 171o"默认全选所有 enabled"裁定），不改按钮 disabled；
只在 `fmtResult`/`fmtFinal` 渲染 `skipped_accounts`。
Valkey 故障或心跳读取异常时原因只写"未处置（状态未知）"，**不臆断为心跳死**。

## 4. 实施方案（标准六面 DoD · 裁定 A · v3）

| 面 | 内容 |
|---|---|
| ① 数据/契约 | 无新库字段；回执新增展示态 `skipped_accounts`（`account_id` + reason）；cmd 载荷增同名字段 |
| ② 写入路径 | **新增单一判定源** `live_runner_states(accounts) -> list[dict]`（每项 tid/account_id/state：alive / no_running_row / hb_stale / valkey_unreachable / hb_error）；**`_live_runners()` 保持签名与二元组返回不变，内部投影自 states**（manual-order 等 4 处调用方零改动）；删 `risk.py:326-334` DB-only 预校验；**改 `:337` 的 `live_running_tasks()` 判定**为同一 states 结果；三态分叉、skipped 原因、audit 三处共用 states（判定只算一次多处消费） |
| ③ 读取/展示 | `fmtResult`（`Emergency.vue:103-136`）、`fmtFinal`（`:147-168`）渲染 `skipped_accounts`（三语）；**数据通路**：`_dispatch_risk_cmd` 写 `risk:cmd:{tid}`（`risk.py:362-366`）时注入 skipped → worker `_final`（`hub_worker.py:291`）从 cmd 读回写入 `:final` → recent 端点（`risk.py:512-566`）可读 ⇒ 刷新可见；`apiErr` 保留 detail 回退；**不改默认勾选、不改按钮 disabled** |
| ④ 可观测/告警 | skipped 及原因落 `audit_log`（继 `:389-390` 之后），状态在页面可见；**不新增告警码**（告警冻结纪律） |
| ⑤ 测试 | `tests/test_batch187_risk_account_scope.py`（186 已回滚作废）：①无任务账号不阻断、不收命令 ②僵尸账号不收且原因准确 ③Valkey 故障原因不臆断 ④`skipped_accounts` 三路径（即时回执 / `:final` / 刷新后 recent）⑤三码分流边界 ⑥`_live_runners` 二元组兼容（manual-order 回归）⑦删错误码后既有 400 测试仍过 |
| ⑥ 文档 | 171o 归档加"实现修订"注记（不改原裁定）；本方案 v3 定型；三份审查报告存档；待办/进展同步 |

**三态分叉重述（一次判定）**：`states = live_runner_states(accounts)` —
`alive` 为空且全局无活 runner → 409 `RISK_NO_ACTIVE_RUNNER`；
`alive` 为空但全局有活 runner（勾选集排除了它们）→ 400 `RISK_NO_MATCH_ACCOUNT`；
非空 → 下发 + `skipped_accounts`。无第三个 DB-only 判定。
