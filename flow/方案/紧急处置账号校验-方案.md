2. **全部消费者**（已逐个核实）：

   - 展示数据：`risk.py:404-465`（`risk_exposure`，`running` 在 `:447`）
   - 文案：`web/src/locales/index.js:1180`（zh）/ `:2645`（en）+ `api.js:30-38`（`apiErr` 吞 detail）
   - 测试：`tests/test_batch171o.py:75-82`、`tests/test_batch171n.py:262-282`
3. **既有机制**：`_live_runners()` 已是"判活"单源，且 171n 归档就是这么立法的；
   `risk_exposure.items[].running` 用的是同一口径。**唯一偏离者是 `risk.py:329` 的

## 1. 设计真源 vs 实现偏差

| 来源 | 原文裁定 | 现状 |
|---|---|---|
| 171n 归档「端点空态分叉」 | 判活 = `live_task status='running'` **∩ 心跳键新鲜**；僵尸 runner 不收——"命令下发给死进程=静默过期" | `_live_runners()` 符合 |
| 171o 归档「通道账号=复选按钮组」 | 数据源 = `trading_account` **enabled 行**；**默认全选**（紧急场景全量处置就绪） | `Emergency.vue:222` 符合 |
| 171o 归档「后端改动」 | accounts 过滤；过滤后空集 = 400 `NO_MATCH_ACCOUNT`；**无效 account_id = 400** | `risk.py:329` 用 **DB-only** 的 `live_running_tasks()` 判"无效"——**偏离 171n 口径** |
| 171o 归档「评审要点②」 | 勾选集不含某账号时该账号在途单仍在——**回执明示未处置账号** | 未落实：无任务账号直接 400，无回执 |

**结论**：两个设计裁定本身不矛盾——"默认全选所有启用账号"是**交互效率**裁定，
"无效账号 = 400"是**安全**裁定；冲突出在实现把"无效"定义成了 DB-only，
于是"启用但没跑任务"这种常态被误判为"无效"。本方案按裁定 A 把安全面从"拒绝"改为
"静默排除 + 明示"，既不推翻用户裁定，也消除必现 400。

## 3. 裁定 A 的语义

无任务账号被勾选时：**不报 400**；后端按 `_live_runners` 过滤后只对可处置账号下发命令，
在回执里列 `skipped_accounts`（未处置账号）及其原因（无运行任务 / 心跳死）；
前端默认只勾可处置账号，`!running` 的账号灰态标"无运行任务"。
理由：紧急场景第一目标是止血，不能因一个无关勾选拒绝整条命令；
且 171o 评审要点②已立"回执明示未处置账号"的约定——A 是落实该约定，不是新发明。

## 4. 实施方案（六面 DoD · 裁定 A）

| 面 | 内容 |
|---|---|
| ① 数据/契约 | 无新字段（`items[].running` 已存在）；回执增 `skipped_accounts`（仅展示态，不落库） |
| ② 写入判定 | **删** `risk.py:326-334` 的 DB-only 预校验；`_live_runners(accounts)` 一次判定；三态分叉基于同一结果；非空下发时把"勾选集 − 实际下发集"作为 `skipped_accounts` 随回执返回 |
| ③ 前端投影 | `Emergency.vue:222` 默认只勾 `enabled && running`；`!running` 账号灰态（沿用 `!enabled` 样式）并标"无运行任务"；保留"默认全选（可处置的）"裁定 |
| ④ 文案/回执 | 删除 `RISK_INVALID_ACCOUNT` 或改语义（不再出现"刷新重试"）；三语 i18n 同步；回执明示未处置账号；`apiErr` 保留 detail 回退展示 |
| ⑤ 测试 | ①无任务账号不阻断、不收到命令 ②僵尸账号不收且原因准确 ③回执列 `skipped_accounts` ④前端默认勾选只含 running ⑤三码分流边界 |
| ⑥ 文档 | 171o 归档加"实现修订"注记（不改原裁定）；本方案定型；待办/进展同步 |

**三态分叉重述（一次判定）**：
`runners = _live_runners(accounts)` —
空且无任何活 runner → 409 `RISK_NO_ACTIVE_RUNNER`；
空但存在活 runner（勾选集排除了它们）→ 400 `RISK_NO_MATCH_ACCOUNT`；
非空 → 下发，回执含 `skipped_accounts`。
不再有第三个基于 `live_running_tasks()` 的独立判定。
