# 紧急处置页方案（终稿 v7 · 账号校验 + 无限循环 + 进度看板 + 取消）

> 性质：账号校验纠偏（v6 已审透部分，**保留**）+ 处置模型重构（无限循环/取消/进度卡片，**新增**）。
> 依据：`批171n/171o/171s` 归档、`D12`、`risk.py`/`config_store.py`/`hub_worker.py`/`trading.py`/`Emergency.vue` 现状。
> **裁定沿革**：A → v3 三轮审 → v4 新裁定（running 即发）→ v4 双盲 → v5 → v6（phase 幂等/重发契约）
> → **v7（用户裁定：循环留 worker 内、无限循环直至成功/取消、UI 进度卡片、取消不 resume）**。
> **v7 关键简化**：循环留 worker 内无限跑 ⇒ 不存在"跨轮重发" ⇒ **删除 v6 的 phase 键与 `/api/risk/retry`**
> （v4/v5 两轮 P0 的全部来源自然消解）；取消标志取代重发成为新的控制面。

## 3. 核心设计

### 3.1 账号校验（v6 已审透，原样纳入）

- 删 `risk.py:326-334` 的 DB-only 预校验；**钉 `:335`**：`runners=[(tid,a) for tid,a in live_running_tasks() if accounts is None or a in accounts]`
  （二元组不变，manual-order 不受影响）；`:343` 409 文案改"无 status=running 的实盘任务"；
- 三态分叉（一次判定）：`running = live_running_tasks() ∩ accounts` —
  空且全局无 running → 409；空但全局有 running → 400 `NO_MATCH`；非空 → 下发 + skipped；
- skipped（无任务账号）忽略并回执明示：cmd 载荷带 `skipped_accounts`，经 `hub_worker.py:75-90` 透传 →
  `:final` → recent 可读（裁定 A，不改默认勾选、不改按钮 disabled）；
- 文案三语修正、"刷新重试"删除、`apiErr` 保留 detail。

### 3.2 无限循环改造（trading.py）

- **删除三个"自终止"条件**：`retry_max`（`:700`）、`deadline_ts`（`:223-226/700`）、`no_quote empty_max`（`:700`）
  对应的 `next_action` 分支（`:588-613`）收敛为仅两类终止：`final:done` / 用户取消；
- **保留一个真实故障终止**：`systemic_down`（valkey 全断，`:684-688/604`）——非人为上限，
  是取价链路不可恢复故障，转人工（告警 `emergency.valkey_down` + `final:systemic`），不无限空转；
- **循环开头检查取消键**（`:689 while True` 内首行）：
  `if _cancel_requested(req_id): final_reason="final:cancelled"; break`——
  `_cancel_requested` 读 `risk:cmd:cancel:{req_id}`，never-throw（读失败=未取消，继续）；
- **轮终止条件单一判源**：`next_action` 去掉三条计数/时限分支后只剩 systemic/done/cancelled，
  不新增第二处判定（守"判定只算一次"纪律）；
- **可中断 sleep**：轮间隔 `time.sleep(wait)`（`:879-880`）改为带取消检查的分段等待
  （每段 ≤0.5s，检查取消键），保证点取消后 ≤0.5s 响应，而非等满 5s。

### 3.3 取消机制（新增）

- **端点**：`POST /api/risk/cancel`，`Depends(require_perm("halt"))` 包裹（路由守门强制）：
  请求体 `{"req_id": "...", "tid": "...", "operator": "..."}`；
  校验 req_id 属于进行中任务（progress 键存在且无 :final）→ `SET risk:cmd:cancel:{req_id}=1`（TTL30min）+ audit_log；
  返回 `{"status":"cancelling","req_id":...}`；
- **worker 响应**：下轮循环检查到取消键 → break → `_final(cmd, result, interrupted=True)`（既有参数，
  `hub_worker.py:281`）写 `final:reason=final:cancelled` + SSE 零内容帧 → 前端重拉，卡片移除；
- **不 resume**：取消只停后续轮次，`risk:halted` 全局键保持（清仓前置已 halt），不自愈恢复——
  用户要恢复须显式点 resume（独立动作）。

### 3.4 进度看板（新增，UI 卡片）

- **进度键**：`risk:cmd:progress:{req_id}`（TTL30min），每轮覆盖写（`trading.py:855` 的
  `first_round_written` 点改为**每轮都写**，payload = 本轮 `out` 快照 + `round_no` + `verb` + `ts`）；
- **进度端点**：`GET /api/risk/progress/{req_id}`（`halt` 权限）：读 progress 键，无键或已有 :final →
  `{status:"done"|"unknown"}`；有键无终局 → `{status:"running", ...快照}`；
- **per-uid 进行中索引**：下发时 `risk:cmd:active:{uid}`（list of req_id，TTL30min，仿 recent 索引
  `risk.py:372-375`）；终局时移除；新增 `GET /api/risk/active`（halt 权限）供页面刷新重建卡片列表；
- **UI 卡片**：处置记录卡片（`Emergency.vue:35`）**上方**插入"处置状态卡片"：
  - 只列进行中任务（`/api/risk/active` → 逐个 `/api/risk/progress/{req_id}`）；
  - **两类逐单行**：待平仓 `pending`（`symbol:volume`，现成）、待撤单（撤单是每轮开头的前置动作，
    `_cancel_working_orders:335` **目前只返回计数无逐单清单**——本期按"撤单 N 笔/失败 M"聚合一行展示，
    逐单 symbol 留后续；如必须逐单需改 `_cancel_working_orders` 增带清单，列为可选增强）；
  - **实时**：onMounted 拉 active + 每 2s 轮询 progress（复用现有 SSE 终局帧触发立即重拉）；
  - **取消图标**：卡片标题栏 `×` 按钮 → `POST /api/risk/cancel`；
  - **完成/取消消失**：终局 SSE 帧 → 重拉 active（已移出）→ 卡片消失；记录仍在下方处置记录（recent 时间线）。

## 6. 一次上产与边界

- 六面同一次提交、同一次上产；禁止"先修后端、前端下一轮"。
- 不做：品种级细分、加密灰态、定时自动处置、取消 171o"默认全选"、改 manual-order 心跳口径、
  取消后 resume、Gate 收窄。
- **v6 机制退役**：phase 键、`/api/risk/retry`、`/api/risk/pending` 全部不实现——无限循环下无跨轮重发，
  这些是 v4/v5 两轮 P0 的产物，留着只会结构臃肿。
- 待办"心跳阈值口径分裂"开工时回填：下发侧消解（改 DB running）、展示侧保留（D12 告警）。
- **硬约束**：判定单源——下发判活只算一次（`live_running_tasks`）、循环终止只算一次（`next_action`）、
  取消只读一个键（`risk:cmd:cancel:{req_id}`）；不得以"简化"为由引入第二真源（v4/v5 教训）。
