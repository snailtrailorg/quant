## 3. 核心设计

### 3.1 账号校验（v6 审透，原样纳入）

删 `risk.py:326-334` 预校验；钉 `:335`：`runners=[(tid,a) for tid,a in live_running_tasks() if accounts is None or a in accounts]`（二元组不变，manual-order 不受影响）；`:343` 改"无 status=running 的实盘任务"；三态分叉（409/400/下发+skipped）；skipped 经 cmd 透传（`hub_worker.py:75-90`）写进 progress；文案三语修正、`apiErr` 保留 detail。

### 3.2 方案 A：payload 与执行参数解耦（v11 核心）

- **`_dispatch_risk_cmd` 改签名**（codegraph 实证仅 3 调用方）：
  `def _dispatch_risk_cmd(verb, *, accounts=None, username, operator_uid, wait_ack=True) -> dict`；
  函数体内 `payload["username"]`（`:340/364/389`）→ `username` 参数，`_operator_uid(payload)`（`:355`）→ `operator_uid` 参数；
  `wait_ack` 控制是否跑 5s 回执窗（web 同步= True，异步派发= False，避免空等）；
- **3 个 web 调用方适配**：`risk_halt:205` 传 `username=payload["username"], operator_uid=_operator_uid(payload)`；
  `risk_cancel_all:485`、`risk_close_all:506` 同；行为零漂移（Web 仍即时拿 `r.cancel`/`r.results`）；
- **异步派发方（halt_dispatch）适配**：从 reason 解析 `username`（`飞书:张三` → `飞书:张三` 原样做显示名）、
  `operator_uid`（非 web 源无 uid → None，看板按 source 分组展示而非 uid；web 源有 uid 走 uid 索引）；
- **manual-order 不动**：`_dispatch_manual_cmd`（`:587`）不依赖 `_dispatch_risk_cmd` 签名，保留。

### 3.3 触发执行解耦 + 去重标记

- **`emergency_halt(reason)` 改造**（`risk_control/risk.py:159-165`）：置 3 键后
  `LPUSH risk:halt:trigger {reason, source, halt_ts, username, operator_uid, sync_dispatched}`（持久化 List，非 pub/sub）；
  source 从 reason 前缀解析（`Web:`/`飞书:`/`close-all:`/`LLM:`，无前缀归 `system`）；never-raise；
- **web 路径保留同步派发**（解决 v10 单审 P0-1）：`risk_halt` 仍即时调 `_dispatch_risk_cmd("cancel-all", ..., wait_ack=True)`
  返回 `r.cancel` 给前端；同时 `emergency_halt` 发事件带 `sync_dispatched=true`；
- **飞书/close-all/LLM 路径**：只 `emergency_halt`（`sync_dispatched=false`），由异步消费者派发；
- **`halt_dispatch` 高频任务**（新增，`app.py` beat 2s，`queue=risk`）：LPOP 消费 trigger →
  若 `sync_dispatched=true` 跳过（web 已派）；否则 SETNX `risk:halt:dispatched:{halt_ts}`（TTL5min，去抖）→
  调 `_dispatch_risk_cmd("cancel-all", ..., username, operator_uid, wait_ack=False)` → 建 progress 事务；
- **为什么 2s 不用 risk_sweep**：`risk_sweep` 是 60s（`app.py:193`），紧急场景延迟不可接受；2s 独立任务即时性够且隔离；
- **沿兜底降级**：`halt_edge_cancel`（`hub_worker.py:1034`）保留为"事件→worker 投递"之间的即时止血（每 runner 撤自己单），
  不承担可见性；其撤单被随后统一命令的撤单覆盖（幂等）。

### 3.4 增量进度看板（旧链保留）

- **键族**：`progress:{req_id}`（含 `items:[{symbol,kind:cancel|close,status,detail,volume}]`、`phase:running|done|cancelled|systemic`、`operator`(reason)、`round_no`、`ts`、`skipped_accounts`）、`active:{uid}`（web 源）/ `active:src:{source}`（非 web 源）、`cancel:{req_id}`（TTL30min）；
- **写口** `trading.write_progress`（never-raise，**独立于** `write_cmd_result`）；旧链全保留（manual-order + web 5s 窗 + 历史时间线）——两链职责不重叠、各一真源；
- **端点（新增，`Depends(require_perm("halt"))` + 路由守门）**：`GET /api/risk/active`、`GET /api/risk/progress/{req_id}`、`POST /api/risk/cancel`（按批次取消）；旧端点不动。

### 3.5 逐单状态（撤单 + 清仓）

- 撤单：`_cancel_working_orders`（`trading.py:335-368`）增 `items:[{symbol,vt_orderid,result:requested|failed|untranslatable}]`，保留计数；归并为 progress 的 `kind:cancel` 行，**untranslatable 进 status 枚举**（三语补词条）；
- 清仓：`_close_all_positions` 每轮 `pending/no_quote/rejected/skipped_t1/closed_requested`（`trading.py:666-674/689-888`）归一为 `kind:close` 行，各自 status 语义保留；
- 三源（web/飞书/LLM）经统一派发后都进看板，操作者 = reason（已含 `飞书:张三`）。

### 3.6 无限循环 + 取消（方向反转）

- `next_action`/`retry_due`/`bump`（`trading.py:584-638`）改签名：删 retry_max/deadline/empty_max，仅 systemic/done/cancelled；调用点 `trading.py:866/875` 同步改；`test_batch171s.py:478-489` S5 断言整段重写（三终止 → 不因计数停+取消即停）；
- 171s 归档 `:16/:98` 与 D12 相关节**整篇重写**（状态文档重写制）；
- 循环首行检查取消键（`:689 while True`）；轮间隔 sleep（`:879-880`）分段可中断（≤0.5s）；取消只停后续轮次，halted 保持（不 resume）；
- 取消粒度：按 operator+批次 ts 取消同批全部 req_id（`risk.py:359-367` 一次下发多 id）。

### 3.7 UI 看板

- `Emergency.vue:35` 上方插入"处置状态卡片"：active(+src) → 逐 req_id 拉 progress；
  - 一个表两类行（cancel/close），每单 status/detail；显示操作者（reason，如 `飞书:张三`）；
  - onMounted 拉 active + 每 2s 轮询 + SSE 终局帧立即重拉；标题栏取消图标 → `POST /api/risk/cancel`（按批次）；
  - 终局 active 移除 → 卡片消失；历史记录走既有 recent 时间线（不动 loadRecent）；
  - 三语：新增 status + 取消按钮 key，zh/en/zh-TW 全覆盖，`§5` 加 key 集合相等断言。

## 6. 一次上产与边界

- 六面同一次提交、同一次上产；禁止"先修后端、前端下一轮"。

- **方向反转落地**：无限循环 + 触发执行解耦须**整篇重写** 171s 归档与 D12 相关节（状态文档重写制），禁加注记式补丁。
