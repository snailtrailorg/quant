# 紧急处置页方案（终稿 v8 · 账号校验 + 统一进度事务 + 逐单状态 + 无限循环 + 取消）

> 性质：账号校验纠偏（v6 审透）+ 处置模型统一重构（进度/逐单/取消/无限循环）。
> 依据：`批171n/171o/171s` 归档、`D12`、`risk.py`/`config_store.py`/`hub_worker.py`/`trading.py`/`Emergency.vue` 现状。
> **裁定沿革**：A → v3 三轮审 → v4 → v5 → v6（phase/重发）→ v7（无限循环/取消/进度卡片）
> → **v8（用户裁定：撤单与清仓都逐单进卡片、统一处理、无用旧机制退役）**。
> **v8 关键**：三种操作（撤单/熔断/清仓）统一走 `_dispatch_risk_cmd` → 统一进度事务；
> 退役 v6 的 phase/retry/pending、退役主回执键与 `:final`/recent 三套并存（合并为一个进度键族）；
> 保留 `halt_edge_cancel` 沿检测（安全兜底，非重复造轮）。

## 0. 三问（前置 · v8 终版）

1. **真源层**：
   - **下发判活** = `live_task.status='running'`（`config_store.py:176-182`），不看心跳；
   - **展示健康度** = `risk_exposure.running`（`risk.py:444/457`，DB∩心跳），仅展示；
   - **进度/逐单/终局真源** = 统一进度键 `risk:cmd:progress:{req_id}`（**v8 唯一**，替代旧主回执键 + `:final`）；
   - **进行中索引** = `risk:cmd:active:{uid}`（新增，替代 `risk:close:recent:{uid}`）；
   - **取消真源** = `risk:cmd:cancel:{req_id}`（新增）。
2. **全部消费者**（逐个核实）：
   - 下发统一入口：`risk.py:309 _dispatch_risk_cmd`；撤单按钮 `:195` 区、熔断 `:192-211`（内部调 cancel-all）、
     清仓 `:505`（preamble halt 后调 close-all）——**三种操作都经此入口**（熔断的 web 路径与撤单同链）
   - 熔断沿兜底：`trading.py:317 halt_edge_cancel` ← `hub_worker.py:1031`（主循环钩子，沿检测，
     防非 web 来源 halted；无 req_id，不入卡片——它撤的正是 web 路径同时在撤的在场单）
   - 撤单执行：`trading.py:335 _cancel_working_orders`，4 消费者（`hub_worker.py:201/212`、`trading.py:331/691`）
   - 清仓循环：`trading.py:638-888`（无限循环改造对象）
   - worker 回执：`hub_worker.py:242-312`（`_handle`/`_final`/SSE 帧）
   - 回执端点：`risk.py:512-583`（recent + 单查）；前端 `Emergency.vue:103-168/210`、`api.js:30-39`
3. **既有机制取舍**（"没用的退役"）：
   - ✅ 复用：`_dispatch_risk_cmd`（统一入口）、`req_id` 生成、`halt_edge_cancel` 沿兜底、SSE 零内容帧；
   - ❌ 退役：v6 `risk:cmd:phase:{req_id}`、`/api/risk/retry`、`/api/risk/pending`（无限循环下无跨轮重发）；
   - ❌ 退役：旧主回执 `risk:cmd:result:{req_id}` + `:final` + `risk:close:recent:{uid}` 三套并存 →
     合并为单一 `progress` 键族（进行中 + 终局同键，用 `phase` 区分）；
   - ❌ 退役：`_ack`（`hub_worker.py:274`）的 cancel-all 专用即时回执（统一由 progress 写口产出）。

## 3. 核心设计

### 3.1 账号校验（v6 审透，原样纳入）

删 `risk.py:326-334` 预校验；钉 `:335`：`runners=[(tid,a) for tid,a in live_running_tasks() if accounts is None or a in accounts]`
（二元组不变，manual-order 不受影响）；`:343` 改"无 status=running 的实盘任务"；三态分叉（409/400/下发+skipped）；
skipped 经 cmd 载荷透传（`hub_worker.py:75-90`）写进 progress；文案三语修正、`apiErr` 保留 detail。

### 3.2 统一进度事务（v8 核心）

- **统一键族**：`risk:cmd:progress:{req_id}`（TTL30min）——一个键承载进行中 + 终局：
  ```
  {req_id, verb: cancel-all|close-all, operator_uid, phase: running|done|cancelled|systemic,
   items: [{symbol, kind: cancel|close, status: requested|failed|no_quote|rejected|skipped|pending,
             detail, volume}], round_no, ts, skipped_accounts}
  ```
- **统一写口**：`trading.write_progress(req_id, verb, items, *, phase, ...)`（never-raise，仿 `write_cmd_result:565`）——
  所有执行体（cancel-all 撤单、close-all 每轮）都调它，**不再有第二处回执写**；
- **统一索引**：`risk:cmd:active:{uid}`（list of req_id，TTL30min，仿旧 recent 索引 `risk.py:372-375`）——
  下发时登记、终局时移除；新增 `GET /api/risk/active`（halt 权限）供页面刷新重建卡片；
- **统一端点**：`GET /api/risk/progress/{req_id}`（halt 权限）——有键返快照、终局返终态；
- **统一取消**：`POST /api/risk/cancel`（halt 权限）写 `risk:cmd:cancel:{req_id}`；三种操作统一响应。

### 3.3 逐单状态（撤单 + 清仓）

- **撤单逐单**：改 `_cancel_working_orders`（`trading.py:335-368`）返回增
  `items:[{symbol, vt_orderid, result: requested|failed|untranslatable}]`，保留原计数字段（4 消费者兼容）；
  worker 的 `_cancel_all`（`:201`）与清仓前置撤单（`:212`）/每轮撤单（`:691`）把 items 归并为 progress 的 `kind:cancel` 行；
- **清仓逐单**：`_close_all_positions` 每轮已有 `pending`(symbol:volume)/`no_quote`/`rejected`/`skipped_t1`/`closed_requested`
  （`trading.py:666-674/689-888`）——归一为 `kind:close` 行，与撤单行同表展示；
- **熔断**：web 路径经 cancel-all 下发（`risk.py:204`）⇒ 天然走统一进度事务，逐单进卡片；
  沿兜底（`hub_worker.py:1031`）无 req_id，不入卡片（其撤的是 web 路径同时在撤的在场单，结果由 web req_id 体现）。

### 3.4 无限循环 + 取消（承 v7）

- 删 `trading.py` 的 `retry_max`/`deadline`/`no_quote empty_max` 三自终止（`:700` + `:588-613` 收敛），
  仅留 `final:done`/取消/`systemic_down`（valkey 全断真实故障转人工）；
- 循环首行检查取消键（`:689 while True` 内）；轮间隔 sleep（`:879-880`）改分段可中断（≤0.5s 检查一次）；
- 取消只停后续轮次，`risk:halted` 保持（不 resume）。

### 3.5 UI 统一卡片

- 处置记录卡片（`Emergency.vue:35`）**上方**插入"处置状态卡片"：列 active 索引全部 req_id → 逐个拉 progress；
  - **一个表、两类行**：`kind:cancel`（待撤单）/ `kind:close`（待平仓），每单一行的 status/detail；
  - **实时**：onMounted 拉 active + 每 2s 轮询 progress + SSE 终局帧立即重拉；
  - **取消图标**：卡片标题栏 `×` → `POST /api/risk/cancel`；
  - **完成/取消消失**：终局写 active 移除 → 重拉 → 卡片消失；记录仍进下方处置记录时间线。
