# 选股器多因子化方案（待定稿 v1——2026-11-02 立项讨论稿）

> 用户诉求：灵活选股、愿付学习成本；参考业界通用规则。
> 结论先行：**不造新语言——复用策略 DSL 因子引擎，加「横截面模式」**；品类参数分而治之原则不变。

## 一、业界范式对照（我们取什么）

| 业界 | 范式 | 借鉴点 |
|---|---|---|
| 果仁网 | 可视化条件组合+排名选股 | 排名（Rank）与过滤（Filter）分离 ✔ |
| 聚宽/JoinQuant | get_fundamentals(query+过滤器)+因子表达式 | 表达式即筛选条件 ✔ |
| QuantConnect / WorldQuant alpha | 表达式因子+横截面 rank/neutralize | 同语言「时序因子→横截面选股」复用 ✔ |

**通用心智模型**（教学成本一次，受益所有品类）：

```
候选宇宙（SM category 注册面）
  → 过滤 Filter（硬条件：pe<30 AND circ_mv>20亿——淘汰不合格）
  → 排名 Rank（软条件：按 (momentum_20d)*0.6 + (1/pe)*0.4 加权排——选最优 N 只）
  → 池（pools 落地，策略绑定）
```

## 二、架构：DSL 引擎双模式（核心决策）

现有 `_safe_eval`（AST 白名单）+窗口函数（mean/std/rsi/slope/ema/avevol）已服务**时序因子**（单标的 K 线上下文）。
新增**横截面模式**：同一表达式语言，上下文从 BarContext 换成 CrossSectionContext——
每标的一行，字段=daily_basic 列+窗口因子预计算列。

- 复用：表达式解析/安全沙箱/函数白名单（零新解析器）
- 新增：`rank(expr)`/`top(N)`/`quantile(x, 0.2)` 三个横截面函数+预计算管道
- 品类扩展：字段集按 category 注册（astock: pe/pb/mv/…；cb: double_low/premium/…）——**与 DataKind/SM 注册机制同构延伸**

## 三、能力分级（学习成本阶梯——用户「愿意学习」的兑现面）

**L1 简单模式**（现三屏强化——零学习成本）
- A股屏开闲置字段：pe_ttm/circ_mv/dv_ratio/ps + ST 过滤 + 上市天数过滤（零成本项）

**L2 条件构建器**（果仁式——低学习成本）
- Filter 行式编辑：字段/操作符/值，AND 组合，字段集按品类注册动态出
- 保存为「筛选方案」（screen_preset 表）可复用可分享

**L3 DSL 表达式选股**（聚宽式——本方案核心增量）
- Filter=表达式（布尔）：`pe > 0 && pe < 30 && rank(momentum_20) > 0.8`
- Rank=表达式（数值）+权重：`(zscore(momentum_20)) * 0.6 + (zscore(dv_ratio)) * 0.4`
- 窗口因子直达：`mean(close,20)/mean(close,60) > 1.05`（动量）
- 与策略因子同一语言：学一次，两处用

## 四、实施分期（每期独立可用）

| 期 | 内容 | 成本 | 价值 |
|---|---|---|---|
| 1 | L1 零成本参数（A股 6 项）+cb/fund 各补 2 项 | 0.5 天 | 立即可用 |
| 2 | L2 条件构建器+screen_preset | 2-3 天 | 中级用户覆盖 |

| 4 | 池快照对比/调仓信号（池变化 diff→告警/策略通知） | 2 天 | 实盘衔接 |

## 五、与注册机制的关系（上轮结论重申）

- 品种注册（DataKind/SM category）不动——横截面字段集按 category 挂（screen_field_registry，新注册面但同构：加品类=加字段集行+测试断言）
- pools/pool_symbols 不动——输出还是落池
- 三屏骨架不动——L1/L2 长在三屏上，L3 是「表达式」页签（第四页签，Screener 容器页扩展）

## 六、风险面

- 预计算性能：全市场 5000+ 标的×窗口因子——预计算管道（SQL 窗口函数优先，Python 兜底）+缓存（池生成时算一次，非每查询）
- DSL 沙箱逃逸：_safe_eval 白名单已立（500 字符限+AST 白名单）——横截面函数入白名单即受同一沙箱
- 前视偏差：横截面取数统一「截至 T-1 收盘」口径（选股在盘前/盘后跑，不用当日未完成数据）
