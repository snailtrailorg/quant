## 一、审计口径

**检查类任务定义**：含 assert / fail / failed_when / 断言 / 校验 / 门 / 守卫 / 白名单 / 绝对路径锚定（LLM 防幻觉）/ fail-closed 语义的任务。纯动作任务（rsync / copy / command 动作 / set_fact 无校验语义 / file 状态）不在审计范围。debug 通告任务（告警/留痕语义）**计入**——它们是闸门体系的组成部分（force 留痕、DDL 旁路留痕）。

**边界裁决（复审重点）**：
- **判定类 set_fact 计入**（`server_changed` / `units_changed` / `req_changed` / `in_window` / `trade_cal_known` / `is_trading_day`）：它们是断言的判据源，删了或判错，下游断言全部失真。纯搬运 set_fact（如 `pinned_before_flat` 固化、`deploy_task_units_live` 解析）不计。
- **探针类任务计入**（healthz / readyz / _probe / pinned / hbcheck / dbro / 磁盘 / rsync 在位）：探针即检查，只是失败语义不同（有的 fail-fast，有的 failed_when:false 吞没后由断言消费）。
- **DDL 门四任务组**（L392/405/413/421 + 联动 L430）计为 **5 条独立条目**：功能不同（门/旁路告警/首部署告警/留痕落盘/联动置位）非重复。
- **rescue 收尾 fail: 计入**（L475/L693）：它们是不变量④（退出码语义）的直接实现。
- **GC 计入**：GC 的孤儿判定/钉住跳过/通道故障 fail-safe 全是守卫逻辑（GC 误删在跑版本是实事故级风险）。
