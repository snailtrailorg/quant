## 2. 三链现行为语义（逐条为 P1b 必须保持的契约）

### 2.1 交易链（下单 → WAL → 发单 → 成交）

| # | 行为 | 锚点 |
|---|---|---|
| T1 | 信号量/价 ≤0 **直接丢弃**，不落任何账 | `strategy_framework/strategy.py:446-449` |
| T2 | SELL **统一截断到可卖仓**（含 0；截断后仍按流程走，不因 0 提前 return） | `strategy.py:455-464` |
| T3 | 风控拒绝=直接 return（不落账、不发单） | `strategy.py:479-483` |
| T4 | **先写 `signal_log` + `order_log(status='submitting')` 再发单**；写失败 fail-closed 弃单 | `strategy.py:485-495`、`:522-563` |
| T5 | `send_order` 抛异常 → `order_log.status='send_failed'` + `error`，异常继续上抛 | `strategy.py:496-506` |
| T6 | `send_order` 返回空委托号 → `send_failed`（error=「adapter 返回空委托号」）+ return | `strategy.py:509-516` |
| T7 | 成功 → `submitted` + `client_order_id` + `vt_orderid`（`COALESCE`，未传不覆盖旧值） | `strategy.py:519-521`、`:566-593` |
| T8 | 急停单审计：`INSERT order_log(... status='submitting', strategy_id='emergency-close', client_order_id=emc-{req}-{sym}-{seq})` **在 send 之前**；失败 never-raise 仅 warning | `trading.py:353-377` |
| T9 | 急停终态回填 `_close_order_mark`：`vt_orderid=adapter.get_vt_orderid(cid)`（None 写 NULL）；`WHERE status <> ALL(all_traded/cancelled/rejected)` | `trading.py:379-401` |

### 2.2 回报链（EVENT_ORDER → order_log 终态）

| # | 行为 | 锚点 |
|---|---|---|
| R1 | 映射：`PARTTRADED→partial`、`ALLTRADED→all_traded`、`CANCELLED→cancelled`、`REJECTED→rejected`；`SUBMITTING/NOTTRADED` **不回写** | `trading.py:70-84` |
| R2 | 关联键两步：先 `vt_orderid` 取**最新**一行（`ORDER BY id DESC LIMIT 1`）；无行再在 `adapter._lock` 下 `_vt2cid` 反查 `client_order_id` | `trading.py:86-104` |
| R3 | 只进不退：`UPDATE ... WHERE id=%s AND status <> ALL(终态集)`；同值 UPDATE 幂等 | `trading.py:108-112` |
| R4 | 无关联行 → warning 后 return；任何异常 → warning，**never-raise** | `trading.py:105-107`、`:115-116` |
| R5 | EVENT_ORDER 消费成功后发**零内容** SSE 帧 `order_update`（失败 fail-open 不阻断） | `main.py:355-366`、`tests/test_batch69.py:21` |
| R6 | EVENT_LOG 只写日志 `[gw] {msg}`（不落库） | `main.py:347-352` |

### 2.3 成交链（EVENT_TRADE → trade_log）

| # | 行为 | 锚点 |

## 3. P1b 等价对照用例（必须逐条钉住）

> 形式：同一事件序列分别喂「旧实现（`_legacy_*` 保留副本）」与「新 domain/port 链」，比对 **DB 行 + 状态序列 + 返回值/告警**。以下每条至少一个断言，禁 `inspect.getsource` 字符串断言。

| 组 | 用例 | 输入 | 期望（与现行为一致） |
|---|---|---|---|
| 状态映射 | 四终态 | `Status.PARTTRADED/ALLTRADED/CANCELLED/REJECTED` | `partial/all_traded/cancelled/rejected` |
| 状态映射 | 非推进态 | `SUBMITTING/NOTTRADED` | 不 UPDATE（0 行变更） |
| 只进不退 | 迟到 partial | 已 `all_traded` 后再喂 PARTTRADED | 仍 `all_traded` |
| 关联键 | vt 命中多行 | 同 vt 两行（id 1/2） | 只改最新 id=2 |
| 关联键 | cid 回落 | vt 无行、`_vt2cid` 有映射 | 按 cid 命中 |
| 成交落库 | 正常 | LONG 100@10，trade_ref=T1 | 1 行 BUY，order_id/strategy_id/account_id 正确 |
| 成交落库 | 幂等 | 同 trade_ref 再喂 | 仍 1 行（DO NOTHING） |
| 成交落库 | vt 反查 | cid 未命中、vt 命中 | order_id 正确 |
| 撤单 | 只撤在场 | 4 单：SUBMITTING/NOTTRADED/PARTTRADED/ALLTRADED | `requested=3`，终态单不被 `cancel_order` |
| 撤单 | 单笔失败 | `cancel_order` 抛异常 | `failed=1`，循环继续，不抛 |
| 熔断沿 | 无沿 | true→true / false→false | 不撤单 |
| 对账 | 在场委托 | query_orders 返回 2 笔 working | 仅告警，**不调用 cancel_order**；成交逐笔补录 |
| 事件接线 | 三事件 | EVENT_LOG/EVENT_ORDER/EVENT_TRADE | 日志 1 条 / 终态回写+order_update / trade_log+trade_update |
| 身份 | 空 vt | `get_vt_orderid` 未命中 | `vt_orderid` 写 NULL，不冒充 cid |
| hub 生命周期 | 四调用 | start_ready/connected/poll_supervise/event_threads_healthy | 调用次数与时序与 §2.6 一致 |
