# 批175f · 标的显示口径全面普查（2026-11-14）

> 触发：用户指出「实盘交易看板持仓标的只有标的代码」——系统内一律应是 `代码.交易所` 形式，边界转换。
> 结论：**上轮检查方法有结构性漏洞**；本轮修显示层，另发现 2 处**数据层**口径未闭环。

## 一、为什么上一轮漏掉了（4 条根因）

1. **检查维度缺"显示层/消费层"**：我的 C1–C8 只覆盖「入站边界 / 持久化 / 读侧 SQL / 守门 / 迁移」，把"接口返回 canonical ⇒ 界面显示 canonical"当成了默认事实。
2. **验证止于接口，没到渲染**：我用 `/api/position` 看到 `.SHSE` 就判定通过，**没有打开 Vue 模板看渲染表达式**。
3. **搜索模式偏了（最关键）**：我搜的是"**错误后缀**"（`.SSE`），没搜"**丢后缀**"的惯用写法（`.split('.')[0]`）。同一缺陷的两个方向，只搜了一边。
4. **见到可疑信号没顺链**：`web/src` 里 `EX = { SH:'SHSE' … }` 被我判为"UI 入参转换"就放过，没看它旁边的列模板正在剥后缀。

## 五、结论与后续判据

- **"显示层"与"派生表"必须作为独立检查维度**，不能由"接口正确"推断。
- 口径普查必须**双向搜索**：错误后缀（`.SSE`/`.SH`）+ 丢后缀（`.split('.')`/裸码），并且**读渲染模板**而非只看 API。
- 后续任何"归一/迁移"批次，验收清单固定加两条：① 界面实际渲染（截图或模板核对）② 派生表与状态表口径一致。
