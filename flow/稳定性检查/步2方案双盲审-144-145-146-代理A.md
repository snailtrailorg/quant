## 批 144 · 僵尸复位误报根治

### 锚点核实（全中）

| 任务书锚点 | 实核 | 判 |
|---|---|---|
| engine.py:217-221 `_mark_running` 只 UPDATE last_status 不刷 ts | :217 def，:219 UPDATE 单 last_status | ✅ |
| tasks.py:782-802 僵尸判定 ts 龄>7200s 复位、NULL 同判 | :781-802 实证，阈值 :792 `_age > 7200` | ✅ |
| tasks.py:875-877 async 派发（SyncLock 吸收重复派发） | :875 apply_async；SyncLock 吸收在 engine.sync():360（lock 未获→skipped） | ✅ |
| okx ~59s 不跨轮 | 无法本地核（prod journal），任务书已注出处 | 采信 |

### 根因链判定（成立）

确认：`sync()` 内 `_mark_running(True)`（engine.py:366）置 running 后，终态 `_update_sync_state`（:265）才刷 ts。运行期间 ts 停留在**上一轮终态时刻**（昨日晨档）→ 调度轮内 `age>7200` 成立 → 误报。修法「running 置位同刷 ts」使锚点对齐，判定逻辑零改动——**方案闭合**。

### P1-144 · running 分支刷 ts 的两个次生影响（须处置，不阻塞）

**1. 半夜故障任务的「未到周期」逃逸（低概率）**：调度器用 last_sync_ts 作 cron base（tasks.py:831 `base = last_sync_ts…`）。若任务 00:30 启动后僵死（真僵尸），次晨 08:3x 被复位 idle；但下一轮 beat 读到的 ts 仍是 00:30 置位时刻，croniter 从 00:30 起算 → next_run 已过 → **立即补触发**。这是修后新增行为（旧 ts 停昨日，同样会补触发——实际旧形态更糟：连补带误报）。结论：非回归，方向同旧，**不阻塞**。
**2. 前端展示语义漂移**：DataManage.vue「同步时间」列直读 last_sync_ts——running 中显示「now」而非上次成功时刻。属可接受语义（「活跃时刻」），无需改代码，建议在 tasks.py 注释（产出 2 那行）顺带一提，防后人误当前端 bug。

### 验收可执行性

验收 1/2 可执行；验收 3 依赖上产后观察（观察窗内顺带），合规。新增三钉（SQL 文本断言/真僵尸仍复位/running+10min 不复位）mock 路径可行（engine.get_conn MagicMock 捕 SQL——任务模板 §四先例齐）。

**结论：过门。** P1-144 建议在注释行处置，编码时落即可。

## 批 145 · data_continuity_check 时限显式声明

### 锚点核实（全中）

- 批 110·D 先例：tasks.py:1722-1724 `data_gap_reconcile` `soft_time_limit=1800` + docstring 显式声明制。✅

### P1-145 · 「软限继续跑完不熔断」的机制表述反了（**须改任务文件一行**）

任务书现状#2 称「SoftLimitExceeded 告警后**继续跑完不熔断**（billiard 软限语义=信号可捕获，任务代码未捕则直达完成）」。实核任务体（tasks.py:553-647）：**SoftLimitExceeded 在抛出点直接炸掉任务**——补采段 `except Exception as e: issues.append(f"{symbol} 补采失败…")`（:635-636）**恰好把 SoftLimitExceeded 一并吞掉**（它继承 Exception），任务带着半程数据继续跑到完成态、返回 `status: ok`。即真实机制=「软限信号在补采段被宽泛 except 捕获吞掉→任务跑完」，不是「未捕则直达完成」。判定影响：**初值选择与验收不受影响**（2400>2093 峰值仍正确，验收 3 仍可验），但 docstring 若照任务书表述写会把错误机制观传播给后来者（本批目的恰是消除沉默态）。**修法**：产出 2 docstring 两行改为「实测 1664~2093s；软限在补采段被 except Exception 吞除（tasks.py:635），soft=2400 后该告警面消失」；校准规则照旧。

### 其余判定

- 初值 2400/2700：软 40min 档，仓内序列（320/1800/3600/7200）合理插位，>峰值 2093s 留 ~15% 软余量。硬限 2700=软+300 同制。✅
- 限定范围：一处装饰器+docstring，最小面。✅
- 无新测试合理（纯装饰器参数，任务模板允许）。✅

**结论：有条件过门**——按 P1-145 改 docstring 表述后进编码（改动一行文字，不必重审）。
