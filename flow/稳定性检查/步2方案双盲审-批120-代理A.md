# 批 120 · 安全态势页 —— 步 2 方案双盲审（代理 A）

> 判据：`flow/规范/八步法.md` 步 1/2 + `flow/规范/任务模板.md`。只读评审，2026-10-11。

## 总评

方向正确（一次性排查转持续自动化，复用 health_monitor/llm_gateway 成熟框架），锚点 5 条抽核 3 条全实。但任务文件存在**一处契约不闭合（调度通道自相矛盾）**与**一处执行不可达面未处理（特权命令无通道方案）**，另有一个数据源缺口（severity 无来源）会直接返工前端 C 区。方案级缺口集中在「采集器怎么跑」这一执行层，恰是批 120 的核心风险面——任务文件通篇没有回答。

## P0（致命）

### P0-1 调度通道自相矛盾：sync_config 行 vs 全局 300s 软超时（契约不闭合）

任务文件 §产出 6 说「sync_config 加 `security_scan` 行（每日 06:00，`supports_backfill=false`）」。但：

- `scheduler/app.py:133` 全局 `task_soft_time_limit=300`（5 分钟）。security_scan 含 pip-audit 全量（任务背景自述「3-4 分钟」）+ dnf check-update（prod 实测可达数十秒）+ 多条 subprocess——**必然逼近/超 300s 软超时**，celery `SoftTimeLimitExceeded` 直接杀任务。
- sync_config 驱动的执行路径 `data_sync_scheduler`（`scheduler/tasks.py`，`sync-scheduler` beat 300s 唤醒）到点**同步调用** `sync(sid)`——一个 3-4 分钟的采集任务挂在 300s 周期的调度 beat 里跑，还会顶住 data 队列的常规数据同步轮。
- 仓内已有先例裁定（批 109，`scheduler/app.py:140-147`）：**对账非拉取 ⇒ 走 beat 独立条目，不进 sync_config**。security_scan 同理：无游标、无 backfill、无 provider——进 sync_config 是复用了错误的模板，与批 109 裁定相悖。
- 且 sync_config 行必须有 `engine._HANDLERS` 注册的 handler（`data_sync/engine.py`：「无 handler 路由」即 error）——security 采集器放 health_monitor 目录、handler 放 data_sync.engine，跨模块寄生，方向拧了。

**修法**：beat 独立条目（先例 data-gap-reconcile/`app.py:135-139` sm-reconcile）+ 独立 celery 任务显式 `soft_time_limit` 覆盖（先例 `pool_data_sync_task` 320/`adj_factor_backfill_task` 7200，`tasks.py` 均有）。

### P0-2 特权命令执行通道缺失（执行不可达）

采集面三条命令需要 root 或等价权限，任务文件零方案：

- `dnf --security`（含 `dnf check-update --security`）：查询不写库但仍需 root（dnf 锁 + repo 元数据权限）。
- `sshd -T`：**必须 root**（读全部生效配置，非 root 直接报错）。
- `ss -tlnp` 的 `-p`（进程名）：非 root 拿不到别进程的进程信息。

采集器运行身份：若随 celery worker（quant 用户，无 sudo——deploy/wrappers 12 只特权通道里无 dnf/sshd 类）⇒ **三条命令全部静默失败**。本仓「禁直接 ssh/scp、一切经 deploy wrapper」+ sudoers 白名单唯一真源是 `deploy/wrappers`——新增特权通道=改部署架构（A06 §9 炸半径清单管辖），必须方案层显式声明，不能编码时才撞。降级方案（grep `/etc/ssh/sshd_config` 文本、`ss -tln` 去 -p）是权限边界内的可行路径，但任务文件一字未提，验收标准里「findings 与 dnf 输出一致」就成了按给定方法测不到的验收（八步法「验收可验性预审」不过）。

**修法（二选一，方案须写明）**：a) 降级为 quant 可读面——`sshd_config` 文本解析（含 Include 展开）+ `ss -tln` 无 -p + dnf 项改由既有部署日志/`quant-pinned` 通道取数或标「不可采集」；b) 立项新增特权 wrapper（进 sudoers 白名单 + A06 变更流程）——本批先降级、二期随 AIDE 一起做特权面。

## P1（严重）

### P1-1 severity 数据源缺口（会返工）

`security_finding.severity` 列 + 前端 C 区「severity 降序/分色/筛选」+ A 区「按 severity 分色点」——但 pip-audit 默认 JSON 输出**无 severity 字段**（包/版本/漏洞 ID/修复版，任务文件 §产出 1 自己列的字段清单里也没有 severity）。dnf --security 输出同样无 severity。C 区排序/分色/A 区计数全部悬空。待裁点②的方向（OSV API 直查 / 弃 severity 用 PYSEC 编号序）须在方案定稿，不能留到编码。

### P1-2 基线 diff 抑制策略缺失（会返工/告警疲劳）

「新增 pip 包」判据：开发机装新依赖 → 部署 → 次日基线 diff 必响。这本身是设计意图（环境漂移检测），但**requirements 声明的合法升级与未声明漂移不分** ⇒ 每次正常发版都告警，静止绿承诺破产（告警疲劳=告警通道失信）。修法：diff 时与 requirements.lock（deploy 已指纹化，`release.yml:340`）比对——声明内的版本变化降级为「组件变更」记录不告警，lock 外的新增包才告警。任务文件「长期不动高危项置顶」同理依赖 first_seen 语义成立，须一并定义。

### P1-3 范围与「≤3 文件」模板约束冲突未声明

模板 §三「限定范围 ≤3 文件」。本批：采集器新文件 + 两张表迁移 + engine/beat 或独立任务注册 + 两 API 路由 + perm_registry（见 P1-4） + Observe.vue/新组件 + 前端 i18n——**≥7 文件跨前后端**。八步法 W7 有大施工切批先例，但任务文件**既未拆步也未声明豁免**。不算现状失实，但按模板是硬伤，须补一句拆步声明（如：后端采集+表 = 批 120a，前端 Tab = 批 120b）或显式豁免理由。

### P1-4 新增 API 权限键连锁未写

两新端点「read 权限」——挂既有 `read` 键则无需动注册表（可行）；但若按同类监控端点惯例需要专属键，则触发「新 perm 键四条齐动」连锁（perm_registry.py:43 + 批 77 P0 迁移 0126 先例 + 前端 permGroups）。方案应钉死「复用 `read`」还是「新增键+迁移」——当前「read 权限」三个字不足以让读者免翻代码判工作量。倾向钉死复用 `read`（监控读面，无越界风险）。

## 一般

1. **06:00 时刻可行性**：核过 beat 全表（`scheduler/app.py:133-233`）——03:33 data-gap-reconcile（周日）、04:00 备份窗（低峰注释可证）、06:51 broker-health。06:00 无冲突；pip-audit 3-4 分钟 + risk 队列 `-c 1` 若 security_scan 入 risk 队列会阻塞 30s 周期的 health-monitor 轮——**须投 data 或独立队列**（P0-1 修法顺带定）。
2. **LLM prompt 注入**：CVE 描述文本（OSV/pip-audit 转述）进摘要 prompt——注入风险真实存在但影响面=摘要文本质量（AI 无工具、只摘要、不判定，任务文件已钉死边界）。修法：finding 喂 LLM 前截断字段（ID/包/版本/severity），不喂自由文本描述。
3. **AI 摘要渲染**：前端 B 区「摘要全文」——若 v-html 渲染则 XSS 面（AI 输出可含注入 HTML）。修法一句话钉死：纯文本插值（Vue `{{ }}` 默认转义），禁 v-html。任务文件未写。
4. **mock 可测性**：「命令输出 fixture 注入解析函数」——隐含采集器=「subprocess 取原始输出 + 纯函数解析」双层结构，方向正确，但未显式声明分层。建议契约节写明：`parse_ss/parse_sshd_config/parse_pip_audit(raw: str) -> dict` 为纯函数（可 fixture 测），subprocess 层薄壳。
5. **E 区「点击日期联动 C/D 过滤」**：C/D 数据来自 snapshot 端点（当日），历史日的 findings 若只存当日快照行、finding 表 first/last_seen 区间查询未定义端点支持——history 端点返回结构里须含按日 findings 或该交互降级。小缺口，接口契约节补一行即可。
6. **模板字段对照**：缺「引用（设计/方案）」字段（模板 8 字段之一）。本批无对应设计文档可引，可写「无——任务文件即设计层」占位声明，但空缺应显式。
