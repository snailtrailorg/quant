## 总评

立项判断成立：三断环（4aa5da1/f5ca7ca/caf3164 三 commit 实在）与 staging/prod wrapper 分叉（本机实测坐实）证明「改输入不认识消费者」是真实结构性病。任务方向（地图/规约/清账/人话）与用户「收敛而非重写」裁定一致，限定范围克制（不重写/不删检查/不外部化）是加分项。八字段骨架齐全。**但方案有三处硬伤**：①现状锚点低估分叉面——实测 staging 分叉不止 pip/dnf/ssh，**hbcheck 也不一致**（且 hbcheck 属 release 需求侧 wrapper，旧版含 TRANSITION-0115 两态分支，分叉直接威胁批 121 自身验收与后续发布判据）；②「wrapper 变更⇒重跑 bootstrap」规约与三入口清单互不一致的现实冲突——规约落地前先得修清单，否则重跑 bootstrap 反而**倒退**（journal/dnf/ssh 三只在 staging 消失）；③人话章「无上下文读者测读」验收定义含混，读者身份与及格线未定义。修掉这三处（改锚点/加清单修复前置/定义测读协议）方案即成立。**过门：有条件通过**——3 P1 必须在步 3 前回写任务文件。

## 严重（P1）

**P1-1 分叉面锚点失真：staging 实测不一致面大于任务文件记载，验收基线即错**
证据（2026-10-12 本机 `ls /usr/local/sbin/quant-*` + md5sum，对比 `deploy/wrappers/`）：
- staging 装位 **11 只**：svc/flip-server/flip-web/install-units/pinned/alembic/importsmoke/pip/emd-build/dbro/hbcheck。**缺 quant-journal**（任务文件未提）；缺 dnf-security/ssh-snapshot（已提）。
- **quant-hbcheck staging=1207a0（6807B, Oct 1）vs 仓库=819927（10248B, Oct 9）——分叉**。任务文件锚点 3 只记 pip 一只分叉。
- dbro/svc 等其余一致（md5 双向核实）。
影响：①验收 2「三方一致」若按任务文件的分叉清单理解，会漏检 hbcheck；②**hbcheck 是 release 阶段 8 心跳判据的依赖**——旧版 6807B（批 66b v2 之前形态）缺两代自适应与 legacy 回落，staging 彩排判据实际跑在旧语义上，彩排价值已被侵蚀，这正是本批「恢复彩排完整性」目标的靶心。修法：锚点 3 改为「装位清单 11 只 + 三处分叉（pip/hbcheck + 缺 journal/dnf/ssh 四只）」，验收 2 明确「14 只全量三方一致」。

**P1-2 目标 2 规约与现状冲突：三入口 wrapper 清单互不一致，规约落地=倒退**
证据（三处清单逐只比对）：
- `deploy/playbooks/bootstrap.yml:123-133`：12 只中列 10 只，**缺 quant-flip-web、quant-emd-build**（A06 §8-6 已自认，属实）；
- `deploy/scripts/bootstrap_staging.sh:42-45`：11 只（缺 **quant-journal**、dnf-security、ssh-snapshot 三只）；
- `deploy/scripts/bootstrap_server.sh:38-41`：11 只（同缺 journal/dnf/ssh）。
任务文件目标 2 立「wrapper 变更 ⇒ 重跑 bootstrap = 唯一装位通道」，但三个 bootstrap 入口清单各不相同且都落后于仓库 14 只。若先立规约后修清单，按规约重跑 bootstrap_staging.sh 会**卸不掉也不装**——实际效果是清单固化 11 只旧集，journal/dnf/ssh 永久缺位（bootstrap.sh 是 install 不是 sync，无删除语义，但清单缺席=新 wrapper 永不装位）。修法：任务「产出」里须加**前置步骤「三清单对齐 14 只」**（或以仓库 wrappers/ 目录清单为单源生成 loop），并把「清单单源化」写进目标 2 判据——否则规约是写给人看的，机器各念各的经。

**P1-3 人话章测读验收（验收 4）不可执行：读者未定义、三问未给出、及格线未定义**
任务文件验收 4：「盲审员 A/B 各读一遍答三问，全对方算过」。问题：①「三问」在目标 5 里是描述性举例（发布分几步/每步谁在守/改 X 要动哪些文件），不是钉死的问题集；②谁读——本批盲审员是带着完整部署链上下文进来的（刚审完任务文件），**不是「无上下文读者」**，测不出「无前置知识依赖」；③「全对」无评分协议（口头答？落文件？答到什么颗粒度算对？）。八步法「验收可验性预审」（八步法.md:96）明文要求每条验收问「按给定方法测得到吗」——本条不满足。修法：验收 4 改为可执行协议：三问钉死为固定题面写进任务文件；读者指定为「未参与部署链任何批次的新会话 agent（无 flow/ 记忆加载）」；答题落文件（`flow/稳定性检查/批121-人话章测读-<reader>.md`），逐题对照标准答案判卷；主会话出标准答案。
