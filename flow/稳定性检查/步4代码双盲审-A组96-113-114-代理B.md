## 致命（P0）

**P0-1 · 批 114 全局端点权限降级泄露敏感信息**
- per-task 端点 `GET /api/live-task/{tid}/freeze-events`（`trading.py:287-297`）挂 `require_perm_any("paper_trade","live_control")` + `assert_task_perm`（`auth.py:159-189`，按任务 mode 二次判定）。docstring 明示收紧理由（`trading.py:292-293`）：「冻结事件含任务运行细节（冻因/水位/缺口目标时刻），属治理原则要挡住 analyst 的那类信息（可推知策略实证表现）」。
- 新全局端点 `GET /api/freeze-events`（`trading.py:300-313`）仅挂 `require_perm("read")`，返回 `list_events(task_id=None)` **完整形状**（`freeze_event.py:91-92` SELECT 含 `symbol, watermark, gap_target_ts, account_id, operator`），无 mode 分档、无字段投影。
- `read` 四角色全有（`perms.py:21/27/29/35`）。故 **viewer**（无 paper_trade/live_control）可跨任务拉冻结详情；**analyst**（有 paper_trade 无 live_control）可越 mode 拉**实盘**任务冻结详情——两者都绕过了批 86-B 的门。
- 端点 docstring（`trading.py:305-309`）用「角标是全局健康信号」辩护，但把「**计数**（read 级合理）」与「**完整事件明细**（批 86-B 特意分档）」混为一谈。角标只需 `task_id`/`symbol`/`freeze_type`，不需要 `watermark`/`gap_target_ts`/`account_id`/`operator`。
- 修向：全局端点只回 `{count}` 或投影掉 `watermark/gap_target_ts/account_id`（symbol 是否保留另裁），明细仍回 per-task 分档端点。**未修则不过门。**
