## P1（2）

### P1-1 · 事件接线无守门：删掉 `subscribe_*` 全绿而生产链静默死亡

- 位置：`server/src/strategy_runner/main.py:376`（`exec_port.subscribe_order(on_order)`）、`server/src/strategy_runner/hub_worker.py:456`（`exec_port.subscribe_trade(on_trade)`）。
- 事实链：
  1. `tests/test_hub_worker_migration.py:126`、`test_batch76_freeze_worker.py:100`、`test_batch171s.py:377` 三处一律注入 `"exec_port": MagicMock()`——worker 侧接线面的**全部**覆盖就这三行，且没有任何一处断言 `subscribe_trade` 被调用/被调用的 cb 是谁（`grep -rn 'subscribe_trade' server/tests/` 只命中 `test_d32_p1b_equivalence.py` 内的端口单测）。
  2. `test_batch69.py:16-25` 的源码钉只钉 `bus.publish_cross_process(0, "trade_update", {})` / `("order_update", {})` 字符串仍在源里，与注册无关。
  3. 等价测试只验证「给 port 一个 cb，port 会翻译并回调」——不验证「hub_worker/main 真的把 cb 交给 port」。
- 后果（删行即发生）：`hub_worker.run` 若漏掉 `exec_port.subscribe_trade(on_trade)`，EVENT_TRADE 不再有任何消费者 → `trade_log` 停止入库（对账 n_new 恒 0、成交不入库），**无异常、无告警、全仓测试绿**。`main` 漏掉 `subscribe_order` 同理让 `order_log` 终态回写彻底停摆（批 68 的 EMT RESTART 重放治愈也一并失效）。这正是「守门自失效」族（门控不覆盖被测属性）。
- 修法（下一批或本批补）：worker 测试的 `exec_port` 换成**记录型假端口**（`subscribe_trade`/`subscribe_order` 收集 cb），断言「拿到的 cb 触发后 `trading.write_trade_log` 被调用且入参是 domain `Trade`」；main 侧至少钉 `subscribe_order` 被调用一次且发生在 `build_td_runtime` 之前（时序合同只在注释里）。

### P1-2 · `_run_hub_mode` 的早到事件路径完全无测试（holder 时序合同靠注释）

- 位置：`server/src/strategy_runner/main.py:359-376`、`:422`。
- 事实：`_adapter_holder={"a":None}` → `subscribe_order` 在 `build_td_runtime` 前注册 → build 返回后 `:422` 赋值。这是本批唯一「新增时序」，而 `grep -rn 'exec_port\|_run_hub_mode' server/tests/` 显示 main 侧唯一的测试是 `test_td_dispatch_pin.py:27`（`inspect.getsource` 断言源里有 `build_td_runtime(` 字样）。
- 后果：把 `:422` 的赋值挪到 build 之前/删掉、或把 `:376` 的订阅挪到 build 之后，测试全绿。前者让早到事件（EMT RESTART 当日重放）永久 `adapter=None`——写库函数不抛（已实测，见下）但 `_client_id_of` 只能走 vt 匹配，跨任务 vt 碰撞时认领错行；后者丢重放窗口，正是批 68 注释里写死的那个事故面。
- 说明：`write_order_status/write_trade_log` 在 adapter=None 下不抛这一点我已实测（见「已核实」第 6 条），所以后果是**静默弱化**而非崩溃，故记 P1 不记 P0。
