# 盲审批109方案 · 代理 A 独立报告（批 109 / 步 2）

> 只读评审；未读代理 B 任何产物。结论独立，不揣测他人。

## 总评
方案方向正确（输出闭环、派生视图、封顶登记、uncertain 抑制），但**两处致命设计缺陷使「对账不漏报」的核心承诺落空**，且若干接线前提与代码现状不符。**不过门（返工）**。四维判据：单一真源（P1-5 双口径漂移、P0-2 派生自救缺钩）、依赖方向（per-date 依赖 trade_cal 完整性，无降级判据）、职责层级（P1-4 与收编纪律冲突）、契约闭合（P0-1 合并语义不闭合）。

## 致命 (P0)
- **P0-1 · 幂等合并在「部分补齐」下语义错误（静默误报）**。UNIQUE 含 `(gap_start, gap_end)`（产出1 行33），合并仅 `ON CONFLICT DO UPDATE SET state=EXCLUDED.state`（行43-44）。若缺口 `[01-01,12-31]` 重拉补了后半段，剩余 `[01-01,06-30]` 与旧键不同 → 插新 open 行，旧行**永不开/关**（Phantom，存量缺口指标虚高）；若保留原键则整段恒显 open（stale 膨胀）。方案「补齐时改走 UPDATE→closed」只对**整段补齐**成立，部分补齐无任何路径 → 设计不可实施 as described。
- **P0-2 · per-date uncertain 门不可实施**。方案称「日历未覆盖（fail-open 回 freq="B"）⇒ uncertain 门接住」。但 `_expected_trade_dates`（`engine.py:2118`）**无覆盖守卫、无回退信号**：step1 有任意行即返回（哪怕仅覆盖近年），step3 静默回 `freq="B"`；与 `_trade_dates_in_range`（:302 有「首行距起点>3天⇒未覆盖」守卫并返回 None）正相反。复用它做期望集却无「日历未覆盖」检测钩子 → 部分 `trade_cal` 下静默漏检，恰是母设计 §九/§5.4 要抑制的形。首跑即全史（§八 验收）在 trade_cal 未全量库上即触发。

## 严重 (P1)
- **P1-1 · excluded 落表前提失真**。当前仅 crypto handler 在返回体写 `excluded`（`engine.py:1352`）；四 A 股 per-date handler（`:1572/:1626/:1391/:1751`）**丢弃** `_family_start` 算出的 `excl`。产出4「批108 handler 返回体 excluded → sync() 落表」只对 crypto 成立；A 股 per-date 的 `policy_discard`/`unreachable` 永不落表 → 闭环缺口，违反 §5.3「封顶不得静默」。须在四 handler 也回传 `excluded`。
- **P1-2 · cb_daily 无逐日重拉路径**。`:1626` 是单次 `fetch_supply` 全区间、`expected_days` 恒 `None`，无 per-day repull。方案「逐缺日重调本 handler 既有拉取路径」对 cb_daily 不实，须重构为按日循环（同 `:1572`）；且「缺日数≤expected_days（有界）」对 cb_daily 无界（expected_days=None）。接线点未写清。
- **P1-3 · 告警风暴无闸**。首跑即全史下一次产生大量 open 行＋ `sync.gap` 告警，仅沿用 `_alert_sync_failure` 的「同标题 1min 去重」（不同行不同标题不聚合）。验收未含告警量/批量聚合。
- **P1-4 · 与收编纪律冲突**。新增独立 beat（产出3）与仓内「批83b/101 收编 beat → sync_config/data_sync_scheduler」既定方向冲突（`app.py:148-151,192-211`；`decisions.md` 2026-09-28 多源刚性）。需显式裁明对账任务豁免收编之由，或改走 `data_sync_scheduler`。
- **P1-5 · Q3 前缀≠SM 转债宇宙**。SM `category='convertible'` 实测含 `10/14` 前缀（`100016.SHSE`、`100087.SHSE` 等，共1172行），`bar_1d` 无 10/14；per-date 用前缀 11/12/13、per-symbol 用 SM 两口径 → 双源漂移；若 cb 源返 10/14 债券则 per-date 静默漏检。应统一以 SM 为转债真源（裁定 G①）。

## 一般 / 陷阱核对
- `gap_dates` 接线：`sync()` 现读 `r.get` 列表（`:374-396`）不含 `gap_dates`，须补读+日志+告警；四 handler 返回体确无 `gap_dates`（新增正确）。
- 禁读闸仅靠 grep 白名单测试（软闸），间接读可绕过；建议运行时注释立法＋更强测试。
- `_expected_trade_dates`(:2118) vs `_expected_trading_days`(:260) 命名易混；方案接口契约引前者正确（需集合），勿接成后者(int)。
- `symbol DEFAULT ''` 规避 NULL UNIQUE 缺陷，合理且与「不臆造」一致。
- 五态 CHECK 与「每行终结于其一」张力已自洽（open 持续态＋四终结态）。
- 重入：per-date inline repull 调 `fetch_supply` 非 `sync()`，per-symbol beat 调 `_reconcile_symbols` 非 `sync()` → 无递归环（方案应明写）。
- `idx_bar_1d_ts` 实测存在、PG 18.6；28ms 成本未独立作证但合理。`trade_cal` SSE 实测 1990-12-19~2026-12-31 全量（故此库不现 P0-2，但设计场景仍触发）。
