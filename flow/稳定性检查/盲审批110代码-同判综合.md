## 三、分歧与仲裁

### D1：P-1/P-3 检测器——A 判「防御哨兵，非缺陷」／B 判「P1，『零误报』半门未执行」

**双方都不完整**：
- A 的**定性对**：这不是代码缺陷（不产生错误数据）。
- B 的**后果评估对**：方案 `:179` 的 R2 宣称定义了「零误报」的可自动判定两类，而这两类（同锚同轮既 open 又 closed；uncertain 轮仍产主张）在 `_sync_gap_sync` 的**单分支结构**下互斥 ⇒ 检测器**恒空**。
- 两人都漏了一点：`stat["false_"]`（`:2417/2428`）**也**恒 0 ⇒ 摘要里那个 `false_=` 字段同样是装饰性的。

**仲裁**：**不返工代码，但必须改文档**——把「R2 本批为**结构哨兵**（防将来重构引入该缺陷），**不构成自动误报门**；『零误报』的实质核验仍在第四类金标准对照（步 8）」写进 `_gap_judge` docstring 与方案 §R2。理由：现状是一份**假事实**（读者会以为自动门已生效），而本仓对「声明面被执行面消费」的要求是硬的。

> 依据：skill §5 的教训「凡『引入某字段/标记来表达连续/状态』的必修，必须连维护语义一起写死——**字段存在 ≠ 判据闭合**」。此处同构：**检测器存在 ≠ 误报门闭合**。

### D2：Valkey 措辞——B 判「方案 `:91`『丢 ⇒ 计数回退』不精确，实际 incr 失败是未推进」

**仲裁：B 该条不成立**（唯一一条被驳回的）。方案说的是**键丢失**场景（`INCR` 从 0 ⇒ 返回 1 ⇒ 相当于回退 ⇒ `last_hit_round != round_id-1` ⇒ 复位）；B 说的是**连接失败**场景（异常 ⇒ `None` ⇒ 该轮不判定）。两种失效不同，方案措辞针对前者，**正确**。这是「两代理一致 ≠ 对」的反向案例：**单人提出的也要独立复核**（这里只有 B 提，经复核为误读）。

### D3：A 的「跳周透明」（一般）／B 的「同 round_id 重跑 reset」（一般）

- 「跳周透明」：A 认为「执行轮」语义内部自洽 ⇒ 可接受。**部分不同意**：见 §四 R1——`hit_rounds` 有断档复位而 `cover_low_streak` **没有**，两者不一致，`cover_low_streak` 侧是真缺口。
- 「同 round_id 重跑 reset」：**同意 B 但判无碍**——生产每轮 `INCR` 单调、`round_id` **不复用**，故该情形不发生；仅手工重放同一 round_id 才触发，属观测者偏差。

## 四、主会话独立复核（**只列新增证据**）

**R1 ⭐ `cover_low_streak` 无断档复位——与 V1 同族不一致（两代理均未提出，A 提了"跳周透明"但定性错）**

- 一手证据：`grep -n '_bump_cover_low' engine.py` ⇒ **全仓单调用点** `:2307`；该点位于 `:2259`（未配置/禁用 `continue`）与 `:2278`（V6 无 symbol `continue`）**之后**。
- ⇒ 该 scope 某轮**未被评估**时，Valkey 键**既不 `INCR` 也不 `DELETE`** ⇒ 冻结 ⇒ 下次评估继续累加 ⇒ `streak >= _SM_COVER_STALE_ROUNDS` 可被**跨过未评估轮**满足。
- 对照 `hit_rounds`：`CASE WHEN last_hit_round = round_id-1 THEN +1 ELSE 1`——**有**复位。
- ⇒ **同一批内两处「连续性」语义不一致**；且 V1 的整个立项理由（「中间整轮跳过 ⇒ 断档被当连续」）**逐字适用于 V7**。
- 定性 **P1**（产生假告警；方向安全＝多报不静默，故不升 P0）。

**R2 `sync.inception_cover_low` 一码两义（两代理均未提出）**

- 一手证据：`_alert_inception_cover_low`（`:2053-2069`）按 `declared is None` 分叉出**两种根因完全不同**的告警体，但**共用同一 code**；调用点 `:2300`（V5 互证闸漂移）与 `:2309`（V7 覆盖率长期低）。
- ⇒ 值班者收到该 code 无法从 code 分辨根因（须读 body）；RUNBOOK 一条只能覆盖一种处置。
- 定性 **一般（可操作性）**，非必修；建议后续批拆为 `sync.inception_drift` / `sync.inception_cover_low`。

**R3 `list_date` 列类型实测＝`date` ⇒ 排除一个候选 P1（**阴性**结论，用于防自己写假 P1**）**

- 我起初怀疑：`sm_inception()` 对畸形字符串返回 `None`，而 `_sm_universe()` 原样返回 ⇒ 两读口归一语义可能分裂（同值不同判）。
- 一手实测：`select data_type from information_schema.columns where table_name='security_master' and column_name='list_date'` ⇒ **`date`**。
- ⇒ psycopg 返回 `datetime.date` 或 `NULL`，**畸形值不可达** ⇒ 该分裂在数据域上**不成立**。降为**加固建议**（若将来改列为 text 则复现，见 §六）。
- ⇒ 本条是「先问同源、再一手实测」的实践：**避免了把假 P1 写进同判**。

**R4 C1 的范围收窄：未闭合的只有两路（比两代理更精确）**

逐路复核 `_gap_judge` 的输入面：
- `round_id is None`（Valkey 不可用）：`:1598-1600` 条件已含 `round_id is not None` ⇒ **`hit_ge_n=0` ✅ 已闭合**；
- `stale_source`：`:2315` 走 `uncertain_map` 全族 ⇒ 全行转 `uncertain` ⇒ `:1598` 只数 `state=="open"` ⇒ **`hit_ge_n=0` ✅ 已闭合**；
- `budget_exceeded`：`:2364` 把 `gaps_map` 全置 `None` ⇒ `:1905` 走 `touch`（只刷 `last_seen`）⇒ **行保持 `open` 且 `hit_rounds` 保留旧值** ⇒ **❌ 未闭合**（旧值 ≥N 时 `hit_ge_n>0`）；
- `sm_covered < sm_total`：只有 `list_date` 空的 sym 转 `uncertain`，**同 scope 其余 sym 照常主张** ⇒ 若其 `hit_rounds≥N` ⇒ **❌ 未闭合**。
- ⇒ 修法＝`_gap_judge` 增 `suppressed: bool` 入参（`budget_exceeded or sm_covered < sm_total` ⇒ `hit_ge_n=0`），**不必改 `judged`**。

**R5 测试缺口补全（合并双方）**：无「budget/coverage 抑制 ⇒ `hit_ge_n==0`」用例（功能未实现故测不出）；无 `false_rounds` 应被写的用例；无 `local_unreadable` 告警用例；无「Valkey 键整键丢失 ⇒ 复位」用例（现仅 `round_id=None` 一路）。
