## 三、严重 P1

- **P1-a（新·假红）冻结集内 legacy 仅改 `upgrade` 段注释/空白 → rc=1 误红**：实测 仅给 `0104` 的 `upgrade` 段加一行 `# 注释`（无任何结构性变更、无新增破坏性 op）→ `rc=1 "发生变化"`。因 `_frozen_legacy_unchanged` 对 `scan_upgrade_section` **逐字节**比对（含注释）。修复：比对前归一（剥注释/空白）或仅比可执行 op 集合。属本批新引入的过度阻塞，非数据风险（fail-closed 安全）。
- **P1-b（新·等效路径未枚举）大小写 variant DDL 完全绕过检测**：判定表正则全大写（`DROP\s+(TABLE...)` 等），`op.execute("drop table x")` 永不命中 → `scan_unsafe_lines==[]` → 无命中 → rc=0 过门（实测 `[]`）。这是与 `legacy` 洞**同构的第三条等效绕过路径**，但本批次 hardening **只硬化了 `legacy` 旗标与 rc 语义，未硬化检测灵敏度**，与 decisions.md 决策1「枚举所有等价路径，不得只硬化其中一条」精神相悖。修复廉价：正则加 `(?i)`。此前同判综合判「一般」，独立上修为 P1（门可被大小写 variant 静默绕过；本仓当前无实例但零成本可堵）。

## 四、全新红队（每条含可复现构造）

**1) 豁免/逃生通道枚举（第三条路径存在）**
可达「破坏性 op 过门」的等价路径全集：
- `allow_contract=true`（调试旗，取消全部 rc=1 阻断，留痕——设计内）
- `legacy` ∈ LEGACY_FROZEN 且 upgrade body 与已部署版逐字一致（本批新校验）
- `phase=contract` + 合法 `pair` 指向已部署 expand（正当两步）
- `EXPLICIT_EXCLUSIONS`（DROP CONSTRAINT/SET DEFAULT，设计内）
- 首部署 rc=3 跳过（W6#4）
- **大小写 variant DDL**（见 P1-b）：`python3 -c "from src.data_platform.migration_policy import scan_unsafe_lines; print(scan_unsafe_lines('\"\"\"x\"\"\"\ndef upgrade():\n    op.execute(\"drop table t\")\n'))"` → `[]`（未检测→过门）。** hardening 未覆盖此路径。**

**2) 码→语义映射（rc=1⇔真命中是否成立）**
穷举生产者：
- `0` = `managed` 空 / 全部合规（`check_release:416`）
- `1` = `rejects` 非空——仅来自 genuine reject（真命中 / 声明冲突互斥 / 冻结 body 变化 / 非冻结 legacy+命中）；**无内部错分支落 1** ⇒ `rc=1⇔真命中` 成立
- `2` = `except Exception`（解码/IO 等内部错；实测坏UTF-8→2）；封闭式补集把 2 当红 ✓
- `3` = `managed is None`（首部署）；`release.yml` `when rc==3` 告警跳过（非放行集但属预期跳过）
- 其它：`argparse` 用法错→2；无其它生产者
`failed_when` 逐字比对 exact（`test_failed_when_normalized_exact`）✓。结论：闭环成立。
⚠ 残点：`allow_contract` 取消**全部** rc=1（含「冻结 legacy body 被篡改」「legacy+phase 互斥」这类完整性违规），即调试旗可 defeat P0-1 的完整性保护——系调试旗语义（显式 `-e` + reason + var 留痕、🔖待移除），归已知边界，建议文档明示。

**3) 守卫扫描面**：语料=release.yml+include目标；`{{}}` 模板化目标断言不存在（防漏扫）；`lookup('pipe', …)` 内判定会被「引用 migrations/versions 任务数=1」唯一性判据捕获（>1→红）。残留：判定若藏进第三层（import_role/动态且不含字面 migrations/versions）可能漏——当前无，一般。

**4) 冻结集语义**：`_frozen_legacy_unchanged` 用 `scan_upgrade_section` 逐字比对，防住「改已部署迁移 body」（实测偷加 DROP→rc=1）。绕过形态仅剩 `upgrade` 段外（docstring/imports/downgrade）——已诚实声明为残余。注释/空白/大小写差异→被比中→**误红**（见 P1-a）。

**5) 新引入假红风险**：(i) P1-a 注释误红；(ii) `_strip_comment` 引号感知正确（字符串内 `#` 不误剥，实测 `op.drop_table('t')` 命中）；但字符串文本含 `DROP TABLE` 会被误判命中（既有，一般）。
