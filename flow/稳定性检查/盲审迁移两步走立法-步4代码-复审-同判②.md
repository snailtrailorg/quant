## 三、分歧与仲裁

### 分歧 1 —— 小写 SQL 逃逸：P1（A2+B2 同判）还是 P0？⇒ **主会话上调 P0-B**

上调判据（**与上轮判 P0-1 的判据同源，保持一致性**；成本不列）：

1. **声明面 ⊋ 执行面**：规范 §1.1 声明的对象是语句 `DROP TABLE` / `RENAME COLUMN` / `RENAME TO` / `ALTER COLUMN … TYPE`；SQL 标准与 Postgres 下**关键字大小写不敏感** ⇒ **同一语义两种判定**（大写拒、小写放）⇒ 判定真源自相矛盾。
2. **静默漏检**（红队定义里最危险的一类：「看起来对、实际不报缺」）：实测 rc=0 且打印 `✓ … 无回滚安全类命中`——**报绿，不报缺**。
3. **与 P0-1 的一致性**：上轮 A 以「需开发者**故意**」求降级，被判**理由不成立**（「`allow_contract` 同为故意，故意性不能区分两者」）。本项**连故意都不需要**（按习惯写小写 SQL 合法且常见）⇒ 若 P0-1 是 P0，本项**不可能低于 P0**。
4. **无机械守卫**：主会话实测确认「仓内 141 个迁移 100% 大写」——但这是**约定**，不是守卫。按本仓既有纪律（「人工/约定跑＝纸面约束」），**约定不构成降级理由**。

**附带（同一判据的强化）**：模块 docstring/注释自称「宽口径是刻意的：…`DROP\s+\w+` 先宽命中」，实现却是 `DROP\s+(TABLE|COLUMN|INDEX)` ⇒ **注释 ≠ 代码**，声明的宽口径从未落地（一般项，随本修对齐）。

### 分歧 2 —— 冻结 legacy「重标 phase=contract」绕过 body-equality（B2 列边角、A2 未提）⇒ **主会话上调 P0-A**

- **隔离复现**（主会话实测，干净临时目录）：prev ＝ {`0100_expand`（phase=expand）、`0010_simplify_llm_gateway`（legacy，body v1）}；new ＝ {`0100` 不变、**`0010` body 改为 v2 且头改 `phase=contract pair=0100`**} ⇒ **rc=0，`✓ 0010_…: 合规 contract（pair=0100 已上产且声明 expand）`**。
- **对照组**（唯一变量＝是否保留 `legacy` 声明）：同篡改 + 保留 `legacy` ⇒ **rc=1**（`冻结 legacy 的 upgrade 段相对已部署版发生变化`）。
- **判据**：上轮 P0-1 的结论正是「`legacy` 是**自声明**⇒ 不可信任，须验证」。本批把清单搬进了模块，却**仍以 `decl["legacy"]` 作触发条件** ⇒ 「自声明不可信」原则在**修复内部失效**（单一真源被自声明旁路）。且规范 §5.1 原文 keying 是「**名在冻结集内**」⇒ 实现 ≠ 规范。⇒ **P0-A**。
- 逃离面已穷举（R4）：删声明 ⇒ 拒；改 `phase=expand` ⇒ 拒；保留 legacy 改 body ⇒ 拒。**唯一逃逸＝重标 `phase=contract` + 有效 pair**。

### 分歧 3 —— body-equality 对「纯注释/空白变更」判红＝假红？（A2+B2 同判 P1）⇒ **主会话裁「非缺陷」**

- 判据：「迁移文件不可变」是本设计的**基本约定**（规范 §6 首条 + 模块 docstring 第 40-41 行）。**已部署迁移的任何字符变更都不得放行**——注释变更同样是「改已部署产物」，fail-closed 方向**正确**。
- 处置：**不改代码**；在规范 §6 **显式写明**「逐字一致＝含注释/空白，改动已部署迁移（哪怕只加一行注释）即拒」，以免下一轮复审重复当假红提。

### 分歧 4 —— TRUNCATE / DELETE FROM 不在判定表（B2 独有）⇒ **主会话裁「挂账 + 明示边界」**

- 判据：本门判的是**回滚安全**（「旧代码可读新 schema」）。TRUNCATE / DELETE **不改 schema**，属**数据类**破坏 ⇒ 归 `docs/design/D18-数据库操作规范.md` §2.3 与备份流程，非本门范围；规范 §1.2 已为同类（前向危险类）立了「显式排除」先例。
- 处置：**挂账**（🔖 复活条件：本仓出现「数据类破坏迁移」需求）+ **写入 §6 已知边界**（否则又成「未声明即静默」——正是 P0-B 的教训）。

## 五、必修清单（修完方可复审）

### P0（门）

**P0-A · 冻结集文件的「upgrade 段不可变」校验被自声明旁路（P0-1 修复未闭合）**
- 现象：冻结集内文件 body 被改 + 头改 `phase=contract pair=<已上产 expand>` ⇒ **rc=0 放行**（实测，见分歧 2）。
- 修法（架构判据：**单一真源** + 已批准规范 §5.1 原文）：`_classify_managed` 中把冻结集校验的**触发条件由 `decl["legacy"]` 改为 `name in LEGACY_FROZEN`** —— 即「名在冻结集内 ⇒ 一律逐字比对 `upgrade` 段（**与声明无关**）」：未变 ⇒ `ℹ` 不阻断；变 / 不在已部署版 ⇒ **拒**。非冻结 legacy 分支保持**拒**。
- 保留：`legacy` 与 `phase`/`pair` **互斥**校验（防一行双通道）。

**P0-B · 判定表大小写敏感 ⇒ 一整类等价破坏性语句无门通过**
- 现象：`op.execute("drop table demo_t")` / `op.execute("alter table t rename to t2")` ⇒ **rc=0**（实测）；同语句大写 ⇒ rc=1。
- 修法：`ROLLBACK_UNSAFE_PATTERNS` / `EXPLICIT_EXCLUSIONS` 的匹配统一加 **`re.IGNORECASE`**；并**把 docstring 的「宽口径」声明与实现对齐**（实现加 `DROP\s+\w+` 或用注释改口径，二选一），且保证「真消费」反证钉⑤ 仍成立。
- 验证：全仓重扫仍 **16 文件**（R3 已证 `re.I` 零差异）；沙箱新增「小写 DROP ⇒ rc=1」。

### P1（须给处置结论）

- **P1-1 文档一致性**：模块 docstring/注释与实现不一致（`DROP\s+\w+` vs 实现；「宽口径」声明不实）⇒ 随 P0-B 对齐。
- **P1-2 沙箱覆盖**：S7 现九例未覆盖「冻结集重标绕过」「小写 SQL」⇒ 各加一例（S7j / S7k）。
- **P1-3 规范 §6 补边界**：① 逐字一致＝含注释/空白；② 数据类破坏 op（TRUNCATE / DELETE）不属本门（挂账 🔖）。
- **一般（挂账）**：ruff 不扫全仓 `tests` ⇒ 独立批次（上轮已定，不重复）。
