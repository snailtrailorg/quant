## 严重（P1）

### P1-1 · 减法未闭合「逗号并列」的**反向**子类——排除项 #3 的通配桥把**前面的**破坏性 action 一起吃掉（**本轮 docstring 声明已闭合，实测未闭合**）

- 位置：`migration_policy.py:109`（`r"ALTER\s+COLUMN[^;\n]*\bSET\s+DEFAULT\b"`）；`[^;\n]*` 贪婪可跨逗号。
- 声明：`migration_policy.py:42`「破坏性 op 与排除项同行 / 同注 / **逗号并列 action** 都不会被洗白」；规范 §1.3:34-37 同义。
- 实测（新模块 `scan_unsafe_lines`，`upgrade` 段单句）：

  | 语句 | 期望 | 实得 |
  |---|---|---|
  | `op.execute("ALTER TABLE t ALTER COLUMN c TYPE int")`（对照） | 1 | **1** |
  | `op.execute("ALTER TABLE t ALTER COLUMN c TYPE int, ALTER COLUMN d SET DEFAULT 1")` | 1 | **0** ⚠ |
  | `op.execute("ALTER TABLE t ALTER COLUMN c DROP DEFAULT, ALTER COLUMN d SET DEFAULT 1")` | 1 | **0** ⚠ |
  | `op.execute("ALTER TABLE t ALTER COLUMN c DROP NOT NULL, ALTER COLUMN d SET DEFAULT 1")` | 1 | **0** ⚠ |
  | `op.execute("ALTER TABLE t ALTER COLUMN c SET DEFAULT 1, ALTER COLUMN d TYPE int")`（破坏性在后） | 1 | 1 ✓ |

  三者皆为**合法 PostgreSQL**（逗号并列 action），且 `ALTER COLUMN … TYPE` 是 §1.1 明列的回滚安全类；`DROP DEFAULT`/`DROP NOT NULL` 是本轮刚裁定的收紧类（应红）。⇒ 残句里 `ALTER COLUMN`…`SET DEFAULT` 被整体摘除，**中间的破坏性 action 随之消失**。
- 同一根因在 fuzz 中另有体现：相对最初基线 `9fa0e7f`，**21/20000** 例新实现更弱（例：`ALTER COLUMN c … RENAME COLUMN a TO b … set default 1` ⇒ 旧 1 / 新 0）。这是 **P0-B（上一轮 IGNORECASE）× 通配桥**的残留，**不是本轮回归**（`55b5e1e` 同为 0）。
- **分级自评：P1 而非 P0**——三条理由：① 非本轮引入、非回归（`9fa0e7f`/`55b5e1e`/`da22709` 三口径全 0）；② 仓内 141 迁移零实例（#3 当前是装饰项，钉⑤ 实测删之 16/33 不变）；③ 需「破坏性 action 位于 `ALTER COLUMN` 与 `SET DEFAULT` 之间」这一特定语序。但它是**唯一**让本轮 docstring 相对执行面过宽的点（声明面 ⊋ 执行面，与 P0-C 同判据）⇒ 若主会话按该判据从严，可上调 P0；本人给 P1 + 处置。
