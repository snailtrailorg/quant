## 严重（P1）

**P1-N1 · 「同行/同注不会静默放行」是假闭环，且本轮把它**扩大**了**

模块 docstring `:36-40` 明写「P1-a 已收窄 ⇒ 破坏性 op 与 `DROP CONSTRAINT` **同行/同注**不会静默放行」。实测证伪，
三条构造全部 **放行**（`scan_unsafe_lines == []` ⇒ `evaluate` 视作无命中 ⇒ rc=0）：

| 构造 | 旧(9fa0e7f) | 新(55b5e1e) |
|---|---|---|
| `op.execute("DROP TABLE old_t -- drop constraint later")` | **命中** | **放行** ←本轮新增负面增量 |
| `op.execute("/* drop constraint */ DROP COLUMN c")` | **命中** | **放行** ←本轮新增负面增量 |
| `op.execute("ALTER TABLE t DROP CONSTRAINT ck_x, DROP COLUMN legacy_c")` | 放行 | 放行（遗留） |

根因：豁免是「语句内**任意位置**包含即整句跳过」（`:216`），而注释剥离只认 Python `#`（`_strip_comment:171`），
不认 SQL 的 `--` / `/* */`；`re.IGNORECASE` 让小写注释也能命中豁免 ⇒ **P0-B 在补窄 d 的同时撬开了这一条**。
处置建议（一行改动）：把「命中即跳过整句」改为「**挖掉匹配片段后再扫残句**」——实测残句仍被宽口径命中，
D1/D3/D4 一并闭合。属**同一判据下的秩序缺陷**，建议随本 batch 修；若不修，则 docstring `:38-40` 必须改写为实情。

**P1-N2 · 宽口径与 §1.3 的「元数据放宽类不属本门」原则自相矛盾（新口径把对称放宽类拉回网）**

`DROP\s+\w+`（`:75`）同时也把 **§1.3 已排除原则的镜像 op** 拉进闸门（`ALTER COLUMN … SET DEFAULT` 在 §1.3/`:104`
被明示为「元数据放宽、可回退」，`DROP DEFAULT` / `DROP NOT NULL` 与之同源对称）：

| 构造 | 旧 | 新 |
|---|---|---|
| `ALTER TABLE t ALTER COLUMN c DROP DEFAULT` | 放行 | **红** |
| `ALTER TABLE t ALTER COLUMN c DROP NOT NULL` | 放行 | **红** |
| `DROP STATISTICS / ROLE / POLICY / TRIGGER / EXTENSION` | 放行 | **红**（此类默认落网，认同） |

处置结论：**分两类**——（a）`ALTER COLUMN … DROP DEFAULT` / `DROP NOT NULL` ⇒ **对称补进 `EXPLICIT_EXCLUSIONS`**
（与 SET DEFAULT 同性原则，否则 §1.3 的原则只在一半成立）；（b）其余对象类型保持宽口径默认落网（**同意**本轮取舍）。
价款：仅「must fix」的是 (a) 一行；当前仓内零影响（重扫 33 == 33），属前向正确性。

**P1-N3 · `prev_dir` 整体不可用 ⇒ rc=3 ⇒ 流水线放行（整机旁路；new/prev 判罚不对称）**

`managed_set:336-345`：`prev` 目录不存在/是文件 ⇒ 返 `(None, …)` ⇒ `check_release:425` 返 **rc=3**，
而 `release.yml:389` 的封闭式补集把 rc=3 列在**放行集**。触达即 fully bypass（连冻结集 body 比对一起跳过）。

供给侧：`release.yml:383` `prev=$(readlink -f '{{ deploy_root }}/server')`，符号链接失效/被删后**每一次发布都 rc=3**。
处置结论：**不在本轮强制修**（跨轮欠债），建议提下一批：把「真首部署（无 previous release）」与
「previous release 存在但 `migrations/versions` 不可读」分档，后者 ⇒ rc=2。
