## 三、分歧与仲裁

### 分歧 1 —— 「排除项整句豁免」：P1（A3）还是 P0（B3）？⇒ **上调 P0-C**

A3 与 B3 抓的是**同一个根因**（「包含即整句豁免」），但 A3 把它降到 P1，理由隐含「只是假闭环」。仲裁依据（**主会话一手实测，见四 C1**）：

1. **本轮回归**（决定性）：`op.execute("DROP TABLE old_t -- drop constraint later")` 与 `… /* drop constraint */` ⇒ **旧命中 1 → 新命中 0**。步 3-c 的目的就是把检测面补齐（P0-B），结果**反而让一处原本会红的 `DROP TABLE` 变绿** ⇒ 门比修复前**更弱**。本仓既有纪律：**修复不得缩小检测面**；「既有漏检（B3 版）」可论批次归属，「回归」不能。
2. **静默且零成本可达**：rc=0 + 无输出；触发只需在 SQL 里写一句注释或并列一个 `DROP CONSTRAINT` action——**不需要 `legacy`、不需要 `allow_contract`、不需要删除声明**，比本批已封的两条通道更易达。
3. **与上轮 P0-B 同判据**：规范 §1.3 声明豁免的是**形态**（`DROP CONSTRAINT` / `SET DEFAULT`），执行面豁免的是**整语句** ⇒ 声明面 ⊋ 执行面。且这正是「**豁免通道必须枚举所有等价路径**」纪律的第三次命中（本批：旗标 `allow_contract` → 文件标记 `legacy` → 语句内关键词）。
4. **A3 自己的证据就是 P0 级**：A3 已给出「旧命中→新放行」的实测，只是分级用了 P1；分级与证据不自洽 ⇒ 按证据上调。

**修法（已实测验证，见四 C2）**：排除项由「整句跳过」改为**减法**——`re.sub` 掉被豁免的**片段**后再匹配判定表（3 行改动）。实测：三式漏检全部转红；真排除项（0116/0062/0095 三形态）仍豁免；全仓重扫仍 **16/33 零差异**。

### 分歧 2 —— `DROP DEFAULT` / `DROP NOT NULL` 由绿变红（A3 N2 建议补进排除表）⇒ **裁「不同意」**

判据：`SET DEFAULT` 是**放宽**（旧代码不写值时现在有默认 ⇒ 仍可读可写）；`DROP DEFAULT` / `DROP NOT NULL` 是**收紧**（旧代码不写值 ⇒ 直接报错）⇒ **破坏「旧代码可读新 schema」**，正是本门所判之物。宽口径把它们卷进来是**正确方向**（未列对象默认落网），补进排除表等于把收紧类洗白。⇒ 不补；随 P0-C 一并写进 §1.1/§6 说明。

### 分歧 3 —— prev 目录整体不可读 ⇒ 表现为「首部署」rc=3 ⇒ 放行（A3 N3）⇒ **裁 P1 + §6 明示**

判据：rc=3 是**已声明**的边界（首部署窗口 prod 侧无门覆盖），N3 是它的**等价路径**（有上一版但读不到 ⇒ 假首部署）。它是**环境故障**而非开发者可达的绕过通道，且 rc=3 带显著告警 ⇒ 不构成静默。但按「不许未声明即静默」，**必须写进 §6**：上一版存在但不可读 ⇒ 同窗口无门覆盖。判罚对称性改正（后者应 rc=2）挂账下一批。

### 分歧 4 —— 冻结集校验作用域＝受管集 ∩ 冻结集（B3 ②）⇒ **裁 P1 挂账**

冻结集文件**改名或从新版消失** ⇒ 不在受管集 ⇒ 无告警。判据：alembic 不重跑已应用的 revision，已部署迁移的 op 到不了 prod ⇒ 非「破坏性 op 直达」类。但属「集合不闭合」（真源有 15 项、执行面只校验其中被改动的子集）⇒ 挂账；复活条件＝下一批门加固（与同判② §六「集合等式」机械验证点合并落）。
