## 四、全新红队（每条含可复现构造）

**ⓐ 减法式豁免第五次漂移**——`\bSET\s+DEFAULT\b[^,;]*`
- **吃过头（漏检）命令**：
  `cd server && ./venv/bin/python -c "from src.data_platform.migration_policy import scan_unsafe_lines as s
  def m(q):return '\"\"\"d\"\"\"\nrevision=\"x\"\ndef upgrade():\n from alembic import op\n op.execute(%r)\n\ndef downgrade():pass\n'%q
  [print('LEAK!' if not s(m(q)) else 'caught',q) for q in ['ALTER TABLE t ALTER COLUMN c SET DEFAULT 1 DROP COLUMN d','ALTER TABLE t ALTER COLUMN c SET DEFAULT 1 ALTER COLUMN d TYPE int','ALTER TABLE t ALTER COLUMN c SET DEFAULT 1 RENAME TO t2','ALTER TABLE t ALTER COLUMN c SET DEFAULT 1 DROP TABLE old']]"`
  **期望** 4×caught；**实得** 4×`LEAK!`（破坏性 op 被 `[^,;]*` 连吃）。根因：`[^,;]*` 不排除空格。
- **吃不足（假红）命令**：同上 `m()` 替换 q 为 `'ALTER TABLE t ALTER COLUMN c SET DEFAULT \'a,b\''` / `'... set default 1'`（小写）/ `'... SET DEFAULT (SELECT 1)'` / `'... SET DEFAULT 1, ADD COLUMN x int'` / `'ALTER COLUMN "c" SET DEFAULT \'TYPE\''`。**期望**全 0；**实得**全 0 ⇒ **本批未引入假红**。
- **结论**：`[^,;]*` 只堵 `,`/`;` ⇒ P0-D「不得跨分隔符」**只修一半**（空格缺口）。逗号前有任何字符即安全，仅纯空格并列漏检。

**ⓑ 结构性**：见五。

**ⓒ S7n 断言强度**：读 `run_scenarios.sh:517-527`，断言 `S7N -ne 0` 且 `grep -q "破坏性 DDL 命中"`。语料 `SET DEFAULT 1 , TYPE varchar(8)`（逗号分隔）⇒ 残句保留 `ALTER COLUMN` 锚点 ⇒ TYPE 命中 ⇒ rc≠0；本人复现同。**判**：S7n 是**真断言**，覆盖 P1-G 可观察判据；但**未覆盖ⓐ空格缺口**（该缺口缺沙箱钉）。

**ⓓ 新用例是否真断言**：`test_exclusion_keeps_alter_column_anchor`(`:499-514`) 三 `assert`（假红面/漏检面/新假红面）；`test_spec_claims_have_cases`(`:517-527`) 三 `assert`（宽口径/收紧类/动态 SQL）。均非空跑；`pytest -q` 71 passed 证。

**ⓔ 判据射程／洗白口**：§6 L92-93 把空格并列 action 声明「已知残留、fail-open」，前提「非合法多 action SQL」。该前提**是洗白口风险**：门对**原始文本**匹配，**无任何代码层判定「合法 SQL」**（执行面不消费该声明）；「PG 语法」只在迁移**执行期**（下游、非门）强制。⇒ 门的 fail-closed 契约被一个声明面假设架空。处置：门不得依赖「SQL 良构」假设——要么解析校验、要么 fail-closed；当前二者皆无 ⇒ 责任层缺口。

**ⓕ 回归**：`cd server && ./venv/bin/python -c "from pathlib import Path;from src.data_platform.migration_policy import scan_unsafe_lines as s,LEGACY_FROZEN as L;f=sorted(Path('migrations/versions').glob('*.py'));h=[x.name for x in f if s(x.read_text(encoding='utf-8'))];e=set(L)|{x.name for x in sorted(Path('migrations/versions').glob('0122_*.py'))};print(len(h),len(set(h)-e),len(e-set(h)))"`
**期望** `16 0 0`；**实得** `16 0 0` ⇒ 命中集 ≡ LEGACY_FROZEN∪{0122}，零差分，无回归。

## 五、结构性判断（减法式豁免 → action 级切分）

**架构判据（非成本）**：
- **单一真源**：豁免「形态」散落 `EXPLICIT_EXCLUSIONS` 正则，被 `scan_unsafe_lines` 全局 `re.sub` 消费；无「完整良性 action」真源。
- **依赖方向**：全局减法 correctness 依赖作者预想 SET DEFAULT 后所有可能破坏性关键词 ⇒ deny-list **倒置**依赖（大小写/整句洗白/贪婪跨分隔符/列名假红/锚点被摘——**五轮实证漂移**）。
- **契约闭合**：门宣称 fail-closed、`rc=0`＝合规；ⓐ下 `rc=0` 却含破坏性 op ⇒ 契约被破（与 P0-B/C/D 同族「声明面不消费」）。
- **声明面被执行面消费**：§6 残留声明无对应断言（SET DEFAULT-在前＋空格漏检无测试）⇒ 声明 ≠ 执行。

**独立判：本批应治本**（action 级切分：按 `,` 切 `ALTER TABLE` 多 action、逐 action 判定，排除只对**精确 action 形态**生效，局部 deny→allow）。理由：同根已产五轮 P0/P1；架构上契约闭合缺口＋声明面未消费；deny-list 必漂预言第六次。
若挂账：须保留书签（已有 `待办.md:22`）且把「无静默风险」更正为「门契约完整性受损＋声明未消费＋持续漂移」，不得静默丢弃。（注：该缺口当前非 P0，因 PG 兜底挡住数据丢失；此点同意书签的 severity，反对其单薄定性。）
