## 四、全新红队（可复现构造）

**ⓐ 减法式豁免第五次漂移**（regex `\bSET\s+DEFAULT\b[^,;]*`，`migration_policy.py:119`）

*吃过头（漏检）——`[^,;]*` 不含空格，P0-D 只堵了 `,`/`;`：*
```
实测（scan_unsafe_lines）:
  ALTER COLUMN c SET DEFAULT 1 DROP COLUMN d            ⇒ 0  ✗漏检（空格并列）
  ALTER COLUMN c SET DEFAULT (SELECT 1) DROP COLUMN d  ⇒ 0  ✗漏检
  ALTER COLUMN c SET DEFAULT 1 DROP COLUMN d -- note   ⇒ 0  ✗漏检
```
均仅「非合法多 action SQL」（空格分隔在 PG 语法错误），由 DB 执行层兜底，无静默风险，与 §6 残留声明一致。

*吃不足（假红）——默认值含逗号时 `[^,;]*` 截断，残句关键词重新暴露：*
```
  ALTER COLUMN c SET DEFAULT 'a, DROP TABLE t'   ⇒ 1  ✗假红（逗号截断→', DROP TABLE t' 命中）
  ALTER COLUMN c SET DEFAULT 'foo, TYPE bar'     ⇒ 1  ✗假红（→'TYPE bar' 命中）
```
根因同为 `[^,;]*` 截断；且这是门既存 quote-unaware 弱点（任意字符串含 `DROP TABLE` 都误命中）的**新触发路径**，非本批新引入（旧 regex 对该例同样 ⇒1）。

**ⓑ 结构性（见五）｜ⓒ S7n（见下）｜ⓓ 新用例（见下）｜ⓔ 判据射程（见五）｜ⓕ 回归（见下）**

**ⓒ S7n 断言强度**：**真断言，非空跑**。语料 `ALTER TABLE demo_t ALTER COLUMN payload SET DEFAULT 1 , TYPE varchar(8)` 恰是 P1-G 例；若锚点被摘则残句 `, TYPE varchar(8)` 失配 ⇒ rc=0，故 `rc≠0` 真正证明锚点保留+TYPE 命中；另 `grep "破坏性 DDL 命中"` 二次确认（`run_scenarios.sh:518-529`）。

**ⓓ 新用例是否真断言**：**均真断言**。`test_exclusion_keeps_alter_column_anchor`（`test_migration_policy.py:499-514`）三 assert：`==[]`/`truthy`/`==[]`；`test_spec_claims_have_cases`（`:517-527`）三 for-循环含真断言。无 `assert True`/纯 import。

## 五、结构性判断（减法式豁免 → action 级切分）

**结论：挂账（非本批治本），但须保持一等挂账随身 repro。**

架构判据（非成本）：
1. **依赖方向**：`re.sub(rx," ",s)`（`migration_policy.py:240-241`）在 SQL token 抽象层之下操作，豁免机制不知道 action 边界，只能按文本「吃到分隔符为止」。
2. **契约闭合**：豁免契约＝「SET DEFAULT 豁免、同句他 action 仍判」仅在「合法 SQL（逗号分隔）」子域闭合；空格并列不闭合 ⇒ 契约未全闭。
3. **单一真源/deny-list 必漂**：`[^,;]*` 是开放枚举，违反「封闭式优于开放枚举」；四轮 P0/P1（大小写／整句洗白／贪婪跨分隔符／列名假红／锚点被摘）同源互咬。

**为何不判「本批必须治本」**：当前漏检仅非法 SQL（PG 语法层强制兜底，无静默数据错误），不构 P0；且待办 row 22 已带显式复活条件（多 action 裸 SQL 迁移出现／下批门加固）。改 action 级切分是非平凡设计裁定，与本轮「1 行代码/断言级、不新增设计裁定」前提冲突。

**ⓔ 判据射程**：§6「非合法多 action SQL」前提本身可接受——「合法 SQL」射程由 **PG 在门下一层强制**，门只做文本近似、本就不应解析 SQL。但该前提**不得泛化为洗白口**：每次引用须随身带「PG 语法可复现证伪」+ 复活条件，否则未来漂移皆可变相挂账。
