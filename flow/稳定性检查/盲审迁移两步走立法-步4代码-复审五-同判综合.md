## 四、结构性裁定：**否决 action 级切分**（并给三项加固）

**裁定：不本批治本，也不仅是「挂账」——是「明确否决该方向」。** 依据（**架构判据**，非成本）：

1. **职责层级（决定性）**：门的职责层级＝**文本近似拦截**，**不是 SQL 解析器**（B6 射程判据正确：「门只做文本近似、本就不应解析 SQL」）。「action 级切分」＝在文本层实现**半个 SQL 词法器**——切分规则自身会成为**新的不闭合面**（字符串内逗号、括号内逗号、`SET DEFAULT func(1,2)`），**第六轮争议点从「豁免粒度」平移到「切分粒度」**，漂移不消失、只搬家。⇒ **职责越级**。
2. **单一真源**：「合法多 action SQL 的分隔规则」真源＝**PG 语法**，非本模块。让本模块复刻它 ⇒ **制造第二个（且不完整的）真源**——违反本仓第一判据。
3. **契约闭合已达成的准确表述**：`声明面 ∩ 合法可执行 SQL 面 ⊆ 执行面`（R1/R2 实测）⇒ **射程内闭合**；射程外（非法 SQL）由 **PG 在门下一层强制兜底**（第二道防线），无静默数据风险。
4. ⇒ 真正的缺口**不是「没治本」**，而是 **A6 指出的「声明面未被消费」**——§6 声明了该残留，却**没有断言锁定它** ⇒ 未来漂移**无测试捕获**。修法＝**补断言**（用本仓刚立的纪律「承诺须有用例」），**不是**改架构。

**三项加固（随本批落地）**：
- **加固①（反向钉）**：新增用例显式锁定「空格并列 ⇒ 当前 fail-open（0 命中）」，并**对照**「合法逗号分隔 ⇒ 必须命中」⇒ **射程内漏检即红**。
- **加固②（定性升级）**：§6 该条由「无分隔符处紧跟 action ⇒ 已知残留」升级为「**门契约在合法 SQL 子域闭合、射程外不闭合；PG 为第二道防线；不得援引本条把射程内的漏检降级**」（吸收 A6 的定性 + B6 的 ⓔ）。
- **加固③（复活条件收紧）**：待办该条复活条件由「出现多 action 裸 SQL 迁移」改为「**出现『`SET DEFAULT` 在前 + 空格并列后续 action』形态的真实迁移**」（grep 可机械判定）。
