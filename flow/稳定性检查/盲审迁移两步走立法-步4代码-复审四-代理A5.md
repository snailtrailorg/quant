## 严重（P1）

### P1-A5-1｜单 action 形态用 `\w+` ⇒ 引号列名 / schema 限定列名的真排除**失效**，引入**新假红**
`migration_policy.py:113` 的 `ALTER\s+COLUMN\s+\w+\s+SET\s+DEFAULT\b`：列名部分只允许 `[A-Za-z0-9_]`。
**可复现构造**（`/tmp/a5_redteam.py`）：

```
op.execute('ALTER TABLE t ALTER COLUMN "c" SET DEFAULT \'TYPE\'')   # 双引号标识符（PostgreSQL 合法）
op.execute("ALTER TABLE t ALTER COLUMN t.c SET DEFAULT 'TYPE'")     # schema 限定
```
实得：cur = **1 处命中**（`alter_column_type`）；`da22709` = **0**。
机理：排除项不触发 ⇒ 残句保留 `ALTER COLUMN … TYPE`（`ALTER\s+COLUMN[^;\n]*\bTYPE\b`）⇒ 误判。而 `SET DEFAULT 'TYPE'` 是 §1.3 明文豁免的元数据放宽 ⇒ **执行面与声明面冲突**。
blast radius：全仓 141 迁移零影响（见 R3），方向是假红（fail-closed）⇒ 不定 P0。但它是**本轮修复引入的新红**，且修法是 1 个 token：
**实测严格更优的候选**：`[^\s,;]+`（见 R7）——既不能跨空格也不能跨逗号（关死原漏洞），又能吃下 `"c"` / `t.c` / `\"c\"`。
