## 三、分歧与仲裁

### 分歧 1 —— 引号列名假红：P1（A5）还是「一般/fail-closed」（B5）？⇒ **采纳 A5 的 P1 + A5 修法**

- **性质**：`ALTER TABLE t ALTER COLUMN "c" SET DEFAULT 'TYPE'` ⇒ 本轮（`\w+`）**1 命中**，期望 **0**（§1.3 明文豁免 `SET DEFAULT`）。主会话一手实测确认（见四 C2）：贪婪旧 0 / 本轮 1 / A5 修法 0。
- **为何不是「fail-closed 即可接受」**：B5 的方向判断对**未声明形态**成立（body-equality 纯注释判红即按此裁为非缺陷），但此处**推翻的是一条§1.3 明文的豁免承诺** ⇒ 属「声明面 ≠ 执行面」，与本批 P0-B/C/D **同一判据族**；只是方向相反（假红而非漏检）⇒ 定 **P1**（非 P0：不放行破坏性 op）。
- **修法**：采纳 A5 的 `ALTER\s+COLUMN\s+[^\s,;]+\s+SET\s+DEFAULT\b`（B5 的 `[\w".]+` 不覆盖反引号与 `schema.col` 之外的形态，面更窄）。实测：假红转 0，P0-D 四例仍 1，真排除全 0，全仓仍 16/33 且命中文件集一致。

### 分歧 2 —— 减法残留洞（B5 独有）⇒ **采纳 P1；修法须与分歧 1 联合验证**

`ALTER COLUMN c SET DEFAULT 1 , TYPE varchar(8)` ⇒ **0 命中**：减法把 `ALTER COLUMN … SET DEFAULT` 片段摘掉后，残句失去 `ALTER COLUMN` 锚点 ⇒ `ALTER\s+COLUMN[^;\n]*\bTYPE\b` 失配。
- **定 P1 而非 P0**：四口径（含 `9fa0e7f`）皆 0 ⇒ **非回归**；且该 SQL 形态在 PG 中是否合法存疑（通常需写全第二个 `ALTER COLUMN`）⇒ 可达性低于 P0-C/D。但它使 §1.3「逗号并列同语句破坏性 op 仍须命中」的承诺为假 ⇒ 必须处置。
- **修法（B5 已实测）**：`scan_unsafe_lines` 的 `re.sub(rx, " ", …)` 改为替换为 `"ALTER COLUMN"`（保留锚点）⇒ 该例转 1、真排除仍 0、全仓仍 16/33。**须与分歧 1 的 `[^\s,;]+` 联合重验**（两处改动相互作用）。

### 分歧 3 —— 三条新承诺零用例 ⇒ **同意；且是本会话自己失守**

主会话上一轮刚立纪律 a「**承诺必须先有用例**」，本轮即在 §1.1（宽口径未列对象）、§1.3（收紧类保守归入）、§6（动态 SQL 无能）写了**三句零用例的承诺**——A5/B5 **各自独立**点出。⇒ 补 3 条断言（三句经实测**都为真**：`DROP VIEW/TRIGGER/SCHEMA/FUNCTION` 实测全 1；`DROP DEFAULT`/`DROP NOT NULL` 实测全 1；`"DROP "+obj+" TABLE t"` 实测 0）。
