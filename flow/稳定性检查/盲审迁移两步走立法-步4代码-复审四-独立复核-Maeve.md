## 三、自证伪留痕（**为什么我初判错了**）
我把「基线命中 > 当前命中」**直接**当作「检测面缩小」，犯了两条同型的错：
1. **未先把语料约束在「可执行 SQL」上** ⇒ 把不可执行形态的差异也算成漏检；
2. **未先核规范 §6 是否已声明该边界** ⇒ 把「已声明的已知残留」当成新洞。

⇒ 与本题四轮反复出现的**同一模式**：**先界定判定面的射程，再谈命中**。
（复核者自己的结论同样要被证伪——本条即为例。）

## 四、遗留（挂账建议，**非 P0**）
- **[技术债]** 排除项 #3 用 `[^,;]*`，是**开放枚举**（「吃到分隔符为止」）⇒ 按本仓
  「**封闭式优于开放枚举 / deny-list 必漂**」纪律，宜改**精确匹配默认值表达式**或
  **action 级切分**。复活条件＝本仓出现多 action 裸 SQL 迁移 或 下一批门加固。
- **[文档]** 「修复不得缩小检测面」这条常设判据，**射程须写明＝合法／可执行 SQL**
  （否则下一轮仍会有人用非法语料测出「缩小」而误判 P0——本轮已发生一次）。

# 语料：合法面多 action 用 ","；非法面用 " "。逐版本 importlib 加载后比对命中数。
def h(mod, text):                      # 命中数
    return len(mod.scan_unsafe_lines(text))
def wrap(sql):                          # 包成迁移文件形态
    return ("from alembic import op\ndef upgrade():\n    op.execute(%r)\n"
            "def downgrade():\n    pass\n" % sql)
# 缩小 = 基线命中 > 当前命中（只应在非法语料上出现；合法语料须为 0）
