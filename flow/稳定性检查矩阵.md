## A. 组件 × 故障模式（核心矩阵）

### A1. live-task runner（现状：每任务一进程）

| 故障模式 | 结论 | 证据/说明 |
|---|---|---|
| crash | ✅❌ | Restart=always 自愈 ✅（12号雷5后验证）；❌ F-1 无 StartLimit → 无限重启风暴（今日 counter=59 实测）；❌ F-2 重启后 history 清零（bar_1min 空表，暖机无效）→ 因子窗口内策略行为漂移 |
| hang（停转） | ❌ F-3 | 无 WatchdogSec/sd_notify，无心跳（S1）；SIGSTOP 不死也不告警 |
| 变慢 | ⬜ | P-2：on_bar 内 PG 同步写延迟（信号落库）× PG 抖动阻塞行情线程；CPUQuota=50% 节流影响 |
| 部分失败 | ❌ F-4 | 下单"先发后写"崩溃窗口重复下单（D1，strategy.py:256 时序实锤） |
| 断连/分区 | ❌❌ | ✅ 每 10s 检查——**但是死代码**（`hasattr(gateway,"is_connected")` 而 XtpGateway 无此方法，xtp_gateway.py grep 零命中）；❌ **F-25 灾难级**：gateway `onDisconnected→login_server()` 单发自愈（xtp_gateway.py:291-297），隔夜/网络抖动一次失败即**永久断线永不再试**，且重连成功也不恢复订阅（无订阅登记）→ 表面健康实为永久失明；❌ **F-24 严重级**：`subscribe()` 在 login_status=False 时静默丢弃（xtp_gateway.py:447-450 无 else 无日志）→ 启动竞态=出生失明零报错；✅ PG 侧连接池 pre_ping+recycle 自愈（db.py:31-37） |
| 资源耗尽 | ✅❌ | MemoryMax=1G ✅（雷5）；❌ F-1 全局 OOM 随机受害者（D4，swap 只缓冲）；fd/连接数 ⬜ P-3 |
| 状态损坏 | ⬜ | P-2：history 列表并发访问（event 线程 append vs 主循环 warmup 重填 `history[:] =`）——**已知嫌疑，需代码确认是否有锁** |
| 时钟异常 | ⬜ | P-3：NTP 跳变对 BarGenerator 分钟切分/ts::date 查询影响 |
| 级联失败 | ⬜ | P-2：PG 挂 → runner 依赖面（live_task 读/status 查/snapshot 写/risk check） |
| 权限/配额 | ✅ | polkit 修复后 Web 启停全通（雷2/3） |
| 原生库异常 | ✅ | teardown ABRT 已修 os._exit(0)（雷6）；segfault 死锁 ⬜ P-5 注入 |
