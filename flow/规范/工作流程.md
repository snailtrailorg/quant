# 工作流程

> **两个层级，别混**——这是本文件的第一件事：
>
> - **§一 项目主循环（项目级）**：项目从「立项」走到「里程碑验收 / 演进」的顶层流程。`charter.md` / `plan.md` 在这一层。
> - **§二 单任务流程（任务级）**：一个任务 / 批次从「取项」到「收口」怎么走。**其强制门禁顺序 = 独立文件 `八步法.md`**。
>
> 贯穿两级的规则：**§三 两制式** · **§四 分层归属** · **§五 核心机制** · **§六 目录归属**。
>
> **注意**：`charter.md` / `plan.md` 属**项目级**（§一）——一个任务**不**走「立项 / 规划」这两步；每个任务走的是 §二 那六步。

## 一、项目主循环（项目级）

```
① 立项 ──> ② 规划 ──> ③ 迭代交付 ──> ④ 沉淀 ──> ⑤ 验收 / 演进
               ↑                                        │
               └──────────── 新方向 / 复盘 ───────────────┘
```

| 环节 | 做什么 | 落在哪 |
|---|---|---|
| **① 立项** | 钉死项目的目标 / 范围（做 + 明确不做）/ 约束 / 成功标准 / 角色。全项目只做一次（大改方向时重填） | `flow/charter.md`（所有 Agent 开工必读第一份） |
| **② 规划** | 里程碑 + 任务拆解（每个任务标：负责角色 / 输入 / 产出落哪 / 验收标准） | `flow/plan.md`——**计划即契约**，要偏离先改这里再动手 |
| **③ 迭代交付** | 把里程碑拆成**批次 / 任务**，逐批交付；**每个任务走 §二** | 任务文件 `flow/任务/批xxx-描述.md` |
| **④ 沉淀** | 每批收工：进展（接力棒）、决策、坑、提炼的规则各归其位 | `flow/进展/<ISO周>.md` · `decisions.md` · `踩坑记录.md` · `CLAUDE.md` |
| **⑤ 验收 / 演进** | 里程碑验收（如「生产一交易日无事故」）→ 达成后推进下一里程碑 / 复盘 | 回 ② 更新 `plan.md` |

**要点**：项目绝大部分活动发生在 **③ 迭代交付**——一个里程碑拆成很多批次，每批 = 一个任务，走 §二。

## 二、单任务流程（任务级）

> **强制门禁顺序见 `八步法.md`**：方案双盲审 → 编码 → 代码双盲审 → 单测 → 提交 → 部署 → 集成测试；**违反顺序＝返工**。
> 本节只补它**没写**的那半——任务**从哪来、文档怎么流转、怎么收口**。

```
待办取项（flow/待办.md）
  ↓
⓪ 取证 ── 先跑事实采集，产出「事实附录」（表/列/约束/键/单元/阶段/存量形态）
  ↓
① 立项分析 ── 纯实施 ｜ 还是 设计/契约变更？（变更必须先进 ②）
  ↓
② 设计先行（仅设计变更）── 改设计文档，重写整篇使其自洽（见 §三）
  ↓
③ 任务文件 ── flow/任务/批xxx-描述.md，引用 ② 的章节，只写实施步骤
  ↓
④ 挂待办行 ── flow/待办.md 加一行索引（概要一句话 + 指向任务文件）
  ↓
⑤ 执行 ── 门禁走 八步法.md（方案双盲审 → 编码 → 代码双盲审 → 单测 → 提交 → 部署 → 集成测试）
  ↓
⑥ 收口 ── 删待办行 ｜ 进展写简述 + 引用 ｜ 任务文件归档
```

### ⓪ 取证（事实层，先于一切）

> 立规缘由（2026-11-19，批189-M1）：一份 90 行的迁移方案，双盲审抓出 **10 个 P0**，其中 6 个是 `grep` 三十秒可查的（两张表其实早已存在、外键目标不存在、正则会拒掉真实 provider 名）。根因不是审核不努力，而是**写作时在凭印象陈述事实**。审核是抽样，抽样抓事实错误必然漏。

**定义**：事实断言 = 关于「表/列/约束/索引/触发器/Redis 键/端点/systemd 单元/部署阶段/wrapper 行为/存量数据分布」的陈述。

**规则**：

1. **先取证，后动笔**：写设计/任务/方案前，先跑事实采集，产出 `flow/任务/批xxx-事实附录.md`（可用脚本生成，也可 psql/`grep` 输出粘贴）。附录只写「是什么」，不写判断。
2. **无出处不落笔**：方案里每条事实断言必须指到附录条目或 `file:line` / psql 输出。**没有出处的句子不许写**。
3. **来源要认全**：表可能来自 `create_table`、**rename**、或幂等 SQL；列可能来自 `add_column` 或初始 schema；**默认值/状态可能由 DML 迁移（UPDATE）改写**（批189 实录：虚拟账户 `enabled` 由 0128 的 UPDATE 置 false，只解析 DDL 会记成 true）。只查一种来源=没查。
4. **分母思维**：凡「N 处引用 / N 个消费者」必须由脚本扫描得出（扫写点与读点），**不接受人工列举**；扫描结果进附录，清单只从附录抄。
5. **取值域交叉**：契约里的正则/枚举，必须拿真实取值跑一遍（如 `emt_emq` 是否过 `^[a-z][a-z0-9-]{1,30}$`）。
6. **数据形态要有判据**：凡依赖「某类行不存在/某列非空」，必须给出 SQL 判据并在前置检查里执行；观测面被过滤（如 API 隐藏 `is_virtual` 行）时须显式声明「不可见」。

**已有工具（模型参考）**：`scripts/verify_b189_schema_facts.py`（解析迁移建表/改名/加列 + `account_id` 读写分母）、`scripts/verify_b189_docs.py`（文档断言台账）。新批次按同款写自己的。

### ① 立项分析

先判断这个任务属于哪一类，决定后面走哪条路：

| 类型 | 判据 | 后续路径 |
|---|---|---|
| **纯实施** | 设计已定，只改实现 | 直接进 ③ |
| **设计变更** | 契约 / 结构 / 取舍要动 | **必须先进 ②**，再进 ③ |
| **纯运维 / 例行检查** | 不改代码 | 抄 `flow/规范/` 里的手册（如 `观察日三查.md`），不进本循环 |

### ② 设计先行（仅在改动设计时）

**顺序是硬的：设计文档先改，任务文件后写。**

反过来（先写任务文件、设计文档后补）会立刻产生「任务文件里一套方案、设计文档里另一套」——两处真源，漂移从此开始。

改法见 §三「重写制」。

### ③ 任务文件

`flow/任务/批<编号>-<描述>.md`，按 `任务模板.md` 写。要点：

- **正文只写**：目标 / 范围（做什么 + 明确不碰什么）/ 实施步骤 / 验收命令 / mock 方式。
- **设计一律引用**：写「见 `docs/architecture/A0x-…md` §N」，**不复制**方案段落。
- 为什么：设计文档是方案的真源。任务文件复述一遍＝造第二个真源，改一处忘一处即失准。

### ④ 挂待办行

`flow/待办.md` 是**索引层**，一行 = 一个未闭合项：

```
| # | 事项（一句话） | 状态 | 方案 | 任务文件 |
```

**禁止**把实施细节、上产记录、裁定推理写进待办——那些各有归宿（见 §四）。

### ⑤ 执行

门禁走 `八步法.md`：顺序强制，未过双盲审不得编码、未过测试不得提交、未过审核不得部署。

**事实附录是执行输入**：编码前确认附录存在且被方案引用；编码中发现的与附录不符处，先改附录再改代码。

**度量（每批收口记一次）**：双盲审 P0 按两类计数——**事实类**（表/列/键/单元/阶段写错或漏）/ **判断类**（取舍、边界、风险）。**事实类 P0 应为 0**；出现即记为该批“工序缺陷”，回查 ⓪ 漏了哪一类来源。

### ⑥ 收口

| 动作 | 落在哪 |
|---|---|
| 任务完成 → **删掉待办那一行**（不留行内史） | `flow/待办.md` |
| 完成史：一句话简述 + 引用（任务文件 / 设计文档 / commit / release id） | `flow/进展/<ISO周>.md` 顶部 |
| 任务文件归档 | `docs/obsolete/任务归档/` |
| 过程中的裁定与理由 | `flow/decisions.md` |
| 过程中的坑与教训 | `flow/踩坑记录.md` |

## 三、两制式：什么该追加，什么必须重写

**这是本体系最容易出错的地方，单独立法（2026-10-04 用户裁定）。**

| 制式 | 适用 | 文件 | 为什么 |
|---|---|---|---|
| **追加制**<br>（append，新的放最上面） | 流水 / 事件 | `flow/进展/<周>.md`<br>`flow/踩坑记录.md`<br>`flow/decisions.md` | 它们是**时间线**——追加就是它们的正确形态，历史本身就是内容 |
| **重写制**<br>（改就重写整篇） | 状态 / 规则 | `docs/architecture/`<br>`docs/design/`<br>`flow/方案/`<br>`flow/规范/`<br>`CLAUDE.md` | 它们是**当前状态的快照**——追加会把它变成「反反复复的时间线」，读者要拼才能得到真相 |

### 重写制怎么操作

- ❌ 在末尾加一节「> 2026-10-05 更新：……」，让新旧说法并存
- ✅ **重读全文，把变化揉进正文各处，删掉被取代的旧表述**，让整篇自洽

允许保留**一行时态声明**（如「现行：… ｜ 挂起待实施：…」）——那是状态标注，不是变更日志。

**判据**：一个新会话第一次读这份文档，能不能**直接**得到「现在的真相」？

- 能 → 合格
- 要翻时间线、要比对前后版本才能拼出来 → 不合格，重写

**变更史去哪了？** `git log`。文档不承担变更史职责。

## 四、分层归属（内容 → 归宿）· 单一真源

| 内容 | 归宿 |
|---|---|
| 技术方案 / 勘察推理 / 设计取舍 | `docs/architecture/`（架构级）· `docs/design/`（模块级 D 系列）· `flow/方案/`（待定稿方案） |
| 实施步骤 / 验收清单 / 限定范围 | `flow/任务/批xxx-描述.md` |
| 完成史（上产 / 五证 / 交付数） | `flow/进展/<ISO周>.md` + git log |
| 裁定与理由 | `flow/decisions.md` |
| 问题与教训 | `flow/踩坑记录.md` |
| 例行检查 / 运维手册 | `flow/规范/` |
| 已完成任务文件 | `docs/obsolete/任务归档/` |

**一句话判据**：协调 / 推进项目的 → `flow/`；要交付的内容 → `docs/`（知识）或 `server/src/`（代码）。

> 本表是**唯一真源**；`flow/待办.md` 表头只引用不复制（复制＝两处真源）。

## 五、三个核心机制

### A. 进展日志 = 接力棒

位置 `flow/进展/<ISO周>.md`（周号 `date +%G-W%V`），**追加、新的放最上面**；`flow/进展.md` 只留索引 + 「最近 3 条」。**最近一条 = 当前交接棒**（`CLAUDE.md` 开工必读）。

每条字段：**做了什么 / 为什么 / 怎么理解 / 产出（路径）/ 问题→解决 / 下一步**。

**铁律：只带「指针 + 增量」**——指向真实产出（给路径）+ 这一棒新增，**不重抄内容**；接手方顺指针回源文件读。

（为什么是一个 append 文件而不是 N 张卡或覆盖快照：N 张卡会堆爆；覆盖会丢历史、没法接力。append 一个文件 = 留历史 + 不爆 + 顶部即棒。）

### B. 共用入口 = 运行时合同

`CLAUDE.md` 每个会话自动加载、是**两个工具共用的规则通道**。精要规则、约束、目录地图、指针必须写在它里面。`AGENTS.md` 软链到它，写一次两端生效。

### C. 跨模型评审

主控（持上下文 / 编排）+ 独立第二双眼。何时：每次交付前、高风险逻辑、设计岔路口。强制形态见 `八步法.md`（一律独立双盲）。

**评审只判「判断类」**：取舍是否成立、边界是否清楚、风险是否覆盖、契约是否自洽。事实核验是 ⓪ 的职责，不是评审的职责。

- 评审若抓到事实类错误 → **记工序缺陷**（⓪ 漏项），不算评审成绩；同时把该类来源补进 ⓪ 的检查清单。
- 迁移/改 schema/改部署这类高风险方案，评审固定六类必查并逐类给 `file:line`：①表列来源 ②约束与依赖序 ③存量数据形态 ④键与单元读写点 ⑤部署阶段与 wrapper ⑥契约取值域。缺证据视为该类未审。

## 六、目录归属

| 文件夹 | 放什么 |
|---|---|
| `flow/` | 控制层：`charter.md`（章程）· `plan.md`（里程碑契约）· `待办.md`（索引）· `进展/`（append 日志）· `任务/`（进行中任务规格）· `方案/`（待定稿方案）· `decisions.md` · `踩坑记录.md` · `规范/` · `审计/` · `稳定性检查/` |
| `docs/` | 内容层：`architecture/`（架构真相 + 契约）· `design/`（模块设计 D 系列）· `manual/`（使用手册）· `reference/`（外部资料）· `obsolete/`（归档） |
| `CLAUDE.md` | 运行时合同（见机制 B） |
| `server/src/` · `web/src/` | 代码产物本身 |

**判据**：这份东西是**协调 / 推进项目**的 → `flow/`；是**项目要交付的内容** → `docs/`（知识 / 文档）或 `server/src/`·`web/src/`（代码）。

控制层**指向**内容层：任务文件 / 进展条里的「产出（路径）」就是 `docs/`·`server/src/` 路径。
