# 异常处理规范（S110/S112 守门）

> 2026-09-29 批 81 落地（技术债清单 P1-1 的处置规则）。目的：让「静默吞异常」从默认行为变成需显式声明的行为。

## 铁律

`except` 块内必须有且仅有三者之一，否则违规：

1. `raise` / `raise ... from e`
2. `logger.warning(..., exc_info=True)`
3. 一行注释写明为什么可以吞（`pass` 带 `# noqa: S110  # <理由>`）

设计意图：`# noqa: S110` 就是那份「可以吞」的声明——在 diff 里可见、可 grep、可 review。静默不是禁止的，但必须显式声明理由。

## 分三类处置

| 类 | 判据 | 动作 |
|---|---|---|
| A 合法忽略 | try 内含清理原语（rollback/close）/ 解析转换带默认值 / 同函数已有 logger | 补理由注释 + `# noqa: S110` |
| B 应记日志 | 往快照/汇总 dict 塞可缺省字段、事件发布 | 加 `logger.warning(..., exc_info=True)` |
| C 应上抛 | 贴近下单链/风控卡口 | 单独 review 后再定，不批量改 |

C 类必须单独看的位置（勿批量改）：`strategy_runner/trading.py`、`strategy_framework/broker.py`（贴近下单）、`risk_control/risk.py`、`data_platform/rate_limit.py`、`data_platform/data_source.py`、`alert_notify/dispatch.py`（fail-open 熔断铁律本体）。

## 参考范式

`health_monitor/collector.py` 是好样板：内层收窄成 `except (TypeError, ValueError)`，外层才 `except Exception`；外层吞但紧跟显式降级（`if thresholds is None: use defaults`）。

## 禁止

- **绝不用 `ruff check --fix` 批改 S110**——ruff 无法推断语义，自动修可能改控制流
- **不要给 `pass` 补 `logger.debug` 充数**——debug 级生产默认不输出，等于没改
