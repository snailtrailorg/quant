# 术语表（进展日志与协作约定的压缩词 → 白话释义）

> 进展日志（`flow/进展/`）与各流程文档里用了大量自造压缩词。本表是唯一释义词源——
> **写进展/文档时，优先用白话；确需用压缩词时，首次出现处以 `词（释义）` 标注，并保证本表有定义。**

## 流程类

| 词 | 释义 |
|---|---|
| **当班全弧** | 一个批次在单个工作会话内走完的完整流程（方案 → 过门 → 编码 → 盲审 → 测试 → 部署） |
| **过门** | 方案/代码通过双盲审，进入下一阶段（例「方案 v2 过门」= 评审通过，可开工编码） |
| **交接棒** | 会话收工时追加到进展日志的一条进展，作为下一个会话的接续起点 |
| **八步法** | 强制交付流程：方案 → 双盲审 → 编码 → 双盲审 → 单测 → 提交 → 部署 → 集成测试 |
| **双盲审** | 两个独立评审（A 侧重正确性 / B 侧重可执行性或隐性 bug）分别审查同一方案/代码，意见合并处置 |
| **快审** | 轻量级评审（微批/低风险改动跳过完整双盲审） |

## 工作状态类

| 词 | 释义 |
|---|---|
| **挂账** | 记录一笔欠下的待办/已知缺口，暂缓处理、留待后续批次清偿 |
| **收编** | 把散落的代码、逻辑、遗漏点归入统一机制（例「五点缺口收编」= 五处遗漏统一纳入熔断归因） |
| **上产** | 部署到生产环境 |
| **彩排** | staging 环境的部署预演；彩排绿（通过）才碰生产 |
| **波次** | 部署时按服务单元分批重启的批次（波次清单、波次重启） |

## 技术机制类

| 词 | 释义 |
|---|---|
| **钉** | 测试里的断言（assert），用于锁定某个行为不回归（例「真路径钉」= 真实路径的测试断言） |
| **守门** | 自动化校验闸门（分层守门、防漂移闸、词条守门） |
| **闸** | 校验/拦截机制（DDL 门、部署窗闸、防漂移闸） |
| **暖机** | 任务启动前的数据预热（加载历史 bar、回放） |
| **回灌** | 历史数据回放到流（hub 回灌流，供 worker 暖机消费） |
| **冻结** | 数据流/进程的挂起（ts 缺口冻结、窗关挂起） |
| **熔断** | 接口调用失败超阈后短期停止调用（熔断器/breaker，配合限速 pacer） |
| **锚** | 关键参考点/锚点（勘察锚点、键锚点） |
