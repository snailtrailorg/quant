# 破坏性迁移两步走（expand → contract）规范

> 立法：批 111（2026-10-07 威廉姆裁定链）。本文件讲 DDL **何时写**（时间维度）；
> `docs/design/D18-数据库操作规范.md` §2.3 讲 DDL **怎么写**。
>
> **⚠ 真源声明**：判定表、受管集、**冻结 legacy 白名单（`LEGACY_FROZEN`）** 的**可执行真源
> ＝`server/src/data_platform/migration_policy.py`**（纯 stdlib、单一实现、两用：pytest import +
> 部署门独立脚本）。本表仅为说明；**两者不一致时以代码为准**——发现不一致请改本文件，
> 不得在别处复刻判定逻辑。

## 1. 判定表（说明版；真源见上）

### 1.1 回滚安全类（命中 ⇒ 须两步走声明，进闸门）

| op | 为何危险 |
|---|---|
| `DROP TABLE` / `DROP COLUMN` / `DROP INDEX`（裸 SQL 与 `op.drop_table/drop_column/drop_index`） | 数据不可逆丢失；旧代码读新 schema 直接崩 |
| `ALTER COLUMN … TYPE` / `alter_column(type_=…)` | 类型收窄可截断/丢数据 |
| **列改名**（`new_column_name=` / `RENAME COLUMN`） | 旧代码读旧列名崩——**2026-09-24 生产分裂事故当事 op**（`0104`），原门正则的盲区，批 111 纳入 |
| **表改名**（`RENAME TO` / `op.rename_table`） | 旧代码读旧表名崩 |

### 1.2 前向危险类（不进本闸门，归 D18 §2.3）

`add_column(nullable=False 无 server_default)`、非 `CONCURRENTLY` 的 `CREATE INDEX`、大表重写。
**为何排除**：它们不破坏「旧代码可读新 schema」⇒ 与回滚安全无关；混进 `phase=` 语义会让机制失焦。

### 1.3 显式排除（真消费——宽口径先命中、排除项后洗白）

| 形态 | 理由 |
|---|---|
| `DROP CONSTRAINT` / `op.drop_constraint` | 放宽约束不删数据；**机制自洽的必要条件**——`0116`（唯一两步走实例的 expand 侧）upgrade 段含它，不排除则 P0-2 收紧后该实例反成非法 |
| `ALTER COLUMN … SET DEFAULT` | 元数据放宽、可回退（`0095` 实例） |

## 2. 受管集

**本版相对上一已部署版「新增 ∪ 内容变更」的迁移文件**。判据＝**内容指纹（sha256）差集**，非文件名差集——
同名文件的就地改动同样落网（复审 P1-6）。计算收在模块 `managed_set(new_dir, prev_dir)`，
部署门 bash **零判定、零映射、纯转发**（退出码原样上浮，由 `release.yml` 阶段 4 封闭式 `failed_when` 消费）。

## 3. 声明格式（文件第 1 行）

```
# EXPAND-CONTRACT: phase=expand pair=<4 位 contract id>     ← expand 步（无命中才合法）
# EXPAND-CONTRACT: phase=contract pair=<4 位 expand id>     ← contract 步（pair 须已上产且声明 expand）
# EXPAND-CONTRACT: legacy reason="<一句>"                   ← 仅历史遗留；新迁移禁用
```

`legacy` 与 `phase`/`pair` **互斥**（同现即拒——防一行声明拿双通道）。

## 4. 两步节奏

1. **expand 上产**：新结构建立（建新表/新列/双写），upgrade 段**零命中**；旧结构留存。
2. （可选）双读双写 / 回填。
3. **观察窗**：确认旧代码不再读旧结构。
4. **contract 上产**（**跨发布**——expand 与 contract 严禁同发布捆绑，门按「pair 是否在上一已部署版」判定）：
   DROP 旧结构。expand 侧残留（兼容代码）在此后清理，否则＝债。

## 5. 两条硬规则

1. **`legacy` 仅限历史遗留，新迁移一律不得标 legacy**（否则 legacy＝新绕过洞）。
   白名单冻结在**模块** `migration_policy.LEGACY_FROZEN`（15 项，**只能减不能增**；加项须用户裁定）
   ——真源住**执行侧**（部署门直接消费），测试只做别名。**部署门对该标记是「验证」而非「信任」**：
   - 名在冻结集内 ⇒ 「ℹ 可见不阻断」，但**另比 `upgrade` 段与上一已部署版逐字一致**（防改已部署迁移的函数体）；
   - 名不在冻结集 ⇒ **拒**（步 4 同判 P0-1：自声明标记不得成为零留痕的绕过通道）。
2. 新迁移要么真两步走、要么 expand-only（不命中判定表）。

## 6. 已知边界（如实列出，不假装）

- 迁移文件视为**不可变**；内容变更会被受管集捕获。**冻结 legacy** 在部署门为「可见不阻断」，
  但 `upgrade` 段须与上一已部署版**逐字一致**——**逐字＝含注释与空白**（改一个字符即拒；
  fail-closed 方向，非假红）。冻结集的 keying 是**文件名**、**不看声明**（P0-A）：冻结集内文件
  无论头写 `legacy`／`phase=contract`／无声明，一律逐字比对 `upgrade` 段。
  残留：`downgrade` 段与 docstring 不参与该比对（downgrade 是合法回滚路径）。
- **判定表匹配大小写不敏感**（P0-B）：§1.1 声明的对象是**语句本身**，而 SQL 关键字与 alembic op 名
  大小写不敏感 ⇒ `drop table t` 与 `DROP TABLE t` 同判（不含此条即成「一整类等价破坏性语句无门通过」）。
- **数据类破坏 op（`TRUNCATE` / `DELETE FROM`）不在本门判定表**：本门判的是**回滚安全**
  （旧代码可读新 schema），数据类破坏**不改 schema** ⇒ 归 `D18 §2.3` 与备份流程；🔖 挂账见
  `flow/待办.md`（复活条件＝本仓出现数据类破坏迁移需求）。
- **alembic 之外的 SQL 手工执行**不在门覆盖内。
- **仓内闸门（pytest）不在部署路径上**（部署链零 pytest）——开发期纪律闸门；prod 侧机械强制点＝
  `release.yml` 阶段 4（**恒跑**）。逃生门（`allow_contract` + `contract_reason`，调试期 🔖 待移除）
  **只能取消 rc=1 的阻断、不能免检**；**`rc=1` 语义唯一＝「有命中且拒」**——门内部错（含文件编码非法）
  **恒返 `2` 且恒红**（步 4 同判 P0-2：否则门崩溃会伪装成命中被豁免）。封闭式补集：`rc=2/126/127/137…` 一律红。
- **首部署（无上一版）门跳过**（rc=3 + 显著告警）——该窗口 prod 侧无门覆盖；与逃生门叠加＝双豁免（W6 第 4 条）。

## 7. 挂接

- **八步法**：步 1 方案即定 phase；步 3 编码写声明行（文件第 1 行）；步 5 单测跑仓内闸门
  （`test_migration_expand_contract.py` / `test_migration_policy.py` / `test_release_playbook_has_no_ddl_logic.py`）；
  步 7 上产由部署门（恒跑）机械强制。
- **D18 §2.3**：前向危险类 op 的写法规范在那边；本规范只管回滚安全类的时间维度。
