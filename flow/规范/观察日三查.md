# 观察日三查（例行检查手册）

> 来源：2026-08-28 立、09-01 影子期收官后成为常规例行；2026-10-04 自 `flow/待办.md` 抽出（待办只留索引，手册归规范）。
> 制式：**两站**——09:31 站查昨日全量 + 开盘健康；15:10 站查今日全量（门禁计数依据）。
> 修法背景（2026-08-28）：原单站 09:31 当刻查**当日** diff = 假绿（当刻当日 bar 才落 0~1 根；08-25~28 首次全量比对实证每日实有 5~10 根差异）。

## ② hub 单侧完整性（两站；批 6b 起改 hub 单侧）

**主指标 = 缺口检测**（绝对行数受已知边界扰动，不作主判）。

时窗 `ts ∈ 当日 09:31 ~ 15:01`（9:31~11:30 = 120 分 + 13:01~15:01 = 121 分 = **241 根/符号**；
第 241 根 = [15:00] 竞价桶 ts=15:01——按 ≤15:00 查恒少一根误报；口径出处 `parts.py::_in_bar_session` × 分钟末标注）。

**已知容忍**（不计缺口，逐项对日志豁免）：
1. 15:01 后到快照 = 240（竞价桶未及落库，查 `max(ts)` 与心跳 bars）
2. 盘中部署重启丢段（重启窗内分钟）
3. 中途新增订阅（该符号前段无数据）

```sql
-- 行数+窗界（≤15:01 口径；09:31 站查 current_date-1，15:10 站查 current_date）
SELECT symbol, count(*), min(ts)::text, max(ts)::text FROM bar_hub
WHERE ts::date=current_date GROUP BY symbol;

-- 缺口检测（主指标）：交易时段连续分钟序列 left join 找洞（symbol 按任务标的替换）
WITH cal AS (
  SELECT gs AS ts FROM generate_series(
    current_date + interval '9h 31min', current_date + interval '15h 1min', interval '1min') gs
  WHERE to_char(gs,'HH24MI') < '1131' OR to_char(gs,'HH24MI') >= '1301')
SELECT c.ts FROM cal c LEFT JOIN bar_hub b ON b.ts=c.ts AND b.symbol='510300.SHSE'
WHERE b.symbol IS NULL;
```

辅助：hub 心跳 8 字段（bars/gen/subs，`quant-hbcheck`）+ worker 心跳
（`quant:hb:task:<tid>` 的 bars/lag/frozen）+ worker 日志 BAR 行逐分
（`quant-journal -u "quant-live-task@*.service" --since "-1h" | grep BAR`）。
