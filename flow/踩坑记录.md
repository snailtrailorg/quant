# 踩坑记录（仍有指导价值的教训）

> 只保留**通用性强、看代码看不出来的**技术陷阱与排查方法论。一次性 bug 修复已清理（代码即答案）。

---

## PG 时区：timestamptz 必须 aware UTC 比较

- **现象**：`verify_token` 拿 naive `datetime.utcnow()` 和 PG `timestamptz`（aware）比较 → TypeError → 端点 500 → 前端显示"失效"。
- **规则**：PG `timestamptz` 列读出是 aware datetime，Python 侧必须用 `datetime.now(timezone.utc)`，**禁用** `datetime.utcnow()`（naive 且 3.12+ deprecated）。

## psycopg3：ANY() 参数必须 list 不是 tuple

- **现象**：Python tuple 被适配为行记录 `(a,b,c)` 而非数组，`ANY(tuple)` 报 `malformed array literal`。
- **规则**：`WHERE col = ANY(%s)` 的参数传 Python **list**（psycopg3 适配为 `ARRAY[...]`）。

## 部署假成功：僵尸进程占端口

- **现象**：8001 被非 systemd 的旧 uvicorn 占据 → systemctl restart 后新进程 crash-loop → 但 health 检查打到僵尸进程返回 ok → 部署报成功、新代码从未上线。
- **根因**：health 只验"端口有人应答"，没验"应答的是不是 systemd 起的进程"。
- **修复**：`restart_server()` 先 `_stabilize`（is-active 连续两次）再 health。
- **排查手法**：怀疑"代码改了没生效"→ 加 `print(...flush=True)` → 重启 → 触发 → journalctl 查；无输出=运行的不是磁盘代码。

## rsync --delete 删运行时数据

- **现象**：服务器上用户上传的头像文件每次部署后被删——本地 `static/avatars/` 为空，rsync --delete 同步删掉远端"多余"文件。
- **规则**：**运行时数据目录必须加 `--exclude`**（`deploy-server.sh` EXCLUDES 列表）。

## vue-cropper 三坑

1. **漏引 CSS** → 裁剪器内部图层全乱完全不可用。**必须** `import 'vue-cropper/dist/index.css'`（在 main.js 全局引；SFC 内引会被 scoped 污染）。
2. **fixed-box=true** → 裁剪框锁死不能缩放，选不满。应为 false。
3. 该包 CSS 自带 `[data-v-a742df44]`，组件 JS 硬编码同款 `__scopeId`——两者配套自洽，**不是**我们的 scoped 污染。
- **通用教训**：引入带 UI 的第三方组件，CSS 导入是必查项。

## v-html → v-text 迁移残留

- **现象**：XSS 修复把 `v-html` 改 `v-text` 后，原来给 v-html 准备的 `.replace(/\n/g, '<br>')` 残留，`<br>` 变成字面文本。
- **规则**：修改渲染方式时，同步清理格式转换代码。`white-space: pre-wrap` 本身就让 `\n` 原生换行。

## Element Plus：不写 type 的灰按钮像禁用

- **现象**：用户反馈中性灰按钮"给用户不可按、被禁用的错觉"。
- **规则**：每个按钮必须有语义色（蓝=主操作+常规 / 绿=启动 / 橙=停止 / 红=删除）。

## 邮件"发送成功"≠送达

- **现象**：SMTP 协议中"已接受"只代表邮件服务器收下了，不代表对方收到（国内→gmail/hotmail 投递链路问题）。
- **排查手法**：发件箱看 sent/pending/failed → sent 则查垃圾箱/服务商控制台 → failed 则看 last_error。
- **解法**：持久发件箱+指数退避+投递日志才能闭环。

## 图像网格切分

- **方法**：亮度/占比探测分隔线位置（非简单均分）→ 找内容区整体边界（过滤噪声）→ 按检测到的行列切分 → 内容居中。
- **注意**：确认格子是否统一大小、间隔宽窄（1-2px vs 大间隔），选择均分 vs 边界检测。

## Bash 工作目录跨调用持久

- `cd` 后不自动复位，下次调用仍在同一目录。跨目录操作用绝对路径。

## Edit 工具与 Unicode 字符

- 文件中的 `─`（U+2500）、`→`（U+2192）等非 ASCII 字符会导致 Edit 匹配失败。复制粘贴时注意实际字符是什么。

## 全局 replace 误伤（飞书 400 bug）

- **现象**：全局替换 `receive_id` → `open_id` 时，误把 `process_message_async` 的 `receive_id`（此时语义是 chat_id）也改了，导致群聊消息发送 400。
- **教训**：同名参数在不同上下文语义不同（receive_id 在回调解析时是 open_id，在发送时可能是 chat_id）；全局替换前 grep 确认每处调用的语义。

## systemd unit 写死 Requires=具体服务名（2026-08-17）

- **现象**：`quant-strategy@.service` 带 `Requires=postgresql.service redis.service`，而这台服务器 PG/Redis 不叫这名 → unit **永远拒载**（"Unit postgresql.service not found"），API 的 systemctl start 静默失败。
- **规则**：unit 不 Requires 具体基础服务名（各机命名不一）；用 `After/Wants=network-online.target`，进程自身首查失败退出 + Restart=always 自愈。

## polkit rules.d 不热加载（al8 实测，2026-08-17）

- **现象**：`install-services` cp 了新 49-quant.rules，quant 用户 systemctl start 仍被拒（规则未生效）。
- **规则**：改 rules 后必须 `systemctl restart polkit`（已写进 quant-deploy.sh install-services）。老 CentOS7 时代"自动重载"不可依赖。

## 远端脚本块没权限穿越 750 目录（2026-08-17）

- **现象**：install_services 以 michael 跑 `[[ -d $SRC ]]` 误报"目录不存在"——/data/.../quant 是 750 quant:quant，michael 进不去（deploy 第二跳 sudo rsync 是成功的，只有检查/ glob/cp 挂）。
- **规则**：远端 heredoc 块整体 `ssh host "sudo bash -s" <<REMOTE` 以 root 跑，别指望逐条 sudo 补。

## 裸模板 systemctl enable 产出 @multi-user 幽灵实例（2026-08-17）

- **现象**：服务器上 quant-{web-api,celery-worker,celery-beat,feishu-bot}@multi-user 四个幽灵跑了数日，吸内存引发全局 OOM。
- **根因**：Aug 11 有人对**裸模板**（`quant-xxx@.service`，无实例名）跑了 enable → wants 里出现模板软链 → systemd 以 @multi-user 实例化。飞书 @quant 实例还因 ws_client fallback（id 查不到→enabled 第一行）与 @10 重复连接同一机器人。
- **共犯**：部署脚本 enable_services/restart_feishu"收集正在运行的实例"→ 把幽灵转正。
- **规则**：① 永不对裸模板 enable；② 实例清单真相源用 DB（feishu_config），不收 active；③ install-services 尾部打印 unit-files 状态快照供人眼扫。

## 1.8G 小内存 + XTP 全市场合约加载尖峰 = 全局 OOM（2026-08-17）

- **现象**：strategy_runner 每次启动 1-5s 后被 SIGKILL（dmesg: global_oom，进程才 360M RSS，total-vm 已 1G）。
- **根因**：XTP 行情登录后拉全市场（SSE+SZSE）合约表，内存尖峰；机器 1.8G 无 swap 无余量。512M 的 MemoryMax 也会被 cgroup OOM。
- **解法**：2G swapfile（fstab 持久化）+ MemoryMax=1G。加完 swap 下一轮自启即存活。

## XTP/vnpy 原生库解释器拆除 abort（2026-08-17）

- **现象**：runner 正常退出时 `FATAL: exception not rethrown`，status=6/ABRT，systemd 记 failure。
- **解法**：finally 清理后 `os._exit(0)` 跳过原生 teardown（原生库拆除崩溃的标准疗法）。

## 新架构 runner 停止条件误查旧架构字段（2026-08-17）

- **现象**：live_task 跑 ~100s 必自杀重启；日志"策略被 Web 停止"但没人停它。
- **根因**：热加载停止检查读 `strategy_config.enabled`（旧架构），新架构任务对应的策略没 enable → 每 60s 退出；Restart=always 拉起，history 每轮清零，**信号永远攒不满窗口**。
- **规则**：新架构查自己的 `live_task.status`；旧架构（--id）才查 strategy_config.enabled。

## 前 alembic 表的列漂移：本地不复现的 500（2026-08-17）

- **现象**：服务器 PUT /api/strategy 500（UndefinedColumn: strategy_config.updated_at），本地同代码 200。
- **根因**：strategy_config 是运行时 DDL 时代建的表，**从未进迁移链**（0027 只收编了 10 张运行时表）；服务器旧形状无 updated_at，本地新版 DDL 建的有。0027 的 if_not_exists 对已存在表整表跳过，列差异永不被补。
- **解法**：迁移 0038 `ADD COLUMN IF NOT EXISTS` 补列。防再发：#48 verify_schema 列级校验。

## XTP TD 同账号同 client_id 会话复用（2026-08-17 观察）

- 会话编号 270532608 跨进程重启保持不变；串行启停无互踢。并发双 runner 同账号行为未验证——避免同时跑多个 TD runner（排错时先停旧再起新）。
