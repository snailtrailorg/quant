## 2026-09-03 · ECharts canvas 不解析 CSS var()——图内色换 var() 会静默回退默认（批一遗留）

**现象**：批一 A 档把 K线/均线/分时/回撤 markPoint 等图表内色换成 `var(--up)/--down/--ma-line`（StockDetail.vue:288/308/323/326/355/357、BacktestView.vue:75-76、Dashboard.vue 图）。这些是 echarts option 里的 color 字符串，走 `CanvasRenderer`，zrender 直接 `ctx.fillStyle = style.fill` 透传（graphic.js:319）——canvas 不解析 `var()`，非法色值被静默忽略 → 曲线/蜡烛/标记用前一次 fillStyle 或默认黑。CSS 上下文（`style="color:var(--up)"`）没问题，**只有进 echarts option 的 canvas 绘制色**踩坑。

**根治方向（待拍板，勿再扩散）**：①加 `cssVar()` 解析器 `getComputedStyle(document.documentElement).getPropertyValue(name)` 把令牌解成 hex 再进 option（一处 helper 全站图统一）；②或按 `--ma-line` 先例：图表数据面用字面 hex + 注释标令牌名（tokens.css 已注「图表数据面专用，不入文本」）。**全仓现零 getComputedStyle 命中**，属批一未验的盲区——UI 数值断言只查 DOM 不查 canvas，三轮同教训（真渲染走真环境）。

## 2026-09-03 · 注释里写 #hex 会被令牌门粗 grep 计数

**现象**：check-tokens.sh 的 `count_hex()` 用 `grep -Eoh "#[0-9a-fA-F]{3,6}"` 扫 views/+components/ 全行（含注释），我在 BacktestView 回撤曲线注释里写 `// #0A7A54=var(--down) 字面值`，把注释的 `#0A7A54` 也计进去了（HEX +1）。排查时按「我删了 3 处 hex」推总数，结果和门对不上，追根是注释自增。

## 2026-08-27 · systemd StartLimit 窗口内 reset-failed 后 start 仍被拒（G4 ④a 实证）

**现象**：hub 五杀（约 2 分钟内）打穿 StartLimit（Burst=5/Interval=300s）→ failed（21:20:26 db6 实证）。L3 首轮 beat 21:20:21 reset-failed+start → start 被拒（l3_failed，新进程未拉起）；第二轮 beat 21:25:21 重试成功（距窗口理论过期 21:24:55 约 26s）。另 21:05:21 beat 曾 l3_guards=lease-held 正确让位（六杀进行中租约未过期）——盲审拾遗。

**根因**（al8 systemd 239-82.0.4.5 实证；上游后续版本行为未核）：`systemctl reset-failed` 清 failed 态，但**不清窗口内已计数的 start 尝试**——StartLimitIntervalSec 未过期时 start 仍被拒。三角互证：本例拒/成同 polkit 语境（49-quant.rules manage-units 全放行，权限解释排除）+ 3a 沙箱同款 + 239 man page 只提清态不提清计数。**注意：quant-svc wrapper 前置 reset-failed 的缓解在 239 上无效**——release/rollback 管道对窗口内 crash-loop 单元仍会中断（自动回滚兜底）。

**防御**：L3 按设计未记退避（l3_failed 不计 attempts），窗口过期后下轮 beat 自然自愈。人工介入：等窗口过期（从最后一次被计数的 start 尝试起算 Interval）再 start；被拒的 start 是否续窗未单独核，勿依赖。

**附带缺口（P2，双盲核确）**：l3_failed 分支不记 stderr 不告警（L1 同型分支记 stderr 入 result，L3 版丢弃）且无 L3 级测试——持续失败会静默每 300s 重试；待补 stderr+告警+测试。

## 长事务锁链闷死 DDL 与部署管道自伤（2026-08-20 锁链事件）

- **现象链**：14:29 手动触发 astock_basic 同步（逐行 INSERT 长事务）→ 15:0x 部署跑 alembic `CREATE INDEX`（要锁）排队等事务 → 部署侧三次中断（闸门差 1 分钟/timeout/`| head` SIGPIPE 杀 rsync）→ 每次"僵尸 alembic"在 PG 侧持锁滞留（pkill 客户端≠PG 释放锁，TCP 半开连接默认等 keepalive 数小时）→ 7 个 CREATE INDEX 排队 + 19min idle in transaction → 后续部署全部"卡在 migrate"。
- **诊断钥匙**：`pg_stat_activity` 按 `xact_start` 排序看事务龄——`Lock/relation` 等锁者+最早一条 `Client/ClientRead` 长事务=源头；`pg_terminate_backend(pid)` 精确清 9 条解锁。**kill 客户端进程不清 PG 锁**，PG 侧 terminate 才是终点。
- **通用教训 1**：**同步任务事务里禁跨网络拉取**（Tushare 慢=49min 事务）；批量写要分段提交（N 行/事务）。→ 已立项数据库操作统一规划（18 号文档）根治。
- **通用教训 2**：**DDL 无限等锁=部署闷死**——alembic/迁移要带 `lock_timeout`；索引上生产用 `CREATE INDEX CONCURRENTLY`。
- **通用教训 3**：**部署命令禁接 `| head`**（SIGPIPE 杀 rsync 半途）；输出重定向文件再 grep。部署超时转后台时,rsync 可能已完成而服务未重启——指纹对比的是"服务器文件"非"进程代码",形成"文件新+进程旧"死循环（重启被指纹跳过）——`--force` 语义扩展为强制重启即为此解（用户审核后同步 michael 版生效）。
- **通用教训 4**：`idle in transaction` 是池化会话事务边界失管的信号（SELECT 完归还未 commit）——PG 侧 `idle_in_transaction_session_timeout` 该设（入 DB 规划）。

## 断流守卫基线必须时段作用域；重启不是疗法（2026-08-18 hub 晨间自杀案）

- **现象**：hub 每晨 09:31:02 必自杀重启（journal：`hub tick 断流 34627s`）。根因链：`first_tick_today`/`last_tick_wall` 是**进程生命周期**变量，昨夜 23:54 回放最后 tick 把基线钉在昨天；09:31 `in_session()` 翻真瞬间 stale=9.6h>300s → 按设计自杀。注释里"防假日误判断流"的保护恰被此击穿。
- **通用教训 1**：任何"staleness/新鲜度"基线必须**会话/时段作用域**（进入沿清零），进程累计值跨日必污染。三所规则不一（沪深收盘竞价/北交所无、可转债临停零 tick 合法）+券商平台偏差（夜间回放），把时段预期编进守卫触发器必在边界翻车。
- **通用教训 2**：**重启只解决进程自身问题**（死锁/内存/内部状态机）；平台/网络问题重启无效且重启风暴有害。守卫动作只认事实信号（连接回调/线程状态/watchdog/unit 状态），数据节奏异常→告警+消费端冻结，不自杀。
- **修复**（15-服务监控设计.md）：删两处自杀改告警；基线改时段内；BUY 安全判定挪 send_order 时刻（`buy_ok_check`），日历从动作路径清零。

## PG 时区：timestamptz 必须 aware UTC 比较

- **现象**：Python tuple 被适配为行记录 `(a,b,c)` 而非数组，`ANY(tuple)` 报 `malformed array literal`。

## 部署假成功：僵尸进程占端口

## 盲审子代理在共享工作树跑 git checkout，提交被孤儿化（2026-09-01 W3 批实锤）

- **形态**：W3 代码双盲子代理执行审查时 `git checkout b5fd2a5`（进 detached HEAD）→ 我随后提的窗口修正 `53279af` 落在游离 HEAD 上 → 代理又切回 main → 提交脱离分支，工作树文件回旧版、修改"消失"。
- **破案钥匙**：`git reflog`——checkout 轨迹+提交在游离 HEAD 的完整记录；`git merge-base --is-ancestor <sha> HEAD` 快速判在链与否。
- **恢复**：reflog 找回 sha → `git cherry-pick --no-commit <sha>` 应用回分支。
- **根因**：子代理与主会话**共享同一工作树**，代理的任何写操作（checkout/reset/stash）直接劫持主会话的 HEAD。
- **规约**：盲审/子代理提示词必须声明"**禁 git checkout/reset/stash 等写操作，只读审查用 git show <sha>:<path> / git diff**"；主会话提交后若发现文件内容"回退"，第一反应查 reflog 而非重写。
