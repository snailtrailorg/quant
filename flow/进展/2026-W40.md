**威廉姆两条裁定**：①「代理不应只支持 socks，普通 http/https 代理也应该支持」；②「服务器设置还是有的，不能硬编码」（各 provider 服务端点走配置面）。设计真源 `flow/方案/多市场数据接入与代理体系-设计-20261006.md` **§三**（表语义 / DNS 约束 / 接线形状 / 验收实证全部落在那里，本文不复制）。

**做了什么**（六面）：

1. **迁移 0135**（expand-only，幂等建表 `IF NOT EXISTS`）：`proxy_config`（池）+ `proxy_binding`（按消费方绑定）。两条约束**落 DB 层**：`CHECK (NOT proxy_enabled OR proxy_name IS NOT NULL)`、`REFERENCES proxy_config(name) ON DELETE SET NULL`——后者使「删被启用绑定引用的池行」被**整体拒绝**（＝路由 409 `PROXY_IN_USE` 的 DB 层根据），不会留悬空启用态。**零 seed**。
2. **层 1 `data_platform/proxy.py`**（全部 SQL 在此）：校验（scheme 词表 / host / **显式端口**）、掩码（只替 userinfo）、池 CRUD、绑定读写、`resolve_proxy`/`resolve_endpoint`、`capable_consumers`、`probe`（**失败不抛**）。
3. **接线＝三层分工（本批最关键的取舍）**：解析在 `engine._apply_exit_config`（构造 adapter 时**一次**）、注入在 `BaseDataAdapter.configure_exit`、使用在 adapter。**解析放 engine 而非 adapter**，是为了让「每任务解析一次」与「手搓 adapter 的单测零 DB 耦合」（`test_engine_provider` / `_pull` 直测）**同时成立**；`exit_config()` 只读注入结果。**解析失败＝回落直连 + WARNING**（口径同本文件 `_routing_pilot_on`）——出口代理是**增强**不是前置，可选配置的存储异常不该打挂同步任务；代价（表象与「正常直连」同形）靠 WARNING + probe 兜底，已在设计 §3.4/§3.6 明账。
4. **能力真源＝adapter 类属性** `supports_exit_config`（现 `binance=True`，SDK 型 tushare/聚宽 False）：不可配的消费方在**写入侧 400 `CONSUMER_NOT_PROXYABLE`** 响亮拒绝、`configure_exit(proxy=…)` 抛 `UnsupportedFeature`、引擎对其**不触库**。102b 接 OKX 后前端**零改动**自动长出该行。
5. **HTTP 栈**：binance `_get` urllib → **requests**（404→None / 其余抛，行为等价）；`requirements.txt` 显式补 `requests>=2.31` + **PySocks>=1.7**（http 路不需要，socks 路需要）。
6. **面（集成中心新增「代理出口」页签）**：池表（掩码地址 / DNS 解析侧标记 / 状态 / 测连通·编辑·删除）+ 绑定表（启用开关 / 选用代理 / 端点覆盖）；绑定行集合由后端 `capable_consumers()` 派生。词条 zh/en 1860 键对称。

**⭐ 附带修掉一个真缺陷：游标契约（`cursor_upto`）**。原实现取**窗口上界**。实测批量站
