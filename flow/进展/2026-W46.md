## 2026-11-13 午 · P3 迁移涟漪 P0：SA4 期望源漏 xtp（hub@1 每 5 分钟被停）

- **现象**：R7（`202611131126-9382671`）上产后 hub@1 反复 inactive；journal 显示 11:31:46 / 11:36:46 / 11:56:46 / 12:01:46 全部卡 **:46 秒、5 分钟倍数**，干净 `SIGTERM → 优雅退出 → Succeeded`（exit 0）；unit `Restart=on-failure` + `RestartPreventExitStatus=0 78` → exit 0 不拉起，故停在 inactive。
- **根因**（推翻原「波内启停竞态」定性）：`scheduler/tasks.py::_desired_units` 的 hub 期望源 provider 白名单只取 `list_md_gateway_providers()`（**legacy 注册表**）。P3 把 XTP MD 迁到 `providers/xtp` 插件端口后，legacy 表只剩 `emt_emq/binance_perp/okx_perp`——**无 xtp**。于是账号 1 不进 `desired`，SA4 beat（每 300s）把 `quant-md-hub@1.service` 判为"多余实例" stop。与部署波/dwell/watchdog/插件缺陷**均无关**：R7 发布期内 dwell 稳定窗、版本收敛断言（MainPID）全 `ok`，RECAP 也 `failed=0`，hub@1 是发布收尾后才掉的。这也统一解释了 11-12 起「hub exit 0 消失 15 小时」。
- **修**：白名单改为 `legacy 注册表 ∪ registry(trading 域声明 market_data 能力) provider`（并集保留 EMT/加密 legacy 双轨）；真跑确认得 `['binance_perp','emt_emq','okx_perp','xtp']`。守门测试 `test_p3_xtp_in_md_provider_allowlist` 直接钉 `conn.execute` 传给 `trading_account` SQL 的 params 含 xtp（不用 mock 的 SQL 前缀分流结果，防「白名单缺 xtp 也假绿」的门控自失效）。全量 3288 绿。
- **教训**：迁移类改动必须按 git diff 扫「旧注册表的**全部**消费方」——hub 侧切了 registry，scheduler 侧期望源没跟上；双轨迁移期任何"provider 能力集合"都要以 registry 为准并与 legacy 取并集，不能只信一处注册表。停服排查先看 `RestartPreventExitStatus` 与退出码，别把"周期性干净退出"当竞态或 watchdog。
