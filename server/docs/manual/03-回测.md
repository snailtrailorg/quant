# 03 · 回测

## 发起

回测 → 新建回测：选策略 + 标的（手输或选池）+ 日期区间 + 初始资金 + 佣金率 + 模式（single/serial/parallel 组）。

组模式：多标的同时回测同一策略——详情页有组汇总（平均收益+排名），池策略用 parallel。

## 结果页

- **四张统计卡**：总收益/胜率/最大回撤/夏普（批次 2 修复——此前恒 '-'）
- 每标的状态（done/failed/error）+ 单标的收益
- 点行进单标的视图：echarts 净值曲线+回撤+成交明细（SSE 实时更新当运行中）
- 「标记回测验证」= 给策略打 backtest_verified（实盘第三级开关）

## 预检（失败≠通过）

发起后自动跑两道预检：
1. **数据完整性**（F-MOD-004）：量够不够因子窗口/时序断点/零值
2. **防未来函数**：因子只见过去 bar

预检失败 → 状态 **failed**（红色）+ 原因在 result——**不是 done**（批次 1 #15 修复：此前静默标 done 存全 0 指标）。
**全败的 run 也是 failed**——零成功标的不能过验证门（#R-S5）。

## 标记验证的条件（F-44 证据门）

- 存在属于该策略、状态 **done** 的回测 run
- 全 failed 的 run 不算证据

## ⚠️ 频率差异声明（重要）

| | 回测 | 实盘 |
|---|---|---|
| bar 频率 | **日线** | **1 分钟** |
| ma_dev(n=20) | 20 日均线 | 20 分钟均线 |

同一策略同一参数在两端**语义不同**——阈值需按频率换算（多频统一见 16 号设计，实施中）。
回测验证的是"策略结构"，不是"分钟阈值"。

## 常见问题

| 现象 | 原因 | 处置 |
|---|---|---|
| 状态 failed + "回测数据预检失败" | 数据量<因子窗口 | 拉长日期区间或减小 n |
| 状态 error | 运行异常 | 看 result.error 详情 |
| 终止按钮无效 | 运行中任务（批次 2 修复 task_id） | 刷新后重试 |
| 标记验证 403 NO_DONE_BACKTEST | 无 done run | 先修数据问题跑出 done |
